# Сравнительный анализ MCP-серверов для кодовых баз 1С

**Конфигурация:** 1С:Документооборот КОРП 3.0 (ДО3)
**Дата тестирования:** 07–08 апреля 2026
**Методология:** 10 идентичных бизнес-вопросов × 6 серверов = 60 прогонов
**Оценщик:** Claude Opus 4.6 (оркестратор)
**Анализатор:** Claude Sonnet (агент)
**Воркфлоу:** [WORKFLOW.md](WORKFLOW.md) | **Тесты:** [E2E_TEST_PROMPTS.md](E2E_TEST_PROMPTS.md)

---

## 1. Описание сравниваемых серверов

### Бесплатные (open-source)

| Сервер              | Описание                                                                                                                                                                                                                                                                                                 |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **1c-mcp-metacode** | Загружает метаданные конфигурации и исходный код в Neo4j-граф, предоставляя структурный и семантический поиск через MCP ([GitHub](https://github.com/ROCTUP/1c-mcp-metacode))                                                                                                                            |
| **rlm-tools-bsl**   | Серверный анализ BSL-кода с 51 встроенной функцией фильтрации, работает напрямую с исходниками; индексирование опционально — улучшает качество и скорость поиска (на ДО3 полнотекстовые индексы построены за ~4 мин), минимизирует расход токенов ([GitHub](https://github.com/Dach-Coin/rlm-tools-bsl)) |

## 8. Выводы и рекомендации

### RAG vs RLM: итоги сравнения

Тестирование на конфигурации 1С:ДО3 показало, что подход **RLM (серверный анализ кода)** в лице rlm-tools-bsl превосходит **RAG-подход (эмбеддинги + семантический поиск)** по всем ключевым метрикам:

| Метрика              | RAG-серверы (лучший) |   RLM (rlm-tools-bsl)    |
| -------------------- | :------------------: | :----------------------: |
| Качество (ПОЛНОСТЬЮ) | 10/10 (code-meta 08) |          10/10           |
| Avg токенов          | 179K (code-meta 08)  |         **117K**         |
| Полезных вызовов     | 87.7% (code-meta 08) |        **92.5%**         |
| Индексирование       |      83–91 мин       | **~4 мин (опционально)** |
| Зависимости          |  Docker, LM Studio   |         **нет**          |
| Стоимость            |       платный        |      **бесплатный**      |

Главное преимущество RLM — **прямой доступ к коду**: агент получает точные тела процедур, а не чанки из семантического поиска. Это исключает галлюцинации и даёт код-верифицируемые ответы.

### Когда использовать RAG

RAG-серверы остаются полезны в сценариях:
- **Быстрый поиск по описанию** — cloud-embeddings находит нужную процедуру за 6 вызовов (TEST-05), когда точное имя неизвестно
- **Анализ зависимостей через граф** — graph-metadata и code-metadata 08 дают карту связей между объектами через graph_dependencies
- **Работа с документацией** — helpsearch находит описания из встроенной справки конфигурации

### Рекомендации для анализа кодовых баз 1С

1. **Для повседневного анализа** — используйте **rlm-tools-bsl**: нулевые затраты на настройку, максимальная точность, минимальный расход токенов
2. **Для глубокого анализа архитектуры** — комбинация **rlm-tools-bsl** + **code-metadata-search (08.04)**: код + структурные зависимости
3. **Для анализа связей и зависимостей** — **graph-metadata-search** через Cypher-запросы (но контролируйте объём properties() чтобы избежать token-взрывов)
4. **При обновлении серверов** — всегда проверяйте новые образы через E2E-тесты: обновление code-metadata дало скачок с 70% до 100% качества

## 9. Почему code-metadata-search внезапно прокачался

Новые релизы code-metadata помимо улучшений работы чанкинга и векторизации имеют под капотом механизмы полнотекстового поиска, заимствованные из rlm, что подтверждает [официальная документация продукта](https://docs.onerpa.ru/mcp-servery-1c/servery/code-metadata-search) (секция «Дополнительно: rlm-tools-bsl (RLM-подход)»).
