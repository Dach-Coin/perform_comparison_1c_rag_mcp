# Воркфлоу E2E-тестирования MCP-серверов

Универсальный протокол сравнительного тестирования MCP-серверов для анализа кодовых баз 1С.
Серверы и их параметры загружаются из файла конфигурации `servers.yaml`.

## Роли

- **Оркестратор** (Opus) — запускает агентов, проверяет инфраструктуру, пишет оценки качества
- **Агент-анализатор** (Sonnet) — выполняет тест на одном MCP-сервере, пишет лог и бизнес-отчёт

## Запуск

Пользователь указывает номера тестов и список серверов:

```
Запускаем анализ по воркфлоу, тесты №№ 1-3, MCP-серверы: cloud-embeddings, rlm-tools-bsl
```

Если серверы не указаны — запускаются все серверы из `servers.yaml`.

---

## Шаг 0: Проверка инфраструктуры (один раз за сессию)

Оркестратор загружает `servers.yaml` и проверяет доступность сервисов.

### 1. Инфраструктурные зависимости

Для каждого элемента из секции `infrastructure`:

```bash
# LM Studio — модель загружена?
curl -s <infrastructure.lm_studio.url> | head -20

# Neo4j — доступен?
curl -s <infrastructure.neo4j.url> | head -5
```

Проверяются только зависимости, указанные в `requires` выбранных серверов.

### 2. Серверы

Для каждого сервера из списка запуска:

- Если `health_check.method == "http"`:
  ```bash
  curl -s <health_check.url>
  ```
- Если `health_check.method == "mcp_call"`:
  ```
  Вызвать <mcp_prefix><health_check.tool> с аргументами <health_check.args>
  ```

Если что-то не отвечает — сообщить пользователю, НЕ запускать тесты.

## Шаг 1: Запуск агентов параллельно

Оркестратор берёт текст теста из `E2E_TEST_PROMPTS.md` и запускает **по одному агенту-сонету на каждый сервер** из списка запуска (Agent tool, model: sonnet).

Каждому агенту передаётся:

1. **Протокол** из E2E_TEST_PROMPTS.md (подставив `<СЕРВЕР>`, `<ID>`, `<ДАТА>`)
2. **Текст тестового промпта**
3. **Строгое ограничение**: использовать ТОЛЬКО свой MCP-сервер

### Серверы и их инструменты

Загружаются из `servers.yaml`. Для каждого сервера:

| Параметр             | Источник в servers.yaml     |
| -------------------- | --------------------------- |
| Имя сервера          | `server.name`               |
| Префикс инструментов | `server.mcp_prefix`         |
| Инструменты          | `server.tools`              |
| Каталог отчётов      | `server.report_dir`         |

### Что пишет каждый агент

- **Лог**: `agent_logs/test<ID>_<short_name>_log.md`
- **Бизнес-отчёт**: `business_reports/<report_dir>/<ДАТА>_test<ID>_<название>.md`
- **Временные файлы** (если нужны): `tmp/test<ID>_<short_name>_*.md`

Краткие названия тестов — в таблице в E2E_TEST_PROMPTS.md.

## Шаг 2: Оценка качества (оркестратор)

После завершения всех агентов оркестратор:

1. Читает все логи и бизнес-отчёты
2. Для КАЖДОГО сервера пишет файл оценки качества:

```
business_reports/<report_dir>/<ДАТА>_test<ID>_<название>_ОценкаКачества.md
```

### Структура файла оценки

```markdown
# Оценка качества: TEST-<ID> — <Название теста>
**Сервер:** <display_name>
**Дата:** <ДАТА>
**Оценщик:** Оркестратор (Claude Opus 4.6)

## Общая оценка: ПОЛНОСТЬЮ / ЧАСТИЧНО / НЕ СМОГ

## Метрики
| Метрика                | Значение |
| ---------------------- | -------- |
| Вызовов MCP            | N        |
| Полезных               | N (%)    |
| Шумных                 | N (%)    |
| Retry                  | N        |
| Общее время агента     | X мин    |
| Токенов агента (total) | ~NK      |

## Что сервер дал хорошо
(конкретные факты, полученные из MCP)

## Что сервер НЕ дал
(что не нашлось, с причинами — чанкинг, отсутствие данных и т.д.)

## Паттерны поведения агента
(сколько попыток, какие стратегии поиска, что сработало)

## Выявленные проблемы RAG
| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |

## Вывод
(2-3 предложения: для каких вопросов сервер подходит, для каких нет)
```

## Как добавить свой MCP-сервер

1. Откройте `servers.yaml`
2. Добавьте новую запись в секцию `servers`:

```yaml
  - name: my-mcp-server              # имя в Claude Code
    display_name: "My MCP Server"     # название для отчётов
    short_name: my-server             # краткое имя для файлов
    report_dir: my-server             # каталог в business_reports/
    description: "Описание сервера"
    url: "https://github.com/..."
    license: free                     # free | paid
    type: rag                         # rag | rlm | graph
    port: 9000                        # порт (если HTTP)
    mcp_prefix: "mcp__my-mcp-server__"
    health_check:
      method: http                    # http | mcp_call
      url: "http://localhost:9000/health"
    tools:
      - tool_name_1
      - tool_name_2
    requires:                         # зависимости из infrastructure
      - docker
```

3. Если серверу нужна новая инфраструктурная зависимость — добавьте её в секцию `infrastructure`
4. Создайте каталог `business_reports/<report_dir>/`
5. Запустите тесты: `Тесты 1-10, серверы my-server`
