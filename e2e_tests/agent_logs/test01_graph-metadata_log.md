### Что получено из MCP (достоверно):
1. Реквизиты справочника ДокументыПредприятия — полный список (80+ реквизитов)
2. Список бизнес-процессов с реквизитами (Рассмотрение, Исполнение, Согласование, Регистрация + 6 других)
3. Жизненный цикл через состояния документа — 20 типовых состояний
4. Инфраструктура нумерации: Справочник Нумераторы, Регистр НастройкиНумерации с измерениями
5. Регистр ДанныеДокументовПредприятия — структура
6. Подписки на события — полный список (229 штук), идентифицированы ключевые для ДокументыПредприятия
7. Табличные части ДокументыПредприятия
8. ВидыКорреспонденции: Входящая / Исходящая

### Что пришлось додумывать/угадывать:
1. Кто конкретно регистрирует входящее письмо — из метаданных видно реквизит Зарегистрировал (тип Сотрудники), но конкретный бизнес-процесс Регистрация назначается исполнителем — это предположение на основе структуры БП
2. Точный код обработчиков ПередЗаписью/ПриЗаписи модуля объекта ДокументыПредприятия — не получен напрямую, только подписки на события
3. Связь "входящее письмо" → "документ предприятия" — логически выводится через ВидКорреспонденции.Входящая

### Чего не хватило:
1. Прямого кода модуля объекта справочника ДокументыПредприятия (search_code не нашел, так как индекс fulltext не проиндексировал код основного объекта)
2. Ресурсы регистра ДанныеДокументовПредприятия — получено только 30 из, вероятно, больше
3. Связи бизнес-процессов с предметом типа ДокументыПредприятия через граф
4. business_search недоступен (вектор не инициализирован)
