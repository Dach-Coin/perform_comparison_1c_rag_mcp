## Субъективная оценка

**Ответ на вопрос: ЧАСТИЧНО**

**Что получено из MCP:**
- Механизм RLS: константа `ДокументооборотИспользоватьОграничениеПравДоступа`, модуль `ДокументооборотПраваДоступа`, подсистема дескрипторов
- Рабочие группы: РС `РабочиеГруппы` с полями `Объект`, `Участник`, `Изменение`, модуль `РаботаСРабочимиГруппами`
- Руководитель видит задачи подчинённых: `ЗаполнитьГруппировкуЗадачиПодчиненных`, команда `ЗадачиПодчиненных`
- Проверка прав: `ДокументооборотПраваДоступа.ПраваСотрудниковПоОбъектам`, `ПраваПользователяПоОбъекту`
- Подписка на события для документа Задача при записи: `ДокументооборотПраваДоступаПередЗаписьюДокумента`
- Функциональная опция `ИспользоватьЗадачи` включает документ Задача

**Что пришлось додумывать:**
- Конкретный список ролей конфигурации, дающих доступ к документу Задача — не найден (metadatasearch не вернул чанки раздела "Роли" с детализацией по объектам)
- Точная структура РС `РабочиеГруппы` (все измерения/ресурсы) — получена частично
- Описание полного механизма RLS в контексте именно документа Задача — получено косвенно через общие механизмы

**Чего не хватило:**
- Прямого поиска раздела "Роли" в отчёте по конфигурации с привязкой к правам на Документ.Задача
- Индексация справки по разделу "Права доступа к задачам" (helpsearch не дал результата)
