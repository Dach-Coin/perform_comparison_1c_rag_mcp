QN: `test-do3/ДокументооборотКОРП/БизнесПроцессы/Согласование`

| Реквизит | Назначение |

## 2. Параметры запуска — Табличная часть "Исполнители"

При запуске согласования заполняется ТЧ **Исполнители** — список согласующих:

| Реквизит ТЧ | Назначение |
|------------|-----------|
| Исполнитель | Ссылка на сотрудника/роль |
| ПорядокСогласования | Определяет последовательность обхода (одинаковые номера = параллельно, разные = последовательно) |
| СрокИсполнения / ...Дни / ...Часы / ...Минуты | Индивидуальный срок для исполнителя |
| ВариантУстановкиСрокаИсполнения | Способ установки срока (абсолютный/относительный) |
| ЗадачаИсполнителя | Ссылка на созданную задачу (заполняется автоматически) |
| Пройден | Флаг — участник завершил свою задачу |
| ИдентификаторИсполнителя | Уникальный ИД для связи с визой |
| Описание | Текстовое описание роли |
| ТрудозатратыПланИсполнителя | Плановые трудозатраты |

**Как заполняется:** Процедура `ЗаполнитьЗадачуСогласовать(Задача, Строка)` в ObjectModule заполняет каждую задачу по строке ТЧ.

**Создание задач:** Функция `СоздатьЗадачиСогласования()` создаёт задачи согласно настройкам ТЧ, возвращает массив незаписанных объектов задач.

## 3. ВизыСогласования — структура и связь с процессом

**Справочник ВизыСогласования** — основной объект, хранящий "отпечаток" согласования каждого участника.

### Атрибуты Справочника ВизыСогласования

| Реквизит | Назначение |
|----------|-----------|
| Владелец | Ссылка на документ-владелец |
| Документ | Согласуемый документ |
| Исполнитель | Участник согласования |
| РольИсполнителя | Роль участника (из Перечисления.ФункцииУчастниковСогласования) |
| ИдентификаторУчастника | Связь с ТЧ Исполнители через ИдентификаторИсполнителя |
| РезультатСогласования | Результат (из Перечисления.РезультатыСогласования) |
| Комментарий | Комментарий согласующего |
| ДатаСоздания | Дата создания визы |
| ДатаИсполнения | Дата проставления результата |
| ДатаПомещенияВИсторию | Дата архивации визы |
| Порядок | Порядок обхода (зеркало ПорядокСогласования из ТЧ) |
| НомерИтерации | Номер итерации (при повторных согласованиях) |
| Подписана | Признак наличия ЭП на визе |
| ПомещенаВИсторию | Флаг архивации |
| Удалена | Флаг мягкого удаления |
| УстановилРезультат | Кто именно установил результат |
| ПоместилВИсторию | Кто поместил в историю |

### Связь виза — процесс
- Виза создаётся для каждого согласующего в момент старта соответствующей "волны" согласования
- Связь: `ВизаСогласования.ИдентификаторУчастника` = `ТЧ_Исполнители.ИдентификаторИсполнителя`
- Создание виз: `РаботаСВизамиСогласования.СоздатьВизыПоДействию(Действие, Участники)`
- Начало итерации: `РаботаСВизамиСогласования.ОбработатьВизыДействияПриНачалеИтерации(Действие, Участники)`

## 4. Результаты согласования

### Перечисление РезультатыСогласования

Прямые значения перечисления через API метаданных не получены (ограничение сервера). На основе анализа кода:

| Значение | Описание |
|----------|---------|
| **Согласовано** | Исполнитель поставил положительный результат |
| **НеСогласовано** | Исполнитель отказал в согласовании |
| **Прервано** | Процесс был прерван (ПричинаПрерывания заполнена) |

Косвенные подтверждения из кода:
- Функция `ЕстьВизыНеСогласованные(Документ)` — явно проверяет несогласованные
- Функция `ЕстьВизыНаСогласовании(Документ)` — визы в процессе
- Функция `НайтиПоРезультатуСогласования(РезультатСогласования)` — преобразует в РезультатыПодписания

### Дополнительные перечисления

- **ФункцииУчастниковСогласования** — роли участников (согласующий, ознакамливаемый и др.)
- **СпособыСогласованияВРежимеЗамечаний** — режим с замечаниями
- **ТипОчередиПодготовкиКСогласованию** — тип очереди подготовки

## 5. Обработка завершения — какой код срабатывает

### Основной обработчик завершения задачи

```
// ObjectModule БизнесПроцессы.Согласование
Процедура ОбработатьЗавершениеЗадачиСогласования(Задача)
// Обрабатывает завершение задачи согласования, выполняя необходимые изменения в процессе.
// Задача - ЗадачаСсылка.ЗадачаИсполнителя
```

### Цепочка обработки при завершении всех согласующих

1. **Задача завершается** (исполнитель нажимает кнопку "Согласовать"/"Не согласовать")
2. **`ОбработатьЗавершениеЗадачиСогласования(Задача)`** — основная обработка в ObjectModule:
   - Помечает строку ТЧ Исполнители.Пройден = Истина
   - Обновляет визу через `РаботаСВизамиСогласования.ОбновитьВизуУчастника`
3. **Проверка `ОбходСогласующихЗавершен()`** — если все исполнители прошли:
   - Вызывается `ИтоговыйРезультатСогласования()` — агрегация результатов
   - Устанавливается `РезультатСогласования` в шапке процесса
4. **`ДобавитьЗадачуОтложеннаяОбработкаЗавершенияСогласования()`** — добавление служебной задачи отложенной обработки
5. **`ОбработатьДобавлениеЗадачиОтложеннаяОбработкаЗавершенияСогласования(Процесс)`** из `ОбщиеМодули.ОбработкаОчередиЗаданийСервер` — выполняет финальную обработку
6. **`РаботаСВизамиСогласования.ПоместитьВизыВИсторию(Визы)`** — архивация виз
7. **Уведомление автора** (задача на обработку результатов для ОбрабатывающийРезультат)

### Условная логика завершения (из кода)

- При **параллельном** согласовании: `МожноВернутьИсполнениеНаДоработку` — если в корне не параллельное — Истина; иначе зависит от результатов
- При наличии режима замечаний: `СогласованиеВРежимеЗамечанийСервер.ЕстьНеЗавершенноеСогласованиеПоДокументу(Документ)`

## Итоговый вывод

Бизнес-процесс **Согласование** в DO3 — полноценный механизм многошагового согласования документов:

1. **Запуск**: Заполняется ТЧ Исполнители (кто, в каком порядке, с каким сроком). ВариантСогласования определяет логику обхода. Задачи создаются функцией `СоздатьЗадачиСогласования()`.

2. **ВизыСогласования**: Для каждого исполнителя создаётся виза-запись в Справочнике ВизыСогласования. Виза хранит результат, комментарий, дату, подпись ЭП.

3. **Результаты**: Перечисление РезультатыСогласования (Согласовано/НеСогласовано/Прервано). Итог агрегируется функцией `ИтоговыйРезультатСогласования()`.

4. **Завершение**: Процедура `ОбработатьЗавершениеЗадачиСогласования(Задача)` в ObjectModule обрабатывает каждую задачу. При завершении всех — отложенная задача через `ОбработкаОчередиЗаданийСервер`. Визы архивируются через `РаботаСВизамиСогласования.ПоместитьВизыВИсторию()`.

5. **Ключевые модули**: РаботаСВизамиСогласования (API виз), РаботаСПроцессамиПоДействиям (жизненный цикл), ИнтеграцияЗадач (интеграция задач), ОбработкаОчередиЗаданийСервер (отложенная обработка).
