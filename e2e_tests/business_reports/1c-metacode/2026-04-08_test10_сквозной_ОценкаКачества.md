## Что сервер дал хорошо

- **Все 5 объектов сквозного сценария** с полной структурой реквизитов:
  - ВходящееПисьмо (25 реквизитов), ИсходящееПисьмо (29 реквизитов), Задача (30 реквизитов), ЗадачаИсполнителя (27 реквизитов), ДействиеЗадачи (24 реквизита)
- **Оба бизнес-процесса** со всеми реквизитами:
  - Рассмотрение (57 реквизитов — один из самых сложных объектов в конфигурации)
  - Исполнение (30 реквизитов)
- **Справочник Резолюции** (11 реквизитов) — промежуточное звено между рассмотрением и исполнением
- **Конкретные процедуры для каждого шага**:
  - Шаг 1: ВвестиДанныеРегистрации (ДелопроизводствоКлиент), ДобавитьВложениеПисьмаИзИнтернетПочтовогоВложения (ВстроеннаяПочтаСервер)
  - Шаг 2: ВыполнитьИнтерактивныйЗапускБизнесПроцесса, ПолучитьРезолюции, ПроверитьДоступНаПодписание
  - Шаг 3: ОбработатьСозданиеПроцессаИсполненияПоРезультатамРассмотрения — **ключевая функция-переход**, ЗаполнитьЗадачуПоБизнесПроцессу, СоздатьКарточкуКонтроляПоПроцессу
  - Шаг 4: ДобавитьФайлКОтчету (клиент), ДобавитьПриложения (сервер)
  - Шаг 5: СоздатьПисьмоНаОсновании, СформироватьТекстИсходящегоПисьма, ПодготовитьПисьмо
- **6 регистров** с измерениями и ресурсами: ДанныеБизнесПроцессов (20 ресурсов), ТекущиеСостоянияДокументов, СведенияОбИсполнителяхЗадач, тст_СрокиИсполненияЗадач, КоличествоЗадач, КоличествоДействийЗадач
- **Связь ПисьмоОснование** в ИсходящееПисьмо — ключевой реквизит, замыкающий цикл «входящее → исходящее»

## Что сервер НЕ дал

- **Табличные части объектов** — list_tabulars / list_tabular_sections не поддерживаются (4 ошибочных вызова из 7 шумных)
- **Модули объектов** — list_modules не поддерживается. Код модулей объектов доступен только через search_code
- **Ресурсы двух регистров** — ТекущиеСостоянияДокументов и СведенияОбИсполнителяхЗадач вернули пустые результаты по list_resources (возможно, данные хранятся только в измерениях)

## Паттерны поведения агента

- **Методичное прохождение по шагам**: агент последовательно разобрал все 5 шагов сценария, для каждого получил структуру объекта + код
- **Комбинирование 3 инструментов**: search_metadata (шаблонные запросы) для структуры → search_metadata_by_description для семантического поиска связанных объектов → search_code для процедур. Все три эффективно использованы
- **search_metadata_by_description как «расширитель контекста»**: 2 вызова по ~63K символов каждый — нашли связанные регистры, модули, процессы, которые не были очевидны из имён. Но **огромный расход токенов** — 2 вызова = 73% от всего объёма
- **Нет retry**: агент не повторял запросы — точные формулировки с первого раза. 7 шумных вызовов — это 4 ошибки неподдерживаемых операций + 2 пустых результата + 1 ошибка пустого имени
- **35 вызовов — много для одного теста**, но оправдано сложностью сквозного сценария (5 шагов × метаданные + код)

## Выявленные проблемы RAG

| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| Отсутствие list_tabulars / list_tabular_sections | 4 ошибочных вызова. Невозможно получить ТЧ документов — критично для полного описания структуры |
| Отсутствие list_modules | 1 ошибочный вызов. Нельзя узнать, какие модули есть у объекта (МодульОбъекта, МодульМенеджера, МодульФормы) |
| search_metadata_by_description — избыточный объём | 2 вызова вернули по ~63K символов (~114K токенов каждый). Это 73% всего расхода. Нужна пагинация или ограничение объёма |
| Пустые ресурсы регистров | list_resources для ТекущиеСостоянияДокументов и СведенияОбИсполнителяхЗадач вернул 0 — возможно, данные хранятся в измерениях, но API не сообщает об этом |

## Вывод

Сервер 1c-metacode-test-do3 **успешно поддержал** самый сложный тест серии — сквозной сценарий из 5 шагов с множеством объектов, процессов и модулей. Шаблонный API обеспечил точное получение структуры каждого объекта, а search_code нашёл конкретные процедуры с сигнатурами. Главная проблема — **расход токенов на search_metadata_by_description** (2 вызова = 127K символов = ~229K токенов), что делает этот инструмент дорогим. Для сквозных сценариев сервер подходит хорошо, но требует контроля объёма семантического поиска.
