## Что сервер дал хорошо

1. **Полная структура регистров нумерации** — РС.Нумерация (11 измерений + ТекущийНомер), РС.НастройкиНумерации (11 измерений + 2 ресурса), РС.ИндексыНумерации, РС.ПропускиРегистрационныхНомеров — все найдены через search_metadata с точным перечислением полей.
2. **Справочник Нумераторы** — 17 атрибутов включая ФорматНомера, Периодичность, 9 флагов НезависимаяНумерацияПо*, тст_ДлинаЧисловогоНомера. Полная картина.
3. **Бизнес-процесс Регистрация** — найден через search_metadata_by_description с 34 атрибутами, ключевые функции Делопроизводство.ЗарегистрироватьПредмет и т.д.
4. **Код нумерации** — search_code нашёл ~60 функций: РазобратьФорматНомера, СформироватьНомерДокументаПоФормату, ПолучитьЗначенияПараметровНомера, НачалоПериодаНумерации, ОсвободитьНомер, ВременныеНомераИспользуются.
5. **Связь с ВидыДокументов** — найдены флаги ИспользоватьВременныеНомера, тст_НеобходимаРегистрация.

## Что сервер НЕ дал

1. **Значения перечислений** — ПериодичностьНумераторов (предположительно: год/квартал/месяц/день), СпособыНумерации, НазначенияНумераторов — сервер вернул имена, но не конкретные значения (нет op list_enum_values).
2. **Тело процедур** — search_code возвращает сигнатуры и описания, но не код. Невозможно увидеть конкретный алгоритм РазобратьФорматНомера или синтаксис шаблона ФорматНомера (хотя общая логика понятна по именам параметров).
3. **list_tabulars** — не поддерживается, 1 ошибочный вызов.

## Паттерны поведения агента

- **Стратегия:** сначала search_metadata для обнаружения объектов, затем drill-down по атрибутам/измерениям/ресурсам, далее search_code для функций. Классический и эффективный подход.
- **1 retry** — попытка list_attributes на общем модуле ВидДокументаНумерация (нулевой результат), затем обход через search_metadata_by_description.
- **Массивный ответ** — call #2 (search_metadata_by_description) вернул 85K символов (60% всех данных). Агент корректно обработал, сохранив во временный файл.
- **Компактность** — 25 вызовов за 6 минут, 84% полезных — хороший баланс.

## Выявленные проблемы RAG
| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| Нет значений перечислений | Периодичность, способы нумерации — только имена объектов |
| search_metadata_by_description возвращает избыток | 85K символов за один вызов (100 результатов), большинство нерелевантны |
| list_tabulars не поддерживается | Невозможно узнать табличные части объекта |
| Нет тел процедур | search_code возвращает только описание и сигнатуру |

## Вывод

Сервер 1c-metacode-test-do3 **отлично** справился с тестом на нумерацию. Структурированные запросы (list_attributes, list_dimensions, list_resources) дают точную информацию о метаданных. search_code находит релевантные функции по описанию. Сервер подходит для задач анализа структуры объектов и поиска связанных процедур. Слабое место — невозможность получить значения перечислений и тела процедур.
