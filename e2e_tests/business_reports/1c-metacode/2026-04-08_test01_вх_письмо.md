## 1. Реквизиты документа ВходящееПисьмо

Документ `Документы.ВходящееПисьмо` содержит 25 реквизитов, которые заполняются при создании:

### Основные идентификационные реквизиты
| Реквизит | Назначение |
|----------|-----------|
| Номер | Номер документа (присваивается при регистрации) |
| Дата | Дата документа в системе |
| Тема | Тема письма |
| ВнутреннийЗаголовок | Внутренний заголовок |
| Важность | Приоритет письма |

### Реквизиты отправителя и получателя
| Реквизит | Назначение |
|----------|-----------|
| ОтправительАдресат | Отправитель (внешний адресат) |
| УчетнаяЗапись | Учётная запись электронной почты |
| ИдентификаторСообщения | Идентификатор email-сообщения |
| Кодировка | Кодировка письма |
| НомерСпособаАдресации | Номер способа адресации |

### Даты и статусы
| Реквизит | Назначение |
|----------|-----------|
| ДатаОтправки | Дата отправки оригинала |
| ДатаПолучения | Дата получения |
| ЕстьВложения | Признак наличия вложений |
| УведомитьОДоставке | Уведомление о доставке |
| УведомитьОПрочтении | Уведомление о прочтении |

### Организационные реквизиты
| Реквизит | Назначение |
|----------|-----------|
| Папка | Папка хранения |
| Предмет | Предмет (ссылка на связанный документ) |
| Проект | Проект, к которому относится |
| ВидМаршрутизации | Вид маршрутизации |

### Контент письма
| Реквизит | Назначение |
|----------|-----------|
| Размер | Размер письма |
| ТекстПисьмаHTMLХранилище | HTML-текст письма |
| ТекстПисьмаПростойТекстХранилище | Текст в plain text |
| ТекстПисьмаРазмеченныйТекстХранилище | Размеченный текст |
| ТипТекста | Тип текстового содержимого |
| Комментарий | Комментарий оператора |

### Специальные функции объекта (методы модуля)
- `ПолучитьHTMLПредставлениеСодержанияПисьма()` — экспортная функция менеджера, возвращает текст в виде HTML
- `ПолучитьТекстовоеПредставлениеСодержанияПисьма()` — возвращает plain text письма
- `УстановитьСодержаниеПисьма(ТекстПисьма, ТипТекста, Кодировка)` — устанавливает текст, тип и кодировку

## 2. Бизнес-процессы по входящему письму

В конфигурации есть три основных бизнес-процесса, запускаемых по входящему письму:

### 2.1. БизнесПроцессы.Регистрация

Процесс регистрации входящего письма. Ключевые реквизиты:

| Реквизит | Назначение |
|----------|-----------|
| Исполнитель | Сотрудник, выполняющий регистрацию |
| ИсточникДанных | Источник (ссылка на ВходящееПисьмо) |
| РезультатРегистрации | Результат: зарегистрировано / отказано / перенаправлено |
| ПовторитьРегистрацию | Признак повторной регистрации |
| Шаблон | Шаблон процесса |
| Состояние | Текущее состояние процесса |
| СрокИсполнения | Срок выполнения задачи регистрации |
| ГлавнаяЗадача | Родительская задача (при вложенности) |
| Проект | Связанный проект |

Перечисление `РезультатыРегистрации` определяет возможные исходы регистрации.

### 2.2. БизнесПроцессы.Рассмотрение

Процесс рассмотрения документа руководителем. Ключевые реквизиты:

| Реквизит | Назначение |
|----------|-----------|
| ИсточникДанных | Предмет рассмотрения (ВходящееПисьмо) |
| Резолюция | Текст резолюции руководителя |
| Исполнитель | Назначенный исполнитель |
| КонтролерИсполнения | Контролёр исполнения |
| ПроверяющийИсполнения | Проверяющий |
| ОбрабатывающийРезолюцию | Обрабатывает результат рассмотрения |
| ВариантРассмотрения | Вариант: с исполнением / без / с ознакомлением |
| ВариантИсполнения | Тип исполнения |
| ПоставитьДокументНаКонтроль | Признак постановки на контроль |
| ШаблонИсполнения | Шаблон подпроцесса исполнения |
| ШаблонОзнакомления | Шаблон подпроцесса ознакомления |

**Важно:** после завершения рассмотрения автоматически может быть создан процесс Исполнения — функция `ОбработатьСозданиеПроцессаИсполненияПоРезультатамРассмотрения` в модуле `РаботаСПроцессамиПоДействиямСобытия`.

### 2.3. БизнесПроцессы.Согласование

Процесс согласования документа. Ключевые реквизиты:

| Реквизит | Назначение |
|----------|-----------|
| ИсточникДанных | Предмет согласования |
| ВариантСогласования | Вариант: параллельное / последовательное / смешанное |
| РезультатСогласования | Итог: согласовано / отклонено |
| ПовторитьСогласование | Признак повторного согласования |
| ПодписыватьЭП | Подписание электронной подписью |
| ЭтапОбработкиПредмета | Этап в рамках комплексного процесса |
| Номер | Номер версии согласования |
| КоличествоИтераций | Количество итераций |

### 2.4. БизнесПроцессы.Исполнение

| Реквизит | Назначение |
|----------|-----------|
| ИсточникДанных | Предмет исполнения |
| Контролер | Контролёр исполнения |
| Проверяющий | Проверяющий результат |
| ВариантИсполнения | Тип исполнения |
| ЭтапОбработкиПредмета | Этап обработки |

### Механизм запуска бизнес-процессов

Запуск бизнес-процессов осуществляется через:
- `ВыполнитьИнтерактивныйЗапускБизнесПроцесса(ШаблоныДляАвтоЗапуска, Предмет, ВидСобытияСтрока, ФормаДокумента, Отказ, ЗакрытьФорму)` — интерактивный запуск
- `ПолучитьШаблоныДляАвтоЗапуска(ВидИнтерактивногоБизнесСобытия, ВидДокумента, Организация, Документ)` — получение шаблонов для авто-запуска

## 3. Регистрация входящего письма — нумерация

### Регистр сведений Нумерация

Регистр `РегистрыСведений.Нумерация` обеспечивает нумерацию всех видов документов:

**Измерения (ключ записи):**
| Измерение | Назначение |
|-----------|-----------|
| ВидДокумента | Вид документа (ВходящееПисьмо) |
| Нумератор | Нумератор (правило нумерации) |
| Организация | Организация |
| Подразделение | Подразделение |
| ПериодНумерации | Период (год, квартал, месяц и т.д.) |
| ВопросДеятельности | Вопрос деятельности |
| ГрифДоступа | Гриф доступа |
| Проект | Проект |
| СвязанныйДокумент | Связанный документ |
| Тематика | Тематика |
| УзелКОД | Узел обмена данными |

**Ресурс:** `ТекущийНомер` — текущее значение счётчика

### Кто регистрирует

Регистрацию выполняет:
- Пользователь с ролью `ФункцииУчастниковРегистрации` (перечисление)
- Через бизнес-процесс `БизнесПроцессы.Регистрация` с исполнителем-регистратором
- Действия регистрации хранятся в справочнике `Справочники.ДействияРегистрации`:
  - Предмет (ссылка на ВходящееПисьмо)
  - Владелец (процесс регистрации)
  - ВидДействия
  - Создал (ответственный)
  - СрокДействия
  - ПомещеноВИсторию

### Функциональная опция
`УчитыватьВходящийНомерИДатуПолучателя` — опция, определяющая, нужно ли учитывать входящий номер и дату от отправителя.

## 4. Обработчики событий при записи

Поскольку операции `list_modules` и `get_module_text` не поддерживаются сервером, обработчики восстановлены через анализ подписок на события:

### Подписки на событие ПриЗаписи (AfterWrite)

| Процедура-обработчик | Модуль | Подписка | Назначение |
|---------------------|--------|----------|-----------|
| `ЗаписатьРеквизитыДокументов(Источник, Отказ)` | ОбщиеМодули.ДелопроизводствоСобытия | ЗаписатьРеквизитыДокументов | Записывает реквизиты всех документов делопроизводства |
| `ЗаписатьВСписокБизнесПроцессов(Источник, Отказ)` | ОбщиеМодули.БизнесПроцессыИЗадачиСобытия | ЗаписатьВСписокБизнесПроцессов | Обновляет список бизнес-процессов по предмету |

### Подписки на событие ПередЗаписью (BeforeWrite)

| Процедура-обработчик | Модуль | Назначение |
|---------------------|--------|-----------|
| `МеханизмРегистрацииОбъектовПередЗаписьюДокумента(...)` | ОбменДаннымиСобытия | Регистрация для обмена данными (синхронизация) |
| `БизнесСобытияПередЗаписьюОбъектаПередЗаписью(Источник, Отказ)` | БизнесСобытияСобытия | Обработчик бизнес-событий ПередЗаписью |
| `ОбновитьСостояниеБизнесПроцесса(Источник, Отказ)` | РаботаСБизнесПроцессамиВызовСервера | Обновление состояния связанных бизнес-процессов |
| `ЗапретитьПометкуУдаленияПредопределенныхЭлементовПередЗаписью(Источник, Отказ)` | СтандартныеПодсистемыСервер | Защита предопределённых элементов от удаления |

### Примечание

Конкретные процедуры `ПередЗаписью` и `ПриЗаписи` в модуле объекта документа `ВходящееПисьмо` недоступны для прямого просмотра через данный MCP-сервер (операции `get_module_text`/`list_modules` не реализованы). Указанные выше подписки срабатывают для всех документов делопроизводства, включая ВходящееПисьмо.

## 6. Жизненный цикл — итоговая схема

```
1. СОЗДАНИЕ письма
   - Из почтового клиента (автоматически через УчетнаяЗапись)
     или вручную через ФормаДокумента
   - Заполняются: Тема, ОтправительАдресат, ДатаПолучения, ЕстьВложения,
     ТекстПисьмаHTMLХранилище, УчетнаяЗапись
   
2. РЕГИСТРАЦИЯ
   - Запуск БП.Регистрация
   - Исполнитель-регистратор заполняет регистрационные данные
   - Присваивается Номер (через РС.Нумерация: ВидДокумента+Нумератор+Организация)
   - Создаётся запись в Справочники.ДействияРегистрации
   - Обновляется РС.ТекущиеСостоянияДокументов → состояние "Зарегистрировано"
   - Обновляется РС.ИсторияСостоянийДокументов

3. МАРШРУТИЗАЦИЯ
   - По ВидМаршрутизации определяется получатель/руководитель
   - Автозапуск БП через ПолучитьШаблоныДляАвтоЗапуска

4. РАССМОТРЕНИЕ руководителем
   - Запуск БП.Рассмотрение
   - Руководитель пишет Резолюцию
   - По результату рассмотрения автоматически создаётся БП.Исполнение
     (через ОбработатьСозданиеПроцессаИсполненияПоРезультатамРассмотрения)
   - При необходимости: ПоставитьДокументНаКонтроль = Истина

5. ИСПОЛНЕНИЕ поручения
   - Запуск БП.Исполнение
   - Исполнитель выполняет поручение
   - Контролёр проверяет результат
   - Обновляется РС.ТекущиеСостоянияДокументов

6. СОГЛАСОВАНИЕ (если требуется)
   - Запуск БП.Согласование
   - Параллельное или последовательное согласование
   - При необходимости подписание ЭП

7. ЗАВЕРШЕНИЕ
   - Документ переходит в состояние "Исполнен" / "Снят с контроля"
   - Обновляется РС.ИсторияСостоянийДокументов
   - Документ помещается в дело хранения (РС.СостоянияДелХраненияДокументов)
```

## 7. Формы документа

| Форма | Роль | По умолчанию |
|-------|------|--------------|
| ФормаДокумента | object | да |
| ФормаВыбора | picker | да |
| ФормаВыбораДляСозданияСвязи | — | нет |
| ОповещенияОНовыхПисьмах | — | нет |

### Команды из формы

- **Ответить** — создать исходящее письмо-ответ
- **ОтветитьВсем** — ответить всем адресатам
- **Переслать** — переслать письмо
