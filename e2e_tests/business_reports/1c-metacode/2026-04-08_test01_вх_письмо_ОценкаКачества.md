## Что сервер дал хорошо

1. **Структура документа ВходящееПисьмо** — полный список из 25 реквизитов через `list_attributes`, включая все 5 групп: идентификационные, отправитель/получатель, даты, организационные, контент
2. **Бизнес-процессы** — все четыре БП найдены и описаны с реквизитами:
   - Регистрация (34 реквизита): Исполнитель, РезультатРегистрации, ПовторитьРегистрацию
   - Рассмотрение (55 реквизитов): Резолюция, ВариантРассмотрения, ОбрабатывающийРезолюцию
   - Согласование (32 реквизита): ВариантСогласования, ПодписыватьЭП
   - Исполнение (30 реквизитов): Контролер, Проверяющий, ВариантИсполнения
3. **Нумерация** — регистр Нумерация: 11 измерений + ресурс ТекущийНомер — полная картина
4. **Регистры состояний** — ТекущиеСостоянияДокументов (Документ, Действие, Состояние), ИсторияСостоянийДокументов с ресурсом Состояние
5. **Подписки на события** — через search_code найдены обработчики ПриЗаписи: ЗаписатьРеквизитыДокументов, ЗаписатьВСписокБизнесПроцессов, БизнесСобытияПередЗаписьюОбъекта
6. **Формы и команды** — 4 формы (ФормаДокумента, ФормаВыбора и др.), 3 команды (Ответить, ОтветитьВсем, Переслать)
7. **search_metadata_by_description** — дала контекстный поиск связанных объектов: ДействияРегистрации, ФункцииУчастниковРегистрации, РезультатыРегистрации, ФункциональнаяОпция УчитыватьВходящийНомерИДатуПолучателя

## Что сервер НЕ дал

1. **Текст модулей объекта** — операции `get_module_text` и `list_modules` не поддерживаются сервером. Конкретный код ПередЗаписью/ПриЗаписи в модуле документа ВходящееПисьмо недоступен напрямую
2. **Табличные части** — операция `list_tabulars` не поддерживается, агент не смог получить список ТЧ документа
3. **Подписки на события** — нет прямого способа перечислить подписки для конкретного документа; поиск по категории ПодпискиНаСобытия дал 0 результатов
4. **Значения перечислений** — нет операции для получения значений перечисления (РезультатыРегистрации)
5. **search_objects** — операция не поддерживается, пришлось использовать `list_objects_by_name`

## Паттерны поведения агента

- **Стратегия "расширяющийся круг"**: начал с точного объекта (list_attributes), затем расширял поиск через search_metadata_by_description для нахождения связанных объектов
- **3 неудачных попытки** на неподдерживаемые операции (list_tabulars, list_modules, get_module_text) — быстро переключился на search_code как альтернативу
- **Большие ответы search_metadata_by_description** (92K, 69K, 76K символов) — содержат 100 результатов; полезная информация в top-10, остальное — шум
- **Повторные вызовы**: #31 — повтор list_attributes БП.Регистрация (уже было в #8); #22-23 — уточнения по ДелопроизводствоСобытия после #21
- **Эффективное использование search_code**: найдены обработчики подписок, процедуры модулей объектов, функции запуска БП

## Выявленные проблемы RAG

| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| Неподдерживаемые операции | list_tabulars, list_modules, get_module_text, search_objects — 5 из ~12 операций не работают, 4 вызова потрачены впустую |
| Перегрузка контекста | search_metadata_by_description возвращает до 100 результатов (~70-92K символов), из которых полезны 5-10 верхних |
| Отсутствие фильтрации по подпискам | Нет способа найти подписки на события конкретного документа |
| Нет значений перечислений | Невозможно получить варианты перечислений через API метаданных |

## Вывод

Сервер 1c-metacode-test-do3 **хорошо подходит** для структурного анализа объектов (реквизиты, формы, команды, измерения/ресурсы регистров) и для контекстного поиска связанных объектов через `search_metadata_by_description`. Для задач, требующих чтения конкретного кода модулей или анализа подписок на события, сервер **недостаточен** — операции get_module_text/list_modules не реализованы, что компенсируется поиском через search_code, но с потерей точности.
