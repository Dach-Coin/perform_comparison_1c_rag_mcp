## Что сервер дал хорошо

1. **7 ролей для задач** — ЧтениеЗадач, ИзменениеВыполнениеЗадач, РаботаСЗадачами, РаботаСЗадачамиИБизнесПроцессами, РаботаСЗадачамиСотрудниковПодразделения, КонтрольЗадачИБизнесПроцессов, ЧтениеПроцессовИЗадачБезОграничения — найдены через search_metadata (list_objects_by_name с category "Роли") и search_metadata_by_description.
2. **Механизм RLS** — полная цепочка: Константа ОграничиватьДоступНаУровнеЗаписей → РС.ДескрипторыДляОбъектов (4 измерения) → РС.ПраваПоДескрипторамДоступаОбъектов (Дескриптор + ОбъектОснование + Сотрудник → Чтение/Изменение/Добавление/Удаление/УправлениеПравами).
3. **РС РабочиеГруппы** — измерения (Объект, Участник), ресурсы (Изменение, Автоподстановка, Источник). Справочник РабочиеГруппы — 9 атрибутов.
4. **Модуль РаботаСРабочимиГруппами** — search_code нашёл ~30 экспортных функций: ДобавитьУчастниковВРабочуюГруппуОбъекта, ПерезаписатьРабочуюГруппуОбъекта, ПроверитьПраваУчастниковРабочейГруппыНаОбъект, РасширитьРабочуюГруппуСвязанныхОбъектов.
5. **Видимость чужих задач** — ДоступныЗадачиПодчиненных, ПодчиненныеИсполнителиЗадач, НеограниченныеПраваНаТаблицу — полный ответ на вопрос о видимости.
6. **Подписка на событие** — ПраваДоступаНаБизнесПроцессы.ПраваДоступаПриЗаписиБизнесПроцессовПриЗаписи — механизм пересчёта прав при записи.
7. **ЗадачаИсполнителя** — собственный метод ПраваСотрудниковПоОбъектам для расчёта прав на конкретные задачи.

## Что сервер НЕ дал

1. **Тексты шаблонов RLS** — конкретные SQL-подобные ограничения, накладываемые на запросы при включённом RLS. Шаблоны хранятся в РС.ПараметрыОграниченияДоступа, но их содержимое через MCP не доступно.
2. **Состав прав в ролях** — какие конкретно объекты разрешены в роли ЧтениеЗадач (Документы.Задача: Чтение? ЗадачаИсполнителя: Чтение?). Сервер возвращает имя роли, но не её содержимое.
3. **Параметры сеанса** — для RLS критичны параметры сеанса (ТекущийПользователь, ИспользуемыеГруппыДоступа и т.п.), но они не обнаружены через MCP.
4. **list_roles / list_modules / list_tabulars** — не поддерживаются, потеря 3 вызовов. Роли найдены обходным путём.

## Паттерны поведения агента

- **Стратегия:** широкий поиск (list_objects "Задача", "Доступ") → drill-down по конкретным регистрам → search_code по 5 направлениям (рабочие группы, RLS, задачи, дескрипторы, ограничения).
- **2 retry:** (a) list_roles не поддерживается → поиск через list_objects_by_name; (b) list_modules не поддерживается → search_code напрямую.
- **2 массивных ответа** — call #20 (85K) и #26 (80K) от search_metadata_by_description. Суммарно 165K из 226K — 73% всех данных за 2 вызова. Агент корректно обработал оба.
- **Неоднозначность РабочиеГруппы** — call #10 вернул ошибку (Подсистемы vs РегистрыСведений), call #11 уточнил путь. Стандартная проблема.

## Выявленные проблемы RAG
| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| search_metadata_by_description: огромные ответы | 85K + 80K символов — 73% контекста за 2 вызова |
| list_roles не поддерживается | Нет прямого доступа к списку ролей конфигурации |
| list_modules / list_tabulars не поддерживаются | 2 ошибки |
| Неоднозначность имён | РабочиеГруппы = Подсистема или РегистрСведений — требует полного пути |
| Нет содержимого ролей | Имя роли найдено, но состав прав (какие объекты, какие операции) — нет |
| Нет тел процедур | Тексты RLS-шаблонов, алгоритмы расчёта дескрипторов — только по сигнатурам |

## Вывод

Сервер **отлично** справился с глубокой темой прав доступа. Найдены все ключевые объекты (роли, регистры, модули), механизм RLS через дескрипторы раскрыт полностью по структуре. search_code дал полный API модулей РаботаСРабочимиГруппами и ДокументооборотПраваДоступа. Слабые стороны — невозможность прочитать содержимое ролей и тексты шаблонов ограничений, а также чрезмерные ответы search_metadata_by_description (до 85K символов), расходующие контекст.
