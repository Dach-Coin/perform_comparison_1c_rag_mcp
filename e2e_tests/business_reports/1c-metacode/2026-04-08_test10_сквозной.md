# Сквозной бизнес-сценарий: Обработка входящего письма с резолюцией и исполнением
**Конфигурация:** 1С:Документооборот КОРП 3.0 (DO3)  
**Дата:** 2026-04-08  
**Тест:** TEST-10 | Сервер: 1c-metacode-test-do3  

---

## Обзор сценария

Сценарий охватывает полный жизненный цикл входящего письма от контрагента:
поступление → рассмотрение руководителем → вынесение резолюции → исполнение задачи → формирование ответного письма.

---

## Шаг 1. Поступление входящего письма от контрагента

### Объект: `Документы.ВходящееПисьмо`

**Ключевые реквизиты:**

| Реквизит | Назначение |
|----------|-----------|
| ОтправительАдресат | Контрагент-отправитель |
| УчетнаяЗапись | Учётная запись эл. почты получателя |
| Тема | Тема письма |
| ДатаПолучения | Дата фактического получения |
| ДатаОтправки | Дата отправки контрагентом |
| Предмет | Связанный предмет (документ, проект) |
| Проект | Привязка к проекту |
| Папка | Папка хранения письма |
| ЕстьВложения | Признак наличия вложений |
| ВидМаршрутизации | Способ маршрутизации на рассмотрение |
| ИдентификаторСообщения | Идентификатор в почтовой системе |

**Формы объекта:**
- `ФормаДокумента` (основная форма, role=object)
- `ФормаВыбора` (role=picker, используется при связывании)
- `ФормаВыбораДляСозданияСвязи`
- `ОповещенияОНовыхПисьмах`

**Способы создания:**
1. **Автоматический** — через встроенную почту при получении письма. Модуль: `ОбщиеМодули.ВстроеннаяПочтаСервер`, функция `ДобавитьВложениеПисьмаИзИнтернетПочтовогоВложения`
2. **Ручной** — пользователь создаёт вручную. Модуль: `ОбщиеМодули.ДелопроизводствоКлиент`, процедура `ВвестиДанныеРегистрации`
3. **По входящим ЭДО** — автоматически по электронному документообороту. Модуль: `ОбщиеМодули.ОбменСКонтрагентамиДО`, процедура `ПередАвтоматическимСозданиемДокументовДОПоВходящимЭДО`

**Регистры, обновляемые при создании:**

| Регистр | Что записывается |
|---------|-----------------|
| `РегистрыСведений.ТекущиеСостоянияДокументов` (измерения: Документ, Действие, Состояние) | Текущее состояние письма |
| `РегистрыСведений.СведенияОФайлахДокументооборот` | Данные о вложениях |

**Уведомления:**  
`ОбщиеМодули.РаботаСУведомлениями` → `ДобавитьУведомленияПоВходящемуДокументу`

## Шаг 2. Рассмотрение письма руководителем. Вынесение резолюции

### Бизнес-процесс: `БизнесПроцессы.Рассмотрение`

Запуск БП осуществляется через:
- `ОбщиеМодули.ИнтерактивныйЗапускБизнесПроцессовКлиент` → `ВыполнитьИнтерактивныйЗапускБизнесПроцесса`
- `ОбщиеМодули.РаботаСБизнесПроцессамиКлиент` → `ПередСтартомБизнесПроцесса` (проверки перед стартом)

**Ключевые реквизиты БП Рассмотрение:**

| Реквизит | Назначение |
|----------|-----------|
| ИсточникДанных | Ссылка на ВходящееПисьмо |
| ГлавнаяЗадача | Задача рассматривающего (ЗадачаИсполнителя) |
| Резолюция | Текст/ссылка резолюции |
| ВариантОбработкиРезолюции | Как обрабатывать резолюцию после рассмотрения |
| ОбрабатывающийРезолюцию | Пользователь, обрабатывающий результат |
| Исполнитель | Рассматривающий сотрудник |
| ИдентификаторИсполнителя | UUID для идентификации |
| ПоставитьДокументНаКонтроль | Флаг постановки на контроль |
| СрокИсполнения / СрокИсполненияДни / Часы / Минуты | Срок исполнения резолюции |
| Шаблон | Шаблон процесса |
| ШаблонИсполнения | Шаблон дочернего БП исполнения |

**Задача рассматривающего:** `Задачи.ЗадачаИсполнителя`
- Поля: `БизнесПроцесс`, `Исполнитель`, `РольИсполнителя`, `СрокИсполнения`, `ДатаНачала`
- Статусы: `Выполнена`, `Отменена`, `ПринятаКИсполнению`

### Справочник `Справочники.Резолюции` — хранение текста резолюции

| Реквизит | Назначение |
|----------|-----------|
| Документ | Ссылка на ВходящееПисьмо |
| АвторРезолюции | Руководитель, вынесший резолюцию |
| ВнесРезолюцию | Кто фактически внёс текст |
| ТекстРезолюции | Текст резолюции |
| ДатаРезолюции | Дата вынесения |
| Источник | БизнесПроцессСсылка.Рассмотрение или ЗадачаСсылка.ЗадачаИсполнителя |
| ИдентификаторУчастника | UUID участника |
| Подписана | Признак подписания ЭП |

**Код работы с резолюциями:**
- `ОбщиеМодули.РаботаСРезолюциями` → `ПолучитьРезолюции(Документ, ТолькоАктивные, ПолучитьДанныеЭП, Источник, ИдентификаторУчастника)` — получить все резолюции по документу
- `ОбщиеМодули.РаботаСРезолюциями` → `ПроверитьДоступНаПодписание(Резолюция)` — проверить право подписания

**Регистры, обновляемые при рассмотрении:**

| Регистр | Что записывается |
|---------|-----------------|
| `РегистрыСведений.ДанныеБизнесПроцессов` (изм: БизнесПроцесс, Завершен; рес: ОсновнойПредмет, Состояние, ГлавнаяЗадача, Автор, СрокИсполнения, Стартован) | Данные запущенного БП Рассмотрение |
| `РегистрыСведений.ТекущиеСостоянияДокументов` (изм: Документ, Действие, Состояние) | Состояние письма обновляется на "На рассмотрении" |
| `РегистрыСведений.тст_СрокиИсполненияЗадач` | Срок исполнения задачи рассмотрения |

## Шаг 3. Создание задачи на исполнение по резолюции

После завершения БП Рассмотрение (руководитель выносит резолюцию и завершает задачу) автоматически запускается БП Исполнение.

**Ключевая функция перехода:**  
`ОбщиеМодули.РаботаСПроцессамиПоДействиямСобытия` → `ОбработатьСозданиеПроцессаИсполненияПоРезультатамРассмотрения(ПроцессРассмотрения: БизнесПроцессОбъект.Рассмотрение) → Булево`

Также участвует:  
`ОбщиеМодули.РаботаСПроцессамиПоДействиям` → `СоздатьПроцессыРассмотренияПоДействию(Действие, ПроцессОбработки)` — для комплексных процессов

### Бизнес-процесс: `БизнесПроцессы.Исполнение`

**Ключевые реквизиты:**

| Реквизит | Назначение |
|----------|-----------|
| ИсточникДанных | Ссылка на ВходящееПисьмо (предмет) |
| ГлавнаяЗадача | Основная задача исполнителя |
| Контролер | Контролёр исполнения |
| Проверяющий | Проверяющий результат |
| ВариантИсполнения | Вариант (единолично, параллельно и т.д.) |
| Шаблон | Шаблон процесса исполнения |
| ЭтапОбработкиПредмета | Текущий этап обработки письма |
| КоличествоИтераций | Для повторного исполнения |
| СрокИсполненияПроцесса | Общий срок |

### Документ `Документы.Задача` — внутренняя задача исполнителя

| Реквизит | Назначение |
|----------|-----------|
| ВышестоящаяЗадача | Ссылка на задачу вышестоящего уровня (от резолюции) |
| Источник | ВходящееПисьмо — источник задачи |
| СостояниеЗадачи | Текущее состояние |
| РезультатЗадачи | Результат выполнения |
| Ответственный | Ответственный исполнитель |
| Срок | Срок выполнения |
| ВидЗадачи | Вид задачи |
| Описание / ОписаниеФорматированное | Содержание поручения из резолюции |

**Заполнение задачи по БП:**  
`ОбщиеМодули.ИнтеграцияЗадач` → `ЗаполнитьЗадачуПоБизнесПроцессу(ЗадачаОбъект, БизнесПроцесс)`

**Регистры при создании задачи:**

| Регистр | Что записывается |
|---------|-----------------|
| `РегистрыСведений.ДанныеБизнесПроцессов` | Данные БП Исполнение (ОсновнойПредмет=ВходящееПисьмо) |
| `РегистрыНакопления.КоличествоЗадач` | +1 активная задача |
| `РегистрыНакопления.КоличествоДействийЗадач` | +1 действие |
| `РегистрыСведений.СведенияОбИсполнителяхЗадач` (изм: Задача, Участник) | Исполнитель задачи |
| `РегистрыСведений.тст_СрокиИсполненияЗадач` | Срок задачи исполнения |
| `РегистрыСведений.НастройкиОтложеногоСтартаПроцессов` | Если старт отложенный |

**Контроль задачи:**  
`ОбщиеМодули.Контроль` → `СоздатьКарточкуКонтроляПоПроцессу(БизнесПроцесс)` — создаёт карточку контроля по БП Исполнение

## Шаг 4. Исполнение задачи. Прикрепление файла-ответа

### Документ `Документы.ДействиеЗадачи` — отчёт об исполнении

| Реквизит | Назначение |
|----------|-----------|
| Задача | Ссылка на ЗадачаИсполнителя |
| Исполнитель | Исполнитель задачи |
| ФактическийИсполнитель | Кто фактически выполнил |
| КтоОтметил | Кто отметил выполнение |
| РезультатДействия | Результат (код перечисления) |
| РезультатДействияТекстом | Текстовый результат |
| ЕстьПриложения | Флаг наличия приложений (файл-ответ) |
| СостояниеУчастникаЗадачи | Текущее состояние участника |
| ОсобоеОписание | Дополнительный комментарий |
| ДатаВыполнения | Фактическая дата выполнения |

**Прикрепление файла к задаче — клиентский код:**  
`ОбщиеМодули.РаботаСЗадачамиКлиент` → `ДобавитьФайлКОтчету(ДействиеЗадачи, ФормаВладелец)` — добавить файл к отчёту об исполнении

**Серверный код прикрепления:**  
`ОбщиеМодули.РаботаСЗадачами` → `ДобавитьПриложения(Действие, Приложения, КтоОтметил, ВзятьВРаботуАвтоматически)`  
`ОбщиеМодули.РаботаСЗадачамиВызовСервера` → `ДобавитьПриложение(Действие, Приложение)`

**Дополнительно — прикрепление через почту:**  
`ОбщиеМодули.ВыполнениеЗадачПоПочтеСервер` → `ОбработатьВложенияВСообщении(ЗадачаСсылка, Сообщение, КтоОтметил)` — при ответе на задачу по почте прикрепляет вложения к БП как вспомогательные предметы

**Учёт трудозатрат:**  
`ОбщиеМодули.УчетВремениКлиент` → `ДобавитьВОтчетПослеВыполненияЗадачи(...)`

**Регистры при выполнении задачи:**

| Регистр | Что обновляется |
|---------|----------------|
| `РегистрыСведений.ДанныеБизнесПроцессов` | Состояние БП → "Завершён" (или следующий шаг) |
| `РегистрыНакопления.КоличествоЗадач` | -1 активная задача |
| `РегистрыНакопления.КоличествоДействийЗадач` | Обновление действий |
| `РегистрыСведений.ТекущиеСостоянияДокументов` | Состояние ВходящегоПисьма → "Исполнено" |

## Шаг 5. Формирование ИсходящегоПисьма с ответом

### Объект: `Документы.ИсходящееПисьмо`

**Ключевые реквизиты:**

| Реквизит | Назначение |
|----------|-----------|
| ПисьмоОснование | **Ссылка на входящее письмо-основание** (ключевая связь) |
| Автор | Автор ответа |
| ТипОтвета | Тип ответа (ответ, пересылка и т.д.) |
| ОтправительКонтакт | Отправитель |
| ПодготовленоКОтправке | Флаг готовности к отправке |
| ОтправкаОтменена | Флаг отмены отправки |
| ПолучателиПисьмаСтрокой | Получатели |
| Тема | Тема ответного письма |
| УчетнаяЗапись | Учётная запись для отправки |
| Предмет | Предмет письма |
| Проект | Проект |

**Создание ИсходящегоПисьма на основании входящего:**  
`ОбщиеМодули.ВстроеннаяПочтаКлиент` → `СоздатьПисьмоНаОсновании(Ссылка: ДокументСсылка.ВходящееПисьмо)` — открывает форму нового ИсходящегоПисьма с заполненным ПисьмоОснование

**Формирование текста ответного письма:**  
`ОбщиеМодули.ВстроеннаяПочтаСервер` → `СформироватьТекстИсходящегоПисьма(Основание, ТипТекста, Кодировка, ТипОтвета)` — формирует HTML/текст письма из шаблона

**Установка содержания:**  
`Документы.ИсходящееПисьмо` (ObjectModule) → `УстановитьСодержаниеПисьма(Текст, ТипТекстаПисьма, КодировкаПисьма)`

**Отправка через помощник "Отправить":**  
`ОбщиеМодули.ПомощникОтправитьКлиент` → `ОтправитьПоВариантуСоздатьПисьмоНаОсновании(Параметры)` — для создания и отправки из формы

**Финальная отправка:**  
`ОбщиеМодули.РаботаСПочтовымиСообщениями` → `ПодготовитьПисьмо(УчетнаяЗапись, ПараметрыПисьма)` — формирует `ИнтернетПочтовоеСообщение` для отправки

**Уведомления после отправки:**  
`ОбщиеМодули.РаботаСУведомлениями` → `ДобавитьУведомленияПоИсходящемуДокументу(ПроизошедшееСобытие, ИсходящийДокумент, ВидСобытия, Объект)`

**Регистры при создании ИсходящегоПисьма:**

| Регистр | Что записывается |
|---------|-----------------|
| `РегистрыСведений.ТекущиеСостоянияДокументов` | Состояние ВходящегоПисьма → "Отвечено" (при необходимости) |
| `РегистрыСведений.ИдентификаторыИмпортированныхПисем` | Идентификатор основания (связь письма-ответа с входящим) |
| `РегистрыСведений.ДанныеБизнесПроцессов` | Если письмо связано с БП — обновление предметов |

## Итоговая схема сквозного сценария

```
[Входящее письмо] ──→ [БП Рассмотрение] ──→ [Справочник.Резолюции]
     ↑                      |
     |                      ↓
     |         [ОбработатьСоздание..ПоРезультатамРассмотрения]
     |                      |
     |                      ↓
     |              [БП Исполнение] ──→ [Задачи.ЗадачаИсполнителя]
     |                      |                      |
     |                      |                      ↓
     |                      |         [Документы.ДействиеЗадачи]
     |                      |         [Файл-ответ прикреплён]
     |                      |
     └──────────────────────↓
               [ИсходящееПисьмо.ПисьмоОснование = ВходящееПисьмо]
```
