## Что сервер НЕ дал

1. **Значения перечисления РезультатыСогласования** — нет операции для извлечения значений перечисления; Согласовано/НеСогласовано/Прервано выведены из контекста кода
2. **Текст модулей** — get_module_text/list_modules не поддерживаются, точный код процедур недоступен; приходится реконструировать из описаний search_code
3. **Тип данных ВариантСогласования** — не удалось определить точный тип (предположительно не перечисление, а ссылка); перечисление ВариантыСогласования не найдено
4. **Точки маршрута БП** — нет инструмента для перечисления точек маршрута (ТочкиМаршрутаБизнесПроцесса)

## Паттерны поведения агента

- **Целенаправленный подход**: агент начал с поиска по описанию, затем точечно запрашивал атрибуты найденных объектов — более экономная стратегия чем в TEST-01
- **Быстрое обучение**: после 3 неудачных вызовов (list_tabulars, list_modules, get_module_text) агент больше не пробовал эти операции, сразу использовал search_code
- **Успешное использование list_tabular_attributes**: агент нашёл рабочую операцию для получения реквизитов ТЧ (в отличие от list_tabulars), что дало ключевые данные о ТЧ Исполнители
- **Эффективный search_code**: 6 вызовов search_code дали высокорелевантные результаты — API модулей, цепочку завершения, функции экспорта
- **Один retry** (#14→15): поиск перечисления ВариантыСогласования через search_objects (unsupported) → list_objects_by_name (не найдено)

## Выявленные проблемы RAG

| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| Неподдерживаемые операции | list_tabulars, list_modules, get_module_text — 3 вызова потрачены впустую |
| Перегрузка контекста | search_metadata_by_description #7 (69K) и #20 (165K) — суммарно 234K символов из 309K (76% контекста) |
| Нет значений перечислений | Ключевые значения РезультатыСогласования приходится выводить из кода |
| Нет точек маршрута | Невозможно получить структуру маршрутной карты БП |

## Вывод

Сервер 1c-metacode-test-do3 показал **отличные результаты** на задаче анализа бизнес-процесса Согласование. Особенно ценна работающая операция `list_tabular_attributes` (недоступная в виде list_tabulars, но доступная при точном указании имени ТЧ). Комбинация `search_metadata_by_description` + `list_attributes` + `search_code` позволила восстановить полную картину: структуру данных, API модулей и цепочку обработки завершения. Слабое место — отсутствие get_module_text, из-за чего точный код обработчиков приходится реконструировать по описаниям процедур.
