# TEST-07: Электронные подписи и подписание документов
**Конфигурация:** 1С:Документооборот КОРП 3.0 (DO3)  
**Сервер:** 1c-metacode-test-do3  
**Дата:** 2026-04-08  
**Вопрос:** Как реализован бизнес-процесс Подписание?

---

## 1. Бизнес-процесс "Подписание"

### Объект метаданных
`БизнесПроцессы.Подписание` — самостоятельный бизнес-процесс конфигурации.

### Атрибуты бизнес-процесса

| Атрибут | Назначение |
|---------|------------|
| СпособПодписания | Определяет тип/способ подписания (ЭП или на бумаге) |
| РезультатПодписания | Итоговый результат выполнения процесса |
| ПорядокВыполненияУчастниками | Последовательный или параллельный порядок |
| КоличествоИтераций | Количество итераций (для повторного подписания) |
| НомерИтерации | Текущий номер итерации |
| ИсточникДанных | Откуда заполнен процесс |
| Шаблон | Шаблон, по которому создан процесс |
| Автор | Инициатор процесса |
| Важность | Приоритет |
| ГлавнаяЗадача | Задача процесса |
| Состояние | Текущее состояние БП |
| Проект / ПроектнаяЗадача | Связь с проектом |
| СрокИсполненияПроцесса | Контрольный срок |
| ПричинаПрерывания | При аварийном завершении |
| Описание | Текстовое описание процесса |

### Табличная часть "Участники"

| Атрибут | Назначение |
|---------|------------|
| Подписывающий | Кто должен подписать |
| Участник | Пользователь-участник |
| Этап | Этап маршрута |
| ТочкаМаршрута | Точка маршрута подписания |
| Пройден | Признак выполнения |
| Идентификатор | Уникальный идентификатор участника |
| СрокИсполнения | Срок подписания |
| ВариантУстановкиСрокаИсполнения | Относительный/абсолютный срок |
| Условие | Условие выполнения для участника |

### Формы бизнес-процесса
- **ФормаБизнесПроцесса** — основная карточка (по умолчанию)
- **ФормаИзменениеПараметров** — изменение параметров запущенного процесса
- **ФормаИсторияПодписания** — история прохождения

## 2. Параметры, задаваемые при запуске

При запуске бизнес-процесса Подписание задаются следующие параметры:

### Обязательные параметры
- **Предмет** — документ или объект, который нужно подписать
- **СпособПодписания** — ЭП (электронная подпись) или на бумаге
- **Участники** — список подписывающих с их ролями и точками маршрута

### Параметры маршрутизации
- **ПорядокВыполненияУчастниками** — последовательно/параллельно/смешанный
- **КоличествоИтераций** — сколько кругов подписания
- **СрокИсполненияПроцесса** — общий срок

### Шаблон подписания
Процесс может быть запущен **по шаблону** (`ЗаполнитьПоШаблону` в ObjectModule), что автоматически заполняет участников, порядок и способ подписания.

Шаблоны хранятся в `Справочники.ШаблоныПодписания`, который содержит:
- Владелец/ВладелецШаблона
- СпособПодписания
- ПорядокВыполненияУчастниками
- ТЧ Участники с условиями (атрибут Условие)

### Интерактивный запуск
Модуль `ОбщиеМодули.ИнтерактивныйЗапускБизнесПроцессовКлиент` содержит процедуру `ВыполнитьИнтерактивныйЗапускБизнесПроцесса(ШаблоныДляАвтоЗапуска, Предмет, ВидСобытияСтрока, ФормаДокумента, Отказ, ЗакрытьФорму)` — это точка входа для запуска из формы документа.

## 3. Поддержка электронной подписи (ЭП/ЭЦП)

### Поддерживается полностью. Два вида ЭП:

#### 3.1. Внутренняя ЭП (на файлах конфигурации)
Реализована через штатную подсистему БСП "Электронная подпись":
- `ОбщиеМодули.РаботаСФайламиКлиент.ПодписатьФайл(...)` — подписывает файл через подсистему
- `ОбщиеМодули.РаботаСФайлами.ДобавитьПодписьКФайлу(...)` — добавляет ЭП к присоединённому файлу
- Поддерживаемые типы: **CMS** (присоединённая/отсоединённая) и **GOST3410**

#### 3.2. Внешнее подписание (КЭП-сервисы)
Через внешние сервисы подписания (например, 1С-ЭДО, МЭДО):
- Модули: `РаботаСВнешнимПодписанием`, `РаботаСВнешнимПодписаниемВызовСервера`, `РаботаСВнешнимПодписаниемКлиент`
- Документ `СведенияОВнешнемПодписании` — хранит данные о каждом внешнем подписании (ПредметПодписания, Действие, Участник, Сервис, ФизическоеЛицо, Результат)
- Очередь: `ОчередьОбработкиРезультатовВнешнегоПодписания`

#### 3.3. Сертификаты ЭП
Хранятся в `Справочники.СертификатыКлючейЭлектроннойПодписиИШифрования`:
- Отпечаток, КомуВыдан, КемВыдан, ДействителенДо
- Флаги: **Подписание** (Булево), **Шифрование** (Булево), **Отозван** (Булево)
- Связи: Пользователь, ФизическоеЛицо, Организация
- Программа криптографии: `Справочники.ПрограммыЭлектроннойПодписиИШифрования`

| Отпечаток | Отпечаток сертификата |

| СертификатДействителен | Булево — действителен ли сертификат |
| ДатаПроверкиПодписи | Дата последней проверки |
| ТребуетсяПроверка | Булево — нужна ли повторная проверка |
| ТекстОшибкиПроверкиПодписи | Описание ошибки проверки |
| ТекстОшибкиПроверкиСертификата | Описание ошибки сертификата |
| СрокДействияПоследнейМеткиВремени | Срок метки времени |
| ИмяФайлаПодписи | Имя файла подписи |

| Объект | Назначение |
|--------|-----------|

| `РегистрыСведений.ТекущиеСостоянияДокументов` | Текущее состояние документа (Документ, Действие, Состояние) |

## 5. Изменение статуса документа после подписания

### Результат процесса
По завершении БП Подписание:
1. Вызывается `ЗаполнитьИтоговыйРезультатПодписания()` (ObjectModule БП Подписание) — заполняет атрибут `РезультатПодписания`
2. Статус документа определяется через `Perечисления.РезультатыПодписания` — функция `НайтиПоРезультатуСогласования` показывает, что результат аналогичен согласованию

### Получение статуса подписи документа
Функция `РезультатПодписанияДокумента(Ссылка)` в `ОбщиеМодули.тст_ДокументыПредприятия` возвращает строку:
- **"Подписан"** — все требуемые подписи получены
- **"НеПодписан"** — подписи отсутствуют или процесс не завершён
- **"Аннулирован"** — подписи аннулированы

### Механизм смены статуса
- `ОбновитьСтатусПроверкиПодписиВРегистре` (РаботаСЭП) — обновляет РС ЭлектронныеПодписи
- `УстановитьСтатусПроверкиДляДокумента(Документ)` (РаботаСЭП) — кеш общего статуса ЭП, учитывает подписи всех подчинённых файлов
- `РегистрыСведений.ТекущиеСостоянияДокументов` — фиксирует смену состояния документа при подписании

## 6. Общие модули с логикой работы с подписями

### Основные модули (серверная/клиент-серверная логика)

| Модуль | Назначение |
|--------|-----------|
| **РаботаСЭП** | Центральный модуль работы с ЭП: запись/чтение/проверка из РС ЭлектронныеПодписи. Функции: ЗаписатьЭПФайлу, НовыйКлючРегистраЭлектронныхПодписей, ЗанестиДанныеСертификатаПодписи, ОбновитьСтатусыПроверкиПодписейВРегистре, УстановитьСтатусПроверкиДляДокумента |
| **РаботаСЭПКлиентСервер** | Клиент-серверные структуры данных для работы с ЭП: НовыеДанныеДляПолученияСтатусаПодписи, НовыеДанныеПодписиДляПроверки |
| **РаботаСФайлами** | Серверная: ДобавитьПодписьКФайлу — добавляет ЭП к присоединённому файлу |
| **МаршрутыПодписанияБЭД** | Маршруты подписания для ЭДО: СформироватьМаршрутПодписанияЭД, ПредставлениеПрогрессаПодписания |
| **МаршрутыПодписанияБЭДКлиентСервер** | Клиент-серверная часть маршрутов подписания ЭДО |
| **МаршрутыПодписанияБЭДСлужебный** | Служебные функции маршрутизации ЭП |
| **РаботаСВнешнимПодписанием** | Интеграция с внешними сервисами ЭП: ПоставитьВОчередьРезультатПодписания, РезультатыВнешнегоПодписанияКОбработке |
| **РаботаСВнешнимПодписаниемВызовСервера** | Серверные вызовы для внешнего подписания |

### Клиентские модули

| Модуль | Назначение |
|--------|-----------|
| **РаботаСФайламиКлиент** | ПодписатьФайл — интерактивное подписание на клиенте через подсистему "Электронная подпись" |
| **МаршрутыПодписанияБЭДКлиент** | Клиентские функции маршрутов |
| **РаботаСВнешнимПодписаниемКлиент** | Клиентские функции внешнего подписания |
| **ИнтерактивныйЗапускБизнесПроцессовКлиент** | ВыполнитьИнтерактивныйЗапускБизнесПроцесса — запуск БП Подписание из UI |

### Криптографические модули (БСП)

| Модуль | Назначение |
|--------|-----------|
| **СервисКриптографии** | Подписать(Данные, Подписант, ТипПодписи="CMS", ...) — серверное подписание |
| **СервисКриптографииКлиент** | Подписать — асинхронное клиентское подписание |
| **ЭлектроннаяПодписьСлужебныйКлиент** | УстановитьСертификат, СохранитьСертификат, УстановитьКорневойСертификат |

## 7. Схема взаимодействия

```
Пользователь → ФормаДокумента
      ↓
ВыполнитьИнтерактивныйЗапускБизнесПроцесса
      ↓
БизнесПроцессы.Подписание (создание по шаблону)
  ├── ЗаполнитьПоШаблону(ШаблонБизнесПроцесса)
  ├── ТЧ Участники (Подписывающий, ТочкаМаршрута, Срок)
  └── Запуск задач подписывающим
            ↓
Задача.Подписание (исполнителю)
      ↓
РаботаСФайламиКлиент.ПодписатьФайл(...)
  или РаботаСВнешнимПодписаниемКлиент
      ↓
СервисКриптографии.Подписать(Данные, Сертификат, ТипПодписи="CMS")
      ↓
РаботаСФайлами.ДобавитьПодписьКФайлу(...)
      ↓
РаботаСЭП.ЗаписатьЭПФайлу → РС.ЭлектронныеПодписи
      ↓
РаботаСЭП.УстановитьСтатусПроверкиДляДокумента
      ↓
БП.ЗаполнитьИтоговыйРезультатПодписания()
      ↓
тст_ДокументыПредприятия.РезультатПодписанияДокумента
  → "Подписан" / "НеПодписан" / "Аннулирован"
```

## 8. Краткие ответы на вопросы теста

| Вопрос | Ответ |
|--------|-------|
| **Параметры при запуске** | Предмет, СпособПодписания, Участники (с ТочкамиМаршрута и Сроками), ПорядокВыполнения, КоличествоИтераций, Шаблон |
| **Поддержка ЭП/ЭЦП** | Да, полная. Типы: CMS (отсоединённая/присоединённая) и GOST3410. Также внешнее подписание через КЭП-сервисы |
| **Хранение данных о подписях** | **РегистрСведений.ЭлектронныеПодписи** (измерения: ПодписанныйОбъект+ПорядковыйНомер; 17 ресурсов включая Подпись, Сертификат, ТипПодписи, ПодписьВерна) |
| **Смена статуса после подписания** | Да. Функция `РезультатПодписанияДокумента` → "Подписан"/"НеПодписан"/"Аннулирован". Обновляется через `ОбновитьСтатусПроверкиПодписиВРегистре` |
| **Общие модули с логикой ЭП** | РаботаСЭП, МаршрутыПодписанияБЭД, РаботаСВнешнимПодписанием, РаботаСФайлами/Клиент, СервисКриптографии/Клиент, ЭлектроннаяПодписьСлужебныйКлиент |
