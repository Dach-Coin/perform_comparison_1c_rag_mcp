## Что сервер дал хорошо

- **Полный реестр подсистемы МЭДО** — 50 объектов через list_objects_by_name, включая все категории (документы, модули, регистры, перечисления, константы)
- **Структура всех 3 документов** — УведомлениеМЭДО (18 реквизитов), ДанныеДокументаМЭДО (19 реквизитов), КвитанцияМЭДО (15 реквизитов) — полный набор через list_attributes
- **8 общих модулей** с точными именами и назначением: МЭДО, МЭДОВызовСервера, МЭДОДокументооборот, МЭДОКлиент, МЭДОКлиентПереопределяемый, МЭДОПереопределяемый, МЭДОПовтИсп, МЭДОСтруктурыДанных
- **Процедуры отправки и получения** через search_code — полная цепочка: ВыполнитьОбменМЭДО → ИсходящиеДокументыКОтправке → ОтправитьИсходящиеДокументы, ОбработатьВходящееЭСД, ВходящиеДокументыКОбработке. С сигнатурами и описаниями параметров
- **Регламентное задание** ВыполнениеОбменаМЭДО — найдено точно
- **Отсутствие HTTP/веб-сервисов** — корректно подтверждено пустыми результатами в обеих категориях
- **4 регистра сведений** с подробными ресурсами НастройкиОрганизацийМЭДО (20 ресурсов: каталоги, FTP, способ обмена)
- **3 справочника** подсистемы
- **Семантический поиск** (search_metadata_by_description) вернул точные описания трёх документов МЭДО с комментариями из конфигуратора

## Что сервер НЕ дал

- **Табличные части документов** — операция list_tabulars не поддерживается сервером. Агент обошёл это через анализ структур данных МЭДОСтруктурыДанных, но прямое получение ТЧ невозможно
- **Список модулей объектов** — операция list_modules не поддерживается. Код модулей приходилось искать через search_code
- **Ресурсы НастройкиКонтрагентовМЭДО** — агент вызвал list_attributes (0 результатов), но не дополнил вызовом list_resources / list_dimensions для этого регистра

## Паттерны поведения агента

- **Стратегия «сверху вниз»**: начал с полного обзора (list_objects_by_name МЭДО → 50 объектов), затем углубился в каждую категорию
- **Комбинирование инструментов**: search_metadata для структуры + search_code для процедур — эффективный подход
- **Быстрая адаптация к ошибкам**: после 4 неудачных вызовов (list_tabulars ×3, list_modules ×1) переключился на альтернативные подходы, не застрял в retry-цикле
- **Целенаправленное использование категорий**: отдельные запросы по Документы, ОбщиеМодули, РегламентныеЗадания, HTTPСервисы, ВебСервисы, РегистрыСведений, Справочники — систематический обход
- **Шумные вызовы**: 4 из 7 — это попытки вызвать неподдерживаемые операции (ожидаемо), 2 — пустые результаты для HTTP/веб-сервисов (нужны для полноты ответа), 1 — низкая релевантность. Доля реального шума минимальна

## Выявленные проблемы RAG

| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| Отсутствие операции list_tabulars | Невозможно получить табличные части документов — ключевая метаинформация о структуре |
| Отсутствие операции list_modules | Невозможно получить список модулей объекта — приходится искать код через search_code |
| Большой объём search_metadata_by_description | Ответ ~4800 символов на 8 результатов — приемлемо, но при масштабировании может быть избыточно |

## Вывод

Сервер 1c-metacode-test-do3 **отлично справился** с анализом подсистемы МЭДО. Шаблонный API (list_objects_by_name с фильтром по категории) позволил быстро и точно получить полный реестр объектов. search_code нашёл все ключевые процедуры с описаниями. Единственные существенные ограничения — отсутствие операций list_tabulars и list_modules, что вынуждает искать эту информацию обходными путями. Для задач анализа подсистем и бизнес-процессов сервер подходит хорошо.
