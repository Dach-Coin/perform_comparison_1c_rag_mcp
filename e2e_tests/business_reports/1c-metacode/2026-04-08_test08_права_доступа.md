## 1. Какие роли определяют доступ к документу Задача

В конфигурации DO3 (ДокументооборотКОРП) выявлены **7 ролей**, непосредственно связанных с задачами:

| Роль | Синоним | Назначение |
|------|---------|-----------|
| `ЧтениеЗадач` | Чтение задач | Базовое право чтения объектов-задач |
| `ИзменениеВыполнениеЗадач` | Изменение и выполнение задач | Право изменять задачи и отмечать выполнение |
| `РаботаСЗадачами` | Работа с задачами | Стандартная роль для работы с задачами |
| `РаботаСЗадачамиИБизнесПроцессами` | Работа с задачами и бизнес-процессами | Расширенная роль, включает бизнес-процессы |
| `РаботаСЗадачамиСотрудниковПодразделения` | Работа с задачами сотрудников подразделения | Доступ к задачам сотрудников своего подразделения |
| `КонтрольЗадачИБизнесПроцессов` | Контроль задач и бизнес-процессов | Надзорный доступ (контроль за ходом) |
| `ЧтениеПроцессовИЗадачБезОграничения` | Чтение процессов и задач без ограничения | **Неограниченный** доступ на чтение всех задач |

Дополнительно существуют роли системы доступа:
- `БазовыеПраваДокументооборот` — базовые права любого пользователя
- `ИзменениеУчастниковГруппДоступа` — управление составом групп доступа
- `ПолныеПрава` — полный доступ администратора

## 2. Может ли сотрудник видеть задачи других сотрудников

**По умолчанию — нет.** Видимость задач строго ограничена. Варианты расширения доступа:

### 2.1 Механизм "Задачи подчиненных"
Руководитель может видеть задачи своих прямых подчиненных. Реализовано через:
- `ОбщиеМодули.РаботаСЗадачами` → функция `ДоступныЗадачиПодчиненных(Пользователь)`
- `ОбщиеМодули.РаботаСЗадачамиПовтИсп` → кэшированная версия `ДоступныЗадачиПодчиненных()`
- `ОбщиеМодули.РаботаСЗадачами` → функция `ПодчиненныеИсполнителиЗадач(Руководитель, ТолькоДействующие, ВключаяЗамещаемых)`

Роль `РаботаСЗадачамиСотрудниковПодразделения` дает доступ к задачам сотрудников своего подразделения.

### 2.2 Механизм "Без ограничения"
Роль `ЧтениеПроцессовИЗадачБезОграничения` позволяет видеть **все** задачи без ограничений (для администраторов, контролеров).

Аналогичную проверку выполняет функция:
- `ОбщиеМодули.ДокументооборотПраваДоступа` → `НеограниченныеПраваНаТаблицу(Таблица, Пользователь)` — возвращает права пользователя **не ограниченные RLS**

### 2.3 Делегирование
Через механизм замещения: функция `ИсполнителиЗадач(МассивПользователейИСотрудников, ВключаяЗамещаемых, ВключаяПереданных)` в `ОбщиеМодули.РаботаСЗадачами` — возвращает задачи, которые направляются пользователю с учетом ролевой адресации и делегирования.

## 3. Есть ли ограничение на уровне записей (RLS) для задач

**Да, RLS реализован.** В конфигурации DO3 используется механизм ограничения доступа на уровне записей через систему **дескрипторов доступа**. Это собственная реализация поверх стандартного механизма БСП.

### 3.1 Ключевые объекты RLS-механизма

| Объект | Тип | Роль в механизме |
|--------|-----|-----------------|
| `Константы.ОграничиватьДоступНаУровнеЗаписей` | Константа-Булево | Глобальный переключатель RLS |
| `Константы.ДокументооборотИспользоватьОграничениеПравДоступа` | Константа | Переключатель собственных прав ДО |
| `РегистрыСведений.ПараметрыОграниченияДоступа` | РС | Хранит шаблоны ограничений: ДляЗаписиОбъектов, ДляОтчета, ДляШаблоновВСеансах |
| `РегистрыСведений.ДескрипторыДляОбъектов` | РС | Связь: Дескриптор ↔ Объект ↔ ОбъектМетаданных ↔ ТипДескриптора |
| `РегистрыСведений.ПраваПоДескрипторамДоступаОбъектов` | РС | Права: Дескриптор + ОбъектОснование + Сотрудник → Чтение/Изменение/Добавление/Удаление/УправлениеПравами |
| `Справочники.ДескрипторыДоступаОбъектов` | Справочник | Хранилище дескрипторов (индивидуальных и групповых) |
| `РегистрыСведений.РазрешенияДляРазрезовДоступа` | РС | Разрешения по разрезам доступа |

### 3.2 Принцип работы RLS

1. **При включенном** `ОграничиватьДоступНаУровнеЗаписей` платформа накладывает условия на запросы
2. Для каждого объекта (задачи) создается **дескриптор доступа** — `ДескрипторыДляОбъектов`
3. Права сотрудников на объекты хранятся в **РС ПраваПоДескрипторамДоступаОбъектов** (измерения: Дескриптор, ОбъектОснование = ссылка на задачу, Сотрудник; ресурсы: Чтение, Изменение, Добавление, Удаление, УправлениеПравами)
4. Проверка прав выполняется через `ОбщиеМодули.ДокументооборотПраваДоступа`:
   - `ОпределитьДескрипторыОбъекта(ОбъектДоступа)` — определяет и записывает дескрипторы
   - `НеограниченныеПраваНаТаблицу(Таблица)` — права без RLS (для ролей "без ограничения")
   - `ПраваСотрудниковПоОбъектам(ОбъектыДоступа, УчитыватьНеограниченные)` — итоговые права

Для **Задачи.ЗадачаИсполнителя** есть собственный метод:
```
Функция ПраваСотрудниковПоОбъектам(ОбъектыДоступа, СотрудникиОтбор) Экспорт
// Возвращает: ОбъектДоступа, Сотрудник, Чтение, Изменение, Добавление, Удаление, УправлениеПравами, Пользователь
```

## 4. Как связаны рабочие группы с доступом к документам

**Рабочая группа** — это набор участников (сотрудников, ролей, рабочих групп), которым предоставляется доступ к конкретному объекту (документу, задаче). Связь двунаправленная:

### 4.1 Структура данных

**РС РабочиеГруппы** (бесконтекстный):
- Измерения: `Объект` (ссылка на документ/задачу), `Участник` (сотрудник/роль/рабочая группа)
- Ресурсы: `Изменение` (Булево — право изменения), `Автоподстановка`, `Источник`

**Справочник РабочиеГруппы** — именованные группы с полями: Наименование, Ответственный, Недействительна, Автозаполнение.

### 4.2 Ключевые функции связывания (ОбщиеМодули.РаботаСРабочимиГруппами)

| Функция | Назначение |
|---------|-----------|
| `ДобавитьУчастниковВРабочуюГруппуОбъекта(Объект, Участники, ОбновитьПрава, ПроверятьПрава)` | Добавить участников + опционально пересчитать права |
| `ПерезаписатьРабочуюГруппуОбъекта(Ссылка, Участники, ОбновитьПрава, ПроверятьПрава, АвторИзменений)` | Полная перезапись состава группы |
| `РасширитьРабочуюГруппуСвязанныхОбъектов(Объект, Немедленно)` | Расширяет группы связанных объектов (предметов процессов) |
| `ПроверитьПраваУчастниковРабочейГруппыНаОбъект(СсылкаИлиДокументОбъект, Участники)` | Проверка прав по грифам, группам доступа, организациям |
| `ОтметитьНачалоВыполненияДействия(Действие, Параметры)` | При старте действия расширяет РГ предмета участниками |

### 4.3 Алгоритм расчёта прав с учётом рабочих групп

При записи объекта (документа, задачи) вызывается подписка на событие через `ОбщиеМодули.ПраваДоступаНаБизнесПроцессы`:
- `ПраваДоступаПриЗаписиБизнесПроцессовПриЗаписи(Источник, Отказ)` — обработчик подписки
- `ПолучитьТаблицуУчастниковПроцесса(БизнесПроцессОбъект)` — возвращает всех участников (новых и старых) с признаками наличия в версиях

Метод `ЗапросДляСтандартногоРасчетаПрав` (Справочники.ДескрипторыДоступаОбъектов) строит запрос с учетом:
- Ограничений по группам доступа
- Рабочих групп
- Прав папок

## 5. Какой общий модуль отвечает за проверку прав (РаботаСРабочимиГруппами)

### 5.1 ОбщиеМодули.РаботаСРабочимиГруппами

Это **центральный модуль** управления рабочими группами. Ключевые экспортные функции:

**Управление составом:**
- `ДобавитьУчастниковВРабочуюГруппуОбъекта` — добавить с пересчётом прав
- `ПерезаписатьРабочуюГруппуОбъекта` — полная замена состава
- `ДобавитьУчастниковВРабочуюГруппуДокументаИзИсточника` — копирование из другого документа
- `ПерезаполнитьРабочуюГруппуДокумента` — перезаполнение (для регламентных заданий)
- `ОбновитьУчастниковРабочейГруппыПоАвтоподстановкам` — автозаполнение по настройкам

**Расширение для процессов:**
- `РасширитьРабочуюГруппуСвязанныхОбъектов(Объект)` — при старте процесса распространяет доступ на предметы
- `РасширитьРабочуюГруппуПредметов(ВсеПредметы, ДобавленныеУчастники, ПравоИзменения, Источник)`
- `ПерезаписатьРабочиеГруппыПредметовБизнесПроцесса` — для всех предметов процесса
- `ОтметитьНачалоВыполненияДействия(Действие, Параметры)` — при начале действия

**Проверка прав:**
- `ПроверитьПраваУчастниковРабочейГруппыНаОбъект(СсылкаИлиДокументОбъект, Участники)` — проверяет права новых участников (грифы, группы доступа, организации)
- `ПроверитьПраваПередЗаписьюРабочейГруппы` — проверка текущего пользователя перед изменением состава

**Форма/UI:**
- `ФормаДокументаДобавитьУчастников(Форма, РабочаяГруппаТаблица)`
- `ДокументУстановитьУсловноеОформлениеСпискаРабочейГруппы(Форма)`
- `ПриСозданииНаСервере(Форма)`, `ПриЧтенииНаСервере(Форма)`, `ДокументПриКопировании(Форма)`

**Вспомогательные:**
- `ПолучитьПустуюТаблицуУчастников()` — создание пустой структуры
- `УчастникиРабочейГруппыПоАлгоритму(Алгоритм)` — автозаполнение через алгоритм
- `ОбновлениеАвтозаполняемыхРабочихГрупп()` — регламентное задание

### 5.2 ОбщиеМодули.ДокументооборотПраваДоступа

Основной модуль **расчёта прав** (не рабочих групп, а итоговых прав):
- `ОпределитьДескрипторыОбъекта` — расчёт и запись дескрипторов
- `НеограниченныеПраваНаТаблицу` — права без RLS
- `ПраваСотрудниковПоОбъектам` — итоговые права по объектам
- `ОбновитьПраваВсехДанных`, `РассчитатьПраваОбъектовТаблицы` — массовый пересчёт

### 5.3 ОбщиеМодули.РаботаСЗадачами

Модуль бизнес-логики задач, включая контроль видимости:
- `ДоступныЗадачиПодчиненных(Пользователь)` — доступны ли задачи подчиненных
- `ПодчиненныеИсполнителиЗадач(Руководитель, ТолькоДействующие, ВключаяЗамещаемых)` — список подчинённых исполнителей
- `ЕстьВсеПраваНаДействие(ВыделенноеДействие)` — проверка прав на конкретное действие задачи
- `ЗадачиМнеВсе(Пользователь)` — все задачи конкретного пользователя
- `ЭтоТекущийИсполнитель(Участник)` — является ли текущий пользователь исполнителем

## Итоговая схема (краткая)

```
Задача/ЗадачаИсполнителя
     │
     ├─ Роли (настраиваются в профилях групп доступа)
     │   ├─ ЧтениеЗадач — базовое чтение
     │   ├─ ИзменениеВыполнениеЗадач — изменение + выполнение
     │   ├─ РаботаСЗадачамиСотрудниковПодразделения — задачи отдела
     │   └─ ЧтениеПроцессовИЗадачБезОграничения — все задачи (контролёры)
     │
     ├─ RLS (Ограничение на уровне записей, если включено)
     │   ├─ РС ДескрипторыДляОбъектов (Объект=задача → Дескриптор)
     │   └─ РС ПраваПоДескрипторамДоступаОбъектов (Дескриптор+Сотрудник → CRUD-права)
     │
     └─ Рабочие группы
         ├─ РС РабочиеГруппы (Объект=задача, Участник=сотрудник/роль, Изменение=булево)
         ├─ При записи: ПраваДоступаНаБизнесПроцессы.ПраваДоступаПриЗаписиБизнесПроцессовПриЗаписи
         └─ Пересчёт: ДокументооборотПраваДоступа.ОпределитьДескрипторыОбъекта
```

## Ключевые выводы

1. **Доступ к задаче по умолчанию** — только свои задачи (где пользователь является исполнителем)
2. **Руководитель** видит задачи подчинённых через механизм иерархии (функция `ДоступныЗадачиПодчиненных`)
3. **Рабочие группы** открывают доступ к конкретному объекту для указанных участников — при старте процесса участники автоматически добавляются в РГ предмета процесса
4. **RLS включён опционально** (константа `ОграничиватьДоступНаУровнеЗаписей`); при включении права хранятся в РС `ПраваПоДескрипторамДоступаОбъектов` и вычисляются по дескрипторам
5. **Центральные модули:** `РаботаСРабочимиГруппами` (управление составом), `ДокументооборотПраваДоступа` (расчёт прав), `РаботаСЗадачами` (бизнес-логика видимости)
6. **Роль `ЧтениеПроцессовИЗадачБезОграничения`** — "суперправа" для администраторов/контролёров, обходит все ограничения RLS
