**Дата анализа:** 2026-04-07  
**Сервер:** 1c-cloud-embeddings  
**Тест:** TEST-09

---

## 1. Общие сведения о подсистеме МЭДО

МЭДО (межведомственный электронный документооборот) — подсистема 1С:ДО КОРП для обмена электронными документами между федеральными органами исполнительной власти по протоколу ЭСД (электронное сообщение документооборота) версий 2.2, 2.5, 2.7 и 2.7.1.

Подсистема включается через функциональную опцию `ИспользоватьМЭДО`. Транспортный механизм — **файловый обмен**: документы помещаются в ZIP-архивы (ЭСД) и передаются через каталоги отправки/получения файловой системы (настраиваются в регистре `НастройкиОрганизацийМЭДО`). HTTP-сервисы и веб-сервисы для МЭДО не предусмотрены — интеграция осуществляется через общий веб-сервис DMService (`ОбработкаЗапросовXDTOОбмен`), не специфичный для МЭДО.

## 2. Документы МЭДО

### 2.1. Документ «УведомлениеМЭДО»

Документ хранит исходящие и входящие уведомления, отправляемые в рамках МЭДО. Управляется через `Документы.УведомлениеМЭДО.МодульМенеджера`.

**Основные реквизиты** (установлены из кода и структур данных):

| Реквизит | Описание |
|---|---|
| Дата | Дата создания уведомления |
| Организация | Наша организация-отправитель |
| Контрагент | Контрагент-получатель (внешняя организация МЭДО) |
| Документ | Ссылка на предмет уведомления (ОпределяемыйТип.ПредметМЭДО) |
| ТипУведомления | Тип из перечисления `ТипыУведомленийМЭДО` |
| Направление | Входящее / Исходящее (Перечисление `НаправленияСообщенийМЭДО`) |
| ГотоваКОтправке | Признак готовности к отправке |
| ВерсияМЭДО | Версия формата МЭДО (2.2, 2.5, 2.7, 2.7.1) |

**Типы уведомлений** (из функций заполнения в `ОбщиеМодули.МЭДО.Модуль`):

- ОтказВРегистрации
- ПринятиеКИсполнению
- ПодготовкаДоклада
- НаправлениеДоклада
- ХодИсполнения
- Опубликование
- DocumentSent (отправлен документ)
- ExecutorAssigned (назначен исполнитель)
- ReportPrepared (доклад подготовлен)
- ReportSent (доклад направлен)
- CourseChanged (изменен ход)
- DocumentPublished (опубликован)

**Поля для некоторых типов уведомлений** (из запросов реквизитов): ОтказВРегистрации (подструктура), ПринятиеКИсполнению, ПодготовкаДоклада, НаправлениеДоклада — каждый тип хранит свою вложенную структуру как реквизит документа.

**Методы модуля менеджера:**
- `ЗаписатьУведомление(УведомлениеОбъект)` — записывает с обработкой ошибок
- `СоздатьИсходящееУведомление_ЗаполнитьОбщиеПоля(ОбщиеПоля, ТипУведомления)` — создаёт новое уведомление

### 2.2. Документ «ДанныеДокументаМЭДО»

Вспомогательный документ для хранения дополнительных данных МЭДО, отсутствующих в основном документе. Управляется через `Документы.ДанныеДокументаМЭДО.МодульМенеджера`.

**Реквизиты** (восстановлены из кода):

| Реквизит | Описание |
|---|---|
| Документ | Ссылка на основной документ МЭДО (ОпределяемыйТип.ПредметМЭДО) |
| ВидДокумента | Вид документа по классификатору МЭДО |
| ГлавныйФайл | Ссылка на главный файл документа |
| ГрифДоступа | Гриф доступа (ОпределяемыйТип.ГрифДоступаМЭДО) |
| ИдентификаторДокумента | Уникальный идентификатор документа в системе МЭДО (uid) |
| МестоСоставления | Место составления документа (из справочника МестаСоставленияДокументовМЭДО) |
| Направление | Входящее / Исходящее |
| Организация | Организация-отправитель/получатель |
| Отправлен | Признак отправки |
| ГотовКОтправке | Признак готовности к отправке |
| ИдентификаторСообщения | Идентификатор транспортного сообщения ЭСД |

**Методы модуля менеджера:**
- `ОбъектДанныхДокумента(Документ, ДанныеОтвета)` — получает/создаёт объект данных
- `ЗаписатьОбъектДанныхДокумента(ДанныеОбъект, ДанныеОтвета)` — записывает с журналированием ошибок
- `СнятьПризнакГотовКОтправке(Документ)` — снимает признак готовности

### 2.3. Документ «КвитанцияМЭДО»

Документ-квитанция (acknowledgment) — подтверждение приёма/отправки ЭСД. Управляется в рамках `ОбщиеМодули.МЭДО.Модуль`.

**Реквизиты** (восстановлены из кода и структур данных `МЭДОСтруктурыДанных`):

| Реквизит | Описание |
|---|---|
| Дата | Дата квитанции |
| ИсходящаяДата | Исходящая дата квитанции |
| Направление | Входящее / Исходящее |
| Предмет | Документ или УведомлениеМЭДО (ОпределяемыйТип.ПредметКвитанцииМЭДО) |
| ИдентификаторСообщения | Идентификатор сообщения ЭСД |
| ИдентификаторКвитанции | Идентификатор квитанции |
| Контрагент | Контрагент |
| Организация | Организация |
| ДанныеСообщения | ХранилищеЗначения — двоичные данные ЭСД квитанции |
| СообщениеПринято | Булево — результат acknowledgment.accepted |
| КодОшибки | Код ошибки (для версии 2.7.1 при СообщениеПринято = Ложь) |
| КомментарийОшибки | Текст ошибки |
| ГотоваКОтправке | Признак готовности к отправке |
| ПометкаУдаления | Булево |

**Табличные части** — из кода не выявлены. По логике протокола МЭДО квитанции не содержат ТЧ.

## 3. Процесс отправки документа через МЭДО

### 3.1. Инициация отправки

Отправка запускается из обработки `ТекущиеДелаМЭДО` или регламентным заданием. Точка входа для ручной отправки — `ИсходящиеДокументыВыполнитьДействиеОтправки` (форма `ТекущиеДелаМЭДО`), которая вызывает серверную процедуру через `МЭДОВызовСервера.ОтправитьИсходящиеДокументы`.

### 3.2. Основные модули и процедуры

```
МЭДОВызовСервера.ОтправитьИсходящиеДокументы(Организация, ДанныеОтвета)
  → РегистрыСведений.НастройкиОрганизацийМЭДО.НастройкиОрганизации()
  → МЭДО.ОтправитьИсходящиеДокументы(Настройки, ДанныеОтвета)
    → МЭДО.ИсходящиеДокументыКОтправке(Настройки) — запрос документов со статусом "готов к отправке"
    → Для каждого документа:
        МЭДО.ОтправитьИсходящийДокумент(...)
          → МЭДОПереопределяемый.ДанныеИсходящегоДокументаДляОтправки() — получение данных
          → МЭДО.ЗаписатьДанныеИсходящегоДокументаМЭДО() — сохранение данных в ДанныеДокументаМЭДО
          → МЭДО.СоздатьПаспортКонтейнераИсходящегоДокумента() — создание XML-паспорта контейнера
          → МЭДО.ЗаписатьСодержимоеКонтейнераИсходящегоДокумента() — запись файлов контейнера
          → МЭДО.ЗаписатьСообщениеПоИсходящемуДокументу() — создание ZIP-файла ЭСД в КаталогОтправки
```

### 3.3. Отправка квитанций

```
МЭДОВызовСервера.ОтправитьИсходящиеКвитанции(Организация, ДанныеОтвета)
  → МЭДО.ОтправитьИсходящиеКвитанции(Настройки, ДанныеОтвета)
    → МЭДО.ДанныеИсходящихКвитанцийДляОтправки() — запрос квитанций с ГотоваКОтправке
    → МЭДО.ЗаписатьСообщениеПоИсходящейКвитанции() — запись ZIP-файла квитанции
```

### 3.4. Отправка уведомлений

```
МЭДОВызовСервера.ОтправитьИсходящиеУведомления(Организация, ДанныеОтвета)
  → МЭДО.ОтправитьИсходящиеУведомления(Настройки, ДанныеОтвета)
    → МЭДО.ИсходящиеУведомленияКОтправке() — отбор уведомлений
    → МЭДО.ОтправитьИсходящееУведомление()
      → МЭДО.ДанныеИсходящегоУведомленияДляОтправки() — заполнение структуры данных
      → МЭДО.ЗаписатьСообщениеПоИсходящемуУведомлению() — запись XML-сообщения уведомления
```

### 3.5. Получение входящих

```
МЭДОВызовСервера.ПолучитьВходящиеДокументы(Организация, ДанныеОтвета)
  → МЭДО.ВходящиеДокументыКОбработке() — сканирование КаталогаПолучения
  → МЭДО.ОбработатьВходящееЭСД(ФайлZip, Организация, ТипКонтента, ДанныеОтвета)
    → Распаковка ZIP → определение версии МЭДО
    → Если "Транспортный контейнер": МЭДО.ОбработатьВходящийТранспортныйКонтейнер() (v2.7, 2.7.1)
                                     МЭДО.ОбработатьВходящийДокумент22_25() (v2.2, 2.5)
    → МЭДО.ЗаписатьДанныеВходящегоДокументаМЭДО()
    → МЭДОПереопределяемый.НайтиСоздатьВходящийДокумент()
    → При необходимости: МЭДО.СоздатьИсходящееУведомлениеОРегистрации() — автоуведомление
```

### 3.6. Автоматическое уведомление при регистрации

При регистрации входящего МЭДО-документа модуль `МЭДОДокументооборот.ПриРегистрацииДокумента()` вызывает:
- `Документы.ДанныеДокументаМЭДО.ЗаписатьОбъектДанныхДокумента()` — обновление данных
- `МЭДО.СоздатьИсходящееУведомлениеОРегистрации()` — создание уведомления о регистрации (если `МЭДОПовтИсп.НужноСоздаватьУведомления()` = Истина)

## 4. HTTP-сервисы и веб-сервисы для интеграции с МЭДО

**Специализированных HTTP-сервисов или веб-сервисов для МЭДО в конфигурации не обнаружено.**

Обмен через МЭДО реализован исключительно через **файловый транспорт**:
- Исходящие: ZIP-архивы ЭСД записываются в `КаталогОтправки` (файловая система)
- Входящие: ZIP-архивы читаются из `КаталогПолучения` (файловая система)

Настройки каталогов хранятся в `РегистрыСведений.НастройкиОрганизацийМЭДО`.

Общий веб-сервис конфигурации DMService (`ОбработкаЗапросовXDTOОбмен`) предназначен для обмена с интегрированными системами и не является МЭДО-специфичным.

## 5. Регламентные задания МЭДО

### 5.1. ВыполнениеОбменаМЭДО

Основное регламентное задание, обслуживающее весь обмен МЭДО.

| Параметр | Значение |
|---|---|
| Имя в метаданных | `ВыполнениеОбменаМЭДО` |
| Обработчик | `МЭДО.ВыполнитьОбменМЭДО()` |
| Функциональная опция | `ИспользоватьМЭДО` |
| РаботаетСВнешнимиРесурсами | Истина |
| ДоступноВМоделиСервиса | Ложь |

**Логика обработчика `ВыполнитьОбменМЭДО()`:**
1. Проверка флага конкурентного выполнения (`ОбщегоНазначения.ПриНачалеВыполненияРегламентногоЗадания`)
2. Проверка доступности внешних ресурсов (`МЭДОПереопределяемый.ПроверитьОбменСВнешнимиРесурсами`)
3. Получение всех настроенных организаций из `РегистрСведений.НастройкиОрганизацийМЭДО`
4. Для каждой организации последовательно выполняет:
   - Получение входящих документов
   - Получение входящих уведомлений и квитанций
   - Отправку исходящих документов
   - Отправку исходящих квитанций
   - Отправку исходящих уведомлений

## 6. Справочники и настройки подсистемы

### 6.1. Регистр сведений НастройкиОрганизацийМЭДО

Ресурсы:
- `ИдентификаторМЭДО` — идентификатор организации в системе МЭДО
- `АдресМЭДО` — адрес организации в МЭДО
- `НаименованиеМЭДО` — наименование организации для МЭДО
- `КаталогОтправки` — путь к каталогу исходящих ЭСД
- `КаталогПолучения` — путь к каталогу входящих ЭСД
- `ГрифОбычнаяИнформация` — гриф доступа для обычных документов
- `ГрифИнформацияОграниченногоРаспространения` — гриф ДСП
- `РегШтампСлева`, `РегШтампСверху` — положение регистрационного штампа

### 6.2. Константы подсистемы (через МЭДОПовтИсп)

| Константа | По умолчанию | Описание |
|---|---|---|
| АвтоматическиОтправлятьКвитанцииМЭДО | Истина | Автоотправка квитанций |
| ВариантАвтосозданияУведомленийМЭДО | НеСоздавать | Вариант автосоздания уведомлений |
| ВремяХраненияЖурналаСобытийМЭДО | 365 дней | Хранение лога |
| РазмерПорцииОбработкиМЭДО | 50 | Количество документов в порции |

### 6.3. Справочники-классификаторы

- `ВидыДокументовМЭДО` — виды документов по приказам
- `МестаСоставленияДокументовМЭДО` — места составления
- `ПричиныОтказаВРегистрацииМЭДО` — причины отказа

### 6.4. Дополнительные регистры сведений

- `НастройкиКонтрагентовМЭДО` — версия МЭДО и адрес для каждого контрагента
- `СостоянияДокументовМЭДО` — журнал состояний (входящее/исходящее)

## 7. Архитектура модулей подсистемы МЭДО

| Модуль | Назначение |
|---|---|
| `ОбщиеМодули.МЭДО` | Основной серверный модуль: вся логика обмена, обработки ЭСД, создания XML |
| `ОбщиеМодули.МЭДОВызовСервера` | Клиент-серверный мост: вызов операций с клиента |
| `ОбщиеМодули.МЭДОКлиент` | Клиентский модуль: UI-операции (открыть форму уведомления и т.п.) |
| `ОбщиеМодули.МЭДОПереопределяемый` | Точки расширения: методы зависящие от конфигурации |
| `ОбщиеМодули.МЭДОДокументооборот` | Реализация переопределяемых методов для DO3 |
| `ОбщиеМодули.МЭДОСтруктурыДанных` | Фабрика структур данных: НовыйОтвет, НовыйДанныеВходящего/Исходящего... |
| `ОбщиеМодули.МЭДОПовтИсп` | Кэшированные настройки (константы) |
| `Обработки.ТекущиеДелаМЭДО` | Рабочее место оператора МЭДО |
| `РегистрыСведений.НастройкиОрганизацийМЭДО` | Настройки организаций (каталоги, идентификаторы) |
