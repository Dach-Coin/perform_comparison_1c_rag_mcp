# Оценка качества: TEST-04 — Какие регистры обновляются при работе с задачами
**Сервер:** 1c-cloud-embeddings  
**Дата:** 2026-04-07  
**Оценщик:** Оркестратор (Claude Opus 4.6)

## Общая оценка: ПОЛНОСТЬЮ

## Метрики
| Метрика                | Значение     |
| ---------------------- | ------------ |
| Вызовов MCP            | 9            |
| Полезных               | 8 (89%)      |
| Шумных                 | 1 (11%)      |
| Retry                  | 1            |
| Общее время агента     | ~4.5 мин     |
| Токенов агента (total) | ~217 000     |

## Что сервер дал хорошо

- **Код ОбработкаПроведения** обоих документов (Задача и ДействиеЗадачи) — получен через codesearch, с фрагментами достаточными для понимания механизма движений
- **Все 5 ключевых регистров** найдены: РН.КоличествоЗадач, РН.КоличествоДействийЗадач, РС.ДействияЗадач, РС.ЗадачиПоАвторам, РС.ВсеИсполнителиДействийЗадач
- **Механизм асинхронного обновления** через очередь кэширующих данных — описан с кодом
- **Связь замещений с регистрами** — найден код ЗамещающиеИПомощники → ВсеИсполнителиДействийЗадач → влияние на КоличествоДействийЗадач
- **Полная схема lifecycle** — от создания через взятие в работу до отмены, с указанием конкретных ресурсов
- **Процедуры смены состояния** — УстановитьСостояние, ОтметитьВыполнена, ОтметитьОтменена

## Что сервер НЕ дал

- **Полные структуры регистров** (измерения с типами, все ресурсы, реквизиты) — metadatasearch вернул пустоту; codesearch дал только упоминания, не описания полей. Агенту пришлось собирать ресурсы из кода ОбработкаПроведения
- **Смежные регистры** — РС.ИсторияЗадач, РС.СведенияОбИсполнителяхЗадач, РС.ПоступившиеОбновленияЗадач упомянуты вскользь, без деталей структуры
- **Тело ЗаполнитьНаборПоДействию** — найдена сигнатура, но не полная логика заполнения набора

## Паттерны поведения агента

- **Стратегия:** Начал с metadatasearch (0 результатов) → быстро переключился на codesearch → серия целенаправленных запросов по именам процедур и регистров
- **Эффективность отличная:** 9 вызовов, 89% полезных. Самый экономный из трёх серверов
- **Умные запросы:** Комбинировал ключевые слова (имя регистра + имя процедуры + контекст), что давало высокорелевантные результаты
- **codesearch — основная рабочая лошадка:** 7 из 9 вызовов — codesearch, все с высокой/средней релевантностью

## Выявленные проблемы RAG

| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| metadatasearch коллекция пуста (0 объектов) | Вызов #2 вернул пустой ответ — индекс metadata не заполнен |
| Нет структуры метаданных | codesearch находит код с именами регистров, но не описание полей (измерения, ресурсы, типы) |
| Чанкинг vs полный код | Код ОбработкаПроведения разбит на чанки; полная процедура собирается из нескольких вызовов |

## Вывод

Сервер cloud-embeddings **наиболее эффективен для TEST-04**: 9 вызовов, минимальный расход токенов (~217K), ПОЛНЫЙ ответ. codesearch отлично находит код по бизнес-терминам. Слабое место — отсутствие индекса metadata (не найдены структуры регистров с типами). Для задач типа «какой код записывает в регистры» — идеальный сервер; для задач «опиши структуру регистра» — потребуется дополнительная работа.
