# Бизнес-процесс «Согласование» в 1С:Документооборот КОРП 3.0
**Конфигурация:** 1С:Документооборот КОРП 3.0 (DO3)  
**Дата отчёта:** 2026-04-07  
**Источник данных:** MCP-сервер 1c-cloud-embeddings (codesearch + helpsearch)  

---

## 1. Обзор

Бизнес-процесс **Согласование** (`БизнесПроцессы.Согласование`) — один из базовых процессов работы с документами в 1С:Документооборот КОРП. Он реализует маршрут направления документа нескольким согласующим лицам с фиксацией результата каждого и определением итогового результата.

---

## 2. Параметры настройки при запуске

При запуске процесса Согласование настраиваются следующие параметры:

### 2.1 Исполнители (согласующие)
- Реквизит процесса: **`Исполнители`** (табличная часть)
- Каждая строка содержит: исполнителя (пользователь/роль) и признак `Пройден`
- Заполняется вручную или автоматически из шаблона согласования (`Справочник.ШаблоныСогласования`)

### 2.2 Вариант согласования
- Реквизит процесса: **`ВариантСогласования`**
- Тип: `Перечисление.ВариантыМаршрутизацииЗадач`
- Возможные значения:
  - **Параллельно** — задачи создаются всем исполнителям одновременно
  - **Последовательно** — следующий исполнитель получает задачу только после завершения предыдущего (в таблице Исполнители перебирается первая строка, у которой `Пройден = Ложь`)
- Обязателен к заполнению: при незаполненном варианте `УсловиеОбходЗавершен` выбрасывает исключение

```bsl
// БизнесПроцессы.Согласование.МодульОбъекта — СоздатьЗадачиСогласования()
Если ВариантСогласования = Перечисления.ВариантыМаршрутизацииЗадач.Параллельно Тогда 
    Для Каждого Строка Из Исполнители Цикл
        МассивСтрок.Добавить(Строка);  // все сразу
    КонецЦикла;    
ИначеЕсли ВариантСогласования = Перечисления.ВариантыМаршрутизацииЗадач.Последовательно Тогда 
    Для Каждого Строка Из Исполнители Цикл
        Если Строка.Пройден Тогда 
            Продолжить;  // пропускаем уже пройденных
        КонецЕсли;
        МассивСтрок.Добавить(Строка);  // берём первого непройденного
        Прервать;
    КонецЦикла;
```

### 2.3 Сроки исполнения
- Реквизиты: `СрокИсполнения` (дата), `СрокИсполненияДни`, `СрокИсполненияЧасы`, `СрокИсполненияМинуты`
- Расчёт сроков выполняет `ОбщиеМодули.СрокиИсполненияПроцессов` (функция `РассчитатьСрокиСогласования`)
- При последовательном порядке сроки рассчитываются цепочкой: каждый следующий исполнитель получает срок после предыдущего

**Типовые сроки (из пользовательской документации):**

| Вид документа | Срок |
|---|---|
| Приказы, распоряжения | 3 дня |
| Инструкции, порядки, регламенты | 5 дней |
| Договоры | 3 дня |
| Служебные записки | 1 день |

### 2.4 Шаблон согласования
- Параметр `Шаблон` (из `Справочник.ШаблоныСогласования`)
- Шаблон связан с видом документа и может предзаполнять исполнителей, порядок и сроки
- Возможен автозапуск по шаблону при закрытии карточки документа

## 3. ВизыСогласования — структура и связь с процессом

### 3.1 Объект конфигурации
- **`Справочник.ВизыСогласования`** — каждая виза представляет собой отдельную запись результата одного согласующего по одному документу

### 3.2 Ключевые поля визы
| Поле | Описание |
|---|---|
| `Источник` | Ссылка на задачу или бизнес-процесс (связь: `Источник.БизнесПроцесс`) |
| `Документ` | Ссылка на согласуемый документ |
| `Исполнитель` | Согласующее лицо |
| `УстановилРезультат` | Ссылка на `Справочник.ФактическиеИсполнители` |
| `РезультатСогласования` | Значение из `Перечисление.РезультатыСогласования` |
| `Комментарий` | Текстовый комментарий согласующего |
| `ДатаИсполнения` | Дата установки результата |
| `Удалена` | Признак удалённой визы |
| `ПомещенаВИсторию` | Признак исторической визы |

### 3.3 Связь с процессом
- Виза привязана к процессу через `Источник.БизнесПроцесс`
- SQL-запросы в коде выбирают визы по `БизнесПроцесс` и `ДатаИсполнения` для группировки результатов
- К визе прикрепляются электронные подписи через `РегистрСведений.ЭлектронныеПодписи` (ЛЕВОЕ СОЕДИНЕНИЕ по визе)
- Версии согласованных файлов хранятся в `РегистрыСведений.ВерсииСогласованныхФайлов` (функции `ДобавитьВерсии`/`УдалитьВерсии`/`ВсеВерсии` по визе)

### 3.4 Модуль формы визы
`Справочники.ВизыСогласования.Модуль` содержит:
- Валидацию: нельзя вручную установить результат если `БизнесПроцессСсылка.Согласование` ещё не завершён
- `РезультатСогласованияПриИзменении` — обработчик изменения результата
- `ПодписатьЭП`, `ПроверитьЭП` — работа с электронной подписью
- `ЗапретитьИзменениеВизы`, `ЕстьДубльВизы`

### 3.5 Работа с визами — общий модуль
**`РаботаСВизамиСогласования`** (общий модуль) — основной модуль для работы с визами:
- `ЕстьВизыНаСогласовании(Документ)` — проверяет незаполненные визы
- `УдалитьВизы(НезаполненныеВизы)` — удаление виз
- `ПолучитьАктивныеВизыДокумента(Предмет)` — выборка активных виз
- `ОбновитьВизыУчастниковДействия(Ссылка, Добавленные, Удалённые)` — обновление при изменении участников

**`РаботаСВизамиСогласованияКлиент`** — клиентская часть:
- `ДобавитьВизу(ЭтаФорма)` — добавление новой визы из формы
- `ПроверитьВизуИсполнителяЗадачи(Задача, ОписаниеОповещения)` — проверка перед выполнением задачи

## 4. Возможные результаты согласующего

**Перечисление:** `Перечисление.РезультатыСогласования`

| Значение | Описание |
|---|---|
| `Согласовано` | Документ согласован без замечаний |
| `СогласованоСЗамечаниями` | Согласован, но есть замечания |
| `НеСогласовано` | Документ не согласован |

В форме задачи исполнителя (`Задачи.ЗадачаИсполнителя.Модуль`) доступны соответствующие команды:
- `ЗадачаСогласовано` → `ЗадачаСогласованоПослеПодзадач`
- `ЗадачаСогласованоСЗамечаниями` → `ЗадачаСогласованоСЗамечаниямиПослеПодзадач`
- `ЗадачаНеСогласовано` → `ЗадачаНеСогласованоПослеПодзадач`

После выполнения задачи отправляется оповещение `"ЗадачаСогласованияВыполнена"` с информацией о задаче и предмете.

**Дополнительные действия согласующего:**
- `ЗавершитьСогласование` — принудительное завершение
- `ЗадачаПовторить` — возврат на повторное согласование (проверка `ПовторитьСогласованиеПроверкаУсловия`)
- `ЗадачаСогласованиеОзнакомился` — ознакомление с результатом

**Состояния документа** (`Перечисление.СостоянияДокументов`):
- `НаСогласовании` — в процессе
- `Согласован` — итоговый положительный
- `НеСогласован` — итоговый отрицательный

## 5. Что происходит при завершении всеми согласующими

### 5.1 Точка маршрута и условие завершения
Ключевая точка маршрута процесса Согласование — `ТочкиМаршрута.Согласовать`.

Обработчик `УсловиеОбходЗавершен` в модуле объекта вызывает `ОбходСогласующихЗавершен()`:

```bsl
// БизнесПроцессы.Согласование.МодульОбъекта
Процедура УсловиеОбходЗавершен(ТочкаМаршрутаБизнесПроцесса, Результат)
    Если Не ЗначениеЗаполнено(ВариантСогласования) Тогда
        ВызватьИсключение НСтр("ru = 'Не заполнен вариант согласования процесса ""%1""'");
    КонецЕсли;
    Результат = ОбходСогласующихЗавершен();
КонецПроцедуры
```

### 5.2 Обработка завершения задачи согласования
Перед выполнением задачи вызывается `СогласоватьПередВыполнением`:

```bsl
Процедура СогласоватьПередВыполнением(ТочкаМаршрутаБизнесПроцесса, Задача, Отказ)
    УстановитьПривилегированныйРежим(Истина);
    ОбработатьЗавершениеЗадачиОтложеннаяПодготовкаСогласования(Задача);
    ОбработатьЗавершениеЗадачиСогласования(Задача);
КонецПроцедуры
```

Функция `ОбработатьЗавершениеЗадачиСогласования(Задача)` — центральная точка обработки результата каждой задачи. В ней:
- Записывается результат в `РезультатыСогласования` (табличная часть процесса)
- При последовательном порядке помечает строку `Пройден = Истина` и создаёт следующую задачу

### 5.3 Определение итогового результата
Функция `ИтоговыйРезультатСогласования()` экспортная, вызывается из менеджера:

```bsl
// Начало функции — если нет результатов, возвращает пустую ссылку
Если РезультатыСогласования.Количество() = 0 Тогда
    Возврат Перечисления.РезультатыСогласования.ПустаяСсылка();
КонецЕсли;
ИтоговыйРезультат = Перечисления.РезультатыСогласования.Согласовано;
// ...далее: если есть НеСогласовано — результат НеСогласовано;
//           если есть СогласованоСЗамечаниями — результат СогласованоСЗамечаниями
```

### 5.4 Модуль менеджера: проверка завершения
`БизнесПроцессы.Согласование.МодульМенеджера` содержит три функции для проверки результата:

```bsl
// Завершился удачно (с любым положительным результатом)
Функция ПроцессЗавершилсяУдачно(Ссылка) Экспорт
    РеквизитыПроцесса = ОбщегоНазначения.ЗначенияРеквизитовОбъекта(
        Ссылка, "Завершен, РезультатСогласования");
    Возврат РеквизитыПроцесса.Завершен 
        И (РеквизитыПроцесса.РезультатСогласования = Перечисления.РезультатыСогласования.Согласовано
           Или РеквизитыПроцесса.РезультатСогласования = 
               Перечисления.РезультатыСогласования.СогласованоСЗамечаниями);
КонецФункции

// Также доступны:
// ПроцессЗавершилсяУдачноСЗамечаниями(Ссылка) — только СогласованоСЗамечаниями
// ПроцессЗавершилсяУдачноБезЗамечаний(Ссылка) — только Согласовано
```

### 5.5 Отложенная обработка
Процесс поддерживает отложенные задачи (фоновые задания):
- `ДобавитьЗадачуОтложеннаяОбработкаЗавершенияСогласования` — отложенная обработка завершения
- `ДобавитьЗадачуОтложеннаяПодготовкаОзнакомления` — подготовка этапа ознакомления после согласования
- `ДобавитьЗадачуОтложеннаяОбработкаЗавершенияОзнакомления`

### 5.6 Ознакомление с результатом
После завершения согласования система создаёт задачи ознакомления (`СоздатьЗадачиОзнакомиться`):
- Задача `ЗадачаСогласованиеОзнакомился` — для ответственного, чтобы ознакомиться с итогом
- При результате "Не согласовано" — возможность повторить согласование или закрыть

## 6. Общие модули, участвующие в логике согласования

| Модуль | Роль |
|---|---|
| `РаботаСВизамиСогласования` | Основная работа с визами: создание, удаление, проверка, обновление |
| `РаботаСВизамиСогласованияКлиент` | Клиентская логика: интерактивное добавление виз, проверка перед выполнением |
| `БизнесПроцессыИЗадачиВызовСервера` | Отмена выполнения задачи, возврат в первоначальное состояние (очистка результата, удаление ЭП) |
| `СрокиИсполненияПроцессов` | Расчёт сроков исполнения: `РассчитатьСрокиСогласования`, `ДлительностьИсполненияСогласования` |
| `ОбработкаЗапросовXDTOОбмен` | Обмен данными с внешними системами: формирование таблиц ВизыСогласовано/ВизыНеСогласовано |
| `ОбработкаЗапросовXDTOДокументы` | XDTO-представление виз: поля Результат, Комментарий, ЭП, исполнитель |
| `КабинетСотрудникаМенеджерОбмена` | Загрузка результатов согласования из сервиса КабинетСотрудника |
| `РаботаСПроцессамиПоДействиямСобытияКлиент` | Обработка завершения согласования в действиях-событиях (`ОбработатьЗавершениеСогласования`) |
| `МиграцияДанныхИзВнешнихСистемДО21` | Конвертация виз согласования при миграции из версии 2.1 |

### 6.1 Схема взаимодействия модулей

```
БизнесПроцессы.Согласование.МодульОбъекта
    └── СоздатьЗадачиСогласования()        ← по ВариантСогласования
    └── ОбработатьЗавершениеЗадачиСогласования()
            └── РаботаСВизамиСогласования.ОбновитьВизы...
            └── РегистрыСведений.ВерсииСогласованныхФайлов
    └── ИтоговыйРезультатСогласования()
    └── ОбходСогласующихЗавершен()
    └── ЗавершениеПриЗавершении()

БизнесПроцессы.Согласование.МодульМенеджера
    └── ПроцессЗавершилсяУдачно()
    └── ОписаниеРезультатаЗавершенияПроцесса()
    └── ЛистСогласования()

СрокиИсполненияПроцессов
    └── РассчитатьСрокиСогласования()
    └── ДатаИсполненияУчастника()
```

## 7. Дополнительно: печать листа согласования

Менеджер процесса содержит функции печати:
- `ЛистСогласования(Процесс)` — формирует печатную форму листа согласования
- `ЛистСогласованияИзЗадачи(Задача)` — формирует лист по задаче

Лист включает: исполнителей, результаты виз, комментарии, даты и электронные подписи.
