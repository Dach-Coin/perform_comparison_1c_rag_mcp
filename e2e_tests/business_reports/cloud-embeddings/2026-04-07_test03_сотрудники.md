# TEST-03: Структура справочника Сотрудники
**Конфигурация:** 1С:Документооборот КОРП 3.0 (DO3)  
**Дата анализа:** 2026-04-07  
**Сервер RAG:** 1c-cloud-embeddings  
**Источник данных:** анализ BSL-кода конфигурации

---

## 1. Общие сведения

Справочник **Сотрудники** является подчинённым справочником (владелец — `Справочник.ФизическиеЛица`). Один сотрудник соответствует одному сочетанию "физическое лицо + должность + подразделение". У одного физического лица может быть несколько записей сотрудников (совмещение, внутреннее совместительство).

---

### Стандартные реквизиты (платформенные)
| Реквизит | Тип | Примечание |
|---|---|---|
| Код | Строка | Автонумерация |

### Реквизиты (прикладные)
| Реквизит | Тип | Примечание |
|---|---|---|
| ПредставлениеВДокументах | Строка | Формат ФИО для подписи в документах |
| ПредставлениеВПереписке | Строка | Формат ФИО для писем и переписки |
| Должность | СправочникСсылка.Должности | Текущая должность |
| Подразделение | СправочникСсылка.СтруктураПредприятия | Подразделение (узел структуры предприятия) |
| ГрафикРаботы | СправочникСсылка.КалендарныеГрафики | График работы сотрудника |
| ДатаНачалаДействия | Дата | Дата приёма / начала действия |
| ДатаОкончанияДействия | Дата | Дата увольнения / окончания (может быть пустой) |

> **Примечание по полю Действует:** заполняется автоматически в обработчике `ПередЗаписью`. Сотрудник считается действующим, если текущая дата попадает в диапазон `[ДатаНачалаДействия, ДатаОкончанияДействия]` (или дата окончания не указана). Именно это поле используется в функции `ЭтоДействительныйСотрудник()`.

## 3. Табличные части

### КонтактнаяИнформация
Стандартная ТЧ из библиотеки стандартных подсистем (БСП). Хранит контактную информацию сотрудника (телефоны, email, адреса).

| Реквизит ТЧ | Тип | Примечание |
|---|---|---|
| Вид | СправочникСсылка.ВидыКонтактнойИнформации | Тип КИ (телефон, почта, адрес) |

| Представление | Строка | Строковое представление |

Других нестандартных табличных частей в справочнике Сотрудники не обнаружено. Дополнительные реквизиты подключаются через стандартный механизм дополнительных реквизитов и сведений (БСП).

## 4. Связи с другими справочниками

### 4.1 Справочник ФизическиеЛица
- **Тип связи:** подчинённость (Сотрудники — подчинённый справочник ФизическихЛиц)
- **Реквизит:** стандартный `Владелец` (тип `СправочникСсылка.ФизическиеЛица`)
- **Семантика:** одно физическое лицо может иметь несколько записей сотрудников
- **Регистр ОсновныеСотрудники:** определяет, какой из сотрудников физического лица является "основным"; используется при определении текущего пользователя

### 4.2 Справочник Должности
- **Реквизит:** `Должность` (тип `СправочникСсылка.Должности`)
- **Функция API:** `Сотрудники.ДолжностьСотрудника(Сотрудник)` — получить должность
- Справочник Должности используется в адресной книге, в правилах коммуникаций, в шаблонах бизнес-процессов

### 4.3 Справочник СтруктураПредприятия
- **Реквизит:** `Подразделение` (тип `СправочникСсылка.СтруктураПредприятия`)
- **Функция API:** `Сотрудники.ПодразделениеСотрудника(Сотрудник)` — получить подразделение
- **Функция API:** `Сотрудники.БлижайшийРуководитель(Сотрудник)` — поиск руководителя через иерархию подразделений
- **Функция API:** `Сотрудники.СотрудникиПодразделения(Подразделение)` — все сотрудники подразделения
- Регистр `ПодчиненностьПодразделений` хранит иерархию: поля `Подчиненное`, `Вышестоящее`, `РуководительПодчиненного`

## 5. Механизм замещения сотрудников

### Объект реализации
Замещение реализовано через **Справочник.ЗамещающиеИПомощники** — отдельный справочник конфигурации.

### Структура справочника ЗамещающиеИПомощники
| Реквизит | Тип | Описание |
|---|---|---|
| Сотрудник | СправочникСсылка.Сотрудники | Кто замещается (отсутствующий сотрудник) |
| Замещающий | СправочникСсылка.Сотрудники | Кто выполняет функции |
| ВидЗамещения | ПеречислениеСсылка.ВидыЗамещения | Замещающий / Помощник |
| Действует | Булево | Флаг активности записи |
| ДатаНачала | Дата | Начало периода замещения |
| ДатаОкончания | Дата | Окончание периода (может быть пустой) |

### Табличная часть ВопросыЗамещения
| Реквизит | Тип | Описание |
|---|---|---|
| Область | СправочникСсылка.ОбластиЗамещения | Область делегирования (документы, задачи и т.д.) |

### Примеры предопределённых областей замещения (Справочник.ОбластиЗамещения)
- `ВсеОбласти` — полное замещение всех функций
- `ДокументыПодписание` — только подписание документов
- Другие: Согласование, Утверждение, Исполнение, Ознакомление, Регистрация

### Программный API замещения
- `Справочники.ЗамещающиеИПомощники.АктуальныеЗамещенияСотрудников(Сотрудник, ОбластиЗамещения)` — получить актуальные замещения
- `ОбщиеМодули.ЗамещающиеИПомощники.ПодходящиеЗамещения(...)` — найти подходящих замещающих по действию задачи
- Уведомления о замещении обрабатываются через `РаботаСУведомлениями.ДобавитьУведомленияПоЗамещению(...)`

### Связанные регистры при замещении
- `РегистрСведений.СотрудникиВКонтейнерах` — определяет доступ замещающего к задачам и документам замещаемого

## 7. Общий модуль Сотрудники — ключевые функции API

Модуль `ОбщиеМодули.Сотрудники` — центральная точка работы со справочником.

**Связь Сотрудник — Пользователь:**
- `СотрудникиПользователя(Пользователь)` — все сотрудники пользователя
- `ОсновнойСотрудникПользователя(Пользователь)` — основной сотрудник
- `ПользователиСотрудника(Сотрудник)` — пользователи данного сотрудника

**Связь Сотрудник — ФизЛицо:**
- `ФизЛицоСотрудника(Сотрудник)` — физическое лицо
- `ВсеСотрудникиФизЛица(ФизЛицо)` — все сотрудники физ. лица
- `ОсновнойСотрудникФизЛица(ФизЛицо)` — основной сотрудник физ. лица

**Структура предприятия:**
- `ПодразделениеСотрудника(Сотрудник)` — подразделение
- `ДолжностьСотрудника(Сотрудник)` — должность
- `БлижайшийРуководитель(Сотрудник)` — ближайший руководитель по иерархии

**Статус и проверки:**
- `ЭтоПолноправныйСотрудник(Сотрудник)` — имеет пользователя + является действующим
- `ЭтоДействительныйСотрудник(Сотрудник)` — поле Действует = Истина
- `ЭтоСотрудникБезПользователя(Сотрудник)` — нет связанной учётной записи

---

## 8. Итоговая схема связей

```
ФизическиеЛица (1)
    └── Сотрудники (N) [подчинённый справочник]
            ├── Должности (N:1)
            ├── СтруктураПредприятия (N:1)
            │       └── иерархия подразделений
            ├── Пользователи (N:M) [через РС.СотрудникиПользователей]
            └── ЗамещающиеИПомощники (N:M)
                    ├── Сотрудник (замещаемый)
                    ├── Замещающий (заместитель)
                    └── ВопросыЗамещения → ОбластиЗамещения
```

## 9. Ограничения анализа

1. **metadatasearch полностью недоступен** — все 5 запросов вернули пустые ответы. Список реквизитов восстановлен косвенно из BSL-кода (через обращения к реквизитам в коде).
2. **helpsearch** не содержит справки по справочнику Сотрудники — раздел справки отсутствует в индексе сервера.
3. Типы данных некоторых реквизитов выведены по контексту кода, а не из прямого чтения метаданных.
4. Реквизит **Организация** (характерный для КОРП-версии с многоорганизационным учётом) не подтверждён явно в найденных фрагментах кода.
