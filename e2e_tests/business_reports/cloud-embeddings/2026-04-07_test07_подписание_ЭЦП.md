## 1. Бизнес-процесс Подписание: общая структура

В конфигурации реализован полноценный бизнес-процесс **`БизнесПроцессы.Подписание`** — самостоятельный объект метаданных типа БизнесПроцесс.

### Точки маршрута
Процесс имеет две точки маршрута:
- **`Подписать`** — основная задача исполнителю-подписанту
- **`ОбработатьРезультат`** — обработка результата после подписания

### Параметры процесса (реквизиты)
Из кода модуля `ИнтеграцияЗадач` получены следующие реквизиты БП:
- `Участники` — табличная часть с исполнителями (подписантами)
- `РезультатПодписания` — итоговый результат
- `РезультатыПодписания` — детализация по каждому участнику
- `РезультатыОбработок` — результаты обработок объектов
- `СпособПодписания` — тип подписи (ПЭП или УЭП)
- `Предметы` — подписываемые объекты (документы, файлы)

## 2. Параметры запуска: кто подписывает, тип подписи

### Участники (подписанты)
При запуске процесса указываются участники — сотрудники/пользователи, которым будет направлена задача на подписание. Используется дерево участников с этапами подписания:
- Форма `ОбщаяФорма.КарточкаЭтапаПодписания` — карточка этапа
- Форма `ОбщаяФорма.НастройкаУчастникаПроцессаПодписанияНаБумаге` — при бумажном подписании
- Поддерживается `ФункцииУчастниковПодписания` — роли участников в процессе

Функция `ПодписывающиеПоЗадачеПодписания()` в `ИнтеграцияЗадач`:
```bsl
// Параметры задачи:
// * БизнесПроцесс - БизнесПроцессСсылка.Подписание
// * ИдентификаторИсполнителя - УникальныйИдентификатор
// * Исполнитель - СправочникСсылка.Сотрудники
// * РольИсполнителя - СправочникСсылка.РолиИсполнителей
```

### Способ (тип) подписи
Тип подписи задаётся через реквизит `СпособПодписания`:
- **`ПЭП`** (Простая электронная подпись) — `Перечисления.СпособыПодписанияПредметаДействия.ПЭП`
- **`УЭП`** (Усиленная электронная подпись) — `Перечисления.СпособыПодписанияПредметаДействия.УЭП`

Дополнительно есть `Перечисление.ВидыЭлектронныхПодписей`:
- `Простая`
- `УсиленнаяКвалифицированная`

Модуль `РаботаСВнешнимПодписанием` содержит функцию `ЭтоПодписаниеУсиленнойЭП()`, которая проверяет принадлежность способа подписания к категории УЭП.

При электронной форме документа способ подписания автоматически устанавливается в ПЭП (`Справочники.НастройкиДействийПодписания`).

### Шаблоны подписания
Справочник `ШаблоныПодписания` хранит готовые шаблоны для повторного использования. Менеджер шаблонов `Справочники.ШаблоныПодписания.МодульМенеджера` содержит метод `ИмяПроцесса()` — возвращает имя соответствующего бизнес-процесса.

## 3. Поддержка электронной подписи (ЭП/ЭЦП)

Электронная подпись поддерживается в полном объёме через несколько уровней:

### Уровень 1 — Функциональный (общие модули)
| Модуль | Назначение |
|--------|-----------|
| `ОбщиеМодули.ЭлектроннаяПодпись` | Серверные функции: `ПроверитьПодпись`, `ПроверитьСертификат`, `ДобавлениеИзменениеЭлектронныхПодписей`, `ДоступнаУсовершенствованнаяПодпись` |
| `ОбщиеМодули.ЭлектроннаяПодписьКлиент` | Клиентские функции: `Подписать`, `НовыйТипПодписи`, `ДобавитьПодписьИзФайла`, `ОткрытьПодпись` |
| `ОбщиеМодули.РаботаСЭП` | Прикладная логика ДО: `ЗаполнитьСписокПодписей`, `ЗанестиИнформациюОПодписи`, `СнятьПризнакПодписанЭП`, `ОбновитьОтметкуЭП`, `ПроверитьПодписиНаСервере` |
| `ОбщиеМодули.СервисКриптографии` | Низкоуровневая криптография: `Подписать`, `ПроверитьПодпись`, `Зашифровать`, `Расшифровать` |
| `ОбщиеМодули.ЭлектроннаяПодписьДокументооборотСобытия` | События ДО при подписании: `ПриЗаполненииОписанияДанныхПриПодписании`, `ОбработатьМатематическуюПроверкуПодписи` |
| `ОбщиеМодули.РаботаСВнешнимПодписанием` | Интеграция с внешними сервисами подписания (DSS и др.) |

### Уровень 2 — Форма подписания
`Справочники.СертификатыКлючейЭлектроннойПодписиИШифрования` — форма содержит полный цикл подписания:
- Выбор сертификата из личного хранилища
- Установка типа подписи
- Указание пароля
- `ПодписатьДанные()` → `ПодписатьДанныеПослеВыполненияНаСторонеКлиента()` → `ПодписатьДанныеПослеВыполнения()`

### Уровень 3 — Поддержка машиночитаемых доверенностей (МЧД)
Встроена поддержка МЧД при подписании: `ДоступныеМЧДДляПодписанияСертификатом`, `СертификатуНужнаДоверенность`, `ВыбраннаяДоверенность` — в форме `ПодписаниеДанных`.

## 4. Хранение данных о подписях

### Основной регистр — `РегистрСведений.ЭлектронныеПодписи`
Является главным хранилищем информации об электронных подписях объектов:

| Поле | Описание |
|------|----------|
| `ПодписанныйОбъект` | Ссылка на подписанный объект (документ, файл и т.д.) |
| `УникальныйИдентификатор` | GUID подписи |
| `Подпись` | Двоичные данные подписи |
| `КомуВыданСертификат` | ФИО/наименование владельца сертификата |
| `Отпечаток` | Отпечаток сертификата |
| `ПодписьВерна` | Булево — результат проверки подписи |
| `СертификатДействителен` | Булево — действительность сертификата |
| `ТипПодписи` | Тип ЭП (Простая/Усиленная/Усовершенствованная) |
| `ДатаПодписи` | Дата и время подписания |
| `ИмяФайлаПодписи` | Имя файла подписи |
| `ТекстОшибкиПроверкиПодписи` | Описание ошибки при неверной подписи |
| `СрокДействияПоследнейМеткиВремени` | Для усовершенствованных подписей |

### Дополнительные регистры
- **`РегистрСведений.ДоверенностиЭлектронныхПодписей`** — хранение данных МЧД к подписям
- **`РегистрСведений.СостояниеПодписанияЭД`** — состояние подписания для электронных документов ЭДО (поля: `Объект`, `Подписант`, `Текущий`, `ПодписантОповещен`)

### Справочник сертификатов
**`Справочники.СертификатыКлючейЭлектроннойПодписиИШифрования`** — хранит сертификаты пользователей с реквизитами: сертификат (двоичные данные), срок действия, программа криптографии.

## 5. Что происходит после подписания

После завершения задачи подписания происходит следующее:

### 5.1 Фиксация подписи в регистре
Вызов `РаботаСЭП.ЗанестиИнформациюОПодписи()` записывает данные подписи в `РС.ЭлектронныеПодписи`.

### 5.2 Обновление штампа ЭП
`РаботаСЭП.ОбновитьОтметкуЭП()` обновляет визуальный штамп ЭП в файлах документа (через ImageMagick при наличии настройки штампа).

### 5.3 Ограничение редактирования
Согласно справке: **"Подписанный документ или файл недоступен для редактирования"**. Логика снятия признака реализована через `РаботаСЭП.СнятьПризнакПодписанЭП()`.

### 5.4 Статус проверки ЭП
Устанавливается статус через `Перечисление.СтатусПроверкиЭП`:
- `ПодписьДействительна` — после успешной проверки
- `ПодписьНедействительна` — при ошибке
- `ПодписиНет` — при отсутствии подписи

Статус хранится в `РС.ЭлектронныеПодписи` через поля `ПодписьВерна` и `СертификатДействителен`.

### 5.5 Запись в протокол работы сотрудников
`ПротоколированиеРаботыСотрудников.ЗаписатьПодписаниеЭП()` — фиксирует факт подписания в журнале аудита.

### 5.6 Смена статуса документа
Прямой код смены статуса документа после подписания в найденных фрагментах не подтверждён (metadata-коллекция пуста). Однако по логике конфигурации: после успешного завершения бизнес-процесса Подписание может изменяться состояние документа через `УстановитьСостояниеПредметаПоДействию()` (модуль `ДействияСервер`).
