## Шаг 1. Поступление ВходящегоПисьма от контрагента

### Объект
**Документ `ВходящееПисьмо`** — создаётся как новый документ ИБ.

Создание через код:
```bsl
ВходящееПисьмоОбъект = Документы.ВходящееПисьмо.СоздатьДокумент();
ВходящееПисьмоОбъект.Предмет = Предмет;  // связанный объект
// ... заполнение реквизитов ...
ВходящееПисьмоОбъект.Записать();
```
*Источник: `ОбщиеМодули.РаботаСУведомлениями.Модуль`*

### Ключевые реквизиты документа
- **Организация** — получатель
- **Контрагент** — отправитель
- **КонтактноеЛицо** — отправитель (ФИО)
- **Дата**, **ДатаРегистрации**, **РегистрационныйНомер** — нумерация
- **Содержание** — текст письма
- **Предмет** — связанный объект (проект, договор и т.п.)
- **Ответственный** — исполнитель по документу

### Регистрация документа
Производится через `Справочники.ДокументыПредприятия` (базовый класс):
```bsl
Нумератор = Нумерация.ПолучитьНумераторДокумента(ДокументОбъект);
Нумерация.СформироватьЧисловойНомерДокумента(СтруктураПараметров, ДокументОбъект.ЧисловойНомер);
Нумерация.СформироватьСтроковыйНомерДокумента(СтруктураПараметров, ДокументОбъект.РегистрационныйНомер, ОписанияОшибок);
```
*Источник: `Справочники.ДокументыПредприятия.Модуль`*

### Регистры, которые обновляются
| Регистр | Действие |
|---|---|
| `РегистрыСведений.Нумерация` | Запись счётчика номера (измерения: Нумератор, Организация, Подразделение, Проект, ГрифДоступа) |
| `РегистрыСведений.ПротоколРаботыСотрудников` | Событие `РегистрацияДокумента` с регистрационным номером |
| `РегистрыСведений.НаличиеФайлов` | Установка флага при прикреплении файлов |
| `РегистрыСведений.ПропускиРегистрационныхНомеров` | Резервирование/освобождение номеров |

### Код, обрабатывающий шаг
- `ОбщиеМодули.РаботаСУведомлениями.Модуль` — создание объекта ВходящегоПисьма из уведомления
- `ОбщиеМодули.ПротоколированиеРаботыСотрудников.ЗаписатьРегистрациюДокумента()` — аудит
- `ОбщиеМодули.МЭДОПереопределяемый.ПриРегистрацииДокумента()` — при МЭДО-доставке
- `ОбщиеМодули.ВстроеннаяПочтаСервер.ЗаписатьДатуВРегистрПроверкаПоступленияНовыхПисем()` — при почтовой доставке

### Бизнес-процессы, запускаемые автоматически
- При настроенных правилах автозапуска: `БизнесПроцессы.Рассмотрение` (направляется руководителю)

## Шаг 2. Рассмотрение письма руководителем и вынесение Резолюции

### Объект
**`БизнесПроцессы.Рассмотрение`** — запускается для ВходящегоПисьма как предмета.

Задача руководителю создаётся автоматически при старте процесса:
```bsl
Задача.ТочкаМаршрута = БизнесПроцессы.Рассмотрение.ТочкиМаршрута.Рассмотреть;
Задача.Исполнитель = Руководитель;
```

### Резолюция
Хранится в реквизитах процесса `БизнесПроцессы.Рассмотрение`:
- **`ОбрабатывающийРезолюцию`** — сотрудник, которому передаётся резолюция
- **`ИдентификаторОбрабатывающегоРезолюцию`** — идентификатор для ролей
- **`ВариантОбработкиРезолюции`** — вариант: исполнить, ознакомить и т.п.
- **`ВариантРассмотрения`** — `Перечисления.ВариантыРассмотрения` (Рассмотрено, НаправитьПомощнику...)

При выполнении задачи рассмотрения:
```bsl
РассмотрениеОбъект.ОбрабатывающийРезолюцию = ПараметрыВыполнения.ИсполнительЗадачи;
РаботаСБизнесПроцессами.ЗаписатьПроцесс(РассмотрениеОбъект, "ЗаписьСОбработкойВыполненияЗадачи");
```
*Источник: `БизнесПроцессы.Рассмотрение.МодульМенеджера`*

### Регистры, которые обновляются
| Регистр | Действие |
|---|---|
| `РегистрыСведений.ПротоколРаботыСотрудников` | Событие выполнения задачи рассмотрения |
| `РегистрыСведений.ПроцессыДействий` | Состояние процесса Рассмотрение |

### Код, обрабатывающий шаг
- `БизнесПроцессы.Рассмотрение.МодульМенеджера` — `ОбрабатывающийРезолюцию`, `ПолучитьРезолюцииПоБизнесПроцессу()`
- `ОбщиеМодули.ИнтеграцияЗадач.ЗаполнитьДанныеЗаполненияДействийПоРассмотрению()` — читает все параметры резолюции
- `ОбщиеМодули.РаботаСПроцессамиПоДействиям.СоздатьПроцессыРассмотренияПоДействию()` — если нужно

## Шаг 3. Создание Задачи на исполнение по резолюции

### Объект
**`БизнесПроцессы.Исполнение`** — создаётся на основании резолюции из процесса Рассмотрение.  
**`Задача.ЗадачаИсполнителя`** — порождается при старте процесса Исполнение.

```bsl
// В БизнесПроцессы.Исполнение.МодульОбъекта:
Функция СоздатьЗадачу(ТочкаМаршрутаБизнесПроцесса)
    Задача = Задачи.ЗадачаИсполнителя.СоздатьЗадачу();
    Задача.Дата = ТекущаяДатаСеанса();
    Задача.Автор = Автор;
    Задача.Описание = Описание;
    Задача.Важность = Важность;
    Задача.СрокИсполнения = СрокИсполненияПроцесса;
    Задача.БизнесПроцесс = ЭтотОбъект.Ссылка;
    Задача.ТочкаМаршрута = ТочкаМаршрутаБизнесПроцесса;
    // ...
КонецФункции
```

Заполнение задачи по результатам рассмотрения:
```bsl
// БизнесПроцессы.Исполнение.МодульОбъекта:
Процедура ЗаполнитьПоРассмотрению(Рассмотрение) Экспорт
    Автор = Рассмотрение.Исполнитель; // руководитель
    // исполнитель берётся из ОбрабатывающийРезолюцию
```

### Ключевые реквизиты задачи
- **Исполнитель** — из резолюции (`ОбрабатывающийРезолюцию`)
- **Автор** — руководитель (выдавший резолюцию)
- **Предмет** — ВходящееПисьмо
- **СрокИсполнения**
- **Описание** — текст резолюции

### Регистры, которые обновляются
| Регистр | Действие |
|---|---|
| `РегистрыСведений.ПроцессыДействий` | Активный процесс Исполнение |
| `РегистрыСведений.ПротоколРаботыСотрудников` | Старт бизнес-процесса |

### Код, обрабатывающий шаг
- `БизнесПроцессы.Исполнение.МодульОбъекта` — `СоздатьЗадачу()`, `ЗаполнитьПоРассмотрению()`, `СтартПередСтартом()`
- `ОбщиеМодули.РаботаСПроцессамиПоДействиям.СоздатьПроцессИсполненияПоДействию()` — при использовании КомплексногоПроцесса
- `ОбщиеМодули.ПротоколированиеРаботыСотрудников.ЗаписатьСтартБизнесПроцесса()`

## Шаг 4. Исполнитель выполняет задачу и прикладывает файл-ответ

### Объект
**`Задача.ЗадачаИсполнителя`** — исполнитель выполняет задачу.  
**Файл** — прикрепляется к задаче или к предмету (ВходящееПисьмо).

### Бизнес-процессы
- Исполнитель открывает форму `ЗадачаИсполнителя`
- Нажимает "Выполнить" — вызывается точка маршрута `Исполнить`
- При выполнении: `БизнесПроцессы.Исполнение.ИсполнитьПередВыполнением()`

Прикрепление файла:
```bsl
// ОбщиеМодули.ПрисоединенныеФайлыКлиент:
ПрисоединенныеФайлыКлиент.ДобавитьФайлы(Владелец, ИдентификаторФормы);
// При записи файла:
// ОбщиеМодули.ПрисоединенныеФайлыСлужебный.ПриЗаписиПрисоединенногоФайлаСервер()
// → РегистрыСведений.НаличиеФайлов обновляется
```

### Регистры, которые обновляются
| Регистр | Действие |
|---|---|
| `РегистрыСведений.НаличиеФайлов` | `ЕстьФайлы = Истина` при добавлении файла к объекту |
| `РегистрыСведений.ПротоколРаботыСотрудников` | Событие `ЗаписатьИзменениеФайла` |
| `РегистрыСведений.ПроцессыДействий` | Состояние задачи → Выполнена |

### Код, обрабатывающий шаг
- `БизнесПроцессы.Исполнение.МодульОбъекта` — `ИсполнитьПередВыполнением()`, `ЗаписатьХодОбработкиВыполнение()`
- `ОбщиеМодули.ИнтеграцияЗадач.ЗаписатьХодОбработкиВыполнение()` — сохранение хода исполнения
- `ОбщиеМодули.ПрисоединенныеФайлыСлужебный.ПриЗаписиПрисоединенногоФайлаСервер()` — регистрация файла
- `ОбщиеМодули.РаботаСЗадачамиКлиентСервер.НовыйДанныеВыполненияДействийЗадач()` — структура данных выполнения

## Шаг 5. Формирование ИсходящегоПисьма с ответом

### Объект
**`Документ.ИсходящееПисьмо`** — создаётся как ответ на ВходящееПисьмо.

### Связь с ВходящимПисьмом
Устанавливается через `СвязиОбъектов`:
```bsl
// Настройка типов связей (ОбновлениеИнформационнойБазыДокументооборот):
// Исходящее письмо → ВходящееПисьмо:
ТипСвязи = Справочники.ТипыСвязей.ПисьмоОтправленоВОтветНа;
// Обратная: ВходящееПисьмо получило ответ:
ТипОбратнойСвязи = Справочники.ТипыСвязей.ОтправленоОтветноеПисьмо;

// Установка связи:
СвязиОбъектов.УстановитьСвязь(ВходящееПисьмо, Неопределено, ИсходящееПисьмо, ТипСвязи);
```

При регистрации ИсходящегоПисьма система автоматически отслеживает связь:
```bsl
// ОбщиеМодули.ИнтеграцияЗадач.ОбработатьРегистрациюИсходящегоДокумента():
ДокументыНаКоторыеОтправленОтвет = СвязиОбъектов.ПолучитьСвязанныеОбъекты(
    ЗарегистрированныйДокумент,
    Справочники.ТипыСвязей.ОтправленВОтветНа);
// Если есть — отмечает событие в задачах
```

### Регистрация ИсходящегоПисьма
Аналогично ВходящемуПисьму через нумератор:
- `РегистрСведений.Нумерация` — получение и запись номера
- `РегистрыСведений.ПротоколРаботыСотрудников` — событие `РегистрацияДокумента`

### Отправка
```bsl
// ОбщиеМодули.ВстроеннаяПочтаСервер:
СформироватьТекстИсходящегоПисьма(Основание, ТипТекста, Кодировка, ТипОтвета);
ОтправитьПисьмо(Письмо, УчетнаяЗапись);
```

При МЭДО-отправке:
```bsl
// ОбщиеМодули.МЭДО:
ОтправитьИсходящийДокумент(Документ, Настройки, ДанныеОтвета);
ЗаписатьДанныеИсходящегоДокументаМЭДО(...);
```

### Регистры, которые обновляются
| Регистр | Действие |
|---|---|
| `РегистрыСведений.Нумерация` | Исходящий регистрационный номер |
| `РегистрыСведений.ПротоколРаботыСотрудников` | Регистрация документа, отправка по почте |
| `РегистрыСведений.ДанныеДокументов` (через СвязиОбъектов) | Связь ИсходящееПисьмо → ВходящееПисьмо |

### Код, обрабатывающий шаг
- `ОбщиеМодули.МЭДОПереопределяемый.ЗаписатьВИсходящийДокументРегистрациюКонтрагента()` — при МЭДО
- `ОбщиеМодули.ВстроеннаяПочтаСервер.ОтправитьПисьмо()` — при e-mail
- `ОбщиеМодули.ИнтеграцияЗадач.ОбработатьРегистрациюИсходящегоДокумента()` — закрытие задач по ВходящемуПисьму

## Сводная схема сквозного сценария

```
Контрагент
    ↓ письмо (e-mail / МЭДО)
[ВходящееПисьмо] ← РаботаСУведомлениями.СоздатьДокумент()
    ↓ Регистрация: Нумерация.СформироватьНомер()
    ↓ Регистр: РС.Нумерация, РС.ПротоколРаботыСотрудников
    ↓
[БП.Рассмотрение] ← автозапуск или вручную
    ↓ Задача руководителю (ТочкаМаршрута.Рассмотреть)
    ↓ Руководитель заполняет ОбрабатывающийРезолюцию
    ↓ ВариантРассмотрения = Рассмотрено / НаправитьПомощнику
    ↓
[БП.Исполнение] ← ИнтеграцияЗадач.СоздатьПроцессИсполненияПоДействию()
    ↓ Задача исполнителю (ТочкаМаршрута.Исполнить)
    ↓ Реквизиты: Предмет=ВходящееПисьмо, Автор=Руководитель
    ↓ Исполнитель прикрепляет файл → РС.НаличиеФайлов
    ↓ Исполнитель выполняет → ЗаписатьХодОбработкиВыполнение()
    ↓
[ИсходящееПисьмо] ← создаётся вручную или автоматически
    ↓ Связь: СвязиОбъектов.УстановитьСвязь(ВходящееПисьмо, ТипСвязи.ПисьмоОтправленоВОтветНа)
    ↓ Регистрация: РС.Нумерация (исходящая нумерация)
    ↓ Отправка: ВстроеннаяПочтаСервер.ОтправитьПисьмо() / МЭДО.ОтправитьИсходящийДокумент()
    ↓ ИнтеграцияЗадач.ОбработатьРегистрациюИсходящегоДокумента() → закрывает задачи
    ↓
Контрагент ← получает ответ
```

## Ключевые модули и регистры

### Общие модули
| Модуль | Роль в сценарии |
|---|---|
| `РаботаСУведомлениями` | Создание ВходящегоПисьма из уведомления |
| `ВстроеннаяПочтаСервер` | Приём и отправка e-mail писем |
| `МЭДО` / `МЭДОПереопределяемый` | Межведомственный электронный документооборот |
| `ИнтеграцияЗадач` | Регистрация исходящего, ОбработатьРезолюцию, связь задач |
| `РаботаСПроцессамиПоДействиям` | Создание процессов по действиям |
| `ПротоколированиеРаботыСотрудников` | Аудит всех действий |
| `ПрисоединенныеФайлыСлужебный` | Прикрепление файлов к объектам |
| `СвязиОбъектов` (общий механизм) | Связи между документами |

### Бизнес-процессы
| БП | Роль |
|---|---|
| `БизнесПроцессы.Рассмотрение` | Рассмотрение ВходящегоПисьма руководителем, резолюция |
| `БизнесПроцессы.Исполнение` | Исполнение по резолюции |
| `БизнесПроцессы.КомплексныйПроцесс` | Оркестрация нескольких процессов |

### Регистры сведений
| Регистр | Данные |
|---|---|
| `Нумерация` | Счётчики регистрационных номеров по нумераторам |
| `ПропускиРегистрационныхНомеров` | Зарезервированные/пропущенные номера |
| `ПротоколРаботыСотрудников` | Аудит-лог всех событий |
| `НаличиеФайлов` | Флаг наличия файлов у объектов |
| `ПроверкаПоступленияНовыхПисем` | Дата последней проверки почты по пользователю |
| `ПроцессыДействий` | Активные процессы по действиям (КомплексныйПроцесс) |

## Примечания по качеству RAG

- Индекс кода (`code`: 136520 чанков) позволил получить конкретный BSL-код по всем шагам сценария
- Индекс метаданных (`metadata`: 0 чанков) — **не проиндексирован**, что не дало возможности получить схему реквизитов документов ВходящееПисьмо / ИсходящееПисьмо напрямую
- Индекс документации (`help`: 1725 чанков) оказался слабым для данного запроса — ответил только общими справками
- Чанкинг кода работает хорошо для поиска конкретных процедур, но не всегда находит "точку входа" (модуль документа)
