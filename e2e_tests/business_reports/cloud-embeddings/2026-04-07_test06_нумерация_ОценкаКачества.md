## Что сервер дал хорошо

1. **codesearch** — главная рабочая лошадка. Дал полную картину архитектуры нумерации:
   - ОбщиеМодули.Нумерация с функциями СформироватьЧисловойНомерДокумента, СформироватьСтроковыйНомерДокумента, РазобратьФорматНомера
   - Справочники.Нумераторы — реквизиты ФорматНомера, Периодичность, 9 флагов независимой нумерации
   - РегистрыСведений.НастройкиНумерации — полная структура с 10 контекстными полями
   - РегистрыСведений.Нумерация — счётчик ТекущийНомер с блокировкой при инкременте
   - Перечисления: СпособыНумерации, НазначенияНумераторов, ПериодичностьНумераторов
   - Переменные формата номера: [Номер], [День], [Месяц], [Год4], [Год2], [Квартал], [ИндексВидаДок]
   - БизнесПроцесс.Регистрация с задачами и ОбщиеМодули.Делопроизводство.ЗарегистрироватьПредмет

2. **helpsearch** — нашёл справку о процессе регистрации, правилах кнопки "N", временных номерах, бизнес-правилах (секретарь/авторы)

3. **Бизнес-отчёт** — самый подробный из трёх: содержит полную архитектурную схему, таблицу переменных формата, примеры форматов номеров, механизм стандартных префиксов (ПрефиксацияОбъектов)

## Что сервер НЕ дал

1. **metadatasearch** — полностью неработоспособен (коллекция metadata = 0 по данным health). Все 4 вызова вернули пустые ответы. Агент потратил 4 бесполезных вызова, прежде чем отказался от инструмента.

2. **Справка по форме нумератора** — helpsearch не нашёл документацию по UI-настройкам нумераторов.

3. **Точный маршрут БП Регистрация** — codesearch нашёл задачи (Зарегистрировано, НеЗарегистрировано, Ознакомиться, Повторить), но полная схема маршрута не получена.

## Паттерны поведения агента

- **Адаптивная стратегия**: после 2 неудач с metadatasearch быстро переключился на helpsearch, а затем на codesearch — правильное решение
- **codesearch-доминирование**: 10 из 17 вызовов — codesearch, и это оптимально для данного сервера, т.к. codesearch единственный рабочий инструмент с большим индексом (136K чанков)
- **Один крупный вызов**: #5 (codesearch) вернул 61,548 символов — это 38% всего контекста MCP за один вызов. Скачок бюджета, но вызов был высокорелевантным
- **Не остановился вовремя**: вызов #16 (13,421 симв.) оказался нерелевантным (модули Диадок) — поздний шум

## Выявленные проблемы RAG
| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| metadatasearch неработоспособен | Коллекция metadata = 0, все 4 вызова пустые |
| Крупные чанки в codesearch | Вызов #5 вернул 61K символов — избыточный размер ответа |
| Шум в codesearch | Вызов #16 вернул модули Диадок вместо нумерации — семантическое пересечение терминов |
| Дубли в helpsearch | Вызов #8 дублирует уже полученную информацию |

## Вывод

Cloud-embeddings справился ПОЛНОСТЬЮ с тестом о нумерации за счёт мощного codesearch (136K чанков кода). Сервер надёжно находит процедуры, модули, регистры по кодовой базе. Главная слабость — отсутствие метаданных (metadatasearch пустой) и крупные чанки codesearch, раздувающие контекст. Для структурных вопросов о метаданных (типы реквизитов, перечисления) сервер подходит хуже, чем для кодовых.
