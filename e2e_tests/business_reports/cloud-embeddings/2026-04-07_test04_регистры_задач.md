# Регистры, обновляемые при работе с задачами (1С:ДО КОРП 3.0)

**Дата:** 2026-04-07  
**Источник:** MCP-сервер 1c-cloud-embeddings  
**Тест:** TEST-04

---

## 1. Общая архитектура

В 1С:Документооборот КОРП 3.0 документ **Задача** является составным объектом. Каждый участник задачи имеет связанный документ **ДействиеЗадачи** (один на участника). Регистры обновляются при проведении обоих документов:

- `Документ.Задача` — хранит заголовочные данные, статус, участников
- `Документ.ДействиеЗадачи` — хранит данные конкретного исполнителя/проверяющего

---

## 2. Регистры накопления

### 2.1. РегистрНакопления.КоличествоЗадач

**Назначение:** Хранит счётчики задач по авторам для построения итогов и дашбордов.

**Регистратор:** `Документ.Задача`

**Записывается при проведении Задачи** (процедура `ОбработкаПроведения`):

```bsl
// Количество задач.
Движения.КоличествоЗадач.Записывать = Истина;
Движение = Движения.КоличествоЗадач.Добавить();
Движение.Регистратор = Ссылка;
Движения.КоличествоЗадач.ОбновитьДанныеЗадачи(РеквизитыЗадачи);
```

**Ресурсы (остатки):** Всего, ВРаботе, ОжидающихВыполнения, ОжидающихПроверки, Выполненных, Новых, Просроченных, Черновиков

**Менеджер регистра** (`РегистрыНакопления.КоличествоЗадач.МодульМенеджера`) предоставляет функции:
- `ЗадачиАвторовИтоги` — итоги по всем авторам
- `ЗадачиАвторовИтогиПоАвторам`, `...ПоВидамЗадач`, `...ПоПриложениям`, `...ПоПроектам`
- `ПометитьПросроченнуюЗадачу`, `ПометитьПросроченныеЗадачи`
- `ОбработатьОбновлениеЗадачи` — обработка очереди кэширующих данных

**Механизм обновления при смене статуса:**  
При изменении состояния задачи через очередь кэширующих данных вызывается `ОбработатьОбновлениеЗадачи(Задача)`, который перечитывает реквизиты и переписывает набор записей в транзакции с блокировкой.

### 2.2. РегистрНакопления.КоличествоДействийЗадач

**Назначение:** Хранит счётчики действий задач по исполнителям — основной регистр для списков "Задачи мне" и "Задачи отдела".

**Регистратор:** `Документ.ДействиеЗадачи`

**Записывается при проведении ДействияЗадачи** (процедура `ОбработкаПроведения`):

```bsl
// Количество действий задач.
Движения.КоличествоДействийЗадач.Записывать = Истина;
РегистрыНакопления.КоличествоДействийЗадач.ЗаполнитьНаборПоДействию(
    Движения.КоличествоДействийЗадач, Ссылка, РеквизитыДействия, РеквизитыЗадачи);
```

**Ключевая процедура `ЗаполнитьНаборПоДействию`** (экспортная, в модуле менеджера РН):

```bsl
// Заполняет набор записей по действию задачи.
// Параметры:
//  НаборЗаписей - РегистрНакопленияНаборЗаписей.КоличествоДействийЗадач
//  ДействиеЗадачи - ДокументСсылка.ДействиеЗадачи
//  РеквизитыДействия - Структура
//  РеквизитыЗадачи - Структура
Процедура ЗаполнитьНаборПоДействию(НаборЗаписей, ДействиеЗадачи,
        РеквизитыДействия = Неопределено, РеквизитыЗадачи = Неопределено) Экспорт
```

Для каждого замещающего исполнителя (из РС.ВсеИсполнителиДействийЗадач) создаётся отдельная запись с признаком замещения.

**Ресурсы (остатки):** ВРаботеОстаток, ВыполненныхОстаток, ВСрокОстаток, ИстекающихОстаток, ОжидающихПроверкиОстаток, ПоступилиОбновленияОстаток

**Менеджер регистра** предоставляет функции:
- `ЗадачиМнеИтоги` — итоги для текущего пользователя
- `ЗадачиОтделаИтоги` — итоги по подразделению
- `ЗадачиИсполнителейИтоги` — итоги по всем исполнителям
- `ЗадачиИсполнителейИтогиПоАвторам`, `...ПоВидамДействий`, `...ПоИсполнителям`, `...ПоПроектам`, `...ПоПриложениям`, `...ПоФлагам`, `...ПоКонтрагентам`
- `ПометитьИстекающуюЗадачу`, `ПометитьПросроченнуюЗадачу`
- `ОбработатьОбновлениеДействияЗадачи`, `ОбработатьОбновлениеЗадачи`

## 3. Регистры сведений

### 3.1. РегистрСведений.ДействияЗадач

**Назначение:** Кэширующий регистр, хранит актуальный "срез" данных по каждому действию задачи. Используется для быстрого чтения при отображении списков задач.

**Регистратор:** `Документ.ДействиеЗадачи`

**Записывается при проведении ДействияЗадачи**:

```bsl
// Действия задач.
Движения.ДействияЗадач.Записывать = Истина;
Движение = Движения.ДействияЗадач.Добавить();
Движение.Регистратор = Ссылка;
Движение.ЕстьПодзадачи = РаботаСЗадачами.ЕстьПодзадачи(Ссылка);
Движение.Трудозатраты = Трудозатраты();
ПараметрыКонтроляДляКэша = Справочники.Контроль.ПараметрыКонтроляДляКэша(Ссылка);
Движение.СостояниеКонтроля = ПараметрыКонтроляДляКэша.СостояниеКонтроля;
Движение.КонтрольныйСрок = ПараметрыКонтроляДляКэша.СрокИсполнения;
Движение.КонтрольныйСрокОбщий = ПараметрыКонтроляДляКэша.СрокИсполненияОбщий;
Движения.ДействияЗадач.ОбновитьДанныеДействия(РеквизитыДействия);
Движения.ДействияЗадач.ОбновитьДанныеЗадачи(РеквизитыДействия, РеквизитыЗадачи);
```

**Модуль набора записей** (`РегистрыСведений.ДействияЗадач.МодульНабораЗаписей`) содержит:

```bsl
// ОбновитьДанныеДействия — устанавливает поля по реквизитам действия:
Запись.РезультатДействия = РеквизитыДействия.РезультатДействия;
Запись.СостояниеУчастникаЗадачи = РеквизитыДействия.СостояниеУчастникаЗадачи;
Запись.Флаг = РеквизитыДействия.Флаг;
Запись.ЕстьЗамещающие = РегистрыСведений.ВсеИсполнителиДействийЗадач
    .ЕстьЗамещающиеПоДействию(Запись.Регистратор);
// Вычисляет Просрочено, МожетБытьПросрочена, Истекает:
Просрочено = Документы.ДействиеЗадачи.Просрочено(
    Запись.Срок, РеквизитыДействия.СостояниеУчастникаЗадачи,
    РеквизитыДействия.ДатаВыполнения);
Запись.Просрочено = Просрочено;
Запись.ПросроченоИОжидаетВыполнения = Просрочено И Запись.ОжидаетВыполнения;
```

**Менеджер регистра** предоставляет:
- `ОбновитьДанныеЗадачи` — обновление данных задачи в записях
- `ОбновитьСостояниеКонтроля` — обновление контрольного срока
- `ОбновитьТрудозатраты`
- `ОбработатьОбновлениеДействияЗадачи`, `ОбработатьОбновлениеЗадачи`
- `ПометитьИстекающуюЗадачу`, `ПометитьПросроченнуюЗадачу`

---

### 3.2. РегистрСведений.ЗадачиПоАвторам

**Назначение:** Кэширующий регистр, хранит данные задач в разрезе авторов.

**Регистратор:** `Документ.Задача`

**Записывается при проведении Задачи**:

```bsl
// Задачи по авторам.
Движения.ЗадачиПоАвторам.Записывать = Истина;
Движение = Движения.ЗадачиПоАвторам.Добавить();
Движение.Регистратор = Ссылка;
```

**Менеджер регистра** предоставляет:
- `ДанныеЗадач`, `ЗадачиАвтора`
- `ОбновитьСостояниеКонтроля`, `ОбновитьТрудозатраты`, `ОбновитьПодзадачи`
- `ОбработатьОбновлениеЗадачи` — обновление в очереди кэша
- `ПометитьПросроченнуюЗадачу`, `ПометитьПросроченныеЗадачи`
- `ЭтоПросроченныеИОжидающиеВыполненияЗадачи`, `ЭтоОжидающиеПроверкиЗадачи`

---

### 3.3. РегистрСведений.ВсеИсполнителиДействийЗадач

**Назначение:** Хранит данные о замещающих и помощниках для каждого действия задачи. Обеспечивает доступ замещающих к задачам исходного исполнителя.

**Записывается:**
- При записи элемента справочника `ЗамещающиеИПомощники` (когда замещение вступает/прекращает действие)
- Через процедуру `ЗаписатьДоступЗамещающихПоДействиюЗадачи` (модуль `ОбщиеМодули.ЗамещающиеИПомощники`)

```bsl
// Замещающие и помощники по действию.
НаборВсеИсполнители = РегистрыСведений.ВсеИсполнителиДействийЗадач.СоздатьНаборЗаписей();
НаборВсеИсполнители.Отбор.ДействиеЗадачи.Установить(ДействиеЗадачи);
// ... заполнение + Записать
```

**Менеджер регистра** (`РегистрыСведений.ВсеИсполнителиДействийЗадач.МодульМенеджера`):
- `ЗамещенияПоДействию(ДействиеЗадачи, ВидЗамещения)` — получить замещающих
- `ЕстьЗамещающиеПоДействию(ДействиеЗадачи)` — проверка наличия замещающих

**Влияние на РН.КоличествоДействийЗадач:** При наличии замещающих в `ЗаполнитьНаборПоДействию` для каждого замещающего создаётся дополнительная строка в наборе движений.

## 5. Схема обновления регистров при смене статуса задачи

### 5.1. Создание задачи (первое проведение)

```
Документ.Задача.ОбработкаПроведения()
├── РН.КоличествоЗадач — добавить 1 в ресурс "Новых"
├── РС.ЗадачиПоАвторам — добавить строку
└── [для каждого участника — проводится ДействиеЗадачи]
    ├── РН.КоличествоДействийЗадач — ЗаполнитьНаборПоДействию()
    │   └── 1 запись на исполнителя + по 1 на каждого замещающего
    └── РС.ДействияЗадач — добавить строку с текущим состоянием
```

### 5.2. Исполнитель берёт задачу в работу ("В работе")

```
ДействиеЗадачи.УстановитьСостояние(СостояниеВРаботе)
└── Документ.ДействиеЗадачи.Записать(РежимПроведения)
    ├── РН.КоличествоДействийЗадач — пересчёт ресурсов
    │   └── ВРаботеОстаток +1, ОжидающихВыполнения -1
    └── РС.ДействияЗадач — обновить СостояниеУчастникаЗадачи

После записи ДействияЗадачи:
└── ОбработатьИзменениеСостоянияДействияЗадачи()
    └── ДобавитьЗаданиеОбновитьЗадачуПоСостояниюДействия()  ← асинхронно
        └── Документы.Задача.МодульМенеджера.ОбновитьЗадачуПоСостояниюДействия()
            └── Документ.Задача.Записать(РежимПроведения)
                ├── РН.КоличествоЗадач — обновить СостояниеЗадачи = ВРаботе
                └── РС.ЗадачиПоАвторам — обновить состояние
```

### 5.3. Исполнитель выполняет задачу

```
ДействиеЗадачи.УстановитьСостояние(СостояниеВыполнена)
└── Документ.ДействиеЗадачи.Записать(РежимПроведения)
    ├── РН.КоличествоДействийЗадач — ВыполненныхОстаток +1, ВРаботеОстаток -1
    └── РС.ДействияЗадач — СостояниеУчастникаЗадачи = Выполнена

Асинхронно:
└── Документ.Задача ПриЗаписи
    ├── СостояниеЗадачи = ОжидаетПроверки? → ОтметитьОжидаетПроверки()
    │   └── Всем исполнителям проверяющего ДействиеЗадачи.Провести()
    └── СостояниеЗадачи = Закрыта? → ОтметитьВыполнена() + ОтметитьПроверено()
        ├── РН.КоличествоЗадач — ОжидающихПроверки/ВРаботе -1, Выполненных +1
        └── РС.ЗадачиПоАвторам — обновить
```

### 5.4. Отмена задачи

```
Документ.Задача.ОтметитьОтменена()
└── для каждого участника:
    └── ДействиеЗадачи.УстановитьСостояние(СостояниеОтменена)
        └── Документ.ДействиеЗадачи.Записать(РежимПроведения)
            ├── РН.КоличествоДействийЗадач — все ресурсы -1 для этого действия
            └── РС.ДействияЗадач — обновить состояние

└── Документ.Задача.Записать(РежимПроведения)
    ├── РН.КоличествоЗадач — ВРаботе/ОжидающихВыполнения -1
    └── РС.ЗадачиПоАвторам — обновить состояние
```

## 7. Выводы

1. **Два документа — два набора регистров.** Задача и ДействиеЗадачи — разные регистраторы. Состояние исполнителя хранится в РН/РС через ДействиеЗадачи, состояние задачи в целом — через Задачу.

2. **Асинхронность.** Обновление состояния Задачи по состоянию действий происходит через очередь заданий (`ОбработкаОчередиЗаданийСервер`), а не синхронно. Это критично при диагностике расхождений.

3. **Кэшируемые данные.** Все регистры являются кэшами: при изменении данных они перезаписываются через механизм `ОчередьОбновленияКэширующихДанных`. Прямое изменение регистров без проведения документов — антипаттерн.

4. **Замещающие.** РС.ВсеИсполнителиДействийЗадач напрямую влияет на РН.КоличествоДействийЗадач — для каждого замещающего создаётся отдельная запись движения, что обеспечивает попадание задачи в список замещающего.

5. **Ресурсы счётчиков** в РН.КоличествоЗадач и РН.КоличествоДействийЗадач — остатки (не обороты), хранящие текущее количество задач в каждом статусе. Перепроведение документа полностью перезаписывает движения.
