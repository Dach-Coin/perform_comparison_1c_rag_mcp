## Что сервер дал хорошо

- **codesearch** — единственный рабочий инструмент на сервере, но через него удалось восстановить:
  - Реквизиты справочника: Должность, Подразделение, ГрафикРаботы, ПредставлениеВДокументах, ПредставлениеВПереписке, ДатаНачалаДействия, ДатаОкончанияДействия, Действует
  - Табличная часть КонтактнаяИнформация (подтверждена из кода БСП)
  - Связь с ФизическиеЛица через Владелец (из обращений `Сотрудник.Владелец` в коде)
  - Механизм замещения через Справочник.ЗамещающиеИПомощники — реквизиты, ТЧ ВопросыЗамещения, ОбластиЗамещения
  - 7+ регистров сведений: ОсновныеСотрудники, ЗанятостьСотрудников, ДоступноеВремяСотрудников, ПолномочияСотрудников, СотрудникиПользователей, СотрудникиВКонтейнерах, НастройкиРабочегоКалендаряСотрудника
  - Модуль объекта с обработчиками ПередЗаписью, ПриЗаписи, логика вычисления Действует
  - Общий модуль Сотрудники с API-функциями (ДолжностьСотрудника, ПодразделениеСотрудника, БлижайшийРуководитель)

## Что сервер НЕ дал

- **metadatasearch полностью нефункционален** — 4 из 14 вызовов потрачены на metadatasearch, все вернули пустой ответ (12 символов). Коллекция metadata содержит 0 записей (по данным health endpoint: `"metadata":0`). Это системная проблема сервера, не проблема запросов.
- **helpsearch не содержит справки по справочнику Сотрудники** — 2 вызова с низкой/нулевой релевантностью. Справочная система не индексирована для этого объекта.
- **Точный список реквизитов с типами** — получен косвенно из кода (обращения к полям), а не из метаданных. Типы данных восстановлены по контексту.
- **Табличная часть ДополнительныеРеквизиты** — не обнаружена (cloud нашёл только КонтактнуюИнформацию).
- **Реквизит Помещение** (ТерриторииИПомещения) — не найден в коде.

## Паттерны поведения агента

- Начал с metadatasearch (4 попытки, включая латинский запрос) — все безрезультатно
- Переключился на codesearch, который стал основным источником данных (8 вызовов, 7 полезных)
- Стратегия codesearch — поиск по обращениям к реквизитам в коде: `Справочники.Сотрудники`, `РегистрСведений.*Сотрудн*`, `ЗамещающиеИПомощники`
- helpsearch использовал как проверочный источник (2 вызова) — не помог
- Хорошая декомпозиция задачи: отдельно реквизиты, замещение, регистры, связи
- Избыточные MCP-ответы: каждый codesearch возвращал ~22K символов при ~10 чанках

## Выявленные проблемы RAG
| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| Пустая коллекция metadata | metadatasearch невозможно использовать (0 записей в индексе). Критическая проблема сервера. |
| Слабый helpsearch | Не содержит справки по справочнику Сотрудники — возвращает нерелевантные результаты (ФизическиеЛица, ВидыДокументов) |
| Косвенное получение метаданных | Реквизиты с типами невозможно получить напрямую, только реконструкция из BSL-кода |
| Крупные чанки codesearch | Каждый ответ ~22K символов при ~10 чанках — высокий расход токенов при частичной релевантности |
| Неполнота восстановления | Через код не видны реквизиты, к которым нет обращений в модулях (Помещение не обнаружен) |

## Вывод

Сервер cloud-embeddings для задач анализа структуры справочника **не подходит** — metadatasearch полностью нерабочий (коллекция пуста). Агент вынужден восстанавливать метаданные из BSL-кода через codesearch, что приводит к неполным результатам (пропущены реквизиты без обращений в коде) и высокому расходу токенов (~356K на MCP-ответы). Для вопросов о коде и бизнес-логике codesearch работает хорошо, но для структурного анализа метаданных сервер непригоден.
