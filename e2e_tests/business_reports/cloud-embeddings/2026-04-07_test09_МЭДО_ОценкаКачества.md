## Что сервер дал хорошо
- **codesearch** — основная рабочая лошадка. Нашёл все 8 общих модулей МЭДО (МЭДО, МЭДОВызовСервера, МЭДОКлиент, МЭДОДокументооборот, МЭДОПереопределяемый, МЭДОСтруктурыДанных, МЭДОПовтИсп)
- Из кода модулей восстановлены реквизиты всех трёх документов (УведомлениеМЭДО, ДанныеДокументаМЭДО, КвитанцияМЭДО)
- Найдена полная цепочка процедур отправки: МЭДОВызовСервера → МЭДО.ОтправитьИсходящиеДокументы → СоздатьПаспортКонтейнера → ЗаписатьСообщение
- Регламентное задание ВыполнениеОбменаМЭДО + полный цикл его обработчика
- Константы подсистемы через МЭДОПовтИсп (АвтоматическиОтправлятьКвитанцииМЭДО, ВариантАвтосозданияУведомленийМЭДО, РазмерПорцииОбработкиМЭДО, ВремяХраненияЖурналаСобытийМЭДО)
- Подтверждён файловый транспорт (ZIP-архивы ЭСД, каталоги отправки/получения)

## Что сервер НЕ дал
- **metadatasearch полностью нерабочий** — все 4 вызова вернули `{"result":[]}` (коллекция metadata = 0 в health). Это критический дефект сервера: метаданные не проиндексированы
- Табличные части документов не обнаружены через код (cloud-embeddings не знает про 9 ТЧ УведомлениеМЭДО и ТЧ Пакеты ДанныеДокументаМЭДО, которые нашли другие серверы)
- Типы данных реквизитов (Строка(36), ОпределяемыйТип.ПредметМЭДО и т.д.) — из кода получается только имя, не полный тип
- Перечисления (СостоянияДокументовМЭДО, ВерсииФорматаМЭДО, СпособыОбменаМЭДО) — значения не раскрыты
- Справочники МЭДО (ВидыДокументовМЭДО, МестаСоставленияДокументовМЭДО, ПричиныОтказаВРегистрацииМЭДО) — упомянуты в коде, но структура неизвестна
- Регистры сведений (ЖурналСобытийМЭДО, СостоянияДокументовМЭДО) — упомянуты в коде, измерения/ресурсы неизвестны

## Паттерны поведения агента
- Быстро отказался от metadatasearch после 3 пустых попыток (правильная стратегия)
- Сконцентрировался на codesearch с разными ключевыми словами — эффективно
- Наименьшее число вызовов среди трёх серверов (12), при этом самый большой объём ответов (~215K символов) — codesearch возвращает крупные чанки
- Один «шумный» вызов codesearch (#11, HTTPСервис) — правильно интерпретирован как отрицательный результат
- Самый быстрый агент (~8.5 мин vs ~12 мин у других)

## Выявленные проблемы RAG
| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| metadatasearch не проиндексирован (metadata=0) | Все 4 вызова metadatasearch → пустой результат. Невозможно получить структуру объектов (реквизиты, ТЧ, типы) |
| Чанки кода слишком крупные | codesearch возвращает ~20-50K на запрос, большая часть — нерелевантные фрагменты соседних модулей |
| Нет helpsearch для МЭДО | Документация по МЭДО отсутствует в справке (helpsearch не тестировался, но другие серверы подтвердили) |

## Вывод
Cloud-embeddings справляется с вопросами о коде и логике процедур МЭДО через codesearch — нашёл все модули, процедуры обмена и константы. Но без metadatasearch (metadata=0) сервер не может дать структуру объектов метаданных (реквизиты, ТЧ, типы), что критично для вопросов о структуре документов. Для TEST-09 это означает, что из 5 подвопросов полностью раскрыты 3 (процесс отправки, HTTP-сервисы, регламентные задания), а 2 (документы МЭДО, структура документов) — только частично.
