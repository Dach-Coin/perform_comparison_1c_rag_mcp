# Права доступа к задачам в 1С:Документооборот КОРП 3.0

**Дата:** 2026-04-07  
**Сервер:** 1c-cloud-embeddings  
**Тест:** TEST-08

---

## 1. Общая архитектура системы прав доступа к задачам

В DO3 права доступа к задачам реализованы через собственный механизм — **систему дескрипторов доступа**, независимую от стандартного RLS платформы 1С. Ключевой модуль системы — `ОбщиеМодули.ДокументооборотПраваДоступа`.

Система работает в двух режимах:
- **Без RLS** — права не проверяются, все объекты доступны всем
- **С RLS** (включается константой `ОграничиватьДоступНаУровнеЗаписей`) — проверка через дескрипторы

Проверка активности режима: `ДокументооборотПраваДоступаПовтИсп.ВключеноИспользованиеПравДоступа()`.

---

## 2. Роли, определяющие доступ к задачам

Система прав задач в DO3 имеет несколько уровней доступа:

### 2.1. Роль «КонтрольЗадачИБизнесПроцессов»
Это **привилегированная роль**, дающая полноправный доступ к задачам любых пользователей. Проверяется в коде:

```bsl
ЭтоПолноправныйПользователь = Пользователи.РолиДоступны(
    "КонтрольЗадачИБизнесПроцессов", Неопределено, Ложь);
```

Пользователь с этой ролью может:
- видеть задачи любых сотрудников
- управлять бизнес-процессами без ограничений

### 2.2. Стандартные роли (через профили групп доступа)
Рядовые сотрудники получают доступ через профили групп доступа. Профиль объединяет несколько ролей. Пользователь без роли `КонтрольЗадачИБизнесПроцессов` видит только:
- свои задачи (раздел «Задачи мне»)
- задачи от себя (раздел «Задачи от меня»)
- задачи подчинённых (если является руководителем — `ДоступныЗадачиПодчиненных`)

### 2.3. Доступ руководителей
Функция `ДоступныЗадачиПодчиненных` в `ОбщиеМодули.РаботаСЗадачами` обеспечивает руководителям видимость задач их прямых подчинённых.

## 3. Может ли сотрудник видеть задачи других сотрудников?

**По умолчанию — нет.** Обычный сотрудник видит только:
- задачи, в которых он является исполнителем, автором или наблюдателем
- задачи своих подчинённых (если он руководитель)

Проверка доступа на просмотр конкретной задачи:

```bsl
ЕстьПраво = ДокументооборотПраваДоступа.ПраваПользователяПоОбъекту(
    Параметры.Ключ).Чтение;
Если Не ЕстьПраво Тогда
    ВызватьИсключение(НСтр("ru = 'У вас нет прав для просмотра задачи'"),
        КатегорияОшибки.НарушениеПравДоступа);
КонецЕсли;
```

**Исключения** — сотрудник может видеть чужую задачу если:
1. Имеет роль `КонтрольЗадачИБизнесПроцессов`
2. Является участником рабочей группы предмета (документа) задачи
3. Является руководителем исполнителя
4. Является делегатом пользователя (функция `РасширитьТаблицуПравРуководителямиИДелегатами`)

## 4. Ограничение на уровне записей (RLS) для задач

В DO3 используется **собственный RLS-механизм**, реализованный через:

### 4.1. Дескрипторы доступа
Для каждого объекта (задачи, документа, процесса) формируются **дескрипторы доступа** — записи в `Справочнике.ДескрипторыДоступаОбъектов`. Они хранят:
- кто имеет доступ (пользователь/группа)
- уровень доступа (Чтение / Изменение)

### 4.2. Расчёт прав
При обращении к задаче проверяется:
```
РегистрСведений.РабочиеГруппы → ДескрипторыДоступаОбъектов → ПраваПоДескрипторамДоступаОбъектов
```

Функция расчёта: `ДокументооборотПраваДоступа.ПраваПользователяПоОбъекту()`.

### 4.3. Режимы RLS
| Режим | Константа | Поведение |
|-------|-----------|-----------|
| Без RLS | `ОграничиватьДоступНаУровнеЗаписей = Ложь` | Все видят всё |
| Стандартный RLS | `ОграничиватьДоступНаУровнеЗаписей = Истина` | Проверка через дескрипторы |
| Производительный RLS | `ОграничиватьДоступНаУровнеЗаписейУниверсально = Истина` | Ускоренный вариант |

### 4.4. Очередь обновления прав
При изменении состава рабочей группы запускается пересчёт прав через `РегистрСведений.ОчередьОбновленияПравДоступа` — оперативно или фоновым заданием.

## 5. Связь рабочих групп с доступом к задачам

**Рабочая группа** — это список участников (пользователи, роли, группы), которым разрешён доступ к объекту. Хранится в `РегистрСведений.РабочиеГруппы`.

### 5.1. Алгоритм заполнения дескрипторов по рабочей группе

```bsl
// В менеджере объекта:
Процедура ЗаполнитьДескрипторыОбъекта(ОбъектДоступа, ТаблицаДескрипторов)
    // Стандартные дескрипторы из рабочей группы:
    ДокументооборотПраваДоступа.ЗаполнитьДескрипторыОбъектаПоРабочейГруппе(
        ОбъектДоступа, ТаблицаДескрипторов);
    
    // Если рабочая группа пуста — доступен всем пользователям:
    ДоступЗаполнен = ТаблицаДескрипторов.Количество() > 0;
    Если Не ДоступЗаполнен Тогда
        ДокументооборотПраваДоступа.ДобавитьИндивидуальныйДескриптор(
            ОбъектДоступа, ТаблицаДескрипторов, 
            Справочники.РабочиеГруппы.ВсеПользователи, Истина);
    КонецЕсли;
КонецПроцедуры
```

**Вывод:** если рабочая группа не заполнена — объект видят все. Если заполнена — только участники.

### 5.2. Автоматическое ведение рабочей группы
Модуль `РаботаСРабочимиГруппами` автоматически добавляет в рабочую группу:
- авторов запущенных процессов
- исполнителей задач по документу
- ответственного (через `ДобавитьИндивидуальныйДескриптор`)

Для бизнес-процессов — модуль `ПраваДоступаНаБизнесПроцессы` перезаписывает рабочие группы предметов при записи процесса.

### 5.3. Расширение рабочей группы при переадресации
При перенаправлении задачи новому исполнителю система проверяет права нового исполнителя на предметы задачи:
```bsl
Мультипредметность.ПроверитьНарушениеПолитикиДоступаПриРасширенииРабочейГруппыПредмета(
    Предмет, Участники);
```
Если у нового исполнителя нет прав на предмет — перенаправление запрещается.

## 6. Модуль РаботаСРабочимиГруппами

**Путь:** `ОбщиеМодули.РаботаСРабочимиГруппами.Модуль`

Ключевые функции модуля:

| Функция | Назначение |
|---------|-----------|
| `ПерезаписатьРабочиеГруппыПредметовБизнесПроцесса` | Обновляет РГ всех предметов при записи процесса |
| `ПерезаполнитьРабочуюГруппуДокумента` | Полный пересчёт РГ документа |
| `ПолучитьРабочуюГруппуДокумента` | Чтение текущего состава РГ |
| `ДобавитьУчастниковВРабочуюГруппуОбъекта` | Добавление участников в РГ |
| `ПроверитьПраваУчастниковРабочейГруппыНаОбъект` | Проверка прав участников РГ |
| `ОбязательноеЗаполнениеРабочихГруппДокументов` | Настройка обязательности РГ |
| `УстановитьДоступностьРедактированияСпискаДоступа` | Управление доступностью вкладки РГ |
| `ОбновлениеАвтозаполняемыхРабочихГрупп` | Регламентный пересчёт РГ |
| `УчастникиРабочейГруппыПоАлгоритму` | Вычисление участников по алгоритму |

Модуль выступает **фасадом** между бизнес-логикой задач/процессов и механизмом прав доступа. Все операции с составом рабочей группы выполняются через него.

## 7. Итоговая схема прав доступа к задачам

```
Пользователь хочет открыть задачу
         ↓
ДокументооборотПраваДоступаПовтИсп.ВключеноИспользованиеПравДоступа()?
  НЕТ → доступ открыт всем
  ДА  →
         ↓
Пользователи.РолиДоступны("КонтрольЗадачИБизнесПроцессов")?
  ДА → доступ открыт (полноправный)
  НЕТ →
         ↓
ДокументооборотПраваДоступа.ПраваПользователяПоОбъекту(Задача).Чтение?
  ДА → доступ открыт
  НЕТ → исключение "У вас нет прав для просмотра задачи"
```

Права рассчитываются через цепочку:
**РабочиеГруппы → ДескрипторыДоступаОбъектов → ПраваПоДескрипторамДоступаОбъектов**
