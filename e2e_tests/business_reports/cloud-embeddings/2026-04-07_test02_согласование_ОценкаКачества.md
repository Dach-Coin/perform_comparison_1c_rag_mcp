# Оценка качества: TEST-02 — Процесс согласования
**Сервер:** 1c-cloud-embeddings
**Дата:** 2026-04-07
**Оценщик:** Оркестратор (Claude Opus 4.6)

## Общая оценка: ПОЛНОСТЬЮ

## Метрики
| Метрика                | Значение        |
| ---------------------- | --------------- |
| Вызовов MCP            | 10              |
| Полезных               | 7 (70%)         |
| Шумных                 | 3 (30%)         |
| Retry                  | 2               |
| Общее время агента     | 2 мин 20 сек    |
| Токенов агента (total) | ~134K           |

## Что сервер дал хорошо

1. **Код ObjectModule БП Согласование** — найдены ключевые процедуры с фрагментами кода:
   - `СоздатьЗадачиСогласования()` — полная логика разветвления по ВариантСогласования (Параллельно vs Последовательно), включая конструкцию цикла по исполнителям с проверкой `Пройден`
   - `УсловиеОбходЗавершен()` → `ОбходСогласующихЗавершен()` — точка условия выхода из цикла
   - `СогласоватьПередВыполнением()` — цепочка вызовов: `ОбработатьЗавершениеЗадачиОтложеннаяПодготовкаСогласования` → `ОбработатьЗавершениеЗадачиСогласования`
   - `ИтоговыйРезультатСогласования()` — начало алгоритма (обрезано на середине)
   - `ОбработкаРезультатаОбработка()` — точка маршрута ОбработкаРезультата

2. **Код ManagerModule** — найдены функции `ПроцессЗавершилсяУдачно()`, `ПроцессЗавершилсяУдачноСЗамечаниями()`, `ПроцессЗавершилсяУдачноБезЗамечаний()`, `ОписаниеРезультатаЗавершенияПроцесса()` — с полными фрагментами BSL-кода

3. **Справочник ВизыСогласования** — поля Источник, Документ, РезультатСогласования, Комментарий, ЭП; связь через `РегистрСведений.ЭлектронныеПодписи` (ЛЕВОЕ СОЕДИНЕНИЕ)

4. **Модуль РаботаСВизамиСогласования** — функции `ЕстьВизыНаСогласовании`, `УдалитьВизы`, `ОбновитьВизыУчастниковДействия`, `ДобавитьВизу` (клиентская часть)

5. **Перечисление РезультатыСогласования** — три значения подтверждены кодом

6. **Расчёт сроков** — `СрокиИсполненияПроцессов` с деталями последовательного расчёта цепочки дат

7. **Документация helpsearch** — типовые сроки по видам документов, инструкции по созданию процесса

## Что сервер НЕ дал

1. **metadatasearch полностью нефункционален** — все 3 вызова вернули пустые ответы (12 символов). Невозможно получить структуру метаданных (реквизиты, ТЧ) через этот инструмент. **Причина:** коллекция metadata = 0 объектов (видно из health check: `"metadata": 0`)

2. **Полный алгоритм `ИтоговыйРезультатСогласования()`** — код обрезан на середине из-за чанкинга. Агент получил только начало: инициализацию ИтоговыйРезультат = Согласовано, но не полный обход с приоритетами

3. **Полный код `ОбходСогласующихЗавершен()`** — только сигнатура, без тела функции (SQL-запрос к незавершённым задачам не показан)

4. **Структура ТЧ Исполнители** — перечень реквизитов строки (ПорядокСогласования, ВариантУстановкиСрокаИсполнения, ИдентификаторИсполнителя и др.) не получен, т.к. metadatasearch не работает

5. **Модуль `РаботаСВизамиСогласования`** не найден напрямую — только вызовы из других модулей

## Паттерны поведения агента

- **Быстрый отказ от metadatasearch** — после 3 неудачных попыток (в т.ч. с упрощённым запросом "Согласование") агент правильно переключился на codesearch
- **Эффективная стратегия codesearch** — 5 из 5 запросов к codesearch дали высокую релевантность. Запросы были хорошо сфокусированы: по именам функций, по бизнес-терминам
- **Чанки codesearch большие** — от 18K до 52K символов за вызов, что обеспечило богатый контекст, но потребило много токенов
- **Минимальное количество вызовов** — 10 вызовов — наименьшее среди трёх серверов
- **helpsearch как дополнение** — 2 вызова дали средний результат (пользовательская документация), но подтвердили бизнес-контекст

## Выявленные проблемы RAG

| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| metadatasearch = 0 объектов | Все 3 вызова вернули пустой массив. Коллекция metadata не заполнена (health: metadata=0) |
| Чанкинг обрезает тело функций | `ИтоговыйРезультатСогласования()` обрезана на середине. Алгоритм приоритетов (НеСогласовано > СЗамечаниями > Согласовано) пришлось восстанавливать из контекста |
| Большие чанки codesearch | Один вызов (#5) вернул 52K символов (~94K токенов). Это высокий расход контекста, хотя релевантность была высокой |
| Отсутствие прямого доступа к модулям | Модуль `РаботаСВизамиСогласования` не нашёлся прямым запросом — только через вызовы из других модулей |

## Вывод

**cloud-embeddings** показал сильный результат благодаря codesearch — агент получил реальные фрагменты BSL-кода всех ключевых функций: создания задач, обработки завершения, расчёта итогового результата. Это самый информативный ответ по части **логики и кода**. Основная слабость — полностью неработающий metadatasearch (коллекция пуста), из-за чего невозможно получить структуру метаданных. Для вопросов по коду и логике — отличный сервер; для вопросов по структуре метаданных — бесполезен без metadatasearch.
