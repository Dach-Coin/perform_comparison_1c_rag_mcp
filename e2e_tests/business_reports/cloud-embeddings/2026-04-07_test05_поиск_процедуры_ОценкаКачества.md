## Что сервер дал хорошо

- **Мгновенная идентификация**: уже первый запрос `codesearch` по бизнес-описанию («исполнители задачи замещение сотрудников роли назначение») вернул модуль `РаботаСЗадачами` с функцией `ОпределитьФактическихИсполнителей` в первой позиции. Это идеальный сценарий семантического поиска по коду.
- **Полная сигнатура с документацией**: получена через уточняющий запрос (#4) — включая описание параметров и возвращаемого значения.
- **Фрагменты алгоритма**: чанки содержали ключевые ветки логики (роли, замещения, прямое исполнение), достаточные для восстановления полного алгоритма.
- **Полный граф вызовов**: запрос #3 нашёл все 5 модулей-вызывателей за один вызов.
- **Вспомогательные объекты**: идентифицированы `ЗамещающиеИПомощники`, `ИсполнителиРолейИДелегаты`, `ВсеИсполнителиДействийЗадач`, `ФактическиеИсполнители`.

## Что сервер НЕ дал

- **Полный текст функции целиком**: функция разбита на несколько чанков, начало тела (инициализация переменных) частично потерялось между чанками. Это типичная проблема чанкинга для больших функций.
- **Структура справочника `ФактическиеИсполнители`**: реквизиты (Адресат, План, Факт, Отметил) не были получены — `metadatasearch` не вызывался. Впрочем, агент и не нуждался в этом, собрав всё из кода.

## Паттерны поведения агента

- **Стратегия «от общего к частному»**: сначала семантический поиск по описанию → уточнение по имени функции → поиск вызывателей → детали параметров → внутренняя логика. Каждый шаг целенаправлен.
- **Минимализм**: всего 5 codesearch + 1 stats. Ни одного лишнего вызова. Агент не пытался использовать `helpsearch` или `metadatasearch`, сразу сфокусировавшись на `codesearch`.
- **Параллельные вызовы**: stats + первый codesearch запущены одновременно — оптимизация времени.

## Выявленные проблемы RAG

| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| Чанкинг больших функций | Функция `ОпределитьФактическихИсполнителей` разбита на ~9 чанков. Начало тела и инициализация переменных частично выпали из контекста. |
| Отсутствие metadata-коллекции | Коллекция `metadata` содержит 0 элементов (stats). Агент не мог бы получить структуру справочника через `metadatasearch` при необходимости. |

## Вывод

cloud-embeddings — **идеальный сервер для задач поиска кода по бизнес-описанию**. Семантический поиск `codesearch` с первого же запроса находит релевантную функцию по нечёткому описанию. Минимальное количество вызовов (6), нулевой шум, максимальная эффективность. Единственное ограничение — чанкинг не позволяет получить полный текст большой функции за один запрос, но для бизнес-анализа достаточно.
