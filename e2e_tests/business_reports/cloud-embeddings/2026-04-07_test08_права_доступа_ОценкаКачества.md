## Что сервер дал хорошо

1. **Код модулей прав доступа** — codesearch нашёл реальные фрагменты из `ДокументооборотПраваДоступа`, `РаботаСРабочимиГруппами`, `РаботаСЗадачами`, `ИнтеграцияЗадач` с точными именами функций и цепочками вызовов.
2. **Механизм дескрипторов** — подтверждён кодом: `ЗаполнитьДескрипторыОбъектаПоРабочейГруппе` → дескрипторы → `ПраваПоДескрипторамДоступаОбъектов`. Найден паттерн «пустая рабочая группа = доступ всем» с конкретным кодом.
3. **Роль КонтрольЗадачИБизнесПроцессов** — найдена в коде с проверкой `Пользователи.РолиДоступны("КонтрольЗадачИБизнесПроцессов")`, подтверждена как ключ к доступу ко всем задачам.
4. **RLS-механизм** — найдены константы `ОграничиватьДоступНаУровнеЗаписей`, `ОграничиватьДоступНаУровнеЗаписейУниверсально`, параметры сеанса, модуль `ДокументооборотПраваДоступаПовтИсп`.
5. **Функции видимости задач** — `ДоступныЗадачиМне`, `ДоступныЗадачиОтМеня`, `ДоступныЗадачиПодчиненных`, `ДоступныЗадачиПоПроектам` — полный набор.
6. **Проверка прав на конкретную задачу** — найден код из `ИнтеграцияЗадач` с `ПраваПользователяПоОбъекту(Ключ).Чтение` и текстом ошибки «НетПравДляПросмотраЗадачи».

## Что сервер НЕ дал

1. **Полный список ролей** — найдена только 1 роль (`КонтрольЗадачИБизнесПроцессов`) из 7 существующих. Коллекция metadata пуста (0 чанков), поэтому metadatasearch не может вернуть роли из метаданных конфигурации. Остальные 6 ролей (ЧтениеЗадач, РаботаСЗадачами, РаботаСЗадачамиИБизнесПроцессами, ИзменениеВыполнениеЗадач, РаботаСЗадачамиСотрудниковПодразделения, ЧтениеПроцессовИЗадачБезОграничения) — не обнаружены.
2. **Структура РегистрСведений.РабочиеГруппы** — получена косвенно из кода, но без точных типов измерений (что тип Объект включает ДокументСсылка.Задача — не подтверждено напрямую).
3. **Константа ДобавлятьРуководителямДоступПодчиненных** — не найдена (graph нашёл).
4. **Перечисление ВидимостьДействийВПредметах** — не обнаружено (graph нашёл).
5. **Грифы доступа** — не упомянуты (graph нашёл константу ИспользоватьГрифыДоступа).

## Паттерны поведения агента

- Агент начал с metadatasearch (2 вызова), получил пустые ответы, быстро диагностировал проблему через stats и переключился на codesearch — **адекватная адаптация**.
- Далее 6 вызовов codesearch с нарастающей конкретизацией: общие запросы → имена функций → конкретные роли. Стратегия «от широкого к узкому» работала хорошо.
- helpsearch использован 2 раза: первый дал справку о рабочих группах (средняя релевантность), второй — шум. Соотношение 50/50 типично для helpsearch.
- Retry был только 1 (#1→#2→#3) — адекватная реакция на пустой metadata-индекс.
- Общий объём ответов MCP ~117K символов — умеренный, без избыточных запросов.

## Выявленные проблемы RAG

| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| Пустая коллекция metadata (0 чанков) | metadatasearch бесполезен — нет ролей, типов, реквизитов. Критический пробел для вопросов о структуре метаданных |
| codesearch как единственный рабочий инструмент | Вся информация получена из кода. Если роль не упомянута в коде (нет явной проверки) — она невидима |
| helpsearch слабо индексирован по теме прав | 1 из 2 вызовов — шум. Справка о правах доступа в DO3 плохо представлена в 1725 чанках help |
| Нет разделения ролей по объектам | Даже если бы metadata была заполнена, непонятно, сохраняет ли RAG связь «Роль → права на конкретный объект» |

## Вывод

Сервер cloud-embeddings через codesearch хорошо показывает **логику работы** системы прав (какой код проверяет, как вызываются функции, как дескрипторы связаны с рабочими группами). Но для вопросов о **структуре метаданных** (список ролей, типы реквизитов, состав регистров) — сервер бесполезен из-за пустой коллекции metadata. Для данного теста это означает потерю ~30% ответа (роли, точная структура регистров). Бизнес-отчёт получился содержательным по логике, но неполным по фактуре.
