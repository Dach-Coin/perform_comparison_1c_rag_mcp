# Жизненный цикл ВходящегоПисьма в 1С:Документооборот КОРП 3.0

**MCP-сервер:** 1c-cloud-embeddings  
**Дата анализа:** 2026-04-07  
**Конфигурация:** DO3 (Документооборот КОРП 3.0)

---

## 1. Архитектура объекта «ВходящееПисьмо»

В конфигурации DO3 **входящее письмо (корреспонденция)** реализовано НЕ как самостоятельный объект метаданных с именем «ВходящееПисьмо», а через универсальную связку:

- **`Справочник.ДокументыПредприятия`** — основной объект-карточка входящего документа
- **`Документ.Корреспонденция`** — связанный документ, хранящий данные о корреспондентах (отправителях/получателях), способах доставки, дате получения
- **`Справочник.ВидыДокументов`** — вид документа с признаком `ЯвляетсяВходящейКорреспонденцией = Истина`

> Важно: в системе также существует объект `Документ.ВходящееПисьмо` — это **встроенная электронная почта** (e-mail клиент), не имеющий отношения к делопроизводству.

Проверка типа документа выполняется через `ОбщиеМодули.РаботаСКорреспонденцией`:
```bsl
Функция ВидДокументаОтноситсяККорреспонденции(ВидДокумента) Экспорт
    Результат = Новый Структура("ЭтоКорреспонденция, ЭтоВходящаяКорреспонденция", Ложь, Неопределено);
    Реквизиты = ОбщегоНазначения.ЗначенияРеквизитовОбъекта(ВидДокумента,
        "ЯвляетсяВходящейКорреспонденцией, ЯвляетсяИсходящейКорреспонденцией");
    Результат.ЭтоКорреспонденция = Реквизиты.ЯвляетсяВходящейКорреспонденцией
        Или Реквизиты.ЯвляетсяИсходящейКорреспонденцией;
    Если Реквизиты.ЯвляетсяВходящейКорреспонденцией Тогда
        Результат.ЭтоВходящаяКорреспонденция = Истина;
    ...
```

## 3. Жизненный цикл и типовые состояния

Из справки конфигурации (`РегистрыСведений.ТекущиеСостоянияДокументов`) получена типовая цепочка прохождения входящего документа:

```
На регистрации          ←  создан секретарём, ожидает регистрации
    ↓
Зарегистрирован         ←  секретарь присвоил рег. номер и дату
    ↓
На рассмотрении         ←  запущен БП "Рассмотрение" руководителем
    ↓
Рассмотрен              ←  руководитель вынес резолюцию
    ↓
На исполнении           ←  запущен БП "Исполнение" для исполнителей
    ↓
Исполнен                ←  все задачи выполнены, документ исполнен
```

Пример из справки:
| Дата | Состояние | Кто/Что изменило |
|------|-----------|-----------------|
| 23.03.2010 | На регистрации | Фролова Е.М. (секретарь) |
| 23.03.2010 | Зарегистрирован | Фролова Е.М. (секретарь) |
| 23.03.2010 | На рассмотрении | Рассмотрение 000000003 от 23.03.2010 |
| 23.03.2010 | Рассмотрен | Рассмотрение 000000003 от 23.03.2010 |
| 23.03.2010 | На исполнении | Исполнение 000000002 от 23.03.2010 |

Изменение состояния хранится в `РегистрыСведений.ТекущиеСостоянияДокументов`.

## 4. Бизнес-процессы по входящему письму

В DO3 по входящему письму могут запускаться следующие бизнес-процессы (типы из кода):

### БП «Рассмотрение» (`БизнесПроцесс.Рассмотрение`)
- Запускается руководителем после регистрации
- Результат: резолюция с указанием исполнителей и сроков
- При старте проверяется, что документ зарегистрирован (`ЗавершениеВопросаОСтартеПриНезарегистрированныхДокументах`)
- Варианты результата: На исполнение, На ознакомление, Принято к сведению

### БП «Исполнение» (`БизнесПроцесс.КомплексныйПроцесс` / `ДействияИсполнения`)
- Запускается по итогам рассмотрения
- Исполнители получают задачи с указанными сроками
- Поддерживает параллельное/последовательное исполнение
- Контролёр проверяет выполнение

### БП «Согласование» (`БизнесПроцесс.КомплексныйПроцесс` / `ДействияСогласования`)
- Может запускаться при необходимости согласования ответа на входящее
- Варианты: Согласовано, Согласовано с замечаниями, Не согласовано

### БП «Ознакомление» (`ДействияОзнакомления`)
- Рассылка для ознакомления сотрудников с документом
- Результат: подтверждение ознакомления

### БП «Регистрация» (`БизнесПроцесс.Регистрация`)
- Процесс регистрации документа секретарём
- Задача: Зарегистрировано / Не зарегистрировано

Запуск всех процессов координируется через `ОбщиеМодули.ОбработкаОчередиЗаданийСервер` и `ОбщиеМодули.ИнтерактивныйЗапускБизнесПроцессовКлиент`.

## 5. Регистрация входящего письма — нумерация

Регистрация — это присвоение официального регистрационного номера и даты.

### Механизм нумерации (ОбщиеМодули.Нумерация)

```bsl
// Из Справочники.ДокументыПредприятия.Модуль (код регистрации):
ДокументОбъект.Записать();

Если РегистрироватьДокументы Тогда
    Нумератор = Нумерация.ПолучитьНумераторДокумента(ДокументОбъект);
    Если ЗначениеЗаполнено(Нумератор) Тогда // автоматическая нумерация
        ДокументОбъект.ДатаРегистрации = ДатаРегистрации;
        СтруктураПараметров = НумерацияКлиентСервер.ПолучитьПараметрыНумерации(ДокументОбъект);
        Нумерация.СформироватьЧисловойНомерДокумента(СтруктураПараметров, ДокументОбъект.ЧисловойНомер);
        Нумерация.СформироватьСтроковыйНомерДокумента(СтруктураПараметров, ДокументОбъект.РегистрационныйНомер, ОписанияОшибок);
        ДокументОбъект.Зарегистрировал = Сотрудники.ОсновнойСотрудник();
    КонецЕсли;
КонецЕсли;
```

### Кто регистрирует
- Регистрацию выполняет **сотрудник с ролью «Делопроизводитель/Секретарь»**
- В задаче БП «Регистрация» исполнитель нажимает «Зарегистрировано»
- При интерактивной регистрации вызывается `ДелопроизводствоКлиент.ВвестиДанныеРегистрации(РегистрационныйНомер, ДатаРегистрации)`

### Настройка нумерации
Хранится в `РегистрыСведений.НастройкиНумерации`:
- Нумератор (ссылка на `Справочники.Нумераторы`)
- Разрезы: Организация, Подразделение, ВидДокумента, ВопросДеятельности, Проект, Тематика
- Периодичность нумерации (Год, Квартал, Месяц и пр.)
- Формат номера: настраиваемый шаблон (например, `[Год]-[Номер]`)

## 6. Обработчики событий при записи

Прямой модуль объекта для входящей корреспонденции (Справочник.ДокументыПредприятия) не попал в индекс напрямую, однако из кода смежных модулей восстанавливается типичный паттерн DO3:

### ПередЗаписью (серверный обработчик)

Вызывается цепочка общих процедур:

1. **Проверка загрузки обмена данными:**
   ```bsl
   Если ОбменДанными.Загрузка Тогда Возврат; КонецЕсли;
   ```

2. **Фиксация флага «новый объект»:**
   ```bsl
   ОбщегоНазначенияДокументооборот.УстановитьДополнительноеСвойствоЭтоНовый(ЭтотОбъект);
   ```

3. **Сохранение предыдущих значений реквизитов:**
   ```bsl
   ОбщегоНазначенияДокументооборот.УстановитьДополнительноеСвойствоПредыдущиеЗначенияРеквизитов(ЭтотОбъект);
   ```

4. **Подготовка данных корреспонденции** (`РаботаСКорреспонденцией.ПередЗаписьюНаСервере`):
   - Добавляет в ДополнительныеСвойства кэш вида документа
   - Подготавливает данные для записи в `Документ.Корреспонденция`

5. **Подготовка рабочих групп** (`РаботаСРабочимиГруппами.ДокументыПередЗаписью`):
   - Проверяет изменения состава участников

6. **Нумерация** (если регистрируется):
   - `Нумерация.УстановитьВременныйНомерПередЗаписью()`

7. **Внешнее подписание** (`РаботаСВнешнимПодписанием.ПередЗаписьюДокумента`):
   - Для документов с ЭЦП

### ПриЗаписи (серверный обработчик)

1. **Запись корреспонденции** (`РаботаСКорреспонденцией.ПриЗаписи`):
   - Обновляет/создаёт `Документ.Корреспонденция` (данные об отправителях, способе доставки)

2. **Обновление рабочих групп** (`РаботаСРабочимиГруппами.ДокументыПриЗаписи`):
   - Записывает участников в `РегистрыСведений.РабочиеГруппы`

3. **Обновление состояния** (`РегистрыСведений.ТекущиеСостоянияДокументов`):
   - Фиксирует новое состояние документа

4. **Уведомления и задачи** (через ОбработкаОчередиЗаданийСервер):
   - Добавляет задания на обновление данных

5. **Обновление «Моих документов»** (`МоиДокументыСобытия`):
   - Для автора и ответственного

## 7. Регистры, обновляемые при работе с входящим письмом

| Регистр | Когда обновляется | Что хранит |
|---------|-------------------|------------|
| `РегистрыСведений.ТекущиеСостоянияДокументов` | При изменении состояния, при записи | Текущее состояние документа (Зарегистрирован, На рассмотрении и т.д.) |
| `РегистрыСведений.РабочиеГруппы` | При изменении состава участников | Список сотрудников с правами доступа к документу |
| `РегистрыСведений.НастройкиНумерации` | При настройке нумераторов | Правила присвоения номеров |
| `РегистрыСведений.ДанныеДокументов` | При записи/изменении | Денормализованные данные для быстрого поиска |
| `РегистрыСведений.МоиДокументы` | При записи | Список «Мои документы» для автора/ответственного |
| `РегистрыСведений.СвязиОбъектов` | При установке связей | Связи между документами (ответ, основание) |
| `Документ.Корреспонденция` | При ПриЗаписи | Данные о корреспондентах, способах доставки |

## 8. Схема жизненного цикла (итог)

```
1. СОЗДАНИЕ
   Сотрудник / Секретарь
   → Справочник.ДокументыПредприятия создан
   → ВидДокумента.ЯвляетсяВходящейКорреспонденцией = Истина
   → Заполнены: Заголовок, Организация, ВидДокумента, Дата получения
   → Состояние: «На регистрации»

2. РЕГИСТРАЦИЯ
   Делопроизводитель/Секретарь
   → ДелопроизводствоКлиент.ВвестиДанныеРегистрации()
   → Нумерация.СформироватьСтроковыйНомерДокумента() → РегистрационныйНомер
   → Зарегистрировал = текущий сотрудник
   → Состояние: «Зарегистрирован»

3. РАССМОТРЕНИЕ
   Руководитель
   → БП «Рассмотрение» запущен
   → Состояние: «На рассмотрении»
   → Результат: резолюция с указанием исполнителей
   → Состояние: «Рассмотрен»

4. ИСПОЛНЕНИЕ
   Исполнители
   → БП «Исполнение» запущен по итогам рассмотрения
   → Состояние: «На исполнении»
   → Задачи распределены среди исполнителей
   → Контролёр проверяет результаты
   → Состояние: «Исполнен»

5. ОПЦИОНАЛЬНО: СОГЛАСОВАНИЕ
   → БП «Согласование» (если требуется согласовать ответ)
   → Несколько вариантов: Согласовано / С замечаниями / Не согласовано

6. СПИСАНИЕ В ДЕЛО
   → Привязка к номенклатуре дел
   → Передача в архив
```

## Примечания по качеству анализа

- Коллекция `metadata` в индексе пуста (0 записей) — прямой поиск по реквизитам через metadatasearch невозможен
- Модуль объекта `Справочник.ДокументыПредприятия.МодульОбъекта` не попал в выдачу — обработчики ПередЗаписью/ПриЗаписи восстановлены по паттернам из смежных объектов
- Конкретный список полей ВидаДокумента для входящей корреспонденции получен косвенно через SQL-запросы в коде
