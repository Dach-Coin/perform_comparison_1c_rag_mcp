# Сквозной сценарий: от входящего письма до исходящего ответа
## Конфигурация: 1С:Документооборот КОРП 3.0 (Тест ДО3)
**Дата:** 2026-06-05 | **Источник:** bsl-indexer v0.15.0 | **Тест:** TEST-10

> Обозначения: **[MCP]** — данные получены из индекса; **[домысел]** — логика восстановлена из контекста, кода не читалось

---

## Общая схема сценария

```
ВходящееПисьмо (Document)
    ↓ руководитель открывает и добавляет резолюцию
Резолюция (Catalog)  ←→  Справочник.Резолюции
    ↓ по резолюции создаётся бизнес-процесс
БизнесПроцесс.Исполнение
    ↓ генерирует задачу
ЗадачаИсполнителя (Task)
    ↓ исполнитель выполняет (с файлом)
ИсходящееПисьмо (Document)  ←→  ВходящееПисьмо.ПисьмоОснование
```

---

## Шаг 1: Поступление входящего письма

### Объект
**Document.ВходящееПисьмо** — документ-письмо в папке почтового ящика.

**[MCP] Ключевые реквизиты:**
- `Тема`, `Дата` — представление документа (ОбработкаПолученияПредставления: "%1 от %2")
- `Папка` — обязательный реквизит (ПередЗаписью выбрасывает исключение при отсутствии)
- `УчетнаяЗапись` — почтовая учётная запись
- `ТипТекста` — Перечисление.ТипыТекстовПочтовыхСообщений (HTML или ПростойТекст)
- `ТекстПисьмаHTMLХранилище`, `ТекстПисьмаПростойТекстХранилище` — ХранилищеЗначения с текстом
- `Кодировка` — по умолчанию utf-8
- `ОтправительАдресат` — контакт отправителя
- `ПолучателиПисьма`, `ПолучателиКопий` — табличные части с адресатами
- `Предмет` — связанный объект (внутренний документ, контрагент и т.п.)
- `ПисьмоОснование` — ссылка на исходное письмо (для цепочки ответов)

**[MCP] Права доступа:** управляются через `Папка` (ЗаполнитьОсновнойДескриптор → ДокументооборотПраваДоступа.ЗаполнитьПапкуДескриптораОбъекта). Настройки: ЧтениеПапокИПисем, ДобавлениеПапокИПисем, ИзменениеПапокИПисем, ПометкаУдаленияПапокИПисем.

### Код, обрабатывающий создание письма

**[MCP] Модуль:** `Documents/ВходящееПисьмо/Ext/ObjectModule.bsl`

**ПередЗаписью (строки 5–48):**
```bsl
// Ключевые действия:
ВстроеннаяПочтаСервер.ПолучитьСпособАдресацииОбъекта(ЭтотОбъект);  // для нового письма
РаботаСФайламиВызовСервера.ПометитьНаУдалениеПриложенныеФайлы(...); // при изменении пометки
ВстроеннаяПочтаСервер.ПрименитьПравила(ЭтотОбъект);                // применение правил обработки
// Обязательная проверка:
Если Не ЗначениеЗаполнено(Папка) Тогда Отказ = Истина; ...
```

**ПриЗаписи (строки 49–106):**
```bsl
// Обновляет счётчик писем в папках:
РегистрыСведений.КоличествоПисемВПапках.ОчиститьЗаписиПоПапке(ПредыдущаяПапка);
РегистрыСведений.КоличествоПисемВПапках.ОчиститьЗаписиПоПапке(Папка);
// При смене пометки удаления:
ПротоколированиеРаботыСотрудников.ЗаписатьПометкуУдаления(Ссылка, ПометкаУдаления);
// Расширение рабочей группы по предмету (контрагенты из ПолучателиПисьма/ПолучателиКопий):
РаботаСРабочимиГруппами.ПерезаписатьРабочуюГруппуОбъекта(Предмет, ТаблицаНабора, Истина);
```

### Регистры, обновляемые при поступлении письма

| Регистр сведений | Действие | Источник |
|-----------------|----------|---------|
| КоличествоПисемВПапках | Пересчёт счётчика по папке | ПриЗаписи |
| СведенияОбАдресатах | Запись контактов получателей | ПриЗаписи (через ВстроеннаяПочтаСервер) |
| HTMLПредставленияСодержанияПисем | Кэш HTML-текста письма | ManagerModule.ПолучитьHTMLПредставление |

**[MCP] Модуль:** `CommonModules/ВстроеннаяПочтаСервер` — центральный модуль обработки почты.

## Шаг 2: Рассмотрение и вынесение резолюции

### Объект
**Catalog.Резолюции** — резолюция хранится в **справочнике** (не документе!), привязанном к документу.

**[MCP] Ключевые реквизиты (из запроса РаботаСРезолюциями.ПолучитьРезолюции):**
- `АвторРезолюции` — сотрудник, формально вынесший резолюцию
- `ВнесРезолюцию` — сотрудник, фактически внёсший запись (может отличаться при делегировании)
- `ФактическийАвтор` — СправочникСсылка.ФактическиеИсполнители (для делегатов)
- `ДатаРезолюции` — дата вынесения
- `ТекстРезолюции` — текст поручения
- `Документ` — ссылка на ВходящееПисьмо (или другой документ)
- `Источник` — ссылка на ДействияИсполнения (привязка к задаче/процессу)
- `Подписана` — признак подписания (с поддержкой ЭП через РС ЭлектронныеПодписи)
- `ИдентификаторУчастника` — для связи с участником комплексного процесса

### Код, обрабатывающий создание резолюции

**[MCP] Модуль:** `Catalogs/Резолюции/Ext/ObjectModule.bsl`

**ПередЗаписью:**
```bsl
// Проверка прав (только автор, исполнитель, их делегаты):
Запрос.Текст = "ВЫБРАТЬ ПЕРВЫЕ 1 ИСТИНА КАК ЕстьЗаписи
|ИЗ РегистрСведений.СоставСубъектовПравДоступа
|ГДЕ Сотрудник В (&СотрудникиПользователя)
|   И (Субъект = &ВнесРезолюцию ИЛИ Субъект = &АвторРезолюции)";

// Добавление участников в рабочую группу документа:
РаботаСРабочимиГруппами.ДобавитьУчастникаВТаблицуНабора(ТаблицаУчастников, АвторРезолюции);
РаботаСРабочимиГруппами.ДобавитьУчастникаВТаблицуНабора(ТаблицаУчастников, ВнесРезолюцию);
РаботаСРабочимиГруппами.ПерезаписатьРабочуюГруппуОбъекта(Документ, ТаблицаУчастников, Истина);
```

**[MCP] Модуль:** `CommonModules/РаботаСРезолюциями/Ext/Module.bsl` — функция `ПолучитьРезолюции` используется при экспорте в архив, отображении на форме документа, создании задач.

### Регистры, обновляемые при записи резолюции

| Регистр сведений | Действие |
|-----------------|----------|
| СоставСубъектовПравДоступа | Проверка прав (чтение) |
| ЭлектронныеПодписи | Данные подписи при Подписана=Истина |

## Шаг 3: Создание задачи на исполнение

### Бизнес-процесс
**BusinessProcess.Исполнение** — запускается вручную по резолюции или автоматически.

**[MCP] Структура данных для заполнения (СтруктураДанныхДляЗаполнения):**
- `Наименование` — заголовок задачи
- `Описание` — описание поручения (из текста резолюции — **[домысел]**)
- `Важность` — Перечисление.ВариантыВажностиОбъектов
- `ВариантИсполнения` — Перечисление.ВариантыМаршрутизацииЗадач
- `Исполнители` — таблица значений с колонками:
  - `ИдентификаторИсполнителя` (УникальныйИдентификатор)
  - `Исполнитель` — СправочникСсылка (Сотрудники | ПолныеРоли | Пользователи)
  - `ВариантУстановкиСрокаИсполнения`
  - `СрокИсполнения` (Дата)
  - `СрокИсполненияДни`, `СрокИсполненияЧасы`, `СрокИсполненияМинуты`
  - `ПорядокИсполнения` — Перечисление.ПорядокВыполненияЗадач
  - `НаименованиеЗадачи`, `Описание`, `Ответственный`
- `Автор`, `Проверяющий` (с ИдентификаторПроверяющего), `Контролер`
- `Предметы` — связанные объекты (включает ссылку на ВходящееПисьмо)
- `ВедущаяЗадача` — ЗадачаСсылка.ЗадачаИсполнителя (для иерархии)
- `КоличествоИтераций`, `ТрудозатратыПланКонтролера`, `ТрудозатратыПланПроверяющего`

**[MCP] Модуль:** `BusinessProcesses/Исполнение/Ext/ObjectModule.bsl` (2570 строк)  
Также: `BusinessProcesses/Исполнение/Ext/ManagerModule.bsl` (1893 строки)

**[MCP] Шаблоны бизнес-процессов:** `Справочники.ШаблоныИсполнения` — процедура `ЗаполнитьПоШаблону` заполняет БП по предустановленному шаблону.

### Создаваемая задача
При запуске БП Исполнение платформа 1С автоматически создаёт записи **Task.ЗадачаИсполнителя** — по одной на каждого исполнителя из табличной части.

**[MCP] Подписки на события при записи задачи:**
- `ЗадачаПриЗаписи` → `БизнесПроцессыИЗадачиСобытия.ЗадачаПриЗаписиПриЗаписи`
- `КонтрольПередЗаписьюЗадачи` → `КонтрольСобытия`
- `КонтрольПриЗаписиЗадачи` → `КонтрольСобытия`
- `ПереносСроковИсполненияПередЗаписьюЗадач` → `ПереносСроковВыполненияЗадач`
- `ПереносСроковИсполненияПриЗаписиЗадач` → `ПереносСроковВыполненияЗадач`
- `МиграцияДанныхИзВнешнихСистемПередЗаписьюЗадачи` → `МиграцияДанныхИзВнешнихСистемСервер`

### Регистры, обновляемые при создании задачи

| Регистр сведений | Действие |
|-----------------|----------|
| тст_СрокиИсполненияЗадач | Заполняется для новых задач (кастомный Тест) |
| КешИнформацииОбОбъектах | Устанавливает признак ЕстьФайлы |
| ПроцессыДействий | Читается для определения прав изменения предмета |

## Шаг 4: Выполнение задачи исполнителем

### Объект
**Task.ЗадачаИсполнителя** — задача в папке "Задачи мне".

**[MCP] Ключевые реквизиты (из ВыполнениеЗадачСервер.ВыполнитьЗадачу):**
- `ТекущийИсполнитель` — назначенный исполнитель
- `РезультатВыполнения` — итог (Перечисление.ВариантыВыполненияПроцессовИЗадач)
- `ДатаИсполнения` — дата фактического выполнения
- `Выполнена` — Булево
- `Предметы` — табличная часть с предметами (ВходящееПисьмо и/или другие объекты)
- `БизнесПроцесс` — ссылка на БП Исполнение
- `СрокИсполнения` — плановый срок

### Прикладывание файла-ответа

**[домысел]** Файл прикладывается через стандартный механизм РаботаСФайлами — функция `РаботаСФайламиВызовСервера.ПолучитьВсеПодчиненныеФайлы`. Файлы хранятся в справочнике присоединённых файлов с владельцем = ЗадачаИсполнителя.

### Код выполнения задачи

**[MCP] Модуль:** `CommonModules/ВыполнениеЗадачСервер/Ext/Module.bsl`

**Процедура ВыполнитьЗадачу (строки 315–366):**
```bsl
// 1. Проверка прав:
ДокументооборотПраваДоступа.ПраваПользователяПоОбъекту(Задача);

// 2. Заполнение параметров выполнения:
ПараметрыВыполнения.ДатаИсполнения = ТекущаяДатаСеанса();
ПараметрыВыполнения.ИсполнительЗадачи = ТекущийИсполнитель;
ПараметрыВыполнения.РезультатВыполнения = ...;

// 3. Проверка очереди заданий (фоновое выполнение):

// 4. Событие для процессов:
РаботаСПроцессамиПоДействиямСобытия.ПриВыполненииЗадачиСПараметрами(Задача, ПараметрыВыполнения);
```

## Шаг 5: Формирование исходящего письма с ответом

### Объект
**Document.ИсходящееПисьмо** — создаётся командой "Ответить" из входящего письма или вручную по задаче.

**[MCP] Ключевые реквизиты:**
- `УчетнаяЗапись` — почтовая учётная запись для отправки (обязательная)
- `ПолучателиПисьма`, `ПолучателиКопий` — табличные части с адресатами
- `Тема` — заполняется с префиксом "Re: " из темы входящего
- `ТипОтвета` — Перечисление.ТипыОтвета (ОтветНаПисьмо | ПересылкаПисьма | ПеренаправлениеПисьма)
- `ПодготовленоКОтправке` — дата подготовки (триггер для РС НеОтправленныеИсходящиеПисьма)
- `ДатаОтправки` — дата фактической отправки
- `ВидМаршрутизации` — Перечисление.ВидыМаршрутизацииПисем (Внешняя | Внутренняя)
- `Папка` — обязательный реквизит
- `Предмет` — связанный объект (ВходящееПисьмо или ЗадачаИсполнителя)
- `ПисьмоОснование` — ссылка на ВходящееПисьмо (для цепочки переписки)
- `ОтправительКонтакт` — контакт отправителя

### Создание ответного письма

**[MCP] Команда "Ответить"** в форме ВходящегоПисьма:  
`Documents/ВходящееПисьмо/Commands/Ответить/Ext/CommandModule.bsl`
```bsl
ВстроеннаяПочтаКлиент.ОтветитьНаПисьмо(ПараметрКоманды);
```

**[MCP] Модуль:** `CommonModules/ВстроеннаяПочтаКлиент`, процедура `ОтветитьНаПисьмо`:
```bsl
ЗначенияЗаполнения.Вставить("Команда", "Ответить");
ЗначенияЗаполнения.Вставить("Письмо", Письмо);
ОткрытьФорму("Документ.ИсходящееПисьмо.ФормаОбъекта", ПараметрыОткрытия, ...);
```

**[MCP] Заполнение при команде "Ответить"** (`ЗаполнитьСтруктуруРеквизитовПоПисьму`):
```bsl
// Из входящего письма берётся:
ПисьмоИнфо = ОбщегоНазначения.ЗначенияРеквизитовОбъекта(Письмо,
    "Ссылка, Кодировка, Предмет, Проект, Тема, УчетнаяЗапись, ОтправительАдресат, ТипТекста");
// Отправитель входящего → получатель исходящего:
ПеренестиОтправителяВПолучатели = Истина;
// Тема с префиксом Re:
ПрефиксТемыПисьма = ВстроеннаяПочтаСервер.ПолучитьПрефиксДляОтветныхПисем();
// Тип ответа:
СтруктураРеквизитов.ТипОтвета = Перечисления.ТипыОтвета.ОтветНаПисьмо;
```

**[MCP] Создание письма по задаче** (`ЗаполнитьСтруктуруРеквизитовПоЗадачеИсполнителя`):
```bsl
СтруктураРеквизитов.Тема = РеквизитыЗадачиИсполнителя.Наименование;  // тема = имя задачи
СтруктураРеквизитов.Проект = РеквизитыЗадачиИсполнителя.Проект;
СтруктураРеквизитов.Предмет = ЗадачаИсполнителя;  // предмет = задача
```

### Код, обрабатывающий запись исходящего письма

**[MCP] Модуль:** `Documents/ИсходящееПисьмо/Ext/ObjectModule.bsl`

**ПередЗаписью:**
```bsl
// Текст письма из ДополнительныхСвойств:
УстановитьСодержаниеПисьма(ДополнительныеСвойства.ТекстПисьма, ТипТекста, Кодировка);
// Определение маршрутизации:
ВидМаршрутизации = ВстроеннаяПочтаСервер.ПолучитьВидМаршрутизацииПисьма(ЭтотОбъект);
// Применение предопределённых правил:
ВстроеннаяПочтаСервер.ПрименитьПредопределенныеПравила(ЭтотОбъект);
```

**ПриЗаписи:**
```bsl
// Регистрация в очереди отправки:
ВстроеннаяПочтаСервер.ДобавитьПисьмоВПодготовленныеКОтправке(Ссылка);
// или снятие с очереди при пометке удаления.
// Обновление счётчика папки:
РегистрыСведений.КоличествоПисемВПапках.ОчиститьЗаписиПоПапке(Папка);
// Привязка к ветке переписки (если черновик):

```

## Особенности конфигурации Тест

Данная конфигурация содержит кастомные расширения (идентифицируются по префиксу `тст_`):

**[MCP] Кастомные регистры сведений, задействованные в сценарии:**
- `тст_СрокиИсполненияЗадач` — заполняется при создании новых задач (ПриЗаписи ЗадачаИсполнителя)
- `тст_СогласованиеЗаявокСБ` — заполняется при выполнении задач Службы безопасности по проверке контрагентов (ПриВыполнении ЗадачаИсполнителя)
- `тст_ИзмененияОценкиРискаКонтрагентов` — фиксирует изменения уровня риска при завершении цикла согласования

## Что установлено из MCP / что является домыслом

### Установлено из MCP (высокая уверенность):
- Реквизиты всех 5 объектов сценария
- Имена и расположение модулей BSL для каждого объекта
- Список регистров сведений с именами процедур их обновления
- Цепочка вызовов команды "Ответить": CommandModule → ВстроеннаяПочтаКлиент.ОтветитьНаПисьмо → ОткрытьФорму ИсходящееПисьмо
- Механизм ветки переписки (РС ПисьмаВеток, Справочник ВеткиПереписки, поле ПисьмоОснование)
- Подписки на события для задач и БП (227 подписок всего, ключевые выбраны)
- Кастомные регистры Тест

### Домысел (средняя/низкая уверенность):
- **Как именно** руководитель открывает форму резолюции из письма — код формы не читался
- **Как** задача создаётся из резолюции — связь Резолюция.Источник = ДействияИсполнения есть в запросе ПолучитьРезолюции, но код создания задачи по резолюции не читался
- **Механизм прикладывания файла** к задаче — только косвенно через РаботаСФайламиВызовСервера
- **Структура XML-описания** объектов (get_object_structure возвращает null для attributes)
