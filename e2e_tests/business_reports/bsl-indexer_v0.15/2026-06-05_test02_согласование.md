# Бизнес-процесс «Согласование» в 1С:Документооборот КОРП 3.0

**Источник данных:** MCP-сервер bsl-indexer v0.15, репозиторий «Тест ДО3»
**Дата:** 2026-06-05

---

## 1. Параметры, настраиваемые при запуске согласования

БП Согласование запускается из формы `ФормаБизнесПроцесса` или через шаблон. Основные параметры задаются в процедуре `ЗаполнитьПоШаблону` (ObjectModule.bsl, стр. 88–348) и экспортируются через `ЗаполнитьРезультатНастроекПроцесса` (ObjectModule.bsl, стр. 1162–1195).

### Исполнители

Табличная часть **Исполнители** — кто будет согласовывать. Каждая строка содержит:

| Реквизит | Назначение |
|---|---|
| `Исполнитель` | Сотрудник / Пользователь / ПолныеРоли |
| `ПорядокСогласования` | `ВместеСПредыдущим` или `ПослеПредыдущего` (Перечисление.ПорядокВыполненияЗадач) |
| `ВариантУстановкиСрокаИсполнения` | Как рассчитывается срок |
| `СрокИсполнения` / `СрокИсполненияДни` / `СрокИсполненияЧасы` / `СрокИсполненияМинуты` | Срок задачи |
| `ТрудозатратыПланИсполнителя` | Плановые трудозатраты (если включена ФО) |
| `ИдентификаторИсполнителя` | UUID для сопоставления при обновлении |
| `Пройден` | Флаг завершения (заполняется в ходе процесса) |
| `ЗадачаИсполнителя` | Ссылка на созданную задачу |

При заполнении из шаблона поддерживаются **автоподстановки** (`Справочник.АвтоподстановкиДляПроцессов`) — они разворачиваются в конкретных сотрудников/роли на момент старта.

### Вариант согласования

Реквизит `ВариантСогласования` берётся из `Перечисление.ВариантыМаршрутизацииЗадач` и определяет порядок выдачи задач:

- **Параллельно** — задачи создаются всем исполнителям одновременно
- **Последовательно** — следующая задача создаётся только после завершения предыдущей
- **Смешанно** — группы исполнителей с признаком `ВместеСПредыдущим` выполняются параллельно, следующая группа — после завершения всей предыдущей

Логика реализована в функции `СоздатьЗадачиСогласования` (ObjectModule.bsl, стр. 1964–2020).

### Сроки и прочие параметры

| Параметр | Реквизит |
|---|---|
| Общий срок процесса | `СрокИсполненияПроцесса` |
| Срок обработки результатов (для ОбрабатывающегоРезультат) | `СрокОбработкиРезультатов` / Дни / Часы / Минуты |
| Количество итераций (повторных кругов) | `КоличествоИтераций` |
| Кто обрабатывает итог | `ОбрабатывающийРезультат` (сотрудник / роль) |
| Подписание ЭП | `ПодписыватьЭП` (при активных ФО ИспользоватьЭлектронныеПодписи + ИспользоватьВизыСогласования) |

## 2. Что такое ВизыСогласования и как они связаны с процессом

**Виза согласования** — элемент справочника `Catalog.ВизыСогласования`. Это постоянная запись о факте рассмотрения документа конкретным участником; она хранится в базе даже после завершения процесса и помещается в историю.

### Ключевые реквизиты визы

| Реквизит | Назначение |
|---|---|
| `Документ` | Ссылка на согласуемый документ (предмет процесса) |
| `Исполнитель` | Согласующий сотрудник |
| `РольИсполнителя` | Роль, от имени которой выдана виза |
| `РезультатСогласования` | Итог визы (см. раздел 3) |
| `ДатаИсполнения` | Дата установки результата |
| `УстановилРезультат` | Кто фактически нажал «Согласовать» |
| `Комментарий` | Текстовый комментарий |
| `Источник` | Ссылка на `Задача.ЗадачаИсполнителя` — задача процесса, породившая визу |
| `ПомещенаВИсторию` / `ДатаПомещенияВИсторию` | Флаг архивирования визы |
| `ИдентификаторУчастника` | UUID строки исполнителя процесса |
| `Автор` | Кто создал визу (обычно автор процесса) |
| `ПоместилВИсторию` | Кто переместил визу в историю |

### Связь с процессом

Функциональная опция **`ИспользоватьВизыСогласования`** управляет видимостью механизма. При её включении совместно с `ИспользоватьЭлектронныеПодписи` активируется поле `ПодписыватьЭП` — визы могут подписываться ЭЦП.

Связь «Виза ↔ Задача» устанавливается через реквизит `Источник` (тип `ЗадачаСсылка.ЗадачаИсполнителя`). При выполнении задачи согласования форма визы реагирует на событие `"ЗадачаСогласованияВыполнена"` и обновляет своё состояние. При записи визы с заполненным `РезультатСогласования` автоматически фиксируются версии файлов (`РегистрСведений.ВерсииСогласованныхФайлов`).

Общая форма `ИсторияВизСогласования` показывает дерево виз по документу: запрашивает `Справочник.ВизыСогласования` по реквизиту `Документ`.

## 3. Результаты, которые может вернуть согласующий

Согласующий выбирает результат в форме визы (`Catalog.ВизыСогласования/Forms/ФормаЭлемента`). Значения из `Перечисление.РезультатыСогласования`:

| Значение перечисления | Отображение пользователю | Маппинг на общий результат |
|---|---|---|
| `Согласовано` | «Результат согласования: Согласовано» | `ВариантыВыполненияПроцессовИЗадач.Положительно` |
| `СогласованоСЗамечаниями` | «Результат согласования: Согласовано с замечаниями» | `ВариантыВыполненияПроцессовИЗадач.ПоложительноСЗамечаниями` |
| `НеСогласовано` | «Результат согласования: Не согласовано» | `ВариантыВыполненияПроцессовИЗадач.Отрицательно` |

Функция `ИтоговыйРезультатСогласования` (ObjectModule.bsl, стр. 1202–1233) вычисляет **итоговый результат всего процесса** по всем строкам `РезультатыСогласования` текущей итерации с приоритетом:
1. Если хотя бы один сказал «НеСогласовано» — итог `НеСогласовано`
2. Если хотя бы один сказал «СогласованоСЗамечаниями» (и никто не сказал НеСогласовано) — итог `СогласованоСЗамечаниями`
3. Иначе — итог `Согласовано`

## 4. Завершение процесса: что происходит, когда все согласующие завершили работу

### Цепочка событий

**Шаг 1.** Согласующий выполняет задачу (`ЗадачаИсполнителя`). Срабатывает обработчик точки маршрута `СогласоватьПриВыполнении` (ObjectModule.bsl, стр. 1678–1682):

```bsl
Процедура СогласоватьПриВыполнении(ТочкаМаршрута, Задача, Отказ)
    ДобавитьЗадачуОтложеннаяОбработкаЗавершенияСогласования();
КонецПроцедуры
```

**Шаг 2.** `ДобавитьЗадачуОтложеннаяОбработкаЗавершенияСогласования` (стр. 1864–1883) создаёт служебную задачу для отложенной обработки через `РаботаСПроцессамиПоДействиямСобытия.ОбработатьДобавлениеЗадачиОтложеннаяОбработкаЗавершенияСогласования`.

**Шаг 3.** `ОбработатьЗавершениеЗадачиСогласования` (стр. 2107–2117) помечает строку исполнителя как пройденную (`Исполнители.Пройден = Истина`) и записывает процесс.

**Шаг 4.** Платформа вызывает условие `УсловиеОбходЗавершен` (стр. 1699–1709) — точка маршрута «УсловиеОбхода»:

```bsl
Процедура УсловиеОбходЗавершен(ТочкаМаршрута, Результат)
    Результат = ОбходСогласующихЗавершен();
КонецПроцедуры
```

**Шаг 5.** `ОбходСогласующихЗавершен` (стр. 1240–1271):
- Запрашивает наличие невыполненных активных задач по процессу (SELECT ПЕРВЫЕ 1 из `Задача.ЗадачаИсполнителя`)
- Если остались незавершённые задачи → возвращает `Ложь` (обход ещё не завершён)
- Если все выполнили, но итог `НеСогласовано` → возвращает `Истина` досрочно
- Иначе проверяет, что все строки исполнителей имеют `Пройден = Истина`

**Шаг 6.** Когда условие вернуло `Истина`, процесс переходит к точке «ОбработкаРезультата» или «Завершение».

**Шаг 7.** Финальная обработка в `ЗавершениеПриЗавершении` (стр. 1761–1770):

```bsl
Процедура ЗавершениеПриЗавершении(ТочкаМаршрута, Отказ)
    ДатаЗавершения = ТекущаяДатаСеанса();
    РаботаСПроектами.ОтметитьОкончаниеВыполненияПроектнойЗадачи(ЭтотОбъект);
    РаботаСПроцессамиПоДействиямСобытия.ПриЗавершенииПроцесса(ЭтотОбъект);
КонецПроцедуры
```

**Шаг 8.** `РаботаСПроцессамиПоДействиямСобытия.ПриЗавершенииПроцесса` (CommonModules, стр. 1005–1028):
- Получает связанное Действие из `РегистрыСведений.ПроцессыДействий`
- Проверяет наличие других активных процессов по этому Действию
- При их отсутствии вызывает `МенеджерДействия.ОбновитьРезультатВыполнения`

### Проверка успешности завершения

Функция `ПроцессЗавершилсяУдачно` (ManagerModule.bsl, стр. 1879–1890):
```bsl
Возврат РеквизитыПроцесса.Завершен
    И (РезультатСогласования = Согласовано
       ИЛИ РезультатСогласования = СогласованоСЗамечаниями);
```

Кастомная логика в конфигурации Тест: `СогласованоПроверкаУсловия` (стр. 2238–2274) дополнительно проверяет, участвовал ли в согласовании «ДД Директор по брэнду», и читает настройку `тст_НеОзнакамливать` для управления шагом ознакомления.

## Итог

Бизнес-процесс «Согласование» в Документооборот КОРП 3.0 — многоэтапный механизм с гибкой маршрутизацией. Параметры задаются через табличную часть «Исполнители» (сотрудники, роли, сроки, порядок) и реквизиты головного объекта (вариант согласования, количество итераций, кто обрабатывает результат). Результаты фиксируются в трёх значениях (Согласовано / СЗамечаниями / НеСогласовано) и агрегируются функцией `ИтоговыйРезультатСогласования` по принципу «жёсткое вето» на НеСогласовано. Завершение обрабатывается цепочкой: `СогласоватьПриВыполнении` → `ОбходСогласующихЗавершен` → `ЗавершениеПриЗавершении` → `РаботаСПроцессамиПоДействиямСобытия.ПриЗавершенииПроцесса`. Визы согласования — отдельный справочник, связанный с задачами через `Источник` и хранящий историю визирования документа с поддержкой ЭЦП.
