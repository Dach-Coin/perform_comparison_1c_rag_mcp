## Как работает функция

Функция принимает массив действий задач (`ДействияЗадач`) и определяет для каждого из них фактического исполнителя с учётом трёх сценариев: прямой исполнитель-сотрудник, исполнитель через роль, исполнитель через замещение/помощничество.

### Шаг 1 — Инициализация

Функция получает реквизит `Исполнитель` для каждого действия задачи. Определяет текущего пользователя: либо от его имени выполняется (тогда используются `ВсеСотрудникиТекущегоПользователя`), либо от имени другого пользователя (`ВыполнитьОтИмени`).

### Шаг 2 — Проверка прямого исполнителя (сотрудник)

Для каждого действия задачи, если `Исполнитель` является сотрудником (`СправочникСсылка.Сотрудники`), проверяется, входит ли он в список сотрудников текущего пользователя. Если да — фактический исполнитель определён сразу.

```bsl
Если ТипЗнч(РеквизитыДействия.Исполнитель) = Тип("СправочникСсылка.Сотрудники") Тогда
    ВыполняетСотрудник = Сотрудники.ЭтоСотрудникТекущегоПользователя(РеквизитыДействия.Исполнитель);
    Если ВыполняетСотрудник Тогда
        ФактическиеИсполнителиПолные[ДействиеЗадачи] =
            Справочники.ФактическиеИсполнители.НайтиСоздатьФактическогоИсполнителя(
                РеквизитыДействия.Исполнитель);
        Продолжить;
    КонецЕсли;
КонецЕсли;
```

### Шаг 3 — Проверка исполнителя через роль

Если исполнитель задан через роль (`СправочникСсылка.ПолныеРоли`), функция проверяет, является ли текущий пользователь исполнителем этой роли через `ЭтоРольТекущегоПользователя`. Затем получает список всех исполнителей роли (`ИсполнителиРоли`) и находит пересечение с сотрудниками пользователя — это и есть фактический исполнитель.

```bsl
ИсполнителиРоли = РегистрыСведений.ИсполнителиРолей.ИсполнителиРоли(РеквизитыДействия.Исполнитель);
ПодходящиеСотрудники = ОбщегоНазначенияДокументооборотКлиентСервер.ПересечениеМассивов(
    ВсеСотрудники, ИсполнителиРоли);
```

### Шаг 4 — Проверка замещений (ключевой для бизнес-вопроса)

Если ни прямой исполнитель, ни роль не подошли, функция обращается к замещениям. Сначала получается полная таблица замещений через `ЗамещающиеИПомощники.ВсеЗамещенияПоДействиямЗадач`. Затем уточняются актуальные замещения через `АктуальныеЗамещенияПоДействиямЗадач`.

Для замещающего (вид замещения `Замещающие`) фактическим исполнителем становится основной сотрудник; адресатом — сотрудник из строки замещения:
```bsl
ФактИсполнитель = Справочники.ФактическиеИсполнители.НайтиСоздатьФактическогоИсполнителя(
    РеквизитыДействия.Исполнитель,
    СтрЗамещения.Сотрудник,   // Адресат (кому адресована задача)
    ОсновнойСотрудник,         // Фактический исполнитель
    ОсновнойСотрудник);        // Основной сотрудник
```

Для помощника (вид замещения `Помощники`) фактическим исполнителем является сам помощник:
```bsl
ФактИсполнитель = Справочники.ФактическиеИсполнители.НайтиСоздатьФактическогоИсполнителя(
    РеквизитыДействия.Исполнитель,
    СтрЗамещения.Сотрудник,
    СтрЗамещения.Сотрудник,
    ОсновнойСотрудник);
```

Если задача адресована нескольким исполнителям (или ни одному) и выбранный фактический исполнитель не задан — задача помещается в `ДействияБезКомуАдресовано` для последующего уточнения.

### Шаг 5 — Возврат результата

Функция возвращает структуру с пятью полями:
- `ДействияБезФактИсполнителя` — действия, для которых исполнитель не определён
- `ДействияБезКомуАдресовано` — действия, требующие уточнения адресата
- `ФактическиеИсполнителиПолные` — соответствие «действие → ФактическийИсполнитель (справочник)»
- `ФактическиеИсполнителиПоДействиям` — соответствие «действие → Сотрудник»
- `ОснованияФактИсполнителейПоДействиям` — соответствие «действие → Замещение (основание)»

## Кто вызывает функцию

Функция вызывается в 5 модулях (6 мест вызова), что подтверждает её центральную роль при выполнении задач:

### 1. `CommonModules/БизнесПроцессыИЗадачиСервер` — функция `ПринятьКИсполнению` (стр. 77)
Вызывается при принятии задачи к исполнению пользователем. Это основной сценарий назначения задачи исполнителю.

### 2. `CommonModules/РаботаСЗадачами` — функция `ВзятьВРаботу` (стр. 798)
Внутренний вызов внутри того же модуля при взятии задачи в работу.

### 3. `CommonModules/РаботаСЗадачамиВызовСервера` — функция `ЗаполнитьФактическогоИсполнителя` (стр. 1332)
Вызов со стороны клиентского слоя (Вызов сервера) — при заполнении параметров выполнения из UI.

### 4. `CommonModules/РаботаСВнешнимПодписанием` — функция `ЗаполнитьПараметрыОбработкиВнешнегоПодписанияПоВыполнениюОтДействия` (стр. 2343)
Вызывается при обработке внешнего подписания — определение исполнителя для действия документа с ЭЦП.

### 5. `CommonModules/РаботаСВнешнимПодписанием` — функция `ЗаполнитьПараметрыОбработкиВнешнегоПодписанияПоВыполнениюОтЗадачи` (стр. 2429)
Аналогично предыдущему, но через задачу (не через действие).

### 6. `CommonModules/ЭскалацияЗадач` — функция `ПрименитьПравилоЭскалацииДействияОзнакомления` (стр. 1756)
Вызывается при эскалации задачи ознакомления — для определения исполнителя в рамках правила эскалации.

## Связанные функции

При поиске также обнаружены тесно связанные функции в `CommonModules/ЗамещающиеИПомощники`:

- **`ПодходящиеЗамещения`** (стр. 482–613) — формирует таблицу замещений для конкретного действия задачи по областям замещения и значениям отбора
- **`ПодходящиеДействияЗадач`** (стр. 539–771) — определяет, какие действия задач входят в область замещения
- **`ЗаписатьДоступЗамещающихПоДействиюЗадачи`** (стр. 307–424) — записывает права замещающих в РС ВсеИсполнителиДействийЗадач
- **`ОбновитьДанныеЗадачПоЗамещению`** (стр. 327–535) — пересчитывает все данные задач при изменении замещения

## Итог

Функция `ОпределитьФактическихИсполнителей` в модуле `РаботаСЗадачами` является центральным алгоритмом системы: она последовательно проверяет три варианта — прямой исполнитель, исполнитель через роль, исполнитель через замещение/помощничество — и возвращает полную структуру с данными о фактическом исполнителе и основании (замещении). Функция вызывается во всех ключевых точках жизненного цикла задачи: при принятии к исполнению, взятии в работу, внешнем подписании и эскалации.
