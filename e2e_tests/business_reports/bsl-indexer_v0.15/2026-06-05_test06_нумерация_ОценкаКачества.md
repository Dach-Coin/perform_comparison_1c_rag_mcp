# Оценка качества: TEST-06 — Нумерация и регистрация документов
**Сервер:** bsl-indexer (v0.15.0)
**Дата:** 2026-06-05
**Оценщик:** Оркестратор (Claude Opus 4.8, 1M context)

## Общая оценка: ПОЛНОСТЬЮ

Все 5 подвопросов закрыты данными из кода и XML: отсутствие автонумерации при создании (`ОбработкаЗаполнения`: РегистрационныйНомер="", ЧисловойНомер=0), БП `Регистрация` + `Делопроизводство.ЗарегистрироватьПредмет` + веб-сервис DMReg, регистры `Нумерация`/`НастройкиНумерации`, шаблон со служебными полями, два предопределённых нумератора, гибкие схемы. Достигнуто за 33 вызова и ≈258K токенов — впервые относительно близко к rlm (1.47×).

## Что сервер дал хорошо
- **FTS `search_function` попадал, когда имя угадано близко к реальному**: `ЗарегистрироватьДокумент` (#7), `СформироватьСтроковыйНомерДокумента` (#12), `ПолучитьПараметрыНумерации` (#15), `ЗарегистрироватьПредмет регистрация документа` (#18) — дали ядро логики.
- **`grep_code`/`grep_body` по ключевым словам** — рабочая лошадка: `РегистрационныйНомер` (#5, #6) нашёл ВидыДокументов, БП Регистрация, ДокументыПредприятия; служебные поля шаблона (#31) собраны из кода подстановки.
- **Структура регистров из XML по ограниченным чанкам** (#13, #16): `Нумерация` — ресурс ТекущийНомер, измерения Нумератор/ПериодНумерации/ГрифДоступа/Организация/… — читалось диапазонами, без гигантских дампов.
- **Предопределённые нумераторы** (#30, Predefined.xml): ДокументыПредприятия, Штрихкоды.
- **`ОбработкаЗаполнения`** (#26, `get_function`) — подтвердил отсутствие автонумерации при создании.
- **Кастомизация Тест** распознана: `тст_ДлинаЧисловогоНомера`.

## Что сервер НЕ дал
- **FTS не берёт концептуальные запросы**: `СформироватьНомер` (#2), `НумерацияДокументов` (#3), `ПолучитьСписокСлужебныхПолей` (#24) → 0. Работает только при близости к реальному имени функции.
- **Структура через `get_object_structure`** — снова `attributes=null` ТРИЖДЫ (#8 Нумерация, #9 Регистрация, #25 Нумераторы) → структуры собраны из сырого XML.
- **Значения перечислений** (Периодичность/СпособыНумерации) как метаданные недоступны — выводились из кода.
- Часть измерений РС `Нумерация` (ВопросДеятельности/Тематика/УзелКОД) получена не из XML, а из кода модуля.

## Паттерны поведения агента
- Stateless, `repo="Тест ДО3"`. Стратегия «grep/FTS по ключевым словам → read_file XML для структур → get_function для логики».
- **Учёл подсказки**: читал XML ограниченными диапазонами строк (не целиком) — поэтому **ни одного ⚠️-дампа** (в отличие от TEST-01/04). Самый крупный ответ — `get_function ОбработкаЗаполнения` (#26, ~14.8K = 10.7%).
- Два retry, оба на «пустой инструмент → альтернатива»: grep_body→grep_code, FTS→grep_code.
- Низкоценные вызовы дешёвые (FTS-пустышки по ~52 симв, null-структуры по ~130–155), почти не влияют на контекст.

## Выявленные проблемы
| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| **`get_object_structure` не отдаёт реквизиты** (`attributes=null`) | Снова 3× (регистры + справочник) → структуры из сырого XML |
| **FTS `search_function` чувствителен к формулировке** | 5 пустых попыток на концептуальных/неточных именах |
| Перечисления недоступны как метаданные | Периодичность/СпособыНумерации выводились из кода |
| Больше вызовов и шума, чем у rlm | 33 vs 27; 8 низкоценных vs 0 нерелевантных |
| (улучшение) Нет ⚠️-дампов | XML читался ограниченными чанками — профиль ровнее, чем в TEST-01/04 |

## Вывод
bsl-indexer v0.15 закрыл TEST-06 полностью и — благодаря дисциплинированному чтению XML по диапазонам — **без единого ⚠️-скачка**, с расходом ≈258K токенов (в 1.47× от rlm, самый близкий результат за серию после TEST-05). FTS `search_function` эффективен при близком к реальному имени функции, но проваливается на концептуальных запросах; структуры регистров снова пришлось добывать из сырого XML из-за `attributes=null`. Итог по тесту: оба сервера дали эквивалентно полный и совпадающий ответ; bsl потребовал больше вызовов и контекста, но удержал профиль ровным.
