# Оценка качества: TEST-09 — Интеграция с МЭДО

**Сервер:** bsl-indexer (v0.15.0)
**Дата:** 2026-06-05
**Оценщик:** Оркестратор (Claude Opus 4.8, 1M context)

## Общая оценка: ПОЛНОСТЬЮ (с недосчётом ТЧ на самом большом документе)

Все 5 подвопросов раскрыты по сути: **3 документа МЭДО** (УведомлениеМЭДО, ДанныеДокументаМЭДО, КвитанцияМЭДО) с реквизитами из XML, цепочка отправки (форма → `МЭДОВызовСервера.ОтправитьИсходящиеДокументы` → `МЭДО.ОтправитьИсходящийДокумент` → версионирование по «Пакетам» → запись в КаталогОтправки), **отсутствие МЭДО HTTP/веб-сервисов подтверждено двумя независимыми `grep_code`**, регл. задание `ВыполнениеОбменаМЭДО` с точным методом и параметрами перезапуска, регистры сведений МЭДО через `grep_body`. Цена прогона — **≈362K токенов контекста (2.4× от rlm)**, плюс инцидент с overflow `get_file_summary`. Сильная сторона — находки, которых нет у rlm (устаревшие реквизиты, команды); слабая — недосчёт табличных частей `УведомлениеМЭДО` и самый высокий шум серии.

> **Сверка с исходником (оркестратор):** прямое чтение XML показывает `УведомлениеМЭДО` = **9 ТЧ**, `ДанныеДокументаМЭДО` = **1 ТЧ** (Пакеты), `КвитанцияМЭДО` = **0 ТЧ**. bsl верно дал 1/0 ТЧ для второго и третьего документа, но по `УведомлениеМЭДО` нашёл лишь **3 имени ТЧ из 9** (НаправлениеДоклада, Опубликование, ОтказВРегистрации) — `grep_code TabularSection` усечён на 10 результатах, а реквизиты прочитаны только у одной ТЧ. Причина — `get_object_structure` вернул `attributes=null` (#5, #6), пришлось читать сырой XML диапазонами и не дойти до конца файла 3362 строки. bsl честно отметил пробел в самооценке («все ТЧ не прочитаны, только первые два»). Документов МЭДО ровно 3 — верно. Регл. задание ровно 1 — верно. HTTP-сервисов ровно 9 (ни одного МЭДО) — bsl назвал «8» (недосчёт на 1), но вывод «нет МЭДО-сервиса» верен и усилен grep-подтверждением.

Поэтому контекстный след считаю без тела overflow: **≈362K токенов**. Самоотчёт агента (≈473K симв / ≈852K ток) завышен — он сложил размер файла на диске с размером контекста. Реальная цифра — **362K**, всё равно 2.4× от rlm (151K) и второй по тяжести bsl-прогон серии после T01/T04.

## Что сервер дал хорошо
- **Список файлов подсистемы одним вызовом** (#3, `list_files **/*МЭДО*`): 97 файлов — Documents, CommonModules, Catalogs, Constants, DefinedTypes, DataProcessors, ScheduledJobs.
- **Реквизиты документов из XML** (детально, диапазонами): ДанныеДокументаМЭДО (ВидДокумента, АрхивЭСД=zip, ГлавныйФайл, ТекущееСостояние, Направление, Организация…), УведомлениеМЭДО (ВерсияМЭДО, ДанныеКонверта/Сообщения как ValueStorage, ТипУведомления…), КвитанцияМЭДО (ИдентификаторКвитанции, КодОшибки, Предмет=документ|уведомление, СообщениеПринято…).
- **ТЧ «Пакеты» с колонками** (#31): ВерсияМЭДО, ИдентификаторСообщения — **версионирование формата МЭДО на уровне документа** (механизм, который rlm упомянул, но не развернул колонки).
- **Находки, которых нет у rlm** (#31): устаревшие реквизиты `УдалитьВерсияМЭДО`/`УдалитьИдентификаторСообщения` (удалены в релизе 3.0.11), команда `РедактироватьДанныеМЭДО` — историческая деталь миграции.
- **Цепочка отправки через FTS** (#21, #23, #33): форма → `МЭДОВызовСервера.ОтправитьИсходящиеДокументы` → `МЭДО.ОтправитьИсходящийДокумент` → `МЭДОПереопределяемый.ДанныеИсходящегоДокументаДляОтправки` → `ЗаписатьСодержимоеКонтейнераИсходящегоДокумента`.
- **Сильное отрицательное доказательство по сервисам** (#17, #18, #29, #35): два `list_files` + два `grep_code` по HTTPServices/** и WebServices/** — 0 упоминаний МЭДО. Надёжнее, чем простое «не нашёл».
- **Регл. задание точно** (#14): `MethodName=CommonModule.МЭДО.ВыполнитьОбменМЭДО`, Predefined=true, **Use=false (выключено по умолчанию)**, перезапуск 3×10 сек — деталь Use=false, которую rlm не выделил.
- **Регистры сведений МЭДО** (#26, `grep_body`): НастройкиОрганизацийМЭДО, НастройкиКонтрагентовМЭДО, СостоянияДокументовМЭДО, ЖурналСобытийМЭДО.

## Что сервер НЕ дал
- **Полный состав ТЧ `УведомлениеМЭДО`** — ключевой пробел: 3 имени из 9 (недостающие ПодготовкаДоклада, ПостановкаНаКонтроль, ПостановкаНаКонтроль_КонтрольныеПунктыДокумента, ПринятиеКИсполнению, Регистрация, ХодИсполнения), колонки — только у 1 ТЧ. Следствие `attributes=null` + усечения grep + недочитанного файла 3362 строки.
- **Транспорт детально** — каталоги отправки/получения выведены из кода, но envelope.ini/passport.xml/XDTO-разбор (что развернул rlm) не показаны.
- **Карта SOAP-сервисов** — rlm перечислил 19 SOAP; bsl ограничился `list_files WebServices/**` без полного разбора.

## Паттерны поведения агента
- Stateless, `repo="Тест ДО3"`. Стратегия: `list_files` → `read_file` XML диапазонами → `search_function` для процедур → `grep_code`/`grep_body` для подтверждений.
- 3 retry: #5→8 и #6→10 (`get_object_structure` null → сырой XML), #24→26 (`list_files InformationRegisters/**/*МЭДО*` = 0 → `grep_body`). Все восстановлены.
- **8 шумных вызовов (23%, максимум серии)**: 2 null-структуры (#5,#6), 4 пустых list_files/grep (#4,#24,#25,#29,#35 — строгие паттерны/0 совпадений), 1 overflow (#20).
- В **контекстной** таблице — ни одного ⚠️ (guard `get_file_summary` удержал 253K вне контекста; иначе #20 дал бы скачок ~55%). Без guard прогон превысил бы 800K токенов.

## Выявленные проблемы
| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| **`get_object_structure` → `attributes=null`** | #5,#6 → сырой XML → недосчёт ТЧ `УведомлениеМЭДО` (3 из 9) |
| `grep_code` усекается (10 результатов) | #32 TabularSection — не все ТЧ перечислены |
| Большой модуль рвёт `get_file_summary` | #20 overflow 253K → temp-файл (guard спас контекст, но вызов потрачен + самоотчёт завышен) |
| Строгие паттерны list_files/grep дают 0 | #4 (`*Мэдо*`), #24/#25 (`InformationRegisters/**/*МЭДО*`), #29/#35 — шум/retry |
| Высокий шум | 8 из 35 (23%) — максимум серии |

## Вывод
bsl-indexer v0.15 ответил на все 5 подвопросов и принёс уникальные находки (ТЧ «Пакеты» с колонками, устаревшие реквизиты с номером релиза 3.0.11, команда РедактироватьДанныеМЭДО, Use=false у задания, двойное grep-подтверждение отсутствия сервисов). Но **структурный пробел**: `get_object_structure` снова `attributes=null` → пришлось читать сырой XML, и на самом большом документе (`УведомлениеМЭДО`, 3362 строки) агент недосчитал ТЧ — **3 из 9** (rlm дал точные 9 одним структурным вызовом). Цена — ≈362K токенов контекста (2.4× от rlm), шум 23% (максимум серии), плюс инцидент overflow `get_file_summary` (guard спас контекст, но раздул самоотчёт агента до фантомных 852K). Итог: **ПОЛНОСТЬЮ** по охвату, но с недосчётом структуры и заметно дороже; на этом тесте rlm точнее по составу документов и кратно экономнее. bsl силён там, где нужно лексическое подтверждение (есть/нет, кто вызывает, исторические артефакты), и проигрывает там, где нужен точный полный инвентарь метаданных крупного объекта.
