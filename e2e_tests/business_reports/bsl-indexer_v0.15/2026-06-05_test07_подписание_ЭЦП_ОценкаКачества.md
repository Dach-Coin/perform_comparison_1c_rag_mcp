# Оценка качества: TEST-07 — Электронные подписи и подписание документов
**Сервер:** bsl-indexer (v0.15.0)
**Дата:** 2026-06-05
**Оценщик:** Оркестратор (Claude Opus 4.8, 1M context)

## Общая оценка: ПОЛНОСТЬЮ

Все 5 подвопросов закрыты данными из кода и XML: БП `Подписание` с 3 точками маршрута, способы НаБумаге/ПЭП/УЭП, РС `ЭлектронныеПодписи` с полным составом криптореквизитов (Подпись/Сертификат как ValueStorage, ТипПодписи, Отпечаток…), флаг `ПодписанЭП` + `РезультатПодписания=Подписано` на документе, 23 модуля подсистемы ЭП + кастомизация Тест (Диадок). Ответ совпадает с rlm по сути; цена — ≈294K токенов (1.65× от rlm).

## Что сервер дал хорошо
- **FTS `search_function` дал ядро подсистемы** (#4, #5): модули ЭП из БСП, точки маршрута, `ОбновитьТочкуМаршрутаУчастникаПодписания`, кастомизация тст_Диадок — но крупными дампами (12K + 14K символов).
- **`search_class "Подписание"`** (#3) сразу нашёл `BusinessProcess.Подписание`, `Subsystem.ВнешнееПодписание`, `Constant.ИспользоватьВнешнееПодписание`.
- **Полный состав РС `ЭлектронныеПодписи` из XML**: Подпись/Сертификат (ValueStorage), ПодписьВерна, СертификатДействителен, ТипПодписи, Отпечаток, КомуВыданСертификат, измерения ПодписанныйОбъект (DefinedType, Master) + ПорядковыйНомер — собрано чтением XML по 6 чанкам.
- **Ключевые процедуры** через `get_function`: `ЗанестиИнформациюОПодписях` (ПодписанЭП=Истина, Подписал, РезультатПодписания, ДатаПодписания), `ОбработкаПередВыполнениемЗадачи`, `ОбработкаЗаполнения` (параметры запуска), `ВсеЭтапыПодписанияПройдены`.
- **Модули и интеграция**: `list_files` нашёл 23 модуля `ЭлектроннаяПодпись*` и 5 `РаботаСЭП*`; `grep_code` — точки `РаботаСВнешнимПодписанием` (ПередЗаписью/ПриЗаписи) и HTTP-сервис тст_STORM (Диадок, задача 89132).
- **`get_file_summary` снова отсёк большой модуль ошибкой** (#41) — без раздувания контекста.

## Что сервер НЕ дал
- **Структура через `get_object_structure`** — снова `attributes=null` ЧЕТЫРЕЖДЫ (#6 БП Подписание, #16 РС ЭлектронныеПодписи, #17 ДействияПодписания, #36 СертификатыКлючей) → состав РС пришлось собирать из сырого XML (6 чтений — основной источник расхода).
- **Перечисления как метаданные** — `СпособыПодписания` читались из XML (`Enums/…xml`), не как структура.
- **Полный состав справочников** `ДействияПодписания` (2476 стр) и `СертификатыКлючейЭП` — не дочитаны (агент опирался на название/контекст — частичное «додумывание»).

## Паттерны поведения агента
- Stateless, `repo="Тест ДО3"`. Стратегия «search_class/search_function → read_file XML для структур → get_function для логики».
- **Учёл подсказки**: XML читал ограниченными диапазонами строк → **ни одного ⚠️-дампа** (самый крупный ответ — #5 search_function ~14K = 8.6%).
- 4 retry — все на «null-структура / пустой grep → альтернатива (read_file / grep_code)».
- 9 низкоценных вызовов (4 пустых grep по строгим regex, 4 null-структуры, 1 file_summary-ошибка) — дешёвые, но повышают шум до 20%.

## Выявленные проблемы
| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| **`get_object_structure` не отдаёт реквизиты** (`attributes=null`) | 4× (БП, РС, 2 справочника) → состав РС ЭлектронныеПодписи из сырого XML (6 чтений) |
| Перечисления недоступны как метаданные | Способы подписания читались из Enums/*.xml |
| Высокий шум | 9 из 44 вызовов (20%) — пустые grep/null-структуры |
| Большие справочники не дочитаны | ДействияПодписания/СертификатыКлючей — частичное додумывание по названию |
| (улучшение) `get_file_summary` отсёк дамп, XML читался чанками | Профиль ровный — без ⚠️ |

## Вывод
bsl-indexer v0.15 закрыл TEST-07 полностью и без ⚠️ (дисциплинированное чтение XML чанками), но ценой ≈294K токенов — в 1.65× больше rlm (179K). FTS `search_function`/`search_class` хорошо вывели на ядро подсистемы ЭП, однако `get_object_structure` снова `attributes=null` (4×), из-за чего полный состав регистра `ЭлектронныеПодписи` пришлось собирать из сырого XML шестью чтениями — это и дало основной перерасход. Доля шума выросла до 20% (пустые grep по строгим regex + null-структуры). Ответ эквивалентен rlm по полноте; разница — в стоимости и чистоте прогона.
