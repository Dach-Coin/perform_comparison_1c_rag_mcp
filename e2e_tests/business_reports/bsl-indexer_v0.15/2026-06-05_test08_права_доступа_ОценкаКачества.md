# Оценка качества: TEST-08 — Права доступа к задачам
**Сервер:** bsl-indexer (v0.15.0)
**Дата:** 2026-06-05
**Оценщик:** Оркестратор (Claude Opus 4.8, 1M context)

## Общая оценка: ЧАСТИЧНО — отвечено про `Task.ЗадачаИсполнителя`, а не про **документ** Задача из промпта

Промпт буквально спрашивает про **«документ Задача»** = `Document.Задача`. bsl же заякорился на **другом объекте** — платформенной `Task.ЗадачаИсполнителя`: в #5 прямо констатировал «прямого доступа к Task.ЗадачаИсполнителя нет в базовых правах» и переключился на `Tasks/`, а `Document.Задача` лишь отметил мимоходом (#15). В итоге:
- **Подвопросы 1 («роли доступа к документу Задача») и 3 («RLS документа») — мимо объекта**: даны 7 ролей и шаблон `#ЧтениеПроцесса` для `Task.ЗадачаИсполнителя`, тогда как у документа `Document.Задача` это **11 ролей и дескрипторный RLS `#ПоДескрипторуОбъекта`**.
- **Подвопросы 4 (рабочие группы) и 5 (модуль `РаботаСРабочимиГруппами`) — в точку** (механизм общий для обоих объектов).
- **Подвопрос 2 («видит ли чужие задачи») — частично**: концепт верен, но через RLS задачи-исполнителя, а не документа.

> **Сверка с исходником (оркестратор):** `#ЧтениеПроцесса(` подтверждён в `Roles/ЧтениеЗадач`, `…/РаботаСЗадачамиИБизнесПроцессами`, `…/ИзменениеВыполнениеЗадач` — но это RLS объекта `Task.ЗадачаИсполнителя`. RLS **документа** `Document.Задача` — `#ПоДескрипторуОбъекта("", "Задача", …)` в `Roles/РаботаСЗадачами/Ext/Rights.xml` — bsl лишь перечислил этот шаблон (#20), но не разобрал. Объект из вопроса — `Document.Задача`; bsl ответил про задачу-исполнителя. Это смещение предмета, а не паритет.

## Что сервер дал хорошо
- **Полный перечень ролей на `Task.ЗадачаИсполнителя`** через `grep_text` по `Roles/*/Ext/Rights.xml` (#11): 167 совпадений в 13 файлах — точный список ролей с RLS и без (`ЧтениеПроцессовИЗадачБезОграничения`, `ПолныеПрава`).
- **Точный SQL RLS-шаблона** `#ЧтениеПроцесса` (#23): JOIN `УчастникиПроцессов`+`СоставСубъектовПравДоступа`, условие `Сотрудник В (&СотрудникиПользователя)` И области делегирования ("", "Задачи", "ЗадачиПросмотр").
- **Прямой ответ «видит ли чужие задачи»** (#24): `ЧтениеПроцессовИЗадачБезОграничения` — Read=true БЕЗ restrictionByCondition (полный обход RLS). Это самый прямой ответ на ключевой подвопрос.
- **Перечень шаблонов ограничений** (#20): `ЧтениеПроцесса`, `ИзменениеПроцесса`, `ПоДескрипторуОбъекта`, `ПоДескрипторуРегистра` — карта всех RLS-механизмов.
- **Структура регистра `РабочиеГруппы`** из XML: измерения Объект (Document.Задача/ДействиеЗадачи/Проекты), Участник; ресурсы Изменение/Источник/Автоподстановка.
- **Поведение `ПриЗаписи` задачи** (#22, #33): `ДобавитьУчастникаВТаблицуНабора` для Исполнителя/РольИсполнителя.
- **Кастомизация Тест найдена точно** (#26): комментарий `//+++ Тест; Тестов Т.Т.; 88958; оптимизация запроса` в `ПроверитьПраваУчастниковРабочейГруппыНаОбъект` — деталь, которую rlm не выделил.

## Что сервер НЕ дал
- **Ответ по объекту из промпта** (`Document.Задача`) — ключевой пробел. Роли и RLS даны для `Task.ЗадачаИсполнителя`; дескрипторный RLS документа (`#ПоДескрипторуОбъекта` + регистры `ДескрипторыДляОбъектов`/`ПраваПоДескрипторамДоступаОбъектов`) лишь упомянут в перечне шаблонов (#20), без SQL и без разбора (это сделал rlm).
- **Структура регистра `СоставСубъектовПравДоступа`** — не читалась (частичное «додумывание» связи с `СотрудникиВКонтейнерах`, по самооценке агента).
- **Полный список ролей** — `list_files Roles/ limit=100` мог обрезать вторую страницу (самооценка агента).

## Паттерны поведения агента
- Stateless, `repo="Тест ДО3"`. Сильная стратегия для прав: `grep_text` по `Roles/*/Ext/Rights.xml` — эффективно нашёл все роли и шаблоны RLS без сессии.
- Читал Rights.xml ролей ограниченными диапазонами строк → **ни одного ⚠️-дампа** (максимум — #4 search_function ~12K = 7.3%).
- 2 retry: #9 (regex `<name>Task\.` не сработал → широкий grep) и #28 (забыл `repo` → повтор). Оба восстановлены.
- 2 пустых grep (#9, #12 по строгим regex) — дешёвый шум.

## Выявленные проблемы
| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| **Смещение предмета: ответил про `Task.ЗадачаИсполнителя`, а не про документ `Document.Задача`** | Промпт просит «документ Задача»; #5 — пивот на `Tasks/`; роли (подвопрос 1) и RLS (подвопрос 3) даны не для того объекта |
| Дескрипторный RLS документа не углублён | `#ПоДескрипторуОбъекта` лишь перечислен; SQL и регистры дескрипторов не разобраны |
| `grep_body`/`grep_text` чувствительны к regex | #9, #12 пустые на строгих паттернах → retry/смена |
| `СоставСубъектовПравДоступа` не прочитан | Связь выведена логически (частичное додумывание) |
| Возможный обрыв списка ролей | `list_files limit=100` — вторая страница не проверена |

## Вывод
bsl-indexer v0.15 технически отработал аккуратно (≈250K токенов, 1.35× от rlm, без ⚠️) и нашёл реальные механизмы — `grep_text` по `Roles/*/Ext/Rights.xml` оказался **эффективным приёмом для анализа прав/RLS**, дал точный SQL `#ЧтениеПроцесса`, обход `ЧтениеПроцессовИЗадачБезОграничения` и даже кастомизацию Тест с авторством. **Но ответ не по объекту из промпта:** вопрос про **документ** `Document.Задача`, а bsl заякорился на платформенной `Task.ЗадачаИсполнителя` (#5 — явный пивот на `Tasks/`). Поэтому подвопросы про роли и RLS **документа** (1, 3) закрыты для смежного объекта, а дескрипторный RLS `Document.Задача` оставлен на уровне упоминания. Подвопросы 4–5 (рабочие группы, модуль) — в точку. Итог: **ЧАСТИЧНО** — корректно, но мимо предмета вопроса; на этом тесте rlm и точнее по объекту, и экономнее.
