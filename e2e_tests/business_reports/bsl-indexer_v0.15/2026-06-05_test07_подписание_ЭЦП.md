## 1. Как реализован бизнес-процесс «Подписание»

В конфигурации реализован полноценный бизнес-процесс **`BusinessProcess.Подписание`** (файл `BusinessProcesses/Подписание.xml`, uuid `8ae3feaf-0038-4967-bd3e-881b5e2edfc1`).

**Маршрут процесса** включает три точки:
- `Подписать` — задача непосредственному подписанту
- `ОбеспечитьПодписание` — задача ответственному, если участник отличается от подписанта (реализовано в `ОбновитьТочкуМаршрутаУчастникаПодписания`: если `Участник <> Подписывающий`, то точка = ОбеспечитьПодписание)
- `ОбработатьРезультат` — задача автору процесса для обработки итога

Задачи формируются типом `Task.ЗадачаИсполнителя`. Процесс поддерживает **итерации** (реквизит `КоличествоИтераций`, по умолчанию 2) и **этапы** (таблица `Этапы`). Порядок выполнения участниками — параллельно или последовательно (`ПорядокВыполненияЭтапаПроцесса`).

**Предметы** процесса задаются через механизм мультипредметности (`Мультипредметность.ПередатьПредметыПроцессу`). Базируется на объектах: `Catalog.Файлы`, `Document.ИсходящееПисьмо`, `Document.ВходящееПисьмо`, `Catalog.Проекты`, `Catalog.Контрагенты` и др.

## 2. Параметры запуска процесса

При создании нового процесса (`ОбработкаЗаполнения` в ObjectModule) автоматически устанавливаются:

| Параметр | Реквизит | Тип | Значение по умолчанию |
|----------|----------|-----|----------------------|
| Автор | `Автор` | `CatalogRef.Сотрудники` | Текущий сотрудник |
| Способ подписания | `СпособПодписания` | `EnumRef.СпособыПодписанияПредметаПроцесса` | **ПЭП** (Простая ЭП) |
| Порядок выполнения | `ПорядокВыполненияУчастниками` | `EnumRef.ПорядокВыполненияЭтапаПроцесса` | **Параллельно** |
| Кол-во итераций | `КоличествоИтераций` | Число | 2 |
| Наименование | `Наименование` | Строка(150) | Авто по предметам |
| Шаблон | `Шаблон` | `CatalogRef.ШаблоныПодписания` | Из шаблона |
| Срок исполнения | `СрокИсполненияПроцесса` | Дата+Время | — |
| Состояние | `Состояние` | `EnumRef.СостоянияБизнесПроцессов` | **Активен** |
| Важность | `Важность` | `EnumRef.ВариантыВажностиОбъектов` | **Обычная** |

**Участники** (таблица `Участники`) заполняются с указанием:
- `Участник` — исполнитель
- `Подписывающий` — фактический подписант (может отличаться)
- `ТочкаМаршрута` — Подписать или ОбеспечитьПодписание

Процесс может запускаться **интерактивно** (функция `МожетЗапускатьсяИнтерактивно` возвращает `Истина`) или из шаблона (`Catalog.ШаблоныПодписания`).

## 3. Поддержка электронной подписи (ЭП/ЭЦП)

ЭП поддерживается полностью. Реализованы три режима подписания через перечисление `Enum.СпособыПодписанияПредметаПроцесса`:

| Значение | Синоним | Описание |
|----------|---------|----------|
| `НаБумаге` | «На бумаге» | Бумажный документ, ЭП не используется |
| `ПЭП` | «Простая ЭП» | Простая электронная подпись (по умолчанию) |
| `УЭП` | «Усиленная ЭП» | Усиленная квалифицированная ЭП с криптосертификатом |

**Подсистема ЭП** из БСП включает 23 общих модуля с префиксом `ЭлектроннаяПодпись*`:
- `ЭлектроннаяПодпись` (3110 строк) — основной API: `ИспользоватьЭлектронныеПодписи()`, `ДобавлениеИзменениеЭлектронныхПодписей()`, `МенеджерКриптографии()`, `ЗаписатьСертификатВСправочник()`
- `ЭлектроннаяПодписьСлужебный` (7643 строки) — внутренняя логика
- `ЭлектроннаяПодписьСлужебныйКлиент` (11074 строки) — клиентская часть криптоопераций
- `ЭлектроннаяПодписьКлиент` (2260 строк) — API для клиента
- `ЭлектроннаяПодписьДокументооборотСобытия` (1251 строка) — интеграция с ДО
- `ЭлектроннаяПодписьДокументооборотХолдинг` (1100 строк) — холдинговая специфика

**Группа модулей ДО** `РаботаСЭП*` (5 модулей):
- `РаботаСЭП` (4670 строк) — основной: `ЗанестиИнформациюОПодписях()`, `ОбъектМожетБытьПодписанЭП()`
- `РаботаСЭПКлиент` (2437 строк) — клиентская часть
- `РаботаСЭПКлиентСервер` (704 строки) — клиент-серверная часть
- `РаботаСЭПВызовСервера` (486 строк) — вызов сервера
- `РаботаСЭППереопределяемый` (97 строк) — точки расширения

**Справочник сертификатов:** `Catalog.СертификатыКлючейЭлектроннойПодписиИШифрования` — хранит ключи ЭП пользователей. Используется через `ЭлектроннаяПодпись.ЗаписатьСертификатВСправочник()`.

**Функциональная опция:** `ИспользоватьЭлектронныеПодписи` — глобальное включение/выключение ЭП. Проверяется во множестве мест: `ЭлектроннаяПодпись.ИспользоватьЭлектронныеПодписи()`.

**Константа:** `Constants.ИспользоватьВнешнееПодписание` — включение режима внешнего подписания (кастомизация Тест).

### Кастомизация Тест: внешнее подписание через Диадок

Задача **89132** (автор: Тестов Т.Т., 06.02.2024) — «Подписание ЭЦП внешним сервисом»:
- Подсистема `Subsystem.ВнешнееПодписание`
- Общий модуль `РаботаСВнешнимПодписанием` — интегрируется в записи документов (`ПередЗаписьюДокумента`, `ПриЗаписиДокумента`) и задачи (`ПриВзятииЗадачиВРаботу`)
- HTTP-сервис `тст_STORM` принимает POST-запросы с подписанными документами (`ПодписатьИОтправитьPOST`, `ПодписатьПакетДокументов`)
- Результат обрабатывается в `тст_ИнтеграцияОбщегоНазначенияСервер.ОтветОПодписанииИОтправкеДокументовВДиадок()`
- `Catalog.СервисыВнешнегоПодписания` — справочник с настройками API-ключей внешних сервисов

## 4. Хранение данных о подписях

### 4.1 Регистр сведений `РегистрСведений.ЭлектронныеПодписи`

Основное хранилище ЭП. Независимый непериодический регистр.

**Измерения (ключ записи):**
| Поле | Тип | Описание |
|------|-----|----------|
| `ПодписанныйОбъект` | `DefinedType.ПодписанныйОбъект` (Master, MainFilter) | Объект, к которому относится подпись |
| `ПорядковыйНомер` | Число | Номер подписи (для множественных подписей) |

**Ресурсы (данные подписи):**
| Поле | Тип | Описание |
|------|-----|----------|
| `Версия` | Число | Версия набора ключевых реквизитов |
| `ДатаПодписи` | Дата+Время | Дата установки подписи |
| `ДатаПроверкиПодписи` | Дата+Время | Дата последней проверки |
| `ИмяФайлаПодписи` | Строка(260) | Имя файла подписи (служебное) |
| `Комментарий` | Строка(0) | Комментарий к подписи |
| `КомуВыданСертификат` | Строка(0) | Владелец сертификата (ФИО, организация, должность) |
| `Отпечаток` | Строка(28) | Отпечаток сертификата (служебное) |
| `Подпись` | ХранилищеЗначения | **Двоичные данные подписи** |
| `ПодписьВерна` | Булево | Результат последней проверки |
| `Сертификат` | ХранилищеЗначения | Двоичные данные сертификата |
| `СертификатДействителен` | Булево | Признак действительности сертификата |
| `СрокДействияПоследнейМеткиВремени` | Дата+Время | Срок действия (CAdES-T и выше) |
| `ТекстОшибкиПроверкиПодписи` | Строка | Текст ошибки (если подпись неверна) |
| `ТекстОшибкиПроверкиСертификата` | Строка | Текст ошибки сертификата |
| `ТипПодписи` | `EnumRef.ТипыПодписиКриптографии` | CAdES-BES, CAdES-T и т.д. |
| `ТребуетсяПроверка` | Булево | Отложенная проверка (нет криптопровайдера) |
| `УстановившийПодпись` | `CatalogRef.Пользователи` | Кто поставил подпись |

**Атрибуты:** `ИдентификаторПодписи` (UUID), `ОшибкаПриАвтоматическомПродлении` (Булево), `ПропуститьПриПродлении` (Булево).

### 4.2 Регистр `InformationRegister.ЭлектронныеПодписиПоМЧД`
Отдельный регистр для подписей МЧД (машиночитаемые доверенности), 467 строк XML.

### 4.3 Реквизиты на документах

На объектах (Catalog.ДокументыПредприятия, Catalog.Файлы, Catalog.ВерсииФайлов) хранятся:
- `ПодписанЭП` (Булево) — флаг наличия ЭП
- `Подписал` (CatalogRef.Сотрудники) — кто подписал
- `РезультатПодписания` (EnumRef.РезультатыПодписания) — итог подписания
- `ДатаПодписания` (Дата+Время) — когда подписано

### 4.4 Внутренняя таблица процесса

Бизнес-процесс Подписание имеет внутреннюю таблицу `РезультатыПодписания` (TabularSection), в которую через `ПоместитьРезультатВыполненияЗадачиПодписать()` записывается результат по каждой задаче.

### 4.5 Справочник ДействияПодписания
`Catalog.ДействияПодписания` (2476 строк XML, ManagerModule 1209 строк) — для электронного документооборота с контрагентами (Диадок). Хранит история действий подписания входящих/исходящих ЭД.

## 5. Что происходит после подписания

### 5.1 Изменение статуса объектов

В процедуре `РаботаСЭП.ЗанестиИнформациюОПодписях()` при успешном подписании:

1. Вызывается `ЭлектроннаяПодпись.ДобавитьПодписьКФайлу()` для файлов
2. Для документов и файлов: **`ПодписанЭП = Истина`**
3. Для `Catalog.ДокументыПредприятия` при виде подписи "ПодписьДокумента":
   - `Подписал = Сотрудники.ОсновнойСотрудникПользователя(УстановившийПодпись)`
   - **`РезультатПодписания = Перечисления.РезультатыПодписания.Подписано`**
   - `ДатаПодписания = СвойстваПодписи.ДатаПодписи`
4. Для `Catalog.ВизыСогласования` и `Catalog.Резолюции`: `Подписана = Истина`
5. Объект записывается: `ПодписываемыйОбъект.Записать()`

### 5.2 Завершение бизнес-процесса

Функция `ПроцессЗавершилсяУдачно(Ссылка)` в ManagerModule проверяет:
```
Результат = РеквизитыПроцесса.Завершен
    И (РезультатПодписания = Перечисления.РезультатыПроцессаПодписания.Подписано)
```

- Реквизит `РезультатПодписания` (EnumRef.РезультатыПроцессаПодписания) фиксирует итог
- `РезультатВыполненияПроцесса()` возвращает `ВариантыВыполненияПроцессовИЗадач.Положительно` при успехе
- Завершение процесса происходит после прохождения всех этапов: `ВсеЭтапыПодписанияПройдены()` — проверяет флаг `Пройден` у всех участников с точками Подписать/ОбеспечитьПодписание

### 5.3 Изменение состояния бизнес-процесса

Реквизит `Состояние` (EnumRef.СостоянияБизнесПроцессов, default=Активен) изменяется платформенным механизмом при завершении процесса.

## Итоговое резюме

Бизнес-процесс **Подписание** в конфигурации реализован полноценно и многоуровнево: поддерживает три способа подписания (на бумаге, ПЭП, УЭП), многоэтапные маршруты с параллельным/последовательным выполнением, шаблоны (`Catalog.ШаблоныПодписания`), итерации. Данные ЭП хранятся в **`РегистрСведений.ЭлектронныеПодписи`** с полным составом криптографических реквизитов (двоичная подпись, сертификат, отпечаток, тип CAdES, дата, проверка). После подписания на документе устанавливаются флаг `ПодписанЭП=Истина`, реквизиты `Подписал` и `РезультатПодписания=Подписано`. В конфигурации Тест добавлена кастомизация: внешнее подписание через HTTP-сервис Диадок (задача 89132).
