## 1. Реквизиты, заполняемые при создании

Документ **Document.ВходящееПисьмо** (из `Documents/ВходящееПисьмо.xml`).

### Параметры нумерации (из MCP)
- **NumberType:** String, длина 50, переменная
- **NumberPeriodicity:** Year (сквозная в рамках года)
- **Autonumbering:** true (автонумерация)
- **Posting:** Deny (документ **не проводится**)

### Как создаётся письмо (из MCP — get_function ЗаписатьВходящееПисьмо)
Входящее письмо **не создаётся вручную пользователем** — форма документа принудительно отказывает при попытке открытия нового объекта (`ПриСозданииНаСервере`: `Если Не ЗначениеЗаполнено(Объект.Ссылка) Тогда Отказ = Истина`).

Создание происходит исключительно через функцию `ВстроеннаяПочтаСервер.ЗаписатьВходящееПисьмо()`:
1. Проверка дубля по `ИдентификаторСообщения` (Message-Id) + `УчетнаяЗапись` → если уже принято, запись в РС.ИдентификаторыПолученныхПисем и выход
2. `Документы.ВходящееПисьмо.СоздатьДокумент()`
3. Заполнение из структуры почтового сообщения (`ЗаполнитьВходящееПисьмоИзСтруктурыПочтовогоСообщения`)
4. Автоопределение проекта из заголовка `X-1C-Project-ID`
5. Поиск основания (In-Reply-To / References) → связь с исходящим письмом
6. `ПисьмоОбъект.Записать()`
7. Запись текста в РС.ТекстыПисем
8. При ошибках доставки → РС.КешИнформацииОбОбъектах
9. Запись идентификаторов → РС.ИдентификаторыПолученныхПисем
10. Регистрация бизнес-события `Справочники.ВидыБизнесСобытий.ПолучениеВходящегоПисьма`
11. Применение пользовательских правил обработки (`ПрименитьПользовательскиеПравила`)

## 2. Бизнес-процессы по входящему письму

Из `grep_code` по xml-файлам бизнес-процессов подтверждено, что все следующие БП имеют `Document.ВходящееПисьмо` в списке допустимых предметов:

| Бизнес-процесс | Файл | Тип |
|---|---|---|
| **Рассмотрение** | BusinessProcesses/Рассмотрение.xml | Направление на рассмотрение руководителю |
| **Исполнение** | BusinessProcesses/Исполнение.xml | Постановка на исполнение |
| **Согласование** | BusinessProcesses/Согласование.xml | Согласование документа |
| **Подписание** | BusinessProcesses/Подписание.xml | Подписание |
| **Утверждение** | BusinessProcesses/Утверждение.xml | Утверждение |
| **Ознакомление** | BusinessProcesses/Ознакомление.xml | Ознакомление сотрудников |
| **КомплексныйПроцесс** | BusinessProcesses/КомплексныйПроцесс.xml | Составной процесс |
| **Регистрация** | BusinessProcesses/Регистрация.xml | Регистрация с присвоением номера |
| **Приглашение** | BusinessProcesses/Приглашение.xml | Приглашение на мероприятие (iCalendar) |
| **РешениеВопросовВыполненияЗадач** | BusinessProcesses/РешениеВопросовВыполненияЗадач.xml | Решение вопросов по задачам |

**Ключевые три** (по условию теста):
- **Рассмотрение** — инициирует рассмотрение письма руководителем, результатом является резолюция
- **Исполнение** — ставит письмо на контроль исполнения, назначает исполнителей и срок
- **Согласование** — запускает маршрут согласования документа с письмом как предметом

## 3. Регистрация входящего письма — нумерация

### Механизм регистрации (из MCP — get_function ЗарегистрироватьПредмет, CommonModules/Делопроизводство)

Регистрация входящего письма выполняется через `Делопроизводство.ЗарегистрироватьПредмет()`:

1. **Проверка права:** `ДокументооборотПраваДоступа.ЕстьПравоРегистрации(Предмет)` — без права регистрации операция запрещена
2. **Блокировка объекта** для исключения гонки
3. **Формирование числового номера:** `Нумерация.СформироватьЧисловойНомерДокумента(СтруктураПараметров, ПредметОбъект.ЧисловойНомер)` — хранится в реквизите `ЧисловойНомер` (реквизит объекта Справочника/Документа предприятия)
4. **Формирование строкового номера:** `Нумерация.СформироватьСтроковыйНомерДокумента(...)` → `ПредметОбъект.РегистрационныйНомер` — форматированная строка по шаблону нумератора
5. **Заполнение регистратора:** `ПредметОбъект.Зарегистрировал = Сотрудники.ОсновнойСотрудник()` для документов предприятия (или `Пользователи.ТекущийПользователь()` для иных)
6. **Запись объекта:** `ПредметОбъект.Записать()`
7. **Уведомление МЭДО:** `МЭДОПереопределяемый.ПриРегистрацииДокумента()` — для входящих направление = Перечисления.НаправленияСообщенийМЭДО.Входящее
8. **Протоколирование:** `ПротоколированиеРаботыСотрудников.ЗаписатьРегистрациюДокумента(Ссылка, РегистрационныйНомер)`

**Важно:** Нумерация ВходящегоПисьма как почтового документа (`Document.ВходящееПисьмо`) отличается от нумерации входящих документов предприятия (`Catalog.ДокументыПредприятия`). Почтовое ВходящееПисьмо имеет собственный **автонумератор** (NumberPeriodicity=Year, Autonumbering=true), а `РегистрационныйНомер` присваивается только тогда, когда пользователь явно запускает процедуру регистрации (через БП Регистрация или вручную). До регистрации документ существует с автоматическим `Number` (системным) без `РегистрационныйНомер`.

**Кто регистрирует:** Пользователь с правом регистрации (роль проверяется через `ДокументооборотПраваДоступа.ЕстьПравоРегистрации`). Для документов предприятия — `Сотрудники.ОсновнойСотрудник()` текущего пользователя.

## 4. Обработчики событий при записи

### 4.1. Объектный модуль — `Documents/ВходящееПисьмо/Ext/ObjectModule.bsl` (из MCP)

#### ПередЗаписью(Отказ, РежимЗаписи, РежимПроведения)
- Пропуск при `ОбменДанными.Загрузка = Истина`
- Установка флага `ЭтоНовоеПисьмо` (Ссылка.Пустая())
- Для нового письма: `ВстроеннаяПочтаСервер.ПолучитьСпособАдресацииОбъекта` → заполняет `НомерСпособаАдресации`
- Для существующего: читает предыдущие значения `ПометкаУдаления` и `Папка`
- При смене `ПометкаУдаления`: `РаботаСФайламиВызовСервера.ПометитьНаУдалениеПриложенныеФайлы`
- При смене `Папка` непривилегированным пользователем: проверяет права удаления/добавления в папку
- `ВстроеннаяПочтаСервер.ПрименитьПравила(ЭтотОбъект)` — применение правил обработки почты
- **Обязательность:** `Если Не ЗначениеЗаполнено(Папка) Тогда Отказ = Истина` — без папки запись запрещена

#### ПриЗаписи(Отказ)
- Пропуск при `ОбменДанными.Загрузка = Истина`
- При смене `Папка` или `ПометкаУдаления`:
  - `РегистрыСведений.КоличествоПисемВПапках.ОчиститьЗаписиПоПапке(ПредыдущаяПапка)`
  - `РегистрыСведений.КоличествоПисемВПапках.ОчиститьЗаписиПоПапке(Папка)`
- При смене `ПометкаУдаления`: `ПротоколированиеРаботыСотрудников.ЗаписатьПометкуУдаления`
- Расширение рабочей группы предмета: при ведении автоматического заполнения РГ — добавляет отправителей/получателей (из РС.СведенияОбАдресатах) как участников рабочей группы предмета

#### ПередУдалением(Отказ)
- `ВстроеннаяПочтаСервер.ПередУдалениемПисьма(ЭтотОбъект.Ссылка)` — очистка связанных данных

## Сводный жизненный цикл

```
[Почтовый сервер]
        │
        ▼ ВстроеннаяПочтаСервер.ЗаписатьВходящееПисьмо()
[1. Проверка дубля по ИдентификаторСообщения → РС.ИдентификаторыПолученныхПисем]
        │
        ▼
[2. Создание: Документы.ВходящееПисьмо.СоздатьДокумент()]
   Заполняются: УчетнаяЗапись, Папка (входящие), ВидМаршрутизации=Внешняя,
   ДатаОтправки, ДатаПолучения, Тема, Отправитель, Получатели, Текст (HTML/PlainText),
   ИдентификаторСообщения, Размер, ЕстьВложения...
        │
        ▼ ПередЗаписью срабатывает:
[3. ВстроеннаяПочтаСервер.ПрименитьПравила() — автоматические правила обработки]
   Проверка Папки (обязательна), НомерСпособаАдресации
        │
        ▼ Документ.Записать()
        │
        ▼ ПриЗаписи срабатывает:
[4. РС.КоличествоПисемВПапках обновляется]
   Расширение рабочей группы предмета (если ведётся)
        │
        ▼
[5. РС.ТекстыПисем, РС.ИдентификаторыПолученныхПисем, РС.КешИнформацииОбОбъектах]
[6. БизнесСобытие ПолучениеВходящегоПисьма]
[7. ОбновитьВеткуПереписки → Catalog.ВеткиПереписки]
[8. Применение пользовательских правил (переместить, пометить, оповестить)]
        │
        ▼
[Письмо доступно пользователю в папке входящих]
        │
        ├──▶ Прочтение → РС.СведенияОПросмотреПисем.УстановитьПризнакПросмотрено
        │
        ├──▶ Регистрация (вручную или через БП Регистрация):
        │     Делопроизводство.ЗарегистрироватьПредмет()
        │     → РегистрационныйНомер, ДатаРегистрации, Зарегистрировал
        │     → ПротоколированиеРаботыСотрудников.ЗаписатьРегистрациюДокумента
        │
        ├──▶ Запуск БП: Рассмотрение / Исполнение / Согласование / Подписание / Утверждение...
        │
        ├──▶ Назначение предмета переписки (Документ, Проект, Задача...)
        │     → замена предмета/проекта у всей ветки переписки
        │
        └──▶ Ответить / ОтветитьВсем / Переслать → создание исходящего письма
```

## Пометки

Данные, полученные **напрямую из MCP**:
- Все реквизиты и ТЧ документа — из `read_file Documents/ВходящееПисьмо.xml`
- Код ПередЗаписью, ПриЗаписи, ПередУдалением — из `get_function` ObjectModule
- Список всех БП — из `grep_code` по xml_1c
- Логика регистрации — из `get_function ЗарегистрироватьПредмет`
- Механизм создания — из `get_function ЗаписатьВходящееПисьмо`
- Обработчики формы — из `read_file Form.xml` (Events-секция) + `get_function`
