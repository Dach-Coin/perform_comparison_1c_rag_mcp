# Система прав доступа к задачам в 1С:Документооборот КОРП 3.0

**Дата анализа:** 2026-06-05  
**Конфигурация:** 1С:Документооборот КОРП 3.0 (индекс «Тест ДО3»)  
**Источник данных:** bsl-indexer v0.15, 33 вызова MCP

---

## 1. Какие роли определяют доступ к документу Задача?

В системе объект задачи представлен типом **`Task.ЗадачаИсполнителя`** (путь: `Tasks/ЗадачаИсполнителя`). Дополнительно существует документ **`Document.Задача`**, который также фигурирует в измерении регистра РабочиеГруппы.

Доступ к объекту `Task.ЗадачаИсполнителя` предоставляется следующими ролями:

| Роль | Права на Task.ЗадачаИсполнителя | Наличие RLS |
|------|----------------------------------|-------------|
| **РаботаСЗадачамиИБизнесПроцессами** | Read, Insert, Update, View, Edit, Execute, InteractiveExecute | Да — `#ЧтениеПроцесса("БизнесПроцесс")` |
| **ЧтениеЗадач** | Read, View, InputByString | Да — `#ЧтениеПроцесса("БизнесПроцесс")` |
| **ИзменениеВыполнениеЗадач** | Read, Update, View, Edit, Execute, InteractiveExecute | Да — `#ЧтениеПроцесса("БизнесПроцесс")` |
| **КонтрольЗадачИБизнесПроцессов** | Read, View | Да — через `#ЧтениеПроцесса` |
| **УправлениеБизнесПроцессами** | Read, View | Да |
| **ЧтениеПроцессовИЗадачБезОграничения** | Read, View | **НЕТ** (без restrictionByCondition) |
| **ПолныеПрава** | Полный доступ | Нет |
| **АдминистраторСистемы** | Полный доступ | Нет |

**Ключевой вывод:** Основная роль для работы с задачами — **`РаботаСЗадачамиИБизнесПроцессами`**. Она даёт права на создание, чтение, изменение и выполнение задач, но с RLS-ограничением — пользователь видит только задачи тех процессов, в которых он является участником.

Роль **`ЧтениеПроцессовИЗадачБезОграничения`** — привилегированная: она читает все задачи без каких-либо ограничений на уровне записей. Предназначена для административных и контрольных функций.

## 2. Может ли сотрудник видеть задачи других сотрудников?

**По умолчанию — нет.** Стандартный механизм ограничения (RLS) настроен так, что сотрудник видит только задачи, связанные с бизнес-процессами, в которых он является участником.

**Механизм отбора** (шаблон `#ЧтениеПроцесса("БизнесПроцесс")`, файл `Roles/РаботаСЗадачамиИБизнесПроцессами/Ext/Rights.xml`, строки 2743–2769):

```sql
ТаблицаПроцесса ИЗ #ТекущаяТаблица КАК ТаблицаПроцесса

  ВНУТРЕННЕЕ СОЕДИНЕНИЕ РегистрСведений.УчастникиПроцессов КАК УчастникиПроцессов
    ПО ТаблицаПроцесса.БизнесПроцесс = УчастникиПроцессов.Процесс

  ВНУТРЕННЕЕ СОЕДИНЕНИЕ РегистрСведений.СоставСубъектовПравДоступа КАК СоставСубъектов
    ПО УчастникиПроцессов.Участник = СоставСубъектов.Субъект

  ГДЕ СоставСубъектов.Сотрудник В (&СотрудникиПользователя)
    И СоставСубъектов.ИмяОбластиДелегирования В ("", "Задачи", "ЗадачиПросмотр")
```

Условие активируется только при включённом параметре конфигурации `&ДокументооборотИспользоватьОграниченияПравДоступа` (директива `#Если`). При отключённых ограничениях все задачи доступны всем пользователям с соответствующей ролью.

**Исключения — случаи, когда сотрудник МОЖЕТ видеть чужие задачи:**
1. Назначена роль **`ЧтениеПроцессовИЗадачБезОграничения`** — читает все задачи без RLS.
2. Назначена роль **`КонтрольЗадачИБизнесПроцессов`** — контролёр видит задачи, где он является автором процесса (по полю ДанныеБизнесПроцессов.Автор).
3. Пользователь является **участником процесса** (через рабочие группы или непосредственно через УчастникиПроцессов) — тогда задача его процесса доступна.
4. Наличие прав **делегирования** с областью `"ЗадачиПросмотр"` позволяет видеть задачи делегирующего сотрудника.

## 3. Есть ли ограничение на уровне записей (RLS) для задач?

**Да, RLS есть и работает на нескольких уровнях.**

### 3.1 RLS на объект Task.ЗадачаИсполнителя

Ограничение определено в ролях `РаботаСЗадачамиИБизнесПроцессами`, `ЧтениеЗадач`, `ИзменениеВыполнениеЗадач` через шаблон `#ЧтениеПроцесса("БизнесПроцесс")`:
- Право **Read** ограничено: пользователь видит только задачи, в бизнес-процессах которых он фигурирует как участник (через `РегистрСведений.УчастникиПроцессов`)
- Право **Update** в роли `РаботаСЗадачамиИБизнесПроцессами` ограничено строже: только автор процесса (`ДанныеБизнесПроцессов.Автор`) может изменять параметры

### 3.2 RLS на регистры, связанные с задачами

Регистр `ПереносыСроковВыполненияПроцессовИЗадач` имеет RLS на операции Read и Update, также завязанный на участие в процессе и авторство.

### 3.3 Регистры, участвующие в RLS

| Регистр | Роль в RLS |
|---------|------------|
| `РегистрСведений.УчастникиПроцессов` | Хранит участников каждого бизнес-процесса |
| `РегистрСведений.СоставСубъектовПравДоступа` | Хранит сотрудников в субъектах доступа, с областями делегирования |
| `РегистрСведений.ДанныеБизнесПроцессов` | Хранит автора процесса для RLS на Update |
| `РегистрСведений.РабочиеГруппы` | Хранит участников объектов (документов, задач) с флагом Изменение |

### 3.4 Структура регистра РабочиеГруппы

Измерения: **Объект** (составной тип: ДокументыПредприятия, Документ.Задача, Мероприятия, Проекты, шаблоны процессов, бизнес-процессы и др.) + **Участник** (КонтейнерыСотрудников).  
Ресурсы: **Изменение** (boolean — есть ли право изменять объект), **Источник** (откуда добавлен участник), **Автоподстановка**.

## 4. Как связаны рабочие группы с доступом к документам?

Механизм рабочих групп работает **параллельно** с RLS-ограничениями ролей и дополняет их для документов предприятия. Для задач (`Task.ЗадачаИсполнителя`) рабочая группа ведётся ограниченно.

### 4.1 Автоматическое ведение рабочих групп

Функция `ПоОбъектуВедетсяАвтоматическоеЗаполнениеРабочейГруппы` (`CommonModules/РаботаСРабочимиГруппами/Ext/Module.bsl`, строки 1281–1306) возвращает `Истина` только для:
- `ДокументыПредприятия` — если не установлен флаг `ЗапретитьАвтоматическоеРасширениеДоступа`
- `Проекты` — если не группа
- `Мероприятия` — всегда

**Для `Task.ЗадачаИсполнителя` — возвращает `Ложь`.** Это означает, что рабочая группа задачи не ведётся через механизм автоматического расширения ДокументыПредприятия.

### 4.2 Расширение рабочей группы задачи при записи

Однако в `ObjectModule` задачи (`Tasks/ЗадачаИсполнителя/Ext/ObjectModule.bsl`, функция `ПриЗаписи`, строки 448–681) напрямую вызываются:
```bsl
РаботаСРабочимиГруппами.ДобавитьУчастникаВТаблицуНабора(
    ТаблицаУчастников, Исполнитель, ПравоИзменения);

РаботаСРабочимиГруппами.ДобавитьУчастникаВТаблицуНабора(
    ТаблицаУчастников, РольИсполнителя, ПравоИзменения);

// Расширение рабочей группы предметов задачи
РаботаСРабочимиГруппами.ДобавитьУчастниковВРабочуюГруппуОбъекта(
    ОбъектДляРасширенияРГ, ТаблицаУчастников, Истина);
```

Таким образом, **исполнитель задачи автоматически добавляется в рабочую группу** самой задачи и её предметов (документов-предметов процесса), что расширяет доступ к связанным объектам.

### 4.3 Расширение рабочей группы через процессы

Функция `РасширитьРабочуюГруппуСвязанныхОбъектов` (`Module.bsl`, строки 1697–1756) копирует участников рабочей группы одного объекта в связанные объекты. Функция `ДействияПриЗаписи` (строки 1910–1960) при добавлении нового участника в действие бизнес-процесса расширяет рабочую группу предмета процесса.

### 4.4 Проверка при сохранении рабочей группы

Функция `ПроверитьПраваУчастниковРабочейГруппыНаОбъект` проверяет, что добавляемые участники не нарушают:
1. Настройки **групп доступа контрагентов** (справочник `ГруппыДоступаКонтрагентов`)
2. Настройки **грифов доступа** (справочник `ГрифыДоступа`)
3. Настройки **доступа организаций** (справочник `Организации`)

> **Кастомизация Тест:** В теле этой функции присутствует оптимизация запроса с комментарием `//+++ Тест; Тестов Т.Т.; 88958; оптимизация запроса` (добавлена индексация ВТ по дескриптору).

## 5. Какой общий модуль отвечает за проверку прав (РаботаСРабочимиГруппами)?

**Модуль:** `CommonModules/РаботаСРабочимиГруппами/Ext/Module.bsl`  
**Размер:** 2565 строк, 170 КБ  
**Тип:** серверный общий модуль (вызывается с клиента через обёртки в `РаботаСРабочимиГруппамиКлиент`)

### Ключевые экспортные функции

| Функция | Строки | Назначение |
|---------|--------|------------|
| `ПерезаписатьРабочуюГруппуОбъекта` | 17–142 | Полная перезапись набора записей регистра РабочиеГруппы для объекта |
| `ДобавитьУчастниковВРабочуюГруппуОбъекта` | 281–300 | Добавление новых участников к существующей группе |
| `ДобавитьУчастниковИзИсточника` | 418–447 | Копирование участников из одного объекта в таблицу |
| `ДобавитьУчастникаВТаблицуНабора` | 460–488 | Добавление одного участника с проверкой через СотрудникиВКонтейнерах |
| `ПолучитьРабочуюГруппуДокумента` | 533–538 | Получение текущей РГ объекта через РегистрыСведений.РабочиеГруппы |
| `ПоОбъектуВедетсяАвтоматическоеЗаполнениеРабочейГруппы` | 1281–1306 | Предикат: работает ли авторасширение (для ДокументыПредприятия, Проекты, Мероприятия) |
| `ПроверитьПраваПередЗаписьюРабочейГруппы` | 1387–1416 | Валидация перед сохранением (вызывается из ОбъектПередЗаписьюНаСервере) |
| `ПроверитьПраваУчастниковРабочейГруппыНаОбъект` | 1448–1678 | Проверка совместимости участников РГ с грифами, ГДК, организациями |
| `РасширитьРабочуюГруппуСвязанныхОбъектов` | 1697–1756 | Распространение РГ на связанные объекты |
| `ДокументыПериЗаписи` | 1860–1889 | Обработчик события ПриЗаписи документов — точка входа для авторасширения |
| `ДействияПриЗаписи` | 1910–1960 | Обработчик события ПриЗаписи действий бизнес-процесса |
| `РасширитьРабочуюГруппуПредметов` | 1969–2013 | Расширение РГ предметов при добавлении участников |

### Схема работы при записи задачи

```
ЗадачаИсполнителя.ПриЗаписи()
  → РаботаСРабочимиГруппами.ДобавитьУчастникаВТаблицуНабора(Исполнитель)
  → РаботаСРабочимиГруппами.ДобавитьУчастникаВТаблицуНабора(РольИсполнителя)
  → Для каждого Предмет задачи:
      РаботаСРабочимиГруппами.ДобавитьУчастниковВРабочуюГруппуОбъекта(Предмет)
```

Функция `ДобавитьУчастникаВТаблицуНабора` перед добавлением проверяет:
1. Участник заполнен (`ЗначениеЗаполнено`)
2. Участник является контейнером сотрудников (`РегистрыСведений.СотрудникиВКонтейнерах.ЭтоКонтейнер`)
3. Участник с таким флагом Изменение ещё не добавлен (дедупликация)

## Итоговое резюме

Система прав доступа к задачам в 1С:Документооборот КОРП 3.0 построена на двух взаимодополняющих механизмах:

**1. Ролевой доступ с RLS.** Основная роль `РаботаСЗадачамиИБизнесПроцессами` предоставляет доступ к `Task.ЗадачаИсполнителя` с ограничением на уровне записей через шаблон `#ЧтениеПроцесса("БизнесПроцесс")`: пользователь видит только задачи тех бизнес-процессов, в которых он числится участником (через `РегистрСведений.УчастникиПроцессов` и `РегистрСведений.СоставСубъектовПравДоступа`). Чтение чужих задач возможно только через специальные роли (`ЧтениеПроцессовИЗадачБезОграничения`, `КонтрольЗадачИБизнесПроцессов`) или при наличии делегирования с областью `"ЗадачиПросмотр"`.

**2. Рабочие группы.** Для задачи при записи исполнитель автоматически добавляется в рабочую группу задачи и её предметов (документов) через `CommonModules/РаботаСРабочимиГруппами`. Рабочая группа хранится в `РегистрСведений.РабочиеГруппы` (измерения: Объект + Участник; ресурс: Изменение). Для документов предприятия механизм авторасширения рабочей группы работает автоматически при каждой записи; для задач — только явно через `ПриЗаписи` модуля задачи. Модуль `РаботаСРабочимиГруппами` (2565 строк) является центральным API управления доступом через рабочие группы и содержит точки контроля совместимости участников с грифами доступа, группами доступа контрагентов и ограничениями организаций.
