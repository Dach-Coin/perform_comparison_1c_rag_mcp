# Оценка качества: TEST-01 — Жизненный цикл входящего документа
**Сервер:** bsl-indexer (v0.15.0)
**Дата:** 2026-06-05
**Оценщик:** Оркестратор (Claude Opus 4.8, 1M context)

## Общая оценка: ПОЛНОСТЬЮ

Все 5 подвопросов закрыты. Структура реквизитов, обработчики записи, бизнес-процессы, регистры и логика регистрации получены через `read_file` / `get_function` / `grep_body` / `grep_code`. Ответ полный, но достигнут ценой существенного расхода контекста и обходных путей.

> Расхождение в оценке токенов: агент оценивал «полезные» символы (~227K) делением на 4 (латиница). По методологии воркфлоу (кириллица ×1.8) и с учётом двух крупных дампов реальный объём MCP-ответов ≈527K токенов — это и есть сопоставимая метрика расхода контекста.

## Что сервер дал хорошо
- **`get_stats` подтвердил индекс**: 21 922 файла, 88 737 функций, 4 616 классов, статус ready.
- **Точное перечисление файлов объекта** через `list_files` (`**/ВходящееПисьмо/**` → 17 файлов с числом строк).
- **Полные тела процедур** через `get_function`: `ПередЗаписью`, `ПриЗаписи`, обработчики формы (`ПриСозданииНаСервере`, `ПриЗаписиНаСервере`, `ПередЗаписьюНаСервере`).
- **Полная логика регистрации** через `grep_body` → `get_function ЗарегистрироватьПредмет` (Делопроизводство): право, авто-формирование числового и строкового номеров (`Нумерация.Сформировать*НомерДокумента`), `Зарегистрировал = Сотрудники.ОсновнойСотрудник()`.
- **Полный цикл создания письма** через `get_function ЗаписатьВходящееПисьмо` (ВстроеннаяПочтаСервер): дедуп по `ИдентификаторСообщения`, запись в РС.ТекстыПисем / КешИнформацииОбОбъектах / ИдентификаторыПолученныхПисем, бизнес-событие.
- **8 бизнес-процессов** через `grep_code` по `xml_1c`.

## Что сервер НЕ дал
- **Реквизиты через `get_object_structure`** — вернул `attributes=null` для Document. Структуру пришлось собирать из **сырого XML за 6 вызовов `read_file`** (стр. 1–1716) — дорого по контексту.
- **Читаемые подписки на события** — `get_event_subscriptions` (полный список) вернул ~89K символов с **повреждённой кириллицей (U+FFFD)**; имена модулей/процедур нечитаемы. Имена конкретных подписок для ВходящегоПисьма установить не удалось.
- **Фильтр подписок по имени события** — `event="ПередЗаписью"` дал 0 (внутренние имена английские: `BeforeWrite`/`OnWrite`).
- **Семантический поиск** — `search_function("регистрация входящего письма номер")` → 0 (инструмент лексический, не семантический).

## Паттерны поведения агента
- Stateless-модель: каждый вызов с `repo="Тест ДО3"`, без сессии.
- Столкнувшись с `attributes=null`, переключился на чтение сырого XML порциями по 300 строк (6 вызовов) — закрыл реквизиты, но раздул контекст.
- Дважды ушёл в **Bash-обход** (#12, #14), пытаясь восстановить кодировку сохранённого дампа подписок — протокольно это «серая зона» (разбор собственного MCP-вывода, не чтение исходников напрямую), но признак, что инструмент не отдал данные пригодно.
- После провала с подписками переключился на `grep_code`/`grep_body` — и закрыл вопрос через код.

## Выявленные проблемы
| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| **Повреждение кириллицы (U+FFFD)** в `get_event_subscriptions` (полный список) | ~89K символов нечитаемы; данные есть, но имена потеряны — критичный баг v0.15 |
| `get_object_structure` не отдаёт реквизиты Document (`attributes=null`) | Потребовалось 6× `read_file` по сырому XML вместо одного структурного вызова |
| **Крупные дампы раздувают контекст** | #10 (≈160K ток.) + #27 `get_file_summary` на большом ObjectModule (≈118K ток.) = 53% всего расхода; два скачка >20% (⚠️) |
| Фильтр `get_event_subscriptions` по русскому имени события не работает | Имена событий хранятся по-английски, фильтр по «ПередЗаписью» даёт 0 |
| `search_function` — только лексика | Семантический запрос вернул 0 результатов |

## Вывод
bsl-indexer v0.15 даёт точный лексический и структурный доступ к коду (`get_function`, `grep_body`, `read_file`) и полностью закрыл TEST-01, но ценой ≈527K токенов MCP-ответов — в ~3.2× больше, чем rlm-tools-bsl (163K) на тот же вопрос. Главные причины перерасхода: `get_object_structure` не отдаёт реквизиты (6× чтение сырого XML) и два гигантских дампа (`get_event_subscriptions`, `get_file_summary`). Отдельный риск — повреждение кириллицы в `get_event_subscriptions`. Сервер хорош для точечного чтения кода и grep по телу процедур; для обзорных задач (структура объекта, подписки) пока требует обходных путей.
