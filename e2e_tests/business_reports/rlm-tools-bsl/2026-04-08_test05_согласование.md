## 1. Общая структура бизнес-процесса

## 2. Параметры настройки при запуске согласования

### 2.1 Шаблон согласования

Основная точка настройки — справочник **ШаблоныСогласования** (24 атрибута, 5 ТЧ). При запуске процедура `ЗаполнитьПоШаблону(ШаблонБизнесПроцесса)` копирует параметры шаблона в бизнес-процесс.

**Параметры шаблона:**

| Параметр | Описание |
|----------|----------|
| ВариантСогласования | По очереди / Всем сразу / Смешанно |
| КоличествоИтераций | Сколько раз процесс может повториться |
| ОбрабатывающийРезультат | Кто обрабатывает результат согласования |
| ПодписыватьЭП | Требовать электронную подпись |
| Срок исполнения процесса | Общий срок |
| Срок обработки результатов | Срок для автора после завершения |
| Сроки (дни/часы/минуты) | Форматы задания сроков |
| ИспользоватьУсловия | Применять условия к исполнителям |

**ТЧ Исполнители шаблона:**

| Колонка | Тип | Описание |
|---------|-----|----------|
| Исполнитель | Сотрудники / ПолныеРоли | Кто согласует |
| ПорядокСогласования | ПорядокВыполненияЗадач | ВместеСПредыдущим / ПослеПредыдущего |
| СрокИсполнения / Дни / Часы / Минуты | DateTime / Decimal | Срок для этого согласующего |
| ВариантУстановкиСрокаИсполнения | Relative / Exact | Тип срока |
| Условие | CatalogRef.АлгоритмыПроверки | Условие включения согласующего |
| ИмяПредметаУсловия | ИменаПредметов | Предмет для проверки условия |

### 2.2 Вариант согласования

Перечисление **ВариантыМаршрутизацииЗадач**:

| Значение | Синоним | Поведение |
|----------|---------|-----------|
| `Параллельно` | Всем сразу | Задачи создаются всем согласующим одновременно |
| `Последовательно` | По очереди | Задача создаётся первому непройденному согласующему |
| `Смешанно` | Смешанно | Группы "вместе с предыдущим" параллельны, группы — последовательны |

### 2.3 Сроки исполнения

Модуль **СрокиИсполненияПроцессов** заполняет срок задачи при создании. Поддерживаются два варианта (`ВариантыУстановкиСрокаИсполнения`):
- `ОтносительныйСрок` — срок в днях/часах/минутах от даты создания
- `ТочныйСрок` — конкретная дата

### 2.4 Как работает ЗаполнитьПоШаблону

```
ЗаполнитьПоШаблону(ШаблонБизнесПроцесса):
  1. Если шаблон по умолчанию — пропускаем заполнение
  2. Наименование = из шаблона (с предметами если ДобавлятьНаименованиеПредмета)
  3. ВариантСогласования = Шаблон.ВариантСогласования
  4. ПодписыватьЭП = из шаблона (если включены ФО ИспользоватьЭлектронныеПодписи и ИспользоватьВизыСогласования)
  5. Для каждой строки Исполнители шаблона:
     - Проверяем условие применимости (через РаботаСАлгоритмамиПроверки)
     - Если условие выполняется или условий нет — добавляем строку в ТЧ Исполнители БП
     - Устанавливаем ПорядокСогласования, ИдентификаторИсполнителя, сроки
```

## 3. ВизыСогласования — что это и как связано с процессом

### 3.1 Структура Справочника ВизыСогласования

Справочник **ВизыСогласования** — это физические "подписи" согласующих, привязанные к документу (не к бизнес-процессу напрямую). 18 атрибутов:

| Атрибут | Назначение |
|---------|------------|
| Документ | CatalogRef.ДокументыПредприятия — документ, к которому относится виза |
| Исполнитель / РольИсполнителя | Кто согласовал |
| УстановилРезультат | Фактический исполнитель (из СведенияОбУчастникахДействий) |
| РезультатСогласования | EnumRef.РезультатыСогласования |
| Комментарий | Текст комментария согласующего |
| НомерИтерации | Номер итерации согласования |
| ДатаИсполнения / ДатаСоздания | Временные метки |
| Источник | ДействияСогласования / ЗадачаИсполнителя / БизнесПроцесс — откуда пришла виза |
| ИдентификаторУчастника | UUID участника |
| Подписана | Признак подписания ЭП |
| ПомещенаВИсторию / ДатаПомещенияВИсторию | Архивирование визы |
| Удалена | Признак удаления |

### 3.2 Связь виз с процессом согласования

Визы **создаются** через модуль `РаботаСВизамиСогласования.СоздатьВизыПоДействию()`:

1. Срабатывает только при `ФО ИспользоватьВизыСогласования = Истина`
2. Срабатывает только если у Действия (КомплексногоПроцесса/Согласования) реквизит `ФормируетВизы = Истина`
3. Визы привязаны к **Документу** (предмету согласования), а не к самому БП
4. Для каждого участника с функцией "Согласующий" создаётся отдельная виза

**Обновление визы** (`ОбновитьВизуУчастника`) происходит при выполнении задачи согласующим:
- Устанавливает результат (`РезультатСогласования`)
- Фиксирует фактического исполнителя (из регистра СведенияОбУчастникахДействий)
- Обновляет НомерИтерации

### 3.3 API модуля РаботаСВизамиСогласования (29 экспортируемых функций)

Ключевые методы:
- `ПолучитьВизыДокумента` / `ПолучитьАктивныеВизыДокумента` — получить визы
- `ЕстьВизыНаСогласовании` / `ЕстьВизыНеСогласованные` — проверить статус
- `ПоместитьВизыВИсторию` — архивировать при новом запуске согласования
- `ВсеРазногласия` / `ЗамечанияПоВеткам` — получить замечания (режим замечаний)
- `ВерсииФайловИзменились` — контроль изменения файлов

## 4. Результаты согласующих

### 4.1 Перечисление РезультатыСогласования

| Значение | Синоним |
|----------|---------|
| `Согласовано` | Согласовано |
| `СогласованоСЗамечаниями` | Согласовано с замечаниями |
| `НеСогласовано` | Не согласовано |

### 4.2 Как результат хранится

Результат каждого согласующего записывается в:
1. **ТЧ РезультатыСогласования** бизнес-процесса: строка с ЗадачаИсполнителя, НомерИтерации, РезультатСогласования
2. **Справочник ВизыСогласования**: запись для конкретного документа с аналогичными полями

### 4.3 Итоговый результат согласования

Функция `ИтоговыйРезультатСогласования()` вычисляет итоговый результат по приоритету:

```
Приоритет (от большего к меньшему):
1. НеСогласовано — если хотя бы один согласующий дал "Не согласовано"
   → цикл прерывается немедленно
2. СогласованоСЗамечаниями — если никто не отказал, но есть замечания
3. Согласовано — все согласовали без замечаний
```

Алгоритм анализирует только строки **текущей итерации** (`НомерИтерации = НомерИтерации`).

## 5. Завершение процесса — что происходит и какой код обрабатывает

### 5.1 Схема точек маршрута

```
Старт
  ↓
[СтартПередСтартом] — фиксирует ДатаНачала, интеграция с проектами
  ↓
[ПодготовкаОбработка] — инкремент НомерИтерации, сброс Пройден у всех исполнителей
  ↓
[СогласоватьПередСозданиемЗадач] — вызов СоздатьЗадачиСогласования()
  ↓
[СогласоватьПриВыполнении] — при выполнении каждой задачи: ДобавитьЗадачуОтложеннаяОбработкаЗавершенияСогласования()
  ↓
[УсловиеОбходЗавершен] — проверяет ОбходСогласующихЗавершен(): все задачи выполнены?
  ↓ Да                ↓ Нет → создаём следующие задачи (Последовательный/Смешанный вариант)
[ОбработкаРезультатаОбработка] — записывает ИтоговыйРезультатСогласования → РезультатСогласования
  ↓
[СогласованоПроверкаУсловия] — решает: переходить к ознакомлению или нет?
  ↓
[ОзнакомитьсяПередСозданиемЗадач]
  ↓
[ЗавершениеПриЗавершении] — ДатаЗавершения, РаботаСПроектами, ПриЗавершенииПроцесса
```

### 5.2 Детальное описание завершения

**Шаг 1. При выполнении каждой задачи** (`СогласоватьПриВыполнении`):
- Вызывает `ДобавитьЗадачуОтложеннаяОбработкаЗавершенияСогласования()`
- Та в свою очередь обращается в `РаботаСПроцессамиПоДействиямСобытия.ОбработатьДобавлениеЗадачиОтложеннаяОбработкаЗавершенияСогласования()`

**Шаг 2. Отложенная обработка** (`РаботаСПроцессамиПоДействиямСобытия`):
- Проверяет: включён режим замечаний + есть замечания в корне действия?
- Если да → `ОбработкаОчередиЗаданийСервер.ОбработатьДобавлениеЗадачиОтложеннаяОбработкаЗавершенияСогласования()`
- Там при включённой опции `ИспользоватьЗадания` создаётся **служебная задача** + **фоновое задание** через очередь

**Шаг 3. Проверка условия обхода** (`УсловиеОбходЗавершен` → `ОбходСогласующихЗавершен()`):
```bsl
// Запрос: есть ли незавершённые задачи?
ВЫБРАТЬ ПЕРВЫЕ 1 ЗадачаИсполнителя.Ссылка
ИЗ Задача.ЗадачаИсполнителя КАК ЗадачаИсполнителя
ГДЕ ЗадачаИсполнителя.БизнесПроцесс = &Процесс
  И ЗадачаИсполнителя.Выполнена = ЛОЖЬ
  И ЗадачаИсполнителя.ПометкаУдаления = ЛОЖЬ
  И ЗадачаИсполнителя.ИсключенаИзПроцесса = ЛОЖЬ
  И ЗадачаИсполнителя.СостояниеБизнесПроцесса = ЗНАЧЕНИЕ(Перечисление.СостоянияБизнесПроцессов.Активен)
  И ЗадачаИсполнителя.ТекущийИсполнитель <> ЗНАЧЕНИЕ(...ПустаяСсылка)

// Если нет незакрытых → проверяем результат
Если ИтоговыйРезультатСогласования() = НеСогласовано → Завершён (без ознакомления)
Иначе → Завершён, если все строки Исполнители.Пройден = Истина
```

**Шаг 4. При завершении всего процесса** (`ЗавершениеПриЗавершении`):
- `ДатаЗавершения = ТекущаяДатаСеанса()`
- `РаботаСПроектами.ОтметитьОкончаниеВыполненияПроектнойЗадачи(ЭтотОбъект)`
- `РаботаСПроцессамиПоДействиямСобытия.ПриЗавершенииПроцесса(ЭтотОбъект)` → обновляет результат выполнения действия (для КомплексногоПроцесса)

**Шаг 5. ОбработатьЗавершениеЗадачиСогласования** (дополнительная точка):
```bsl
НайденнаяСтрока = Исполнители.Найти(Задача, "ЗадачаИсполнителя");
НайденнаяСтрока.Пройден = Истина;
РаботаСБизнесПроцессами.ЗаписатьПроцесс(ЭтотОбъект, "ПростаяЗапись");
```

### 5.3 Повторное согласование

При `ПовторитьСогласование = Истина` процесс возвращается к точке `ПодготовкаОбработка`:
- `НомерИтерации += 1`
- `ПовторитьСогласование = Ложь`
- Для всех строк Исполнители: `Пройден = Ложь`, `ЗадачаИсполнителя = Неопределено`
- Создаются новые задачи согласования

## 7. Кастомные доработки проекта Тест (тст)

В стандартных процедурах БП обнаружен один кастомный блок:

### СогласованоПроверкаУсловия (L2238) — хардкод роли
```bsl
// Кастомная логика: при несогласовании проверяем, был ли среди согласующих
// "ДД Директор по брэнду" — для него результат "Не согласовано" 
// не переводит к ознакомлению
ДиректорПоБренду = Справочники.РолиИсполнителей.НайтиПоНаименованию("ДД Директор по брэнду", Истина);

// +Кокоев; 23.04.2024; задача 89181
// Дополнительная проверка через регистр ПроцессыДействий + реквизит тст_НеОзнакамливать
// Если НеОзнакамливать = Истина → не переходим к ознакомлению при несогласовании
```

**Значение:** При несогласовании директором по бренду или при настройке `тст_НеОзнакамливать` в действии — шаг ознакомления пропускается.

## 8. Сводка: ответы на вопросы теста

### Параметры настройки при запуске

Настраиваются через **ШаблоныСогласования** или вручную в форме бизнес-процесса:
1. **Исполнители** (ТЧ Исполнители): Сотрудник/Роль + Порядок (ВместеСПредыдущим/ПослеПредыдущего) + Срок (в днях/часах/минутах или точная дата)
2. **Вариант согласования**: Параллельно / Последовательно / Смешанно
3. **Количество итераций**: сколько раз процесс может повториться при несогласовании
4. **Срок процесса / срок обработки результатов**: для автора после завершения согласования
5. **ПодписыватьЭП**: требовать ЭЦП на документе
6. **Условия применимости** согласующих через `АлгоритмыПроверки`

### ВизыСогласования

Визы — отдельный справочник, привязанный к **документу** (не к бизнес-процессу). Хранят: исполнителя, результат, комментарий, дату, номер итерации. Создаются при включённом `ФО ИспользоватьВизыСогласования`. Обновляются при выполнении задачи согласующим.

### Результаты согласующих

Три значения: **Согласовано**, **Согласовано с замечаниями**, **Не согласовано**. Итоговый результат — приоритет: НеСогласовано > СЗамечаниями > Согласовано.

### Завершение процесса

При выполнении задачи согласующим → `СогласоватьПриВыполнении` → отложенная обработка через очередь заданий. Условие завершения обхода проверяется запросом к таблице ЗадачаИсполнителя. Итоговый результат записывается в `ОбработкаРезультатаОбработка`. Финальное завершение через `ЗавершениеПриЗавершении` обновляет действие в комплексном процессе.

### Общие модули

Ключевые: РаботаСБизнесПроцессами, РаботаСПроцессамиПоДействиямСобытия, РаботаСПроцессамиПоДействиям, СтартПроцессовСервер, ОбработкаОчередиЗаданийСервер, РаботаСВизамиСогласования, СрокиИсполненияПроцессов.
