## 1. Природа документа

`ВходящееПисьмо` — это документ электронной почты (Email), **не** управленческий документ предприятия. Он не проводится (нет регистрационных движений по бухгалтерским/накопительным регистрам), не имеет регистрационной карточки ДО. Это аналог записи в почтовом ящике, интегрированном в ДО.

**Модули документа:**
- `Documents/ВходящееПисьмо/Ext/ObjectModule.bsl` — обработчики ПередЗаписью, ПриЗаписи, ПередУдалением
- `Documents/ВходящееПисьмо/Ext/ManagerModule.bsl` — менеджер (права доступа, представление)
- Команды: Ответить, Ответить всем, Переслать
- Формы: ФормаДокумента, ФормаВыбора, ОповещенияОНовыхПисьмах

## 3. Создание и заполнение входящего письма

Письма создаются автоматически при получении почты через функцию `ЗаполнитьВходящееПисьмоИзСтруктурыПочтовогоСообщения` в модуле `ВстроеннаяПочтаСервер`:

```bsl
// Из структуры почтового сообщения заполняется:
ПисьмоОбъект.Важность = Сообщение.Важность;
ПисьмоОбъект.ДатаОтправки = Сообщение.ДатаОтправки;
ПисьмоОбъект.ДатаПолучения = ДатаПолучения;
ПисьмоОбъект.ВнутреннийЗаголовок = Сообщение.Заголовок;
ПисьмоОбъект.ИдентификаторСообщения = Сообщение.ИдентификаторСообщения;
ПисьмоОбъект.Кодировка = Сообщение.Кодировка;
ПисьмоОбъект.ОтправительАдресат = ...; // через АдресатыПочтовыхСообщений
ПисьмоОбъект.Тема = Сообщение.Тема;
// Заполняются: ПолучателиПисьма, ПолучателиКопий, ПолучателиОтвета
// ЕстьВложения = (ЧислоВложений <> 0)
```

**Автоматическое определение папки** (в `ПередЗаписью` через `ПрименитьПредопределенныеПравила`):
- Новые входящие без папки → папка **"Входящие"** для данной учетной записи
- Папка обязательна: при отсутствии `Папки` → `Отказ = Истина`

**Нумерация:** через подписку `OnSetNewNumber` → `ПрефиксацияОбъектовСобытия.УстановитьПрефиксИнформационнойБазы`. Номер включает префикс информационной базы.

## 5. Регистрация входящего письма

**Важно:** Входящее письмо — это Email-документ, не управленческий документ предприятия. Его "регистрация" в смысле ДО происходит через отдельный бизнес-процесс **"Регистрация"** (BusinessProcesses/Регистрация), который может:
- Присвоить документу регистрационный номер в системе ДО
- Создать запись в журнале регистрации
- Связать письмо с ДокументомПредприятия

**Нумерация документа** (технический номер письма):
- Механизм: `OnSetNewNumber` → `ПрефиксацияОбъектовСобытия`
- Формат: [Префикс ИБ][Порядковый номер]
- Пример: `000000123` или `ДО-000000123`

**Кто регистрирует:**
- Технически: система при получении почты (`ВстроеннаяПочтаСервер.ЗаполнитьВходящееПисьмоИзСтруктурыПочтовогоСообщения`)
- По регламенту: пользователь с ролью `РаботаСоВстроеннойЭлектроннойПочтой`
- Роль регистратора ДО назначается при запуске БП "Регистрация"

**БП "Регистрация"** содержит процедуры:
- `ЗаполнитьПоШаблону` — заполнение по шаблону процесса
- `ЗаполнитьПоШаблонуИПредмету` — заполнение с учётом предмета
- `ИзменитьРеквизитыНевыполненныхЗадач` — обновление задач при изменении
- `ОбновитьАктивныйПроцесс` — обновление состояния процесса

## 6. Обработчики событий (ObjectModule)

### 6.1 ПередЗаписью (строки 5–47)

```bsl
Процедура ПередЗаписью(Отказ, РежимЗаписи, РежимПроведения)
    // 1. Пропуск при загрузке данных обмена
    Если ОбменДанными.Загрузка Тогда Возврат; КонецЕсли;
    
    // 2. Определение нового письма
    ДополнительныеСвойства.Вставить("ЭтоНовоеПисьмо", Ссылка.Пустая());
    
    // 3. Для нового письма — определение способа адресации
    Если ДополнительныеСвойства.ЭтоНовоеПисьмо Тогда
        НомерСпособаАдресации = ВстроеннаяПочтаСервер.ПолучитьСпособАдресацииОбъекта(ЭтотОбъект);
    КонецЕсли;
    
    // 4. Для существующего письма — запоминаем предыдущие значения
    //    (Папка, ПометкаУдаления)
    
    // 5. При смене папки — проверка прав на перемещение
    
    // 6. Применение правил (авто-раскладка по папкам)
    ВстроеннаяПочтаСервер.ПрименитьПравила(ЭтотОбъект);
    
    // 7. Контроль обязательности папки
    Если Не ЗначениеЗаполнено(Папка) Тогда
        Отказ = Истина;
        ВызватьИсключение "Не указана папка письма";
    КонецЕсли;
КонецПроцедуры
```

### 6.2 ПриЗаписи (строки 49–107)

```bsl
Процедура ПриЗаписи(Отказ)
    // 1. Пропуск при загрузке данных обмена
    Если ОбменДанными.Загрузка Тогда Возврат; КонецЕсли;
    
    // 2. При смене папки или пометки удаления — обновление

## 9. Жизненный цикл: диаграмма

```
[Сервер почты] 
    ↓ IMAP/POP3
[ВстроеннаяПочтаСервер.ЗаписатьВходящееПисьмо()]
    ↓
[Создание объекта ВходящееПисьмо]
    → Заполнение реквизитов из структуры сообщения
    → Определение папки (Входящие)
    → Определение способа адресации
    ↓
[ПередЗаписью (ObjectModule)]
    → ПрименитьПравила → папка "Входящие"

## Итоговые выводы

1. **ВходящееПисьмо** в ДО КОРП — это **почтовый документ**, интегрированный в систему документооборота. Его жизненный цикл начинается с автоматического получения через почтовый протокол (IMAP/POP3).

2. **Реквизиты** заполняются автоматически из структуры email-сообщения. Единственный обязательный для пользователя — **Папка** (автоматически "Входящие").

3. **Бизнес-процессы**: 10 типов, наиболее типичный для входящих — **Рассмотрение** (явно поддерживает тип `ДокументСсылка.ВходящееПисьмо` в качестве предмета). Также актуальны: Регистрация, Исполнение, Ознакомление.

4. **Регистрация** в смысле ДО — отдельный бизнес-процесс "Регистрация", который инициируется вручную или по правилам. Технический номер документа — через механизм префиксации.

5. **При каждой записи** срабатывает более 30 подписок на события (BeforeWrite ~18, OnWrite ~14, BeforeDelete ~4), обеспечивающих версионирование, права доступа, обмен данными, временны́е метки и интеграции.

6. **Регистры**: напрямую обновляются 2 регистра из ObjectModule (`КоличествоПисемВПапках`, `HTMLПредставленияСодержанияПисем`), через подписки — `ВерсииОбъектов`, `ДанныеБизнесПроцессов`. В почтовом модуле задействовано более 33 регистров сведений.
