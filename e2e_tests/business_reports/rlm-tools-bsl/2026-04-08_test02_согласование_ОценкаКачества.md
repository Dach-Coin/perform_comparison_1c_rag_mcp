## Что сервер дал хорошо

1. **Полная структура БП Согласование** — 30 реквизитов, 6 табличных частей через `parse_object_xml`, с точными типами и синонимами
2. **Параметры запуска** — процедура `СтруктураДанныхДляЗаполнения` дала исчерпывающий список: ВариантСогласования, Исполнители (ТЧ), ПодписыватьЭП, КоличествоИтераций, ОбрабатывающийРезультат, сроки
3. **ВизыСогласования** — полная структура справочника (18 реквизитов), код `ПередЗаписью` с логикой прав доступа, код `ПриЗаписи` с фиксацией версий файлов
4. **Перечисления** — все три: `РезультатыСогласования` {Согласовано, СогласованоСЗамечаниями, НеСогласовано}, `ВариантыМаршрутизацииЗадач` {Последовательно, Параллельно, Смешанно}, `ПорядокВыполненияЗадач` {ВместеСПредыдущим, ПослеПредыдущего}
5. **Алгоритм итогового результата** — `ИтоговыйРезультатСогласования()` с приоритетом: НеСогласовано > СогласованоСЗамечаниями > Согласовано — прямая цитата кода
6. **Цепочка завершения** — полная трассировка: `СогласоватьПриВыполнении` → отложенная обработка → `ОбработатьЗавершениеЗадачиСогласования` (Пройден=Истина) → `ОбходСогласующихЗавершен()` → `ОбработкаРезультатаОбработка` → `ЗавершениеПриЗавершении`
7. **Общие модули** — 12 модулей с API (find_exports для `РаботаСБизнесПроцессами` — 39 экспортов, `СогласованиеВРежимеЗамечанийСервер` — 25 экспортов)
8. **Подписки на события** — 20 подписок для БП Согласование
9. **Кастомизации Тест** — обнаружены: регистр `тст_СогласованиеЗаявокСБ`, флаг `тст_НеОзнакамливать`, хардкод "ДД Директор по брэнду"

## Что сервер НЕ дал

1. **Точка создания ВизыСогласования** — не найдено прямого вызова `Справочники.ВизыСогласования.СоздатьЭлемент()` в основном коде. Вероятно, создание происходит через форму задачи или ДействияСогласования — не прослежено до конца
2. **Маршрутная карта в XML** — визуальная схема маршрута БП не извлечена (XML маршрута не парсился)

**Причины:** ограниченное время агента и сложность трассировки межмодульных связей. Сервер технически способен всё найти при дополнительных вызовах.

## Паттерны поведения агента

- **Глубокая трассировка**: агент прошёл полную цепочку от запуска до завершения (8+ read_procedure последовательно) — это наиболее сложный паттерн, который хорошо работает именно с rlm-tools-bsl
- **Эффективный поиск перечислений**: `find_enum_values` за один вызов (#8) дал все 3 перечисления
- **Целенаправленные read_procedure**: агент точно знал какие процедуры читать (из extract_procedures), не блуждал
- **Единственный retry (#20→21)**: техническая ошибка Python (None в sorted) — не связана с качеством данных, быстро исправлена
- **Нулевой шум**: все 29 полезных вызовов дали релевантные данные — лучший показатель из трёх тестов

## Выявленные проблемы RAG
| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| Нет проблем RAG | rlm-tools-bsl даёт прямой доступ к коду, чанкинг/эмбеддинги не задействованы |
| Python-ошибки в песочнице | Call #20 — TypeError в sorted() из-за None значений. Легко обходится, но занимает лишний вызов |
| Нет быстрого "кто создаёт объект X" | Трассировка "кто вызывает СоздатьЭлемент для ВизыСогласования" потребовала бы grep по всей кодобазе — агент не стал тратить вызовы |

## Вывод

rlm-tools-bsl показал **лучший результат** на задаче анализа бизнес-процесса — самой сложной из трёх тестов. 94% полезных вызовов, 0% шума. Сервер идеально подходит для задач, требующих **трассировки логики**: чтение цепочек процедур, анализ точек маршрута, поиск экспортных функций. Единственное ограничение — глубина трассировки ограничена лимитом вызовов (31 за сессию), но при effort=high этого хватило для ПОЛНОГО ответа на все 5 вопросов. Для сравнения: три RAG-сервера на TEST-02 давали ЧАСТИЧНО или ПОЛНОСТЬЮ с существенным шумом.
