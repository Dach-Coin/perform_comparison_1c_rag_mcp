## 1. Состав подсистемы МЭДО

Подсистема МЭДО входит в состав стандартных подсистем 1С:Документооборот и управляется функциональной опцией `ИспользоватьМЭДО` (константа `Constant.ИспользоватьМЭДО`). Всего в подсистеме **50 объектов** метаданных.

### Документы МЭДО

| Документ | Назначение |
|----------|-----------|
| `ДанныеДокументаМЭДО` | Данные исходящего/входящего документа для обмена по МЭДО |
| `УведомлениеМЭДО` | Уведомления между ведомствами (о регистрации, исполнении и т.д.) |
| `КвитанцияМЭДО` | Квитанция о доставке/обработке сообщения МЭДО |

### Общие модули

| Модуль | Тип | Назначение |
|--------|-----|-----------|

| `МЭДОВызовСервера` | Вызов сервера | Клиент-серверный фасад для UI-вызовов |

## 3. Процесс отправки документа через МЭДО

### 3.1 Автоматический обмен (регламентное задание)

```
ВыполнениеОбменаМЭДО (РегламентноеЗадание)
  → CommonModule.МЭДО.ВыполнитьОбменМЭДО()
      ├── РС.НастройкиОрганизацийМЭДО — получить список настроенных организаций
      ├── Для каждой организации:
      │   ├── ПолучитьВходящиеСообщения(Настройки)
      │   │     ├── Сканировать КаталогПолучения на наличие ZIP-архивов
      │   │     ├── Для каждого ZIP: ОбработатьВходящееЭСД()
      │   │     │     ├── Распаковать ZIP во временный каталог
      │   │     │     ├── Прочитать envelope.ini/.ltr (адрес отправителя)
      │   │     │     ├── Определить тип контента (документ / уведомление / квитанция)
      │   │     │     └── Создать объект в 1С: ДанныеДокументаМЭДО / УведомлениеМЭДО / КвитанцияМЭДО
      │   │     └── Переместить обработанные файлы в /processed или /errors
      │   │
      │   ├── ОтправитьИсходящиеКвитанции(Настройки, ДанныеОтвета)
      │   │     └── Для каждой КвитанцияМЭДО с ГотоваКОтправке=Истина:
      │   │           └── Записать в КаталогОтправки
      │   │
      │   ├── ОтправитьИсходящиеДокументы(Настройки, ДанныеОтвета)
      │   │     └── Для каждого ДанныеДокументаМЭДО с ГотовКОтправке=Истина:
      │   │           └── ОтправитьИсходящийДокумент()
      │   │                 ├── МЭДОПереопределяемый.ДанныеИсходящегоДокументаДляОтправки()
      │   │                 ├── Разбить по версиям МЭДО получателей (пакеты по версиям)
      │   │                 ├── ЗаписатьСодержимоеКонтейнераИсходящегоДокумента()
      │   │                 └── ЗаписатьСообщениеПоИсходящемуДокументу(КаталогОтправки)
      │   │
      │   └── ОтправитьИсходящиеУведомления(Настройки, ДанныеОтвета)
      │
      └── ОчиститьСтарыеЗаписиЖурнала()
```

### 3.2 Ручная отправка через форму документа

**ДанныеДокументаМЭДО.ФормаДокумента.ОтправитьПоМЭДО:**
```
МЭДОВызовСервера.ОтправитьИсходящиеДокументы(Организация, ДанныеОтвета, [Ссылка])
  → МЭДО.ОтправитьИсходящиеДокументы(Настройки, ДанныеОтвета, МассивДокументов)
```

**КвитанцияМЭДО.ФормаДокумента.ОтправитьПоМЭДО:**
```
МЭДОВызовСервера.ОтправитьИсходящиеКвитанции(Организация, ДанныеОтвета, [Ссылка])
```

**УведомлениеМЭДО.ФормаДокумента.ОтправитьПоМЭДО:**
```
МЭДОВызовСервера.ОтправитьИсходящиеУведомления(Организация, ДанныеОтвета, [Ссылка])
```

### 3.3 Транспортный протокол

МЭДО использует **файловый обмен** через разделяемые каталоги или FTP:
- **Способ 1:** Диск/локальная сеть (`СпособыОбменаМЭДО.ДискСеть`) — настройки `КаталогОтправки` / `КаталогПолучения`
- **Способ 2:** FTP (`СпособыОбменаМЭДО.FTP`) — настройки `КаталогОтправкиFTP` / `КаталогПолученияFTP`

Формат сообщений — **ZIP-архив**, внутри:
- `envelope.ini` или `envelope.ltr` — конверт с адресом отправителя (секция `[АДРЕСАТЫ]`)
- XML-файл сообщения в формате IEDMS (XDTO-сериализация через пакеты `IEDMSMessage*` / `IEDMSContainer*`)

**Поддерживаемые версии МЭДО:** 2.5, 2.7, 2.7.1 (перечисление `ВерсииФорматаМЭДО`). Для 2.7.1 используется пространство имён `urn:IEDMS:MESSAGE`, для 2.5/2.7 — `http://www.infpres.com/IEDMS`.

### 3.4 Синхронизация при записи документа

Подписка на событие `EventSubscription.СинхронизироватьДанныеДокументаМЭДОПриЗаписи` вызывает `МЭДО.СинхронизироватьДанныеДокументаМЭДОПриЗаписи()` — синхронизирует пометку удаления между документом-владельцем и связанным `ДанныеДокументаМЭДО`.

## 4. HTTP-сервисы и веб-сервисы для МЭДО

**HTTP-сервисов для МЭДО нет.** В конфигурации 9 HTTP-сервисов (MobileApp, ПередачаДанных, тст_ROSE, тст_STORM и др.) — ни один не относится к МЭДО.

**Веб-сервисов для МЭДО нет.** В конфигурации 19 веб-сервисов (DM*, Exchange*, Files, InterfaceVersion и др.) — ни один не относится к МЭДО.

МЭДО **не использует SOAP/REST**. Интеграция реализована через файловый обмен (каталоги или FTP). XDTO-пакеты (`IEDMSContainer*`, `IEDMSMessage*`) используются внутри кода для сериализации XML-сообщений, но не публикуются как веб-сервисы.

## 5. Регламентные задания МЭДО

### ВыполнениеОбменаМЭДО

| Параметр | Значение |
|----------|----------|
| Имя | `ВыполнениеОбменаМЭДО` |
| Обработчик | `CommonModule.МЭДО.ВыполнитьОбменМЭДО` |
| Включено по умолчанию | **Нет** (`use=False`) |
| Назначение | Полный цикл: получение входящих + отправка квитанций + отправка документов + отправка уведомлений |

> **Важно:** Задание отключено (`use=False`). Обмен либо запускается вручную через обработку "Текущие дела МЭДО", либо должен быть включён администратором.

### Настройки поведения (константы)

| Константа | Назначение |
|-----------|-----------|
| `АвтоматическиОтправлятьКвитанцииМЭДО` | Автоотправка квитанций |
| `ВариантАвтосозданияУведомленийМЭДО` | Вариант автосоздания уведомлений |
| `РазмерПорцииОбработкиМЭДО` | Количество архивов за один запуск |
| `ВремяХраненияЖурналаСобытийМЭДО` | Срок хранения записей журнала |

## 6. Перечисления и состояния

### Типы уведомлений (ТипыУведомленийМЭДО)
- О регистрации
- Об отказе в регистрации
- О постановке на контроль
- О принятии к исполнению
- О подготовке доклада
- О направлении доклада
- О ходе исполнения
- Об опубликовании

### Состояния документа (СостоянияДокументовМЭДО)
16 состояний: от "Исходящий документ ещё не отправлен" до "Получено уведомление", охватывая весь жизненный цикл документа в МЭДО.

## 7. Рабочее место пользователя

Обработка `ТекущиеДелаМЭДО` (включена в функциональную опцию `ИспользоватьМЭДО`) предоставляет:
- Просмотр входящих документов, уведомлений, квитанций
- Ручной запуск получения и отправки по каждому типу объектов
- Отображение состояний документов МЭДО

## Итоговая схема подсистемы

```
Внешняя система МЭДО
        │
     ZIP-файлы (IEDMS XML)
        │
  ┌─────▼──────────────────────────────────────────┐
  │  КаталогПолучения  КаталогОтправки             │
  │      ↑                   ↓                     │
  │  МЭДО.ПолучитьВходящиеСообщения()              │
  │  МЭДО.ОтправитьИсходящийДокумент()             │
  │  МЭДО.ОтправитьИсходящееУведомление()          │
  │  МЭДО.ОтправитьИсходящуюКвитанцию()            │
  └─────────────────────────────────────────────────┘
        │
  ┌─────▼──────────────────────────────────────────┐
  │  Документы 1С:ДО                               │
  │   ДанныеДокументаМЭДО  ←→  Документ ДО         │
  │   УведомлениеМЭДО                              │
  │   КвитанцияМЭДО                               │
  └─────────────────────────────────────────────────┘
        │
  ┌─────▼──────────────────────────────────────────┐
  │  Инфраструктура                                │
  │   РС.НастройкиОрганизацийМЭДО (каталоги, адреса│
  │   РС.НастройкиКонтрагентовМЭДО (версии МЭДО)  │
  │   РС.СостоянияДокументовМЭДО (статусы)        │
  │   РС.ЖурналСобытийМЭДО (ошибки)              │
  └─────────────────────────────────────────────────┘
```
