## 2. Создание входящего письма — процесс получения почты

Входящие письма создаются **автоматически** при получении почты с внешнего сервера. Ключевой метод — `ВстроеннаяПочтаСервер.ЗаписатьВходящееПисьмо()`.

### Алгоритм создания (метод ЗаписатьВходящееПисьмо)

1. **Проверка дублей** — по `ИдентификаторСообщения` + учетная запись. Если письмо уже было принято — возврат без создания.
2. **Начало транзакции** (`НачатьТранзакцию`)
3. **Создание документа**: `Документы.ВходящееПисьмо.СоздатьДокумент()`
4. **Заполнение реквизитов** через `ЗаполнитьВходящееПисьмоИзСтруктурыПочтовогоСообщения`:
   - `Дата` = текущая дата сеанса (или дата получения, если она старше суток)
   - `ДатаОтправки`, `ДатаПолучения` — из IMAP-сообщения
   - `Важность`, `Тема`, `Размер`, `Кодировка` — из IMAP
   - `ВнутреннийЗаголовок` — заголовок с удалёнными XML-символами
   - `ОтправительАдресат` — через `ВстроеннаяПочтаСерверПовтИсп.ПолучитьПочтовогоАдресата`
   - `ТекстПисьма*` — текст письма в разных форматах
   - `ПолучателиПисьма`, `ПолучателиКопий`, `ПолучателиОтвета`, `АдресаУведомленияОПрочтении` — из адресатов IMAP
   - `ЕстьВложения` — подсчёт вложений
   - `ВидМаршрутизации` = Внешняя
5. **Привязка к проекту** — из X-1C-Project-ID заголовка письма
6. **Установка основания** — по заголовкам In-Reply-To и References (связь с исходящим письмом)
7. **Запись документа** (`Записать`)
8. **Запись текста** в РС.ТекстыПисем
9. **Регистрация идентификатора** в РС.ИдентификаторыПолученныхПисем (защита от повторного приема)
10. **Регистрация бизнес-события** `БизнесСобытия.ПолучениеВходящегоПисьма`
11. **Фиксация транзакции**
12. **Применение пользовательских правил** (автоматическая обработка: перемещение в папку, пометка)
13. **Запись вложений** в файловый каталог

### Регламентные задания для получения почты

| Задание | Активно | Назначение |
|---------|---------|------------|
| ПриемОтправкаПочты1-10 | Нет | Прием/отправка для 10 учетных записей одновременно |
| ПриемПисемПоВнутреннейМаршрутизацииБыстрый | Да | Быстрый прием внутренней почты |
| ПриемПисемПоВнутреннейМаршрутизацииДолгий | Да | Долгий цикл внутренней маршрутизации |
| ОтправкаПисем | Да | Отправка исходящих |
| ОтправкаПисемПоВнутреннейМаршрутизации | Да | Отправка по внутренним правилам |
| ПроверкаРаботыПриемкиПочты | Да | Мониторинг работы приемки |

> **Примечание:** задания ПриемОтправкаПочты1-10 не активны (use=False). Активен только механизм внутренней маршрутизации. Реальный приём внешней почты, вероятно, настраивается отдельно.

## 3. Нумерация входящих писем

Входящие письма используют **стандартный механизм автонумерации** с префиксом информационной базы:

- Подписка `OnSetNewNumber` → обработчик `ПрефиксацияОбъектовСобытия.УстановитьПрефиксИнформационнойБазы`
- Нумераторы управляются через справочник `Нумераторы`
- Номер формируется как: `[префикс ИБ]-[порядковый номер]`

**Кто регистрирует:** регистрация (присвоение номера) происходит автоматически при записи документа — система нумерации срабатывает без ручного участия. Специального "сотрудника-регистратора" для входящих писем в коде не предусмотрено — письма приходят и регистрируются автоматически при получении с почтового сервера.

## 4. Бизнес-процессы по входящему письму

Входящее письмо может быть **предметом** следующих бизнес-процессов:

| Бизнес-процесс | Синоним | Кол-во реквизитов |
|----------------|---------|-------------------|
| Рассмотрение | Рассмотрение | 59 |
| Исполнение | Исполнение | 30 |
| Согласование | Согласование | 31 |

**Подтверждение связи:** реквизит `Предмет` в бизнес-процессах Рассмотрение и Исполнение включает тип `DocumentRef.ВходящееПисьмо`.

### Как запустить бизнес-процесс

Из формы документа «Входящее письмо» через кнопку/команду открывается `ОбщаяФорма.ПроцессыИЗадачи` с передачей параметра `Предмет = Объект.Ссылка`. На этой форме пользователь выбирает тип бизнес-процесса и создаёт его.

**Условие:** функциональная опция `ИспользоватьБизнесПроцессыИЗадачи` должна быть включена.

### Характеристики бизнес-процессов

**Рассмотрение** (59 реквизитов) — наиболее сложный процесс:
- Автор (сотрудник или пользователь)
- Важность (ВариантыВажностиОбъектов)
- ВариантРассмотрения, ВариантИсполнения
- ВариантУстановкиСрокаИсполнения (несколько)
- ВариантОбработкиРезолюции
- Предмет (включая DocumentRef.ВходящееПисьмо)

**Исполнение** (30 реквизитов):
- Автор, Важность
- ВариантИсполнения
- Предмет (включая DocumentRef.ВходящееПисьмо)
- ГлавнаяЗадача, ДатаНачала, ДатаЗавершения

**Согласование** (31 реквизит):
- Автор, Важность
- ВариантСогласования
- ГлавнаяЗадача, ДатаНачала, ДатаЗавершения
- КоличествоИтераций

## 5. Обработчики событий при записи

### ПередЗаписью (ObjectModule, строки 5-47)

```
Процедура ПередЗаписью(Отказ, РежимЗаписи, РежимПроведения)
```

**Что происходит:**
1. Пропуск при загрузке данных обмена (`ОбменДанными.Загрузка`)
2. Определение нового письма (`ЭтоНовоеПисьмо = Ссылка.Пустая()`)
3. Для нового письма: определение `НомерСпособаАдресации` через `ВстроеннаяПочтаСервер.ПолучитьСпособАдресацииОбъекта`
4. Для существующего: чтение предыдущих значений `ПометкаУдаления` и `Папка`
5. При смене пометки удаления: `РаботаСФайламиВызовСервера.ПометитьНаУдалениеПрисоединенныеФайлы`
6. При смене папки (для непривилегированных пользователей): проверка прав удаления из папки и добавления в папку
7. **Применение правил почты**: `ВстроеннаяПочтаСервер.ПрименитьПравила(ЭтотОбъект)` — автоматическая фильтрация
8. **Валидация**: если не заполнена `Папка` — отказ с исключением "Не указана папка письма"

### ПриЗаписи (ObjectModule, строки 49-107)

```
Процедура ПриЗаписи(Отказ)
```

**Что происходит:**
1. Пропуск при загрузке данных обмена
2. При смене папки или пометки удаления: **обновление РС.КоличествоПисемВПапках** (очистка по предыдущей и текущей папке)
3. При смене пометки удаления: **запись в протокол** `ПротоколированиеРаботыСотрудников.ЗаписатьПометкуУдаления`
4. При активном автозаполнении рабочей группы предмета: поиск контактов-сотрудников из адресатов письма через РС.СведенияОбАдресатах и добавление их в рабочую группу предмета

### Подписки на события (87 штук)

Полный перечень по категориям:

**BeforeWrite (33 подписки):**
- `ОбменДаннымиСобытия` (4): включение плана обмена, регистрация изменений, фильтры миграции, проверка изменений
- `КОДСобытия` (3): обработка объектов для КОД (Корпоративный Обмен Данными)
- `ДокументооборотПраваДоступа`: проверка прав перед записью документа
- `ВерсионированиеОбъектовСобытия`: запись версии объекта
- `БизнесПроцессыИЗадачиСервер`: обработка изменения предмета
- `НастройкаПорядкаЭлементов`: заполнение реквизита упорядочивания
- `РаботаСФайлами`: обработка присоединённых файлов
- `РаботаСРабочимиГруппами`: обработка рабочих групп
- `МиграцияДанных/СводныеПриложения`: интеграционные механизмы
- `СПАРКРиски`: обработчик СПАРК
- `ИнтеграцияЭДО`, `МЭДО`: электронный документооборот
- `ЗащитаПерсональныхДанных`: обработка персональных данных
- `ПрисоединенныеФайлы`: пометка удаления файлов

**OnWrite (20+ подписок):**
- `РаботаСБизнесПроцессамиВызовСервера`: обновление БП при записи
- `БизнесСобытияСобытия`: регистрация бизнес-событий
- `ДокументооборотПраваДоступа`: обновление прав доступа
- `ДействияСобытия`: выполнение действий при записи
- `ОтметкиВремениСобытия`: обновление отметок времени
- `КОДСобытия` (2): обработка объектов и документов
- `МЭДО`: синхронизация данных МЭДО
- `НапоминанияПользователя`: проверка дат для напоминаний
- `РаботаСРабочимиГруппами`: обновление рабочих групп
- `ПользователиСлужебный`: обновление внешних пользователей
- `ЭлектронныеДокументы`: запись машиночитаемых доверенностей

**BeforeDelete (7 подписок):**
- `РаботаСФайлами`: удаление присоединённых файлов
- `СтандартныеПодсистемы`: запрет удаления предопределённых, обновление ИБ
- `ОбменДанными` (3): очистка ссылок, отключение плана обмена

## 8. Итоговая схема жизненного цикла

```
[Почтовый сервер IMAP]
       ↓
[РегЗадание: ПриемОтправкаПочты / ПриемПисемПоВнутреннейМаршрутизации]
       ↓
[ВстроеннаяПочтаСервер.ЗаписатьВходящееПисьмо()]
  → Проверка дубля по ИдентификаторСообщения
  → Создание Документы.ВходящееПисьмо.СоздатьДокумент()
  → Заполнение реквизитов из IMAP (ЗаполнитьВходящееПисьмо...)
  → Привязка к проекту (X-1C-Project-ID)
  → Поиск основания (In-Reply-To / References)
  → Документ.Записать()
  → РС.ТекстыПисем (текст письма)
  → РС.ИдентификаторыПолученныхПисем (защита от дублей)
  → БизнесСобытия.ПолучениеВходящегоПисьма
  → Применение пользовательских правил
  → Файлы вложений
       ↓
[Документ ВходящееПисьмо в базе]
       ↓ (пользователь работает с письмом)
  ├── [Открытие] → ПротоколРаботыСотрудников.ЗаписатьОткрытие
  ├── [Смена папки/пометка] → ПередЗаписью: проверка прав, применение правил
  │                         → ПриЗаписи: РС.КоличествоПисемВПапках
  ├── [Запуск БП] → ОбщаяФорма.ПроцессыИЗадачи
```
