## Что сервер дал хорошо

1. **Полная структура справочника** — `parse_object_xml` + `find_attributes`: 9 реквизитов заголовка с типами, 2 ТЧ (КонтактнаяИнформация 13 колонок, ДополнительныеРеквизиты 3 колонки). Включая стандартный реквизит Владелец → ФизическиеЛица.

2. **Связи со справочниками** — все три связи раскрыты с кодом:
   - ФизическиеЛица: через Владелец (1:N), регистр ОсновныеСотрудники, функция `ПодобратьИУстановитьОсновногоСотрудника`
   - Должности: прямая ссылка, обнаружен кастомный тст_ТиповаяПечатнаяФорма
   - СтруктураПредприятия: двунаправленная — Подразделение + Руководитель, функция `БлижайшийРуководитель` с обходом иерархии

3. **Механизм замещения — полностью раскрыт**:
   - Справочник `ЗамещающиеИПомощники` (9 реквизитов + ТЧ ВопросыЗамещения)
   - Перечисление `ВидыЗамещения`: Замещающие / Помощники
   - Автовычисление `Действует` в ПередЗаписью по датам
   - При записи → обновление ИсполнителиРолейИДелегаты + пересчёт адресации задач
   - Документ `Отсутствие` как основание
   - API: `АктуальныеЗамещения`, `АктуальныеЗамещенияСотрудников`, `ОбновитьДанныеЗадачПоЗамещению`

4. **11 регистров** (10 сведений + 1 накопительный):
   - ОсновныеСотрудники, СотрудникиПользователей, ИсполнителиРолейИДелегаты, ПолномочияСотрудников, ПротоколРаботыСотрудников, СотрудникиВКонтейнерах, ДанныеSAPСотрудники
   - 3 устаревших: ДоступноеВремяСотрудников, ЗанятостьСотрудников, НастройкиРабочегоКалендаряСотрудника
   - Накопительный: РабочееВремяСотрудников (4 ресурса, пишут ЕжедневныйОтчет/ЕженедельныйОтчет)

5. **116 экспортных функций** модуля Сотрудники — найдены через `find_exports`.

6. **Mermaid-диаграмма связей** — агент самостоятельно построил ER-диаграмму в бизнес-отчёте.

7. **Код ключевых функций**: `ОбработкаЗаполнения`, `ПередЗаписью`, `ПриЗаписи`, `ФизЛицоСотрудника`, `ЭтоПолноправныйСотрудник`, `БлижайшийРуководитель`, `АктуальныеЗамещения`.

## Что сервер НЕ дал

1. **Ничего существенного не пропущено** — все 5 подвопросов теста раскрыты полностью с кодом и данными.

2. **Устаревшие регистры** — обнаружены и правильно помечены как устаревшие, но без деталей их текущего использования.

## Паттерны поведения агента

- **Ложный старт**: агент запустил первую сессию с запросом "система нумерации регистрации документов" вместо "Справочник Сотрудники". Провёл полный анализ нумерации (12 вызовов, ~44K символов) и только потом начал правильный анализ. Это потратило ~80K токенов впустую.
- **Безошибочный второй прогон**: после исправления — 28 вызовов, 100% полезных, 0 retry. Лучший показатель эффективности среди трёх тестов.
- **Систематический подход**: объект → реквизиты → связи → замещение → регистры → функции. Каждый аспект закрыт группой из 2-4 вызовов.
- **Хороший батчинг**: `parse_object_xml` нескольких объектов за один вызов, grep + extract + read в одном коде.
- **Инициативность**: нашёл документ Отсутствие как основание замещения (не был в вопросе), ДанныеSAPСотрудники (кэш SAP-данных), Mermaid-диаграмму.

## Вывод

rlm-tools-bsl показал **идеальный результат** по содержанию: 100% полезных вызовов, все 5 подвопросов раскрыты полностью, включая глубокий анализ механизма замещения (6 объектов + 3 уровня вложенности) и 11 регистров. Единственная проблема — ложный старт с неверным запросом, потративший ~44K символов. Это проблема агента (неверная интерпретация промпта), а не сервера.
