## Что сервер дал хорошо

1. **Полный список ролей с правами** — find_roles вернул исчерпывающий перечень для обоих объектов (Document.Задача и Task.ЗадачаИсполнителя) с точными правами (Read, Update, Insert и т.д.)
2. **Тексты RLS-шаблонов** — из Rights.xml извлечены полные SQL-подобные тексты шаблонов `#ПоДескрипторуОбъекта` и `#ЧтениеПроцесса`, включая JOIN-ы по регистрам дескрипторов и участников процессов
3. **Механизм замещений** — обнаружены области делегирования в RLS: ЗадачиПостановкаПоручений, Задачи, ВсеОбласти через Справочник.ЗамещающиеИПомощники
4. **Код ключевых функций** — прочитаны тела ПолучитьРабочуюГруппуДокумента, ПроверитьПраваПередЗаписьюРабочейГруппы, ЗаполнитьДескрипторыОбъектаПоРабочейГруппе, ПраваСотрудникаПоОбъекту — полная цепочка от рабочей группы до проверки прав
5. **Структура регистра РабочиеГруппы** — измерения (Объект, Участник), ресурсы (Изменение, Источник) с типами
6. **Подписки на события** — 15 подписок для Document.Задача, включая пересчёт дескрипторов при записи
7. **Константа-выключатель** — найдена ДокументооборотИспользоватьОграничениеПравДоступа с точным кодом проверки

## Что сервер НЕ дал

1. **Полный состав типов измерения Участник** — в регистре РабочиеГруппы не раскрыт полный список допустимых типов для измерения Участник (частичная информация)
2. **Роль РаботаСЗадачамиСотрудниковПодразделения** — функциональное назначение не выяснено: 0 вызовов из кода, в RLS не участвует. Возможно, используется только для назначения пользователям в Конфигураторе

## Паттерны поведения агента

- **Стратегия "от общего к частному"**: начал с find_roles и find_exports, затем углубился в Rights.xml и тела процедур — эффективная воронка
- **Систематическое покрытие обоих объектов**: агент не забыл, что "задача" — это два разных объекта (Document.Задача и Task.ЗадачаИсполнителя), и исследовал оба
- **Один шумный вызов** (#25 parse_object_xml с ошибкой пути) — быстро обошёл через find_attributes
- **Батчинг**: несколько вызовов объединяли 2-3 операции в одном rlm_execute (например, #15 — find_module для трёх модулей сразу)
- **Глубина анализа**: прочитал не только API модулей, но и сами тела RLS-запросов из XML — это дало реальные SQL-условия, а не абстракции

## Выявленные проблемы RAG

| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| parse_object_xml ненадёжен | Ошибка пути при попытке разобрать XML справочника РабочиеГруппы (#25) |
| Нет хелпера для RLS-анализа | Агенту пришлось вручную читать Rights.xml — нет специализированной функции для извлечения RLS-шаблонов |

## Вывод

rlm-tools-bsl отлично справляется с анализом прав доступа: find_roles даёт полный перечень, read_file позволяет извлечь RLS-шаблоны из XML, а find_exports + read_procedure раскрывают алгоритмы проверки прав. Сервер подходит для любых вопросов о ролях, RLS, рабочих группах и механизмах доступа. Единственный нюанс — отсутствие специализированного хелпера для RLS вынуждает вручную читать Rights.xml.
