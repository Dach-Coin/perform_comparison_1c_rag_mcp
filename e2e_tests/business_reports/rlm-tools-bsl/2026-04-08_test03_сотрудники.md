**Дата анализа:** 2026-04-08

## 1. Общие сведения о справочнике

| Параметр              | Значение                                                                   |
|-----------------------|----------------------------------------------------------------------------|
| Имя объекта           | `Сотрудники`                                                               |
| Синоним               | Сотрудники                                                                 |
| Комментарий           | "Содержит сотрудников на определенных должностях в структурных единицах"   |
| Иерархия              | Нет (`Hierarchical = false`)                                               |
| Подчинён              | `Catalog.ФизическиеЛица` (стандартный атрибут `Владелец`)                  |
| Длина наименования    | 150 символов                                                               |
| Код                   | Отсутствует (`CodeLength = 0`)                                             |
| Предопределённые      | Нет                                                                        |
| Команды               | СотрудникиПодразделения, СотрудникиДолжности, ОтправитьСотрудникам        |

**Ключевой факт:** Один сотрудник = одно физическое лицо в одной должности в одном подразделении. У одного физлица может быть несколько записей в справочнике Сотрудники (работа в разных подразделениях/должностях). Среди них один назначается **основным** через регистр `ОсновныеСотрудники`.

- `Ложь`, если текущая дата > `КонецДня(ДатаОкончанияДействия)`

## 4. Связи с другими справочниками

### 4.1 Справочник ФизическиеЛица (ключевая связь)

Сотрудники подчинены ФизическимЛицам через стандартный атрибут `Владелец`. Архитектурный смысл:
- **ФизическоеЛицо** — человек (ФИО, биометрика, документы)
- **Сотрудник** — роль человека в организации (должность + подразделение + период)

Реквизиты ФизическихЛиц:

| Реквизит           | Тип                                       |
|--------------------|-------------------------------------------|
| `Наименование`     | `String` (ФИО)                            |
| `Пол`              | `EnumRef.ПолФизическогоЛица`             |
| `ДатаРождения`     | `DateTime`                                |
| `ИНН`              | `String`                                  |
| `СтраховойНомерПФР`| `String` (СНИЛС)                         |
| `ГруппаДоступа`    | `CatalogRef.ГруппыДоступаФизическихЛиц`  |
| `ФайлФотографии`   | `ValueStorage`                            |
| `Комментарий`      | `String`                                  |

Наименование сотрудника автоматически синхронизируется с ФИО физлица: `Наименование = Строка(Владелец)`.

### 4.2 Справочник Должности

| Реквизит                    | Тип                                                    |
|-----------------------------|--------------------------------------------------------|
| `Наименование`              | `String`                                               |
| `тст_ТиповаяПечатнаяФорма`  | `CatalogRef.тст_ТиповыеФормыПечатныхДокументов`       |

Простой справочник. Один кастомный реквизит Тест — привязка типовой печатной формы к должности.

### 4.3 Справочник СтруктураПредприятия (подразделения)

| Параметр    | Значение                                  |
|-------------|-------------------------------------------|
| Иерархия    | `HierarchyOfItems` (иерархия элементов)   |
| Код         | 9 символов, автонумерация                 |

Реквизиты:

| Реквизит          | Тип                                                         |
|-------------------|-------------------------------------------------------------|
| `ВидПодразделения`| `CatalogRef.ВидыПодразделений`                             |
| `ГрафикРаботы`    | `CatalogRef.ГрафикиРаботы`                                 |
| `Руководитель`    | `CatalogRef.Сотрудники \| CatalogRef.Пользователи`         |
| `Ранг`            | `Number`                                                    |
| `УказанОсобыйРанг`| `Boolean`                                                   |
| `Комментарий`     | `String`                                                    |

**Важно:** реквизит `Руководитель` → `CatalogRef.Сотрудники` создаёт обратную связь: подразделение знает своего руководителя-сотрудника.

Табличная часть `ДополнительныеРеквизиты` — стандартная (Свойство / Значение / ТекстоваяСтрока).

## 5. Механизм замещения сотрудников

### 5.1 Архитектура замещения

Замещение реализовано через связку трёх объектов:

```
Справочник ЗамещающиеИПомощники
    Сотрудник (кого замещают)  →  CatalogRef.Сотрудники
    Замещающий (кто замещает)  →  CatalogRef.Сотрудники
    ВидЗамещения               →  EnumRef.ВидыЗамещения
    ДатаНачала / ДатаОкончания →  DateTime
    Действует                  →  Boolean (вычисляемый)
    Основание                  →  DocumentRef.Отсутствие
    Создал                     →  CatalogRef.Сотрудники
    Комментарий                →  String
    ТЧ ВопросыЗамещения:
        Область                →  CatalogRef.ОбластиЗамещения
        ЗначениеОтбора         →  составной
```

### 5.2 Виды замещения

Перечисление `ВидыЗамещения` содержит два значения:
- **Замещающие** — полноценное замещение (выполнение задач отсутствующего)
- **Помощники** — расширенный доступ (помощник руководителя и т.п.)

### 5.3 Области замещения

Справочник `ОбластиЗамещения` определяет области, в которых действует замещение (задачи, документы, конкретные виды процессов). Реквизит `Порядок` — для сортировки областей.

### 5.4 Основание — Документ Отсутствие

Замещение привязывается к документу `Отсутствие`:

| Реквизит              | Тип                                                     |
|-----------------------|---------------------------------------------------------|
| `Сотрудник` (Кто)     | `CatalogRef.Сотрудники \| CatalogRef.Пользователи`     |
| `ВидОтсутствия`       | `CatalogRef.ВидыОтсутствий`                            |
| `ДатаНачала`          | `DateTime`                                              |
| `ДатаОкончания`       | `DateTime`                                              |
| `БудуРазбиратьЗадачи` | `Boolean` (флаг "Буду на связи")                       |
| `ВесьДень`            | `Boolean`                                               |
| `Комментарий`         | `String`                                                |
| `Автор`               | `CatalogRef.Сотрудники \| CatalogRef.Пользователи`     |

### 5.5 Выборка актуальных замещений

Метод `АктуальныеЗамещенияСотрудников(СотрудникиМассив, ОбластиЗамещения)` из менеджера справочника выполняет:

```sql
ВЫБРАТЬ РАЗЛИЧНЫЕ
    ЗамещающиеИПомощники.Ссылка КАК Замещение,
    ЗамещающиеИПомощники.ВидЗамещения,
    ЗамещающиеИПомощники.Сотрудник,
    ЗамещающиеИПомощники.Замещающий
ИЗ
    Справочник.ЗамещающиеИПомощники
    ВНУТРЕННЕЕ СОЕДИНЕНИЕ Справочник.ЗамещающиеИПомощники.ВопросыЗамещения
    ПО Ссылка = ВопросыЗамещенияТЧ.Ссылка
ГДЕ
    Сотрудник В (&Сотрудники)
    И Действует
    И ВопросыЗамещенияТЧ.Область В (&ОбластиЗамещения)
УПОРЯДОЧИТЬ ПО Замещающий
```

### 5.6 Связь с делегированием прав

Регистр `ИсполнителиРолейИДелегаты` хранит делегатов задач:

| Измерение               | Тип                                                                    |
|-------------------------|------------------------------------------------------------------------|
| `ИсполнительДелегат`    | `CatalogRef.Сотрудники \| CatalogRef.Пользователи`                    |
| `РольСотрудник`         | `CatalogRef.Сотрудники \| CatalogRef.ПолныеРоли \| CatalogRef.Пользователи` |
| `НастройкаДелегирования`| `CatalogRef.ЗамещающиеИПомощники`                                     |
| `ИмяОбластиДелегирования`| `String`                                                              |

При каждой записи сотрудника вызывается `ОбновитьЗаписиПоСотруднику()`, который синхронизирует этот регистр.

## 8. Доработки Тест

В справочнике `Сотрудники` **нет кастомных доработок** с префиксом `тст_` (0 процедур, 0 атрибутов, 0 регионов).

Единственная кастомная доработка в связанных объектах — реквизит `тст_ТиповаяПечатнаяФорма` у справочника `Должности` (привязка типовой печатной формы к должности).

## 9. Диаграмма связей

```
ФизическиеЛица
│  ФИО (Наименование), Пол, ДатаРождения, ИНН, СНИЛС, Фото
│
└── Сотрудники [подчинён ФизЛицу как владельцу]
        Должность          →  Должности
        Подразделение      →  СтруктураПредприятия
        ГрафикРаботы       →  ГрафикиРаботы
        Помещение          →  ТерриторииИПомещения
        Действует (auto)
        ДатаНачала/Окончания

        ↓ при записи
        ОсновныеСотрудники [ФизЛицо → осн.Сотрудник]
        ИсполнителиРолейИДелегаты [делегирование]

СтруктураПредприятия (иерархический)
    Руководитель → Сотрудники  (обратная связь)

ЗамещающиеИПомощники
    Сотрудник     →  Сотрудники
    Замещающий    →  Сотрудники
    ВидЗамещения  →  ВидыЗамещения {Замещающие, Помощники}
    Основание     →  Документ.Отсутствие
    ТЧ ВопросыЗамещения → ОбластиЗамещения

Регистры накопления:
    РабочееВремяСотрудников [Сотрудник, Проект, ВидРабот → длительности]

Регистры сведений (18+):
    ОсновныеСотрудники, СотрудникиПользователей
    ФактическиеТрудозатраты, ДоступноеВремяСотрудников, ЗанятостьСотрудников
    ПраваПоДескрипторам (2), СоставСубъектовПравДоступа
    ПротоколРаботыСотрудников, МоиДокументы
    СотрудникиВКонтейнерах, ДанныеSAPСотрудники, ...
```

## Итог

Справочник `Сотрудники` в ДО КОРП 3.0 является **подчинённым** справочнику `ФизическиеЛица` и представляет собой "трудовую роль" человека: конкретную должность в конкретном подразделении на определённый период. Один человек может иметь несколько записей сотрудника, основная определяется через регистр `ОсновныеСотрудники`.

Механизм замещения полностью реализован через справочник `ЗамещающиеИПомощники` с видами "Замещающие" и "Помощники", привязан к документу `Отсутствие` и разграничен по областям через `ОбластиЗамещения`. Права делегируются через регистр `ИсполнителиРолейИДелегаты`.

Данные сотрудников хранятся в 18+ регистрах: рабочее время (накопление), трудозатраты, занятость, права доступа, протокол работы, интеграция с SAP HR.

Кастомных доработок Тест непосредственно в справочнике Сотрудники нет.
