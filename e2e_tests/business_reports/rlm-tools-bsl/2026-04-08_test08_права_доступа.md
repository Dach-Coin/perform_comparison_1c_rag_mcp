# Система прав доступа к задачам в 1С:Документооборот КОРП 3.0

**Дата:** 2026-04-08  
**Конфигурация:** ДокументооборотКОРП v3.0.14.31 (проект "Тест ДО3")  
**Источник:** анализ кода через rlm-tools-bsl

---

## 1. Объекты метаданных — "Задача"

В конфигурации существуют два разных объекта:

| Объект | Тип | Назначение |
|--------|-----|-----------|
| `Document.Задача` | Документ | Задача (поручение) в системе документооборота |
| `Task.ЗадачаИсполнителя` | Задача (механизм бизнес-процессов) | Задача в рамках бизнес-процессов (согласование, ознакомление и пр.) |

Это принципиально разные объекты: Document.Задача — ручные поручения, Task.ЗадачаИсполнителя — задачи из бизнес-процессов.

---

## 2. Роли, определяющие доступ к задачам

### 2.1 Роли для Document.Задача

| Роль | Права | Ограничения RLS |
|------|-------|----------------|
| `РаботаСЗадачами` | Полный CRUD + история данных | Да — `#ПоДескрипторуОбъекта` (через рабочую группу) |
| `КонтрольЗадачИБизнесПроцессов` | Полный CRUD + история данных | **Нет** — неограниченный доступ |
| `ИзменениеВыполнениеЗадач` | Read, Update, View, Edit, Execute | Нет |
| `УправлениеБизнесПроцессами` | Read, Insert, Update, View, Edit | Нет |
| `тст_ПросмотрНовыхОбъектов` | View | Нет |
| `тст_РаботаСДоверенностями` | Read | Нет |
| `РаботаСПротоколомРаботыСотрудников` | View | Нет |

### 2.2 Роли для Task.ЗадачаИсполнителя

| Роль | Права | Ограничения RLS |
|------|-------|----------------|
| `КонтрольЗадачИБизнесПроцессов` | Read, Update, View, Edit, Execute | **Нет** — неограниченный доступ |
| `РаботаСЗадачамиИБизнесПроцессами` | Read, Insert, Update, View, Edit, Execute | Нет |
| `ИзменениеВыполнениеЗадач` | Read, Update, View, Edit, Execute | Да — `#ЧтениеПроцесса("БизнесПроцесс")` |
| `ЧтениеЗадач` | Read, View, InputByString | Да — `#ЧтениеПроцесса("БизнесПроцесс")` |
| `ЧтениеПроцессовИЗадачБезОграничения` | Read, View | Нет по ЗадачаИсполнителя, но есть по файлам |
| `УправлениеБизнесПроцессами` | Read, Insert, Update, View, Edit, Execute | Нет |

## 3. Может ли сотрудник видеть задачи других сотрудников?

**По умолчанию — нет.** Доступ строго ограничен.

### Механизм видимости Document.Задача

Роль `РаботаСЗадачами` для операции **Read** использует RLS-шаблон `#ПоДескрипторуОбъекта`:

```sql
ТекущаяТаблица ИЗ #ТекущаяТаблица КАК ТекущаяТаблица
ВНУТРЕННЕЕ СОЕДИНЕНИЕ РегистрСведений.ДескрипторыДляОбъектов КАК ДескрипторыДляОбъектов
    ПО ТекущаяТаблица.Ссылка = ДескрипторыДляОбъектов.Объект
ГДЕ ДескрипторыДляОбъектов.Дескриптор В (
    ВЫБРАТЬ ПраваПоДескрипторамДоступаОбъектов.Дескриптор
    ИЗ РегистрСведений.ПраваПоДескрипторамДоступаОбъектов
    ГДЕ ПраваПоДескрипторамДоступаОбъектов.Сотрудник В (&СотрудникиПользователя)
)
```

**Для операции Update** дополнительно проверяется замещение:
- сотрудник может редактировать задачу, если является замещающим её автора
- через `Справочник.ЗамещающиеИПомощники` и области замещения `ЗадачиПостановкаПоручений`, `Задачи`, `ВсеОбласти`

### Механизм видимости Task.ЗадачаИсполнителя

Роли `ЧтениеЗадач` и `ИзменениеВыполнениеЗадач` используют шаблон `#ЧтениеПроцесса("БизнесПроцесс")`:

```sql
ТаблицаПроцесса ИЗ #ТекущаяТаблица КАК ТаблицаПроцесса
ВНУТРЕННЕЕ СОЕДИНЕНИЕ РегистрСведений.УчастникиПроцессов КАК УчастникиПроцессов
    ПО ТаблицаПроцесса.БизнесПроцесс = УчастникиПроцессов.Процесс
ВНУТРЕННЕЕ СОЕДИНЕНИЕ РегистрСведений.СоставСубъектовПравДоступа КАК СоставСубъектов
    ПО УчастникиПроцессов.Участник = СоставСубъектов.Субъект
ГДЕ СоставСубъектов.Сотрудник В (&СотрудникиПользователя)
    И СоставСубъектов.ИмяОбластиДелегирования В ("", "Задачи", "ЗадачиПросмотр")
```

**Вывод:** сотрудник видит задачи исполнителя только если является участником соответствующего бизнес-процесса.

### Исключения

Сотрудник видит задачи других в следующих случаях:
1. Имеет роль **КонтрольЗадачИБизнесПроцессов** — полный доступ без RLS
2. Является **полноправным пользователем** ИБ (`ПолныеПрава`)
3. Система прав **отключена** (константа `ДокументооборотИспользоватьОграничениеПравДоступа = Ложь`)
4. Является **замещающим** сотрудника по задачам (через Справочник.ЗамещающиеИПомощники)
5. Включён в **рабочую группу** документа-задачи с флагом Изменение

## 4. Ограничения на уровне записей (RLS) для задач

**Да, RLS включён.** Ограничения настраиваются через константу `ДокументооборотИспользоватьОграничениеПравДоступа`.

Функция-переключатель:
```bsl
// CommonModules/ДокументооборотПраваДоступаПовтИсп
Функция ВключеноИспользованиеПравДоступа() Экспорт
    Возврат Константы.ДокументооборотИспользоватьОграничениеПравДоступа.Получить();
КонецФункции
```

**Два механизма RLS:**

| Объект | Шаблон RLS | Таблицы доступа |
|--------|-----------|----------------|
| Document.Задача | `#ПоДескрипторуОбъекта` | ДескрипторыДляОбъектов + ПраваПоДескрипторамДоступаОбъектов |
| Task.ЗадачаИсполнителя | `#ЧтениеПроцесса` | УчастникиПроцессов + СоставСубъектовПравДоступа |

## 5. Связь рабочих групп с доступом к документам

### Структура РегистрСведений.РабочиеГруппы

| Поле | Тип | Назначение |
|------|-----|-----------|
| Объект (измерение) | Многотипное (включает DocumentRef.Задача) | Документ, для которого задана рабочая группа |
| Участник (измерение) | Ссылочный тип | Сотрудник или группа пользователей |
| Изменение (ресурс) | Булево | Право на изменение (если Ложь — только чтение) |
| Автоподстановка (ресурс) | CatalogRef | Источник автоматического добавления |
| Источник (ресурс) | Многотипный | Откуда добавлен участник |

### Алгоритм связи

1. При записи рабочей группы автоматически вызывается `ОпределитьДескрипторыПриЗаписиРабочейГруппы`
2. Для каждого объекта из набора проверяется, входит ли он в механизм прав
3. Вызывается `ДокументооборотПраваДоступа.ОпределитьДескрипторыОбъекта(Объект)`
4. Функция `ЗаполнитьДескрипторыОбъектаПоРабочейГруппе` формирует или обновляет дескрипторы в `Справочник.ДескрипторыДоступаОбъектов`
5. На основе дескрипторов обновляется `РегистрСведений.ПраваПоДескрипторамДоступаОбъектов`
6. Именно этот регистр используется в RLS-запросах при чтении документов

**Итог:** рабочая группа документа определяет, кто может его читать/изменять через механизм дескрипторов доступа.

### Расширение рабочих групп

Функция `РасширитьРабочуюГруппуСвязанныхОбъектов` автоматически распространяет доступ:
- Если у документа есть рабочая группа, связанные объекты получают тех же участников
- Используется `СвязиОбъектов.СвязанныеОбъектыДляРасширенияРабочихГрупп` с вариантом синхронизации `Расширять`
- Поддерживает отложенное обновление через `РегистрСведений.ОчередьРасширенияРабочихГрупп`

## 6. Модуль РаботаСРабочимиГруппами

### Расположение
`CommonModules/РаботаСРабочимиГруппами/Ext/Module.bsl`

### Ключевые экспортируемые функции

| Функция | Назначение |
|---------|-----------|
| `ПолучитьРабочуюГруппуДокумента(Документ)` | Возвращает таблицу участников рабочей группы (в привилегированном режиме) |
| `ПерезаполнитьРабочуюГруппуДокумента(Документ, ЗаписатьДокумент)` | Полностью пересчитывает рабочую группу из источников |
| `ПроверитьПраваПередЗаписьюРабочейГруппы(...)` | Проверяет права автора и участников перед записью |
| `ПроверитьПраваУчастниковРабочейГруппыНаОбъект(...)` | Проверяет, имеют ли новые участники право быть добавлены |
| `РасширитьРабочуюГруппуСвязанныхОбъектов(Объект)` | Распространяет рабочую группу на связанные объекты |
| `ОбновитьУчастниковРабочейГруппыПоАвтоподстановкам(...)` | Обновляет участников по правилам автоматической подстановки |
| `ДобавитьУчастниковИзИсточника(ТаблицаНабора, Источник)` | Добавляет участников из внешнего источника |

### Алгоритм ПроверитьПраваПередЗаписьюРабочейГруппы

```bsl
Если Не ДокументооборотПраваДоступаПовтИсп.ВключеноИспользованиеПравДоступа() Тогда
    Возврат; // без RLS — проверка не нужна
КонецЕсли;

// Проверяем только объекты, входящие в механизм прав
// (не всё: например, ТемыОбсуждений исключены)
Если ТипыОбъектовИспользующихДескрипторы.Найти(ТипСсылки) = Неопределено
    Или ТипСсылки = Тип("СправочникСсылка.ТемыОбсуждений") Тогда
    Возврат;
КонецЕсли;

ПроверитьПраваАвтораПередЗаписьюРабочейГруппы(...);
Если ЕстьНовыеУчастники Тогда
    ТекстОшибки = ПроверитьПраваУчастниковРабочейГруппыНаОбъект(...);
    Если ЗначениеЗаполнено(ТекстОшибки) Тогда
        ВызватьИсключение ТекстОшибки;
    КонецЕсли;
КонецЕсли;
```

## 7. Центральная функция проверки прав — алгоритм

`ДокументооборотПраваДоступа.ПраваСотрудникаПоОбъекту(ОбъектДоступа, Сотрудник)`:

```
1. Если RLS отключена → возвращает все права = Истина
2. Если пользователь = ПолныеПрава → возвращает все права = Истина
3. Иначе → запрашивает ПраваСотрудниковПоОбъекту (через дескрипторы)
   → результат: {Добавление, Изменение, Удаление, УправлениеПравами, Чтение}
```

## 8. Обновление прав при записи документа-задачи

При записи `Document.Задача` срабатывают подписки:
- `ДокументооборотПраваДоступа.ДокументооборотПраваДоступаПередЗаписьюДокумента` (BeforeWrite)
- `ДокументооборотПраваДоступа.ДокументооборотПраваДоступаПриЗаписиОбъектаДоступа` (OnWrite)

Второй обработчик пересчитывает дескрипторы доступа для всех участников рабочей группы документа, что немедленно отражается в RLS-таблицах.

## Итоговая схема системы прав доступа к задачам

```
Document.Задача (поручение)
├── Рабочая группа (РегистрСведений.РабочиеГруппы)
│   ├── Участник + Изменение (True/False)
│   └── → Дескрипторы (Справочник.ДескрипторыДоступаОбъектов)
│       └── → ПраваПоДескрипторамДоступаОбъектов (регистр)
│           └── [используется в RLS при Read/Update]
└── Роли:
    ├── РаботаСЗадачами → с RLS (#ПоДескрипторуОбъекта)
    └── КонтрольЗадачИБизнесПроцессов → без RLS (полный доступ)

Task.ЗадачаИсполнителя (задача бизнес-процесса)
├── БизнесПроцесс → УчастникиПроцессов (регистр)
│   └── → СоставСубъектовПравДоступа (регистр)
│       └── [используется в RLS при Read]
└── Роли:
    ├── ЧтениеЗадач → с RLS (#ЧтениеПроцесса)
    ├── ИзменениеВыполнениеЗадач → с RLS (#ЧтениеПроцесса)
    └── КонтрольЗадачИБизнесПроцессов → без RLS
```

**Константа ДокументооборотИспользоватьОграничениеПравДоступа** — главный выключатель всей системы RLS.
