## 1. Архитектура бизнес-процесса Подписание

### Тип объекта
`BusinessProcesses.Подписание` — полноценный бизнес-процесс 1С с картой маршрута (Flowchart), объектным модулем, модулем-менеджером и тремя формами.

### Карта маршрута (Flowchart)

```
[Старт]
    ↓  BeforeStart → СтартПередСтартом
[ПодготовкаИтерации]  — "Подготовка итерации подписания"
    ↓  Processing → ПодготовкаИтерацииОбработка
[ПодготовкаЭтапаКВыполнению]  — "Подготовка этапа к выполнению"
    ↓
[Разделение (Split)]
    ├──→ [ОбеспечитьПодписание]  — задача "Обеспечить подписание"
    └──→ [Подписать]  — задача "Подписать" (основная)
              ↓
         [ОбработатьРезультат]  — задача "Обработать результат"
              ↓
         [НеПодписано?]  — условие
          ├── Да → [ПовторитьПодписание?]
          │         ├── Да → возврат к ПодготовкаИтерации
          │         └── Нет → [Завершение (НеПодписано)]
          └── Нет → [ВсеЭтапыПройдены?]
                    ├── Нет → следующий этап
                    └── Да → [Завершение (Подписано)]
```

Ключевые события обработчиков:
- `ПодготовкаЭтапаКВыполнениюОбработка` — выбирает очередной этап
- `ПодписатьПередСозданиемЗадач` — формирует задачи для каждого участника этапа
- `НеПодписаноПроверкаУсловия` — проверяет есть ли неподписавшие на итерации
- `ВсеЭтапыПодписанияПройдены` — проверяет все этапы
- `ЗавершениеПриЗавершении` — фиксирует итоговый результат

## 3. Поддержка электронной подписи (ЭП/ЭЦП)

### Да, поддерживается. Три уровня ЭП:

#### 3.1 На уровне бизнес-процесса Подписание
Параметр **СпособПодписания** определяет режим:
- `НаБумаге` — физическое подписание, без ЭП
- `ПЭП` — Простая электронная подпись (без криптографии, фиксация факта)
- `УЭП` — Усиленная электронная подпись (с сертификатом и криптографией)

#### 3.2 На уровне ЭДО (электронные документы)
Справочник `МаршрутыПодписания` содержит:
- **ВидПодписи** (EnumRef.ВидыЭлектронныхПодписей): `Простая` / `УсиленнаяКвалифицированная`
- Таблица подписантов с полем **Сертификат** (CatalogRef.СертификатыКлючейЭлектроннойПодписиИШифрования)
- **Требование** (EnumRef): `И` (все), `ИЛИ` (любое), `ПоПорядку`

#### 3.3 Типы криптографической подписи (EnumRef.ТипыПодписиКриптографии)
- ОбычнаяCMS
- БазоваяCAdESBES (CAdES-BES)
- СМеткойДоверенногоВремениCAdEST (CAdES-T)
- СПолнымНаборомПроверочныхДанныхCAdESC (CAdES-C)
- CAdES-X Long, CAdES-X Type 1/2, CAdES-X Long Type 1
- РасширеннаяДолгосрочнаяCAdESXLongType2 (CAdES-X Long Type 2)
- CAdESAv2, АрхивнаяCAdESAv3

Константы системы:
- `ТипПодписиКриптографииПоУмолчанию`
- `УсовершенствоватьПодписиАвтоматически`
- `УсовершенствоватьПодписиСДаты`

#### 3.4 Внешнее подписание (Подсистема: ВнешнееПодписание)
Документ `СведенияОВнешнемПодписании` — хранит данные об отправке документа на подписание во внешний сервис (Сервис, ФизическоеЛицо, Результат).

## 5. Что происходит после подписания

### 5.1 Фиксация результата на уровне БП
В `ЗавершениеПриЗавершении`:
1. `ДатаЗавершения = ТекущаяДатаСеанса()`
2. `ЗаполнитьИтоговыйРезультатПодписания()` → проверяет `ЕстьНеПодписаноНаТекущейИтерации()` → устанавливает `РезультатПодписания = Подписано / НеПодписано`
3. `РаботаСБизнесПроцессами.ЗаписатьПроцесс()`
4. `РаботаСПроектами.ОтметитьОкончаниеВыполненияПроектнойЗадачи()`
5. `РаботаСПроцессамиПоДействиямСобытия.ПриЗавершенииПроцесса()` → обновляет результат "Действия" (объект-предмет процесса)

### 5.2 Результат выполнения процесса
- `РезультатПодписания = Подписано` → процесс завершился удачно → вариант выполнения: `Положительно`
- `РезультатПодписания = НеПодписано` → вариант: `Отрицательно`

### 5.3 Изменение статуса документа-предмета
При непосредственном подписании объекта (РаботаСЭП.ЗанестиИнформациюОПодписях):
- Для документов предприятия (`ДелопроизводствоКлиентСервер.ЭтоДокументПредприятия`):
  - `ПодписанЭП = Истина`
  - `Подписал = [сотрудник]` (при ВидПодписи = "ПодписьДокумента")
  - `РезультатПодписания = Подписано`
  - `ДатаПодписания = [дата]`
- Для файлов: `ПодписанЭП = Истина`, запись в регистр ЭлектронныеПодписи
- Для ЭД (ЭДО): поставка в очередь формирования ЭД

### 5.4 Повторное подписание
При условии `ПовторитьПодписание = Истина`:
- `НеобходимоПовторитьПодписание()` возвращает Истина, если КоличествоИтераций > НомерИтерации
- Процесс инициирует новую итерацию — `ПодготовитьПроцессКНовойИтерации()`

## 8. Выводы и особенности реализации

1. **БП Подписание многоэтапный**: поддерживает неограниченное количество этапов, параллельное и последовательное подписание внутри каждого этапа.

2. **Три способа подписания** в рамках одного БП: НаБумаге (без ЭП), ПЭП (простая), УЭП (усиленная с криптографией). Способ задаётся один для всего процесса.

3. **ЭП не хранится в документе напрямую** — используется отдельный регистр `ЭлектронныеПодписи` (для УЭП с полным хранением двоичных данных) и `ПростыеЭлектронныеПодписи` (для ПЭП). На документе устанавливается только флаг `ПодписанЭП`.

4. **Результат на документе** после подписания через ЭП: `ПодписанЭП = Истина`, `Подписал`, `ДатаПодписания`, `РезультатПодписания`. Эти реквизиты есть у справочника `ДокументыПредприятия`, файлов и версий файлов.

5. **Статус БП** = `РезультатПодписания` (Подписано/НеПодписано). Процесс считается успешным только когда все участники всех этапов подписали.

6. **Повторное подписание** управляется атрибутом `КоличествоИтераций` — при достижении итерации без подписания процесс можно повторить.

7. **Внешнее подписание** (аутсорс на внешний сервис через подсистему ВнешнееПодписание) реализовано через документ `СведенияОВнешнемПодписании` и модули `РаботаСВнешнимПодписанием`.

8. **Поддержка МЧД** (машиночитаемых доверенностей): в модуле РаботаСЭП есть методы `ЗанестиИнформациюОДоверенностиЭП`, `ДоступныеМЧДДляПодписанияСертификатом`, `ПроверитьДоверенностиЭлектронныхПодписей`.
