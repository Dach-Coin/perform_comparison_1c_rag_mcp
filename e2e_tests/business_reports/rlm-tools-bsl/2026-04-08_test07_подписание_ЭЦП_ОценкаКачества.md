## Что сервер дал хорошо

1. **Полная карта маршрута БП** — из Flowchart.xml извлечена вся структура: Старт → ПодготовкаИтерации → Разделение → ОбеспечитьПодписание/Подписать → ОбработатьРезультат → условия НеПодписано/ВсеЭтапыПройдены/ПовторитьПодписание → Завершение. Это уникальная возможность rlm-tools-bsl — прочитать Flowchart.xml напрямую
2. **Три способа подписания** — перечисление СпособыПодписанияПредметаПроцесса: НаБумаге, ПЭП, УЭП с точными синонимами
3. **Полная структура регистров хранения подписей** — ЭлектронныеПодписи (17 полей, включая ValueStorage для Подпись и Сертификат) и ПростыеЭлектронныеПодписи (6 полей) — измерения, ресурсы, типы
4. **Типы криптографической подписи** — 10 значений перечисления ТипыПодписиКриптографии от ОбычнаяCMS до АрхивнаяCAdESAv3
5. **Код смены статуса документа** — из процедуры ЗанестиИнформациюОПодписях прочитано, что при подписании: ПодписанЭП=Истина, Подписал=[сотрудник], РезультатПодписания=Подписано, ДатаПодписания=[дата]
6. **Атрибут ПодписанЭП** — найден на 5 объектах: ДокументыПредприятия, Файлы, ВерсииФайлов, Мероприятия + РС.ДанныеДокументовПредприятия
7. **115 экспортных методов РаботаСЭП** — полный API модуля, включая МЧД (машиночитаемые доверенности)
8. **Шаблоны подписания** — справочник ШаблоныПодписания с 47 атрибутами
9. **Внешнее подписание** — обнаружена отдельная подсистема ВнешнееПодписание с документом СведенияОВнешнемПодписании
10. **Маршруты подписания для ЭДО** — справочник МаршрутыПодписания с ВидПодписи (Простая/УсиленнаяКвалифицированная) и ТребованияКПодписаниюЭД (И/ИЛИ/ПоПорядку)

## Что сервер НЕ дал

1. **Интеграция с конкретными видами документов** — какие именно документы поддерживают подписание через БП (не через прямое ЭП) — агент отметил как "можно было глубже изучить"
2. **Механизм проверки подписей** — упомянуты методы УстановитьСтатусПроверки, ЗафиксироватьРезультатПроверки, но код проверки не прочитан (не запрашивался в тесте)

## Паттерны поведения агента

- **100% полезность, 0 retry** — идеальные метрики. Агент ни разу не промахнулся с запросом
- **Инициативное исследование Flowchart.xml**: агент самостоятельно нашёл и разобрал карту маршрута бизнес-процесса — это дало наглядную схему, которую невозможно получить из RAG-серверов
- **Многоуровневый анализ ЭП**: агент разделил ЭП на три уровня (БП Подписание, ЭДО через МаршрутыПодписания, внешнее подписание) — системный подход
- **parse_form**: использование parse_form для ФормаБизнесПроцесса и ФормаИсторияПодписания дало информацию о пользовательском интерфейсе
- **Батчинг**: эффективный — в одном вызове совмещал find_enum_values для нескольких перечислений + find_attributes
- **65 процедур ObjectModule**: extract_procedures дал полную картину обработчиков маршрута

Эталонный результат наравне с TEST-09 (МЭДО): нулевой шум, нулевые retry, 100% полезность.
