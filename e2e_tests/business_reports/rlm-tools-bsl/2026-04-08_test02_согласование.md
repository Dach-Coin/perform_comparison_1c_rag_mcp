## 1. Что такое бизнес-процесс Согласование

Бизнес-процесс **Согласование** (`BusinessProcesses.Согласование`) — ключевой объект 1С:Документооборот для организации коллегиального принятия решений по документам. Процесс маршрутизирует задачи между согласующими в заданном порядке, собирает результаты (визы) и формирует итоговый результат.

Основные файлы:
- `BusinessProcesses/Согласование/Ext/ObjectModule.bsl` — 2274 строки, вся логика процесса
- `BusinessProcesses/Согласование/Ext/ManagerModule.bsl` — ~2400 строк, API менеджера

### 2.2 Варианты согласования (ВариантыМаршрутизацииЗадач)

| Значение | Синоним | Описание |
|----------|---------|---------|
| `Последовательно` | По очереди | Задачи создаются одна за другой, следующая — только после выполнения предыдущей |
| `Параллельно` | Всем сразу | Задачи создаются всем согласующим одновременно |
| `Смешанно` | Смешанно | Комбинация: строки с ПорядокСогласования=ВместеСПредыдущим идут параллельно, ПослеПредыдущего — последовательно |

### 2.3 Табличная часть Исполнители (Лист согласования)

ТЧ `Исполнители` определяет кто, когда и в каком порядке согласует:

| Реквизит | Тип | Описание |
|----------|-----|---------|
| Исполнитель | `CatalogRef.Сотрудники / ПолныеРоли / Пользователи` | Кто согласует |
| ИдентификаторИсполнителя | UUID | Уникальный идентификатор строки (для обновления активного процесса) |
| ПорядокСогласования | `EnumRef.ПорядокВыполненияЗадач` | ВместеСПредыдущим / ПослеПредыдущего |
| ВариантУстановкиСрокаИсполнения | `EnumRef.ВариантыУстановкиСрокаИсполнения` | Способ задания срока |
| СрокИсполнения | Дата | Конкретная дата дедлайна |
| СрокИсполненияДни/Часы/Минуты | Число | Относительный срок |
| Описание | Строка | Комментарий к задаче исполнителя |
| ЗадачаИсполнителя | `TaskRef.ЗадачаИсполнителя` | Ссылка на созданную задачу |
| Пройден | Булево | Флаг — задача выполнена (заполняется автоматически при завершении задачи) |
| ТрудозатратыПланИсполнителя | Число | Плановые трудозатраты |

### 2.4 Заполнение по шаблону

Процедура `ЗаполнитьПоШаблону(ШаблонБизнесПроцесса)` заполняет процесс из `Справочника.ШаблоныСогласования`:
- Переносит Наименование, Важность, Описание
- Копирует список Исполнителей с их порядком
- Устанавливает ВариантСогласования
- Применяет условия из шаблона (РаботаСАлгоритмамиПроверки)
- Если включена функциональная опция `ИспользоватьВизыСогласования` и `ИспользоватьЭлектронныеПодписи` — устанавливает ПодписыватьЭП

## 3. ВизыСогласования — структура и назначение

### 3.1 Что такое виза

`Справочник.ВизыСогласования` — это **запись факта согласования** конкретным исполнителем. Каждый элемент справочника фиксирует:
- кто согласовал
- какой результат дал
- когда
- к какому документу и процессу относится

Используется только при включённой функциональной опции `ИспользоватьВизыСогласования`.

### 3.2 Структура справочника ВизыСогласования

| Реквизит | Синоним | Тип |
|----------|---------|-----|
| Автор | Автор | `CatalogRef.Сотрудники / Пользователи` |
| Исполнитель | Исполнитель | `CatalogRef.Сотрудники / ПолныеРоли / Пользователи` |
| РольИсполнителя | Роль исполнителя | `CatalogRef.ПолныеРоли` |
| УстановилРезультат | Установил результат | `CatalogRef.Сотрудники / ФактическиеИсполнители / Пользователи` |
| Документ | Документ | `CatalogRef.ДокументыПредприятия` |
| Источник | Источник | `CatalogRef.ДействияСогласования / TaskRef.ЗадачаИсполнителя / BusinessProcessRef.Согласование` |
| РезультатСогласования | Результат согласования | `EnumRef.РезультатыСогласования` |
| ИдентификаторУчастника | Идентификатор участника | UUID |
| Комментарий | Комментарий | Строка |
| ДатаСоздания | Дата создания | Дата |
| ДатаИсполнения | Дата исполнения | Дата |
| Порядок | Порядок | Число |
| НомерИтерации | Номер итерации | Число |
| Подписана | Подписана | Булево |
| Удалена | Удалена | Булево |

### 3.3 Связь визы с процессом

- Поле `Источник` связывает визу с конкретной задачей (`TaskRef.ЗадачаИсполнителя`) или бизнес-процессом (`BusinessProcessRef.Согласование`) или действием согласования (`CatalogRef.ДействияСогласования`)
- При записи визы с установленным `РезультатСогласованиям` автоматически фиксируются версии файлов документа: `РегистрыСведений.ВерсииСогласованныхФайлов.ДобавитьВерсииФайловПоВизе()`
- Права на добавление визы — у автора, права на изменение — у автора и исполнителя (и их делегатов/руководителей)

## 4. Результаты согласования

### 4.1 Возможные результаты задачи согласующего

Перечисление `РезультатыСогласования`:

| Значение | Синоним | Описание |
|----------|---------|---------|
| `Согласовано` | Согласовано | Положительный результат без замечаний |
| `СогласованоСЗамечаниями` | Согласовано с замечаниями | Положительный, но с замечаниями (при режиме замечаний) |
| `НеСогласовано` | Не согласовано | Отрицательный результат |

### 4.2 Маппинг на ВариантыВыполненияПроцессовИЗадач

Функция `РезультатВыполненияЗадачи` (ManagerModule) переводит результат согласования в системный вариант выполнения задачи:

| РезультатыСогласования | ВариантыВыполненияПроцессовИЗадач |
|------------------------|-----------------------------------|
| НеСогласовано | Отрицательно |
| Согласовано | Положительно |
| СогласованоСЗамечаниями | ПоложительноСЗамечаниями |

### 4.3 Правило определения итогового результата

Функция `ИтоговыйРезультатСогласования()` применяет приоритет:

```
1. Если хотя бы один результат = НеСогласовано → итог = НеСогласовано (выход немедленно)
2. Если хотя бы один = СогласованоСЗамечаниями → итог = СогласованоСЗамечаниями
3. Иначе → итог = Согласовано
```

Учитываются только результаты текущей итерации (`НомерИтерации`).

### 4.4 Успешное завершение процесса

Функция `ПроцессЗавершилсяУдачно`:
- Возвращает `Истина` если процесс завершён И (РезультатСогласования = Согласовано ИЛИ СогласованоСЗамечаниями)
- То есть "Не согласовано" не является удачным результатом

## 5. Что происходит при завершении всех задач

### 5.1 Маршрут бизнес-процесса

Маршрут процесса Согласование включает точки:
- **Согласовать** — задача согласующему
- **ОбработкаРезультата** — задача обрабатывающему результат
- **Завершение** — финальная точка

Схема прохождения (упрощённо):

```
Старт → Согласовать (все исполнители по порядку/параллельно)
           ↓ (при выполнении каждой задачи: СогласоватьПриВыполнении)
       УсловиеОбходЗавершен? (ОбходСогласующихЗавершен())
           → НЕТ: продолжаем
           → ДА:  ОбработкаРезультата → ОбработкаРезультатаОбработка()
                      ↓
                  СогласованоПроверкаУсловия?
                      → ДА: ознакомление (Ознакомиться)
                      → НЕТ: Повторить? → ДА: возврат к Согласовать
                                        → НЕТ: Завершение
```

### 5.2 СогласоватьПриВыполнении

```bsl
Процедура СогласоватьПриВыполнении(ТочкаМаршрутаБизнесПроцесса, Задача, Отказ)
    ДобавитьЗадачуОтложеннаяОбработкаЗавершенияСогласования();
КонецПроцедуры
```

При выполнении задачи создаётся **служебная отложенная задача** для обработки завершения. Это необходимо при режиме замечаний для асинхронной обработки.

### 5.3 ОбработатьЗавершениеЗадачиСогласования

```bsl
Процедура ОбработатьЗавершениеЗадачиСогласования(Задача)
    НайденнаяСтрока = Исполнители.Найти(Задача, "ЗадачаИсполнителя");
    // ...
    НайденнаяСтрока.Пройден = Истина;
    РаботаСБизнесПроцессами.ЗаписатьПроцесс(ЭтотОбъект, "ПростаяЗапись");
КонецПроцедуры
```

Отмечает строку исполнителя как пройденную — это отслеживает прогресс прохождения листа согласования.

### 5.4 ОбходСогласующихЗавершен — условие перехода к обработке результата

```bsl
Функция ОбходСогласующихЗавершен() Экспорт
    // Запрос: есть ли незавершённые задачи с активными исполнителями?
    // Если есть → Ложь (ещё не все согласовали)
    // Если нет И итог = НеСогласовано → Истина (прерываем досрочно)
    // Если нет → проверяем что все строки Исполнителей имеют Пройден=Истина
КонецФункции
```

### 5.5 ОбработкаРезультатаОбработка — точка маршрута "ОбработкаРезультата"

```bsl
Процедура ОбработкаРезультатаОбработка(ТочкаМаршрутаБизнесПроцесса)
    РезультатСогласования = ИтоговыйРезультатСогласования();
    РаботаСБизнесПроцессами.ЗаписатьПроцесс(ЭтотОбъект, "ПростаяЗапись");
КонецПроцедуры
```

Вычисляет и сохраняет итоговый результат в реквизит шапки.

### 5.6 ЗавершениеПриЗавершении — финальная точка

```bsl
Процедура ЗавершениеПриЗавершении(ТочкаМаршрутаБизнесПроцесса, Отказ)
    ДатаЗавершения = ТекущаяДатаСеанса();
    РаботаСПроектами.ОтметитьОкончаниеВыполненияПроектнойЗадачи(ЭтотОбъект);
    РаботаСПроцессамиПоДействиямСобытия.ПриЗавершенииПроцесса(ЭтотОбъект);
КонецПроцедуры
```

Итоговые действия:
1. Фиксируется дата завершения
2. Если процесс связан с проектной задачей — отмечается её окончание
3. Вызывается `РаботаСПроцессамиПоДействиямСобытия.ПриЗавершенииПроцесса` — обновляет результат выполнения у связанного действия (ДействияСогласования)

### 5.7 ПриЗавершенииПроцесса (РаботаСПроцессамиПоДействиямСобытия)

```bsl
Процедура ПриЗавершенииПроцесса(Процесс) Экспорт
    Действие = РегистрыСведений.ПроцессыДействий.ДействиеПоПроцессу(Процесс.Ссылка);
    // Если есть другие активные процессы действия — ждём
    // Если нет → МенеджерДействия.ОбновитьРезультатВыполнения(Действие);
КонецПроцедуры
```

Когда все процессы завершены — результат выполнения действия обновляется.

## 6. Общие модули в логике согласования

| Модуль | Назначение |
|--------|-----------|
| `РаботаСБизнесПроцессами` | Основной модуль работы с БП: запись процессов/задач, получение задач по точкам маршрута, обновление результатов выполнения |
| `РаботаСПроцессамиПоДействиямСобытия` | Обработка событий процессов при работе через ДействияСогласования: запуск, завершение, обновление результата действия |
| `РаботаСПроцессамиПоДействиям` | Утилиты для работы с действиями: получение действия задачи, результат выполнения задачи по параметрам |
| `СогласованиеВРежимеЗамечанийСервер` | Управление файлами в режиме замечаний: HTML-версии, замечания, проверка наличия правок |
| `СогласованиеВРежимеЗамечанийКлиент` | Клиентская часть режима замечаний |
| `СогласованиеВРежимеЗамечанийHTMLСервер` | Серверная обработка HTML-файлов с замечаниями |
| `БизнесПроцессыИЗадачи` / `БизнесПроцессыИЗадачиКлиент` | БСП-механизм бизнес-процессов и задач (стандарт) |
| `РаботаСАлгоритмамиПроверки` | Проверка условий применимости шаблонных строк исполнителей |
| `МультипредметностьКлиентСервер` | Работа с предметами бизнес-процесса (список документов/объектов для согласования) |
| `ОбработкаОчередиЗаданийСервер` | Постановка отложенных задач для асинхронной обработки завершения согласования |
| `РаботаСПроектами` | Отметка завершения проектных задач при завершении процесса |
| `РаботаСРабочимиГруппами` | Расширение рабочей группы документа при создании/изменении визы |

## 7. Итоговая схема процесса Согласование

```
Инициатор создаёт БП Согласование
    ↓
Заполнение параметров (через шаблон или вручную):
  • Список исполнителей (ТЧ Исполнители)
  • Вариант согласования: Последовательно / Параллельно / Смешанно
  • Сроки исполнения для каждого согласующего
  • Автор (обычно = инициатор)
  • ОбрабатывающийРезультат (кто обрабатывает итог)
  • ПодписыватьЭП (при использовании ЭП)
    ↓
Запуск процесса → создаются задачи (СоздатьЗадачиСогласования)
    ↓
Согласующие выполняют задачи с результатом:
  • Согласовано
  • Согласовано с замечаниями
  • Не согласовано
    ↓
При каждом выполнении:
  • ОбработатьЗавершениеЗадачиСогласования → Пройден=Истина
  • Если режим замечаний → отложенная обработка
    ↓
ОбходСогласующихЗавершен()?
  • НЕТ → ждём следующего исполнителя (по порядку/параллельно)
  • ДА  → точка маршрута ОбработкаРезультата
    ↓
ОбработкаРезультатаОбработка:
  • РезультатСогласования = ИтоговыйРезультатСогласования()
    (НеСогласовано > СогласованоСЗамечаниями > Согласовано)
    ↓
ОбрабатывающийРезультат обрабатывает итог
    ↓
Повторить? → ДА → новая итерация (КоличествоИтераций++)
            → НЕТ → ЗавершениеПриЗавершении:
                       • ДатаЗавершения = ТекущаяДата()
                       • ОтметитьОкончаниеПроектнойЗадачи
                       • ПриЗавершенииПроцесса → ОбновитьРезультатДействия
```

## 8. Кастомизации (доработки тст_)

В коде обнаружены следующие кастомизации проекта Тест:

1. **Реестр тст_СогласованиеЗаявокСБ** — отдельный регистр сведений для учёта согласования заявок службой безопасности

2. **тст_НеОзнакамливать** (задача 89181, разработчик Кокоев, 23.04.2024):
   - В `СогласованоПроверкаУсловия` добавлена проверка флага `тст_НеОзнакамливать` из настройки действия
   - Если флаг установлен — не запускать ознакомление при несогласовании
   
3. **Хардкод ДД Директор по брэнду** (в `СогласованоПроверкаУсловия`):
   - Поиск роли исполнителя "ДД Директор по брэнду" по наименованию
   - Если результат согласован без участия директора по бренду — ознакомление не требуется
