## Что сервер дал хорошо

1. **Полная структура БП** — `parse_object_xml` вернул 31 атрибут и 6 ТЧ (Исполнители, РезультатыСогласования, Предметы, ПредметыЗадач, РезультатыОзнакомлений, ДополнительныеРеквизиты). Аналогично для ШаблоныСогласования (24 атрибута, 5 ТЧ) и ВизыСогласования (18 атрибутов).

2. **Все перечисления** — `find_enum_values` нашёл:
   - РезультатыСогласования: НеСогласовано, Согласовано, СогласованоСЗамечаниями
   - ВариантыМаршрутизацииЗадач: Последовательно, Параллельно, Смешанно
   - ПорядокВыполненияЗадач: ВместеСПредыдущим, ПослеПредыдущего
   - ВариантыУстановкиСрокаИсполнения: ОтносительныйСрок, ТочныйСрок

3. **Ключевые алгоритмы** — через `read_procedure` получен реальный BSL-код:
   - `ИтоговыйРезультатСогласования`: приоритет НеСогласовано > СЗамечаниями > Согласовано
   - `ОбходСогласующихЗавершен`: SQL-запрос на незакрытые задачи
   - `СоздатьЗадачиСогласования`: ветвление по вариантам маршрутизации
   - `ЗаполнитьПоШаблону`: заполнение параметров из шаблона с проверкой условий

4. **Схема маршрута БП** — реконструирована полная цепочка точек маршрута: Старт → Подготовка → Согласовать → ОбходЗавершен → ОбработкаРезультата → Согласовано? → Ознакомиться → Завершение.

5. **Механизм отложенной обработки** — раскрыта полная цепочка: СогласоватьПриВыполнении → ОбработкаОчередиЗаданийСервер → служебная задача + фоновое задание.

6. **API виз** — `find_exports` дал 29 экспортов модуля РаботаСВизамиСогласования.

7. **20 подписок на события** — полный перечень обработчиков BeforeWrite/OnWrite/OnCopy/Filling.

8. **Кастомный код Тест** — обнаружен хардкод роли "ДД Директор по брэнду" в `СогласованоПроверкаУсловия` + реквизит `тст_НеОзнакамливать` (задача #89181, 23.04.2024).

## Что сервер НЕ дал

1. **XML маршрута БП** — точки маршрута со связями не найдены через glob (MDO-файл не обнаружен). Маршрут пришлось реконструировать по именам обработчиков — это правильно, но не 100% гарантия полноты.

2. **Полный текст ЗаполнитьПоШаблону** — обрезан на ~3500 символов (ограничение `max_output_chars`). Основная логика получена, но хвост потерян.

3. **Визуальная схема** — не генерировалась (Mermaid-диаграмма отсутствует).

## Паттерны поведения агента

- **Стратегия "от структуры к коду"**: parse_object_xml → extract_procedures → read_procedure для ключевых функций → find_callers/exports для общих модулей. Оптимальный паттерн.
- **Минимум ошибок**: единственный retry (#3) — попытка `import os` в sandbox. Исправлено немедленно.
- **Широкий охват модулей**: агент исследовал 7 общих модулей + 5 интеграционных, дал классификацию по назначению.
- **Целенаправленный drill-down**: агент прошёл полную цепочку завершения (6 уровней вызовов) — от СогласоватьПриВыполнении до фонового задания.
- **92% полезных вызовов** — лучший показатель среди трёх тестов.

## Выявленные проблемы RAG

| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| sandbox не позволяет import os | #3: retry, агент пытался проверить наличие файла через os.path.exists |
| max_output_chars обрезает длинные процедуры | ЗаполнитьПоШаблону обрезана на 3500 символов |
| Нет API для чтения маршрута БП из XML | Точки маршрута пришлось реконструировать по именам обработчиков |
| find_custom_modifications не находит inline-кастомизации | 0 кастомных процедур, хотя кастомный код встроен в стандартные процедуры через регионы |

## Вывод

rlm-tools-bsl показал **лучший результат** из трёх тестов: 92% полезных вызовов, 1 retry, полное раскрытие всех 5 подвопросов теста. Особенно ценно: доступ к реальному BSL-коду алгоритмов (ИтоговыйРезультатСогласования, ОбходСогласующихЗавершен, цепочка отложенной обработки) и обнаружение кастомного кода Тест, который RAG-серверы не нашли бы без прямого чтения процедур.
