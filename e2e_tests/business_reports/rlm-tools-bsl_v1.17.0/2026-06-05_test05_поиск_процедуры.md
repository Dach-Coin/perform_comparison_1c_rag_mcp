## Как работает функция

Функция определяет фактического исполнителя для каждого действия задачи, последовательно проходя три уровня проверки:

### Уровень 1 — Прямой исполнитель-сотрудник (строки 69–95)

Если исполнитель действия задачи является записью справочника `Сотрудники` (`СправочникСсылка.Сотрудники`), проверяется является ли текущий пользователь (или указанный в `ВыполнитьОтИмени`) этим сотрудником. Если да — фактический исполнитель найден немедленно, вызывается `Справочники.ФактическиеИсполнители.НайтиСоздатьФактическогоИсполнителя()` и обработка этого действия завершается.

### Уровень 2 — Исполнитель через роль (строки 97–138)

Если исполнитель является записью справочника `ПолныеРоли` (`СправочникСсылка.ПолныеРоли`), функция:
1. Получает список сотрудников роли через `РегистрыСведений.ИсполнителиРолей.ИсполнителиРоли()`
2. Находит пересечение с сотрудниками текущего пользователя через `ОбщегоНазначенияДокументооборотКлиентСервер.ПересечениеМассивов()`
3. Если пересечение найдено — берёт первого подходящего сотрудника, иначе использует основного сотрудника

### Уровень 3 — Замещение (строки 141–228)

Если ни прямой, ни ролевой исполнитель не найден, функция обращается к справочнику замещений:

**Шаг 3а — все замещения:** получает полную таблицу через `Справочники.ЗамещающиеИПомощники.ВсеЗамещенияПоДействиямЗадач()`. Если для одного действия более одного замещения — задача помечается как требующая интерактивного выбора адресата (`ДействияБезКомуАдресовано`).

**Шаг 3б — явно выбранный исполнитель:** если пользователь уже выбрал исполнителя (`ВыбранныйФактическийИсполнитель ≠ Неопределено`), применяет его, различая замещающего (`ЭтоЗамещающий = Истина`) и помощника.

**Шаг 3в — актуальные замещения:** запрашивает `Справочники.ЗамещающиеИПомощники.АктуальныеЗамещенияПоДействиямЗадач()` и перебирает результаты. Для каждого замещения различает:
- **Помощник** (`ВидыЗамещения.Помощники`): сам является фактическим исполнителем
- **Замещающий** (`ВидыЗамещения.Замещающие`): основной сотрудник — физический исполнитель, замещающий — адресат

### Возвращаемое значение

Функция возвращает структуру с пятью полями:
```
ДанныеФактическихИсполнителей:
  .ДействияБезФактИсполнителя      — список действий без определённого исполнителя
  .ДействияБезКомуАдресовано       — список действий, требующих уточнения адресата
  .ФактическиеИсполнителиПолные    — соответствие: ДействиеЗадачи → ФактическийИсполнитель (ссылка)
  .ФактическиеИсполнителиПоДействиям — соответствие: ДействиеЗадачи → Сотрудник
  .ОснованияФактИсполнителейПоДействиям — соответствие: ДействиеЗадачи → ЗаписьЗамещения
```

## Кто вызывает процедуру (6 вызывающих)

### 1. `ПринятьКИсполнению` — `CommonModules/БизнесПроцессыИЗадачиСервер/Ext/Module.bsl:77`

Основной сценарий — принятие задачи к исполнению пользователем. Вызывается когда у задачи-процесса не заполнен реквизит `Исполнитель` (строки 66–80). Использует результат: если остались `ДействияБезФактИсполнителя` — возвращает флаг `НужноВыбратьФактическогоИсполнителя = Истина` для интерактивного диалога.

Этот метод вызывается из `ОбработатьВзятиеВРаботу` (CommonModules/ИнтеграцияЗадач).

### 2. `ВзятьВРаботу` — `CommonModules/РаботаСЗадачами/Ext/Module.bsl:798`

Внутренний вызов в том же модуле при взятии задачи в работу. Вызывается из шести мест второго уровня: `ОбработатьВзятиеВРаботу`, `ОбработатьСохранениеРезультатаДействия` (ИнтеграцияЗадач), `ДобавитьПриложения`, `СохранитьРезультатДействия` (РаботаСЗадачами), `ВзятьВРаботу` (РаботаСЗадачамиВызовСервера), `ПриСозданииНаСервере` (форма документа Задача).

### 3. `ЗаполнитьФактическогоИсполнителя` — `CommonModules/РаботаСЗадачамиВызовСервера/Ext/Module.bsl:1332`

Обёртка-адаптер: принимает `ПараметрыВыполнения` и `ДанныеВыполнения`, вызывает `ОпределитьФактическихИсполнителей` и записывает результаты обратно в `ПараметрыВыполнения`. Если исполнитель не найден — устанавливает `ДанныеВыполнения.ВыбратьИсполнителяЗадачи = Истина` для интерактивного режима.

Вызывается из `ВыполнитьДействиеЗадачи` (РаботаСЗадачамиВызовСервера) — основной точки входа при выполнении действий задач.

### 4. `ЗаполнитьПараметрыОбработкиВнешнегоПодписанияПоВыполнениюОтДействия` — `CommonModules/РаботаСВнешнимПодписанием/Ext/Module.bsl:2343`

Подсистема внешнего подписания документов. Определяет фактического исполнителя при подписании от имени действия задачи.

### 5. `ЗаполнитьПараметрыОбработкиВнешнегоПодписанияПоВыполнениюОтЗадачи` — `CommonModules/РаботаСВнешнимПодписанием/Ext/Module.bsl:2429`

Аналогично предыдущему, но при подписании от имени задачи целиком.

Оба вызова собраны в `ЗаполнитьПараметрыОбработкиВнешнегоПодписанияПоВыполнению` (РаботаСВнешнимПодписанием).

### 6. `ПрименитьПравилоЭскалацииДействияОзнакомления` — `CommonModules/ЭскалацияЗадач/Ext/Module.bsl:1756`

Подсистема эскалации. При применении правила эскалации для действия ознакомления определяет нового фактического исполнителя с учётом замещений. Вызывается из `ЭскалацияДействийОзнакомления` (ЭскалацияЗадач).
