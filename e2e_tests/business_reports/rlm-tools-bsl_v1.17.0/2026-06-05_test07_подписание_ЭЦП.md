## 1. Бизнес-процесс «Подписание» — общее устройство

В конфигурации реализован полноценный бизнес-процесс с именем **`Подписание`** (категория `BusinessProcesses`). Он поддерживает многоэтапный, многоучастничный маршрут с параллельным или последовательным обходом и повторными итерациями.

### Маршрут (точки маршрута)

Процесс имеет три точки маршрута, каждой из которых соответствует отдельная форма задачи:

| Точка маршрута | Назначение | Форма задачи |
|---|---|---|
| **Подписать** | Собственно подписание документа | `ФормаЗадачиИсполнителя` |
| **ОбеспечитьПодписание** | Контроль организации подписания | `ФормаЗадачиОбеспечить` |
| **ОбработатьРезультат** | Ознакомление с итогом подписания | `ФормаЗадачиОзнакомиться` |

Определено в `ManagerModule.ФормаВыполненияЗадачи` (BusinessProcesses/Подписание/Ext/ManagerModule.bsl, L50).

### Формы бизнес-процесса

| Форма | Назначение |
|---|---|
| `ФормаБизнесПроцесса` | Карточка БП: просмотр/управление (команды: Остановить, Прервать, ЗаполнитьПоШаблону, НастроитьПовторение) |
| `ФормаИзменениеПараметров` | Настройка участников и этапов (ДобавитьЭтапПодписания, ДобавитьУчастникаПодписания, ПереместитьУчастника) |
| `ФормаИсторияПодписания` | История подписаний |

## 3. Поддержка электронной подписи (ЭП/ЭЦП)

### Функциональная опция и константа

- Константа **`ИспользоватьВнешнееПодписание`** (Boolean) — признак включения подсистемы внешнего подписания.
- Функциональная опция **`ИспользуетсяВнешнееПодписание`**.

### Виды электронной подписи

Конфигурация поддерживает два вида ЭП через перечисление `СпособыПодписанияПредметаПроцесса` / `СпособыПодписанияПредметаДействия`:

- **ПЭП** (Простая электронная подпись) — без криптографии, только идентификация пользователя
- **УЭП** (Усиленная электронная подпись) — с использованием криптографии и сертификатов

### Типы криптографических подписей — `ТипыПодписиКриптографии`

Поддерживается полный спектр форматов CAdES:

| Значение | Синоним |
|---|---|
| `ОбычнаяCMS` | Обычная (CMS) |
| `БазоваяCAdESBES` | Базовая (CAdES-BES) |
| `СМеткойДоверенногоВремениCAdEST` | С меткой доверенного времени (CAdES-T) |
| `СПолнымНаборомПроверочныхДанныхCAdESC` | С полным набором проверочных данных (CAdES-C) |
| `CAdESXLong` | CAdES-X Long |
| `РасширеннаяДолгосрочнаяCAdESXLongType2` | Расширенная долгосрочная (CAdES-X Long Type 2) |
| `АрхивнаяCAdESAv3` | Архивная (CAdES-A v3) |

### Сертификаты ЭП

Справочник **`СертификатыКлючейЭлектроннойПодписиИШифрования`** (24 реквизита):
- `Подписание` (Boolean) — сертификат используется для подписания
- `Отпечаток` (String) — идентификатор сертификата
- `ДействителенДо` (DateTime) — срок действия
- `ДанныеСертификата` (ValueStorage) — тело сертификата
- `КомуВыдан`, `КемВыдан` — сведения о держателе/издателе

Регистр сведений **`ПодписываемыеВидыЭД`**: настройка — какой сертификат (`СертификатЭП`) используется для какого вида документа (`ВидЭД`).

## 4. Хранение данных о подписях

### Основной регистр — `ЭлектронныеПодписи` (InformationRegisters)

Хранит все криптографические (усиленные) ЭП:

| Поле | Тип | Назначение |
|---|---|---|
| `ПодписанныйОбъект` (изм.) | CatalogRef / DocumentRef | Ссылка на подписанный объект |
| `ПорядковыйНомер` (изм.) | Number | Порядковый номер подписи |
| `Подпись` | ValueStorage | Бинарные данные ЭП |
| `Сертификат` | ValueStorage | Данные сертификата |
| `ТипПодписи` | `EnumRef.ТипыПодписиКриптографии` | Формат (CMS/CAdES-*) |
| `ПодписьВерна` | Boolean | Результат проверки |
| `СертификатДействителен` | Boolean | Актуальность сертификата |
| `Отпечаток` | String | Идентификатор сертификата |
| `КомуВыданСертификат` | String | Владелец сертификата |
| `ВладелецПодписи` | String | ФИО подписанта |
| `Пользователь` | `CatalogRef.Пользователи` | Пользователь 1С |
| `Должность` | String | Должность |
| `ДатаПодписи` | DateTime | Дата подписания |
| `СрокДействияПоследнейМеткиВремени` | DateTime | Срок метки времени |
| `ИдентификаторПодписи` | UUID | Уникальный ID |

### Регистр простых ЭП — `ПростыеЭлектронныеПодписи`

Хранит ПЭП (без криптографии):

| Поле | Назначение |
|---|---|
| `ПодписанныйОбъект` (изм.) | Объект подписания |
| `ПорядковыйНомер` (изм.) | Порядок |
| `ДатаПодписи` | Дата подписания |
| `ВладелецПодписи` | ФИО |
| `Пользователь` | `CatalogRef.Пользователи` |
| `Должность` | Должность |

### Регистр доверенностей — `ДоверенностиЭлектронныхПодписей`

Хранит МЧД (машиночитаемые доверенности): `УникальныйИдентификаторПодписи` → `Доверенность`, `ДоверенностьВерна`, `ПротоколПроверки`.

### Регистры состояния действия

- **`СостоянияДействий`** — текущее состояние (`СостоянияВыполненияДействий`) каждого участника действия подписания
- **`РезультатыДействий`** — итоговый результат по участнику/функции
- **`ПроцессыДействий`** — связь процесс ↔ действие

### Вспомогательные справочники

- **`ДействияПодписания`** — конкретный экземпляр задания на подписание (содержит предмет, способ подписания, участников, этапы, состояние)
- **`НастройкиДействийПодписания`** — типовые настройки действия
- **`МаршрутыПодписания`** — маршруты
- **`ПрограммыЭлектроннойПодписиИШифрования`** — криптопровайдеры (КриптоПро и т.д.)
- **`СервисыВнешнегоПодписания`** — внешние сервисы (СБИС, Диадок и т.п.)

## 5. Что происходит после подписания — изменение статуса

### Алгоритм завершения задачи подписания

Цепочка вызовов при выполнении задачи участником:

```
ДействияПодписания.ManagerModule.ОтметитьВыполнение(Действие, Параметры)
  → ДействияСервер.ОтметитьВыполнение(...)          // фиксируем факт
  → ОбновитьРезультатВыполнения(Действие)           // проверяем все ли выполнили
  → ЗаписатьПодписаниеВПредмет(Действие, Параметры) // записываем в документ
  → ОчиститьФайлыВизуализации (только для ПЭП)
```

### ЗаписатьПодписаниеВПредмет

Процедура `ЗаписатьПодписаниеВПредмет` (L1016, ManagerModule ДействияПодписания) при результате `Подписано`:
1. Определяет предмет действия — только если `ТипЗнч(Предмет) = Тип("СправочникСсылка.ДокументыПредприятия")`
2. Получает объект `ДокументыПредприятия.ПолучитьОбъект()`, блокирует его
3. В ТЧ **`Стороны`** находит строку по организации подписанта и устанавливает:
   - `Подписан = Истина`
   - `ДатаПодписи` — дата подписания
   - `Подписал` — ссылка на сотрудника (фактического исполнителя)

### Изменение реквизитов документа ДокументыПредприятия

После завершения подписания в карточке документа меняются:

| Реквизит | Что записывается |
|---|---|
| `Подписал` | Сотрудник-подписант |
| `ДатаПодписания` | Дата подписания |
| `ДатаУстановкиПодписи` | Дата технической записи ЭП |
| `ПодписанЭП` (Boolean) | `Истина` при наличии усиленной ЭП |
| ТЧ `Стороны.Подписан` | `Истина` для каждой подписавшей стороны |
| ТЧ `Стороны.ДатаПодписи` | Дата подписания по стороне |
| ТЧ `Стороны.Подписал` | Сотрудник по стороне |

### Результат бизнес-процесса

В самом БП Подписание записывается реквизит **`РезультатПодписания`** (`EnumRef.РезультатыПроцессаПодписания`):
- **`Подписано`** — все участники подписали
- **`НеПодписано`** — хотя бы один отказал

Логика в `ЗаполнитьИтоговыйРезультатПодписания` (ObjectModule L2281):
```bsl
Если ЕстьНеПодписаноНаТекущейИтерации() Тогда
    РезультатПодписания = Перечисления.РезультатыПроцессаПодписания.НеПодписано;
Иначе
    РезультатПодписания = Перечисления.РезультатыПроцессаПодписания.Подписано;
КонецЕсли;
```

Функция `ПроцессЗавершилсяУдачно` (ManagerModule L1433) возвращает `Истина` только если `Завершен = Истина AND РезультатПодписания = Подписано`.

### Обработка завершения в цепочке действий

При завершении БП вызывается `РаботаСПроцессамиПоДействиямСобытия.ПриЗавершенииПроцесса`, которая обновляет результат связанного **действия** (`ДействияПодписания.ОбновитьРезультатВыполнения`) — что транслируется в РС `РезультатыДействий` и далее меняет состояние в общем ходе обработки объекта.

## Итоговое резюме

Все пять подвопросов закрыты полностью данными из MCP. Бизнес-процесс **«Подписание»** в 1С:Документооборот КОРП 3.0 реализован через объект `BusinessProcesses.Подписание` с тремя точками маршрута (Подписать / ОбеспечитьПодписание / ОбработатьРезультат), гибкими этапами и участниками (Сотрудники или Роли). Поддерживаются три типа подписи: **на бумаге**, **ПЭП** (простая) и **УЭП** (усиленная с криптографией), с полной поддержкой форматов CAdES (BES, T, C, XL, A). Данные ЭП хранятся в регистрах сведений **`ЭлектронныеПодписи`** (усиленные) и **`ПростыеЭлектронныеПодписи`** (простые), а сертификаты — в справочнике **`СертификатыКлючейЭлектроннойПодписиИШифрования`**. После подписания реквизиты справочника **`ДокументыПредприятия`** обновляются: `Подписал`, `ДатаПодписания`, `ПодписанЭП`, а в ТЧ `Стороны` по каждой организации фиксируется флаг `Подписан`. Итоговый результат процесса (`Подписано` / `НеПодписано`) записывается в реквизит `РезультатПодписания` самого БП. Ключевая логика сосредоточена в модулях: `ЭлектроннаяПодпись`, `РаботаСВнешнимПодписанием`, `ЭлектроннаяПодписьДокументооборот*`, ObjectModule и ManagerModule БП Подписание, ManagerModule справочника ДействияПодписания.
