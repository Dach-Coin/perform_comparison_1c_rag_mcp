# Права доступа к задачам в 1С:Документооборот КОРП 3.0
**Конфигурация:** ДокументооборотКОРП v3.0.14.31  
**Дата анализа:** 2026-06-05  
**Источник данных:** MCP-сервер rlm-tools-bsl v1.17.0, проект «Тест ДО3»

## 1. Роли, определяющие доступ к документу «Задача»

В конфигурации выявлено **11 ролей**, дающих права на документ `Documents.Задача`:

| Роль | Тип доступа | Примечание |
|------|-------------|------------|
| **РаботаСЗадачами** | Полный CRUD + история | Основная рабочая роль. Содержит RLS. |
| **КонтрольЗадачИБизнесПроцессов** | Полный набор + история данных | Для контролёров. Содержит RLS через бизнес-процессы. |
| **РаботаСЗадачамиИБизнесПроцессами** | Read, Insert, Update, View, Edit, Execute | Работа с задачами через процессы |
| **ИзменениеВыполнениеЗадач** | Read, Update, View, Edit, Execute | Без Insert/Delete |
| **УправлениеБизнесПроцессами** | Read, Insert, Update, View, Edit, Execute | Для управляющих процессами |
| **ЧтениеЗадач** | Read, View, InputByString | Только чтение. RLS: `#ЧтениеПроцесса("БизнесПроцесс")` |
| **ЧтениеПроцессовИЗадачБезОграничения** | Read, View | **Без ограничений доступа** (см. имя роли). RLS только на файлы задач. |
| **РаботаСПротоколомРаботыСотрудников** | View | Только просмотр |
| **РаботаСЗадачамиСотрудниковПодразделения** | (см. ниже) | Для руководителей подразделений |
| **тст_ПросмотрНовыхОбъектов** | View | Кастомная роль (префикс тст) |
| **тст_РаботаСДоверенностями** | Read | Кастомная роль |

### Профили групп доступа
Роли объединяются в профили через `УправлениеДоступомПереопределяемый.ПриЗаполненииПоставляемыхПрофилейГруппДоступа()`:
- **Пользователи** (основной профиль): включает `РаботаСЗадачами`
- **Руководители подразделений** (ID `a35aa932-db5a-11de-a544-00179ab398dc`): включает `РаботаСЗадачамиСотрудниковПодразделения`

## 2. Может ли сотрудник видеть задачи других сотрудников?

**Ответ: В общем случае — нет, только свои. Но есть исключения.**

Доступ к задачам строго ограничен через механизм **рабочих групп** и **дескрипторов доступа**:

### Кто видит задачу по умолчанию
Сотрудник видит задачу, если он является **участником рабочей группы** этой задачи. Рабочая группа формируется автоматически при записи задачи из следующих реквизитов:
- **Создал** — автор задачи
- **Ответственный** — назначенный исполнитель
- **Проект** — руководитель проекта (и все участники, если у проекта установлен флаг `ПраваНаДокументыВсемУчастникам`)
- **ТЧ Участники** — явно добавленные участники

### Кто видит задачи других
1. **Руководители подразделений** — роль `РаботаСЗадачамиСотрудниковПодразделения` даёт доступ к задачам сотрудников подразделения без RLS-ограничений по рабочей группе
2. **Замещающие** — в RLS-условии на право Update явно проверяется таблица `ЗамещающиеИПомощники`. Замещающий автора задачи получает право редактирования
3. **Полноправные пользователи** (роль с флагом `ЭтоПолноправныйПользовательИБ`) — функция `ПраваПользователяПоОбъекту` возвращает все права без обращения к дескрипторам
4. **Пользователи с ролью `ЧтениеПроцессовИЗадачБезОграничения`** — чтение задач без ограничения по рабочей группе

### Конкретные команды интерфейса
Набор команд документа «Задача» это подтверждает:
- `ЗадачиМне` — задачи только текущего пользователя
- `ЗадачиПодчиненных` / `ЗадачиПодчиненныхПросроченные` / `ЗадачиПодчиненныхНеНачатые` — для руководителей
- `ВсеЗадачи` — доступна только при наличии роли без RLS-ограничения

## 3. Ограничения на уровне записей (RLS) для задач

В конфигурации реализован **многоуровневый механизм RLS** через дескрипторы. Это **не стандартный 1С RLS** (не через параметры сеанса), а собственный механизм Документооборота.

### RLS шаблоны в роли РаботаСЗадачами

| Право | RLS-шаблон |
|-------|-----------|
| Read (чтение) | `#ПоДескрипторуОбъекта("", "Задача", "", "")` |
| Update (изменение) | `#ПоДескрипторуОбъекта("Изменение", "Задача", "", "")` |

Шаблон `#ПоДескрипторуОбъекта` разворачивается в SQL-запрос (фактически — это псевдокод для генерации RLS):

```sql
#Если &ДокументооборотИспользоватьОграниченияПравДоступа #Тогда
ТекущаяТаблица ИЗ #ТекущаяТаблица КАК ТекущаяТаблица
ГДЕ ИСТИНА В (
  -- Вариант 1: через дескрипторы рабочей группы
  ВЫБРАТЬ ПЕРВЫЕ 1 ИСТИНА ИЗ
    РегистрСведений.ДескрипторыДляОбъектов
    ВНУТРЕННЕЕ СОЕДИНЕНИЕ РегистрСведений.ПраваПоДескрипторамДоступаОбъектов
      ПО ДескрипторыДляОбъектов.Дескриптор = ПраваПоДескрипторамДоступаОбъектов.Дескриптор
  ГДЕ ДескрипторыДляОбъектов.Объект = ТекущаяТаблица.Ссылка
    И ПраваПоДескрипторамДоступаОбъектов.Сотрудник В (&СотрудникиПользователя)
  
  ОБЪЕДИНИТЬ ВСЕ
  
  -- Вариант 2: замещающий автора может редактировать
  ВЫБРАТЬ ПЕРВЫЕ 1 ИСТИНА ИЗ
    РегистрСведений.СотрудникиВКонтейнерах
    ВНУТРЕННЕЕ СОЕДИНЕНИЕ Справочник.ЗамещающиеИПомощники
      ПО СотрудникиВКонтейнерах.Сотрудник = ЗамещающиеИПомощники.Сотрудник
    ВНУТРЕННЕЕ СОЕДИНЕНИЕ Справочник.ЗамещающиеИПомощники.ВопросыЗамещения
  ГДЕ ТекущаяТаблица.Автор = СотрудникиВКонтейнерах.Контейнер
    И ТекущаяТаблица.Источник = НЕОПРЕДЕЛЕНО
    И ТекущаяТаблица.ВышестоящаяЗадача = ЗНАЧЕНИЕ(Документ.Задача.ПустаяСсылка)
    И ВопросыЗамещенияТЧ.Область В (
        ЗНАЧЕНИЕ(Справочник.ОбластиЗамещения.ЗадачиПостановкаПоручений),
        ЗНАЧЕНИЕ(Справочник.ОбластиЗамещения.Задачи),
        ЗНАЧЕНИЕ(Справочник.ОбластиЗамещения.ВсеОбласти))
    И ЗамещающиеИПомощники.Замещающий В (&СотрудникиПользователя))
#КонецЕсли
```

### Включение механизма RLS
RLS активируется константой **`ДокументооборотИспользоватьОграничениеПравДоступа`** (читается через `ДокументооборотПраваДоступаПовтИсп.ВключеноИспользованиеПравДоступа()`). При выключенной константе все пользователи имеют полный доступ.

### Объекты, участвующие в RLS
Документ `Задача` включён в `ОпределяемыйТип.ОбъектДоступа` (48 типов), что делает его участником механизма дескрипторов.

### Дополнительные RLS на вложения
В роли `ЧтениеПроцессовИЗадачБезОграничения` есть отдельные RLS-условия для файлов/версий, привязанных к задачам:
```
ГДЕ Файл.ВладелецФайла ССЫЛКА Документ.Задача
ИЛИ Файл.ВладелецФайла ССЫЛКА Документ.ДействиеЗадачи
ИЛИ Файл.ВладелецФайла ССЫЛКА БизнесПроцесс.Исполнение
```

## 4. Связь рабочих групп с доступом к документам

### Архитектура

Рабочие группы — основной механизм управления доступом в Документообороте КОРП:

```
Документ «Задача»
    ↓ запись
РегистрыСведений.РабочиеГруппы
    [Измерения: Объект(=Задача.Ссылка), Участник]
    [Ресурсы: Изменение(bool), Источник, Автоподстановка]
    ↓ для каждого участника
Справочник.ДескрипторыДоступаОбъектов
    [КонтейнерСотрудников + Изменение → уникальный дескриптор]
    ↓ перерасчёт прав
РегистрСведений.ДескрипторыДляОбъектов
    [Объект → Дескриптор (связь)]
РегистрСведений.ПраваПоДескрипторамДоступаОбъектов
    [Дескриптор + Сотрудник + ОбъектОснование → Добавление/Изменение/Удаление/УправлениеПравами/Чтение]
    ↓ используется в RLS
```

### Как формируется рабочая группа задачи

Подписки на события документа `Задача`:
- **BeforeWrite** → `РаботаСРабочимиГруппами.ДокументыПередЗаписью` — фиксирует изменённые реквизиты `Создал`, `Ответственный`, `Проект`
- **OnWrite** → `РаботаСРабочимиГруппами.ДокументыПриЗаписи` — добавляет новых участников через `ПерезаписатьРабочуюГруппуОбъекта`

Правило заполнения рабочей группы:
- `Создал` → участник с флагом `Изменение=Истина`
- `Ответственный` → участник с флагом `Изменение=Истина`
- `Проект` → руководитель проекта (через `ПроектыКонтейнеры.НайтиСоздатьПроектКонтейнер`); если у проекта `ПраваНаДокументыВсемУчастникам=Истина` — все участники проекта с `Изменение=Ложь`

### Автоматическое расширение рабочей группы
Функция `РасширитьРабочуюГруппуСвязанныхОбъектов` (с флагом `Немедленно`) расширяет рабочие группы связанных объектов. Фоновое задание `ОбработкаОчередиРасширенияРабочихГрупп` обрабатывает очередь отложенных обновлений.

### Обновление прав при изменении рабочей группы
После изменения рабочей группы объекта срабатывают подписки:
- **OnWrite** → `ДокументооборотПраваДоступа.ДокументооборотПраваДоступаПриЗаписиОбъектаДоступа` → вызывает `ОпределитьДескрипторыОбъекта` → в т.ч. `ЗаполнитьДескрипторыОбъектаПоРабочейГруппе` → пересчёт `ПраваПоДескрипторамДоступаОбъектов`

## 5. Общий модуль РаботаСРабочимиГруппами: ответственность и ключевые функции

Модуль `CommonModules/РаботаСРабочимиГруппами/Ext/Module.bsl` — **центральный хаб управления рабочими группами**. 47 экспортных функций.

### Ключевые функции

#### Управление составом рабочей группы
| Функция | Назначение |
|---------|-----------|
| `ПолучитьРабочуюГруппуДокумента(Документ)` | Возвращает таблицу участников РГ из `РабочиеГруппы.ПолучитьУчастниковПоОбъекту` в привилегированном режиме |
| `ПерезаписатьРабочуюГруппуОбъекта(Ссылка, Участники, ОбновитьПрава, ПроверятьПрава)` | Атомарное обновление РГ: сравнивает «было/стало», записывает дельту в РегистрСведений.РабочиеГруппы |
| `ДобавитьУчастниковВРабочуюГруппуОбъекта(Объект, Участники, ОбновитьПрава, ПроверятьПрава)` | Добавляет участников без полной перезаписи |
| `РасширитьРабочуюГруппуСвязанныхОбъектов(Объект, Немедленно)` | Распространяет участников РГ на связанные объекты |

#### Проверка прав
| Функция | Назначение |
|---------|-----------|
| `ПроверитьПраваПередЗаписьюРабочейГруппы(Ссылка, Участники, АвторИзменений, ЕстьНовыеУчастники)` | Проверяет право добавления новых участников (вызывает `ДокументооборотПраваДоступаПовтИсп.ВключеноИспользованиеПравДоступа()`) |
| `ПроверитьПраваУчастниковРабочейГруппыНаОбъект(Ссылка, Участники)` | Проверяет соответствие новых участников настройкам ГруппДоступаКонтрагентов; возвращает текст ошибки или Неопределено |

#### Обработчики событий (экспортные, вызываются из подписок)
| Функция | Событие |
|---------|---------|
| `ДокументыПередЗаписью(Источник, Отказ)` | BeforeWrite документов — определяет изменившиеся реквизиты РГ |
| `ДокументыПриЗаписи(Источник, Отказ)` | OnWrite документов — записывает новых участников в РГ |
| `ДействияПередЗаписью / ДействияПриЗаписи` | Аналогично для объектов типа «Действие» |
| `РабочиеГруппыБизнесПроцессыПередЗаписьюПередЗаписью / ПриЗаписи` | Для бизнес-процессов |

#### Вспомогательные
| Функция | Назначение |
|---------|-----------|
| `ПоОбъектуВедетсяАвтоматическоеЗаполнениеРабочейГруппы(Объект)` | Проверяет, нужно ли автозаполнение РГ для данного объекта |
| `ОбязательноеЗаполнениеРабочихГруппДокументов(ВидДокумента)` | Является ли заполнение РГ обязательным для вида документа |
| `ОбновитьУчастниковРабочейГруппыПоАвтоподстановкам(РабочаяГруппа, Объект)` | Обновляет участников по настроенным автоподстановкам |
| `ОбработкаОчередиРасширенияРабочихГрупп()` | Обрабатывает фоновую очередь расширения РГ |

### Связь с ДокументооборотПраваДоступа
Модуль `РаботаСРабочимиГруппами` не занимается расчётом прав напрямую — он управляет **составом рабочих групп** в регистре `РабочиеГруппы`. Расчёт вычисленных прав делегируется в `ДокументооборотПраваДоступа.ОпределитьДескрипторыОбъекта` → `ЗаполнитьДескрипторыОбъектаПоРабочейГруппе` → пересчёт `ПраваПоДескрипторамДоступаОбъектов`.

## Общий вывод

Система прав доступа к задачам в 1С:Документооборот КОРП 3.0 реализована через **собственный программно-RLS механизм** на основе дескрипторов:

1. **Видимость задачи** определяется регистром `РабочиеГруппы` — сотрудник видит только те задачи, где он является участником рабочей группы (автор, ответственный, участник ТЧ, участник проекта)

2. **RLS активируется** константой `ДокументооборотИспользоватьОграничениеПравДоступа`. При выключенной константе система работает без ограничений.

3. **Исключения — видят чужие задачи:**
   - Руководители подразделений (профиль «Руководители подразделений», роль `РаботаСЗадачамиСотрудниковПодразделения`)
   - Замещающие (через `ЗамещающиеИПомощники`, прямо в SQL-условии RLS)
   - Полноправные пользователи (`ЭтоПолноправныйПользовательИБ`)
   - Пользователи с ролью `ЧтениеПроцессовИЗадачБезОграничения`

4. **Технически RLS** реализован в XML-файлах ролей через шаблон `#ПоДескрипторуОбъекта`, который разворачивается в JOIN-запрос к регистрам `ДескрипторыДляОбъектов` + `ПраваПоДескрипторамДоступаОбъектов`

5. **Рабочая группа** задачи автоматически формируется и обновляется при каждой записи документа через подписки на события, управляемые модулем `РаботаСРабочимиГруппами`
