## 1. Реквизиты справочника Сотрудники

Справочник расположен в ветке `Catalogs/Сотрудники`. Содержит **9 реквизитов**:

| Имя реквизита | Синоним | Тип |
|---|---|---|
| `ГрафикРаботы` | График работы | `CatalogRef.ГрафикиРаботы` |
| `ДатаНачалаДействия` | Дата начала действия | `DateTime` |
| `ДатаОкончанияДействия` | Дата окончания действия | `DateTime` |
| `Действует` | Действует | `Boolean` |
| `Должность` | Должность | `CatalogRef.Должности` |
| `Подразделение` | Подразделение | `CatalogRef.СтруктураПредприятия` |
| `Помещение` | Помещение | `CatalogRef.ТерриторииИПомещения` |
| `ПредставлениеВДокументах` | Представление в документах | `String` |
| `ПредставлениеВПереписке` | Представление в переписке | `String` |

**Важные особенности:**
- Стандартный реквизит **Наименование** заполняется автоматически из `Строка(Владелец)` — то есть ФИО берётся из владельца-физического лица (см. раздел 3)
- Флаг `Действует` в связке с `ДатаНачалаДействия` / `ДатаОкончанияДействия` определяет, является ли запись сотрудника актуальной
- `ПредставлениеВДокументах` и `ПредставлениеВПереписке` — управляемые строки для отображения ФИО в разных контекстах; автоматически синхронизируются с Наименованием при изменении

## 3. Связи с ФизическиеЛица, Должности, СтруктураПредприятия

### 3.1. ФизическиеЛица — связь типа Владелец (Owner)
Это **ключевая архитектурная особенность**: справочник Сотрудники является **подчинённым** (subordinate) справочнику `ФизическиеЛица`. Это означает:
- Каждый сотрудник обязательно принадлежит конкретному физическому лицу (реквизит `Владелец` типа `CatalogRef.ФизическиеЛица`)
- Наименование сотрудника автоматически совпадает с представлением физического лица (`Наименование = Строка(Владелец)`)
- Одно физическое лицо может иметь **несколько сотрудников** в разных периодах (ротация должностей, совместительство)

Дополнительно для поиска актуального сотрудника по физическому лицу используется **регистр сведений `ОсновныеСотрудники`** (измерение: `ФизическоеЛицо → CatalogRef.ФизическиеЛица`; ресурс: `Сотрудник → CatalogRef.Сотрудники`).

Справочник `ФизическиеЛица` содержит базовые персональные данные:
- `ДатаРождения`, `Пол` (`EnumRef.ПолФизическогоЛица`), `ИНН`, `СтраховойНомерПФР` (СНИЛС)
- `ГруппаДоступа` → `CatalogRef.ГруппыДоступаФизическихЛиц`
- `ФайлФотографии` (`ValueStorage`)

### 3.2. Должности — связь через реквизит Должность
Реквизит `Должность` справочника Сотрудники имеет тип `CatalogRef.Должности`. Сам справочник Должности содержит лишь 1 дополнительный реквизит:
- `тст_ТиповаяПечатнаяФорма` → `CatalogRef.тст_ТиповыеФормыПечатныхДокументов` (кастомизация Тест)

Таким образом, справочник Должности содержит только наименование должности и, в конфигурации Тест, ссылку на типовую печатную форму.

### 3.3. СтруктураПредприятия — связь через реквизит Подразделение
Реквизит `Подразделение` → `CatalogRef.СтруктураПредприятия`. Сам справочник СтруктураПредприятия содержит:
- `ВидПодразделения` → `CatalogRef.ВидыПодразделений`
- `ГрафикРаботы` → `CatalogRef.ГрафикиРаботы`
- `Руководитель` → `CatalogRef.Сотрудники` | `CatalogRef.Пользователи` (**обратная ссылка на Сотрудника!**)
- `Ранг` (`Number`), `УказанОсобыйРанг` (`Boolean`), `Комментарий` (`String`)

## 4. Механизм замещения сотрудников

Механизм замещения реализован через **справочник `ЗамещающиеИПомощники`** и связанную инфраструктуру.

### 4.1. Справочник ЗамещающиеИПомощники
Синоним: «Замещающие и помощники». Содержит **9 реквизитов**:

| Реквизит | Тип | Назначение |
|---|---|---|
| `Сотрудник` | `CatalogRef.Сотрудники` | Замещаемый сотрудник |
| `Замещающий` | `CatalogRef.Сотрудники` | Кто замещает |
| `ВидЗамещения` | `EnumRef.ВидыЗамещения` | Замещающий **или** Помощник |
| `ДатаНачала` | `DateTime` | Начало периода замещения |
| `ДатаОкончания` | `DateTime` | Конец периода |
| `Действует` | `Boolean` | Флаг актуальности |
| `Основание` | `DocumentRef.Отсутствие` | Документ-основание (например, отпуск) |
| `Создал` | `CatalogRef.Сотрудники` | Кто создал запись |
| `Комментарий` | `String` | Произвольный комментарий |

**Табличная часть `ВопросыЗамещения`** (2 колонки):
- `Область` → `CatalogRef.ОбластиЗамещения` — функциональная область (задачи, документы и т.д.)
- `ЗначениеОтбора` — дополнительный фильтр

**Перечисление ВидыЗамещения:** `Замещающие` (полноценное замещение) и `Помощники` (ограниченные права).

### 4.2. Где реализована логика замещения

**Общий модуль `ЗамещающиеИПомощники`** (15 процедур, 14 экспортных) — основной программный интерфейс:
- `АктуальныеЗамещенияСотрудников(СотрудникиМассив, ОбластиЗамещения)` — возвращает таблицу активных замещений; реализован запросом к справочнику с фильтром `Действует=Истина`
- `ОбработкаСроковЗамещающихИПомощников()` — регламентная обработка сроков
- `ПодходящиеЗамещения(...)` — подбор замещающего
- `ОбластиДелегированияПоОбластямЗамещения()`, `ОбластиЗамещенияПоОбластямДелегирования()` — маппинг областей

**Менеджерный модуль справочника** (`ManagerModule.bsl`):
- `АктуальныеЗамещенияСотрудников(...)` — запрос SELECT DISTINCT по справочнику и ТЧ ВопросыЗамещения
- `ВсеЗамещенияПоДействиямЗадач(...)`, `АктуальныеЗамещенияПоДействиямЗадач(...)` — для задач
- `ОбновитьДанныеЗадачПоЗамещению(...)` — пересчёт данных задач при изменении замещения

**Регистры сведений, реализующие делегирование:**
- **`ИсполнителиРолей`** — измерение `НастройкаДелегирования` → `CatalogRef.ЗамещающиеИПомощники` | `UdалитьДелегированиеПрав`
- **`ИсполнителиРолейИДелегаты`** — аналогично, денормализованная таблица делегатов
- **`ВсеИсполнителиДействийЗадач`** — измерение `Основание` → `CatalogRef.ЗамещающиеИПомощники`

**Регистр накопления `КоличествоДействийЗадач`** содержит измерение `Замещающий` → `CatalogRef.Сотрудники` — для учёта задач, выполняемых по замещению.

**Регламентное задание `ОбработкаСроковЗамещающихИПомощников`** (use=True) — автоматически активирует/деактивирует замещения по датам.

**Подписки на события:** при записи/изменении справочника ЗамещающиеИПомощники запускаются подписки `ДокументооборотПередЗаписьюПравообразующихОбъектов` и `ДокументооборотПриЗаписиПравообразующихОбъектов` → модуль `ДокументооборотПраваДоступа`, что обеспечивает **автоматический пересчёт прав доступа** при изменении замещений.

## 5. Регистры, хранящие данные о сотрудниках

### 5.1. Регистры сведений (основные)

| Регистр | Синоним | Назначение |
|---|---|---|
| `ОсновныеСотрудники` | Основные сотрудники | Связь ФизЛицо → актуальный Сотрудник |
| `СотрудникиПользователей` | Сотрудники пользователей | Связь ИБ-пользователь ↔ Сотрудник (для сессии) |
| `СотрудникиВКонтейнерах` | Сотрудники в контейнерах | Принадлежность сотрудника рабочим группам/подразделениям |
| `СотрудникиДляКонтроляСамочувствия` | Контроль самочувствия | Сотрудники для мониторинга состояния здоровья |
| `ИсполнителиРолей` | Исполнители ролей | Назначение сотрудника на роль адресации задач; с поддержкой делегирования |
| `ИсполнителиРолейИДелегаты` | Исполнители ролей и делегаты | Денормализованная таблица с делегатами (на основе ЗамещающиеИПомощники) |
| `ВсеИсполнителиДействийЗадач` | Все исполнители действий задач | Плоский список исполнителей + делегатов для конкретных действий задач |
| `ОтветственныеЛицаОрганизаций` | Ответственные лица организаций | Привязка сотрудника к роли ответственного лица организации (тст: ГенДиректор, Доверенность) |
| `НастройкиРабочегоКалендаряСотрудника` | Настройки рабочего календаря | (помечен «будет удалён») Индивидуальные настройки расписания |
| `ДоступноеВремяСотрудников` | Доступное время | (помечен «будет удалён») Временные слоты доступности |
| `ЗанятостьСотрудников` | Занятость сотрудников | (помечен «будет удалён») Периоды занятости; `EnumRef.СостоянияЗанятости` |
| `ДанныеSAPСотрудники` | Данные SAP (сотрудники) | Интеграционные данные из SAP: ФИО, ИНН, ПФР, должность, подразделение по табельному номеру |

### 5.2. Регистр накопления рабочего времени

**`РабочееВремяСотрудников`** — ключевой регистр для учёта трудозатрат:

| Измерение | Тип |
|---|---|
| `Сотрудник` | `CatalogRef.Сотрудники` \| `CatalogRef.Пользователи` |
| `ВидРабот` | `CatalogRef.ВидыРабот` |
| `Источник` | составной (документы, задачи, файлы, мероприятия, проекты) |
| `Проект` | `CatalogRef.Проекты` |
| `ПроектнаяЗадача` | `CatalogRef.ПроектныеЗадачи` |

Ресурсы: `ДлительностьВВыходные`, `ДлительностьВсего`, `ДлительностьРабочая`, `ДлительностьСверхурочно` (все `Number`).

### 5.3. Регистры накопления задач с участием сотрудников

- **`КоличествоДействийЗадач`** — содержит измерение `Замещающий → CatalogRef.Сотрудники`, что позволяет разделить выполненные задачи на «свои» и «по замещению»
- **`КоличествоЗадач`** — агрегированная статистика задач (без прямой ссылки на Сотрудника — адресуется через автора/роль)

### 5.4. Параметры сеанса, связанные с сотрудниками

Модуль сеанса (через `СотрудникиСобытия`) при старте сессии устанавливает:
- `СотрудникиПользователя` — ФиксированныйМассив активных сотрудников текущего пользователя
- `ОсновнойСотрудник` — основной сотрудник текущего пользователя
- `РолиТекущегоПользователя` — роли адресации задач для текущего сотрудника

Если у пользователя нет ни одного действительного сотрудника — при входе выбрасывается исключение (кроме профиля «ПолныеПрава» и служебных пользователей).

## Итоговое резюме

Справочник **Сотрудники** в 1С:ДО КОРП 3.0 — это учётная запись сотрудника компании, **подчинённая физическому лицу** (справочнику ФизическиеЛица). ФИО автоматически наследуется из физлица. Должность и подразделение — реквизиты-ссылки на соответствующие справочники. Периоды действия управляются тремя реквизитами (`Действует`, `ДатаНачалаДействия`, `ДатаОкончанияДействия`).

Механизм замещения реализован через справочник **ЗамещающиеИПомощники** (2 вида: Замещающие/Помощники) с ТЧ областей замещения, автоматической активацией по регламентному заданию и немедленным пересчётом прав через подписки на события. Роли задач делегируются через регистры `ИсполнителиРолей` и `ИсполнителиРолейИДелегаты`.

Регистровая инфраструктура: рабочее время — `РабочееВремяСотрудников` (накопления); связка пользователь↔сотрудник — `СотрудникиПользователей`; исполнение ролей — `ИсполнителиРолей`; интеграция SAP — `ДанныеSAPСотрудники`.
