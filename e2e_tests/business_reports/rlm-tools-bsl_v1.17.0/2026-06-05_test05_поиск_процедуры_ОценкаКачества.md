# Оценка качества: TEST-05 — Поиск процедуры по бизнес-описанию
**Сервер:** rlm-tools-bsl (v1.17.0)
**Дата:** 2026-06-05
**Оценщик:** Оркестратор (Claude Opus 4.8, 1M context)

## Общая оценка: ПОЛНОСТЬЮ

Искомая процедура найдена: `ОпределитьФактическихИсполнителей` в `CommonModules/РаботаСЗадачами/Ext/Module.bsl` (стр. 24–251), прочитан полный код, найдены все 6 вызывающих + построено дерево вызовов глубиной 2. Ответ полный — но путь к цели длиннее, чем у bsl: процедура найдена на 9-м вызове (5-м `rlm_execute`), а не сразу.

## Что сервер дал хорошо
- **Полный код целевой процедуры** (#10): 228 строк, логика трёх уровней (сотрудник → роль `ПолныеРоли` → замещение `ЗамещающиеИПомощники`).
- **Глубокое дерево вызовов** (#15, `find_call_hierarchy` depth=2) — преимущество над bsl: показал не только 6 прямых вызывающих, но и второй уровень: `ПриСозданииНаСервере`(форма) → `ВзятьВРаботу` → целевая; `ОбработатьВзятиеВРаботу` → `ПринятьКИсполнению` → целевая.
- **Контекст вызовов с разбором** (#12–14): `find_callers_context` дал все 6 вызывающих с именами, модулями и строками; прочитан код ключевых обёрток (`ПринятьКИсполнению`, `ЗаполнитьФактическогоИсполнителя`).
- **Ровный профиль расхода**: ни одного скачка >20% (максимум — #10 read_procedure ≈18.6%). Нет ⚠️.

## Что сервер НЕ дал
- **Прямого «семантического» попадания**: `search_methods` не поддержал составные запросы (#5 «замещени исполнитель задач» → 0); пришлось искать по одиночным словам, затем перебирать модули через `find_module`/`extract_procedures` (#6–9) до выхода на цель. Эквивалента FTS `search_function` (которым bsl нашёл сразу) у rlm нет.

## Паттерны поведения агента
- Сессионный цикл: `rlm_help`(иерархия вызовов) → `rlm_start` → `search_methods` → `find_module` → `extract_procedures` ×3 → `read_procedure` → `find_callers_context`/`find_call_hierarchy`.
- Два retry: #5 (составной search_methods → 0, перешёл на одиночные слова) и #11 (`find_callers_context` без module_hint вернул total=6/returned=0 — нужен hint).
- Стратегия «от ключевых слов к модулям, затем перебор процедур» — сработала, но потребовала 4 разведочных вызова (#6–9) до цели.
- Расход рос плавно, без ⚠️.

## Выявленные проблемы
| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| `search_methods` не принимает составные запросы | #5 «слова через пробел» → 0; нужен поиск по одиночным токенам |
| `find_callers_context` требует module_hint | #11 без hint: total=6, returned=0 — список пуст без подсказки модуля |
| Длиннее путь к цели, чем у FTS-поиска | 5 рабочих вызовов до процедуры против 1 (search_function) у bsl |

## Вывод
rlm-tools-bsl v1.17.0 закрыл TEST-05 полностью и с ровным профилем (≈89K токенов, без ⚠️), а по глубине ответа даже богаче — единственный из двух построил **дерево вызовов на 2 уровня** (`find_call_hierarchy`). Но по скорости выхода на цель проиграл: отсутствие FTS-поиска по функциям заставило перебирать модули и процедуры (9 вызовов до цели против 3 у bsl), и суммарный контекст вышел в 1.5× больше. Вывод по тесту: на «найти процедуру по описанию» лексический FTS bsl эффективнее для самого попадания, а rlm сильнее для последующего анализа иерархии вызовов.
