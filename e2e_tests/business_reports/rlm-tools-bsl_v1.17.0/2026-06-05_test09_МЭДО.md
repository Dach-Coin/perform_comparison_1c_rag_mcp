## 3. Процесс обмена через МЭДО

### 3.1. Транспортный механизм

МЭДО в данной конфигурации работает через **файловую интеграцию** — обмен ZIP-архивами через каталоги на файловой системе или FTP-сервер. Никаких специализированных HTTP или SOAP сервисов именно для МЭДО в конфигурации нет.

**Поддерживаемые способы обмена** (из перечисления СпособыОбменаМЭДО):
- `Диск/локальная сеть` — каталоги КаталогОтправки и КаталогПолучения
- `FTP` — каталоги КаталогОтправкиFTP и КаталогПолученияFTP

**Версии протокола** (из перечисления ВерсииФорматаМЭДО): `2.5`, `2.7`, `2.7.1`

> Транспортный контейнер версий 2.7 и 2.7.1 поддерживается полностью. Версия 2.5 поддерживается для совместимости (обработка входящих документов без транспортного контейнера).

### 3.2. Структура исходящего пакета

При отправке документа формируется ZIP-архив (транспортный контейнер), содержащий:
1. **passport.xml** — паспорт контейнера (XDTO-объект типа container)
2. **Файл документа** (обычно PDF) — основной файл
3. **Регистрационный штамп** (PNG) — изображение штампа ДО
4. **Файлы подписей** (p7s) — для каждой ЭП
5. **Отметки подписей** (PNG) — визуализация ЭП
6. **Приложения** (при наличии) — прикреплённые файлы

### 3.3. Структура входящего пакета

Входящие ЭСД ожидаются в каталоге получения в виде:
- **ZIP-архивов** (*.zip) — основной формат
- **Папок** с файлами — приводятся к ZIP автоматически

Каждый ZIP содержит файл конверта **envelope.ini** или **envelope.ltr** (кодировка ANSI, секция `[АДРЕСАТЫ]`), из которого извлекается адрес МЭДО отправителя. После обработки ZIP перемещается в:
- `processed/` — при успехе
- `errors/` — при ошибке

### 3.4. Цикл обмена — ВыполнитьОбменМЭДО

Процедура `МЭДО.ВыполнитьОбменМЭДО()` запускается регламентным заданием и выполняет следующие шаги **для каждой организации** из регистра НастройкиОрганизацийМЭДО:

```
1. Проверить критически важные поля настроек организации
2. ПолучитьВходящиеСообщения(Настройки)
   → Сканировать каталог получения
   → Для каждого ZIP: распаковать → прочитать envelope.ini
   → Определить тип содержимого (Транспортный контейнер / Документ / Уведомление / Квитанция)
   → ОбработатьВходящееЭСД(...)
      → ОбработатьВходящийТранспортныйКонтейнер (версии 2.7/2.7.1)
         → разобрать passport.xml через XDTO
         → по типу: ОбработатьВходящийДокумент22_25 | ОбработатьВходящееУведомление | ОбработатьВходящуюКвитанцию
   → ZIP → processed/ или errors/
3. ОтправитьИсходящиеКвитанции(Настройки, ...)
   → Найти квитанции с ГотоваКОтправке = Истина
   → Упаковать и записать в КаталогОтправки
4. ОтправитьИсходящиеДокументы(Настройки, ...)
   → Найти ДанныеДокументаМЭДО с ГотовКОтправке = Истина
   → Для каждого документа: ОтправитьИсходящийДокумент(...)
      → Разбить по версиям МЭДО получателей (из НастройкиКонтрагентовМЭДО)
      → ЗаписатьСодержимоеКонтейнераИсходящегоДокумента (passport.xml + PDF + PNG + p7s)
      → ЗаписатьСообщениеПоИсходящемуДокументу → в КаталогОтправки
5. ОтправитьИсходящиеУведомления(Настройки, ...)
   → Найти УведомленияМЭДО с ГотовоКОтправке = Истина
   → Аналогично упаковать и записать в каталог
6. ОчиститьСтарыеЗаписиЖурнала(...)
```

### 3.5. Модули, задействованные в отправке

### 3.6. Обработка входящих уведомлений

`ОбработатьВходящееУведомление(communication, ...)`:
1. Из XDTO: `communication.notification.uid` — ID документа
2. Поиск документа в ИБ через `МЭДОПереопределяемый.ПолучитьДокументПоИдентификатору`
3. Разбор типа уведомления: `notification.type` → ТипыУведомленийМЭДО
4. Проверка через регистр СостоянияДокументовМЭДО (ДокументОтправлен)
5. Вызов `МЭДОПереопределяемый.ТребуемыеДанныеИсходящегоДокумента` для записи результата

### 3.7. Обработка входящих квитанций

`ОбработатьВходящуюКвитанцию(communication, ...)`:
1. Из XDTO: `communication.acknowledgment.uid` — ID исходящего сообщения
2. Поиск предмета по ИД в РегистреСведений.СостоянияДокументовМЭДО (ОБЪЕДИНИТЬ ВСЕ: исходящий документ + исходящее уведомление)
3. Запись нового состояния: «Получена квитанция» или «Получена квитанция об ошибке»

## 4. HTTP-сервисы и веб-сервисы

### 4.1. Специализированных МЭДО-сервисов нет

В конфигурации нет HTTP-сервисов или SOAP-сервисов, предназначенных специально для МЭДО. Интеграция построена на файловом обмене.

### 4.3. SOAP веб-сервисы конфигурации (19 штук)

Из 19 SOAP-сервисов наиболее близкий к МЭДО-тематике:

**DMMessageService** (ns: http://www.1c.ru/dmmessage) — сервис обмена сообщениями с интегрированными системами ДО:
- `get(externalSystemID)` → DMMessage — извлечь следующее сообщение из очереди
- `put(message, externalSystemID)` → DMResponse — поместить сообщение в очередь

> Этот сервис работает с планом обмена ИнтегрированныеСистемы и регистром сведений ОчередьСообщенийВИнтегрированныеСистемы. Он предназначен для интеграции ДО с внешними системами в целом, а не специфически для МЭДО. МЭДО взаимодействует с ним косвенно.

Остальные SOAP-сервисы (Exchange_*, EnterpriseData*, Files, InterfaceVersion и др.) относятся к синхронизации данных и мобильному приложению — не связаны с МЭДО.

## 9. Подписки на события

Конфигурация содержит **одну специализированную МЭДО-подписку**:

| Подписка | Событие | Обработчик |
|----------|---------|------------|
| СинхронизироватьДанныеДокументаМЭДОПриЗаписи | OnWrite | CommonModule.МЭДО.СинхронизироватьДанныеДокументаМЭДОПриЗаписи |

Обработчик синхронизирует пометку удаления между документом-владельцем и связанным документом ДанныеДокументаМЭДО. Если вид документа изменился и документ перестал быть МЭДО-документом — вспомогательный документ помечается на удаление.
