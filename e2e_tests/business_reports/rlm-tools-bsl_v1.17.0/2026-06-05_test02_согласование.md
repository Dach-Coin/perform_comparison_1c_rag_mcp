## 1. Параметры, настраиваемые при запуске согласования

Параметры запуска описаны в функции `СтруктураДанныхДляЗаполнения()` объектного модуля бизнес-процесса (`BusinessProcesses/Согласование/Ext/ObjectModule.bsl`, строка 37) и соответствуют реквизитам объекта БП.

### Исполнители (Лист согласования)
Табличная часть **`Исполнители`** (синоним «Лист согласования») содержит следующие колонки:
- `Исполнитель` — сотрудник или роль исполнителя
- `ИдентификаторИсполнителя` — UUID для однозначной идентификации
- `ПорядковыйНомер / ПорядокСогласования` — порядок обхода
- `ЗадачаИсполнителя` — ссылка на созданную задачу
- `Пройден` — признак того, что исполнитель завершил работу
- `СрокИсполнения` / `СрокИсполненияДни` / `СрокИсполненияЧасы` / `СрокИсполненияМинуты` — срок по задаче
- `ВариантУстановкиСрокаИсполнения` — перечисление `ВариантыУстановкиСрокаИсполнения`:
  - `ОтносительныйСрок` — относительный срок (дни/часы/минуты от старта)
  - `ТочныйСрок` — конкретная дата/время

### Вариант согласования
Реквизит **`ВариантСогласования`** типа `EnumRef.ВариантыМаршрутизацииЗадач`:
| Значение | Синоним |
|---|---|
| `Последовательно` | По очереди |
| `Параллельно` | Всем сразу |
| `Смешанно` | Смешанно |

### Сроки процесса и обработки результатов
- **`СрокИсполненияПроцесса`** — общий срок выполнения согласования
- **`СрокОбработкиРезультатов`** / `СрокОбработкиРезультатовДни` / `...Часы` / `...Минуты` — срок для обработки итогов автором
- **`ВариантУстановкиСрокаОбработкиРезультатов`** — `ОтносительныйСрок` или `ТочныйСрок`

### Прочие параметры запуска
- **`Автор`** — инициатор согласования (CatalogRef.Сотрудники или CatalogRef.Пользователи)
- **`ОбрабатывающийРезультат`** — сотрудник или роль, которая обрабатывает итог
- **`Шаблон`** — ссылка на CatalogRef.ШаблоныСогласования (заполнение через `ЗаполнитьПоШаблону`)
- **`Наименование`** / **`Описание`** — текстовые реквизиты
- **`Важность`** — `EnumRef.ВариантыВажностиОбъектов` (Высокая / Обычная / Низкая)
- **`ПодписыватьЭП`** — признак подписания электронной подписью (виден при включённой опции `ИспользоватьВизыСогласования`)
- **`КоличествоИтераций`** — допустимое количество повторных итераций
- **`ТрудозатратыПланИсполнителя`** / **`ТрудозатратыПланОбрабатывающегоРезультат`** — плановые трудозатраты
- **`Предметы`** — ТЧ с объектами согласования (документами/файлами)

## 2. ВизыСогласования — что это и как связано с процессом

### Что такое ВизыСогласования
**Справочник `ВизыСогласования`** (`Catalogs/ВизыСогласования`) — это персистентная запись факта согласования конкретного документа конкретным исполнителем. Визы являются «следом» процесса, который хранится на уровне документа независимо от жизненного цикла бизнес-процесса.

### Ключевые атрибуты справочника
| Реквизит | Тип | Назначение |
|---|---|---|
| `Документ` | CatalogRef.ДокументыПредприятия | Документ, к которому относится виза |
| `Исполнитель` | Сотрудники / ПолныеРоли / Пользователи | Кто согласовывал |
| `Автор` | Сотрудники / Пользователи | Инициатор процесса |
| `РезультатСогласования` | EnumRef.РезультатыСогласования | Итог (Согласовано / Не согласовано / С замечаниями) |
| `Источник` | ДействияСогласования / ЗадачаИсполнителя / **BusinessProcessRef.Согласование** | Связь с БП или задачей |
| `ДатаСоздания` / `ДатаИсполнения` | DateTime | Временные метки |
| `НомерИтерации` | Number | Итерация согласования |
| `Порядок` | Number | Порядок в листе |
| `Подписана` | Boolean | Наличие ЭП |
| `Комментарий` | String | Комментарий согласующего |
| `ПомещенаВИсторию` | Boolean | Архивная виза |
| `Удалена` | Boolean | Мягкое удаление |

### Как визы связываются с процессом
Визы создаются модулем **`РаботаСВизамиСогласования`** (`CommonModules/РаботаСВизамиСогласования/Ext/Module.bsl`) через процедуру `СоздатьВизыПоДействию(Действие, Участники)`:
1. Функция проверяет включённость функциональной опции `ИспользоватьВизыСогласования`
2. Проверяет реквизит `ФормируетВизы` у объекта действия согласования
3. Из участников выбираются только имеющие роль `ФункцииУчастниковСогласования.Согласующий`
4. Для каждого создаётся элемент справочника через внутреннюю `СоздатьВизуУчастника`

Атрибут `Источник` визы ссылается либо на `ДействияСогласования`, либо на `ЗадачаИсполнителя`, либо напрямую на `BusinessProcessRef.Согласование`, обеспечивая трассировку от визы к бизнес-процессу.

При записи визы (`ПередЗаписью`, строка 17 ObjectModule):
- Проверяются права: автор может добавлять, автор+исполнитель могут изменять
- Исполнитель добавляется в рабочую группу документа
- При установке `РезультатСогласования` фиксируются версии файлов в `РС.ВерсииСогласованныхФайлов`

### Управление жизненным циклом виз
Модуль `РаботаСВизамиСогласования` предоставляет 31 экспортную функцию, ключевые из которых:
- `ПолучитьВизыДокумента` / `ПолучитьАктивныеВизыДокумента` — получение виз по документу
- `ОбновитьВизуУчастника` / `ОбновитьВизыУчастниковДействия` — обновление при изменении результата
- `ПоместитьВизыВИсторию` — архивирование после завершения
- `УдалитьВизу` / `УдалитьВизы` — мягкое удаление
- `ЕстьВизыНаСогласовании` / `ЕстьВизыНеСогласованные` — проверки статуса

## 3. Результаты согласующего

### Перечисление РезультатыСогласования
| Значение | Синоним |
|---|---|
| `Согласовано` | Согласовано |
| `НеСогласовано` | Не согласовано |
| `СогласованоСЗамечаниями` | Согласовано с замечаниями |

### Как результат передаётся в систему
1. Согласующий выполняет задачу точки маршрута `Согласовать` через форму задачи
2. В `ПараметрыВыполнения` передаётся ключ `РезультатСогласования`
3. Процедура `ОбработкаПередВыполнениемЗадачи` (`ManagerModule`, строка 626) перехватывает параметр, блокирует объект БП и помещает результат в `ДополнительныеСвойства.РезультатСогласования`
4. В `ПередЗаписью` ObjectModule (строка 1471) результат фиксируется в строке ТЧ `РезультатыСогласования`, соответствующей данной задаче

### Маппинг на ВариантыВыполненияПроцессовИЗадач (функция РезультатВыполненияЗадачи, ManagerModule стр.2146)
| РезультатыСогласования | ВариантыВыполненияПроцессовИЗадач |
|---|---|
| `Согласовано` | `Положительно` |
| `НеСогласовано` | `Отрицательно` |
| `СогласованоСЗамечаниями` | `ПоложительноСЗамечаниями` |

### Итоговый результат всего процесса (функция ИтоговыйРезультатСогласования, ObjectModule стр.1202)
Логика «пессимистичного» голосования:
1. Начальное значение — `Согласовано`
2. Если хотя бы один участник текущей итерации вернул `НеСогласовано` — результат становится `НеСогласовано`, цикл прерывается
3. Если хотя бы один вернул `СогласованоСЗамечаниями` — результат становится `СогласованоСЗамечаниями` (но поиск `НеСогласовано` продолжается)

## 4. Что происходит при завершении всеми согласующими

### Схема обработки завершения

#### Шаг 1: Выполнение задачи согласующим
Согласующий выполняет задачу. В `СогласоватьПриВыполнении` (ObjectModule, строка 1678) вызывается:
```
ДобавитьЗадачуОтложеннаяОбработкаЗавершенияСогласования()
```

#### Шаг 2: Отложенная обработка завершения
`ДобавитьЗадачуОтложеннаяОбработкаЗавершенияСогласования` (ObjectModule, строка 1864):
- Проверяет, нет ли уже служебной задачи обработки
- Делегирует в `РаботаСПроцессамиПоДействиямСобытия.ОбработатьДобавлениеЗадачиОтложеннаяОбработкаЗавершенияСогласования`
- Если это согласование с замечаниями (`СогласованиеВРежимеЗамечаний`) и все согласовали — передаётся в `ОбработкаОчередиЗаданийСервер`

#### Шаг 3: Проверка завершения обхода
Функция `ОбходСогласующихЗавершен()` (ObjectModule, строка 1240):
- Запрос к `Задача.ЗадачаИсполнителя` — ищет невыполненные задачи процесса
- Если такие есть → возвращает `Ложь` (обход не завершён)
- Если итоговый результат `НеСогласовано` → возвращает `Истина` немедленно
- Иначе → проверяет, что все строки ТЧ `Исполнители` имеют `Пройден = Истина`

#### Шаг 4: Завершение задачи исполнителя в ТЧ
`ОбработатьЗавершениеЗадачиСогласования(Задача)` (ObjectModule, строка 2107):
- Находит строку в ТЧ `Исполнители` по `ЗадачаИсполнителя`
- Устанавливает `Пройден = Истина`
- Вызывает `РаботаСБизнесПроцессами.ЗаписатьПроцесс(ЭтотОбъект, "ПростаяЗапись")`

#### Шаг 5: Переход к ОбработкаРезультата
Точка маршрута `ОбработкаРезультатаОбработка` (ObjectModule, строка 1711):
- Вызывает `УправлениеМероприятиями.УстановитьСостояниеМероприятияИзБизнесПроцесса`
- Вычисляет итоговый результат через `ИтоговыйРезультатСогласования()`
- Сохраняет результат в реквизит `РезультатСогласования` процесса
- Записывает процесс через `РаботаСБизнесПроцессами.ЗаписатьПроцесс`

#### Шаг 6: Финальное завершение процесса
Обработчик точки маршрута `Завершение.ПриЗавершении` — процедура `ЗавершениеПриЗавершении` (ObjectModule, строка 1761):
- `ДатаЗавершения = ТекущаяДатаСеанса()`
- `РаботаСПроектами.ОтметитьОкончаниеВыполненияПроектнойЗадачи(ЭтотОбъект)` — закрывает проектную задачу
- `РаботаСПроцессамиПоДействиямСобытия.ПриЗавершенииПроцесса(ЭтотОбъект)` — уведомляет связанное действие

#### Шаг 7: Обновление результата действия
`ПриЗавершенииПроцесса` (`РаботаСПроцессамиПоДействиямСобытия`, строка 1005):
- Получает связанное `Действие` через `РС.ПроцессыДействий.ДействиеПоПроцессу`
- Проверяет, нет ли других активных процессов этого действия
- Вызывает `МенеджерДействия.ОбновитьРезультатВыполнения(Действие)`

#### Шаг 8: Запись в регистр результатов
`ОбновитьРезультатВыполненияЗадачи` (`РаботаСБизнесПроцессами`, строка 16):
- Через транзакцию с блокировкой записывает результат в `РС.РезультатыВыполненияПроцессовИЗадач`

### Условие успешного завершения (ManagerModule)
Функция `ПроцессЗавершилсяУдачно` (строка 1879): процесс завершён (`Завершен = Истина`) **И** результат — `Согласовано` **ИЛИ** `СогласованоСЗамечаниями`.

## Итоговое резюме

Бизнес-процесс «Согласование» в 1С:Документооборот КОРП 3.0 — зрелый и детально проработанный механизм с чётким разделением ответственности: объектный модуль содержит логику маршрутизации, ManagerModule управляет внешними взаимодействиями, а общие модули `РаботаСБизнесПроцессами` и `РаботаСПроцессамиПоДействиямСобытия` обеспечивают инфраструктуру. Визы согласования — это отдельный справочник, хранящий след каждого согласования на уровне документа, создаваемый опционально при включённой опции `ИспользоватьВизыСогласования`. Завершение процесса реализовано через отложенные служебные задачи платформы, что обеспечивает атомарность и параллелизм при одновременном согласовании несколькими исполнителями.
