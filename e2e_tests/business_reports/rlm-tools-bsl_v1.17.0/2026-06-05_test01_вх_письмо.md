### Особенность создания **[MCP]**
В `ПриСозданииНаСервере` формы документа стоит **явный запрет ручного создания**:
```bsl
// Запрет создания новых
Если Не ЗначениеЗаполнено(Объект.Ссылка) Тогда
    Отказ = Истина;
    Возврат;
КонецЕсли;
```
Письмо создаётся **только автоматически** при получении почты через учётную запись (`УчетнаяЗапись`).

При создании через `ПередЗаписью`:
- Определяется `НомерСпособаАдресации` через `ВстроеннаяПочтаСервер.ПолучитьСпособАдресацииОбъекта`
- Применяются правила из `Справочник.ПравилаОбработкиПисем` — автоматическая раскладка по папкам, присвоение предмета и т.п.
- Проверяется обязательность заполнения `Папка` (иначе `Отказ = Истина`)

## 2. Бизнес-процессы по входящему письму

### Список бизнес-процессов, поддерживающих ВходящееПисьмо как предмет **[MCP — XML-метаданные]**

Из XML-описаний бизнес-процессов подтверждено:

| Бизнес-процесс | Ключевые реквизиты | Назначение |
|---------------|-------------------|-----------|
| **Рассмотрение** | Исполнитель, Резолюция, ВариантРассмотрения, КонтролерИсполнения, Шаблон (ШаблоныРассмотрения) | Руководитель рассматривает письмо, выносит резолюцию |
| **Исполнение** | Исполнитель (ТЧ Исполнители), Контролер, Проверяющий, Шаблон (ШаблоныИсполнения) | Поручение исполнителям по письму |
| **Согласование** | ВариантСогласования, РезультатСогласования, ОбрабатывающийРезультат, ПодписыватьЭП | Согласование документа/письма |
| **Ознакомление** | Исполнители (ТЧ), ВариантИсполнения, Шаблон (ШаблоныОзнакомления) | Ознакомление сотрудников с письмом |
| **Подписание** | Аналогично Согласованию, поддерживает ЭП | Подписание |
| **Утверждение** | Утверждающий, РезультатУтверждения | Утверждение |

Бизнес-процесс **Регистрация** в XML не содержит ВходящееПисьмо как явный допустимый предмет, но структура имеет реквизиты `ПовторитьРегистрацию`, `РезультатРегистрации`, `Шаблон (ШаблоныРегистрации)`, `Исполнитель` — **[предположение]** применяется к ДокументыПредприятия, созданному из письма.

### Механизм запуска БП **[MCP]**
Запуск инициируется из UI через `CommonModule.РаботаСПроцессамиПоДействиям`:
- `СоздатьПроцессИсполненияПоДействию`
- `СоздатьПроцессСогласованияПоДействию`
- `СоздатьПроцессРегистрацииПоДействию`
- `СоздатьПроцессУтвержденияПоДействию`
- `СоздатьПроцессПодписанияПоДействию`

Привязка предмета (ВходящегоПисьма) к БП при заполнении: `МультиПредметность.ПередатьПредметыПроцессу(ЭтотОбъект, ДанныеЗаполнения, ...)` в `ОбработкаЗаполнения` ObjectModule БП Рассмотрение **[MCP]**.

## 3. Регистрация входящего письма — нумерация, кто регистрирует

### Природа объекта ВходящееПисьмо **[MCP]**
`Documents/ВходящееПисьмо` — это **почтовое сообщение** (email), а не деловой документ предприятия. У него **нет собственного регистрационного номера**.

Регистрационный номер (нумерация) в системе работает через:
- **Справочник `ДокументыПредприятия`** — деловой документ предприятия
- Нумерация регулируется `CommonModules/НумерацияКлиентСервер` → `ПолучитьПараметрыНумерации`, которая использует реквизиты: `ЧисловойНомер`, `ДатаРегистрации`, `ВидДокумента`, `Организация`, `НоменклатураДел`, `Ответственный` **[MCP]**

### Жизненный цикл регистрации **[предположение с опорой на MCP]**
1. Пользователь получает письмо → оно появляется в `Documents/ВходящееПисьмо` (создаётся автоматически)
2. Пользователь привязывает письмо к деловому документу через реквизит **Предмет** → `CatalogRef.ДокументыПредприятия`
3. Запускается БП **Регистрация** с предметом = `ДокументыПредприятия`
4. Исполнитель (регистратор) назначается через реквизит `Исполнитель` БП Регистрация
5. По завершении БП `РезультатРегистрации` (**[MCP]** — EnumRef.РезультатыРегистрации) фиксируется в документе

### Учёт входящего номера **[MCP]**
Функция `ДелопроизводствоПовтИсп.ЕстьИсходящиеВидыДокументовСУчетомВходящегоНомера()` — поддержка учёта входящего номера в исходящих документах (ответ на письмо).

## 4. Обработчики событий при записи ВходящегоПисьма

### ObjectModule: `Documents/ВходящееПисьмо/Ext/ObjectModule.bsl` **[MCP]**

#### `ПередЗаписью(Отказ, РежимЗаписи, РежимПроведения)` — строки 5–47

Выполняется ДО записи объекта. Основные действия:
1. **Пропуск при обмене данными:** `Если ОбменДанными.Загрузка Тогда Возврат`
2. **Определение нового письма:** `ДополнительныеСвойства.Вставить("ЭтоНовоеПисьмо", Ссылка.Пустая())`
3. **Установка способа адресации** для нового письма: `ВстроеннаяПочтаСервер.ПолучитьСпособАдресацииОбъекта`
4. **Сохранение предыдущей папки и пометки удаления** (для последующего обновления счётчиков)
5. **Пометка вложений при удалении письма:** `РаботаСФайламиВызовСервера.ПометитьНаУдалениеПрисоединенныеФайлы`
6. **Проверка прав при смене папки:** `Пользователи.ЭтоПолноправныйПользователь()`
7. **Применение правил:** `ВстроеннаяПочтаСервер.ПрименитьПравила(ЭтотОбъект)` — автоматические правила входящих
8. **Валидация папки:** `Если Не ЗначениеЗаполнено(Папка) Тогда Отказ = Истина`

#### `ПриЗаписи(Отказ)` — строки 49–107

Выполняется ПОСЛЕ записи объекта. Основные действия:
1. **Пропуск при обмене данными**
2. **Обновление счётчика писем в папке:**
   ```bsl
   РегистрыСведений.КоличествоПисемВПапках.ОчиститьЗаписиПоПапке(ПредыдущаяПапка);
   РегистрыСведений.КоличествоПисемВПапках.ОчиститьЗаписиПоПапке(Папка);
   ```
   (при смене папки или изменении пометки удаления)
3. **Протоколирование пометки удаления:**
   `ПротоколированиеРаботыСотрудников.ЗаписатьПометкуУдаления(Ссылка, ПометкаУдаления)`
4. **Расширение рабочей группы предмета** (если по предмету ведётся автоматическое заполнение):
   - Запрос к `РегистрСведений.СведенияОбАдресатах` — определение контактов из адресатов
   - `РаботаСРабочимиГруппами.ДобавитьУчастникаВТаблицуНабора` — добавление сотрудников в рабочую группу
   - `РаботаСРабочимиГруппами.ПерезаписатьРабочуюГруппуОбъекта`

## Итоговая схема жизненного цикла

```
[Почтовый сервер]
        ↓ (автоматическое получение почты)
[Documents/ВходящееПисьмо] ← создание ТОЛЬКО автоматически
        |
        ├─ ПередЗаписью: определение способа адресации, применение правил,
        |                 сохранение предыдущей папки, проверка прав
        ├─ ПриЗаписи:    обновление КоличествоПисемВПапках,
        |                 расширение рабочей группы (через СведенияОбАдресатах),
        |                 протоколирование
        |
        ├─ Пользователь устанавливает реквизит [Предмет] → CatalogRef.ДокументыПредприятия
        |
        └─ Запуск бизнес-процессов (по кнопкам формы):
               ├─ Рассмотрение → Резолюция, Исполнение
               ├─ Исполнение   → Поручения исполнителям
               ├─ Согласование → Согласующие, РезультатСогласования
               ├─ Ознакомление → Ознакомление сотрудников
               ├─ Подписание   → Подпись ЭП
               ├─ Утверждение  → Утверждение документа
               └─ КомплексныйПроцесс → Цепочка процессов

[CatalogRef.ДокументыПредприятия]
        └─ БП Регистрация → нумерация (ЧисловойНомер, ДатаРегистрации, ВидДокумента)
                            Исполнитель = регистратор
                            РезультатРегистрации ∈ EnumRef.РезультатыРегистрации
```

## Примечания к полноте анализа

- Нумерация ВходящегоПисьма как почтового документа **отсутствует** — это задача ДокументыПредприятия **[MCP-подтверждено]**
- Код запуска БП из интерфейса (кнопки форм) не трассировался — инициатор вне ObjectModule **[предположение]**
- 86 глобальных подписок применяются ко многим типам объектов; не все из них специфичны именно для ВходящегоПисьма **[MCP + предположение]**
