## Что сервер дал хорошо
- **Структуры объектов одним вызовом**: БП Подписание (34 реквизита + 5 ТЧ), РС `ЭлектронныеПодписи`, 3 справочника подписания (#17), `ДокументыПредприятия` (#33) — без чтения сырого XML.
- **Перечисления напрямую** (`find_enum_values`, #8, #34): `СпособыПодписанияПредметаПроцесса` (НаБумаге/ПЭП/УЭП), `РезультатыПроцессаПодписания`, `ТипыПодписиКриптографии` (CAdES-BES/T/…).
- **Код всех ключевых процедур**: `ЗанестиИнформациюОПодписях` (ПодписанЭП=Истина, Подписал, ДатаПодписания, РезультатПодписания=Подписано), `ОбработкаПередВыполнениемЗадачи`, `ЗаписатьПодписаниеВПредмет`, `ПриЗавершенииПроцесса`.
- **Маршрут и завершение** (#13–14, #29–31): 3 точки (Подписать/ОбеспечитьПодписание/ОбработатьРезультат), завершение по `ВсеЭтапыПодписанияПройдены`.
- **Модули и точки вызова** (#16, #18, #28): `ЭлектроннаяПодпись*` (БСП, 23 модуля), `РаботаСЭП*`, `РаботаСВнешнимПодписанием`; подписки и вызывающие `ДобавитьПодпись`.
- **Кастомизация Тест**: внешнее подписание Диадок (`РаботаСВнешнимПодписанием`, HTTP-сервис, задача 89132).

## Что сервер НЕ дал
- Принципиальных пробелов нет — все 5 подвопросов закрыты прямыми данными, без додумывания.

## Паттерны поведения агента
- Сессионный цикл, полный структурный инструментарий: `get_object_full_structure`, `find_enum_values`, `find_module`/`find_exports`, `read_procedure`, `parse_form`, `find_event_subscriptions`, `find_callers`, `git_search`.
- Один retry (#6→7) — снова ключи `get_object_full_structure` (повтор дефекта). Больше — ни одного шумного вызова за весь прогон.
- Расход ровный: **ни одного скачка >20%** (максимум — #4 rlm_start ≈9.3%). Нет ⚠️.
