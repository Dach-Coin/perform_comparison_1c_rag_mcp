# Оценка качества: TEST-06 — Нумерация и регистрация документов
**Сервер:** rlm-tools-bsl (v1.17.0)
**Дата:** 2026-06-05
**Оценщик:** Оркестратор (Claude Opus 4.8, 1M context)

## Общая оценка: ПОЛНОСТЬЮ

Все 5 подвопросов закрыты прямыми данными: автонумерация (нет при создании, только при регистрации + временные номера), БП `Регистрация` и ядро `Делопроизводство.ЗарегистрироватьПредмет`, регистры `Нумерация`/`НастройкиНумерации`/`ИндексыНумерации`, алгоритм счётчик+шаблон со служебными полями `[ИндексОрг]…[Номер]`, гибкие схемы по видам/организациям. Реконструкция полностью на коде и метаданных.

## Что сервер дал хорошо
- **Структуры 3 регистров одним вызовом** (#9): `Нумерация` (11 измерений + ресурс ТекущийНомер), `НастройкиНумерации` (11 измерений + Нумератор/СпособНумерации), `ИндексыНумерации`. Без чтения сырого XML.
- **Перечисления напрямую** (`find_enum_values`): `Периодичность` (Год/Квартал/Месяц/День/Непериодический), `СпособыНумерации` (Автоматически/Вручную), `НазначенияНумераторов` (РегистрационныйНомер/ВременныйНомер).
- **Полный код алгоритма** (#10, #25): `СформироватьЧисловойНомерДокумента` (атомарный инкремент с блокировкой, флаги `НезависимаяНумерацияПо*`), `РазобратьФорматНомера`, `ПолучитьЗначенияПараметровНомера` (подстановка индексов из РС ИндексыНумерации).
- **18 служебных полей формата** (#11) из `ПолучитьСписокСлужебныхПолей` — точный список меток шаблона.
- **Цепочка регистрации** (#16–18): `ПередЗаписью ДокументыПредприятия` → `Делопроизводство.ЗарегистрироватьПредмет` (право → блокировка → числовой+строковый номер → Зарегистрировал=ОсновнойСотрудник).
- **Где запускается** (#20, `find_callers`): ObjectModule, ИнтеграцияЗадач, форма тст_ЗадачиМне, веб-сервис DMReg.
- **Кастомизация Тест**: `тст_ДлинаЧисловогоНомера`, `тст_НеобходимаРегистрация`, `тст_Номер/тст_Дата`.

## Что сервер НЕ дал
- **Пример реального формата номера** — читался синтаксис шаблона, не строка данных конкретного Нумератора (несущественно).

## Паттерны поведения агента
- Сессионный цикл, полный «структурный» инструментарий: `get_object_full_structure`, `find_module`/`find_exports`, `find_enum_values`, `read_procedure`, `find_event_subscriptions`, `find_callers`, `git_search`.
- Один retry (#6→7) — снова ключи `get_object_full_structure` (attr_name→name по HINT).
- Расход ровный: **ни одного скачка >20%** (максимум — #4 rlm_start ≈10%). Нет ⚠️.

## Выявленные проблемы

## Вывод
rlm-tools-bsl v1.17.0 закрыл TEST-06 полностью при ≈176K токенов, ровно и без ⚠️. Структуры регистров и значения перечислений получены прямыми структурными вызовами (без сырого XML), алгоритм нумерации и цепочка регистрации прочитаны из кода, точки запуска найдены через `find_callers`. Единственная шероховатость — повторяющаяся хрупкость ключей `get_object_full_structure` (1 retry). Тест на стыке «структура + код + поток» — органичная зона силы RLM-подхода.
