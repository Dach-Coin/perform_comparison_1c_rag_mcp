# Оценка качества: TEST-09 — Интеграция с МЭДО

**Сервер:** rlm-tools-bsl (v1.17.0)
**Дата:** 2026-06-05
**Оценщик:** Оркестратор (Claude Opus 4.8, 1M context)

## Общая оценка: ПОЛНОСТЬЮ

Все 5 подвопросов закрыты данными из индекса и кода: **3 документа МЭДО** (ДанныеДокументаМЭДО, КвитанцияМЭДО, УведомлениеМЭДО) с **точной структурой** (реквизиты + ТЧ), полная цепочка отправки (`ВыполнитьОбменМЭДО` → `ПолучитьВходящиеСообщения`/`ОтправитьИсходящиеКвитанции`/`…Документы`/`…Уведомления`), транспорт (ZIP + envelope.ini + passport.xml, каталоги processed/errors, режимы Диск/FTP из РС `НастройкиОрганизацийМЭДО`), отсутствие МЭДО-специфичных HTTP/SOAP-сервисов (подтверждено `find_http_services`/`find_web_services`), единственное регл. задание `ВыполнениеОбменаМЭДО`. 27 вызовов, ≈151K токенов, ровно и без ⚠️.

> **Сверка с исходником (оркестратор):** структуры документов проверены прямым чтением XML — **rlm попал точно**: `УведомлениеМЭДО` = **9 ТЧ** (НаправлениеДоклада, Опубликование, ОтказВРегистрации, ПодготовкаДоклада, ПостановкаНаКонтроль, ПостановкаНаКонтроль_КонтрольныеПунктыДокумента, ПринятиеКИсполнению, Регистрация, ХодИсполнения), `ДанныеДокументаМЭДО` = **1 ТЧ** (Пакеты), `КвитанцияМЭДО` = **0 ТЧ** — совпадает с ответом rlm (17 рекв.+9 ТЧ / 18 рекв.+1 ТЧ / 14 рекв.+0 ТЧ). Документов МЭДО ровно 3 — верно. Регл. задание ровно 1 (`ScheduledJobs/ВыполнениеОбменаМЭДО.xml`) — верно. HTTP-сервисов ровно 9 (ни одного МЭДО) — rlm назвал «9», точно. На фоне bsl, который недосчитал ТЧ `УведомлениеМЭДО` (нашёл 3 из 9), здесь rlm и точнее по структуре, и кратно экономнее.

## Что сервер дал хорошо
- **Точная структура всех 3 документов** (#7, `get_object_full_structure`): УведомлениеМЭДО 17 рекв.+9 ТЧ, ДанныеДокументаМЭДО 18 рекв.+1 ТЧ, КвитанцияМЭДО 14 рекв.+0 ТЧ — **полный инвентарь ТЧ одним структурным вызовом**, подтверждён сверкой с XML.
- **Полный код цепочки обмена** (#9, #10, #16): `ВыполнитьОбменМЭДО` (цикл по `НастройкиОрганизацийМЭДО`), `ПолучитьВходящиеСообщения` (сканирование `КаталогПолучения`, *.zip, processed/errors), `ОтправитьИсходящийДокумент` (формирование пакета: passport.xml + PDF + регштамп PNG + p7s + приложения → ZIP).
- **Механизм транспорта детально** (#12): разбор входящего ЭСД — ZIP → envelope.ini (секция [АДРЕСАТЫ]) → транспортный контейнер → passport.xml → XDTO; версии формата 2.7 / 2.7.1.
- **Оба режима обмена** (#15, #18): Диск и FTP — из структуры РС `НастройкиОрганизацийМЭДО` (`КаталогОтправкиFTP`, `КаталогПолученияFTP`, `СпособОбмена`).
- **Перечисления жизненного цикла** (#11): ВерсииФорматаМЭДО (2.5/2.7/2.7.1), 16 СостоянийДокументов, 8 ТиповУведомлений, СпособыОбмена (Диск/FTP).
- **XDTO-пакеты** (#13, #24): 4 пакета IEDMSMessage/IEDMSContainer для v2.7 и v2.7.1 с пространствами имён (minsvyaz.ru/container, infpres.com/IEDMS).
- **Регл. задание точно** (#13): `ВыполнениеОбменаМЭДО` → `CommonModule.МЭДО.ВыполнитьОбменМЭДО`, предопределённое, 3 перезапуска × 10 сек.
- **Карта сервисов** (#5, #19–20): `find_http_services`/`find_web_services` — нет МЭДО-специфичных; `DMMessageService` корректно атрибутирован как общий механизм интеграции ДО (план обмена ИнтегрированныеСистемы), а **не** МЭДО.

## Что сервер НЕ дал
- **Типы XDTO-пакетов** (поля IEDMSMessage/IEDMSContainer) — в индексе хранятся как ссылки на .xsd, не раскрыты; объекты communication/notification/acknowledgment агент вывел из кода, а не из схемы.
- **Детальные права ролей** `БазовыеПраваМЭДО`/`РаботаСМЭДО` — не в индексе (ожидаемо для ролей).
- **Колонки ТЧ** — состав реквизитов табличных частей детально не разворачивался (имена ТЧ — полностью; колонки — нет).

## Паттерны поведения агента
- Сессионный цикл, профильный рецепт `topic=мэдо` (#2) дал готовый план: find_http_services → find_web_services → find_xdto_packages → find_scheduled_jobs.
- 1 retry (#6→7): `get_object_full_structure` ждал ключи name/synonym/type, агент сначала запросил attr_name — мгновенно исправлено.
- Расход **ровный, ни одного ⚠️** (максимум — #8 экспорты модулей ≈9.8% от итога). 21 из 26 контентных вызовов — высокая релевантность.

## Вывод
rlm-tools-bsl v1.17.0 закрыл TEST-09 полностью при ≈151K токенов, ровно и без ⚠️ — **самый экономный прогон из двух на этом тесте (2.4× дешевле bsl)**. Структурный инструмент `get_object_full_structure` дал **точный полный инвентарь табличных частей** всех трёх документов (9/1/0 ТЧ — подтверждено сверкой с XML), а `read_procedure` развернул реальную цепочку файлового обмена (ZIP/envelope.ini/passport.xml, processed/errors, Диск/FTP). Профильный рецепт `topic=мэдо` сразу задал верный план обхода. Единственный пробел — XDTO-типы (хранятся как .xsd-ссылки вне индекса). Для вопросов «опиши подсистему — документы, структура, процесс, сервисы, задания» сервер показал сильнейший результат серии: точно, дёшево, дисциплинированно.
