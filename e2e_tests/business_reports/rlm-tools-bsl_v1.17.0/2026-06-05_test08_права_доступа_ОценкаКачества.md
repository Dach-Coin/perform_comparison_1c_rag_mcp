# Оценка качества: TEST-08 — Права доступа к задачам
**Сервер:** rlm-tools-bsl (v1.17.0)
**Дата:** 2026-06-05
**Оценщик:** Оркестратор (Claude Opus 4.8, 1M context)

## Общая оценка: ПОЛНОСТЬЮ

Все 5 подвопросов закрыты: 11 ролей на `Document.Задача`, RLS через **дескрипторный механизм** (`#ПоДескрипторуОбъекта` + регистры `ДескрипторыДляОбъектов`/`ПраваПоДескрипторамДоступаОбъектов`), регистр `РабочиеГруппы` (измерение Объект включает Document.Задача), центральный модуль `РаботаСРабочимиГруппами` (47 экспортов). Прочитаны полные SQL-тексты RLS-условий. Анализ заякорен на **буквальном «документе Задача»** (`Document.Задача`).

> **Сверка с исходником (оркестратор):** подтверждено — `#ПоДескрипторуОбъекта("", "Задача", …)` действительно присутствует в `Roles/РаботаСЗадачами/Ext/Rights.xml`, объект `Document.Задача` существует. **Промпт спрашивает именно про «документ Задача» = `Document.Задача`, и rlm зашёл точно на этот объект** (`find_roles('Задача')`, `parse_object_xml('Documents/Задача')`, дескрипторный RLS) — попадание в предмет вопроса. Смежный объект `Task.ЗадачаИсполнителя` (RLS `#ЧтениеПроцесса`) rlm затронул легче (роль `ЧтениеЗадач`, #36) — но это не предмет промпта. Для сравнения: bsl на этом тесте сместился именно на `Task.ЗадачаИсполнителя` и до документа глубоко не дошёл (его оценка — ЧАСТИЧНО).

## Что сервер дал хорошо
- **11 ролей одним вызовом** (`find_roles`, #5) с точными наборами прав (Read/Update/Execute/…).
- **Полный SQL RLS-условий** (#30–33): `#ПоДескрипторуОбъекта("", "Задача", "", "")` (Read), `#ПоДескрипторуОбъекта("Изменение", "Задача", …)` (Update) + инлайн-SQL с JOIN `ДескрипторыДляОбъектов`+`ПраваПоДескрипторамДоступаОбъектов` и веткой замещений (`СотрудникиВКонтейнерах`+`ЗамещающиеИПомощники`).
- **Архитектура дескрипторов** (#24–25): `ЗаполнитьДескрипторыОбъектаПоРабочейГруппе`, структуры регистров дескрипторов, `ОпределяемыйТип.ОбъектДоступа` (48 типов, Document.Задача подтверждён).
- **Регистр `РабочиеГруппы`** (#15): измерение Объект (Document.Задача), Участник; ресурс Изменение. Код заполнения (`ДокументыПередЗаписью`/`ПриЗаписи`, #35).
- **Модуль прав** `ДокументооборотПраваДоступа` (87 экспортов) + `…ПовтИсп` (25); подписки записи (BeforeWrite→ОпределитьДескрипторы, OnWrite→проверка прав, #26–27).
- **Профиль «Руководители подразделений»** (#39–40): роль `РаботаСЗадачамиСотрудниковПодразделения` (без RLS → видимость задач подчинённых).

## Что сервер НЕ дал
- **Глубокий разбор `#ЧтениеПроцесса` для `Task.ЗадачаИсполнителя`** — затронут лишь через роль `ЧтениеЗадач` (#36), без полного SQL участия в процессе (это глубоко разобрал bsl). Для буквального «документа Задача» — не пробел, но для задач-исполнителей покрытие тоньше, чем у bsl.
- **Параметры шаблона `#ПоДескрипторуОбъекта`** — расшифровка аргументов не доведена (самооценка агента).

## Паттерны поведения агента
- Сессионный цикл, профильный «правовой» рецепт: `find_roles` → чтение Rights.xml ролей → `find_defined_types` → `read_procedure` ключевых функций прав → `find_event_subscriptions`.
- 2 retry: #9 (grep по «ОграничениеДоступа» дал 0 — RLS в restrictionByCondition, не в тексте) и #13 (регистр назван `РабочиеГруппы`, не `РабочаяГруппа`). Оба восстановлены.
- Расход ровный: **ни одного скачка >20%** (максимум — #4 rlm_start ≈9.2%). Нет ⚠️.

| Поиск RLS по тексту не сработал | #9 grep «ОграничениеДоступа» → 0; RLS лежит в restrictionByCondition Rights.xml |
| Неоднозначность «Задача» (не дефект) | Верно выбрал `Document.Задача` — предмет промпта (дескрипторы); смежный `Task.ЗадачаИсполнителя` (#ЧтениеПроцесса) разобран тоньше |

## Вывод
rlm-tools-bsl v1.17.0 закрыл TEST-08 полностью при ≈186K токенов, ровно и без ⚠️. Ключевое: **он ответил про объект из промпта** — буквальный `Document.Задача` — дав наиболее глубокий разбор дескрипторного RLS (`#ПоДескрипторуОбъекта` + регистры дескрипторов + полный SQL), механизма рабочих групп и профилей доступа. Сверка с исходником подтвердила корректность. Смежный `Task.ЗадачаИсполнителя` (#ЧтениеПроцесса) покрыт легче — но это не предмет вопроса. На фоне bsl, сместившегося на задачу-исполнителя (ЧАСТИЧНО), rlm здесь и точнее по предмету, и экономнее (1.35×).
