## Что сервер дал хорошо

- **Полный код ОбработкаПроведения** обоих документов — получен целиком (не чанками) через `execute_metadata_cypher` запросом property `program_code`. Это уникальное преимущество graph-metadata
- **Полный код модуля РаботаСЗадачами** (581K символов) — содержит ЗакрытьЗадачу(), ВзятьВРаботу(), ВернутьНаДоработку() с полной логикой транзакций
- **Структуры всех регистров из Neo4j** — execute_metadata_cypher по связям HAS_DIMENSION/HAS_RESOURCE даёт точные структуры
- **Расширенный список регистров сведений** — нашёл 13 релевантных (больше чем другие серверы): включая ИсторияСобытийЗадач, ЭскалированныеЗадачи/Действия, ЗадачиСПодзадачами, ИтерацииЗадачДействий, ПереносыСроковВыполненияПроцессовИЗадач
- **Структура документов** Задача (27 реквизитов) и ДействиеЗадачи (24 реквизита) — контекст для понимания кэшируемых реквизитов
- **Список из 59 общих модулей** со словом "Задач"/"Действ" — полная карта программных модулей

## Что сервер НЕ дал

- **search_metadata не работает** — требует OpenAI API (только embedding-based поиск), переключился на Cypher
- **Семантический search_code не инициализирован** — Vector indexer not initialized
- **Код модулей набора записей** (ОбновитьДанныеДействия, ОбновитьДанныеЗадачи) — не запрошен отдельно, хотя мог быть получен через program_code

## Паттерны поведения агента

- **Стратегия Cypher-first:** После неудачи с search_metadata быстро освоил execute_metadata_cypher и использовал его для всех структурных запросов
- **Обход ограничения инструментов:** MCP-инструменты не появились в ToolSearch (SSE-транспорт) — агент обошёл через прямые HTTP-запросы к REST API сервера. Креативное решение
- **Программный код через Neo4j:** Агент обнаружил property `program_code` на узлах MetadataObject и использовал его для получения полных модулей — мощная стратегия, но с огромным расходом токенов
- **Проблема масштаба:** Запрос program_code для Документ.Задача вернул 927K символов, РаботаСЗадачами — 581K. Суммарно 5 запросов program_code дали ~1.85M символов из общих 1.88M

## Выявленные проблемы RAG

| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| search_metadata требует OpenAI API | Вызов #1 — ошибка, вынужден переключиться на Cypher |
| search_code: semantic не инициализирован | Вызов #10 — Vector indexer not initialized |
| Нет гранулярности при чтении кода | program_code возвращает ВЕСЬ модуль целиком (до 927K символов), нет возможности запросить отдельную процедуру |
| Огромный расход токенов | 1.88M символов ≈ 3.4M токенов — в 16× больше чем cloud-embeddings и 20× больше чем code-metadata |

## Вывод

Сервер graph-metadata даёт **самый полный ответ** из трёх: полный код модулей, расширенный список регистров (13 vs 5-7 у других), структуры из графа. Однако ценой **катастрофического расхода токенов** (~3.4M vs ~207K у cloud и ~164K у code). Причина — program_code возвращает модули целиком без возможности фильтрации. Для задач, требующих полный код процедур — незаменим; для типовых аналитических вопросов — избыточен. Рекомендация: добавить в сервер возможность запроса отдельных процедур/функций по имени.
