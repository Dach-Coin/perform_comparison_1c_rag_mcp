## 1. Общая структура бизнес-процесса

**Тип объекта:** БизнесПроцесс.Согласование  
**Назначение:** Маршрутизация документа к группе согласующих с фиксацией решений (Согласовано / НеСогласовано / СогласованоСЗамечаниями) и формированием визы на документе.

Процесс входит в подсистему «Документооборот» и запускается как отдельный бизнес-процесс или в составе **КомплексногоПроцесса**. Каждый запущенный процесс создаёт задачи типа **ЗадачаИсполнителя** для каждого согласующего.

## 2. Параметры запуска согласования

### 2.1 Кто согласует — Табличная часть «Исполнители»

| Реквизит ТЧ | Тип | Назначение |
|---|---|---|
| **Исполнитель** | Сотрудники / ПолныеРоли / Пользователи | Кто должен согласовать |
| **ПорядокСогласования** | Перечисление.ПорядокВыполненияЗадач | ПослеПредыдущего или ВместеСПредыдущим |
| **СрокИсполнения** | Дата | Конкретная дата срока для этого исполнителя |
| **СрокИсполненияДни** | Число | Относительный срок (дни) |
| **СрокИсполненияЧасы** | Число | Относительный срок (часы) |
| **СрокИсполненияМинуты** | Число | Относительный срок (минуты) |
| **ВариантУстановкиСрокаИсполнения** | ТочныйСрок / ОтносительныйСрок | Способ задания срока |
| **ЗадачаИсполнителя** | ЗадачаСсылка | Ссылка на созданную задачу (заполняется при запуске) |
| **ИдентификаторИсполнителя** | УникальныйИдентификатор | Для идентификации строки при замене исполнителей |
| **Пройден** | Булево | Признак что исполнитель уже отработал |
| **Описание** | Строка | Дополнительный комментарий по исполнителю |
| **ТрудозатратыПланИсполнителя** | Число | Плановые трудозатраты |

### 2.2 Вариант маршрутизации — реквизит «ВариантСогласования»

Тип: `Перечисление.ВариантыМаршрутизацииЗадач`

| Значение | Смысл |
|---|---|
| **Последовательно** | Задачи создаются по одной: следующий получает задачу только после завершения предыдущего |
| **Параллельно** | Все задачи создаются одновременно |
| **Смешанно** | Управляется через ПорядокСогласования в каждой строке ТЧ Исполнители (ПослеПредыдущего / ВместеСПредыдущим) |

### 2.3 Сроки процесса в целом

| Реквизит | Тип | Назначение |
|---|---|---|
| **СрокИсполненияПроцесса** | Дата | Общий срок завершения всего процесса |
| **СрокОбработкиРезультатов** | Дата | Срок для обработки итогов автором |
| **СрокОбработкиРезультатовДни/Часы/Минуты** | Число | Относительный срок обработки |
| **ВариантУстановкиСрокаОбработкиРезультатов** | Перечисление | ТочныйСрок / ОтносительныйСрок |

### 2.4 Прочие параметры запуска

| Реквизит | Тип | Назначение |
|---|---|---|
| **Шаблон** | СправочникСсылка.ШаблоныСогласования | Шаблон, по которому создан процесс |
| **ПодписыватьЭП** | Булево | Требовать электронную подпись при визировании |
| **ПовторитьСогласование** | Булево | Признак что это повторный запуск |
| **КоличествоИтераций** | Число | Сколько итераций разрешено |
| **НомерИтерации** | Число | Текущая итерация |
| **Важность** | Перечисление.ВариантыВажностиОбъектов | Приоритет процесса |
| **Автор** | Сотрудники / Пользователи | Инициатор согласования |
| **ОбрабатывающийРезультат** | Сотрудники / ПолныеРоли | Кто обработает итоги согласования |
| **ГлавнаяЗадача** | ЗадачаСсылка | Задача-родитель (для вложенных процессов) |
| **Описание** | Строка(0) | Текст задания для согласующих |

Документы и объекты, которые нужно согласовать:

| Реквизит | Тип | Назначение |
|---|---|---|
| **Предмет** | ДокументыПредприятия / ВходящееПисьмо / ИсходящееПисьмо / Файлы / Проекты / Контрагенты / Мероприятия / ПроектныеЗадачи | Ссылка на согласуемый объект |

## 4. Визы согласования

### 4.1 Что такое виза

**Виза согласования** — запись в справочнике `ВизыСогласования`, создаваемая для каждого участника процесса при выполнении им задачи. Это аналог электронной подписи в журнале согласования документа.

Функциональная опция `ИспользоватьВизыСогласования` управляет включением этого механизма.

### 4.2 Структура визы (Справочник.ВизыСогласования)

| Реквизит | Тип | Назначение |
|---|---|---|
| **Документ** | ДокументыПредприятия | Документ, к которому относится виза |
| **Исполнитель** | Сотрудники / ПолныеРоли / Пользователи | Кто выдал визу |
| **УстановилРезультат** | Сотрудники / ФактическиеИсполнители / Пользователи | Фактический пользователь (может отличаться при делегировании) |
| **РольИсполнителя** | ПолныеРоли | Роль исполнителя |
| **РезультатСогласования** | Перечисление.РезультатыСогласования | Итог: Согласовано / НеСогласовано / СогласованоСЗамечаниями |
| **Комментарий** | Строка(0) | Текстовый комментарий согласующего |
| **Источник** | ДействияСогласования / ЗадачаИсполнителя / БП.Согласование | Откуда пришла виза |
| **ДатаСоздания** | Дата | Когда создана запись визы |
| **ДатаИсполнения** | Дата | Когда исполнитель принял решение |
| **НомерИтерации** | Число | Итерация согласования |
| **Порядок** | Число | Порядковый номер в списке виз |
| **Подписана** | Булево | Признак наличия ЭП |
| **ПомещенаВИсторию** | Булево | Перенесена в архив истории |
| **ДатаПомещенияВИсторию** | Дата | Когда помещена в историю |
| **Удалена** | Булево | Мягкое удаление визы |
| **ИдентификаторУчастника** | УникальныйИдентификатор | Для связи с конкретной строкой ТЧ Исполнители |

### 4.3 Связь виз с процессом

```
БП.Согласование ──┐
                  ├── ТЧ.Исполнители.ЗадачаИсполнителя ──► Задача.ЗадачаИсполнителя
                  │                                               │
                  └── ТЧ.РезультатыСогласования ◄──── при выполнении задачи
                                                                │
                  Справочник.ВизыСогласования.Источник ◄────────┘
                  (ссылается на Задачу или сам БП)
```

Форма `ИсторияВизСогласования` (ОбщаяФорма) отображает хронологию всех виз по документу.

## 5. Результаты согласования

### 5.1 Что может вернуть согласующий

Перечисление `РезультатыСогласования`:

| Значение | Смысл |
|---|---|
| **Согласовано** | Документ одобрен без замечаний |
| **НеСогласовано** | Документ отклонён; как правило, прерывает процесс |
| **СогласованоСЗамечаниями** | Документ одобрен, но с комментариями/замечаниями |

Результат фиксируется одновременно в трёх местах:
1. В реквизите задачи `ЗадачаИсполнителя.РезультатВыполнения`
2. В строке ТЧ `БП.Согласование.РезультатыСогласования`
3. В записи `ВизыСогласования.РезультатСогласования`

Итоговый результат всего процесса записывается в `БП.Согласование.РезультатСогласования`.

### 5.2 Состояния процесса

Перечисление `СостоянияБизнесПроцессов`:

| Значение | Смысл |
|---|---|
| **Активен** | Процесс выполняется, есть незакрытые задачи |
| **Остановлен** | Процесс приостановлен вручную |
| **Прерван** | Процесс прерван (например, при отказе одного из согласующих при последовательном варианте) |

Причина прерывания хранится в реквизите `ПричинаПрерывания`.

## 6. Обработка завершения процесса

### 6.1 Механизм

Когда все согласующие завершают свои задачи, платформа 1С вызывает стандартные события в модуле объекта БП Согласование — функцию `ОбработкаВыполнения` точки маршрута и обработчики событий задачи.

**Ключевые модули, участвующие в логике завершения:**

| Модуль | Роль |
|---|---|
| **РаботаСБизнесПроцессами** (ОбщийМодуль, Сервер) | Содержит секцию `РезультатыВыполненияПроцессовИЗадач` — центральная логика определения итогового результата процесса |
| **БизнесПроцессыИЗадачиСервер** | Серверные процедуры подсистемы БП и задач, принятие задачи к исполнению |
| **ИнтеграцияЗадачКлиент** | Клиентский обработчик выполнения задач при интерактивном завершении |
| **РаботаСПроцессамиПоДействиямСобытия** | Серверные обработчики событий взаимодействия процессов с действиями |
| **ПравилаОбработкиСервер** | Заполнение действий в форме предмета согласно настройкам |

### 6.2 Логика завершения (по архитектуре метаданных)

На основании структуры данных можно восстановить типовую логику:

1. Исполнитель выполняет задачу `ЗадачаИсполнителя`, устанавливает результат
2. Создаётся запись `ВизыСогласования` для документа
3. Заполняется строка ТЧ `РезультатыСогласования` процесса
4. В ТЧ `Исполнители` строке исполнителя устанавливается `Пройден = Истина`
5. **Если вариант Последовательно:** при `НеСогласовано` процесс может прерваться (`Состояние = Прерван`), заполняется `ПричинаПрерывания`
6. **Если все исполнители завершили:** определяется итоговый `РезультатСогласования` процесса
7. Создаётся задача для `ОбрабатывающегоРезультат` — на обработку итогов
8. Срок для обработки берётся из `СрокОбработкиРезультатов` / относительных полей
9. При `КоличествоИтераций > 1` и `ПовторитьСогласование = Истина` — запускается новая итерация

### 6.3 Задача для обработки результатов

После завершения согласующих создаётся отдельная задача для `ОбрабатывающегоРезультат` (автора или ответственного). Срок: `СрокОбработкиРезультатов`. Эта задача позволяет принять итоговое решение по документу.

## 8. Шаблоны согласования

Справочник `ШаблоныСогласования` — предустановленные конфигурации процесса:

- Хранит: ВариантСогласования, список исполнителей, сроки, ОбрабатывающийРезультат, КоличествоИтераций, ПодписыватьЭП
- Поддерживает: `ИспользоватьУсловия` — условные маршруты, `СрокОтложенногоСтарта` — отложенный запуск
- Может принадлежать КомплексномуПроцессу (`ВладелецШаблона`)
- Поддерживает наследование: `ИсходныйШаблон` — ссылка на базовый шаблон
