## Что сервер дал хорошо

1. **Полный список ролей для задач** — 7 ролей найдены через Cypher-запрос к графу: ЧтениеЗадач, РаботаСЗадачами, РаботаСЗадачамиИБизнесПроцессами, ИзменениеВыполнениеЗадач, РаботаСЗадачамиСотрудниковПодразделения, КонтрольЗадачИБизнесПроцессов, ЧтениеПроцессовИЗадачБезОграничения. **Это уникальная находка** — ни cloud, ни code не смогли извлечь роли.
2. **Точная структура РегистрСведений.РабочиеГруппы** — Cypher-запрос вернул измерения (Участник: КонтейнерыСотрудников, Объект: составной тип с ДокументСсылка.Задача), ресурсы (Изменение, Источник, Автоподстановка). Подтверждено, что Задача входит в составной тип Объект.
3. **Полный список констант управления доступом** — ОграничиватьДоступНаУровнеЗаписей, ДокументооборотВключитьПраваДоступа, ДокументооборотИспользоватьОграничениеПравДоступа, **ДобавлятьРуководителямДоступПодчиненных**, **ИспользоватьГрифыДоступа**, ДокументооборотИспользоватьОтложенноеОбновлениеПравДоступа — 6 констант, самый полный набор.
4. **Перечисление ВидимостьДействийВПредметах** — уникальная находка: Всем / АвторамИОтветственным / УчастникамДействия / Никому. Найдена привязка к Справочник.ВидыДействий.НастройкаВидимости — дополнительный слой контроля видимости.
5. **Справочник ВидыУчастниковЗадач** — флаги ЭтоИсполнитель, ЭтоОтветственный, ЭтоПроверяющий — детализация ролей участников внутри задачи.
6. **Карта всех модулей прав доступа** — 26 модулей найдены через Cypher (Права, Доступ, РабочимиГрупп) — полная топология подсистемы.
7. **Регистры задач и доступа** — 48 регистров, включая ЗадачиПоАвторам, СведенияОбИсполнителяхЗадач, ВсеИсполнителиДействийЗадач (с раскрытием замещений через ЗамещающиеИПомощники), НастройкиПравОбъектов, НаследованиеНастроекПравОбъектов.
8. **Подписки на события для задач** — ЗадачаПриЗаписи, КонтрольПередЗаписьюЗадачи, КонтрольПриЗаписиЗадачи, РабочиеГруппыДокументыПередЗаписью — полная картина триггеров.
9. **ГруппыДоступа (БСП)** — структура: Профиль → ПрофилиГруппДоступа, ТабЧасти: Пользователи, ЗначенияДоступа, ВидыДоступа.

## Что сервер НЕ дал

1. **Код модулей** — фактический BSL-код из РаботаСРабочимиГруппами, ДокументооборотПраваДоступа не получен. search_code вернул только краткие описания («ФУНКЦИИ ДЛЯ РАБОТЫ С РАБОЧЕЙ ГРУППОЙ ДОКУМЕНТА»), но не тела процедур. Semantic search и business_search нефункциональны.
2. **Текст RLS-шаблонов** — шаблоны ролевых ограничений не хранятся в графе метаданных.
3. **Логика определения «своих» vs «чужих» задач** — без кода невозможно увидеть, как конкретно проверяется принадлежность задачи пользователю.
4. **Код проверки прав** — `ПраваСотрудникаПоОбъекту()`, `ПраваПользователяПоОбъекту()` — только упоминания, без реализации.

## Паттерны поведения агента

- Агент начал с answer_metadata_question и search_metadata — оба не сработали (нерелевантный контекст, OpenAI unavailable). Быстро перешёл к get_metadata_prompt → Cypher — **правильная адаптация**.
- **execute_metadata_cypher стал основным инструментом** — 28 из 40 вызовов. Агент строил Cypher-запросы по схеме БД, последовательно раскрывая структуру: объекты → реквизиты → табличные части → роли → регистры → модули → подписки → перечисления → константы.
- **Стратегия «широкий обход графа»** — агент методично прошёл все категории метаданных (роли, регистры, модули, подписки, справочники, перечисления, константы, формы, отчёты). Это дало самую полную картину объектной модели среди трёх серверов.
- search_code использован 5 раз: 3 полезных, 1 низкая, 1 нефункциональный (semantic). Fulltext поиск кода работает, но бедно — даёт описания, не тела функций.
- business_search — не работает (vector indexer not initialized).
- answer_metadata_question — не работает корректно (возвращает ЭлементыСтиля вместо релевантного контекста).
- **Расход контекста минимальный** — ~69K символов за 40 вызовов. Cypher-ответы компактны (300–3000 символов), что позволило сделать много итераций без выжигания контекста.

## Выявленные проблемы RAG

| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| answer_metadata_question возвращает нерелевантный контекст | Оба вызова (#1, #31) вернули ЭлементыСтиля (ЦветТекстаРоли, ШрифтОписанияЗадачи) вместо данных о задачах. Баг в RAG-пайплайне: неправильный контекст подаётся в LLM |
| search_metadata нефункционален (нет OpenAI API) | Вызов #2 — ошибка. Сервер требует OpenAI API для семантического поиска по метаданным, но API недоступен |
| semantic search_code нефункционален | Вызов #17 — «Vector indexer not initialized». Векторный индекс кода не создан |
| business_search нефункционален | Вызов #18 — «Vector indexer not initialized». Аналогично |
| search_code (fulltext) не возвращает тела функций | Даёт описания и имена, но не код. Для вопросов о логике работы — недостаточно |
| Граф = дерево метаданных, не код | Основная ценность — структура (роли, регистры, типы), но код модулей не хранится в графе. Это системное ограничение архитектуры |

## Вывод

Сервер graph-metadata через Cypher-запросы даёт **самую полную структурную картину** системы прав: все 7 ролей, точные типы регистров, полная карта модулей, подписки на события, перечисления, константы. Это единственный сервер, нашедший роли задач, перечисление ВидимостьДействийВПредметах и константу ДобавлятьРуководителямДоступПодчиненных. Однако без кода модулей (search_code слаб, semantic не работает) сервер не может объяснить **как именно** работает проверка прав — только **из чего** она состоит. Для вопросов об архитектуре прав доступа graph — лучший выбор; для вопросов о логике — нужен cloud или code.
