## Что сервер дал хорошо

1. **Исчерпывающая структура БП Согласование через Cypher** — 31 реквизит с точными типами, все 6 табличных частей, все реквизиты ТЧ (Исполнители: 12 реквизитов включая ИдентификаторИсполнителя, ТрудозатратыПланИсполнителя — **детали, которые другие серверы не дали**)

2. **Все перечисления одним запросом** — Cypher вернул все 5 перечислений разом:
   - РезультатыСогласования: Согласовано, НеСогласовано, СогласованоСЗамечаниями
   - ВариантыМаршрутизацииЗадач: Последовательно, Параллельно, Смешанно
   - ПорядокВыполненияЗадач: ПослеПредыдущего, ВместеСПредыдущим
   - ВариантыУстановкиСрокаИсполнения: ТочныйСрок, ОтносительныйСрок
   - СостоянияБизнесПроцессов: Активен, Остановлен, Прерван

3. **Справочник ВизыСогласования** — 18 реквизитов с полной типизацией: Исполнитель, Документ, РезультатСогласования, Источник, ДатаСоздания, Подписана, ПомещенаВИсторию, ИдентификаторУчастника и др. **Самый полный среди трёх серверов**

4. **Структура ЗадачаИсполнителя** — 19 реквизитов, включая ТекущийИсполнитель, ФактическийИсполнитель, ИсключенаИзПроцесса, Отменена

5. **Справочник ШаблоныСогласования** — 24 реквизита: ВариантСогласования, ИспользоватьУсловия, СрокОтложенногоСтарта, ИсходныйШаблон, ВладелецШаблона. **Уникальная находка** — другие серверы не дали такой глубины по шаблонам

6. **Связи объектов** — найдена обратная ссылка `ДокументыПредприятия.тст_БизнесПроцесс` → `БизнесПроцессСсылка.Согласование`. **Уникальная находка** графового подхода

7. **Полный список общих модулей** — 8 специализированных (РаботаСВизамиСогласования, СогласованиеВРежимеЗамечаний в 6 вариантах) + 52 модуля БП и задач. **Самый полный список** из трёх серверов

8. **Формы БП** — 3 формы: ФормаБизнесПроцесса, ФормаИзменениеПараметров, ФормаИсторияСогласования

## Что сервер НЕ дал

1. **Код ObjectModule БП Согласование** — основная слабость. Функции `ИтоговыйРезультатСогласования()`, `ОбходСогласующихЗавершен()`, `СоздатьЗадачиСогласования()`, `ОбработкаРезультатаОбработка()` — только имена, без тела. search_code не нашёл модуль объекта БП (7 попыток, включая 4 неудачных)

2. **Семантический поиск и business_search** — "Vector indexer not initialized". Это лишает граф-сервер возможности отвечать на бизнес-вопросы через RAG

3. **Точки маршрута** — не представлены как узлы в Neo4j. Маршрут БП (Согласовать → ОбработкаРезультата → Ознакомиться) получен только из контекста search_code

4. **answer_metadata_question промахнулся** — первый вызов вернул нерелевантные данные (стили и мероприятия вместо согласования). RAG-вектора не нашли нужный контекст

## Паттерны поведения агента

- **Стратегия "граф сначала"**: агент начал с `answer_metadata_question` (неудачно), затем переключился на `search_metadata` + `get_metadata_prompt` + прямые Cypher-запросы. Правильное решение
- **Интенсивное использование Cypher**: 13 из 25 вызовов — `execute_metadata_cypher`. Это сильная сторона агента — точные структурные запросы
- **Упорные попытки найти код**: 8 вызовов search_code с разными стратегиями (hybrid, fulltext, semantic, фильтры). Из 8 только 3 дали полезный результат. Агент правильно диагностировал проблему: модуль объекта БП не индексируется
- **Максимальное число вызовов**: 25 — почти в 2.5 раза больше, чем cloud-embeddings (10). Это следствие комбинации: много структурных запросов (каждый точный, но узкий) + неудачные попытки поиска кода
- **Минимальный расход токенов**: ~76K MCP-токенов при 25 вызовах. Средний ответ ~1700 символов — Cypher-запросы возвращают компактные результаты

## Выявленные проблемы RAG

| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| Vector indexer not initialized | business_search и semantic search_code недоступны. 3 вызова вернули 0 результатов с ошибкой |
| answer_metadata_question нестабилен | Первый вызов промахнулся мимо БП Согласование — вернул стили и мероприятия |
| Модули объектов не индексируются в search_code | 4 попытки найти ObjectModule БП Согласование — все неудачны (0 результатов по filter=БизнесПроцессы, AND-запрос, semantic) |
| Точки маршрута вне графа | Нет узлов RoutePoint в Neo4j — маршрут БП невидим для Cypher |
| search_code filter по категориям не работает | filter=БизнесПроцессы дал 0 результатов, хотя fulltext без фильтра находил связанный код |
| Граф = дерево, не граф | Связи между объектами (БП → Задача → Виза) не представлены как рёбра — только через типы реквизитов |

## Вывод

**graph-metadata** — **лидер по полноте структурных данных**: реквизиты, ТЧ, перечисления, связи между объектами получены точнее и полнее, чем у других серверов. Cypher даёт уникальную возможность за один запрос вытянуть все значения перечислений или все реквизиты. Однако **неспособность получить код** (модуль объекта БП не индексируется) делает ответ неполным по вопросу "какой код обрабатывает завершение". Для структурных вопросов (реквизиты, связи, перечисления) — лучший сервер; для вопросов по коду и логике — неэффективен.
