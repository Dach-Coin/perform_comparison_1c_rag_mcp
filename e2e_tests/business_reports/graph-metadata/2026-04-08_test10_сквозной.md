# Сквозной бизнес-сценарий в 1С:Документооборот КОРП 3.0
## TEST-10 | Сервер: graph-metadata | 2026-04-08

---

## Сценарий: ВходящееПисьмо → Рассмотрение → Резолюция → Задача → ИсходящееПисьмо

---

## Шаг 1. Поступление ВходящегоПисьма от контрагента

### Объект
**Документ.ВходящееПисьмо**

| Реквизит | Тип | Назначение |
|----------|-----|------------|
| Тема | Строка(1024) | Тема письма |
| ОтправительАдресат | СправочникСсылка.АдресатыПочтовыхСообщений | Контрагент-отправитель |
| ДатаОтправки | ДатаВремя | Дата отправки контрагентом |
| ДатаПолучения | ДатаВремя | Дата получения |
| УчетнаяЗапись | СправочникСсылка.УчетныеЗаписиЭлектроннойПочты | Ящик-получатель |
| Папка | СправочникСсылка.ПапкиПисем | Папка хранения |
| Предмет | составной тип | Связанный объект (Проект, Задача, Файл...) |
| ЕстьВложения | Булево | Наличие файлов-вложений |
| Важность | ПеречислениеСсылка.ВажностьПисем | Срочность |

**Табличные части:**
- `ПолучателиПисьма` — Адресат (АдресатыПочтовыхСообщений)
- `ПолучателиКопий` — Адресат
- `ПолучателиОтвета` — Адресат
- `АдресаУведомленияОПрочтении` — Адресат

### Бизнес-процессы при поступлении
- Регламентное задание **"Получение и отправка писем"** запускает получение почты

### Регистры, обновляемые при создании ВходящегоПисьма

| Регистр | Что фиксируется |
|---------|-----------------|
| РегистрСведений.ПисьмаВПапках | {Письмо, Папка} — помещение в папку |
| РегистрСведений.НеполученныеВходящиеПисьма | очередь необработанных писем |
| РегистрСведений.ИдентификаторыПолученныхПисем | уникальный идентификатор для дедупликации |
| РегистрСведений.ОповещенияОПисьмах | уведомления получателям |
| РегистрСведений.НаличиеФайлов | {ОбъектСФайлами=ВходящееПисьмо, ЕстьФайлы} — при наличии вложений |

### Код (модули)
- **ВстроеннаяПочтаСервер** — обработчик регл.задания "Получение и отправка писем"
- **РаботаСПочтовымиСообщениями** — основная логика работы с почтовыми сообщениями
- **РаботаСПочтовымиСообщениямиСлужебный** — служебные процедуры
- **РаботаСФайлами** — прикрепление вложений из письма

## Шаг 2. Рассмотрение письма руководителем и вынесение Резолюции

### Объект
**БизнесПроцесс.Рассмотрение**

Создаётся как предмет бизнес-процесса, указывающего на ВходящееПисьмо.

| Реквизит | Тип | Назначение |
|----------|-----|------------|
| Наименование | Строка(250) | Описание рассмотрения |
| Резолюция | Строка | **Текст резолюции руководителя** |
| ВариантОбработкиРезолюции | ПеречислениеСсылка.ВариантыОбработкиРезолюции | Способ дальнейшей обработки |
| ВариантРассмотрения | ПеречислениеСсылка.ВариантыРассмотрения | Тип рассмотрения |
| Исполнитель | Сотрудники / ПолныеРоли / Пользователи | Назначенный исполнитель |
| КонтролерИсполнения | Сотрудники / ПолныеРоли / Пользователи | Контролёр |
| ОбрабатывающийРезолюцию | Сотрудники / ПолныеРоли | Секретарь, обрабатывающий резолюцию |
| ГлавнаяЗадача | ЗадачаСсылка.ЗадачаИсполнителя | Главная адресная задача |
| ПоставитьДокументНаКонтроль | Булево | Флаг контроля исполнения |
| СрокИсполнения | ДатаВремя | Срок исполнения резолюции |
| ШаблонИсполнения | СправочникСсылка.ШаблоныИсполнения | Шаблон для создания БП Исполнение |
| ШаблонОзнакомления | СправочникСсылка.ШаблоныОзнакомления | Шаблон для рассылки ознакомления |

### Задача адресата (при запуске Рассмотрения)
**Задача.ЗадачаИсполнителя** (единственный объект категории "Задачи"):
- `ТекущийИсполнитель` — руководитель (Сотрудники / ПолныеРоли / Пользователи)
- `Описание` — задание из процесса
- `СрокИсполнения` — срок рассмотрения
- `СостояниеБизнесПроцесса` — Активный / Завершён

### Регистры при запуске и выполнении Рассмотрения

| Регистр | Что фиксируется |
|---------|-----------------|
| РегистрСведений.ДанныеБизнесПроцессов | {БизнесПроцесс, ОсновнойПредмет, Состояние, Стартован, ДатаНачала, Автор} |
| РегистрСведений.УчастникиПроцессов | {Процесс, Участник, Основание} — все участники рассмотрения |
| РегистрСведений.СостоянияДействий | {Действие, Участник, ИдентификаторУчастника, Состояние} — состояние адресных задач |
| РегистрСведений.ИсторияЗадач | {Задача, Событие, ДействиеЗадачи, Дата, Контекст} — история событий |
| РегистрНакопления.КоличествоЗадач | счётчик активных задач |

### Код (модули)
- **РаботаСРезолюциямиКлиент** — `ДобавитьРезолюцию(ЭтаФорма)` — UI-логика ввода резолюции
- **РаботаСРезолюциями** — серверная обработка резолюции
- **РаботаСРезолюциямиКлиентСервер** — общая логика клиент/сервер
- **ИнтерактивныйЗапускБизнесПроцессов** — интерактивный запуск процесса Рассмотрение
- **ИнтерактивныйЗапускБизнесПроцессовКлиент** — клиентская часть запуска
- **БизнесПроцессыИЗадачиСервер** — `ПринятьЗадачуКИсполнению()` — принятие задачи
- **РаботаСБизнесПроцессами** — обработка результатов выполнения
- **СрокиИсполненияПроцессовКОРП** — расчёт сроков (КОРП-специфичный модуль)

## Шаг 3. Создание Задачи на исполнение по резолюции

### Объект
**Документ.Задача** (создаётся из резолюции или запуском БП.Исполнение)

| Реквизит | Тип | Назначение |
|----------|-----|------------|
| Заголовок | Строка(250) | Название задачи |
| Описание | Строка | Подробное описание (текст резолюции) |
| Источник | ОпределяемыйТип.ИсточникЗадач | Источник: БП Рассмотрение |
| ВышестоящаяЗадача | ДокументСсылка.Задача | Родительская задача |
| ВышестоящееДействие | ДокументСсылка.ДействиеЗадачи | Действие, породившее задачу |
| Ответственный | ОпределяемыйТип.УчастникЗадач | Ответственный исполнитель |
| Срок | ДатаВремя | Срок из резолюции |
| СостояниеЗадачи | СправочникСсылка.СостоянияЗадач | Текущее состояние |
| РезультатЗадачи | СправочникСсылка.РезультатыЗадач | Итоговый результат |
| Контрагент | СправочникСсылка.Контрагенты | Контрагент из письма |

**БизнесПроцесс.Исполнение** (создаётся при необходимости маршрутизации):

| Реквизит | Тип | Назначение |
|----------|-----|------------|
| ВариантИсполнения | ПеречислениеСсылка.ВариантыМаршрутизацииЗадач | Параллельное/последовательное |
| Контролер | Сотрудники / ПолныеРоли / Пользователи | Контролёр исполнения |
| Проверяющий | Сотрудники / ПолныеРоли / Пользователи | Проверяющий результат |
| СрокИсполненияПроцесса | ДатаВремя | Общий срок |
| ГлавнаяЗадача | ЗадачаСсылка.ЗадачаИсполнителя | Адресная задача в ГП |

### Регистры при создании Задачи

| Регистр | Что фиксируется |
|---------|-----------------|
| РегистрСведений.ЗадачиПоАвторам | {Автор → Задача} — для быстрого поиска |
| РегистрСведений.ЗадачиСПодзадачами | иерархия задач |
| РегистрСведений.ДанныеБизнесПроцессов | {БизнесПроцесс.Исполнение, ОсновнойПредмет} |
| РегистрСведений.СведенияОбИсполнителяхЗадач | данные об исполнителях |
| РегистрНакопления.КоличествоЗадач | +1 к счётчику |
| РегистрНакопления.КоличествоДействийЗадач | счётчик действий |
| РегистрСведений.ИсторияСобытийЗадач | создание задачи |

### Код (модули)
- **РаботаСБизнесПроцессами** — `РезультатыВыполненияПроцессовИЗадач` — запись результатов
- **БизнесПроцессыИЗадачиСервер** — принятие задачи к исполнению
- **ОбработкаОчередиЗаданийСервер** — `СформироватьПроцессДляОбработкиОбъекта()` — формирование процесса обработки
- **ШаблоныБизнесПроцессов** — применение шаблона Исполнения

## Шаг 4. Исполнитель выполняет задачу и прикладывает файл-ответ

### Объект — изменяется: Задача.ЗадачаИсполнителя

| Реквизит | До | После |
|----------|----|-------|
| ПринятаКИсполнению | Ложь | Истина |
| ДатаПринятияКИсполнению | — | текущая дата |
| РезультатВыполнения | "" | текст отчёта исполнителя |
| ДатаИсполнения | — | дата выполнения |
| ФактическийИсполнитель | — | СправочникСсылка.ФактическиеИсполнители |

### Присоединение файла-ответа

Файл прикрепляется к объекту (Задаче или связанному документу) через подсистему файлов:

| Регистр | Что фиксируется |
|---------|-----------------|
| РегистрСведений.НаличиеФайлов | {ОбъектСФайлами=Задача, ЕстьФайлы=Истина} |
| РегистрСведений.СведенияОФайлах | метаданные файла |
| РегистрСведений.СведенияОФайлахДокументооборот | расширенные данные |
| РегистрСведений.ДвоичныеДанныеФайлов | бинарное содержимое файла |
| РегистрСведений.ТекстыВерсийФайлов | текстовое содержимое для поиска |

### Регистры при выполнении задачи

| Регистр | Что фиксируется |
|---------|-----------------|
| РегистрСведений.РезультатыВыполненияПроцессовИЗадач | {Объект=ЗадачаИсполнителя, Результат} |
| РегистрСведений.ИсторияЗадач | {Задача, Событие="Выполнена", ДействиеЗадачи} |
| РегистрСведений.ИсторияСостоянийДокументов | изменение состояния связанного документа |
| РегистрСведений.СостоянияДействий | {Действие, Участник, Состояние="Выполнено"} |

### Код (модули)
- **ВыполнениеЗадачСервер** — `ВыполнитьЗадачуПоПравилуЭскалации(Задача, ВариантВыполнения, Комментарий)`
- **БизнесПроцессыИЗадачиСервер** — принятие / завершение задачи
- **РаботаСФайлами** — добавление файла-ответа к задаче
- **РаботаСБизнесПроцессами** — фиксация результата, переход процесса на следующий этап

## Шаг 5. Формирование ИсходящегоПисьма с ответом контрагенту

### Объект
**Документ.ИсходящееПисьмо**

| Реквизит | Тип | Значение |
|----------|-----|----------|
| Тема | Строка(1024) | "Re: " + Тема входящего |
| ПисьмоОснование | ДокументСсылка.ВходящееПисьмо | Ссылка на исходное письмо |
| Автор | Сотрудники / Пользователи | Исполнитель задачи |
| ТипОтвета | ПеречислениеСсылка.ТипыОтвета | Ответ / Пересылка |
| УчетнаяЗапись | СправочникСсылка.УчетныеЗаписиЭлектроннойПочты | Ящик-отправитель |
| ОтправительКонтакт | составной тип | Исполнитель (Сотрудник/Пользователь) |
| ПодготовленоКОтправке | ДатаВремя | Дата готовности к отправке |
| ЕстьВложения | Булево | Истина (файл-ответ приложен) |

**Табличные части** (аналогичны ВходящемуПисьму):
- `ПолучателиПисьма` — адресаты-контрагенты
- `ПолучателиКопий` — копии

**Реквизит ПисьмоОснование** — прямая связь с документом ВходящееПисьмо (или ИсходящееПисьмо при переадресации).

### Регистры при создании и отправке ИсходящегоПисьма

| Регистр | Что фиксируется |
|---------|-----------------|
| РегистрСведений.ПодготовленныеКОтправкеПисьма | {Письмо, ВидМаршрутизации, ПодготовленоКОтправке, УчетнаяЗапись} |
| РегистрСведений.НеотправленныеИсходящиеПисьма | {Письмо, ОсталосьПопытокОтправки} — до успешной отправки |
| РегистрСведений.ПисьмаВПапках | {Письмо, Папка} — в папке "Отправленные" |
| РегистрСведений.ВложенныеПисьма | связь с вложением ВходящегоПисьма при переадресации |
| РегистрСведений.НаличиеФайлов | {ОбъектСФайлами=ИсходящееПисьмо, ЕстьФайлы=Истина} |

### Код (модули)
- **ВстроеннаяПочтаКлиент** — `ОтветитьНаПисьмо(ПараметрКоманды)`, `ПереслатьПисьмо(ПараметрКоманды)` — UI-команды формы ВходящегоПисьма
- **ВстроеннаяПочтаСервер** — регламентное задание отправки
- **ПомощникОтправитьКлиентКОРП** — специфичная для КОРП логика помощника отправки
- **ПомощникОтправить** — серверные процедуры помощника Отправить
- **РаботаСПравиламиОбработкиПисем** — применение правил к папке

## Сводная схема сквозного сценария

```
Контрагент отправляет письмо
    │
    ▼
[Рег.задание] ВстроеннаяПочтаСервер
    │ создаёт
    ▼
Документ.ВходящееПисьмо
    │ → РегС.ПисьмаВПапках
    │ → РегС.НаличиеФайлов (вложения)
    │
    ▼ (вручную или автоматически)
БизнесПроцесс.Рассмотрение
    │ создаёт ЗадачаИсполнителя для Руководителя
    │ → РегС.ДанныеБизнесПроцессов
    │ → РегС.УчастникиПроцессов
    │
    ▼ (Руководитель вводит резолюцию)
РаботаСРезолюциямиКлиент.ДобавитьРезолюцию()
    │ БП.Рассмотрение.Резолюция = "Подготовить ответ"
    │ → РегС.СостоянияДействий
    │ → РегС.ИсторияЗадач
    │
    ▼
Документ.Задача / БП.Исполнение
    │ создаётся с Источник=БП.Рассмотрение
    │ → РегС.ЗадачиПоАвторам
    │ → РегС.СведенияОбИсполнителяхЗадач
    │ → РегН.КоличествоЗадач
    │
    ▼ (Исполнитель выполняет, прикладывает файл)
ВыполнениеЗадачСервер.ВыполнитьЗадачу()
    │ ЗадачаИсполнителя.РезультатВыполнения = "Ответ подготовлен"
    │ → РегС.РезультатыВыполненияПроцессовИЗадач
    │ → РегС.НаличиеФайлов (файл-ответ)
    │ → РегС.ДвоичныеДанныеФайлов
    │
    ▼
Документ.ИсходящееПисьмо (ПисьмоОснование = ВходящееПисьмо)
    │ Команда: ВстроеннаяПочтаКлиент.ОтветитьНаПисьмо()
    │ → РегС.ПодготовленныеКОтправкеПисьма
    │ → РегС.НеотправленныеИсходящиеПисьма
    │
    ▼ (Рег.задание отправки)
ВстроеннаяПочтаСервер → Отправлено контрагенту
    │ → РегС.ПисьмаВПапках (папка "Отправленные")
```

## Ключевые объекты конфигурации DO3 в сценарии

| Объект | Категория | Роль в сценарии |
|--------|-----------|-----------------|
| ВходящееПисьмо | Документы | Входная точка сценария |
| ИсходящееПисьмо | Документы | Выходная точка, ответ контрагенту |
| Задача | Документы | Задача-поручение для исполнителя |
| ДействиеЗадачи | Документы | Действие в рамках задачи |
| ЗадачаИсполнителя | Задачи | Адресная задача бизнес-процесса |
| Рассмотрение | БизнесПроцессы | БП рассмотрения руководителем |
| Исполнение | БизнесПроцессы | БП исполнения по резолюции |
| ПисьмаВПапках | РегистрыСведений | Хранение письма в папке |
| ДанныеБизнесПроцессов | РегистрыСведений | Сводные данные по БП |
| СостоянияДействий | РегистрыСведений | Состояния адресных задач |
| ИсторияЗадач | РегистрыСведений | Журнал событий задачи |
| НаличиеФайлов | РегистрыСведений | Флаг наличия вложений |
| ПодготовленныеКОтправкеПисьма | РегистрыСведений | Очередь отправки |
| НеотправленныеИсходящиеПисьма | РегистрыСведений | Письма на повторной отправке |
| РезультатыВыполненияПроцессовИЗадач | РегистрыСведений | Итоги выполнения |
| КоличествоЗадач | РегистрыНакопления | Счётчик задач |
