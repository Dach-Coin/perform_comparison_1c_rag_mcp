**Сервер:** 1c-graph-metadata
**Дата:** 2026-04-07
**Оценщик:** Оркестратор (Claude Opus 4.6)

## Что сервер дал хорошо

- **Граф объектов**: Cypher-запросы (#8, #9) дали полную карту объектов области замещений — 33 объекта с именами «замещ*» и «исполнител*». Это структурная информация, которую другие серверы не могут дать за один запрос.
- **Полный код модулей через `program_code`**: Cypher-запрос к свойству `program_code` вернул полные тексты модулей `ФактическиеИсполнители` (~9 500 символов), `ВсеИсполнителиДействийЗадач` (~7 200 символов), `РаботаСЗадачами` (630 527 символов). Это уникальная возможность graph-сервера — получить **весь код** модуля без чанкинга.
- **Реквизиты через Cypher** (#10): структура справочника `ФактическиеИсполнители` (Адресат, План, Факт, Отметил) получена точно за один запрос.
- **Точный поиск вызывателей** (#23): `WHERE program_code CONTAINS 'ОпределитьФактическихИсполнителей'` нашёл ровно 5 модулей — это самый надёжный способ найти все места вызова, без ложных срабатываний.
- **Контексты вызовов** (#24, #25): Cypher с `split/substring` по `program_code` извлёк фрагменты кода вокруг вызовов из каждого модуля. Творческое использование Cypher для задач, для которых он не предназначен.

## Что сервер НЕ дал

- **Семантический поиск нерабочий**: `business_search` (#2) и `search_code` с `search_type=semantic` (#16) вернули ошибку «Vector indexer not initialized». Это критическая деградация — сервер потерял семантические возможности.
- **`search_metadata` нерабочий** (#4): «OpenAI API access currently unavailable». Ещё один сломанный инструмент.
- **`answer_metadata_question` деградирован** (#5, #6): LLM-компонент работает только с подсистемами и стилями, не видит справочников и модулей. Фактически бесполезен для этого теста.
- **Огромный расход токенов**: модуль `РаботаСЗадачами` весит 630 527 символов (~1.1M токенов). Один этот запрос потребил больше контекста, чем оба других сервера вместе взятые. При этом из 630K нужны были ~200 строк одной функции.

## Паттерны поведения агента

- **Разведка → разочарование → обходной путь**: агент начал с `search_code` (hybrid) — получил короткие, но релевантные результаты. Попробовал `business_search` и `search_metadata` — оба сломаны. Попробовал `answer_metadata_question` дважды — бесполезно. Затем **переключился на Cypher-стратегию** через `get_metadata_prompt` + `execute_metadata_cypher` — и это сработало.
- **Творческий Cypher**: агент использовал `WHERE toLower(o.name) CONTAINS`, `WHERE program_code CONTAINS`, `split/substring` для извлечения контекста вызовов. Это продвинутое использование, выходящее за типичные паттерны.
- **Вынужденный перебор**: 25 вызовов (vs 6 и 10 у конкурентов) — следствие 6 нерабочих/малополезных инструментов, потребовавших обходных путей.
- **Дамп целого модуля** (#21): запрос полного кода `РаботаСЗадачами` (630K) — вынужденная мера, т.к. `search_code` не нашёл вызовы по имени функции. Агент затем обработал файл через Python grep.

## Выявленные проблемы RAG

| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| Vector indexer выключен | `business_search` и semantic `search_code` нерабочие. Критическая деградация сервера. |
| OpenAI API недоступен | `search_metadata` полностью нерабочий. |
| answer_metadata_question ограничен | LLM видит только подсистемы и стили, не видит справочники/модули. Бесполезен для 90% вопросов. |
| search_code fulltext слаб | fulltext-поиск вернул 10 нерелевантных результатов для запроса вызовов (#22). Не ищет внутри кода, только по описаниям объектов. |
| Отсутствие контроля размера ответа | Cypher вернул 630K за один запрос — нет лимитов на размер `program_code`. Расходуется весь контекст агента. |
| Дублирование запросов | Вызовы #15 и #17 почти идентичны. Вызовы #12 и #20 — дубли (полный код ФактическиеИсполнители дважды). |

## Вывод

graph-metadata **справился с задачей, но ценой 4x вызовов и 14x токенов** по сравнению с cloud-embeddings. Главное преимущество — возможность получить **полный код модуля** без чанкинга и **точный поиск вызовов через Cypher** (`WHERE program_code CONTAINS`). Однако 3 из 6 инструментов нерабочие (vector search, search_metadata, answer_metadata_question), что вынуждает агента использовать обходные пути. Сервер подходит для структурного анализа метаданных и точного поиска по имени, но неэффективен для семантического поиска по описанию — и это именно то, что требовал TEST-05.
