# Жизненный цикл входящего письма в 1С:Документооборот КОРП 3.0

**Дата:** 2026-04-07  
**Конфигурация:** Документооборот КОРП 3.0 (DO3)  
**Источник данных:** MCP-сервер 1c-graph-metadata (Neo4j)

---

## 1. Объект хранения: Справочник «ДокументыПредприятия»

В 1С:ДО КОРП 3.0 входящие письма хранятся в **справочнике ДокументыПредприятия** — универсальном контейнере для всех документов организации. Вид корреспонденции определяется перечислением **ВидыКорреспонденции** со значениями:
- `Входящая` — для входящих писем
- `Исходящая` — для исходящих писем

Также существует отдельный объект **ВходящееПисьмо** (почтовый объект) — для электронной почты, импортируемой из почтовых клиентов. Он связывается с записью в ДокументыПредприятия через реквизит `Предмет`.

## 3. Регистрация входящего письма

### 3.1 Механизм нумерации

Нумерация документов реализована через специализированную инфраструктуру:

**Справочник Нумераторы** — хранит шаблоны номеров.

**Регистр сведений НастройкиНумерации** — связывает вид документа с нумератором:
- **Измерения:** ВидДокумента, ГрифДоступа, Назначение, Организация, Подразделение, ВопросДеятельности, Тематика, Проект, Контрагент, ТипДокумента, УзелКОД
- **Ресурсы:** Нумератор, СпособНумерации

Это означает, что для каждого вида входящего документа в разрезе организации и подразделения можно настроить свой нумератор.

**Общие модули нумерации:**
- `Нумерация` — основная логика, процедура `СформироватьЧисловойНомерДокумента`
- `НумерацияКлиент` — клиентская часть
- `НумерацияКлиентСервер` — общая часть
- `НумерацияПереопределяемый` — точки расширения

**Дополнительные регистры:**
- `ИндексыНумерации` — текущие значения счётчиков
- `НумерацияШК` — штрихкоды документов

### 3.2 Бизнес-процесс «Регистрация»

Входящее письмо регистрируется через **бизнес-процесс Регистрация**:

| Реквизит БП | Описание |
|---|---|
| Автор | Кто запустил процесс регистрации |
| Исполнитель | Регистратор (сотрудник, который регистрирует) |
| ДатаНачала / ДатаЗавершения | Сроки регистрации |
| СрокИсполнения | Срок регистрации |
| Состояние | Текущее состояние процесса |
| РезультатРегистрации | Результат: зарегистрировано / не зарегистрировано |
| ПовторитьРегистрацию | Признак повтора |
| ИсточникДанных | Предмет — ссылка на ДокументыПредприятия |

После завершения БП Регистрация в документе заполняются:
- `РегистрационныйНомер` (из нумератора)
- `ДатаРегистрации`
- `Зарегистрировал` (исполнитель из БП)

Состояние документа переходит: `НаРегистрации` → `Зарегистрирован`.

## 4. Бизнес-процессы по входящему письму

### 4.1 Полный список бизнес-процессов конфигурации

| Бизнес-процесс | Применимость к входящему |
|---|---|
| **Регистрация** | Да — обязательный первый шаг |
| **Рассмотрение** | Да — рассмотрение руководителем, наложение резолюции |
| **Исполнение** | Да — исполнение поручений по письму |
| **Согласование** | Редко — при необходимости согласовать ответ |
| **Ознакомление** | Да — ознакомление сотрудников с письмом |
| **Подписание** | Да — подписание ответного письма |
| **Утверждение** | Редко |
| **КомплексныйПроцесс** | Да — комбинированный маршрут |
| **РешениеВопросовВыполненияЗадач** | Сервисный |
| **Приглашение** | Нет |

### 4.2 Бизнес-процесс «Рассмотрение» — ключевой для входящих писем

| Реквизит | Описание |
|---|---|

| Резолюция | Текст резолюции |
| ВариантРассмотрения | Способ рассмотрения |

## 5. Жизненный цикл — состояния документа

Полный жизненный цикл входящего письма через состояния перечисления **СостоянияДокументов**:

```
[Создание] 
    → Проект
    → НаРегистрации         (бизнес-процесс Регистрация запущен)
    → НеЗарегистрирован     (регистрация отклонена)
    → Зарегистрирован       (регистрация завершена, номер присвоен)
    → НаРассмотрении        (бизнес-процесс Рассмотрение запущен)
    → НаОзнакомлении        (бизнес-процесс Ознакомление)
    → НаИсполнении          (бизнес-процесс Исполнение запущен)
    → НаДоработке           (возврат на доработку)
    → ОзнакомлениеЗавершено
    → Рассмотрен
    → Исполнен              (финальное состояние)
    → Отклонен
```

Дополнительные состояния (тст-расширение для DO3):
- тст_Черновик, тст_ОжидаетВозврата, тст_ТребуетсяАннулирование, тст_Аннулирован

## 8. Итоговая схема жизненного цикла

```
ВХОДЯЩЕЕ ПИСЬМО (ДокументыПредприятия, ВидКорреспонденции = Входящая)
│
├─ СОЗДАНИЕ
│   Реквизиты: Заголовок, Контрагент, Организация, ВидДокумента, ГрифДоступа...
│   Состояние: Проект
│
├─ РЕГИСТРАЦИЯ (БП «Регистрация»)
│   Исполнитель = Регистратор (сотрудник канцелярии)
│   Результат: РегистрационныйНомер + ДатаРегистрации
│   Состояние: НаРегистрации → Зарегистрирован
│   Регистры: НастройкиНумерации → ИндексыНумерации → РегистрационныйНомер
│             ДанныеДокументовПредприятия (обновляется)
│             ТекущиеСостоянияДокументов (Зарегистрирован)
│             ИсторияСостоянийДокументов (+запись)
│
├─ РАССМОТРЕНИЕ (БП «Рассмотрение»)
│   Исполнитель = Руководитель
│   Результат: Резолюция + Срок + Исполнитель
│   Состояние: НаРассмотрении → Рассмотрен
│
├─ ИСПОЛНЕНИЕ (БП «Исполнение»)
│   Исполнитель = Назначенный сотрудник
│   Контролёр = при необходимости
│   Состояние: НаИсполнении → [НаДоработке →] Исполнен
│   Регистры: ДанныеДокументовПредприятия (Исполнен = Истина)
│             ТекущиеСостоянияДокументов (Исполнен)
│
└─ ПАРАЛЛЕЛЬНО ВОЗМОЖНЫ:
    ├─ Ознакомление (ознакомить сотрудников)
    ├─ Согласование (согласовать ответ)
    └─ Подписание (подписать ответ)
```

## 9. Примечания по конфигурации DO3

Конфигурация содержит расширения с префиксом `тст_`, включающие:
- Дополнительные реквизиты: тст_БизнесПроцесс, тст_Договор, тст_ВидДеятельностиПризнак, тст_Брэнд
- Дополнительные ТЧ: тст_НастройкаПрав, тст_ПлатежноРасчетныеРеквизиты, тст_ГрифыУтверждения
- Дополнительные состояния: тст_Черновик, тст_Аннулирован и другие
- Дополнительные подписки: тст_РегистрацияДокументовТребующихАктуализации, тст_ПометкаСвязаныхДокументовНаУдаление
