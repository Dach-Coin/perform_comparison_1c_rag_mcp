## Что сервер НЕ дал

- **Тела процедур**: search_code показывает только начало (имя модуля + первые строки), не полный BSL-код
- **Точную последовательность вызовов**: какая процедура вызывает какую — цепочка не восстанавливается только по именам модулей
- **Механизм автоперехода Рассмотрение → Исполнение**: связь в метаданных не прямая, модуль найден но без тела
- **Код создания ВходящегоПисьма**: ВстроеннаяПочтаСервер найден, но конкретная процедура создания документа — нет

## Паттерны поведения агента

- Начал с `search_metadata` (неудачно — нет OpenAI key), быстро переключился на `get_metadata_prompt` + `execute_metadata_cypher`
- Cypher-стратегия оказалась наиболее результативной: 12 из 26 вызовов — Cypher, и все 12 высокорелевантны
- `search_code` дал смешанные результаты: 10 вызовов, из них 7 высокая + 3 средняя
- 3 нерабочих инструмента: search_metadata (нет OpenAI), semantic search (vector indexer не инициализирован), answer_metadata_question (нерелевантный контекст)
- Бизнес-отчёт: самый подробный по регистрам (включая ПисьмаВПапках, ИдентификаторыПолученныхПисем, ДвоичныеДанныеФайлов, ТекстыВерсийФайлов — уникальные находки)
- Агент указал уровень уверенности: «реквизиты — высокая, последовательность вызовов модулей — средняя» — честная самооценка
- Путаница с объектом Документ.Задача vs Задача.ЗадачаИсполнителя на шаге 3 — агент описал оба, но не разграничил чётко

## Выявленные проблемы RAG
| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| search_metadata недоступен (нет OpenAI key) | Вызов #1 вернул 0 результатов; пришлось использовать только Cypher для метаданных |
| Semantic search недоступен (vector indexer) | Вызов #12 вернул пустоту; retry на текстовый поиск |
| answer_metadata_question нерелевантен | Вызов #15 вернул контекст об ЭлементыСтиля и штрихкодах вместо бизнес-процессов |
| search_code обрезает тела процедур | Видны только имена модулей + начало, невозможно восстановить логику вызовов |
| Высокое количество вызовов | 26 вызовов vs 11 у двух других серверов — приходится дополнять метаданные кодом многими запросами |

## Вывод

Сервер graph-metadata уникально силён в точных метаданных через Cypher: полные реквизиты объектов с типами, структура регистров с измерениями/ресурсами, карта модулей конфигурации. Это делает его незаменимым для анализа структуры. Однако для сквозного сценария, где важна логика и последовательность действий, сервер ограничен: search_code показывает только начало процедур, а 3 из 6 инструментов фактически неработоспособны. Лучше всего подходит как дополнение к code-metadata — даёт структуру, которую другой сервер дополняет кодом.
