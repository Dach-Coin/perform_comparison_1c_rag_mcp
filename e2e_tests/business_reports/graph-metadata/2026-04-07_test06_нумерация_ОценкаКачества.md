## Что сервер дал хорошо

1. **execute_metadata_cypher** — главный рабочий инструмент (19 из 26 вызовов). Предоставил:
   - Полный список объектов нумерации (16 объектов с "нумер" в названии)
   - Полный список объектов регистрации (52 объекта с "регистрац")
   - Реквизиты Справочника.Нумераторы: ФорматНомера, Периодичность, 9 флагов НезависимаяНумерацияПо*, ИспользоватьПропущенныеНомера, тст_ДлинаЧисловогоНомера
   - Измерения и ресурсы РС.Нумерация (11 измерений + ТекущийНомер)
   - Полная структура РС.НастройкиНумерации (11 измерений, 2 ресурса)
   - **Значения перечислений** (уникальная находка!): СпособыНумерации (Вручную/Автоматически), НазначенияНумераторов, ПериодичностьНумераторов (5 значений), РезультатыРегистрации
   - БП.Регистрация — 42 элемента структуры (реквизиты, ТЧ, формы)
   - РС.ИндексыНумерации — составной тип измерения Объект
   - РС.ПропускиРегистрационныхНомеров — полная структура
   - ДокументыПредприятия — РегистрационныйНомер, ВременныйНомер, ЧисловойНомер, ДатаРегистрации, Зарегистрировал

2. **search_code** — нашёл ОМ.Нумерация с процедурой СформироватьЧисловойНомерДокумента

3. **get_metadata_prompt** — дал схему Neo4j для навигации по графу

4. **Бизнес-отчёт** — самый структурно полный: содержит все 4 регистра сведений с измерениями и ресурсами, все перечисления с их значениями, полную структуру БП.Регистрация, включая ШаблоныРегистрации и роли

## Что сервер НЕ дал

1. **Код процедур** — search_code дал только превью (имена процедур), но не полный алгоритм. Весовая система приоритетов нумераторов не обнаружена. Синтаксис ФорматНомера (переменные [Номер], [Год4]) не найден.

2. **answer_metadata_question** — вместо нумерации нашёл Мероприятия и ЭлементыСтиля (семантическая ошибка)

3. **search_metadata и business_search** — не работают (OpenAI API / Vector indexer недоступны)

4. **Алгоритм формирования номера** — как именно из ФорматНомера + ИндексыНумерации + ТекущийНомер собирается строковый номер — не раскрыто

## Паттерны поведения агента

- **Cypher-экспертиза**: после неудач с высокоуровневыми инструментами (#1, #2, #17) агент перешёл на прямые Cypher-запросы и работал с ними до конца — правильное решение
- **Декомпозиция запросов**: разбил исследование на мелкие Cypher-запросы (реквизиты отдельно, измерения отдельно, ресурсы отдельно) — эффективно, но привело к 26 вызовам
- **Одна ошибка синтаксиса** (#23 — OFFSET не поддерживается в Neo4j) — быстро обошёл
- **Минимальный размер ответов**: средний ответ ~1,300 символов — самый экономный сервер по токенам (35K символов суммарно vs 162K у cloud и 110K у code)

## Выявленные проблемы RAG
| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| answer_metadata_question семантический промах | Вопрос о нумерации → ответ о Мероприятиях и ЭлементыСтиля |
| search_metadata не работает | OpenAI API недоступен — инструмент полностью неработоспособен |
| business_search не работает | Vector indexer не инициализирован |
| Граф = дерево (метаданные) | Cypher-запросы дают только структуру (реквизиты, типы), но не алгоритмы и не код |
| HAS_ATTRIBUTE без контекста | Вызов #6: запрос на РС.Нумерация без указания категории вернул пустой результат |

## Вывод

Graph-metadata — лучший сервер для структурного анализа метаданных: компактные ответы (35K символов vs 162K и 110K), точные данные о типах и измерениях, уникальная возможность получить значения перечислений через Cypher. Критическая слабость — 3 из 6 инструментов не работают (answer_metadata_question, search_metadata, business_search). Для вопросов о коде и алгоритмах сервер подходит слабо — search_code даёт только превью.
