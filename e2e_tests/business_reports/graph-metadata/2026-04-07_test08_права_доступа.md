**Дата анализа:** 2026-04-07  
**Источник:** MCP-сервер 1c-graph-metadata (Neo4j, граф метаданных)  
**Тест:** TEST-08

## 1. Объектная модель задач

В конфигурации существуют два принципиально разных объекта "задача":

### 1.1 Документ.Задача (прикладной объект)
Используется для ручных/самостоятельных задач сотрудников:

| Реквизит | Тип | Назначение |
|----------|-----|-----------|
| Автор | ОпределяемыйТип.УчастникЗадач | Кто создал |
| Ответственный | ОпределяемыйТип.УчастникЗадач | Контролирует |
| Создал | Сотрудники / Пользователи | Технический автор |
| КтоОтменил | ОпределяемыйТип.УчастникЗадач | Отменивший |
| ВышестоящаяЗадача | ДокументСсылка.Задача | Иерархия задач |
| Проект | Справочник.Проекты | Привязка к проекту |

**Табличные части:**
- **Участники** (Участник, ВидУчастника, ДействиеУчастника) — список участников задачи
- **Приложения** (Приложение) — вложения

### 1.2 Задача.ЗадачаИсполнителя (платформенный объект)
Задача бизнес-процесса (поручение в маршруте):

| Реквизит | Тип | Назначение |
|----------|-----|-----------|
| ТекущийИсполнитель | Сотрудники / ПолныеРоли / Пользователи | Кому назначена |
| Автор | Сотрудники / Пользователи | Кто запустил процесс |
| ФактическийИсполнитель | Справочник.ФактическиеИсполнители | Кто выполнил |
| ПринятаКИсполнению | Булево | Принята ли |
| Отменена | Булево | Отменена ли |

## 2. Роли, определяющие доступ к задачам

### 2.1 Ролевая матрица

| Роль | Назначение | Уровень доступа |
|------|-----------|-----------------|
| **ЧтениеЗадач** | Просмотр задач | Базовый (с ограничениями RLS) |
| **РаботаСЗадачами** | Работа со своими задачами | Пользователь |
| **РаботаСЗадачамиИБизнесПроцессами** | + бизнес-процессы | Пользователь расширенный |
| **ИзменениеВыполнениеЗадач** | Изменение и выполнение | Активный исполнитель |
| **РаботаСЗадачамиСотрудниковПодразделения** | Задачи сотрудников подразделения | Руководитель подразделения |
| **КонтрольЗадачИБизнесПроцессов** | Контроль всех задач и процессов | Контролёр / руководитель |
| **ЧтениеПроцессовИЗадачБезОграничения** | Чтение без ограничений RLS | Администратор / аналитик |

### 2.2 Ключевые выводы по ролям

- Обычный сотрудник получает **РаботаСЗадачами** — видит только свои задачи (где он автор, исполнитель или участник).
- Руководитель подразделения получает **РаботаСЗадачамиСотрудниковПодразделения** — дополнительно видит задачи подчинённых.
- Контролёр получает **КонтрольЗадачИБизнесПроцессов** — видит все задачи для целей контроля.
- Роль **ЧтениеПроцессовИЗадачБезОграничения** снимает все RLS-ограничения — используется для служебных задач (отчёты, интеграции).

## 3. Может ли сотрудник видеть задачи других сотрудников?

### Ответ: ПО УМОЛЧАНИЮ — НЕТ. Но есть исключения.

Сотрудник видит чужие задачи только если выполняется одно из условий:

1. **Он указан в табличной части "Участники"** задачи (с любым видом участия).
2. **Он является ответственным или автором** задачи (реквизиты Ответственный, Автор).
3. **Он попал в рабочую группу** объекта через РегистрСведений.РабочиеГруппы.
4. **Он руководитель** и включена константа **ДобавлятьРуководителямДоступПодчиненных**.
5. **Ему назначена роль** КонтрольЗадачИБизнесПроцессов или ЧтениеПроцессовИЗадачБезОграничения.

### Механизм ВидыУчастниковЗадач

Вид участника задачи определяет права внутри задачи:

| Флаг | Значение |
|------|---------|
| ЭтоИсполнитель | Участник выполняет задачу |
| ЭтоОтветственный | Участник контролирует выполнение |
| ЭтоПроверяющий | Участник проверяет результат |

## 4. Ограничение на уровне записей (RLS) для задач

### 4.1 Главный переключатель

Система RLS управляется константами:
- **ОграничиватьДоступНаУровнеЗаписей** — глобальный переключатель RLS платформы
- **ДокументооборотВключитьПраваДоступа** — включение прав ДО (прикладной уровень)
- **ДокументооборотИспользоватьОграничениеПравДоступа** — использование ограничения
- **ДокументооборотИспользоватьОтложенноеОбновлениеПравДоступа** — отложенное пересчитывание

### 4.2 Регистры RLS для задач

| Регистр | Измерения | Назначение |
|---------|-----------|-----------|
| **РегистрСведений.РабочиеГруппы** | Участник + Объект (вкл. Задача) | Основная таблица RLS — кто видит какой объект |
| **РегистрСведений.ЗадачиПоАвторам** | Задача + Автор + Дата | Индекс задач по авторам + состояние |
| **РегистрСведений.СведенияОбИсполнителяхЗадач** | Задача + Участник | Связь задача→участник для RLS |
| **РегистрСведений.ВсеИсполнителиДействийЗадач** | ДействиеЗадачи + Исполнитель + Основание | С учётом замещения |
| **РегистрСведений.НастройкиПравОбъектов** | Объект + Пользователь + Право | Тонкая настройка прав |
| **РегистрСведений.НаследованиеНастроекПравОбъектов** | Объект + Родитель | Наследование прав от родителя |
| **РегистрСведений.ПараметрыОграниченияДоступа** | Версия | Шаблоны RLS для сессий |

### 4.3 Схема работы RLS

```
Пользователь запрашивает список задач
            ↓
[Роль ЧтениеПроцессовИЗадачБезОграничения?]
    Да → показать все
    Нет ↓
[Применить RLS-шаблон из ПараметрыОграниченияДоступа]
            ↓
Фильтр по РегистрСведений.РабочиеГруппы
    WHERE Участник = ТекущийПользователь
      AND Объект = Задача (ДокументСсылка.Задача)
            ↓
Показать только задачи из рабочей группы
```

## 5. Как связаны рабочие группы с доступом к документам

### 5.1 Структура рабочей группы

**Справочник.РабочиеГруппы:**
- Ответственный (Сотрудники/Пользователи)
- Автозаполнение (Булево) + АлгоритмАвтозаполнения
- ТабЧасть.Состав → Участник (Сотрудники)

**РегистрСведений.РабочиеГруппы** (основной регистр доступа):

| Измерение | Тип | Смысл |
|-----------|-----|-------|
| Участник | КонтейнерыСотрудников | Сотрудник / роль / подразделение |
| Объект | Составной тип | К какому объекту доступ |

Тип измерения **Объект** включает: Задача, ДействиеЗадачи, ДокументыПредприятия, Проекты, ПроектныеЗадачи, ТемыОбсуждений, Мероприятия, все шаблоны процессов.

**Ресурсы:**
- **Изменение** (Булево) — есть ли право на изменение (или только чтение)
- **Источник** — откуда появилась запись (документ, процесс, явная настройка)
- **Автоподстановка** — алгоритм автозаполнения

### 5.2 Автоматическое обновление рабочих групп

Система обновляет рабочие группы автоматически:
- **ПодпискаНаСобытие.РабочиеГруппыДокументыПередЗаписью / ПриЗаписи** — при записи документа
- **ПодпискаНаСобытие.РабочиеГруппыБизнесПроцессыПередЗаписью / ПриЗаписи** — при записи бизнес-процесса
- **ПодпискаНаСобытие.ЗадачаПриЗаписи** — при записи задачи
- **РегламентноеЗадание.ОбновлениеАвтозаполняемыхРабочихГрупп** — фоновое обновление
- **РегламентноеЗадание.ОбработкаОчередиРасширенияРабочихГрупп** — асинхронная обработка очереди

### 5.3 Видимость действий (процессных задач) в предметах

Управляется через Справочник.ВидыДействий.НастройкаВидимости = **ВидимостьДействийВПредметах**:

| Значение | Кто видит действие в карточке предмета |
|----------|----------------------------------------|
| **Всем** | Все пользователи системы |
| **АвторамИОтветственным** | Только автор и ответственный документа |
| **УчастникамДействия** | Только назначенные исполнители |
| **Никому** | Скрыто от всех (служебное действие) |

## 6. Общий модуль РаботаСРабочимиГруппами

### 6.1 Расположение и состав

| Модуль | Тип | Назначение |
|--------|-----|-----------|
| **РаботаСРабочимиГруппами** | Серверный | Основная логика работы с рабочими группами |
| **РаботаСРабочимиГруппамиКлиент** | Клиентский | Клиентские обёртки |

Из доступных фрагментов кода известно, что модуль содержит:
- Раздел **"ФУНКЦИИ ДЛЯ РАБОТЫ С РАБОЧЕЙ ГРУППОЙ ДОКУМЕНТА"**
- Функцию **перезаписи участников рабочей группы** документа

### 6.2 Смежные модули прав доступа

| Модуль | Назначение |
|--------|-----------|
| **ДокументооборотПраваДоступа** | ПраваСотрудникаПоОбъекту() — основная функция проверки прав |
| **ДокументооборотПраваДоступаПереопределяемый** | ЗапросНаПраваПоОбъекту() — переопределяемая часть |
| **ДокументооборотПраваДоступаПовтИсп** | Кеширование прав |
| **ДокументооборотПраваДоступаХолдинг** | Права в холдинговой структуре |
| **УправлениеДоступомДокументооборот** | Интеграция с БСП УправлениеДоступом |
| **ПраваДоступаНаБизнесПроцессы** | Участники процесса → объект доступа |
| **НастраиваемоеДелегированиеПрав** | Области делегирования прав |
| **НастройкиДоступа** | Настройки разрезов доступа |

### 6.3 Группы доступа (БСП)

Стандартный механизм БСП используется через:
- **Справочник.ГруппыДоступа** (Профиль, ТабЧасти: Пользователи, ЗначенияДоступа, ВидыДоступа)
- **Справочник.ПрофилиГруппДоступа** (поставляемые профили)
- **ПланВидовХарактеристик.ВидыДоступа** (разрезы: по документу, организации и т.д.)
- **РегистрСведений.ЗначенияГруппДоступа** (ГруппаДоступа + ВидДоступа + ЗначениеДоступа)
- **РегистрСведений.ПраваГруппДоступаНаТаблицы** (права группы на таблицы БД)

## 7. Сводная схема системы прав доступа к задачам

```
┌─────────────────────────────────────────────────────────────┐
│              СИСТЕМА ПРАВ ДОСТУПА К ЗАДАЧАМ                  │
└─────────────────────────────────────────────────────────────┘

Уровень 1: РОЛИ КОНФИГУРАЦИИ
├── ЧтениеЗадач                    ← видит с ограничениями RLS
├── РаботаСЗадачами                ← свои задачи
├── РаботаСЗадачамиИБизнесПроцессами
├── ИзменениеВыполнениеЗадач
├── РаботаСЗадачамиСотрудниковПодразделения  ← + подчинённые
├── КонтрольЗадачИБизнесПроцессов  ← все задачи
└── ЧтениеПроцессовИЗадачБезОграничения ← без RLS

Уровень 2: RLS (при включённой константе ОграничиватьДоступНаУровнеЗаписей)
├── РегистрСведений.РабочиеГруппы
│   ├── Измерение: Участник (Сотрудник/Роль/Подразделение)
│   └── Измерение: Объект → ДокументСсылка.Задача
├── РегистрСведений.ЗадачиПоАвторам (Задача + Автор)
└── РегистрСведений.СведенияОбИсполнителяхЗадач (Задача + Участник)

Уровень 3: ТОНКАЯ НАСТРОЙКА ПРАВ ОБЪЕКТА
├── РегистрСведений.НастройкиПравОбъектов
│   └── (Объект + Пользователь + Право → Разрешено/Запрещено)
└── РегистрСведений.НаследованиеНастроекПравОбъектов

Уровень 4: ВИДИМОСТЬ ДЕЙСТВИЙ В ПРЕДМЕТАХ
└── Справочник.ВидыДействий.НастройкаВидимости
    └── Всем / АвторамИОтветственным / УчастникамДействия / Никому

Уровень 5: ГРИФЫ ДОСТУПА (при ИспользоватьГрифыДоступа = Истина)
└── Дополнительный фильтр по грифу (ДСП, Конфиденциально и т.д.)
```

## 8. Практические рекомендации

1. **Для аудита прав** — проверять содержимое РегистрСведений.РабочиеГруппы по конкретной задаче.
2. **Для расширения доступа** — добавить сотрудника в табличную часть Участники задачи или явно в рабочую группу.
3. **При проблемах с видимостью** — проверить константы ДокументооборотВключитьПраваДоступа и ОграничиватьДоступНаУровнеЗаписей.
4. **Для руководителей** — использовать роль РаботаСЗадачамиСотрудниковПодразделения или включить константу ДобавлятьРуководителямДоступПодчиненных.
5. **Для контроллёров/аналитиков** — роль КонтрольЗадачИБизнесПроцессов или ЧтениеПроцессовИЗадачБезОграничения.
6. **Отложенное обновление** — при массовых изменениях пользователей использовать ДокументооборотИспользоватьОтложенноеОбновлениеПравДоступа.
