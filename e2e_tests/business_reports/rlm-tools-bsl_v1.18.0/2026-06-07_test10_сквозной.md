## Шаг 1. Поступление ВходящегоПисьма

### Создаваемый объект
**Документ.ВходящееПисьмо** — непроводимый документ электронной почты.

**Структура (из MCP — get_object_full_structure):**
- 23 атрибута: ВидМаршрутизации (`EnumRef.ВидыМаршрутизацииПисем`), ДатаОтправки, ДатаПолучения
- 4 табличные части: ПолучателиПисьма, ПолучателиКопий, ПолучателиОтвета, АдресаУведомленияОПрочтении
- Формы: ФормаДокумента, ФормаВыбора, ОповещенияОНовыхПисьмах

### Бизнес-процессы при сохранении
Нет запускаемых бизнес-процессов — документ записывается через обычную запись (Posting=Deny).

### Обновляемые регистры (из MCP — ПриЗаписи, get_object_full_structure)
| Регистр | Тип | Событие | Что делается |
|---|---|---|---|
| `РС КоличествоПисемВПапках` | Сведений | ПриЗаписи | Пересчёт количества писем в папке при смене папки |
| `РС ПисьмаВеток` | Сведений | ПриЗаписи | ОпределитьВеткуДляЧерновика — привязка к ветке переписки |
| `РС СведенияОбАдресатах` | Сведений | ПриЗаписи | Связь почтового адреса отправителя с карточкой контакта |

### Обрабатывающий код (из MCP — read_procedure)

**`Documents/ВходящееПисьмо/Ext/ObjectModule.bsl`**

| Процедура | Строки | Назначение |

## Шаг 2. Рассмотрение письма и вынесение Резолюции

### Создаваемый объект
**БизнесПроцесс.Рассмотрение** — запускается руководителем вручную (из карточки письма или папки входящих).

**Структура (из MCP — get_object_full_structure):**
- 59 атрибутов, ключевые:
  - `Резолюция` (xs:string) — текст резолюции руководителя
  - `Исполнитель` (CatalogRef.Сотрудники | ПолныеРоли) — кому исполнять
  - `КонтролерИсполнения` — контролёр
  - `ВариантОбработкиРезолюции` (`EnumRef.ВариантыОбработкиРезолюции`) — по умолчанию `НаправитьНаИсполнение`
  - `ВариантРассмотрения` (`EnumRef.ВариантыРассмотрения`) — по умолчанию `Рассмотрено`
  - `Шаблон` (CatalogRef.ШаблоныРассмотрения) — шаблон процесса
- 5 табличных частей: ИсполнителиИсполнения (11 колонок), ИсполнителиОзнакомления, Предметы, ПредметыЗадач, ДополнительныеРеквизиты
- В ТЧ `Предметы` хранится DocumentRef.ВходящееПисьмо как предмет процесса

### Инициализация при создании (из MCP — ОбработкаЗаполнения)

**`BusinessProcesses/Рассмотрение/Ext/ObjectModule.bsl` стр. 803–985:**
```bsl
// При создании нового Рассмотрения из ВходящегоПисьма:
Мультипредметность.ПередатьПредметыПроцессу(ЭтотОбъект, ДанныеЗаполнения, Ложь, Истина);
// ВходящееПисьмо автоматически попадает в ТЧ Предметы
ВариантОбработкиРезолюции = Перечисления.ВариантыОбработкиРезолюции.НаправитьНаИсполнение;
```

### Запускаемые бизнес-процессы
После заполнения резолюции и старта БП — в точке маршрута "Рассмотреть" вызывается:

**`BusinessProcesses/Рассмотрение/Ext/ObjectModule.bsl` стр. 1202–1241:**
```bsl
Процедура РассмотретьПередСозданиемЗадач(ТочкаМаршрутаБизнесПроцесса, ФормируемыеЗадачи, СтандартнаяОбработка)
    Задача = Задачи.ЗадачаИсполнителя.СоздатьЗадачу();
    Задача.РезультатВыполнения = Резолюция; // текст резолюции
    Задача.БизнесПроцесс = ЭтотОбъект.Ссылка;
    Задача.ТочкаМаршрута = ТочкаМаршрутаБизнесПроцесса;
    // ...исполнитель, срок, проект...
    ФормируемыеЗадачи.Добавить(Задача);
```

Платформа автоматически создаёт задачу `Tasks.ЗадачаИсполнителя` (системный объект).

### Модуль РаботаСРезолюциями (из MCP — find_exports)
**`CommonModules/РаботаСРезолюциями/Ext/Module.bsl`** — 7 экспортов:
- `ПолучитьРезолюции(Документ, ТолькоАктивные, ПолучитьДанныеЭП, Источник, ИдентификаторУчастника)` стр. 42 — получение всех резолюций документа
- `ПолучитьСтруктуруКлючевыхРеквизитовРезолюции()` стр. 13 — ключевые реквизиты
- `ЭтоАвторРезолюции(Резолюция, Пользователь)` стр. 222 — проверка авторства

## Шаг 3. Создание Задачи по резолюции

### Создаваемый объект
**Документ.Задача** — создаётся явно (через кнопку или программно).

**Структура (из MCP — get_object_full_structure):**
- 30 атрибутов, ключевые:
  - `ВидЗадачи` (CatalogRef.ВидыЗадач)
  - `СостояниеЗадачи` (CatalogRef.СостоянияЗадач)
  - `Источник` — связь с основанием (письмо, резолюция)
  - `ВышестоящаяЗадача` (DocumentRef.Задача) — иерархия задач
  - `ВышестоящееДействие` (DocumentRef.ДействиеЗадачи)
  - `Ответственный`, `Автор`, `Срок`, `Проект`, `Контрагент`
- 2 ТЧ: Приложения (`[Приложение]`), Участники (`[ВидУчастника, ДействиеУчастника, Участник, ВнешнийИдентификатор]`)

### Метод создания задачи (из MCP — read_procedure)
**`CommonModules/РаботаСЗадачами/Ext/Module.bsl` стр. 9330–9369:**
```bsl
Функция СоздатьЗадачу(ВидЗадачи, ОтКого, Кому, Заголовок, Описание, Срок) Экспорт
    НачатьТранзакцию();
    ЗадачаОбъект = Документы.Задача.СоздатьДокумент();
    ЗадачаОбъект.Заполнить(ПараметрыЗаполнения);
    ЗадачаОбъект.УстановитьУчастника(Кому, ДанныеВидаЗадачи.ВидУчастникаИсполнитель);
    ЗадачаОбъект.Записать(РежимЗаписиДокумента.Проведение);
    НаправитьНаИсполнение(ЗадачаОбъект.Ссылка);
    ЗафиксироватьТранзакцию();
```

**Связь с Рассмотрением — `BusinessProcesses/Исполнение/Ext/ObjectModule.bsl` стр. 478–537:**
```bsl

    Мультипредметность.ПередатьПредметыПроцессу(ЭтотОбъект, Рассмотрение);
    Исполнители.Загрузить(Рассмотрение.ИсполнителиИсполнения.Выгрузить());
```

## Шаг 4. Исполнение задачи и прикрепление файла-ответа

### Объект — ДействиеЗадачи
При направлении задачи на исполнение платформа создаёт документ `ДействиеЗадачи` для каждого участника-исполнителя (создаётся в `ПередЗаписью` задачи, строки 2030–2037).

### Взятие задачи в работу
**`Documents/Задача/Ext/ObjectModule.bsl` стр. 648–674:**
```bsl
Процедура ОтметитьВРаботе() Экспорт
    // Для каждого участника-исполнителя:
    ДействиеУчастникаОбъект.УстановитьСостояние(
        ДанныеВидаЗадачи.СостояниеУчастниковВРаботе,
        Сотрудники.ОсновнойСотрудник(), Ложь);
    ДействиеУчастникаОбъект.Записать(РежимЗаписиДокумента.Проведение);
```

### Прикрепление файла-ответа (из MCP — read_procedure)
**`CommonModules/РаботаСЗадачами/Ext/Module.bsl` стр. 1605–1673:**
```bsl
Функция ДобавитьПриложения(Действие, Приложения, КтоОтметил, ВзятьВРаботуАвтоматически) Экспорт
    НачатьТранзакцию();
    ДействиеОбъект = Действие.ПолучитьОбъект(); // Документ.ДействиеЗадачи
    // Файл добавляется в ТЧ ДействиеЗадачи.Приложения
    СтрокаПриложения = ДействиеОбъект.Приложения.Добавить();
    СтрокаПриложения.Приложение = Приложение;
    ДействиеОбъект.Записать();
    // Если задача новая — автоматически взять в работу
    Если ВзятьВРаботуАвтоматически И ЭтоНовоеДействие Тогда
        ВзятьВРаботу(Действие, КтоОтметил);
```

Файл-ответ хранится как элемент справочника `Справочник.Файлы` и прикрепляется к `ДействиеЗадачи` через ТЧ Приложения.

### Выполнение задачи (из MCP — read_procedure)
**`CommonModules/РаботаСЗадачами/Ext/Module.bsl` стр. 1227–...**
```bsl
Процедура ВыполнитьДействиеЗадачи(ДействиеЗадачи, РезультатДействия, КтоОтметил, ПараметрыВыполнения) Экспорт
    // Проверка прав: ДокументооборотПраваДоступа.ПраваПользователяПоОбъекту
    ВыполнениеОбработано = ИнтеграцияЗадач.ОбработатьВыполнениеДействияЗадачи(...);
    // Если РезультатДействия = Выполнена И нет проверяющего:
    ДействиеЗадачиОбъект.УстановитьСостояние(СостояниеУчастниковВыполнена, КтоОтметил, Истина);
    // Если есть проверяющий:
    ДействиеЗадачиОбъект.УстановитьСостояние(СостояниеУчастниковОжидаетПроверки, ...);
```

**`Documents/Задача/Ext/ObjectModule.bsl` стр. 748–774:**

## Итоговая оценка

**ПОЛНОСТЬЮ**

Сквозной сценарий полностью прослежен на уровне кода конфигурации:
- Установлена цепочка объектов: ВходящееПисьмо → БП Рассмотрение (с резолюцией) → ЗадачаИсполнителя (системная задача маршрута) → Документ.Задача → ДействиеЗадачи → ИсходящееПисьмо
- Для каждого шага определены создаваемые объекты, обновляемые регистры, обрабатывающие модули с номерами строк
- Ключевые методы прочитаны из исходного кода: РассмотретьПередСозданиемЗадач, ЗаполнитьПоРассмотрению, СоздатьЗадачу, ВыполнитьДействиеЗадачи, ДобавитьПриложения, ОтветитьНаПисьмо
- Все данные получены исключительно через инструменты rlm-tools-bsl (37 вызовов)
