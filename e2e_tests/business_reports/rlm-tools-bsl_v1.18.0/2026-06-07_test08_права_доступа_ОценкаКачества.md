# Оценка качества: TEST-08 — Права доступа к задачам
**Сервер:** rlm-tools-bsl (v1.18.0)
**Дата:** 2026-06-07
**Оценщик:** Оркестратор (Claude Opus 4.8, 1M context)

## Общая оценка: ПОЛНОСТЬЮ

Все 5 подвопросов закрыты по объекту **`Document.Задача`** (объект из промпта): **11 ролей** доступа (главные — `КонтрольЗадачИБизнесПроцессов` без RLS, `РаботаСЗадачами` с RLS, `ЧтениеПроцессовИЗадачБезОграничения`; кастомные `тст_*`); **видимость чужих задач** — обычный сотрудник видит только свои (RLS), исключения: `КонтрольЗадачИБизнесПроцессов`, заместители (через `ЗамещающиеИПомощники` в RLS), руководители через `ДоступныЗадачиПодчиненных`→`ЭтоРуководительИлиПомощник`; **RLS** — `#ПоДескрипторуОбъекта` + SQL к `ДескрипторыДляОбъектов`/`ПраваПоДескрипторамДоступаОбъектов`, управляется константой `ДокументооборотИспользоватьОграничениеПравДоступа`; **рабочие группы** — РС `РабочиеГруппы` (Объект+Участник), формируется `ЗаполнитьДескрипторыОбъекта` (`Documents/Задача/Ext/ManagerModule.bsl` [868–952]); **ключевые модули** — `ДокументооборотПраваДоступа` (87 exports) + `РаботаСРабочимиГруппами` (47 exports).

> **Сверка с источником (оркестратор):** `Document.Задача` + `#ПоДескрипторуОбъекта` в `Roles\РаботаСЗадачами\Ext\Rights.xml`. v1.18.0 **заякорился на объекте из промпта верно** — это ровно тот пункт, где в раунде 2 bsl-indexer ошибся (сместился на платформенную `Task.ЗадачаИсполнителя`, RLS `#ЧтениеПроцесса`), а rlm ответил по `Document.Задача`. v1.18.0 повторил корректное поведение: **ЧАСТИЧНО у bsl → ПОЛНОСТЬЮ у rlm сохраняется**.

## Что сервер дал хорошо
- **Ролевой инвентарь + RLS из XML** (#4, #15–18, #20–21): 11 ролей через `find_roles`, 51 RLS-ограничение по `#ПоДескрипторуОбъекта` через `git_search`, полный RLS-запрос `Document.Задача` (стр. 812–860) с SQL и UNION заместителей.
- **Алгоритм рабочей группы построчно** (#33–34): `ЗаполнитьДескрипторыОбъекта` (Автор/Создал/Участники/Руководитель проекта/Все исполнители действий/Контролеры/Участники процессов) — стр. 868–952.
- **Механизм дескрипторов** (#24): структуры `ДескрипторыДляОбъектов` и `ПраваПоДескрипторамДоступаОбъектов` (Добавление/Изменение/Удаление/УправлениеПравами/Чтение).
- **Доступ руководителя** (#39–40): `ДоступныЗадачиПодчиненных` → `ЭтоРуководительИлиПомощник` (области замещения `ЗадачиПросмотр`/`Задачи`).
- **Профили доступа** (#37–38): связь роли `КонтрольЗадач` с профилем через `УправлениеДоступомПереопределяемый`.

## Что сервер НЕ дал
- **Права роли `РаботаСЗадачамиСотрудниковПодразделения`** — определены программно, не в Rights.xml (отмечено агентом как додумывание).
- **Полный список профилей доступа** — прочитан фрагмент.
- Точное обращение к XML потребовало 3 retry (формат пути/кавычки) — мелкие трения синтаксиса.

## Паттерны поведения агента
- Цикл: `search_objects`+`find_roles` → `get_object_full_structure` → `find_module`/`find_exports` (РаботаСРабочимиГруппами) → `git_search` (RLS в Roles) → `read_file`/`read_procedure` (RLS-запрос, дескрипторы) → `find_event_subscriptions` → ManagerModule (`ЗаполнитьДескрипторыОбъекта`).
- 3 retry (формат `params`, путь `parse_object_xml`, кавычки `git_search`) — все быстро исправлены.
- Самый объёмный прогон раунда по числу вызовов (41), профиль ровный без ⚠️.

## Вывод
rlm-tools-bsl v1.18.0 закрыл TEST-08 полностью и — что важно — **по объекту из промпта** (`Document.Задача`), точно воспроизведя RLS-механизм `#ПоДескрипторуОбъекта` с SQL-запросом и алгоритм формирования рабочей группы. Это тот самый тест, где bsl-indexer в раунде 2 получил ЧАСТИЧНО из-за смещения на `Task.ЗадачаИсполнителя`; v1.18.0 сохранил преимущество rlm. Цена — самый длинный прогон раунда (41 вызов, ≈175K) и 3 мелких retry на синтаксисе путей/кавычек, но без ⚠️ и с 98% полезных.
