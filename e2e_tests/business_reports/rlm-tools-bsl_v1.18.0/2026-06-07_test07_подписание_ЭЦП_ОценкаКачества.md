# Оценка качества: TEST-07 — Электронные подписи и подписание
**Сервер:** rlm-tools-bsl (v1.18.0)
**Дата:** 2026-06-07
**Оценщик:** Оркестратор (Claude Opus 4.8, 1M context)

## Общая оценка: ПОЛНОСТЬЮ

Все 5 подвопросов закрыты: **БП Подписание** (20 реквизитов, 7 ТЧ; `СпособПодписания` НаБумаге/ПЭП/УЭП, `РезультатПодписания`, шаблон `ШаблоныПодписания`); **ЭЦП поддержана полно** — 12 форматов криптоподписи (`ОбычнаяCMS`…`АрхивнаяCAdESAv3`), МЧД; **хранение** — РС `ЭлектронныеПодписи` (измерения `ПодписанныйОбъект`+`ПорядковыйНомер`, ресурсы Подпись/Сертификат ValueStorage + 21 поле) + РС `ЭлектронныеПодписиПоМЧД`; реквизит `ПодписанЭП` (Boolean) у 5 объектов (ДокументыПредприятия, Файлы, ВерсииФайлов, Мероприятия, РС ДанныеДокументовПредприятия); **после подписания** — перечисление `СтатусПроверкиЭП` (4 значения) через `ПриЗаписиЭлектронныхПодписей` → `УстановитьСтатусПроверкиДляДокумента`; **модули** — `РаботаСЭП` (126 процедур), `ЭлектроннаяПодпись` (49 exports, ядро БСП), `ЭлектроннаяПодписьДокументооборот*`.

## Что сервер дал хорошо
- **Структура БП + РС подписей** (#5, #7): 20 реквизитов/7 ТЧ БП и полная структура РС `ЭлектронныеПодписи` (измерения + 21 ресурс) одним структурным вызовом.
- **Полный реестр форматов подписи** (#27): перечисление `ТипыПодписиКриптографии` — 12 значений CAdES, `ФункцииУчастниковПодписания`.
- **Цепочка смены статуса построчно** (#29, #31–32): `ПриЗаписиЭлектронныхПодписей` → `УстановитьСтатусПроверкиДляДокумента` (стр. 1352) → `СтатусПроверкиЭП` (4 значения); `СнятьПризнакПодписанЭП` (сброс `ПодписанЭП`).
- **`find_attributes('ПодписанЭП')`** (#30): точный список 5 объектов с реквизитом — структурный ответ вместо догадки.
- **Глубокий модуль РаботаСЭП** (#28): 126 процедур, ключевые с номерами строк.

## Что сервер НЕ дал
- **Без потерь по сути, но 2 ошибки кода** (#8–9): доступ к `params` как к словарю на `list[str]` — два пустых вызова до исправления (типичная «грабля» формата возврата хелперов).
- **Прямого обновления статуса документа внутри `ДействияПодписания`** (#23) нет — нулевой результат, статус идёт через `РаботаСЭП`.

## Паттерны поведения агента
- Цикл: `search_objects` → `get_object_full_structure` (БП + РС) → `find_enum_values` (форматы) → `find_exports`/`extract_procedures` (РаботаСЭП, ЭлектроннаяПодпись) → `read_procedure` (статусы) → `find_attributes`.
- 2 retry вокруг одной причины (#8→9→10): неверный обход `params`; после исправления — чисто.
- Самый высокий расход «процессных» тестов (≈185K) из-за глубины РаботаСЭП; профиль ровный, без ⚠️.

## Выявленные проблемы
| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| Формат `params` (list[str]) провоцирует ошибки доступа | #8–9 два пустых вызова → retry |
| `rlm_projects` не вызван (стартовал прямо по project) | health-цепочка короче, но сессия открылась корректно |
| Поиск «статуса» внутри неверного файла | #23 нулевой результат |

## Вывод
rlm-tools-bsl v1.18.0 закрыл TEST-07 полностью при ≈185K токенов, без ⚠️: структурные хелперы дали инвентарь БП и РС хранения подписей, `find_enum_values` — полный реестр 12 криптоформатов, а `read_procedure` развернул реальную цепочку смены `СтатусПроверкиЭП`. Единственное трение — две ошибки доступа к `params` (list[str]), стоившие 2 пустых вызова. Для вопроса «как реализовано подписание — параметры, ЭП, хранилище, статус, модули» сервер дал верифицируемый и полный ответ.
