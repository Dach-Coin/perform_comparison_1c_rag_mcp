## 2. Процесс отправки документа через МЭДО

### 2.1. Общая схема (модуль `CommonModules/МЭДО/Ext/Module.bsl`)

Весь обмен организован файловым способом — через каталоги отправки и получения (настройка в РС НастройкиОрганизацийМЭДО). Поддерживаются два способа (СпособыОбменаМЭДО): **Диск/локальная сеть** и **FTP**. HTTP REST-сервис специально для МЭДО отсутствует.

#### Точка входа: `ВыполнитьОбменМЭДО()` (строки 238–284)
```
ВыполнитьОбменМЭДО() — экспортная процедура, вызывается регламентным заданием
  ├─ читает РС НастройкиОрганизацийМЭДО (организация, КаталогПолучения, КаталогОтправки)
  ├─ для каждой настроенной организации:
  │   ├─ ПолучитьВходящиеСообщения(Настройки)          [строки 294–365]
  │   ├─ ОтправитьИсходящиеКвитанции(Настройки, ...)   [строки 409–447]
  │   ├─ ОтправитьИсходящиеДокументы(Настройки, ...)   [строки 377–396]
  │   └─ ОтправитьИсходящиеУведомления(Настройки, ...) [строки 459–473]
  └─ ОчиститьСтарыеЗаписиЖурнала(...)
```

#### Процедура отправки одного документа: `ОтправитьИсходящийДокумент()` (строки 3041–3092)
```
ОтправитьИсходящийДокумент(Настройки, ИсходящийДокумент, ДанныеОтвета)
  ├─ МЭДОПереопределяемый.ДанныеИсходящегоДокументаДляОтправки(...)   [стр. 624–906]
  ├─ для каждого пакета по версии МЭДО получателей:
  │   ├─ ЗаписатьСодержимоеКонтейнераИсходящегоДокумента(...)          [стр. 3099–3163]
  │   │   ├─ создаёт временный каталог
  │   │   ├─ СоздатьПаспортКонтейнераИсходящегоДокумента() → passport.xml  [стр. 3174–3396]
  │   │   ├─ записывает файл документа (pdf)
  │   │   ├─ записывает регистрационный штамп (png)
  │   │   └─ записывает файлы подписей (p7s) + отметки ЭП
  │   └─ ЗаписатьСообщениеПоИсходящемуДокументу(КаталогОтправки, ...)  [стр. 3404–3638]
  └─ при ошибке: ДанныеДокументаМЭДО.СнятьПризнакГотовКОтправке(...)
```

#### Формат паспорта контейнера: `СоздатьПаспортКонтейнераИсходящегоДокумента()` (строки 3174–3396)
Формирует XML-файл `passport.xml` по XDTO-схеме формата МЭДО 2.7 / 2.7.1:
- `container.uid` — идентификатор документа
- `container.requisites.documentKind` — вид документа (CatalogRef.ВидыДокументовМЭДО)
- `container.requisites.documentPlace` — место составления (обязательно для 2.7.1)
- `container.requisites.classification` — гриф доступа
- Отправитель, получатели, регистрационный номер, дата, подписи

#### Получение входящих: `ПолучитьВходящиеСообщения()` (строки 294–365)
- Сканирует каталог получения, паки ZIP → обрабатывает через `ОбработатьВходящееЭСД()`
- Подпапки: `processed/` (обработанные), `errors/` (с ошибками)
- Поддерживаемые типы контента: «Транспортный контейнер, Документ, Уведомление, Квитанция»
- Размер порции — из константы `РазмерПорцииОбработкиМЭДО`

## 3. HTTP-сервисы и веб-сервисы для интеграции с МЭДО

### 3.1. HTTP REST-сервисы (специализированные для МЭДО)
**Специального HTTP-сервиса для МЭДО НЕТ.** Обмен МЭДО осуществляется исключительно через файловую систему (каталоги отправки/получения) или FTP, а не через HTTP API.

Имеющиеся 9 HTTP-сервисов конфигурации относятся к другим подсистемам:
- `MobileApp` (root=/MobileApp) — мобильное приложение
- `ПередачаДанных` (root=/dt) — передача файлов
- `тст_ROSE`, `тст_STORM` — кастомные сервисы Тест
- `ЭДО` (root=/edi) — электронный документооборот (не МЭДО)

### 3.2. SOAP веб-сервисы, связанные с документооборотом (DM-сервисы)

Конфигурация содержит 4 веб-сервиса с префиксом DM (DocumentManagement), которые обеспечивают машинную интеграцию с внешними системами документооборота:

| Веб-сервис | Namespace | Операции | Процедуры реализации |
|------------|-----------|----------|----------------------|
| **DMMessageService** | http://www.1c.ru/dmmessage | `get`, `put` | `Get()` стр.14–92, `Put()` стр.105–163 |
| **DMService** | http://www.1c.ru/dm | `execute` | `ОбработатьЗапрос()` |
| **DMReg** | http://www.1c.ru/DMReg | `GetNewBarCodeNum`, `RegisterDocument` | по методам |
| **DMX** | http://www.1c.ru/DMX | `Get`, `Put` | по методам |

**DMMessageService** — основной сервис для синхронного обмена сообщениями с интегрированными системами:
- `Get(ИдентификаторУзлаИС)` — выбирает очередное сообщение из РС `ОчередьСообщенийВИнтегрированныеСистемы` для узла плана обмена `ИнтегрированныеСистемы`, возвращает XDTO-объект
- `Put(Сообщение, ИдентификаторУзлаИС)` — принимает входящее XDTO-сообщение через `ОбработкаЗапросовXDTO.ОбработатьУниверсальноеСообщение()`, сохраняет ответ в очередь
