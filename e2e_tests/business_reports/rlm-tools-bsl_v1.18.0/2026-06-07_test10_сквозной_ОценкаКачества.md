# Оценка качества: TEST-10 — Сквозной сценарий
**Сервер:** rlm-tools-bsl (v1.18.0)
**Дата:** 2026-06-07
**Оценщик:** Оркестратор (Claude Opus 4.8, 1M context)

## Общая оценка: ПОЛНОСТЬЮ

Сквозной сценарий прослежен на уровне кода по всем 5 шагам: **ВходящееПисьмо** (структура, `ПередЗаписью`/`ПриЗаписи`, РС `КоличествоПисемВПапках`/`ПисьмаВеток`/`СведенияОбАдресатах`) → **БП Рассмотрение** (резолюция как реквизит, `ОбработкаЗаполнения` стр. 803, `РассмотретьПередСозданиемЗадач` стр. 1202 создаёт `ЗадачаИсполнителя` с текстом резолюции в `РезультатВыполнения`) → **Документ.Задача** (`РаботаСЗадачами.СоздатьЗадачу` стр. 9330, БП Исполнение `ЗаполнитьПоРассмотрению` стр. 478, РН `КоличествоЗадач`, РС `ЗадачиПоАвторам`/`ИсторияЗадач`) → **Исполнение** (`ДобавитьПриложения` стр. 1605, `ВыполнитьДействиеЗадачи` стр. 1227, `ОтметитьВыполнена` стр. 748) → **ИсходящееПисьмо** (команда «Ответить» → `ВстроеннаяПочтаКлиент.ОтветитьНаПисьмо` стр. 475 → `ОбработкаЗаполнения`/`СформироватьСтруктуруРеквизитовПисьма` → РС `ПисьмаВеток`). Для каждого шага — объекты, процессы, регистры, код с номерами строк.

> **Нюанс точности (оркестратор, для сравнения).** Как и v1.17.0, v1.18.0 подал «резолюцию» как **реквизит** БП Рассмотрение (`Резолюция` xs:string → `РезультатВыполнения` задачи) и раскрыл модуль `РаботаСРезолюциями` (exports `ПолучитьРезолюции`/`ЭтоАвторРезолюции`), но **не выделил `Catalog.Резолюции` как отдельный объект** (в раунде 2 этот объект назвал bsl-indexer). Слой Тест-кастомизации (`тст_`-регистры на задачах) в TEST-10 также **не выделен** отдельно (хотя `тст_СрокиИсполненияЗадач` сервер нашёл в TEST-04). **Это те же два остаточных пробела, что и у v1.17.0 — не ухудшение.** По остальному охвату (БП Рассмотрение/Исполнение, регистры, цепочка «Ответить») прогон полный и код-верифицированный.

## Что сервер дал хорошо
- **Чистый прогон крупного сценария**: 37 вызовов, 0 шума, 0 retry — притом что это самый «широкий» по охвату тест (5 объектов + 2 БП + 6 регистров).
- **Цепочка создания задачи из резолюции построчно** (#30): `РассмотретьПередСозданиемЗадач` — создание `ЗадачаИсполнителя`, перенос текста резолюции, исполнитель/срок/проект.
- **Перенос Рассмотрение→Исполнение** (#18): `ЗаполнитьПоРассмотрению` — исполнители, сроки, предметы (Мультипредметность), контролёр.
- **Финал сценария — команда «Ответить»** (#34–36): `read_file` команды + `ОтветитьНаПисьмо` — открытие формы ИсходящегоПисьма с `{Команда: "Ответить", Письмо}` → `ОбработкаЗаполнения`.
- **Полная карта регистров** (#21, #28): структуры `КоличествоЗадач`/`ЗадачиПоАвторам`/`ИсторияЗадач`/`ПисьмаВеток` с измерениями/ресурсами.

## Что сервер НЕ дал
- **`Catalog.Резолюции` как отдельный объект** — подан как реквизит БП + модуль `РаботаСРезолюциями` (тот же пробел, что в v1.17.0; в раунде 2 объект назвал bsl).
- **Слой `тст_`-регистров на задачах** в этом тесте не выделен отдельно (найден в TEST-04, но не в сквозном).
- **Код уведомлений при смене состояний** — структура подписок известна, тела не читались (отмечено агентом).

## Паттерны поведения агента
- Цикл: `rlm_help(структура/ввод на основании)` → `search_objects` (все объекты) → `get_object_full_structure` ×N → `find_register_movements`/`find_event_subscriptions` → `read_procedure` по каждому шагу → `find_based_on_documents` → `read_file` (команда Ответить).
- 0 retry, 0 шума — образцовая дисциплина на самом крупном сценарии раунда.
- Крупнейший вклад — #8 (структура БП Рассмотрение 7 462 симв, 7%), без ⚠️.

## Выявленные проблемы
| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| «Резолюция» как реквизит, а не объект `Catalog.Резолюции` | подана через БП + модуль РаботаСРезолюциями |
| Слой `тст_`-кастомизации на задачах не выделен в сквозном | найден в TEST-04, не в TEST-10 |
| Код уведомлений не дочитан | подписки известны, тела не читались |

## Вывод
rlm-tools-bsl v1.18.0 закрыл TEST-10 полностью, **без шума и без retry** на самом широком сценарии раунда (5 объектов, 2 БП, 6 регистров, 37 вызовов, ≈184K, без ⚠️). Сквозная цепочка прослежена кодом построчно — от обработчиков письма до команды «Ответить», формирующей исходящее. Два остаточных пробела (`Catalog.Резолюции` как объект; слой `тст_`-регистров) идентичны v1.17.0 — то есть **не ухудшение, а сохранение прежней границы охвата**; именно здесь в раунде 2 ответы rlm и bsl были взаимодополняющими. Для моделирования сквозного бизнес-процесса сервер дал связную, код-верифицируемую картину.
