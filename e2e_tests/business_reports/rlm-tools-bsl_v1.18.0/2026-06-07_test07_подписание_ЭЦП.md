## 4. Статус документа после подписания

### 4.1 Перечисление СтатусПроверкиЭП

| Значение | Синоним |
|---|---|
| ПодписьДействительна | Подпись действительна |
| ПодписьНедействительна | Подпись недействительна |
| ПодписьНеПроверена | Подпись не проверена |
| ПодписиНет | Подписи нет |

### 4.2 Механизм обновления статуса

Цепочка вызовов после записи ЭП:

```
РС.ЭлектронныеПодписи (OnWrite)
  → РаботаСЭП.ПриЗаписиЭлектронныхПодписей (стр.1416)
    → РаботаСЭП.УстановитьСтатусПроверкиДляФайла (стр.1317)
    → РаботаСЭП.УстановитьСтатусПроверкиДляДокумента (стр.1352)
      → РаботаСЭП.УстановитьСтатусПроверки (стр.1294)
        → Устанавливает EnumRef.СтатусПроверкиЭП на объекте
```

**УстановитьСтатусПроверкиДляДокумента** (стр.1352):
- Нет подписей → `ПодписиНет`
- Подпись создана, не проверена → `ПодписьНеПроверена`
- ПодписьВерна=Ложь → `ПодписьНедействительна`
- Все подписи верны → `ПодписьДействительна`

### 4.3 Результат бизнес-процесса Подписание

**ЗаполнитьИтоговыйРезультатПодписания** (стр.2281, ObjectModule):
```bsl
Если ЕстьНеПодписаноНаТекущейИтерации() Тогда
    РезультатПодписания = Перечисления.РезультатыПроцессаПодписания.НеПодписано;
Иначе
    РезультатПодписания = Перечисления.РезультатыПроцессаПодписания.Подписано;
КонецЕсли;
```

**ПроцессЗавершилсяУдачно** (стр.1433, ManagerModule):
```bsl
Результат = РеквизитыПроцесса.Завершен
    И (РеквизитыПроцесса.РезультатПодписания =
    Перечисления.РезультатыПроцессаПодписания.Подписано);
```

### 4.4 Обновление действия (связь с ДокументооборотПредприятия)

Завершение БП запускает:  
**РаботаСПроцессамиПоДействиямСобытия.ПриЗавершенииПроцесса** (стр.1005):
```
→ РС.ПроцессыДействий.ДействиеПоПроцессу(Процесс)
  → Справочники.ДействияПодписания.ОбновитьРезультатВыполнения(Действие)
    → РС.СостоянияДействий: проверка завершённости всех участников
    → РС.РезультатыДействий: агрегация результатов
    → обновление состояния обработки объекта
```

```

        ПодписьДействительна | Недействительна | НеПроверена | ПодписиНет
```

## Итоговая оценка

**ПОЛНОСТЬЮ**

Все пять вопросов теста получили конкретные, документированные ответы на основе кода конфигурации:

1. **Параметры запуска БП Подписание:** реквизиты СпособПодписания (НаБумаге/ПЭП/УЭП), ТЧ Участники с полями Подписывающий и ТочкаМаршрута, шаблон (CatalogRef.ШаблоныПодписания), итерационность (КоличествоИтераций)
2. **Поддержка ЭЦП:** да, полноценная — 12 форматов CAdES, ПЭП и УЭП; отдельная подсистема ЭлектронныеПодписи с МЧД (машиночитаемая доверенность)
3. **Хранение подписей:** РС ЭлектронныеПодписи (двоичные данные в ValueStorage + метаданные), РС ЭлектронныеПодписиПоМЧД, флаг ПодписанЭП на объектах
4. **Статус после подписания:** устанавливается перечисление СтатусПроверкиЭП (4 значения) + реквизит РезультатПодписания БП (Подписано/НеПодписано); через ПриЗавершенииПроцесса обновляется связанное Действие в системе действий ДО3
5. **Общие модули:** РаботаСЭП (126 exports — главный модуль ДО3), ЭлектроннаяПодпись (49 exports — БСП-ядро), ЭлектроннаяПодписьДокументооборот* (ДО3-специфика), РаботаСВнешнимПодписанием (внешние системы)
