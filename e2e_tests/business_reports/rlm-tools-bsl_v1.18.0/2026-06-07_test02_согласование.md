## 4. Логика создания задач согласования

**Функция:** `СоздатьЗадачиСогласования()` — `ObjectModule.bsl`, строки 1964–2020

Алгоритм выбора согласующих из ТЧ Исполнители зависит от `ВариантСогласования`:

```
Если Параллельно → все строки ТЧ Исполнители (одновременно)
ИначеЕсли Последовательно → только первая непройденная строка
ИначеЕсли Смешанно →
    первая непройденная строка +
    все следующие с ПорядокСогласования = ВместеСПредыдущим
```

Для каждой выбранной строки:
1. Создаётся задача `Задачи.ЗадачаИсполнителя.СоздатьЗадачу()` (строка 2001)
2. Заполняется через `ЗаполнитьЗадачуСогласовать(Задача, Строка)` (строка 2028–2066):
   - Автор, Описание, Важность, БизнесПроцесс, ТочкаМаршрута = Согласовать
   - Исполнитель или РольИсполнителя (зависит от типа строки)
   - Срок — через `СрокиИсполненияПроцессов.ЗаполнитьСрокИсполненияЗадачи()`
   - Копирование дополнительных реквизитов
3. В ТЧ `РезультатыСогласования` добавляется строка (НомерИтерации, ЗадачаИсполнителя) (строка 2012)

### Как визы связаны с процессом

Виза — **параллельная подсистема учёта результатов** рядом с ТЧ `РезультатыСогласования`:

1. Создаётся в `РаботаСВизамиСогласования.СоздатьВизуУчастника()` (строки 1664–1695)
2. Вызывается из `РаботаСВизамиСогласования.СоздатьВизыПоДействию()` (строки 1111–1144):
   - Проверяет ФО `ИспользоватьВизыСогласования`
   - Проверяет флаг `ФормируетВизы` у Действия согласования (справочник ДействияСогласования)
   - Создаёт визы только для участников с ролью `Согласующий`
3. Поле `Источник` — ссылка на `ДействияСогласования` (или задачу/процесс)
4. После завершения задачи `ОбновитьВизуУчастника()` записывает результат

**Смысл:** Справочник ВизыСогласования — **журнал истории согласований** по документам предприятия. Позволяет видеть все итерации, версии, результаты и ЭП-подписи по документу в разрезе итераций и согласующих.

## 6. Что происходит когда все согласующие завершили работу

### Шаг 1: Выполнение задачи → отложенная обработка

При выполнении задачи точки маршрута `Согласовать` вызывается:

**`СогласоватьПриВыполнении()`** — `ObjectModule.bsl`, строки 1678–1682:
```bsl
Процедура СогласоватьПриВыполнении(ТочкаМаршрутаБизнесПроцесса, Задача, Отказ)
    ДобавитьЗадачуОтложеннаяОбработкаЗавершенияСогласования();
КонецПроцедуры
```

### Шаг 2: Проверка условия «все завершили»

**Условие перехода:** `УсловиеОбходЗавершен()` — `ObjectModule.bsl`, строки 1699–1709:
```bsl
Процедура УсловиеОбходЗавершен(ТочкаМаршрутаБизнесПроцесса, Результат)
    Результат = ОбходСогласующихЗавершен();
КонецПроцедуры
```

**`ОбходСогласующихЗавершен()`** — `ObjectModule.bsl`, строки 1240–1271 [export]:
- Выполняет запрос к `Задача.ЗадачаИсполнителя` — ищет активные невыполненные задачи по данному процессу
- Если есть хотя бы одна невыполненная → возвращает `Ложь` (обход не завершён)
- Если `ИтоговыйРезультатСогласования() = НеСогласовано` → возвращает `Истина` (можно прерваться досрочно)
- Иначе проверяет: `Исполнители.Найти(Ложь, "Пройден") = Неопределено` (все строки ТЧ помечены Пройден)

### Шаг 3: Определение итогового результата

**`ИтоговыйРезультатСогласования()`** — `ObjectModule.bsl`, строки 1202–1233 [export]:
```
Алгоритм (приоритет НеСогласовано):
  Начинаем с Согласовано
  Если хоть одна задача = НеСогласовано → итог НеСогласовано, стоп
  Если хоть одна задача = СогласованоСЗамечаниями → итог СогласованоСЗамечаниями
  Возврат итога
```
Анализирует только записи `РезультатыСогласования` с текущим `НомерИтерации`.

### Шаг 4: Обработка завершённой задачи

**`ОбработатьЗавершениеЗадачиСогласования(Задача)`** — строки 2107–2117:
- Находит строку в ТЧ Исполнители по `ЗадачаИсполнителя`
- Устанавливает `Пройден = Истина`
- Записывает процесс через `РаботаСБизнесПроцессами.ЗаписатьПроцесс(..., "ПростаяЗапись")`

### Шаг 5: Обработка результата (точка ОбработкаРезультата)

**`ОбработкаРезультатаОбработка()`** — строки 1711–1723:
- Устанавливает состояние мероприятия через `УправлениеМероприятиями`
- Записывает `РезультатСогласования = ИтоговыйРезультатСогласования()`
- Сохраняет процесс

### Шаг 6: Завершение БП

**`ЗавершениеПриЗавершении()`** — строки 1761–1770:
```bsl
УстановитьПривилегированныйРежим(Истина);
ДатаЗавершения = ТекущаяДатаСеанса();
РаботаСПроектами.ОтметитьОкончаниеВыполненияПроектнойЗадачи(ЭтотОбъект);
РаботаСПроцессамиПоДействиямСобытия.ПриЗавершенииПроцесса(ЭтотОбъект);
```

**`ПриЗавершенииПроцесса()`** — `РаботаСПроцессамиПоДействиямСобытия`, строки 1005–1028:
- Находит связанное `Действие` через РС `ПроцессыДействий` (измерение Процесс → ресурс Действие)
- Если нет других активных процессов того же действия — вызывает `МенеджерДействия.ОбновитьРезультатВыполнения(Действие)`

### Маппинг результата задачи

## 9. Схема потока (маршрут БП)

```
[Старт]
   ↓
[Подготовка]  ← ПодготовкаОбработка() (стр. 1644)
   ↓ (создание задач согласования)
[Согласовать] ← СогласоватьПередСозданиемЗадач() → СоздатьЗадачиСогласования()
   ↓ (задачи выполняются согласующими)
   ↓ СогласоватьПриВыполнении() → ДобавитьЗадачуОтложеннаяОбработка...
   ↓ УсловиеОбходЗавершен() ← ОбходСогласующихЗавершен()
   ↓
[Проверка результата: СогласованоПроверкаУсловия()]
   ├─ Истина (согласовано) → [Ознакомиться] → [ОбработкаРезультата]
   └─ Ложь (не согласовано) → ПовторитьСогласование?
       ├─ Да → [Согласовать] (новая итерация)
       └─ Нет → [ОбработкаРезультата]
   ↓
[ОбработкаРезультата] ← ОбработкаРезультатаОбработка() → РезультатСогласования = ИтоговыйРезультат
   ↓
[Завершение] ← ЗавершениеПриЗавершении() → ПриЗавершенииПроцесса()
```

Все пять вопросов теста TEST-02 отвечены на основе кода и метаданных конфигурации:

1. **Параметры запуска** — ВариантСогласования (3 варианта), ТЧ Исполнители с порядком/сроками, шаблон, ЭП, важность — всё получено из структуры объекта и кода `ЗаполнитьПоШаблону`.

2. **ВизыСогласования** — отдельный справочник (18 реквизитов), управляется через `РаботаСВизамиСогласования`, создаётся при наличии ФО `ИспользоватьВизыСогласования`, связан с документом через поле `Документ` и с процессом через `Источник`.

3. **Результаты согласующего** — три значения перечисления `РезультатыСогласования`: **Согласовано**, **Не согласовано**, **Согласовано с замечаниями**. Сохраняются в ТЧ `РезультатыСогласования` процесса.

4. **Завершение процесса** — цепочка: `ОбходСогласующихЗавершен()` (stri 1240) → `ИтоговыйРезультатСогласования()` (строки 1202) → `ОбработкаРезультатаОбработка()` (строки 1711) → `ЗавершениеПриЗавершении()` (строки 1761) → `ПриЗавершенииПроцесса()` в `РаботаСПроцессамиПоДействиямСобытия`.

5. **Общие модули** — 6 ключевых: ObjectModule/ManagerModule БП, `РаботаСБизнесПроцессами`, `БизнесПроцессыИЗадачиСервер`, `РаботаСВизамиСогласования`, `РаботаСПроцессамиПоДействиямСобытия` + 6 модулей режима замечаний.
