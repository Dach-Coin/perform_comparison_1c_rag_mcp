# Оценка качества: TEST-01 — Жизненный цикл входящего документа
**Сервер:** rlm-tools-bsl (v1.18.0)
**Дата:** 2026-06-07
**Оценщик:** Оркестратор (Claude Opus 4.8, 1M context)

## Общая оценка: ПОЛНОСТЬЮ

Все 5 подвопросов закрыты данными из индекса и кода: **23 реквизита + 4 ТЧ** документа `ВходящееПисьмо` (структурным вызовом `get_object_full_structure`); **4 бизнес-процесса** (Рассмотрение, Исполнение, Согласование, Ознакомление) + БП `Регистрация` с явным включением `ДокументСсылка.ВходящееПисьмо` в `ТипыОсновныхПредметов` (стр. 1027); **обработчики записи** `ПередЗаписью` (5–47) и `ПриЗаписи` (49–107) прочитаны построчно; **13 регистров сведений**, связанных с письмом; **86 подписок на события** (4 специфичных для `ВходящееПисьмо`); нумерация раскрыта как косвенная — рег. номер хранится в карточке `ДокументыПредприятия` (`РегистрационныйНомер`/`ДатаРегистрации`/`Зарегистрировал`) и присваивается при БП «Регистрация». Профиль ровный, ни одного ⚠️.

## Что сервер дал хорошо
- **Структура объекта одним вызовом** (#6, `get_object_full_structure`): 23 реквизита + 4 ТЧ получателей + 4 формы — после исправления ключей.
- **Код обработчиков записи** (#9–10): `ПередЗаписью` (автоустановка папки «Входящие», контроль заполнения, применение правил сортировки), `ПриЗаписи` (обновление РС `КоличествоПисемВПапках`, протоколирование, расширение рабочей группы предмета).
- **Бизнес-процессы с верификацией** (#11–15): 4 БП + точное доказательство участия письма в БП «Регистрация» (read_procedure `ТипыОсновныхПредметов`, стр. 1027).
- **Карта регистров и подписок** (#20–22): `find_register_movements`+`find_event_subscriptions` дали 13 регистров и 86 подписок (4 специфичных), без переполнения контекста.
- **Ровный профиль**: максимальный единичный вклад — #8 (13 747 симв, 14% от итога), без ⚠️.

## Что сервер НЕ дал
- **Прямого кода присвоения регистрационного номера** — он в `ObjectModule` `ДокументыПредприятия` / в задаче БП «Регистрация»; агент вышел на факт хранения номера, но не на сам момент присвоения (закрывается в TEST-06).
- **Платформенный реквизит «Предмет» БП** не отображается в `find_attributes` (системный) — отмечено агентом как додумывание.

## Паттерны поведения агента
- Цикл: `rlm_help(структура объекта)` → `search_objects` → `get_object_full_structure` → `analyze_document_flow`/`find_event_subscriptions` → `read_procedure` (обработчики) → `git_search` (подтверждения по XML БП).
- 1 retry (#5→6): неинтуитивные ключи структуры — мгновенно исправлено по HINT.
- Стратегия «структура → код обработчиков → процессы → регистры» — без тупиков, расход рос плавно.

## Выявленные проблемы
| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| Ключи `get_object_full_structure` неинтуитивны | #5 KeyError `attr_kind` → retry на `name/synonym/type` |
| `search_methods` по «РегистрационныйНомер» даёт утилитарный шум | #16 — единственный шумный вызов |
| Нумерация документа не локализуется прямо на объекте | рег. номер косвенно через `ДокументыПредприятия` |

## Вывод
rlm-tools-bsl v1.18.0 закрыл TEST-01 полностью и дисциплинированно (≈183K токенов, без ⚠️, 97% полезных): структурные хелперы дали точный инвентарь письма и его процессов, `read_procedure` развернул реальные обработчики записи, а косвенная схема нумерации (через `ДокументыПредприятия`) восстановлена корректно. Для вопроса «опиши жизненный цикл документа — реквизиты, процессы, регистрация, обработчики, регистры» сервер показал сильный, верифицируемый результат.
