# Оценка качества: TEST-05 — Поиск процедуры по бизнес-описанию
**Сервер:** rlm-tools-bsl (v1.18.0)
**Дата:** 2026-06-07
**Оценщик:** Оркестратор (Claude Opus 4.8, 1M context)

## Общая оценка: ПОЛНОСТЬЮ

Найдена и прочитана процедура работы с замещениями при назначении задачи: **`ЗаписатьДоступЗамещающихПоДействиюЗадачи`** (`CommonModules/ЗамещающиеИПомощники/Ext/Module.bsl`, стр. 307–424) + вспомогательная **`ПодходящиеЗамещения`** (стр. 482–613). Прочитан полный код обеих, установлены вызывающие (2 exact для основной — `ПриЗаписи` `ДействиеЗадачи` стр. 422 и `Задача` стр. 2371; 10 exact для `ПодходящиеЗамещения`), плюс смежная `ОбновитьДанныеЗадачПоЗамещению` (обновление при изменении записи замещения). Ответ полный и код-верифицирован.

> **Нюанс точности (оркестратор, важно для сравнения с v1.17.0).** В раунде 2 на этот же промпт rlm v1.17.0 вышел на **`ОпределитьФактическихИсполнителей`** (`РаботаСЗадачами`, стр. 24–251) — процедуру, чьё имя дословно совпадает с формулировкой («определяет фактических исполнителей») и которая **явно обрабатывает роли** (Уровень 2 — `ПолныеРоли`) и замещения. v1.18.0 пошёл другим путём поиска (`search_methods 'Замещен'/'Исполнител'`) и остановился на **`ЗаписатьДоступЗамещающихПоДействиюЗадачи`** — тоже реальной и код-верифицированной процедуре механизма замещения, но критерий «работает с ролями исполнителей» здесь закрыт **косвенно** (через РС `СотрудникиВКонтейнерах` = контейнеры-роли), а не через прямую обработку `ПолныеРоли`. Обе процедуры валидны; v1.17.0 попал в более «каноничную» по формулировке промпта точку. **Это вариативность пути агента-Sonnet, а не регресс сервера** — те же инструменты (`search_methods`/`extract_procedures`) в v1.17.0 вывели на `ОпределитьФактическихИсполнителей`. Обе оценки — ПОЛНОСТЬЮ.

## Что сервер дал хорошо
- **Полный код целевой и вспомогательной процедур** (#14–15): 118 + 132 строки с логикой областей замещения, вида задачи/документа.
- **Точные вызывающие** (#16, #18): `find_callers_context` дал 2 exact для основной и 10 exact для `ПодходящиеЗамещения` — с модулями и строками.
- **Контекст вызова прочитан** (#17, #19–20): подтверждено условие вызова (ЭтоНовый ИЛИ смена Исполнителя), зафиксирована кастомизация Тест («AIS PIRA 01.01.23»).
- **Смежный путь обновления** (#22–25): `ОбновитьДанныеЗадачПоЗамещению` при изменении записи замещения — полнота картины механизма.
- Ровный профиль, без ⚠️; экономичный прогон (≈107K).

## Что сервер НЕ дал
- **«Семантического» попадания одним запросом**: `search_methods` не принял составную фразу (#5 → 0), пришлось искать по одиночным токенам имени метода и перебирать модули.
- **Каноничной по формулировке процедуры `ОпределитьФактическихИсполнителей`** — не выведена в этом прогоне (путь поиска привёл к процедуре записи доступа замещающих; см. нюанс выше).

## Паттерны поведения агента
- Цикл: `rlm_help(иерархия вызовов)` → `search_methods` (токены) → `find_module`/`extract_procedures` → `read_procedure` → `find_callers_context`/`find_call_hierarchy`.
- 1 retry (#5→6): составной `search_methods` → 0 → одиночные токены.
- Стратегия «от ключевых слов к модулю замещений» сработала, но увела от дословно-каноничной процедуры к смежной валидной.

## Выявленные проблемы
| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| `search_methods` не принимает составные запросы | #5 фраза → 0 → одиночные токены |
| Путь поиска чувствителен к выбору токенов | вышел на `ЗаписатьДоступЗамещающих`, а не на `ОпределитьФактическихИсполнителей` (v1.17.0) |
| Нет FTS по функциям (как `search_function` у bsl) | цель найдена на 14-м вызове |

## Вывод
rlm-tools-bsl v1.18.0 закрыл TEST-05 полностью, код-верифицировав найденную процедуру и все её вызывающие, при ровном экономном профиле (≈107K, без ⚠️). Содержательно ответ корректен: найдена реальная процедура механизма замещения с точными вызывающими. Единственная оговорка — выбор токенов поиска увёл к `ЗаписатьДоступЗамещающихПоДействиюЗадачи` вместо дословно-каноничной `ОпределитьФактическихИсполнителей`, на которую вышел v1.17.0; критерий «роли исполнителей» закрыт косвенно. Это вариативность пути агента, не регресс сервера. Как и в v1.17.0, узкое место класса — отсутствие FTS-поиска по функциям для мгновенного попадания.
