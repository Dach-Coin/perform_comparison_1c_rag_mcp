# Оценка качества: TEST-03 — Структура справочника Сотрудники
**Сервер:** rlm-tools-bsl (v1.18.0)
**Дата:** 2026-06-07
**Оценщик:** Оркестратор (Claude Opus 4.8, 1M context)

## Общая оценка: ПОЛНОСТЬЮ

Все 5 подвопросов закрыты: **9 реквизитов + 2 ТЧ** (`ДополнительныеРеквизиты`, `КонтактнаяИнформация`); **связи** — `ФизическиеЛица` владелец (1:N, `ref_kind='owner'`), `Должности`/`СтруктураПредприятия` через реквизиты; **наименование = `Строка(Владелец)`** (ФИО из физлица, синхронизируется `ПриЗаписиФизическогоЛица`); **механизм замещения** — справочник `ЗамещающиеИПомощники` (Сотрудник→Замещающий, `ВидЗамещения`, ТЧ `ВопросыЗамещения`, 22 экспортных метода) + 2 активных регламентных задания (`ОбработкаСроковЗамещающихИПомощников`, `ОбновлениеДействияСотрудников`); **регистры** — `ОсновныеСотрудники`, `СотрудникиПользователей`, `СотрудникиВКонтейнерах`, `ПолномочияСотрудников`, `ИсполнителиРолейИДелегаты`, `РабочееВремяСотрудников` (РН), `ДанныеSAPСотрудники` (интеграция Тест).

> **Сверка с источником (оркестратор):** механизм замещения — `Catalogs\ЗамещающиеИПомощники` + активное `ScheduledJobs\ОбработкаСроковЗамещающихИПомощников`; `Documents\Отсутствие` — основание замещения. v1.18.0 указал текущий механизм **верно** (совпадает с источник-сверкой раунда 2, где rlm был прав против bsl, опёршегося на устаревший путь Отсутствие/Заместители).

## Что сервер дал хорошо
- **Связь-владелец доказана** (#7–8): `parse_object_xml` → references → `ФизическиеЛица` (`ref_kind='owner'`), а не догадка.
- **Многозаписность ФизЛицо→Сотрудники** (#22): прочитан `ПодобратьИУстановитьОсновногоСотрудника` — одно физлицо → несколько сотрудников, `ОсновныеСотрудники` хранит «основного».
- **Триггер синхронизации** (#25–26): найден `СотрудникиСобытия.ПриЗаписиФизическогоЛица` — при записи физлица обновляются наименования всех его сотрудников (`WHERE Владелец=&ФизЛицо`).
- **Полный API замещения** (#11–13): справочник + 22 экспортных метода; перечисление `ВидыЗамещения` (Замещающие/Помощники).
- **Регистры одним блоком** (#9–10, #17–19): инвентарь всех регистров сотрудников с измерениями/ресурсами, включая РН `РабочееВремяСотрудников`.

## Что сервер НЕ дал
- **Стандартные атрибуты** (Ссылка/ПометкаУдаления/Код/Наименование) — не в индексе (стандарт 1С); агент добрал по знанию платформы.
- **Тип иерархии** справочника (`HierarchyType` из XML вернул None — данные неполные).
- **Периодичность регламентных заданий** — статус вкл/выкл получен, точное расписание нет.

## Паттерны поведения агента
- Цикл: `get_object_full_structure` → `parse_object_xml` (references) → `find_attributes` (регистры) → `search_methods/search_objects` (замещение) → `read_procedure` (ПередЗаписью/ПриЗаписи/ЗаполнитьНаименование) → `find_scheduled_jobs`.
- 2 retry: #6 (путь `parse_object_xml` — нужна директория объекта), #24 (`git_search` по EventSubscriptions пуст → переход на поиск модуля событий).
- Самый экономный из «структурных» тестов раунда (≈108K), профиль ровный без ⚠️.

## Выявленные проблемы
| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| `parse_object_xml` требует путь-директорию | #6 FileNotFoundError → retry |
| `git_search` по EventSubscriptions малорезультативен | #24 → 0 → поиск через модуль `*События` |
| Стандартные атрибуты/иерархия не в индексе | добор по знанию платформы |

## Вывод
rlm-tools-bsl v1.18.0 закрыл TEST-03 полностью и **самым дешёвым прогоном раунда** (≈108K токенов, без ⚠️). Сервер не только перечислил реквизиты/ТЧ/регистры, но и **доказал связи кодом** (владелец через references, синхронизация ФИО через `ПриЗаписиФизическогоЛица`, многозаписность через `ОсновныеСотрудники`) и **указал актуальный механизм замещения** (`ЗамещающиеИПомощники` + активные регл. задания) — что подтверждается сверкой с источником. Сильный профиль для вопросов инвентаризации справочника с раскрытием связей.
