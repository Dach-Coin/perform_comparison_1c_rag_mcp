## 2. Может ли сотрудник видеть задачи других сотрудников?

**Ответ: по умолчанию — нет, только в особых случаях.**

### 2.1 Механизм RLS ограничивает доступ

Для роли `РаботаСЗадачами` на операцию `Read` для `Document.Задача` установлено RLS-ограничение `#ПоДескрипторуОбъекта("", "", "", "")` (строка 817 файла `Roles/РаботаСЗадачами/Ext/Rights.xml`).

Полный SQL-запрос для операции `Update` (строки 828-860) проверяет:
```sql
ТекущаяТаблица ИЗ #ТекущаяТаблица КАК ТекущаяТаблица
ГДЕ ИСТИНА В
  (ВЫБРАТЬ ПЕРВЫЕ 1 ИСТИНА
   ИЗ РегистрСведений.ДескрипторыДляОбъектов КАК ДескрипторыДляОбъектов
     ВНУТРЕННЕЕ СОЕДИНЕНИЕ РегистрСведений.ПраваПоДескрипторамДоступаОбъектов
     ПО ДескрипторыДляОбъектов.Дескриптор = ПраваПоДескрипторамДоступаОбъектов.Дескриптор
   ГДЕ ДескрипторыДляОбъектов.Объект = ТекущаяТаблица.Ссылка
     И ПраваПоДескрипторамДоступаОбъектов.Сотрудник В (&СотрудникиПользователя)
  ОБЪЕДИНИТЬ ВСЕ
  -- UNION: проверка через заместителей (Справочник.ЗамещающиеИПомощники)
  -- с условием: ВопросыЗамещения.Область В (ЗадачиПостановкаПоручений, Задачи, ВсеОбласти))
```

### 2.2 Исключения — кто видит задачи других

1. **Роль `КонтрольЗадачИБизнесПроцессов`** — полный доступ ко всем задачам **без RLS** (строки 1774-1835 в `Roles/КонтрольЗадачИБизнесПроцессов/Ext/Rights.xml`). Соответствует профилю «Контроль задач и бизнес-процессов».

2. **Роль `ЧтениеПроцессовИЗадачБезОграничения`** — Read+View без RLS (строки 908-916). Несмотря на название «без ограничения», другие объекты в этой роли имеют RLS.

3. **Руководители/заместители** — через механизм замещения (Справочник.ЗамещающиеИПомощники) могут видеть задачи, где является заместителем автора (проверяется в RLS-запросе, строки 847-858).

4. **Функция `ДоступныЗадачиПодчиненных`** (`CommonModules/РаботаСЗадачами/Ext/Module.bsl` [2706], `CommonModules/РаботаСЗадачамиПовтИсп/Ext/Module.bsl` [366-377]): сотрудник может видеть задачи подчинённых через `РаботаСПользователями.ЭтоРуководительИлиПомощник()` с областями замещения `ЗадачиПросмотр` и `Задачи`.

## 4. Связь рабочих групп с доступом к документам

### 4.1 Регистр сведений РабочиеГруппы

Центральный объект механизма. Структура (`InformationRegisters/РабочиеГруппы`):
- Измерение **Объект** — полиморфное: включает `DocumentRef.Задача`, `CatalogRef.ДокументыПредприятия`, `CatalogRef.Мероприятия`, `CatalogRef.Проекты`, `CatalogRef.ТемыОбсуждений` и др. (~20 типов)
- Измерение **Участник** — кто входит в рабочую группу объекта
- Ресурс **Изменение** (bool) — признак права на изменение
- Ресурс **Источник** — от какого объекта унаследован участник

### 4.2 Алгоритм формирования рабочей группы задачи

При записи Document.Задача срабатывает подписка `ДокументооборотПраваДоступаПриЗаписиОбъектаДоступа` (OnWrite), которая вызывает цепочку:

```
ДокументооборотПраваДоступаПриЗаписиОбъектаДоступа [2964]
  → ОпределитьДескрипторыОбъекта [1322]
    → Документы.Задача.ЗаполнитьДескрипторыОбъекта [868]  (менеджер)
```

**Функция `ЗаполнитьДескрипторыОбъекта`** в `Documents/Задача/Ext/ManagerModule.bsl` формирует список участников рабочей группы:

| Источник участника | Право на изменение | Строки кода |
|---|---|---|
| Автор задачи (`Задача.Автор`) | **Да** (Изменение=Истина) | 875-877 |
| Создавший задачу (`Задача.Создал`) | Нет | 880-882 |
| Участники из ТЧ Участники (`Задача.Участники`) | Нет | 884-895 |
| Руководитель проекта (через `ПроектыКонтейнеры`) | Нет | 897-904 |
| Все исполнители действий (из `РегистрСведений.ВсеИсполнителиДействийЗадач`) | Нет | 909-927 |
| Контролеры (из `Справочник.Контроль`) | Нет | 930-944 |
| Участники бизнес-процессов (через `ИнтеграцияЗадач.ЗаполнитьКонтейнерыОбъекта`) | — | 947 |

### 5.2 Цепочка проверки прав при записи задачи

```
Document.Задача.BeforeWrite
  → подписка ДокументооборотПраваДоступаПередЗаписьюДокумента [2957]
    → ДокументооборотПраваДоступаПередЗаписьюОбъектаДоступа
      (проверяет: включены ли права, не загрузка, есть права у пользователя)

Document.Задача.OnWrite
  → подписка ДокументооборотПраваДоступаПриЗаписиОбъектаДоступа [2964]
    → проверка: ВключеноИспользованиеПравДоступа() == Истина
    → ОпределитьДескрипторыОбъекта [1322]
      → Документы.Задача.ЗаполнитьДескрипторыОбъекта [868]
        (формирует контейнеры: Автор, Создал, Участники, Исполнители, Контролеры)
      → ЗаполнитьДескрипторыОбъектаПоРабочейГруппе [1443]
        (для каждого участника создаёт/находит ДескрипторДоступаОбъекта)
      → РегистрыСведений.ДескрипторыДляОбъектов.Сохранить [1369]
```

## 6. Итоговая схема системы прав доступа к задачам

```
Пользователь запрашивает Document.Задача
        │
        ▼
Проверка роли (RLS в Rights.xml)
        │
        ├── КонтрольЗадачИБизнесПроцессов → доступ БЕЗ ограничений
        │
        ├── ЧтениеПроцессовИЗадачБезОграничения → Read/View БЕЗ ограничений
        │
        └── РаботаСЗадачами / ИзменениеВыполнениеЗадач → RLS:
                │
                ▼
        #ПоДескрипторуОбъекта → запрос к:
                │
                ├── РегистрСведений.ДескрипторыДляОбъектов
                │     (Объект = Задача.Ссылка, Дескриптор)
                │
                └── РегистрСведений.ПраваПоДескрипторамДоступаОбъектов
                      (Дескриптор + Сотрудник IN &СотрудникиПользователя)
                              │
                              ▼
                    Дескриптор формируется при записи задачи:
                    - Автор (право Изменение)
                    - Создал
                    - Участники (ТЧ)
                    - Исполнители действий
                    - Контролеры
                    - Участники процессов
```
