## 1. Общая структура объекта

Бизнес-процесс **БизнесПроцессы.Согласование** — самостоятельный объект конфигурации, не использующий стандартные команды. Основная форма: `БизнесПроцесс.Согласование.Форма.ФормаБизнесПроцесса`.

### Реквизиты объекта

| Реквизит | Тип | Назначение |
|----------|-----|-----------|
| Наименование | Строка(150) | Заголовок процесса, обязательно |
| Описание | Строка(0), многострочный | Комментарий к процессу |
| ВариантСогласования | ПеречислениеСсылка.ВариантыМаршрутизацииЗадач | Порядок обхода согласующих, **обязательно** |
| РезультатСогласования | ПеречислениеСсылка.РезультатыСогласования | Итоговый результат (заполняется автоматически) |
| Состояние | ПеречислениеСсылка.СостоянияБизнесПроцессов | По умолчанию: Активен |
| ВариантУстановкиСрокаОбработкиРезультатов | ПеречислениеСсылка.ВариантыУстановкиСрокаИсполнения | Как задаётся срок для обработки результата |

### Табличные части

| **Исполнители** | Список согласующих с индивидуальными параметрами |

## 2. Параметры запуска согласования

При создании и запуске процесса согласования настраиваются следующие параметры:

### 2.1. Исполнители (согласующие)
Заполняются в ТЧ «Исполнители». Для каждого согласующего указывается:
- **Исполнитель** (пользователь или роль) — конкретный согласующий либо роль бизнес-процесса
- **ВариантУстановкиСрокаИсполнения** — как задаётся срок: из общего срока, персональный или относительный
- **ПорядокСогласования** — номер в очереди при последовательном варианте

Типовые сроки согласования (из инструкции):
- Приказы, распоряжения: **3 дня**
- Договоры: **3 дня**
- Инструкции, порядки, регламенты: **5 дней**
- Служебные записки: **1 день**

### 2.2. Вариант согласования
Реквизит **ВариантСогласования** — тип `ПеречислениеСсылка.ВариантыМаршрутизацииЗадач`, обязательный для заполнения:

| Значение | Синоним | Описание |
|----------|---------|---------|
| Последовательно | «По очереди» | Задачи выдаются по одной, следующая — после завершения предыдущей |
| Параллельно | «Всем сразу» | Задачи выдаются всем согласующим одновременно (значение по умолчанию в шаблонах) |
| Смешанно | «Смешанно» | Комбинированный вариант (используется в сложных маршрутах) |

### 2.3. Срок обработки результатов
Реквизит **ВариантУстановкиСрокаОбработкиРезультатов** — управляет сроком, который даётся инициатору для ознакомления с итогами согласования.

### 2.4. Предметы согласования
ТЧ «Предметы» содержит документы (СправочникСсылка.ДокументыПредприятия и другие объекты), в отношении которых ведётся согласование.

## 3. Визы согласования

### Что такое визы?
**Визы согласования** — это записи в Справочнике `ВизыСогласования`, которые формируются параллельно с задачами и хранят официальную отметку о позиции каждого согласующего. Функционал включается через константу `ИспользоватьВизыСогласования` (тип Булево), управляемую через функциональную опцию `ФО.ИспользоватьВизыСогласования`.

### Структура записи визы

| Реквизит | Тип | Описание |
|----------|-----|---------|
| Наименование | Строка(150) | Автоматически: "Виза согласования документа «имя»" |
| Документ | СправочникСсылка.ДокументыПредприятия | Предмет согласования |
| Источник | Составной тип | Задача / Действие согласования / БП Согласование |
| РезультатСогласования | ПеречислениеСсылка.РезультатыСогласования | Решение согласующего |
| ДатаСоздания | Дата(ДатаВремя) | Дата формирования визы |
| УстановилРезультат | (пользователь) | Кто проставил результат |
| ДатаИсполнения | Дата | Дата простановки результата |
| Подписана | Булево | Подписана ли виза УЭП |

### Связь с процессом
Визы создаются общим модулем **РаботаСВизамиСогласования** (процедура `СоздатьВизыПоДействию`). Условие создания: `Справочник.ДействияСогласования.ФормируетВизы = Истина`. При отмене выполнения задачи подпись визы снимается.

Регистр сведений `ВерсииСогласованныхФайлов` фиксирует, какая версия файла была представлена на визирование.

## 4. Результаты согласования

Согласующий выбирает один из трёх результатов перечисления `РезультатыСогласования`:

| Значение перечисления | Пользовательское название | Требуется комментарий |
|-----------------------|--------------------------|----------------------|
| **Согласовано** | «Согласовано» | Нет |
| **СогласованоСЗамечаниями** | «Согласовано с замечаниями» | Обязателен |
| **НеСогласовано** | «Не согласовано» | Обязателен |

> Из кода формы визы: если результат = НеСогласовано или СогласованоСЗамечаниями, и поле «Комментарий» не заполнено — система выдаёт ошибку.

### Соответствие вариантам выполнения процессов

| Результат согласования | Вариант выполнения процесса/задачи |
|------------------------|-----------------------------------|
| Согласовано | ВариантыВыполненияПроцессовИЗадач.Положительно |
| СогласованоСЗамечаниями | ВариантыВыполненияПроцессовИЗадач.ПоложительноСЗамечаниями |
| НеСогласовано | (завершение с отрицательным результатом) |

## 5. Завершение процесса — код обработки

### 5.1. Точки маршрута

Бизнес-процесс Согласование содержит следующие точки маршрута:
- **Согласовать** — основная точка, где согласующий фиксирует результат
- **ОбработкаРезультата** — точка подведения итогов после завершения обхода
- **Ознакомиться** — опциональная точка для ознакомления с результатами

### 5.2. Логика завершения обхода согласующих

**Функция `ОбходСогласующихЗавершен()`** (ObjectModule):
```bsl
// Проверяет, остались ли незавершённые задачи
Запрос.Текст = 
    "ВЫБРАТЬ ПЕРВЫЕ 1
    |   ЗадачаИсполнителя.Ссылка
    |ИЗ
    |   Задача.ЗадачаИсполнителя КАК ЗадачаИсполнителя
    |ГДЕ
    |   ЗадачаИсполнителя.БизнесПроцесс = &Процесс
    |   И ЗадачаИсполнителя.Выполнена = ЛОЖЬ"
```
Процесс считается завершённым, если все задачи выполнены (запрос возвращает пустой результат).

### 5.3. Обработчик точки ОбработкаРезультата

```bsl
Процедура ОбработкаРезультатаОбработка(ТочкаМаршрутаБизнесПроцесса)
    // Обновление состояния мероприятия (если процесс связан с мероприятием)
    УправлениеМероприятиями.УстановитьСостояниеМероприятияИзБизнесПроцесса(...)
    
    // Подсчёт итогового результата
    РезультатСогласования = ИтоговыйРезультатСогласования();
    
    // Запись процесса
    РаботаСБизнесПроцессами.ЗаписатьПроцесс(ЭтотОбъект, "ПростаяЗапись");
КонецПроцедуры
```

### 5.4. Приоритеты при расчёте итогового результата

**Функция `ИтоговыйРезультатСогласования()`** применяет следующий приоритет (сканирует ТЧ РезультатыСогласования):

```
НеСогласовано  >  СогласованоСЗамечаниями  >  Согласовано
```

- Если хотя бы один сказал «Не согласовано» — итог «Не согласовано»
- Если никто не сказал «Не согласовано», но есть «С замечаниями» — итог «С замечаниями»
- Если все согласовали без замечаний — итог «Согласовано»

## 7. Схема жизненного цикла процесса

```
Запуск → [Точка Согласовать] → задачи выдаются согласующим
             ↕ (цикл по вариантам: последовательно/параллельно/смешанно)
         Согласующий выполняет задачу:
           - выбирает результат (Согласовано / С замечаниями / Не согласовано)
           - оставляет комментарий (обязателен при отрицательных результатах)
           - при необходимости формируется виза (Справочник.ВизыСогласования)
             ↕
         [УсловиеОбходЗавершен] — все задачи выполнены?
           - Нет → следующий согласующий (последовательно) или ждём остальных (параллельно)
           - Да  → переход к ОбработкаРезультата
             ↕
         [Точка ОбработкаРезультата]:
           - ИтоговыйРезультатСогласования() — расчёт итога
           - Запись РезультатаСогласования в реквизит процесса
           - Уведомление инициатора
             ↕
         [Точка Ознакомиться] (опционально):
           - Инициатор знакомится с итогами
             ↕
         Завершение процесса
```

## Выводы

Бизнес-процесс Согласование в DO3 представляет собой полнофункциональный объект с гибкой маршрутизацией (три варианта порядка) и чёткой иерархией результатов. Ключевой принцип: наиболее негативный результат имеет наивысший приоритет. Визы согласования — дополнительный механизм КОРП-редакции для формального фиксирования позиции согласующего с возможностью подписи УЭП. Логика реализована преимущественно в ObjectModule самого бизнес-процесса при поддержке специализированного общего модуля РаботаСВизамиСогласования.
