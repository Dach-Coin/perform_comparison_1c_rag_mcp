# Оценка качества: TEST-01 — Жизненный цикл входящего документа

**Оценщик:** Оркестратор (Claude Opus 4.6)

## Что сервер дал хорошо

1. **Реквизиты документа** — metadatasearch вернул полный список реквизитов ВходящегоПисьма с типами, включая табличные части (ПолучателиПисьма, ПолучателиОтвета, ПолучателиКопий, АдресаУведомленияОПрочтении). Это сильная сторона CodeMetadata — парсер ОтчётаПоКонфигурации.
2. **Бизнес-процессы** — metadatasearch нашёл все 8 БП, где ВходящееПисьмо входит в тип поля Предмет (Рассмотрение, Исполнение, Согласование, Утверждение, Подписание, Ознакомление, КомплексныйПроцесс, РешениеВопросовВыполненияЗадач).
3. **Регистры сведений** — 11 регистров найдены через metadatasearch по типу измерения. Отличный результат.
4. **Подписки на события** — найдена ключевая подписка ПередЗаписью (ДокументооборотПраваДоступа).

## Что сервер НЕ дал

1. **Нумератор ВходящегоПисьма** — два запроса (#2, #3) не нашли верхний блок документа с нумератором. Нашли только ИсходящееПисьмо. Это проблема чанкинга — верхний блок документа (с нумератором, типом номера, автонумерацией) не попал в релевантные чанки.
2. **Тело функции ЗаписатьВходящееПисьмо** — codesearch нашёл имя функции, но не вернул её тело. Причина: чанки обрезаны на 1000 символов (RecursiveCharacterTextSplitter), процедура длиннее одного чанка.
3. **Обработчик ПриЗаписи** — не найден ни в модуле объекта, ни в подписках. Возможно, его просто нет для ВходящегоПисьма (логика через подписки на ОпределяемыйТип).
4. **Справка (Help) по документу ВходящееПисьмо** — helpsearch не нашёл. Либо справки нет в конфигурации, либо она не проиндексирована.

## Паттерны поведения агента

- Агент сделал 18 вызовов — многовато для одного вопроса. Причина: codesearch плохо работает для поиска конкретных обработчиков событий (ПередЗаписью/ПриЗаписи), агент делал 4 попытки с разными формулировками.
- Первый вызов metadatasearch вернул 79K символов (40 чанков) — избыточно, но содержательно.
- helpsearch дал один полезный результат из трёх попыток.

## Выявленные проблемы RAG

| Проблема              | Проявление в этом тесте                                         |
| --------------------- | --------------------------------------------------------------- |
| Чанкинг 1000 символов | Нумератор документа, тело ЗаписатьВходящееПисьмо — обрезаны     |
| Нет границ процедур   | codesearch возвращает середины процедур без начала/конца        |
| Шум в метаданных      | Запрос про нумерацию ВходящегоПисьма возвращает ИсходящееПисьмо |
| Справка неполная      | helpsearch не содержит справки по ВходящемуПисьму               |

## Вывод

CodeMetadata хорошо справляется с **структурными вопросами** (реквизиты, типы, связи через метаданные), но слабо — с **поиском конкретного кода** (тела процедур, обработчики событий). Для бизнес-вопроса про жизненный цикл документа сервер дал ~70% информации, остальное агенту пришлось додумывать или оставить без ответа.
