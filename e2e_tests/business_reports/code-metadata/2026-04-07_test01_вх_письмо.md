# Жизненный цикл ВходящегоПисьма в 1С:Документооборот КОРП 3.0

**Конфигурация:** 1С:Документооборот КОРП 3.0 (DO3)  
**MCP-сервер:** 1c-code-metadata  
**Дата анализа:** 2026-04-07

---

## 1. Реквизиты, заполняемые при создании

### Стандартные реквизиты (платформа 1С)
- **Дата** (синоним: "Создано") — дата и время создания документа
- **Номер** — строка до 50 символов, автонумерация, периодичность год

### Собственные реквизиты документа

| Реквизит | Тип | Описание |
|----------|-----|----------|
| `ОтправительАдресат` | СправочникСсылка.АдресатыПочтовыхСообщений | Отправитель письма (адресат) |
| `Тема` | Строка(1024) | Тема письма |
| `Предмет` | Составной тип | Предмет переписки (Проекты, Задачи, Файлы, ДокументыПредприятия, Мероприятия и др.) |
| `Важность` | ПеречислениеСсылка.ВажностьПисем | Отметка о важности письма |
| `ДатаПолучения` | Дата(ДатаВремя) | Дата загрузки письма с почтового сервера |
| `НомерСпособаАдресации` | Число(1,0) | Технический реквизит адресации |
| `ТипТекста` | ПеречислениеСсылка.ТипыТекстовПочтовыхСообщений | Тип текста письма (HTML/Plain) |
| `ВнутреннийЗаголовок` | Строка | Служебная информация почтовых систем (скрытый реквизит) |

### Табличные части

| Табличная часть | Реквизит | Тип |
|-----------------|----------|-----|
| `ПолучателиПисьма` | Адресат | АдресатыПочтовыхСообщений |
| `ПолучателиОтвета` | Адресат | АдресатыПочтовыхСообщений |
| `ПолучателиКопий` | Адресат | АдресатыПочтовыхСообщений |
| `АдресаУведомленияОПрочтении` | Адресат | АдресатыПочтовыхСообщений |

### Создание письма (программное)

Входящее письмо создаётся через функцию `ЗаписатьВходящееПисьмо` в общем модуле `ВстроеннаяПочтаСервер`. Это происходит автоматически при получении сообщений с почтового сервера через регламентное задание или команду "Получить почту". После записи применяются правила оповещения (`ПрименитьПравилаОповещенияДляВходящихПисем`).

Также письмо может быть создано вручную пользователем из журнала "Электронная почта".

## 2. Бизнес-процессы по входящему письму

ВходящееПисьмо может быть указано в качестве предмета (поле `Предметы.Предмет`) следующих бизнес-процессов:

| Бизнес-процесс | Назначение |
|----------------|-----------|
| **Рассмотрение** | Направление руководителю на рассмотрение и наложение резолюции |
| **Исполнение** | Поручение исполнения по письму сотруднику (сотрудникам) |
| **Согласование** | Согласование ответного письма или действий |
| **Утверждение** | Утверждение документа |
| **Подписание** | Подписание связанного исходящего письма или документа |
| **Ознакомление** | Ознакомление сотрудников с содержанием письма |
| **КомплексныйПроцесс** | Сложный составной процесс, включающий несколько этапов |
| **РешениеВопросовВыполненияЗадач** | Эскалация вопросов при выполнении задач |

> **Замечание:** Бизнес-процесс **Регистрация** также существует в конфигурации (найден в подписках на события), однако его прямая связь с ВходящимПисьмом через предмет не подтверждена в метаданных — возможно, работает через ДокументыПредприятия.

### Типовая последовательность (из справки):

```
[Создание письма]
       ↓
[На регистрации] ← вручную (секретарь)
       ↓
[Зарегистрирован] ← вручную (секретарь)
       ↓
[На рассмотрении] ← автоматически при запуске БП "Рассмотрение"
       ↓
[Рассмотрен] ← автоматически при завершении БП "Рассмотрение"
       ↓
[На исполнении] ← автоматически при запуске БП "Исполнение"
```

Состояния хранятся в регистре `ТекущиеСостоянияДокументов`. Изменение состояния происходит:
- **Вручную** — пользователь в поле "Состояние" карточки документа
- **Автоматически** — при создании и завершении бизнес-процесса

## 3. Регистрация входящего письма

### Нумерация

Документ ВходящееПисьмо имеет автонумерацию (платформенная нумерация документов). По аналогии с ИсходящимПисьмом:
- Тип номера: Строка
- Длина номера: 50 символов
- Периодичность: Год
- Нумератор: собственный (не общий с другими документами)

> **Важно:** Для входящих писем электронной почты (e-mail) номер — это внутренний номер документа базы данных. Для входящих документов (корреспонденция, МЭДО) регистрационный номер ведётся в справочнике `ДокументыПредприятия` (реквизиты: `РегистрационныйНомер`, `ДатаРегистрации`).

### Кто регистрирует

Из справки по регистру `ТекущиеСостоянияДокументов`:
- **Секретарь** (пользователь с соответствующей ролью) вручную меняет состояние документа с "На регистрации" на "Зарегистрирован"
- При регистрации заполняются поля регистрационного номера и даты регистрации
- Права доступа на регистрацию определяются через справочник `ВидыДокументов` (реквизит `ЯвляетсяВходящейКорреспонденцией`)

### Правила обработки писем

Справочник `ПравилаОбработкиПисем` содержит реквизит `ДляВходящихПисем` (Булево), что позволяет настраивать автоматическую обработку входящих писем: перемещение в папки, пометка на удаление и т.д.

## 4. Обработчики событий при записи

### Подписки на события (найдено в метаданных)

**Событие ПередЗаписью:**

| Подписка | Источник | Обработчик |
|---------|----------|------------|
| `ДокументооборотПраваДоступаПередЗаписьюДокумента` | `ДокументОбъект.ВходящееПисьмо` (явно) | `ДокументооборотПраваДоступа.ДокументооборотПраваДоступаПередЗаписьюДокумента` |
| `КОДПередЗаписьюСсылочногоОбъектаДокумента` | `ОпределяемыйТип.СсылочныеОбъектыДокументыКОД` (возможно включает ВходящееПисьмо) | `КОДСобытия.ПередЗаписьюОбъектаДокумента` |

**Событие ПриЗаписи:**

Явных подписок с `ДокументОбъект.ВходящееПисьмо` для события ПриЗаписи в метаданных не найдено. Модуль объекта документа ВходящееПисьмо, вероятно, не содержит обработчиков ПередЗаписью/ПриЗаписи напрямую — используются подписки на события.

### Что происходит при записи

1. **ПередЗаписью** (подписка `ДокументооборотПраваДоступа`):
   - Проверка и обновление прав доступа к документу
   - Контроль разрезов доступа (Организация, ВидыДокументов, ГрифДоступа и т.д.)

2. **После записи** (программный код):
   - Применение правил оповещения для входящих писем (`ПрименитьПравилаОповещенияДляВходящихПисем`)
   - Обновление регистров сведений (ОтметкиВремени, ТекстыПисем, СведенияОПросмотре и др.)

## Сводный вывод

**ВходящееПисьмо** в DO3 — это документ почтового клиента (встроенный e-mail), а не документооборотный объект в классическом смысле (как ДокументыПредприятия).

Ключевые характеристики:
- **Создаётся** автоматически при получении почты с сервера (функция `ЗаписатьВходящееПисьмо`) или вручную
- **Бизнес-процессы** запускаются из карточки письма через "Создать на основании" — Рассмотрение, Исполнение, Согласование и другие
- **Регистрация** в классическом смысле (с регистрационным номером) производится вручную секретарём через изменение состояния; регистрационные номера хранятся в ДокументыПредприятия
- **Обработчик ПередЗаписью** — единственная явная подписка `ДокументооборотПраваДоступа`, управляющая правами доступа
- **Регистры** — широкий набор (~10 регистров) для хранения текстов, состояний прочтения, папок, истории доставки
