## Что сервер дал хорошо

- **Полная структура ВходящегоПисьма**: реквизиты Тема (Строка 1024), ОтправительАдресат → АдресатыПочтовыхСообщений, УчетнаяЗапись, Предмет; ТЧ ПолучателиПисьма/Копий/Ответа
- **Полная структура ИсходящегоПисьма**: ПисьмоОснование → ВходящееПисьмо/ИсходящееПисьмо, УчетнаяЗапись, ОтправительКонтакт, ДатаОтправки; те же ТЧ
- **Процесс Рассмотрение**: полная структура с Резолюция (Строка, многострочный), ВариантОбработкиРезолюции (умолчание НаправитьНаИсполнение), ОбрабатывающийРезолюцию, СрокИсполненияПроцессаИсполнения — всё из metadatasearch
- **Процесс Исполнение**: ТЧ Исполнители (ПроверкаЗаполнения = ВыдаватьОшибку), СрокИсполненияПроцесса
- **КонтекстВыполненияЗадачи**: полная структура — ТекстРезультатаВыполнения, ПриложенияРезультатаВыполнения (слепок файлов через `РаботаСЗадачами.СлепокПриложенийРезультатаПоИсточнику`), РезультатДействия, ФактическийИсполнитель, ОснованиеФактическогоИсполнителя
- **Регистры**: ТекущиеСостоянияДокументов, ДанныеБизнесПроцессов, ИсторияЗадач, СведенияОПросмотреПисем, ОповещенияОПисьмах, НеотправленныеИсходящиеПисьма
- **Ключевой код ОбработатьРегистрациюИсходящегоДокумента**: полная процедура с BSL — поиск связи через `ТипыСвязей.ОтправленВОтветНа`, формирование событий, `ЗаписатьПоступившиеОбновленияЗадач`
- **Документация (helpsearch)**: описание Рассмотрения — назначение, три ветви обработки резолюции, задача "Обработать резолюцию"

## Что сервер НЕ дал

- **Конкретный модуль ПриЗаписи ВходящегоПисьма** — найден только косвенно через ВстроеннаяПочтаСервер
- **Регистр Нумерация** — агент не искал нумерацию специально (но это не дефицит сервера)
- **Регистры файлов** — НаличиеФайлов не найден (но ИсторияЗадач с приложениями найдена — компенсировано)
- **Регистры накопления** (КоличествоЗадач, КоличествоДействийЗадач) — не покрыты

## Паттерны поведения агента

- Чередование metadatasearch и codesearch — грамотная стратегия: сначала метаданные для понимания структуры, затем код для логики
- 5 вызовов metadatasearch + 4 codesearch + 1 helpsearch + 1 metadatasearch = сбалансированное использование всех трёх инструментов
- 0 retry — каждый запрос был результативен, что говорит о качестве индексации и подборе запросов
- helpsearch дал высокорелевантный результат по процессу Рассмотрение (в отличие от cloud-embeddings)
- Бизнес-отчёт высокого качества: таблицы реквизитов с типами, полный BSL-код ОбработатьРегистрациюИсходящегоДокумента, карта объектов сценария
- Реквизиты документов корректные (не выдуманные) — проверено по метаданным

## Вывод

Сервер code-metadata показал лучший результат из трёх: 100% полезных вызовов, 0 retry, сбалансированное использование metadatasearch + codesearch + helpsearch. Наличие проиндексированных метаданных позволило получить точную структуру документов и бизнес-процессов, а codesearch дополнил картину конкретными процедурами. Оптимален для сквозных сценариев, где нужно знать и «что» (структуру), и «как» (код).
