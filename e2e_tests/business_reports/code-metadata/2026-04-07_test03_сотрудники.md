## 1. Общая характеристика справочника Сотрудники

**Имя:** `Справочники.Сотрудники`  
**Синоним:** Сотрудники  
**Комментарий:** "Содержит сотрудников на определенных должностях в структурных единицах."

**Ключевые свойства:**
| Свойство | Значение |
|---|---|
| Иерархический | Ложь |
| Владелец (подчинён) | `Справочник.ФизическиеЛица` |
| ИспользованиеПодчинения | Элементам |
| ДлинаНаименования | 150 символов |
| ИспользоватьСтандартныеКоманды | Ложь |

**Важно:** Справочник Сотрудники является **подчинённым** справочнику ФизическиеЛица. Один человек (ФизЛицо) может иметь несколько записей-сотрудников (например, совместитель на нескольких должностях).

## 4. Связи с другими объектами конфигурации

### 4.1. Справочник ФизическиеЛица
**Тип связи:** Владелец/Подчинённый.  
- Стандартный реквизит **Владелец** имеет синоним "Физическое лицо" и тип `СправочникСсылка.ФизическиеЛица`
- ФизЛицо хранит ФИО, дату рождения, пол и другие персональные данные
- Один человек = одно ФизЛицо + один или несколько Сотрудников (на разных должностях/периодах)

### 4.2. Справочник Должности
**Тип связи:** Реквизит Должность.  
- Тип: `СправочникСсылка.Должности`
- **Обязательный** (ПроверкаЗаполнения: ВыдаватьОшибку)
- Комментарий: "Занимаемая сотрудником должность"

### 4.3. Справочник СтруктураПредприятия
**Тип связи:** Реквизит Подразделение.  
- Тип: `СправочникСсылка.СтруктураПредприятия`
- **Обязательный** (ПроверкаЗаполнения: ВыдаватьОшибку)
- Индексируется (Индексирование: Индексировать)

### 4.4. Связи через регистры
- **РС.СотрудникиПользователей** (Пользователь + Сотрудник) — связывает сотрудника с пользователем информационной базы
- **РС.ОсновныеСотрудники** — хранит "основного" сотрудника

## 5. Механизм замещения сотрудников

Механизм замещения реализован через отдельный справочник **ЗамещающиеИПомощники** и сопутствующие объекты.

### 5.1. Справочник ЗамещающиеИПомощники

**Реквизиты:**

| Имя | Тип | Обязательный | Примечание |
|---|---|---|---|
| Сотрудник | `СправочникСсылка.Сотрудники` | **Да** | Замещаемый сотрудник (индексируется) |
| Замещающий | `СправочникСсылка.Сотрудники` | **Да** | Кто замещает (индексируется) |
| ВидЗамещения | `ПеречислениеСсылка.ВидыЗамещения` | Нет | Замещающие / Помощники |
| ДатаНачала | Дата(Дата) | **Да** | Начало действия замещения |
| ДатаОкончания | Дата(Дата) | Нет | Окончание действия |
| Действует | Булево | Нет | Флаг актуальности |
| Основание | `ДокументСсылка.Отсутствие` | Нет | Документ-основание (индексируется) |
| Создал | `СправочникСсылка.Сотрудники` | Нет | Кто создал запись |
| Комментарий | Строка(0) | Нет | |

**Табличная часть ВопросыЗамещения:**
- **Область** (`СправочникСсылка.ОбластиЗамещения`) — область/сфера действия замещения
- **ЗначениеОтбора** (`ОпределяемыйТип.ЗначениеОтбораОбластиЗамещения`) — конкретное значение для отбора

### 5.2. Перечисление ВидыЗамещения
| Значение | Назначение |
|---|---|
| Замещающие | Полное замещение на период отсутствия |
| Помощники | Постоянные помощники сотрудника |

### 5.3. Инфраструктура механизма замещения

| Объект | Тип | Назначение |
|---|---|---|
| ЗамещающиеИПомощники | Общий модуль (Сервер, Внешнее соединение) | Бизнес-логика замещения |
| ОбработкаСроковЗамещающихИПомощников | Регламентное задание | Автоматически обрабатывает сроки: активирует/деактивирует замещения |
| ОбластиЗамещения | Справочник | Справочник областей, на которые распространяется замещение |
| ВсеИсполнителиДействийЗадач | Регистр сведений | Хранит исполнителей задач с учётом замещений |

**Алгоритм регламентного задания:** вызывает метод `ЗамещающиеИПомощники.ОбработкаСроковЗамещающихИПомощников`, запускается предопределённо с 3 повторами при аварийном завершении.

**Связь с документом Отсутствие:** поле Основание ссылается на `ДокументСсылка.Отсутствие` — замещение создаётся на основании документа об отсутствии сотрудника.

## 7. Итоговая схема структуры

```
ФизическиеЛица (ФИО, персональные данные)
    └── Сотрудники [подчинён ФизЛицам]
            ├── Должность → Справочник.Должности (обязательный)
            ├── Подразделение → Справочник.СтруктураПредприятия (обязательный)
            ├── ГрафикРаботы → Справочник.ГрафикиРаботы
            ├── Помещение → Справочник.ТерриторииИПомещения
            ├── ДатаНачалаДействия, ДатаОкончанияДействия, Действует
            ├── ПредставлениеВДокументах, ПредставлениеВПереписке
            ├── ТЧ: ДополнительныеРеквизиты
            └── ТЧ: КонтактнаяИнформация

Механизм замещения:
    ЗамещающиеИПомощники
        ├── Сотрудник → Сотрудники (замещаемый)
        ├── Замещающий → Сотрудники (кто замещает)
        ├── ВидЗамещения → Перечисление.ВидыЗамещения (Замещающие/Помощники)
        ├── ДатаНачала, ДатаОкончания, Действует
        ├── Основание → Документ.Отсутствие
        └── ТЧ: ВопросыЗамещения (Область, ЗначениеОтбора)
    ОбщийМодуль.ЗамещающиеИПомощники (логика)
    РегламентноеЗадание.ОбработкаСроковЗамещающихИПомощников (автоматика)
    РС.ВсеИсполнителиДействийЗадач (учёт замещающих в задачах)
```

## 8. Выводы для разработчика

1. **ФИО сотрудника** берётся из справочника ФизическиеЛица через `Сотрудник.Владелец` — в самом справочнике Сотрудники ФИО не хранится.

2. **Статус** определяется реквизитами `Действует` (булево, индексируется), `ДатаНачалаДействия` и `ДатаОкончанияДействия`.

3. **Замещение** полностью вынесено в отдельный справочник ЗамещающиеИПомощники. Активация/деактивация выполняется регламентным заданием автоматически. Документ Отсутствие является основанием.

4. **Связка с пользователем ИБ** — через регистр СотрудникиПользователей, не через реквизит самого справочника.

5. **Рабочее время** накапливается в РегистреНакопления РабочееВремяСотрудников; хронометраж — в РС.ХронометражРабочегоВремениСотрудников.

6. **Права доступа** хранятся в нескольких регистрах: ПолномочияСотрудников (профили), СоставСубъектовПравДоступа, ПраваПоДескрипторамДоступаРегистров, ПраваПоДескрипторамДоступаОбъектов.
