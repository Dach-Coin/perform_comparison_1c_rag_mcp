## Что сервер дал хорошо
- **metadatasearch по структурированным путям** — главное преимущество сервера. Запросы вида `Документы.УведомлениеМЭДО.Реквизиты` и `Документы.УведомлениеМЭДО.ТабличныеЧасти` вернули полные списки реквизитов и ТЧ со всеми типами данных
- **Полная структура всех 3 документов** с типами реквизитов (Строка(36), ОпределяемыйТип.ПредметМЭДО, ПеречислениеСсылка.ТипыУведомленийМЭДО и т.д.)
- **9 табличных частей УведомлениеМЭДО** — самый полный результат по ТЧ среди трёх серверов (Регистрация, ОтказВРегистрации, ПостановкаНаКонтроль, ПодготовкаДоклада, НаправлениеДоклада, Опубликование, ХодИсполнения, ПринятиеКИсполнению, ПостановкаНаКонтроль_КонтрольныеПунктыДокумента)
- **Константа АвтоматическиОтправлятьКвитанцииМЭДО** найдена
- **Состав подсистемы МЭДО** через metadatasearch "HTTPСервисы МЭДО" — вернул полный перечень объектов подсистемы
- **codesearch** дал процедуры обмена: ВыполнитьОбменМЭДО, ОтправитьИсходящиеДокументы, ПолучитьВходящиеСообщения
- **Полная цепочка обмена** восстановлена: получение + отправка документов, уведомлений, квитанций через каталоги ФС

## Что сервер НЕ дал
- **Первый вызов metadatasearch по имени** ("УведомлениеМЭДО") — 61K символов с битой кодировкой (кириллица в source_file нечитаема). 48 чанков, но полезной информации минимум
- **helpsearch** не содержит справки по МЭДО — вернул общую документацию по ЭДО (обмен с контрагентами, банки) без релевантности
- **Значения перечисления СпособыОбменаМЭДО** — не удалось получить ни через metadatasearch, ни через codesearch
- **ТЧ документа КвитанцияМЭДО** — не подтверждено их отсутствие (graph-metadata подтвердил: ТЧ нет)
- **ТЧ документа ДанныеДокументаМЭДО** — не найдена ТЧ "Пакеты" (graph-metadata нашёл)

## Паттерны поведения агента
- Начал с metadatasearch по имени → битая кодировка → переключился на helpsearch → промах → переключился на codesearch (правильная эскалация)
- Освоил паттерн структурированных путей для metadatasearch (`Документы.ХХХ.Реквизиты`, `Документы.ХХХ.ТабличныеЧасти`) — это ключевая находка: metadatasearch работает хорошо с точными путями
- Дублирующий вызов #17 (полный повтор #15) — 1 лишний вызов
- Пропущен вызов #8 в нумерации лога (17 фактических вызовов при заявленных 18)
- Средний по эффективности: 78% полезных, но самый информативный по структуре метаданных

## Выявленные проблемы RAG
| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| Кодировка в metadatasearch по имени | Первый вызов (61K) вернул битую кириллицу в полях document и source_file. Формально данные есть, но нечитаемы |
| helpsearch не покрывает МЭДО | Справочная документация по МЭДО отсутствует — helpsearch возвращает нерелевантную общую документацию по ЭДО |
| metadatasearch не раскрывает значения перечислений | Запрос `Перечисления.СпособыОбменаМЭДО значения` не нашёл значения перечисления |
| Дублирование при нечётких запросах | Один и тот же запрос (#15 и #17) выполнен дважды с почти идентичным результатом |

## Вывод
Code-metadata — лучший сервер для вопросов о структуре документов МЭДО. Паттерн `Документы.ХХХ.Реквизиты` через metadatasearch позволяет получить полные списки реквизитов с типами. Найдены все 9 ТЧ УведомлениеМЭДО. По коду (codesearch) сервер также силён — нашёл все процедуры обмена. Слабые стороны: битая кодировка при поиске по имени, отсутствие справки по МЭДО, неспособность раскрыть значения перечислений. Из 5 подвопросов 4 раскрыты полно (документы, структура, HTTP-сервисы, регламентные задания), 1 частично (процесс отправки — модули найдены, но детали из codesearch менее подробны, чем у cloud-embeddings).
