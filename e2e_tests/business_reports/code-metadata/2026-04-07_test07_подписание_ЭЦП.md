## 1. Общая информация о бизнес-процессе

В конфигурации существует отдельный бизнес-процесс **БизнесПроцессы.Подписание** — полноценный объект метаданных с собственными реквизитами, табличными частями, маршрутом и формами.

Основная форма процесса: `БизнесПроцесс.Подписание.Форма.ФормаБизнесПроцесса` (синоним в интерфейсе — "Согласование").  
Дополнительная форма: `ФормаИзменениеПараметров` (синоним — "Повтор подписания") — используется при перезапуске.

## 3. Поддержка электронной подписи (ЭП/ЭЦП)

### Типы подписания — Перечисление «СпособыПодписанияПредметаПроцесса»

| Значение | Синоним | Описание |
|---|---|---|
| **НаБумаге** | "На бумаге" | Традиционная собственноручная подпись |
| **ПЭП** | "Простая ЭП" | Простая электронная подпись (значение по умолчанию) |
| **УЭП** | "Усиленная ЭП" | Усиленная электронная подпись (квалифицированная или неквалифицированная) |

Реквизит `СпособПодписания` задаётся как на уровне экземпляра процесса, так и в шаблоне (`Справочники.ШаблоныПодписания`).

### Шаблоны подписания — Справочник «ШаблоныПодписания»

Иерархический справочник, позволяющий сохранять готовые конфигурации процесса Подписание:
- **СпособПодписания** — тип ЭП для шаблона (по умолчанию ПЭП)
- **Участники** (ТЧ) — список подписантов с типами: Сотрудники / ПолныеРоли / **АвтоподстановкиДляПроцессов** (динамическое определение подписанта)
- **ИспользоватьУсловия** — признак использования условий запуска
- **КоличествоИтераций** — по умолчанию 2
- **ВладелецШаблона** — может принадлежать КомплексномуПроцессу или шаблону комплексного процесса

### Работа с ЭП включается функциональной опцией

Флаг **«Электронные подписи»** (в Администрировании → Настройки программы → Настройки криптографии) включает работу с криптографией. Требует установки криптопровайдера (КриптоПро CSP, ViPNet CSP и т.д.).

### Сертификаты — Справочник «СертификатыКлючейЭлектроннойПодписиИШифрования»

Хранит личные сертификаты пользователей. Реквизиты: КомуВыдан, Организация, ФизическоеЛицо, Пользователи, срок действия. Используется при подписании документов с помощью УЭП.

## 4. Хранение данных о подписях

### Регистр сведений «ЭлектронныеПодписи» (основной)

Независимый непериодический регистр:

| Структура | Имя | Тип | Примечание |
|---|---|---|---|
| Измерение | ПодписанныйОбъект | ОпределяемыйТип.ПодписанныйОбъект | Полиморфный — файл, документ и т.д. |
| Измерение | ПорядковыйНомер | Число | Порядковый номер подписи у объекта |
| Ресурс | Подпись | ХранилищеЗначения (двоичные данные) | Сами данные подписи |
| Реквизит | ПодписьВерна | Булево | Результат последней проверки |
| Реквизит | СертификатДействителен | Булево | Действительность сертификата |
| Реквизит | ТипПодписи | Перечисление.ТипыПодписиКриптографии | CAdES, и т.п. |

Записи отображаются на закладке **«ЭП»** учётной карточки документа.

### Регистр сведений «ПростыеЭлектронныеПодписи»

Отдельный регистр для хранения ПЭП (простая электронная подпись) — применяется в контексте ЭДО.

### Регистр сведений «ЭлектронныеПодписиПоМЧД»

Для хранения подписей в контексте машиночитаемых доверенностей (МЧД). Измерения: ПодписанныйОбъект, ХешПодписи.

### Регистр сведений «ДоверенностиЭлектронныхПодписей»

Хранит сведения о доверенностях, на основании которых подписывается документ.

### Регистр сведений «СостояниеПодписанияЭД»

Хранит текущее состояние процесса подписания электронных документов.

### Регистр сведений «СведенияОВнешнемПодписанииЭлектронныхПодписей»

Хранит сведения о подписании документов внешними системами.

**Вывод:** Данные о подписях хранятся в **регистрах сведений** (не в справочниках). Основной — `РегистрСведений.ЭлектронныеПодписи`.

## 5. Что происходит после подписания — смена статуса документа

### Статусы в процессе подписания

В общем модуле `ДействияСервер` определена следующая логика смены состояния:

| Этап | Состояние документа |
|---|---|
| Процесс запущен, задача выдана | `Перечисления.СостоянияДокументов.НаПодписании` |
| Подписывающий завершил задачу | `Перечисления.СостоянияДокументов.Подписан` |

### Реквизит «РезультатПодписания»

После завершения процесса в реквизите `БП.РезультатПодписания` устанавливается значение из перечисления **РезультатыПроцессаПодписания**:
- **Подписано** — все участники подписали успешно

В модуле `Делопроизводство` проверяется: `Документ.РезультатПодписания = Перечисления.РезультатыПодписания.Подписано`.

### Блокировка документа

После применения ЭП документ становится **недоступным для изменений** — это обеспечивается платформенным механизмом: подписанные данные блокируются от редактирования.

├── РаботаСЭП (серверный - запись и чтение ЭП)

## 8. Итоговые ответы на вопросы

**Бизнес-процесс Подписание** — реализован как отдельный объект `БизнесПроцессы.Подписание`. Имеет маршрут с точками действия, поддерживает итерации, многоэтапное подписание и шаблоны.

**Параметры при запуске:** Подписывающие задаются в ТЧ Участники (конкретные сотрудники, роли, или через автоподстановки). Тип подписи задаётся реквизитом СпособПодписания (НаБумаге / ПЭП / УЭП). Срок — как общий, так и индивидуальный для каждого участника.

**Поддержка ЭП/ЭЦП:** Да, полноценно. Поддерживаются ПЭП (простая ЭП) и УЭП (усиленная ЭП). По умолчанию тип — ПЭП. Для УЭП требуется криптопровайдер и сертификат из справочника СертификатыКлючейЭлектроннойПодписиИШифрования.

**Хранение данных о подписях:** В **регистрах сведений**: основной — `РегистрСведений.ЭлектронныеПодписи` (ключ — подписанный объект + порядковый номер, ресурс — двоичные данные подписи). Отдельные регистры для ПЭП и МЧД-подписей.

**Смена статуса документа:** При запуске процесса документ получает статус **«НаПодписании»**, после завершения всех задач — **«Подписан»**. Реквизит `РезультатПодписания` устанавливается в значение **«Подписано»**. Документ блокируется от изменений.

**Общие модули:** `РаботаСЭП` (серверный), `РаботаСЭПКлиент` (клиентский), `РаботаСЭПКлиентСервер`, `ЭлектроннаяПодписьСлужебный`, `ФайловыеФункции`, `Делопроизводство`, `ДействияСервер`.
