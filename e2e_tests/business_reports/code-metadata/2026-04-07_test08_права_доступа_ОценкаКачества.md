# Оценка качества: TEST-08 — Права доступа к задачам
**Сервер:** 1c-code-metadata  
**Дата:** 2026-04-07  
**Оценщик:** Оркестратор (Claude Opus 4.6)

## Общая оценка: ЧАСТИЧНО

## Метрики
| Метрика                | Значение     |
| ---------------------- | ------------ |
| Вызовов MCP            | 16           |
| Полезных               | 12 (75%)     |
| Шумных                 | 4 (25%)      |
| Retry                  | 1            |

| Токенов агента (total) | ~308K        |

## Что сервер дал хорошо

1. **Константа-переключатель RLS** — `ДокументооборотИспользоватьОграничениеПравДоступа` найдена через metadatasearch вместе с функциональной опцией и её составом (УправлениеРасчетомПрав, ОбновлениеПравДоступа, УровниДоступа и др.) — ценная структурная информация.
2. **Подписка на события для Задачи** — metadatasearch нашёл `ПодпискиНаСобытия.ДокументооборотПраваДоступаПередЗаписьюДокумента` с источником `ДокументОбъект.Задача` — прямое доказательство привязки RLS к записи задачи.
3. **Модуль РаботаСРабочимиГруппами** — codesearch нашёл функции: `ПерезаписатьРабочуюГруппуОбъекта`, `ДобавитьУчастниковВРабочуюГруппуОбъекта`, `ПроверитьПраваАвтораПередЗаписьюРабочейГруппы`, `ПроверитьПраваУчастниковРабочейГруппыНаОбъект`.
4. **Руководитель видит задачи подчинённых** — найден конкретный код формы `Задачи` с функцией `ЗаполнитьГруппировкуЗадачиПодчиненных` и вызовом `РаботаСПользователями.ПодразделенияПодчиненных()`.
5. **Команда «ЗадачиПодчиненных»** — найдена через metadatasearch как команда документа Задача (группа навигации «Важное»).
6. **Проверка прав в коде** — codesearch дал полную цепочку: `ДокументооборотПраваДоступаПовтИсп.ВключеноИспользованиеПравДоступа()` → `ПраваСотрудникаПоОбъекту()` → полные права если полноправный.
7. **Механизм дескрипторов** — найдены все 5 ключевых регистров (ДескрипторыДляОбъектов, ПраваПоДескрипторамДоступаОбъектов, ПраваПоДескрипторамДоступаРегистров, ОчередьОбновленияПравДоступа, ДескрипторыДоступаРегистров).

## Что сервер НЕ дал

1. **Конкретные роли доступа к задачам** — ни одна из 7 ролей (ЧтениеЗадач, РаботаСЗадачами и др.) не найдена. metadatasearch не индексирует раздел «Роли» конфигурации с привязкой к объектам.
2. **Точная структура РС РабочиеГруппы** — измерение `Участник` найдено с типом `ОпределяемыйТип.КонтейнерыСотрудников`, но измерение `Объект` и его составной тип не раскрыты.
3. **Перечисление ВидимостьДействийВПредметах** — не обнаружено (graph нашёл).
4. **Константа ДобавлятьРуководителямДоступПодчиненных** — упомянута косвенно через подписку, но сама константа не найдена в metadatasearch.
5. **Грифы доступа** — не упомянуты.
6. **helpsearch по теме прав** — полностью нерелевантный результат (настройки пользователей, регламентные задания).

## Паттерны поведения агента

- Агент начал с metadatasearch (2 вызова), затем helpsearch, далее перешёл на codesearch — **стандартная стратегия** обхода трёх инструментов.
- codesearch использован 8 раз с точными именами модулей и функций — высокая эффективность. Агент быстро понял, что codesearch — основной источник.
- metadatasearch использован 5 раз: 3 полезных, 2 нерелевантных. Качество выше чем у cloud (где metadata пуста), но всё ещё без ролей.
- helpsearch использован 2 раза: 1 нерелевантный, 1 средний (но ~57K символов — очень тяжёлый ответ, сохранён во временный файл). **Проблема**: helpsearch склонен возвращать огромные нерелевантные чанки.
- **Расход контекста**: ~165K символов — самый высокий из трёх серверов, во многом из-за тяжёлого helpsearch (#14 ~57K).

## Выявленные проблемы RAG

| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| metadatasearch не индексирует роли по объектам | Запрос «Роли конфигурации Задача доступ» не нашёл ни одной роли — только функциональные опции и команды |
| helpsearch возвращает чрезмерно большие чанки | Вызов #14 вернул ~57K символов (~102K токенов) за один раз — 34% всего контекста. Плохой chunking справочной документации |
| helpsearch нерелевантен по теме прав | «документ Задача права доступа исполнитель» → настройки пользователей и регламентные задания. Семантическая связь слабая |
| metadatasearch дублирует при общих запросах | Вызов #11 «РегистрСведений.РабочиеГруппы Объект Изменение» вернул обрывки с `РежимСокращенияТипа` — парсер XML путает имена реквизитов с атрибутами XML |

## Вывод

Сервер code-metadata обеспечил наиболее **сбалансированный** результат среди трёх: metadatasearch дал структурную информацию (константы, функциональные опции, подписки на события), а codesearch — логику работы (функции, проверки, цепочки вызовов). Бизнес-отчёт — самый подробный и структурированный. Главная слабость — отсутствие ролей (как и у cloud) и тяжёлый helpsearch, раздувающий контекст. Для данного теста сервер показал ~70% покрытия вопросов.
