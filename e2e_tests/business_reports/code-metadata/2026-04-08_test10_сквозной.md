# Бизнес-отчёт: Сквозной сценарий Документооборот КОРП 3.0
**Тест:** TEST-10 | **Сервер:** 1c-code-metadata | **Дата:** 2026-04-08

---

## Описание сценария

Входящее письмо от контрагента поступает в организацию, проходит рассмотрение руководителем, который выносит резолюцию. По резолюции создаётся задача на исполнение, исполнитель выполняет её с прикреплением файла-ответа, после чего формируется исходящее письмо.

---

## ШАГ 1. Поступление ВходящееПисьмо от контрагента

### Объект: Документ.ВходящееПисьмо

**Ключевые реквизиты:**
| Реквизит | Тип | Описание |
|----------|-----|----------|
| Тема | Строка(1024) | Тема письма |
| ОтправительАдресат | СправочникСсылка.АдресатыПочтовыхСообщений | Отправитель-контрагент |
| УчетнаяЗапись | СправочникСсылка.УчетныеЗаписиЭлектроннойПочты | Почтовый ящик-получатель |
| ВнутреннийЗаголовок | Строка | Служебная информация почты (скрытый реквизит) |
| Предмет | СправочникСсылка (множественный тип) | Предмет переписки |

**Табличные части:**
- ПолучателиПисьма → Адресат (АдресатыПочтовыхСообщений)
- ПолучателиКопий → Адресат
- ПолучателиОтвета → Адресат

### Регистры, обновляемые при создании:
- **РегистрыСведений.ТекущиеСостоянияДокументов** — фиксируется текущее состояние (Измерение: Состояние → ПеречислениеСсылка.СостоянияДокументов)
- **РегистрыСведений.СведенияОПросмотреПисем** — признак просмотра письма пользователями
- **РегистрыСведений.ОповещенияОПисьмах** — оповещения ответственных пользователей (применяются правила ПравилаОбработкиПисем через процедуру ПрименитьПравилаОповещенияДляВходящихПисем)

### Код, обрабатывающий:
- **ОбщийМодуль.ВстроеннаяПочтаСервер** — основная логика получения писем, применение правил оповещения, запись в регистр ОповещенияОПисьмах
- Проверка на дублирование по ИдентификаторуСообщения через `Документ.ВходящееПисьмо КАК ВходящееПисьмо ГДЕ ВходящееПисьмо.ИдентификаторСообщения = &ИдентификаторСообщения`

## ШАГ 2. Рассмотрение письма и вынесение Резолюции

### Объект: БизнесПроцесс.Рассмотрение

**Ключевые реквизиты:**
| Реквизит | Тип | Описание |
|----------|-----|----------|
| Наименование | Строка(250) | Описание поручения (обязательное) |
| Резолюция | Строка(неогр.) | Текст резолюции руководителя (многострочный) |
| ОбрабатывающийРезолюцию | Сотрудники / ПолныеРоли | Кто обрабатывает резолюцию |
| ВариантОбработкиРезолюции | ПеречислениеСсылка.ВариантыОбработкиРезолюции | Умолчание: НаправитьНаИсполнение |
| Важность | ПеречислениеСсылка.ВариантыВажностиОбъектов | Умолчание: Обычная |
| СрокИсполненияПроцесса | Дата | Срок рассмотрения |
| СрокИсполненияПроцессаИсполнения | Дата | Срок для дочернего процесса Исполнение |

**Табличные части:**
- ИсполнителиОзнакомления → Исполнитель + СрокИсполнения (при варианте "направить на ознакомление")

**Формы:**
- ФормаБизнесПроцесса (синоним "Рассмотрение") — основная форма
- ФормаИзменениеПараметров (синоним "Задача рассмотрения") — форма задачи для руководителя

**Варианты обработки резолюции (Перечисление ВариантыОбработкиРезолюции):**
- НаправитьНаИсполнение (умолчание)
- НаправитьНаОзнакомление
- НеНаправлять

### Задача для руководителя: Задача.ЗадачаИсполнителя
- СостояниеБизнесПроцесса → ПеречислениеСсылка.СостоянияБизнесПроцессов

### Регистры, обновляемые:
- **РегистрыСведений.ДанныеБизнесПроцессов** — фиксируется Состояние процесса (СостоянияБизнесПроцессов)
- **РегистрыСведений.ТекущиеСостоянияДокументов** — обновляется состояние связанного документа

### Код, обрабатывающий:
- Модуль менеджера **БизнесПроцесс.Рассмотрение.МодульМенеджера** — логика маршрутизации
- Шаблон инструкции: Обработка.ЗагрузкаТиповыхИнструкций → ПроцессРассмотрение ("Как создать процесс Рассмотрение")
- При завершении задачи рассмотрения → ЗадачаНаОзнакомлениеСРассмотрением ("Как выполнить задачу Обработать резолюцию")

## ШАГ 3. Создание Задачи на исполнение

### Объект: БизнесПроцесс.Исполнение

**Ключевые реквизиты:**
| Реквизит | Тип | Описание |
|----------|-----|----------|
| СрокИсполненияПроцесса | Дата | Срок исполнения (берётся из Рассмотрения.СрокИсполненияПроцессаИсполнения) |

**Табличные части:**
- Исполнители (ПроверкаЗаполнения = ВыдаватьОшибку) — список исполнителей задачи

### Объект: Задача.ЗадачаИсполнителя

Создаётся автоматически при старте БизнесПроцесса.Исполнение. Исполнитель видит задачу в своём списке дел.

**Связь с шаблонами:** КомплексныйПроцесс может содержать в ТЧ ПредметыЗадач ссылки на ШаблоныИсполнения.

### Регистры, обновляемые:
- **РегистрыСведений.ДанныеБизнесПроцессов** — состояние нового процесса Исполнение
- **РегистрыСведений.ТекущиеСостоянияДокументов** — состояние исходного ВходящееПисьмо меняется (например, "На исполнении")

### Код, обрабатывающий:
- При завершении Рассмотрения с вариантом НаправитьНаИсполнение → автоматически стартует БизнесПроцесс.Исполнение
- Обработка вопросов по задаче: **БизнесПроцесс.РешениеВопросовВыполненияЗадач** (форма "Карточка вопроса по задаче")

---

## ШАГ 4. Исполнитель выполняет задачу и прикладывает файл-ответ

### Объект: Задача.ЗадачаИсполнителя (выполнение)

При выполнении задачи формируется **КонтекстВыполненияЗадачи** — структура с полями:
| Поле | Описание |
|------|----------|
| ТекстРезультатаВыполнения | Текстовый комментарий исполнителя |
| ПриложенияРезультатаВыполнения | Слепок прикреплённых файлов (РаботаСЗадачами.СлепокПриложенийРезультатаПоИсточнику) |
| РезультатДействия | СправочникСсылка.РезультатыДействийЗадач |
| ФактическийИсполнитель | Сотрудник, фактически выполнивший задачу |
| ОснованиеФактическогоИсполнителя | СправочникСсылка.ЗамещающиеИПомощники (если замещение) |

### Регистры, обновляемые:
- **РегистрыСведений.ИсторияЗадач** — сохраняется КонтекстВыполненияЗадачи (ТекстРезультата, ПриложенияРезультата, РезультатДействия)
- **РегистрыСведений.ДанныеБизнесПроцессов** — состояние процесса Исполнение переходит в "Завершён"
- **РегистрыСведений.ТекущиеСостоянияДокументов** — состояние документа обновляется

### Код, обрабатывающий:
- **БизнесПроцесс.Исполнение.МодульМенеджера** — функция РезультатВыполненияЗадачи → Истина (есть метод)
- **БизнесПроцесс.РешениеВопросовВыполненияЗадач.МодульМенеджера** — аналогичная структура КонтекстВыполненияЗадачи
- **ОбщийМодуль.РаботаСЗадачами** — методы ДобавитьПоступившееОбновлениеЗадачи, ЗаписатьПоступившиеОбновленияЗадач

## ШАГ 5. Формирование ИсходящееПисьмо с ответом

### Объект: Документ.ИсходящееПисьмо

**Ключевые реквизиты:**
| Реквизит | Тип | Описание |
|----------|-----|----------|
| ПисьмоОснование | ДокументСсылка.ВходящееПисьмо / ИсходящееПисьмо | Письмо-основание (связь с входящим) |
| УчетнаяЗапись | СправочникСсылка.УчетныеЗаписиЭлектроннойПочты | Почтовый ящик для отправки |
| ОтправительКонтакт | Сотрудники / Контрагенты / КонтактныеЛица | Отправитель |
| ДатаОтправки | Дата | Дата фактической отправки |
| Тема | Строка | Тема письма |
| Предмет | множественный тип (Проекты, ЗадачаИсполнителя, ДокументыПредприятия и др.) | Предмет переписки |

**Табличные части:**
- ПолучателиПисьма → Адресат (АдресатыПочтовыхСообщений)
- ПолучателиКопий → Адресат
- ПолучателиОтвета → Адресат

### Связи объектов:
```
ВходящееПисьмо ←→ ИсходящееПисьмо
  ТипСвязи: ПисьмоОтправленоВОтветНа (Справочники.ТипыСвязей)
  ТипСвязи: ПолученоВОтветНаПисьмо
  ТипСвязи: ОтправленВОтветНа
```

### Регистры, обновляемые:
- **РегистрыСведений.НеотправленныеИсходящиеПисьма** — фиксируется письмо до момента отправки (Измерение: Письмо → ДокументСсылка.ИсходящееПисьмо)
- **РегистрыСведений.ТекущиеСостоянияДокументов** — состояние письма (Черновик → Отправлено)
- При регистрации исходящего документа → **ОбщийМодуль.ИнтеграцияЗадач.ОбработатьРегистрациюИсходящегоДокумента** формирует события ЗарегистрированОтветныйДокумент / СозданОтветныйДокумент для всех активных задач по входящему документу

### Код, обрабатывающий:
```bsl
// ОбщийМодуль.ИнтеграцияЗадач
Процедура ОбработатьРегистрациюИсходящегоДокумента(ЗарегистрированныйДокумент) Экспорт
    // Ищем связанный входящий документ
    ДокументыНаКоторыеОтправленОтвет = СвязиОбъектов.ПолучитьСвязанныеОбъекты(
        ЗарегистрированныйДокумент, Справочники.ТипыСвязей.ОтправленВОтветНа);
    // Формируем событие для активных задач
    ОжидающиеВыполненияДействияЗадач = РаботаСЗадачами
        .ОжидающиеВыполненияДействияЗадачПоПриложениям(ДокументыНаКоторыеОтправленОтвет);
    Для Каждого ДействиеЗадачи Из ОжидающиеВыполненияДействияЗадач Цикл
        РаботаСЗадачами.ДобавитьПоступившееОбновлениеЗадачи(
            НовыеПоступившиеОбновленияЗадач, ДействиеЗадачи,
            Справочники.СобытияОбновленияЗадач.ЗарегистрированОтветныйДокумент);
    КонецЦикла;
    РаботаСЗадачами.ЗаписатьПоступившиеОбновленияЗадач(НовыеПоступившиеОбновленияЗадач, Ложь);
КонецПроцедуры
```

- **ОбщийМодуль.ВстроеннаяПочтаКлиент** — открытие формы ИсходящееПисьмо с параметром Основание:
  ```bsl
  ОткрытьФорму("Документ.ИсходящееПисьмо.ФормаОбъекта", Новый Структура("Основание", Ссылка));
  ```
- **ОбщийМодуль.ВстроеннаяПочтаСервер** — отправка письма через SMTP, запись ДатаОтправки

## Сводная карта объектов сценария

```
[Контрагент] → [Документ.ВходящееПисьмо]
                    │
                    ▼
           [БизнесПроцесс.Рассмотрение]
           (Резолюция, ОбрабатывающийРезолюцию)
                    │
                    ▼ (ВариантОбработкиРезолюции = НаправитьНаИсполнение)
           [БизнесПроцесс.Исполнение]
           (ТЧ Исполнители, СрокИсполненияПроцесса)
                    │
                    ▼
           [Задача.ЗадачаИсполнителя]
           (выполнение + ПриложенияРезультатаВыполнения)
                    │
                    ▼
           [Документ.ИсходящееПисьмо]
           (ПисьмоОснование → ВходящееПисьмо)
                    │
                    ▼
              [Контрагент-получатель]
```

## Ключевые регистры сквозного сценария

| Регистр | Назначение |
|---------|-----------|
| РегистрыСведений.ТекущиеСостоянияДокументов | Текущее состояние ВходящееПисьмо и ИсходящееПисьмо |
| РегистрыСведений.ДанныеБизнесПроцессов | Состояния процессов Рассмотрение и Исполнение |
| РегистрыСведений.ИсторияЗадач | История выполнения задач, тексты результатов, файлы |
| РегистрыСведений.СведенияОПросмотреПисем | Признак просмотра входящего письма |
| РегистрыСведений.ОповещенияОПисьмах | Оповещения ответственных при поступлении письма |
| РегистрыСведений.НеотправленныеИсходящиеПисьма | Очередь исходящих до отправки |
