- **Замещение** (вызов #2) — одним запросом получена полная структура:
  - 9 реквизитов ЗамещающиеИПомощники с точными типами

  - Документ Отсутствие как основание замещения

## Что сервер НЕ дал

- **Код общего модуля ЗамещающиеИПомощники** — codesearch (вызов #6) вернул нерелевантный код (СрокиИсполненияПроцессов вместо логики замещения). Семантический поиск по коду не нашёл нужный модуль.
- **helpsearch** (вызов #7) — справка по замещению не найдена. Результат: справка по замене элементов, синхронизации данных — полностью нерелевантно.
- **API-функции общего модуля Сотрудники** — не были запрошены агентом (не критично, т.к. metadatasearch дал исчерпывающие структурные данные).

## Паттерны поведения агента

- Эффективная стратегия: начал с metadatasearch «Справочники.Сотрудники» (limit=50) — получил максимум данных сразу
- Целенаправленные последующие запросы: отдельно ЗамещающиеИПомощники, РабочееВремя, Полные права, СотрудникиПользователей
- Всего 5 запросов к metadatasearch — все с высокой релевантностью
- Попытка codesearch и helpsearch (2 запроса) — неудачны, но показывают ограничения этих инструментов
- **Самый эффективный агент** из трёх: 7 вызовов, 71% полезных, все ключевые вопросы закрыты
- Первый вызов metadatasearch дал ~55% всей необходимой информации

## Вывод

Сервер code-metadata — **лучший для структурного анализа справочников**. Один вызов metadatasearch «Справочники.Сотрудники» даёт исчерпывающую структуру: реквизиты с точными типами, проверки заполнения, индексирование, табличные части, формы, команды. Для TEST-03 хватило 5 целевых запросов metadatasearch. Слабые стороны: codesearch и helpsearch неэффективны для поиска бизнес-логики и справки. Главная проблема — объём первого ответа (103K символов), который может исчерпать контекст при сложных вопросах.
