## Что сервер дал хорошо

- **Полные структуры регистров с типами** — metadatasearch вернул измерения, ресурсы, реквизиты с типами данных для всех ключевых регистров. Это уникальное преимущество code-metadata
- **РН.КоличествоЗадач:** 7 измерений с типами (Автор: УчастникЗадач, ВидЗадачи: СправочникСсылка.ВидыЗадач и т.д.), 2 реквизита, 9 ресурсов
- **РН.КоличествоДействийЗадач:** 10 измерений, 3 реквизита (включая ОписаниеПоступившихОбновлений: Строка150), 11 ресурсов
- **6 регистров сведений** найдены через metadatasearch: ДействияЗадач, ВсеИсполнителиДействийЗадач, ЗадачиПоАвторам, ИсторияЗадач, СведенияОбИсполнителяхЗадач, ПоступившиеОбновленияЗадач + НаименованияЗадачУчастниковДействий
- **Код ОбработкаПроведения** обоих документов — ключевые фрагменты через codesearch
- **Механизм записи замещающих** в ВсеИсполнителиДействийЗадач — полный код из ЗамещающиеИПомощники.ManagerModule
- **Таблицы смены статусов** — детальная карта переходов с изменениями в ресурсах обоих регистров накопления

## Что сервер НЕ дал

- **Полный текст ЗаполнитьНаборПоДействию** — код распределён по чанкам, агент получил вызов процедуры, но не всё тело
- **Точная логика вычисления ресурсов** при смене статуса — агент реконструировал таблицу переходов из понимания архитектуры, но точный код заполнения каждого ресурса не получен
- **Механизм асинхронного обновления** — упомянут ОбработатьОбновлениеДействияЗадачи, но без деталей очереди

## Паттерны поведения агента

- **Стратегия двойная:** metadatasearch для структур + codesearch для кода — оптимальное распределение
- **Параллельные вызовы:** Агент активно использовал параллельные пары (#3/#4, #5/#6, #7/#8 и т.д.) — ускорение в ~2 раза
- **18 вызовов** — больше чем у cloud-embeddings (9), но оправдано: metadatasearch даёт структуру, codesearch даёт код
- **Самый быстрый:** 2 мин 09 сек — быстрее cloud-embeddings (4.5 мин) и graph-metadata (13 мин)
- **Бизнес-отчёт самый структурированный:** полная карта регистров с типами, lifecycle diagram, итоговая архитектурная схема

## Выявленные проблемы RAG

| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| Чанкинг: код процедуры разбит | Тело ЗаполнитьНаборПоДействию не получено целиком — распределено по chunk_17, chunk_19 и т.д. |
| Дублирование в результатах | Вызовы #5/#6 вернули частично пересекающиеся результаты (оба нашли КоличествоДействийЗадач) |
| Шум в codesearch при длинных запросах | Вызовы #12 и #18 с длинными запросами вернули нерелевантные результаты (миграции, справочники состояний) |

## Вывод

Сервер code-metadata показал **лучший баланс полноты и эффективности** в TEST-04. metadatasearch — ключевое преимущество: полные структуры регистров с типами полей недоступны другим серверам. Самый быстрый (2 мин), самый структурированный отчёт. Для задач типа «опиши регистры» — оптимальный выбор. Слабое место — чанкинг codesearch не даёт длинных процедур целиком.
