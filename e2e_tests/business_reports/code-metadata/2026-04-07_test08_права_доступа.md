**Дата анализа:** 2026-04-07  
**Источник:** MCP-сервер 1c-code-metadata (код и метаданные конфигурации DO3)  
**Запросов к MCP:** 16

---

## 1. Общая архитектура системы прав доступа

В 1С:Документооборот КОРП 3.0 используется **двухуровневая система прав доступа**:

### Уровень 1 — Ролевые права (стандартные роли 1С)
Определяют, что пользователь вообще может делать с типом объекта (читать, изменять, удалять). Управляются через профили групп доступа (подсистема БСП "Управление доступом").

### Уровень 2 — Ограничение на уровне записей (RLS)
Дополнительный механизм, специфичный для Документооборота. Определяет, какие **конкретные документы** видит пользователь. Включается/отключается через:
- **Константа** `ДокументооборотИспользоватьОграничениеПравДоступа` (синоним: "Ограничивать права доступа")
- **Функциональная опция** `ДокументооборотИспользоватьОграничениеПравДоступа`

**Важно:** Если RLS отключён — каждый пользователь видит все документы (только ролевые права).

## 2. Роли, определяющие доступ к документу Задача

Документ `Задача` включён в функциональную опцию `ИспользоватьЗадачи` (хранится в константе `ИспользоватьЗадачи`). Состав опции:
- `Документ.Задача`
- `Документ.ДействиеЗадачи`
- `РегистрНакопления.КоличествоЗадач`
- `РегистрСведений.ЗадачиПоАвторам`
- `РегистрСведений.ДействияЗадач`
- Справочники видов, состояний, приоритетов задач

Структура ролевого доступа строится через **профили групп доступа** (`Справочник.ПрофилиГруппДоступа`). Пользователь назначается в группу доступа (`Справочник.ГруппыДоступа`), группа связана с профилем, профиль содержит набор ролей.

При включённом ограничении прав (RLS) подсистема дополнительно проверяет вхождение пользователя в **рабочую группу** конкретного документа.

Полноправные пользователи (роль "Полные права") получают доступ ко всем документам независимо от рабочих групп — это явно закодировано в модуле `ДокументооборотПраваДоступа`:

```bsl
// Роли Полные права — все разрешено.
Пользователь = Сотрудники.ЛюбойПользовательСотрудника(Сотрудник);
Если ПользователиСерверПовтИсп.ЭтоПолноправныйПользовательИБ(Пользователь) Тогда
    Права = Новый Структура("Добавление, Изменение, Удаление, УправлениеПравами, Чтение",
        Истина, Истина, Истина, Истина, Истина);
```

## 3. Может ли сотрудник видеть задачи других сотрудников?

**По умолчанию (без RLS):** Да, если есть ролевые права на чтение документа Задача.

**При включённом RLS:** Нет, только задачи, к которым сотрудник имеет отношение через:

### 3.1 Прямое участие в задаче
Сотрудник является исполнителем, автором или членом рабочей группы задачи.

### 3.2 Руководитель видит задачи подчинённых
Это явно реализовано в форме `Documents/Задача/Forms/Задачи`:

```bsl
// Для руководителя отображаем задачи подчиненных.
ПодразделенияПодчиненных = РаботаСПользователями.ПодразделенияПодчиненных(
    Пользователи.ТекущийПользователь(),
    Ложь,
    ИерархияПодчиненныхПодразделений);
```

Также есть специальная команда документа Задача: `ЗадачиПодчиненных` (синоним: "Задачи подчиненных", группа панели навигации "Важное").

Алгоритм: руководитель получает список подчинённых подразделений через иерархию структуры предприятия, затем сотрудников подразделений, исключая тех, кто в списке исключений (`РаботаСЗадачами.ИсключенияИзПодчиненных`).

### 3.3 Особые права просмотра
Модуль `РаботаСЗадачами` содержит функцию `ЕстьОсобыеПраваПросмотра`, которая через `ДокументооборотПраваДоступа.ПраваПользователейПоОбъектам` проверяет право чтения конкретных задач.

### 3.4 Константа ДобавлятьРуководителямДоступПодчиненных
В подписках на события `ДокументооборотПраваДоступаПередЗаписьюПравообразующихКонстант` и `ДокументооборотПраваДоступаПриЗаписиПравообразующихКонстант` упоминается константа `ДобавлятьРуководителямДоступПодчиненных` — она управляет автоматическим расширением прав руководителей.

## 4. Ограничение на уровне записей (RLS) для задач

### Механизм дескрипторов доступа

В конфигурации реализован собственный механизм RLS через систему дескрипторов:

| Объект | Назначение |
|--------|-----------|
| `РегистрСведений.ДескрипторыДляОбъектов` | Связь каждого документа с его дескриптором доступа |
| `Справочник.ДескрипторыДоступаРегистров` | Шаблоны прав для групп объектов |
| `РегистрСведений.ПраваПоДескрипторамДоступаОбъектов` | Вычисленные права: Сотрудник + Объект → Чтение/Изменение/Удаление |
| `РегистрСведений.ПраваПоДескрипторамДоступаРегистров` | То же для регистров |
| `РегистрСведений.ОчередьОбновленияПравДоступа` | Очередь пересчёта при изменении правообразующих данных |

### Пересчёт прав

При записи документа Задача срабатывает подписка на событие:
- `ДокументооборотПраваДоступаПередЗаписьюДокумента` (событие `ПередЗаписью`, источник включает `ДокументОбъект.Задача`)
- Обработчик: `ДокументооборотПраваДоступа.ДокументооборотПраваДоступаПередЗаписьюДокумента`

Пересчёт прав выполняется через:
```bsl
ДокументооборотПраваДоступа.ОпределитьПраваОбъектовТаблицы(Ссылка, Истина);
ДокументооборотПраваДоступа.РассчитатьПраваОбъектовТаблицы(Ссылка, Истина);
```

Также при изменении правообразующих констант (организации, грифы доступа, структура предприятия и т.д.) срабатывают подписки `ДокументооборотПраваДоступаПередЗаписьюПравообразующихКонстант` и `ДокументооборотПраваДоступаПриЗаписиПравообразующихКонстант`.

### Проверка прав в коде

Центральная точка проверки прав при работе с задачами:

```bsl
// В РаботаСБизнесПроцессамиВызовСервера:
ПраваСотрудниковПоЗадачам = ДокументооборотПраваДоступа.ПраваСотрудниковПоОбъектам(
    ЗадачиПоПриложению,
    Истина,
    ПараметрыСеанса.СотрудникиПользователя);

// Проверка права чтения:
Для Каждого СтрокаПрав Из ПраваСотрудниковПоЗадачам Цикл
    ПраваЧтенияПоЗадачам[СтрокаПрав.ОбъектДоступа] = 
        ПраваЧтенияПоЗадачам[СтрокаПрав.ОбъектДоступа] Или СтрокаПрав.Чтение;
КонецЦикла;
```

## 5. Рабочие группы и их связь с доступом к документам

### Структура РС РабочиеГруппы

`РегистрСведений.РабочиеГруппы` — ключевой регистр механизма прав доступа:
- **Измерение `Объект`** — ссылка на документ (Задача, ДокументыПредприятия, Проекты и т.д.)
- **Измерение `Участник`** — тип `ОпределяемыйТип.КонтейнерыСотрудников` (может быть сотрудник, рабочая группа из справочника, подразделение)
- **Ресурс `Изменение`** — булево, определяет право на изменение (не только чтение)

### Как рабочая группа определяет доступ

Если `RLS включён`:
1. При записи документа автоматически формируется рабочая группа (список участников в РС `РабочиеГруппы`)
2. На основе рабочей группы через дескрипторы рассчитываются права (РС `ПраваПоДескрипторамДоступаОбъектов`)
3. При запросе пользователя проверяется наличие записи с его сотрудником и флагом `Чтение = Истина`

### Автоматическое формирование рабочей группы

Функция `РаботаСРабочимиГруппами.ПоОбъектуВедетсяАвтоматическоеЗаполнениеРабочейГруппы` определяет, нужно ли заполнять рабочую группу автоматически.

Для документов шаблон формирования:
```bsl
// В ШаблоныБизнесПроцессов:
Если РабочаяГруппа.Количество() > 0 Тогда
    // Рабочая группа задана — использовать её
    ДокументооборотПраваДоступа.ЗаполнитьДескрипторыОбъектаПоРабочейГруппе(
        ОбъектДоступа, ТаблицаДескрипторов);
Иначе
    // Рабочая группа пуста — доступ для всех пользователей
    ДокументооборотПраваДоступа.ДобавитьИндивидуальныйДескриптор(
        ОбъектДоступа, ТаблицаДескрипторов, Справочники.РабочиеГруппы.ВсеПользователи, Ложь);
КонецЕсли;
// Ответственный всегда получает право изменения:
ДокументооборотПраваДоступа.ДобавитьИндивидуальныйДескриптор(
    ОбъектДоступа, ТаблицаДескрипторов,
    Сотрудники.ЛюбойПользовательСотрудника(ОбъектДоступа.Ответственный),
    Истина); // Истина = право изменения
```

### Расширение рабочей группы на связанные объекты

При добавлении нового участника в рабочую группу задачи, участники автоматически распространяются на связанные объекты:
```bsl
// РаботаСРабочимиГруппами:
МассивДокументов = СвязиОбъектов.СвязанныеОбъектыДляРасширенияРабочихГрупп(Объект,
    Перечисления.ВариантыСинхронизацииДоступа.Расширять);
```

## 6. Общий модуль РаботаСРабочимиГруппами

`CommonModules/РаботаСРабочимиГруппами/Ext/Module.bsl` — ключевой модуль для управления доступом через рабочие группы.

### Основные функции модуля

| Функция | Назначение |
|---------|-----------|
| `ПолучитьПустуюТаблицуУчастников()` | Создаёт пустую таблицу участников нужной структуры |
| `ДобавитьУчастникаВТаблицуНабора(Участники, Сотрудник, Объект)` | Добавляет сотрудника в набор участников |
| `ПерезаписатьРабочуюГруппуОбъекта(Объект, Участники, ...)` | Записывает рабочую группу в РС РабочиеГруппы |
| `ДобавитьУчастниковВРабочуюГруппуОбъекта(Объект, Участники)` | Добавляет участников к существующей группе |
| `ПоОбъектуВедетсяАвтоматическоеЗаполнениеРабочейГруппы(Объект)` | Проверяет признак автозаполнения |
| `РасширитьРабочуюГруппуСвязанныхОбъектов(Объект)` | Расширяет группы связанных документов |
| `ПроверитьПраваАвтораПередЗаписьюРабочейГруппы(Ссылка, Участники, Автор)` | Проверяет права автора изменений |
| `ПроверитьПраваУчастниковРабочейГруппыНаОбъект(Объект, Участники)` | Проверяет, что новые участники не нарушают политику |

### Связь с модулем ДокументооборотПраваДоступа

`РаботаСРабочимиГруппами` — управляет **составом рабочих групп** (кто входит).  
`ДокументооборотПраваДоступа` — управляет **вычислением и хранением прав** (что каждый может делать).

Взаимодействие: при изменении рабочей группы `РаботаСРабочимиГруппами` вызывает `ДокументооборотПраваДоступа.ОпределитьДескрипторыОбъекта`, которая пересчитывает права и записывает результат в РС `ПраваПоДескрипторамДоступаОбъектов`.

### Модуль РаботаСРабочимиГруппамиКлиент

Клиентский модуль (`РаботаСРабочимиГруппамиКлиент`) реализует UX-взаимодействие:
- `РабочаяГруппаПриНачалеРедактирования` — обработчик начала редактирования строки таблицы РГ
- `РабочаяГруппаПриОкончанииРедактирования` — обработчик окончания редактирования
- `РабочаяГруппаТаблицаПередУдалением` — обработчик удаления участника

Используется в формах: `ДокументыПредприятия`, `Мероприятия`, `СообщенияОбсуждений`, `ШаблоныКомплексныхБизнесПроцессов`, `ШаблоныСогласования`.

## 7. Итоговая схема работы прав доступа к задачам

```
Пользователь запрашивает список задач
        │
        ▼
Есть роль для чтения Документ.Задача?
    НЕТ → Доступ запрещён на уровне платформы
    ДА  ↓
        ▼
Включена константа ДокументооборотИспользоватьОграничениеПравДоступа?
    НЕТ → Видит все задачи (только ролевые права)
    ДА  ↓
        ▼
Проверяется РС ПраваПоДескрипторамДоступаОбъектов
        │
        ├── Сотрудник входит в рабочую группу задачи → ВИДИТ
        ├── Сотрудник — ответственный задачи → ВИДИТ + ИЗМЕНЯЕТ
        ├── Сотрудник — руководитель исполнителя → ВИДИТ (задачи подчинённых)
        ├── Константа ДобавлятьРуководителямДоступПодчиненных → влияет
        └── Рабочая группа задачи пуста → все пользователи ВИДЯТ
```

## 9. Ограничения и оговорки

1. **Специфика серверного поиска:** Конкретный список ролей конфигурации (раздел "Роли" в метаданных) с привязкой к объекту `Документ.Задача` в данном анализе не был получен напрямую — metadatasearch возвращал общие роли без детализации по объектам.

2. **Отключение RLS:** Если RLS отключён (по умолчанию в некоторых конфигурациях), видимость определяется только ролями. Это важно для небольших внедрений.

3. **Задача vs ЗадачаИсполнителя:** В конфигурации есть два разных объекта: `Документ.Задача` (документ со списком исполнителей) и `Задачи.ЗадачаИсполнителя` (стандартный объект задачи 1С, порождается бизнес-процессами). Права на них управляются по-разному.
