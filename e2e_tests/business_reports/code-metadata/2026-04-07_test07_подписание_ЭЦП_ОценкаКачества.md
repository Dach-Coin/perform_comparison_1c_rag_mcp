## Что сервер дал хорошо

- **Полная структура БП Подписание** — через metadatasearch получены все 20 реквизитов с точными типами: Автор, Важность, СпособПодписания (по умолчанию ПЭП), КоличествоИтераций, РезультатПодписания и др.
- **Табличные части** — полная структура ТЧ Участники (Подписывающий: Сотрудники/ПолныеРоли, СрокИсполнения, Пройден, ТочкаМаршрута), ТЧ Предметы (составной тип из 12 объектов)
- **Перечисление СпособыПодписанияПредметаПроцесса** — три значения (НаБумаге, ПЭП, УЭП) с синонимами, значение по умолчанию ПЭП
- **Регистр ЭлектронныеПодписи** — подтверждён с измерениями (ПодписанныйОбъект, ПорядковыйНомер), связанные регистры (ПростыеЭП, ЭПпоМЧД, ДоверенностиЭП)
- **Смена статуса документа** — через codesearch чётко найден переход `НаПодписании → Подписан` в модуле `ДействияСервер`, а также проверка `РезультатПодписания = Подписано` в модуле `Делопроизводство`
- **Шаблоны подписания** — полная структура справочника ШаблоныПодписания, включая `АвтоподстановкиДляПроцессов` как тип подписывающего
- **Общие модули** — РаботаСЭП с функциями (ЗаполнитьСписокПодписейФайла, ЗаписатьЭПФайлу, ЗанестиИнформациюОПодписях), РаботаСЭПКлиент, РаботаСЭПКлиентСервер, ЭлектроннаяПодписьСлужебный
- **Подписки на события** — найдены: БизнесСобытияПередЗаписьюБизнесПроцесса, ПраваДоступаПриЗаписиБизнесПроцессов, РезультатыВыполненияПередЗаписьюБизнесПроцесса

## Что сервер НЕ дал

- **Ресурсы РС ЭлектронныеПодписи** — точный список ресурсов получен косвенно из кода (не из структуры метаданных). Graph-metadata дал эту информацию полностью через Cypher
- **Точный список форм БП Подписание** — формы упомянуты (ФормаБизнесПроцесса, ФормаИзменениеПараметров), но их содержимое не раскрыто
- **Константы управления ЭП** — не найдены (ИспользоватьЭлектронныеПодписи и др.)
- **Общее количество модулей по теме ЭП** — найдены основные 8 модулей, но graph нашёл 96 модулей через Cypher

## Паттерны поведения агента

- Отличная стратегия: начал с helpsearch для контекста, затем metadatasearch для структуры, затем codesearch для логики — логичный порядок
- 7 из 12 вызовов — metadatasearch, 3 — codesearch, 2 — helpsearch. Грамотный баланс инструментов
- Ноль шумных вызовов и ноль retry — каждый запрос дал полезный результат
- Запросы были точно сформулированы (например, `БизнесПроцессы.Подписание.ТабличныеЧасти.Участники.Реквизиты`) — сервер хорошо отвечает на структурированные запросы
- Объём ответов умеренный (6-14K символов за вызов) — нет проблемы с гигантскими чанками
- Самый экономный по токенам из трёх серверов (~190K vs ~550K у cloud и ~85K у graph)

## Выявленные проблемы RAG

| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| Нет прямого доступа к ресурсам РС | Ресурсы регистра получены из кода, а не из структуры метаданных |
| Helpsearch не знает про БП Подписание | Справка по конкретному БП не найдена — только общие инструкции по ЭП/ЭДО |
| Ограниченный список модулей | Найдено 8 модулей из 96 реально существующих — codesearch возвращает top-5, потеря полноты |

## Вывод

Code-metadata показал лучший результат из трёх серверов на этом тесте: **100% полезных вызовов, ноль retry, полное покрытие всех 5 вопросов**. Metadatasearch даёт точную структуру объектов с типами, codesearch дополняет кодовой логикой. Сервер идеально подходит для задач, требующих одновременно знания структуры метаданных и поиска кода. Единственное ограничение — ограниченный top-N результатов не позволяет найти все 96 модулей по теме ЭП (нашёл только 8 основных).
