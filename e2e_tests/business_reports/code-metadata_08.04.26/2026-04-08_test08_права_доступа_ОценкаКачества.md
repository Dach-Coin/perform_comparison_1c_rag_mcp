## Что сервер дал хорошо

- **Конфигурационные роли для Задачи** — `ЧтениеЗадач`, `ИзменениеВыполнениеЗадач`, `ЧтениеПроцессовИЗадачБезОграничения` найдены через search_metadata_xml (вызовы #28-30)
- **Полная цепочка RLS** — РС.РабочиеГруппы → РС.ДескрипторыДляОбъектов → РС.ПраваПоДескрипторамДоступаОбъектов — раскрыта через комбинацию codesearch (#27) + search_metadata_xml (#8) + get_metadata_details (#26)
- **Модуль РаботаСРабочимиГруппами** — полная карта: 55 методов, 2565 строк, ключевые процедуры с номерами строк (get_module_structure, вызов #5)
- **Модуль ДокументооборотПраваДоступа** — 106 процедур/функций, 5854 строки (get_module_structure, вызов #9)
- **Главный переключатель RLS** — Константа.ДокументооборотИспользоватьОграничениеПравДоступа и код функции ВключеноИспользованиеПравДоступа (codesearch #18)
- **Механизм замещения** — ОбластиЗамещения.Задачи / ЗадачиПросмотр / ВсеОбласти (metadatasearch #20 + codesearch #16-17)
- **Структура Документ.Задача** — 30 реквизитов, 2 ТЧ, привилегированный режим при проведении (get_metadata_details #15)
- **Структура РС.РабочиеГруппы** — измерение Объект включает DocumentRef.Задача, ресурсы Изменение/Автоподстановка (get_metadata_details #26)
- **Код проверки прав** — ПроверитьПраваПередЗаписьюРабочейГруппы, ПроверитьПраваУчастниковРабочейГруппыНаОбъект — реальный BSL-код (codesearch #25)
- **Паттерн ВЫБРАТЬ РАЗРЕШЕННЫЕ** — подтверждён в запросах к ЗадачаИсполнителя (codesearch #23)

## Что сервер НЕ дал

- **Тексты RLS-ограничений в ролях** — конкретный WHERE-clause платформенного RLS из XML роли `ЧтениеЗадач` не извлечён. Это ограничение: search_metadata_xml ищет по тексту, но сами тексты ограничений — длинные XML-атрибуты, которые могут не попасть в индекс
- **Профили пользователей** (Делопроизводитель, Руководитель и их полномочия) — хранятся в данных, а не в метаданных конфигурации
- **search_function** — ошибка валидации (#11), аналогично TEST-07
- **graph_dependencies** — ошибка параметра depth (#24), не критично

## Паттерны поведения агента

- **Глубокое исследование**: 30 вызовов — самый «тяжёлый» тест в серии. Агент не остановился на поверхностном ответе, а раскопал всю цепочку RLS до конкретного SQL
- **Разнообразие инструментов**: codesearch (13), metadatasearch (4), search_metadata_xml (5), get_module_structure (4), get_metadata_details (2), stats (1), search_function (1 ошибка), graph_dependencies (1 ошибка)
- **Без retry**: ни одного повторного вызова — все 30 вызовов были уникальные запросы, агент не дублировал
- **Эффективный search_metadata_xml**: именно через него нашлись конфигурационные роли (вызовы #28-30), которые не находились через metadatasearch (#3)

## Выявленные проблемы RAG

| Проблема | Проявление в этом тесте |
| -------- | ----------------------- |
| metadatasearch по object_type=Роль не находит конфигурационные роли | Вызов #3: вместо ролей конфигурации нашёл прикладные справочники (ПрофилиГруппДоступа, ПолныеРоли) |
| search_function — нестабильный API | Ошибка #11: агент не угадал сигнатуру (name vs query) |
| graph_dependencies — ошибка параметра depth | Вызов #24: параметр не принят |
| Тексты RLS-ограничений не индексированы | Длинные XML-атрибуты ограничений доступа не попали в поиск |

## Вывод

Сервер отлично подходит для анализа системы прав доступа — сложнейшей подсистемы DO3. Благодаря комбинации codesearch + search_metadata_xml + get_module_structure агент раскрыл полную архитектуру: от конфигурационных ролей до прикладного механизма дескрипторов. Единственное ограничение — конкретные тексты WHERE-ограничений платформенного RLS не извлекаются. Для практического анализа прав доступа сервер полностью достаточен.
