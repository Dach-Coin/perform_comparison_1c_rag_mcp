## Что сервер дал хорошо

1. **Полная архитектура нумерации** — все 4 ключевых объекта найдены и раскрыты:
   - Справочник.Нумераторы (16 реквизитов, включая 8 флагов НезависимаяНумерацияПо*)
   - РС.НастройкиНумерации (15 реквизитов — привязка нумератора к контексту)
   - РС.Нумерация (12 измерений, ресурс ТекущийНомер)
   - РС.ПропускиРегистрационныхНомеров (14 реквизитов)

2. **Карта модуля Нумерация** — get_module_structure показал все 30 функций с номерами строк. Это позволило агенту точно ориентироваться: СформироватьЧисловойНомерДокумента (8-190), СформироватьСтроковыйНомерДокумента (193-248), РазобратьФорматНомера (251-406), ПолучитьНумераторДокумента (1014-1204).

3. **Алгоритм формирования номера** — двухэтапный процесс (числовой → строковый) раскрыт через codesearch: шаблонный механизм с маркерами в квадратных скобках ([Номер], [ИндексВидаДок], [ДатаРегистрации]).

4. **Бизнес-правила из справки** — helpsearch дал ценную информацию: кто регистрирует (секретарь vs авторы), сроки (в день утверждения), обязательные поля. Два вызова helpsearch дали 13694 символа полезного контента.

5. **Перечисления** — найдены значения ПериодичностьНумераторов (Год, Квартал, Непериодический), НазначенияНумераторов (РегистрационныйНомер, ВременныйНомер).

6. **Связь с делопроизводством** — обнаружены РС.ИсторияСостоянийДокументов и РС.ТекущиеСостоянияДокументов, процедуры ПредметМожетБытьЗарегистрирован и ЗарегистрироватьПредмет.

## Что сервер НЕ дал

1. **Значения перечисления СпособыНумерации** — найден сам объект, но конкретные значения не извлечены (get_metadata_details не был вызван для этого перечисления).

2. **Полный список маркеров шаблона** — найдены [Номер], [ИндексВидаДок], [ДатаРегистрации], [Контрагент], [РегистрационныйНомер], но не весь перечень (он задаётся динамически в коде РазобратьФорматНомера).

3. **Тело функции ЗарегистрироватьПредмет** — найдена только проверочная функция ПредметМожетБытьЗарегистрирован, но не основная процедура регистрации. Возможно, имя отличается от ожидаемого.

## Паттерны поведения агента

- **Широкий обзор → углубление**: агент начал с metadatasearch + helpsearch для обзора, затем углубился в get_metadata_details для каждого объекта, затем codesearch для кода. Правильная стратегия для обзорного вопроса.
- **2 ошибки search_function** (вызовы #11, #12) — агент передал неправильный параметр (query вместо name). Быстро переключился на codesearch как fallback. Это баг в API search_function или в понимании агентом его интерфейса.
- **24 вызова за ~12 минут** — больше всех трёх тестов, но тема широкая (нумерация + регистрация + настройки + процесс). Каждый вызов приносил новую информацию.
- **0 шумных вызовов** (не считая ошибок инструмента) — каждый успешный вызов дал релевантные результаты.

## Вывод

Сервер code-metadata нового образа дал **исчерпывающую картину** системы нумерации DO3: от справочника Нумераторы с 8 флагами независимости до алгоритма формирования номера через шаблон. Комбинация metadatasearch (обнаружение) + get_metadata_details (полные структуры) + get_module_structure (карта модуля) + codesearch (код) + helpsearch (бизнес-правила) покрывает все аспекты вопроса. Две ошибки search_function — единственная проблема, легко обойдённая через codesearch.
