## Сигнатура функции

```bsl
Функция ОпределитьФактическихИсполнителей(
    ДействияЗадач,
    ВыполнитьОтИмени,
    ВыбранныйФактическийИсполнитель,
    РеквизитыДействийЗадач = Неопределено) Экспорт
```

**Параметры:**
| Параметр | Описание |
|---|---|
| `ДействияЗадач` | Массив ссылок на документы `ДействиеЗадачи` |
| `ВыполнитьОтИмени` | Пользователь, выполняющий действие (или Неопределено = текущий) |
| `ВыбранныйФактическийИсполнитель` | Структура с данными явно выбранного исполнителя (при ролевой адресации) |
| `РеквизитыДействийЗадач` | Кеш реквизитов действий (опционально) |

**Возвращает:** Структура с ключами:
- `ДействияБезФактИсполнителя` — действия, для которых исполнитель не определён
- `ДействияБезКомуАдресовано` — действия без однозначного адресата (несколько замещающих)
- `ФактическиеИсполнителиПолные` — соответствие {ДействиеЗадачи → СправочникСсылка.ФактическиеИсполнители}
- `ФактическиеИсполнителиПоДействиям` — соответствие {ДействиеЗадачи → Сотрудник}
- `ОснованияФактИсполнителейПоДействиям` — соответствие {ДействиеЗадачи → Замещение}

## Алгоритм работы

Функция последовательно проверяет три случая для каждого действия задачи:

### Шаг 1. Прямой исполнитель — сотрудник

```
Если исполнитель действия = Сотрудник (не роль):
    Проверяем: совпадает ли он с текущим пользователем/выполняющим от имени?
    Если да → фактический исполнитель = этот сотрудник
```

### Шаг 2. Исполнитель роли

```
Если исполнитель действия = ПолнаяРоль:
    Проверяем: входит ли текущий пользователь в исполнителей этой роли?
    (через РС.ИсполнителиРолей.ИсполнителиРоли())
    Находим пересечение сотрудников пользователя с исполнителями роли.
    Если пересечение не пусто → первый подходящий = фактический исполнитель
    Иначе → основной сотрудник пользователя
```

### Шаг 3. Замещение или помощничество

```
Если ни шаг 1, ни шаг 2 не дали результата:
    Обращаемся к Справочники.ЗамещающиеИПомощники.ВсеЗамещенияПоДействиямЗадач()
    (запрос в РС.ВсеИсполнителиДействийЗадач + Справочник.ЗамещающиеИПомощники)
    
    Если замещающих несколько → добавить в список "требует выбора"
    
    Если выбранный исполнитель передан явно → применить его
    
    Иначе → Справочники.ЗамещающиеИПомощники.АктуальныеЗамещенияПоДействиямЗадач()
    
    По виду замещения:
    - ВидЗамещения = Помощники → фактический = помощник (СтрЗамещения.Сотрудник)
    - ВидЗамещения = Замещающие → фактический = основной сотрудник (ОсновнойСотрудник)
```

### Шаг 4. Запись результата

Для каждого варианта вызывается:
```bsl
Справочники.ФактическиеИсполнители.НайтиСоздатьФактическогоИсполнителя(
    Адресат,   // кому адресована задача (роль или сотрудник)
    План,      // плановый исполнитель
    Факт,      // фактический исполнитель
    Отметил)   // кто отметил выполнение
```

Запись сохраняется в `Справочник.ФактическиеИсполнители`.

## Ключевые бизнес-правила

1. **Сотрудник как исполнитель:** если задача адресована конкретному сотруднику — он и есть фактический исполнитель (без проверки замещений).

2. **Роль как исполнитель:** система ищет сотрудников, входящих одновременно в роль и в список сотрудников текущего пользователя. Первый подходящий становится фактическим исполнителем.

3. **Замещающий:** всегда является адресатом задачи ("Кому"), но фактическим исполнителем остаётся **основной сотрудник** (тот, кого замещают).

4. **Помощник:** и адресат, и фактический исполнитель — **сам помощник** (не тот, кому помогают).

5. **Неоднозначность:** если несколько замещающих — система требует интерактивного выбора (форма `ОбщаяФорма.ВыборФактическогоИсполнителяЗадачи`).

6. **Хранение:** запись `Справочник.ФактическиеИсполнители` содержит 4 субъекта: Адресат (кому), План (кто должен был), Факт (кто реально выполнил), Отметил (кто зафиксировал).

Функция `ОпределитьФактическихИсполнителей` в `ОбщиеМодули.РаботаСЗадачами` (строки 24–251) является центральным механизмом разрешения ролевой адресации задач с учётом замещений. Она вызывается при взятии задачи в работу, при выполнении действия задачи, при эскалации и при внешнем подписании.
