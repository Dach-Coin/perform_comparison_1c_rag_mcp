## 1. Параметры настройки при запуске согласования

БП Согласование (`БизнесПроцессы.Согласование`) при запуске настраивается следующими параметрами:

### Исполнители (таб. часть `Исполнители`)

| Реквизит | Тип | Описание |
|---|---|---|
| Исполнитель | СправочникСсылка.Сотрудники / ПолныеРоли / Пользователи | Кто согласовывает |
| ПорядокСогласования | ПеречислениеСсылка.ПорядокВыполненияЗадач | Порядок в обходе |
| СрокИсполнения | Дата(ДатаВремя) | Персональный срок |
| СрокИсполненияДни/Часы/Минуты | Число | Относительный срок |
| Пройден | Булево | Флаг завершения участника |

### Сроки процесса (реквизиты объекта)

- `СрокИсполненияПроцесса` — общий срок процесса
- `СрокОбработкиРезультатов` — срок для обработки результатов автором
- `ВариантУстановкиСрокаОбработкиРезультатов` — как вычисляется этот срок

### Вариант согласования

Реквизит `ВариантСогласования` типа `ПеречислениеСсылка.ВариантыМаршрутизацииЗадач`. Значения:
- **Параллельно** — все согласующие получают задачи одновременно
- **Последовательно** — каждый следующий получает задачу только после завершения предыдущего
- **Смешанно** — комбинированный режим (определяется полем ПорядокСогласования в строке исполнителя)

Логика создания задач реализована в функции `СоздатьЗадачиСогласования()` объектного модуля:
- Параллельно → все строки Исполнителей
- Последовательно → первый непройденный исполнитель
- Смешанно → первая строка с Пройден=Ложь

### Шаблон и автозаполнение

Реквизит `Шаблон` (СправочникСсылка.ШаблоныСогласования). Процедура `ЗаполнитьПоШаблону()` переносит из шаблона:
- ВариантСогласования
- Список исполнителей (таб. часть Исполнители)
- ПодписыватьЭП (при активации функциональных опций)
- Наименование, описание процесса

### Прочие параметры

- `ОбрабатывающийРезультат` — кто обрабатывает результат (автор или роль)
- `ПодписыватьЭП` — требуется ли подпись ЭЦП на визах
- `КоличествоИтераций` / `НомерИтерации` — для повторных согласований
- `ПовторитьСогласование` (Булево) — флаг повторного запуска после ознакомления автора

## 2. Что такое ВизыСогласования и их связь с процессом

`ВизыСогласования` — это **справочник** (Справочники.ВизыСогласования), представляющий отдельную запись о факте согласования конкретным участником конкретного документа.

### Структура Справочника.ВизыСогласования

| Реквизит | Тип | Назначение |
|---|---|---|
| Документ | СправочникСсылка.ДокументыПредприятия | Согласуемый документ |
| Исполнитель | Сотрудники / ПолныеРоли / Пользователи | Кто согласовывал |
| РольИсполнителя | СправочникСсылка.ПолныеРоли | Роль при ролевой адресации |
| РезультатСогласования | ПеречислениеСсылка.РезультатыСогласования | Итог согласования |
| Комментарий | Строка | Замечания согласующего |
| Источник | ДействиеСогласования / ЗадачаИсполнителя / БизнесПроцессСогласование | Откуда создана виза |
| НомерИтерации | Число | При повторных согласованиях |
| Порядок | Число | Порядковый номер в списке |
| Подписана | Булево | Подписана ли ЭП |
| ПомещенаВИсторию | Булево | Сохранена ли в истории |
| Удалена | Булево | Помечена на удаление |
| Автор | Сотрудники / Пользователи | Создавший визу |
| ДатаСоздания, ДатаИсполнения | Дата | Временные метки |

### Связь с бизнес-процессом

Визы создаются и обновляются через **общий модуль РаботаСВизамиСогласования**:
- `СоздатьВизыПоДействию()` — создание виз при старте согласования
- `ОбновитьВизуУчастника()` — обновление при выполнении задачи согласующим
- `ОбновитьВизыУчастниковДействия()` — массовое обновление

Виза привязана к документу (реквизит `Документ`) и к источнику (задача или процесс). Таким образом, одному процессу соответствует набор виз — по одной на каждого согласующего в каждой итерации.

### Ключевые методы работы с визами

- `ПолучитьВизыДокумента()` — все визы документа
- `ПолучитьАктивныеВизыДокумента()` — только активные (не в истории)
- `ЕстьВизыНаСогласовании()` — есть ли незавершённые визы
- `ЕстьВизыНеСогласованные()` — есть ли визы с результатом НеСогласовано
- `ВсеРазногласия()` — получение всех замечаний
- `ТекстЗапросаДляЛистаСогласования()` — запрос для формирования листа согласования

## 3. Результаты согласования

Перечисление `РезультатыСогласования` содержит три значения:

| Значение | Синоним | Описание |
|---|---|---|
| **Согласовано** | Согласовано | Документ согласован без замечаний |
| **СогласованоСЗамечаниями** | Согласовано с замечаниями | Документ согласован, но есть замечания |
| **НеСогласовано** | Не согласовано | Документ не согласован |

Эти результаты устанавливает каждый согласующий при выполнении своей задачи (точка маршрута **Согласовать**).

### Типовые пользовательские сроки (из инструкций)

| Вид документа | Типовой срок |
|---|---|
| Приказы, распоряжения | 3 дня |
| Инструкции, порядки, регламенты | 5 дней |
| Договоры | 3 дня |
| Служебные записки | 1 день |

## 4. Что происходит при завершении всеми согласующими

### Карта маршрута БП Согласование

Маршрут состоит из следующих точек (в порядке прохождения):

```
Старт → Подготовка → [обход] Согласовать → ОбработкаРезультата → Ознакомиться → Завершение
```

- **Подготовка** — подготовительные действия, обновление состояний мероприятий
- **Согласовать** — точка, на которой создаются задачи согласующим (с учётом варианта)
- **УсловиеОбходЗавершен** — условие выхода из цикла обхода согласующих
- **ОбработкаРезультата** — точка обработки итогового результата
- **Ознакомиться** — автор процесса ознакамливается с результатом (может повторить согласование)
- **ПовторитьСогласованиеПроверкаУсловия** — ветка возврата к согласованию
- **Завершение** — финальная точка

### Определение итогового результата

Функция `ИтоговыйРезультатСогласования()` в объектном модуле БП вычисляет итог с приоритетами:

```
НеСогласовано  >  СогласованоСЗамечаниями  >  Согласовано
```

Логика: если хотя бы один согласующий поставил НеСогласовано — итог НеСогласовано. Если все согласовали, но кто-то с замечаниями — итог СогласованоСЗамечаниями. Если все согласовали без замечаний — итог Согласовано.

Результат берётся только из текущей итерации (фильтр по `НомерИтерации`).

### Обработка завершения обхода согласующих

Проверка `ОбходСогласующихЗавершен()` определяет, все ли согласующие завершили работу. При завершении обхода:

1. Функция `ОбработатьДобавлениеЗадачиОтложеннаяОбработкаЗавершенияСогласования()` модуля **РаботаСПроцессамиПоДействиямСобытия** проверяет:
   - `ИтоговыйРезультатСогласования()` — каков итог
   - `ОбходСогласующихЗавершен()` — все ли завершили
   - Наличие замечаний в режиме замечаний

2. При выполнении условий — передаётся в **ОбработкаОчередиЗаданийСервер.ОбработатьДобавлениеЗадачиОтложеннаяОбработкаЗавершенияСогласования** (отложенная обработка)

3. В точке маршрута **ОбработкаРезультата** (процедура `ОбработкаРезультатаОбработка`) — итоговый результат записывается в реквизит `РезультатСогласования` БП

4. Переход к точке **Ознакомиться** — создаются задачи для автора/обрабатывающего результат

5. В точке **Завершение** (процедура `ЗавершениеПриЗавершении`) вызывается `РаботаСПроцессамиПоДействиямСобытия.ПриЗавершенииПроцесса()` — оповещение связанных объектов

### Функции оценки результата завершения (ManagerModule.bsl)

| Функция | Описание |
|---|---|
| `ПроцессЗавершилсяУдачно()` | Завершен И РезультатСогласования <> НеСогласовано |
| `ПроцессЗавершилсяУдачноСЗамечаниями()` | Завершен И РезультатСогласования = СогласованоСЗамечаниями |
| `ПроцессЗавершилсяУдачноБезЗамечаний()` | Завершен И РезультатСогласования = Согласовано |
| `РезультатВыполненияПроцесса()` | Общий метод получения результата |

## Итог

Бизнес-процесс **Согласование** в ДО КОРП 3 реализован как полноценный маршрутный процесс с:
- Гибкими вариантами обхода (параллельный / последовательный / смешанный)
- Хранением результатов в таб.части `РезультатыСогласования` и справочнике `ВизыСогласования`
- Приоритетной логикой итогового результата (НеСогласовано > СогласованоСЗамечаниями > Согласовано)
- Механизмом повторного согласования через точку Ознакомиться автора
- Интеграцией с Комплексным процессом через Справочник.ДействияСогласования
- Поддержкой ЭЦП на визах при наличии функциональных опций
