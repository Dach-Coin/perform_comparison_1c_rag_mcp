## 1. Бизнес-процесс «Подписание»: общее описание

В DO3 бизнес-процесс подписания реализован объектом `БизнесПроцессы.Подписание`. Он является самостоятельным бизнес-процессом наряду с Согласованием, Утверждением, Исполнением и другими. Основная форма — `БизнесПроцесс.Подписание.Форма.ФормаБизнесПроцесса`.

**Точки маршрута (карта маршрута):**
```
ОбеспечитьПодписание → Подписать → [НеПодписано? → ПовторитьПодписание]
                                  ↓
                         ВсеЭтапыПройдены → ОбработатьРезультат → Завершение
```

Процесс поддерживает итерации (`КоличествоИтераций`, `НомерИтерации`) — повторное подписание при неудаче.

## 2. Параметры при запуске: кто подписывает и тип подписи

### 2.1 Участники подписания

Подписывающие задаются в табличной части **`Участники`**:

| Поле | Тип | Описание |
|------|-----|----------|
| `Участник` | `Сотрудники` / `ПолныеРоли` | Исполнитель задачи |
| `Подписывающий` | `Сотрудники` / `ПолныеРоли` | Кто фактически подписывает |
| `ТочкаМаршрута` | ТочкаМаршрутаБизнесПроцессаСсылка.Подписание | Подписать / ОбеспечитьПодписание |
| `СрокИсполнения` | Дата | Срок подписания |
| `ВариантУстановкиСрокаИсполнения` | Перечисление | Как задаётся срок |
| `Пройден` | Булево | Признак завершения этапа |

В шаблоне (`Справочники.ШаблоныПодписания`) участники могут задаваться через `АвтоподстановкиДляПроцессов` — автоматическое определение подписывающего по роли или условию.

Процесс поддерживает **многоэтапное подписание**: данные по этапам хранятся в ТЧ `Этапы` (НаименованиеЭтапа, ПорядокВыполнения, Пройден). Порядок выполнения (`ПорядокВыполненияУчастниками`) — параллельно или последовательно.

### 2.2 Тип подписи (СпособПодписания)

Реквизит `СпособПодписания` (тип `ПеречислениеСсылка.СпособыПодписанияПредметаПроцесса`) задаётся в момент создания процесса. **Значение по умолчанию: ПЭП.**

| Значение | Синоним | Описание |
|----------|---------|----------|
| `НаБумаге` | На бумаге | Бумажное подписание, без ЭП |
| `ПЭП` | Простая ЭП | Простая электронная подпись (отметка в системе) |
| `УЭП` | Усиленная ЭП | Усиленная электронная подпись (криптография) |

**Важно:** значение `УЭП` доступно только если включена **функциональная опция `ИспользоватьЭлектронныеПодписи`**. Это проверяется в коде:
```bsl
Если ПолучитьФункциональнуюОпцию("ИспользоватьЭлектронныеПодписи") Тогда
    Элементы.СпособПодписания.СписокВыбора.Добавить(
        Перечисления.СпособыПодписанияПредметаДействия.УЭП);
КонецЕсли;
```

Для бумажных документов способ подписания автоматически переключается на «На бумаге» (логика в `ОМ.ПравилаОбработкиСервер.ИзмененитьСпособПодписанияНастроек`).

### 2.3 Предметы процесса (что подписывается)

Табличная часть `Предметы` содержит объекты для подписания:

- `ДокументыПредприятия` (внутренние документы)
- `ВходящееПисьмо`, `ИсходящееПисьмо`
- `Файлы`
- `Контрагенты`, `Проекты`, `ПроектныеЗадачи`
- `ПротоколыМероприятий`, `Мероприятия`
- `ТемыОбсуждений`, `СообщенияОбсуждений`
- `Бронь`

### 2.4 Шаблон подписания

Процесс может быть создан по шаблону (`Справочники.ШаблоныПодписания`). Шаблон хранит:
- СпособПодписания, КоличествоИтераций, ПорядокВыполненияУчастниками
- Список участников с автоподстановками и условиями
- УсловияЗапретаВыполнения (алгоритмы проверки перед стартом)
- ИсходныйШаблон — иерархия шаблонов

## 3. Поддержка электронной подписи (ЭП/ЭЦП)

### 3.1 Да, ЭП поддерживается в полном объёме

DO3 поддерживает три уровня ЭП:

| Уровень | Реализация |
|---------|------------|
| ПЭП (Простая ЭП) | Фиксация факта подписания в системе, без криптографии |
| УЭП (Усиленная ЭП) | Криптографическая подпись через сертификат X.509 |
| На бумаге | Офлайн-подписание бумажного документа |

### 3.2 Инфраструктура ЭП

**Справочник сертификатов:** `Справочники.СертификатыКлючейЭлектроннойПодписиИШифрования`  
Реквизиты: ДанныеСертификата (ValueStorage), ДатаПолученияСертификата, ДействителенДо, Отозван, Отпечаток, Должность, КемВыдан, КомуВыдан, **Подписание** (boolean — разрешено ли использование для подписания), Пользователь, Шифрование.

**Регистры, связанные с ЭП:**

| Регистр | Назначение |
|---------|------------|
| `РегистрыСведений.ЭлектронныеПодписи` | Основное хранилище ЭП файлов |
| `РегистрыСведений.СостояниеПодписанияЭД` | Состояние подписания электронных документов (ЭДО) |
| `РегистрыСведений.ПодписываемыеВидыЭД` | Настройка: какой сертификат для каких видов ЭД |
| `РегистрыСведений.ХранилищеСертификатов` | Локальное хранилище сертификатов |
| `РегистрыСведений.ЭлектронныеПодписиПоМЧД` | Подписи с машиночитаемой доверенностью (МЧД) |

**Общие модули для работы с ЭП:**

| Модуль | Назначение |
|--------|------------|
| `ОМ.ЭлектроннаяПодписьСлужебный` | Базовые операции: ПараметрыПодписиКриптографии, СвойстваСертификата |
| `ОМ.ЭлектроннаяПодписьДокументооборотКлиентСервер` | Утилиты ЭП для DO3: параметры отображения сертификатов |
| `ОМ.ЭлектроннаяПодписьДокументооборотСобытияКлиентСервер` | Обработка событий проверки подписи |
| `ОМ.ЭлектроннаяПодписьДокументооборотСобытияКлиент` | Клиентские события ЭП (сертификат, проверка) |
| `ОМ.ЭлектроннаяПодписьДокументооборотСобытия` | Серверные события ЭП |
| `ОМ.ФайловыеФункцииСлужебный` | КриптографияПриСозданииФормыНаСервере |

## 4. Где хранятся данные о подписях

### 4.1 Регистр сведений «ЭлектронныеПодписи» — основное хранилище

Структура `РегистрыСведений.ЭлектронныеПодписи`:

| Поле | Тип | Описание |
|------|-----|----------|
| **Измерение: ПодписанныйОбъект** | Любой ссылочный тип | Что подписано (файл, документ) |
| **Измерение: ПорядковыйНомер** | Число | Номер подписи |
| `Подпись` | v8:ValueStorage | Двоичные данные самой подписи |
| `Сертификат` | v8:ValueStorage | Данные сертификата |
| `ДатаПодписи` | ДатаВремя | Когда подписано |
| `УстановившийПодпись` | Справочник.Пользователи | Кто подписал |
| `ИмяФайлаПодписи` | Строка | Имя .sig файла |
| `КомуВыданСертификат` | Строка | Владелец сертификата |
| `Отпечаток` | Строка | Отпечаток сертификата |
| `ТипПодписи` | Перечисление.ТипыПодписиКриптографии | Тип криптоподписи |
| `ПодписьВерна` | Булево | Результат последней проверки |
| `ДатаПроверкиПодписи` | ДатаВремя | Когда проверена |
| `ТребуетсяПроверка` | Булево | Флаг необходимости проверки |
| `СрокДействияПоследнейМеткиВремени` | ДатаВремя | Метка времени TSP |

### 4.2 Результаты подписания в самом бизнес-процессе

В БП.Подписание хранятся ссылки на результаты в ТЧ **`РезультатыПодписания`**:

| Поле | Тип |
|------|-----|
| `ЗадачаПроцесса` | ЗадачаСсылка.ЗадачаИсполнителя |
| `Идентификатор` | УникальныйИдентификатор |
| `НомерИтерации` | Число |
| `РезультатПодписания` | ПеречислениеСсылка.РезультатыПроцессаПодписания |

Итоговый результат хранится в реквизите `РезультатПодписания` самого БП.

### 4.3 Отдельный справочник шаблонов

`Справочники.ШаблоныПодписания` — справочник-шаблон (иерархический, 2 уровня), хранит настройки многократно используемых процессов подписания.

## 5. Что происходит после подписания: смена статуса документа

### 5.1 Завершение бизнес-процесса

При завершении БП вызывается `ЗавершениеПриЗавершении`:

```bsl
Процедура ЗавершениеПриЗавершении(ТочкаМаршрута, Отказ)
    ДатаЗавершения = ТекущаяДатаСеанса();
    ЗаполнитьИтоговыйРезультатПодписания();          // Подписано / НеПодписано
    РаботаСБизнесПроцессами.ЗаписатьПроцесс(ЭтотОбъект, "ПростаяЗапись");
    РаботаСПроектами.ОтметитьОкончаниеВыполненияПроектнойЗадачи(ЭтотОбъект);
    РаботаСПроцессамиПоДействиямСобытия.ПриЗавершенииПроцесса(ЭтотОбъект);
КонецПроцедуры
```

**Итоговый результат:**
```bsl
Процедура ЗаполнитьИтоговыйРезультатПодписания()
    Если ЕстьНеПодписаноНаТекущейИтерации() Тогда
        РезультатПодписания = Перечисления.РезультатыПроцессаПодписания.НеПодписано;
    Иначе
        РезультатПодписания = Перечисления.РезультатыПроцессаПодписания.Подписано;
    КонецЕсли;
КонецПроцедуры
```

### 5.2 Смена состояния документа

Механизм смены статуса реализован в `Справочники.ДокументыПредприятия / ПередЗаписью`:

```bsl
// При изменении признака ПодписанВсеми:
Если ПодписанВсеми Тогда
    УстановитьСостояние = Перечисления.СостоянияДокументов.Подписан;
Иначе 
    УстановитьСостояние = Перечисления.СостоянияДокументов.НаПодписании;
КонецЕсли;
```

**Жизненный цикл состояний документа при подписании:**

| Состояние | Когда устанавливается |
|-----------|----------------------|
| `НаПодписании` | При запуске БП.Подписание |
| `Подписан` | При завершении — если все подписали (`ПодписанВсеми = Истина`) |
| `тст_ВПодписиОтказано` | Кастомное состояние (расширение Тест) — отказ в подписании |

После подписания также вызывается `Делопроизводство.СтрокаПодписалУтвердил` — формирование строки «Подписал/Утвердил» для вывода в карточке документа.

### 5.3 Состояние самого бизнес-процесса

Реквизит `Состояние` (тип `СостоянияБизнесПроцессов`) отслеживает состояние БП.Подписание:
- По умолчанию при создании: **Активен**
- После завершения: устанавливается платформой автоматически

## 7. Схема взаимодействия объектов

```
Пользователь
    ↓ (запускает)
БизнесПроцессы.Подписание
    ├── Шаблон → Справочники.ШаблоныПодписания
    ├── Участники → Справочники.Сотрудники / ПолныеРоли
    ├── Предметы → Справочники.ДокументыПредприятия / Файлы / ...
    └── СпособПодписания → НаБумаге / ПЭП / УЭП*
            * УЭП доступна только при ФО "ИспользоватьЭлектронныеПодписи"

При выполнении:
    ЗадачаИсполнителя (Подписать)
        ↓ (при УЭП)
    ОМ.ЭлектроннаяПодписьСлужебный → Справочники.СертификатыКлючей...
        ↓ (сохранение)
    РегистрыСведений.ЭлектронныеПодписи (Подпись, Сертификат, ДатаПодписи)

После подписания:
    БП.Подписание.РезультатПодписания = Подписано / НеПодписано
    Справочники.ДокументыПредприятия.Состояние = Подписан / НаПодписании
```

## Итог

Бизнес-процесс **Подписание** в DO3 полностью реализован и поддерживает:
- Три способа подписания: на бумаге, простая ЭП (ПЭП), усиленная ЭП (УЭП)
- Многоэтапное и многократное (итерации) подписание
- Шаблоны с автоподстановками участников
- Криптографическую ЭП через сертификаты X.509 при включённой ФО
- Хранение ЭП в регистре `ЭлектронныеПодписи` (двоичные данные подписи + сертификат)
- Автоматическую смену статуса документа (НаПодписании → Подписан)
- Интеграцию с проектами, комплексными процессами, действиями
