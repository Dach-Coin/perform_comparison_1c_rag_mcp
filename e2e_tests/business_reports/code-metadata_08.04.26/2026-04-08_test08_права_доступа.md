## 1. Объект «Задача» в конфигурации

Документ `Документы.Задача` является полноценным прикладным объектом конфигурации со следующими ключевыми характеристиками:

- **Тип:** Документ (не задача платформы — это прикладной документ 1С)
- **Нумератор:** строковый, непериодический, автонумерация
- **Проведение:** разрешено (привилегированный режим), движения в `РегистрНакопления.КоличествоЗадач`
- **Основные формы:** `ФормаЭлемента`, `ФормаСписка`
- **Вводится на основании:** `Документ.ВходящееПисьмо`

**Состав реквизитов (ключевые):**

| Реквизит | Тип | Назначение |
|----------|-----|------------|
| Автор | ОпределяемыйТип.УчастникЗадач | Создатель задачи |
| Ответственный | ОпределяемыйТип.УчастникЗадач | Ответственный исполнитель |
| Создал | Сотрудники/Пользователи | Технический создатель |
| СостояниеЗадачи | СправочникСсылка.СостоянияЗадач | Текущий статус |
| Проект | СправочникСсылка.Проекты | Проект (если задача проектная) |
| ВышестоящаяЗадача | ДокументСсылка.Задача | Иерархия задач |
| Срок | Дата(ДатаВремя) | Срок исполнения |

**Табличные части:**
- `Участники` — список участников задачи (ВидУчастника, Участник, ДействиеУчастника)
- `Приложения` — вложенные предметы

## 2. Конфигурационные роли для документа «Задача»

В конфигурации определены следующие роли, связанные с документом Задача:

| Имя роли | Синоним | Описание |
|----------|---------|---------|
| `ЧтениеЗадач` | Чтение задач | Базовое право на чтение документов Задача. Содержит ограничения (RLS). |
| `ИзменениеВыполнениеЗадач` | Изменение и выполнение задач | Право на изменение задач и отметку о выполнении |
| `ЧтениеПроцессовИЗадачБезОграничения` | Чтение процессов и задач без ограничения | Право читать задачи **без RLS** — для администраторов и руководителей |
| `ЧтениеДокументовПредприятияБезОграничения` | Чтение документов предприятия без ограничения | Право на чтение всех документов без ограничения |

**Хранение прав ролей:** Регистр сведений `ПраваРолей` (измерения: ОбъектМетаданных, Роль; ресурсы: Изменение, Добавление, ЧтениеБезОграничения, ИзменениеБезОграничения, ДобавлениеБезОграничения, Просмотр, Редактирование, ИнтерактивноеДобавление).

**Важно:** Роли назначаются пользователям не напрямую, а через механизм **Полномочий** (`Справочники.ПрофилиГруппДоступа`, синоним — «Полномочия»). Профиль объединяет набор ролей конфигурации + виды доступа.

## 3. Может ли сотрудник видеть задачи других сотрудников?

**По умолчанию — нет.** Сотрудник видит только те задачи, в рабочую группу которых он включён.

### Механизм ограничения видимости

Система использует двухуровневую проверку:

**Уровень 1 — Платформенный RLS (роли конфигурации):**
- Роль `ЧтениеЗадач` содержит ограничение на уровне записей
- Во всех запросах к задачам используется ключевое слово `ВЫБРАТЬ РАЗРЕШЕННЫЕ` — платформа автоматически фильтрует недоступные записи
- Функция `ДокументооборотПраваДоступа.ДополнитьТекстЗапросаПоПравам()` добавляет условия в динамические запросы

**Уровень 2 — Прикладной механизм дескрипторов:**
```
Документ.Задача
    ↓ (при записи)
РС.РабочиеГруппы [Объект=Задача, Участник, Изменение, Автоподстановка]
    ↓
РС.ДескрипторыДляОбъектов [Объект → Дескриптор]
    ↓
РС.ПраваПоДескрипторамДоступаОбъектов [Дескриптор, Сотрудник, Чтение, Изменение, Добавление, Удаление, УправлениеПравами]
```

**Расчёт прав:** Функция `ДокументооборотПраваДоступа.ПраваСотрудникаПоОбъекту(Объект, Сотрудник)` выполняет JOIN таблиц дескрипторов и возвращает структуру: `{Чтение, Изменение, Добавление, Удаление, УправлениеПравами}`.

### Кто может видеть чужие задачи?

Сотрудник получает доступ к чужой задаче в следующих случаях:

1. **Включён в рабочую группу задачи** — автоматически при добавлении в ТЧ Участники или как Автор/Ответственный
2. **Имеет роль `ЧтениеПроцессовИЗадачБезОграничения`** — видит все задачи без ограничений (администраторы, секретари с расширенными правами)
3. **Является замещающим** с областью замещения `ОбластиЗамещения.Задачи` или `ОбластиЗамещения.ВсеОбласти` — автоматически добавляется в рабочие группы задач замещаемого
4. **Является руководителем** — механизм `РасширитьТаблицуПравРуководителямиИДелегатами()` расширяет права

## 4. Ограничение на уровне записей (RLS) для задач

**Да, RLS существует и работает.**

### Главный переключатель

```bsl
// ОбщиеМодули.ДокументооборотПраваДоступаПовтИсп
Функция ВключеноИспользованиеПравДоступа() Экспорт
    УстановитьПривилегированныйРежим(Истина);
    Возврат Константы.ДокументооборотИспользоватьОграничениеПравДоступа.Получить();
КонецФункции
```

Константа `ДокументооборотИспользоватьОграничениеПравДоступа` — **главный рубильник** системы ограничения прав. При значении «Ложь» все RLS-проверки пропускаются.

Дополнительная ФО: `ФункциональныеОпции.ДокументооборотИспользоватьОграничениеПравДоступа` управляет видимостью элементов интерфейса.

### Механизм RLS для Задачи

Модуль `ОбщиеМодули.БизнесПроцессыИЗадачиСервер` содержит функцию `ЗапросДляРасчетаПрав()` (строки 1207-1232), которая:
1. Формирует запрос к данным задачи
2. Вызывает `ДокументооборотПраваДоступа.ДополнитьТекстЗапросаПоПравам(Запрос.Текст)`
3. Возвращает запрос с добавленными условиями безопасности

Этот запрос используется механизмом расчёта прав платформы 1С для определения, какие записи доступны текущему пользователю.

### Роль без ограничений

Пользователям с ролью `ЧтениеПроцессовИЗадачБезОграничения` RLS **не применяется** — они видят все задачи в системе вне зависимости от рабочих групп.

## 5. Рабочие группы и их связь с доступом к задачам

**Рабочая группа** — это набор участников, имеющих доступ к конкретному объекту. Хранится в `РегистрСведений.РабочиеГруппы`.

### Структура РС РабочиеГруппы

```
Измерения:
  - Объект (тип: DocumentRef.Задача, CatalogRef.ДокументыПредприятия, BizProcessRef, ...)
  - Участник (тип: ОпределяемыйТип.КонтейнерыСотрудников — сотрудники, подразделения, роли)
Ресурсы:
  - Изменение (Булево) — имеет ли участник право изменения
  - Автоподстановка (ссылка на правило автоподстановки)
  - Источник (откуда добавлен участник)
```

### Как формируется рабочая группа задачи

При записи документа Задача в обработчике `ПриЗаписи` (строки 2093-2696) вызывается `РаботаСРабочимиГруппами.ПерезаписатьРабочуюГруппуОбъекта()`, которая:

1. Считывает текущую РГ из РС: `РС.РабочиеГруппы.ПолучитьУчастниковПоОбъекту(СсылкаНаЗадачу)`
2. Сравнивает с новым составом участников
3. При наличии изменений — проверяет права: `ПроверитьПраваПередЗаписьюРабочейГруппы()`
4. Записывает изменённый состав

**Автоматически включаются в РГ задачи:**
- Автор задачи
- Ответственный
- Все участники из ТЧ «Участники»
- Участники вышестоящей задачи (при связанных задачах)
- Участники бизнес-процессов, связанных с задачей

### Расширение рабочей группы на предметы (приложения)

Процедура `РасширитьРабочиеГруппыПриложений()` (строки 2945-3318 модуля Задача) автоматически распространяет доступ участников задачи на её предметы (вложенные документы), вызывая `ДокументооборотПраваДоступа.ПраваСотрудникаПоОбъекту()` для проверки прав автора задачи на приложение.

## 7. Сводная схема системы прав доступа к задачам

```
Пользователь
    │
    ├─► [Роль ЧтениеПроцессовИЗадачБезОграничения]
    │       └─► Видит ВСЕ задачи (без RLS)
    │
    └─► [Роль ЧтениеЗадач] + [ограничение RLS]
            │
            ▼
    Константа ДокументооборотИспользоватьОграничениеПравДоступа
            │
    ┌───────┴──────────┐
    │ RLS включён      │ RLS выключен
    ▼                  ▼
РС.РабочиеГруппы   Видит все задачи
[Объект=Задача]
    │
    ▼
РС.ДескрипторыДляОбъектов
    │
    ▼
РС.ПраваПоДескрипторамДоступаОбъектов
[Сотрудник, Чтение, Изменение, ...]
    │
    ▼
ВЫБРАТЬ РАЗРЕШЕННЫЕ — платформенный фильтр
```

## 8. Особые случаи доступа

### Замещение (делегирование)

При настройке замещения через `Справочники.ЗамещающиеИПомощники`:
- Область `ОбластиЗамещения.Задачи` — замещающий добавляется в РГ задач (полный доступ)
- Область `ОбластиЗамещения.ЗадачиПросмотр` — только просмотр задач замещаемого
- Область `ОбластиЗамещения.ВсеОбласти` — полное замещение, включая задачи

Если у замещающего нет ни одной из этих областей — он добавляется как участник в РГ задач программно (код в `Справочники.ЗамещающиеИПомощники.ОбновитьДанныеЗадачПоЗамещению`).

### Проверка прав при расширении РГ

При добавлении нового участника в рабочую группу задачи система проверяет, не нарушит ли это политику доступа. Если задача имеет предметы (приложения) — новый участник должен иметь право доступа к этим предметам. Иначе — ошибка «Нарушение политики доступа».

### Полноправный пользователь

Функция `Пользователи.ЭтоПолноправныйПользователь()` — пользователи с полными правами обходят все проверки прав (код: `Если Не Пользователи.ЭтоПолноправныйПользователь(ТекущийПользователь) Тогда`).

## Итоговые выводы

1. **Роли конфигурации для задач:** `ЧтениеЗадач`, `ИзменениеВыполнениеЗадач`, `ЧтениеПроцессовИЗадачБезОграничения`. Назначаются через профили групп доступа («Полномочия»).

2. **Видимость чужих задач:** по умолчанию сотрудник видит только задачи, в рабочую группу которых он включён. Видеть чужие задачи можно только при наличии роли `ЧтениеПроцессовИЗадачБезОграничения`, делегировании или административных правах.

3. **RLS для задач:** да, реализован через механизм дескрипторов доступа (РС.РабочиеГруппы → РС.ДескрипторыДляОбъектов → РС.ПраваПоДескрипторамДоступаОбъектов). Управляется константой `ДокументооборотИспользоватьОграничениеПравДоступа`.

4. **Рабочие группы:** связаны с задачами через `РС.РабочиеГруппы` (измерение Объект=DocumentRef.Задача). Автоматически формируются при записи задачи из состава участников, автора, ответственного. Расширяются на предметы задачи.

5. **РаботаСРабочимиГруппами:** центральный модуль управления составом рабочих групп (2565 строк, 55 методов). Ключевые: `ПроверитьПраваПередЗаписьюРабочейГруппы`, `ПроверитьПраваУчастниковРабочейГруппыНаОбъект`, `ПерезаписатьРабочуюГруппуОбъекта`.
