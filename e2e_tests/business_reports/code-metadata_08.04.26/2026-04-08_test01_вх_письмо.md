## 1. Что такое ВходящееПисьмо в системе

Документ `Документы.ВходящееПисьмо` — это объект подсистемы встроенного почтового клиента. В отличие от `Справочника.ДокументыПредприятия`, ВходящееПисьмо представляет собой **электронное письмо**, поступившее на почтовый ящик учётной записи пользователя. Оно является частью подсистемы взаимодействий (Interactions) и имеет двойную роль: технический объект почтового клиента + предмет документооборотных процессов.

**Нумерация:** строковый тип, длина 50 символов, периодичность — год, автонумерация включена, контроль уникальности — Ложь.

## 3. Жизненный цикл — состояния документа

Типовая цепочка прохождения входящего документа (из справки регистра `ТекущиеСостоянияДокументов`):

```
Создание письма (получение по почте / ввод вручную)
    ↓
[На регистрации] — вручную, секретарём
    ↓
[Зарегистрирован] — вручную, секретарём
    ↓
[На рассмотрении] — автоматически при создании бизнес-процесса "Рассмотрение"
    ↓
[Рассмотрен] — автоматически при завершении процесса "Рассмотрение"
    ↓
[На исполнении] — автоматически при создании бизнес-процесса "Исполнение"
    ↓
[Исполнен] — при завершении всех задач исполнения
```

Изменение состояния может быть:
- **Вручную** — пользователь выбирает состояние в поле карточки
- **Автоматически** — при создании процесса на основании письма

## 4. Бизнес-процессы по входящему письму

ВходящееПисьмо может выступать **предметом** (основанием) следующих бизнес-процессов:

### 4.1 Рассмотрение (`БизнесПроцессы.Рассмотрение`)
- Запускается: Создать на основании → Рассмотрение
- Назначается конкретному руководителю/рассматривающему
- Результат: резолюция, поручения
- Автоматически меняет состояние письма: На рассмотрении → Рассмотрен

### 4.2 Исполнение (`БизнесПроцессы.Исполнение`)
- Запускается: на основании резолюции или напрямую
- Назначаются исполнители (один или несколько)
- Варианты: последовательно, параллельно, смешанно
- После выполнения — проверяющий принимает решение (выполнено / на доработку)
- Автоматически меняет состояние: На исполнении → Исполнен

### 4.3 Согласование (`БизнесПроцессы.Согласование`)
- Может запускаться для согласования ответного письма или действий по нему
- Преимущественно используется для документов предприятия, но применим к любому предмету

### 4.4 Ознакомление (`БизнесПроцессы.Ознакомление`)
- Рассылка письма для ознакомления группе сотрудников
- Каждый исполнитель подтверждает ознакомление

### 4.5 Подписание (`БизнесПроцессы.Подписание`)
- Применяется при необходимости подписать ответ на входящее письмо

### 4.6 КомплексныйПроцесс (`БизнесПроцессы.КомплексныйПроцесс`)
- Объединяет несколько этапов в одном процессе по схеме
- Может включать рассмотрение, согласование, исполнение

## 5. Регистрация входящего письма

### Источники создания
1. **Автоматически** — при получении почты через встроенный почтовый клиент (ВстроеннаяПочтаСервер). Письмо создаётся в нужной папке IMAP-структуры.
2. **Импорт из Microsoft Outlook** — через обработку ЖурналыДокументов.ЭлектроннаяПочта.ФормаИмпортаИзMicrosoftOutlook.
3. **Вручную** — пользователь создаёт новое письмо.
4. **Программно** — `Документы.ВходящееПисьмо.СоздатьДокумент()`.

### Нумерация
- Тип номера: **Строка(50)**, периодичность: **Год**
- Автонумерация: **Истина** — номер присваивается автоматически
- Контроль уникальности: **Ложь** — одинаковые номера допустимы (электронные письма не имеют классических регистрационных номеров)
- Кнопка "№" в форме документа формирует номер вручную (для делопроизводственной регистрации)

### Роли при регистрации
- **Секретарь/делопроизводитель** — регистрирует входящую корреспонденцию, устанавливает состояние "Зарегистрирован", назначает исполнителей
- **Рядовой пользователь** — работает со своим почтовым ящиком самостоятельно
- Правило: документы, подписанные руководством, регистрирует секретарь; остальные — авторы самостоятельно
- Срок регистрации: **в день получения или не позднее первой половины следующего рабочего дня**

## 6. Обработчики событий при записи

### 6.1 Модуль объекта (ObjectModule) — серверная часть

Структура `/app/code/Documents/ВходящееПисьмо/Ext/ObjectModule.bsl`:

**`ПередЗаписью(Отказ)` [стр. 5–47]:**
На основании структуры модуля и паттернов конфигурации:
- Проверка `ОбменДанными.Загрузка` → выход без обработки
- Установка вспомогательных свойств для последующей обработки
- Логика работы со статусом прочтения/папки письма
- Подготовка данных для обновления регистра `КоличествоПисемВПапках`

**`ПриЗаписи(Отказ)` [стр. 49–107]:**
- Проверка `ОбменДанными.Загрузка` → выход
- Обновление регистра `КоличествоПисемВПапках` — пересчёт количества писем в папке
- Обновление регистра `HTMLПредставленияСодержанияПисем` (через ManagerModule)
- Протоколирование (при изменении пометки удаления)

**`ПередУдалением` [стр. 217–225]:**
- Очистка связанных данных при удалении письма

**Экспортируемые функции:**
- `ПолучитьСодержаниеПисьма()` — возвращает структуру содержимого
- `ПолучитьТекстовоеПредставлениеСодержанияПисьма()` — текстовое представление

### 6.2 Форма документа (ФормаДокумента) — клиент-серверная часть

**`ПередЗаписью` [НаКлиенте, стр. 228–234]:**
- Минимальная обработка на клиенте перед сохранением
- Вероятно: удаление пустых строк табличных частей

**`ПередЗаписьюНаСервере` [НаСервере, стр. 237–261]:**
- Установка содержимого письма `УстановитьСодержаниеПисьма`
- Подготовка дополнительных свойств объекта

**`ПриЗаписиНаСервере` [НаСервере, стр. 264–294]:**
- Обновление связей письма (переписка, предмет)
- Обновление задач по письму
- Запись протокола работы в `РегистрыСведений.ПротоколРаботыСотрудников`

**`ПослеЗаписиНаСервере` [НаСервере, стр. 297–313]:**
- Обновление отображения формы
- Обновление сведений о прочтении

## 7. Регистры, обновляемые при работе с ВходящимПисьмом

| Регистр | Тип | Назначение | Когда обновляется |
|---------|-----|------------|-------------------|
| `КоличествоПисемВПапках` | РС Независимый | Кэш количества писем в папке (всего/прочтено) | При каждой записи документа |
| `HTMLПредставленияСодержанияПисем` | РС | Кэш HTML-представления содержимого письма | При записи через ManagerModule |
| `СведенияОПросмотреПисем` | РС | Отметка о прочтении письма пользователем | При открытии/просмотре письма |
| `ОповещенияОПисьмах` | РС | Оповещения о новых/непрочтённых письмах | При получении новых писем |
| `ПапкиУчетныхЗаписей` | РС | Структура IMAP-папок учётной записи | При синхронизации папок |
| `ПротоколРаботыСотрудников` | РС | Протокол действий пользователя | При записи с изменением пометки удаления |

## 8. Связанные объекты конфигурации

- **Общий модуль:** `ВстроеннаяПочтаСервер` — основная бизнес-логика почтового клиента
- **Журнал документов:** `ЭлектроннаяПочта` — общий журнал входящих и исходящих писем
- **Справочник:** `ПапкиПисем` — IMAP-структура папок
- **Справочник:** `АдресатыПочтовыхСообщений` — контакты отправителей/получателей
- **Справочник:** `УчетныеЗаписиЭлектроннойПочты` — почтовые ящики
- **Документ:** `ИсходящееПисьмо` — зеркальный объект для отправляемых писем

## 9. Итоговая схема жизненного цикла

```
Получение письма (IMAP/POP3/SMTP или вручную)
     │
     ▼
Документ ВходящееПисьмо создан
 └─ Реквизиты: Тема, Дата, Отправитель, Получатели, Папка, УчетнаяЗапись
 └─ Регистры: КоличествоПисемВПапках +1, ОповещенияОПисьмах
     │
     ▼
Пользователь открывает письмо
 └─ СведенияОПросмотреПисем: отметка о прочтении
     │
     ▼
Привязка к предмету (Предмет = ДокументыПредприятия / Проект / Задача)
     │
     ▼
Регистрация (смена состояния вручную или через бизнес-процесс)
 └─ На регистрации → Зарегистрирован (секретарь)
     │
     ▼
Запуск бизнес-процесса "Рассмотрение"
 └─ Состояние: На рассмотрении → Рассмотрен
 └─ Результат: резолюция
     │
     ▼
Запуск бизнес-процесса "Исполнение" (по резолюции)
 └─ Состояние: На исполнении → Исполнен
 └─ Проверяющий: принимает/возвращает на доработку
     │
     ▼
Архивирование / Перемещение в папку
 └─ КоличествоПисемВПапках обновляется
```
