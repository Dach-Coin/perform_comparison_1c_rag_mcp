## Что сервер дал хорошо

1. **Точное нахождение целевой функции** — `ОпределитьФактическихИсполнителей` в `ОбщиеМодули.РаботаСЗадачами` (строки 24-251) найдена через codesearch на 4-м вызове по семантическому запросу "фактические исполнители задачи с учётом замещений роль". Это ключевой тест — по бизнес-описанию, без знания точного имени.

2. **Полное тело функции** (9800 символов) — search_function с exact=true отдал весь код (228 строк), что позволило полностью реконструировать алгоритм (3 шага: прямой сотрудник → роль → замещение/помощник).

3. **Полная иерархия вызовов** — get_method_call_hierarchy с depth=3 вернул 68841 символов с 6 прямыми вызывающими и полным деревом до глубины 3. Это **эксклюзивная возможность** нового образа — ни один другой MCP-сервер не имеет инструмента call hierarchy.

4. **Структура модуля** — get_module_structure показал все 199 процедур/функций модуля РаботаСЗадачами, подтвердив расположение целевой функции на строке 24.

5. **Вспомогательные функции** — ВсеЗамещенияПоДействиямЗадач (справочник ЗамещающиеИПомощники), НайтиСоздатьФактическогоИсполнителя (справочник ФактическиеИсполнители), ВзятьВРаботу (клиент→сервер цепочка) — все найдены через search_function.

## Что сервер НЕ дал

Практически ничего критичного не упущено. Единственное — полный список ролей/типов замещений, но это уже уровень бизнес-данных, а не метаданных конфигурации.

## Паттерны поведения агента

- **Стратегия «проб и ошибок» → точное попадание**: агент начал с семантического codesearch (#1), затем попробовал угадать имя через search_function (#2 "ОпределитьИсполнителей" — 0 результатов, #3 "ПолучитьИсполнителей" — не то, #5 "НазначитьИсполнителей" — 0). Это нормальное поведение при поиске по описанию. Переломный момент — codesearch #4 с более точным запросом, давший правильное имя.
- **Эффективный переход от поиска к навигации**: после нахождения имени — точный search_function (#7) → get_module_structure (#8) → get_method_call_hierarchy (#9). Это именно тот паттерн, для которого разработаны новые инструменты.
- **12 вызовов за 3 минуты** — самый быстрый из трёх тестов, отличная эффективность.
- **68K символов от call hierarchy** — вызов #9 принёс больше половины всех символов (56%). Это ожидаемо для дерева вызовов глубиной 3, но стоит учитывать при оценке расхода контекста.

## Вывод

Этот тест — **showcase нового образа**. Именно для такого сценария (найти функцию по описанию → показать код → показать кто вызывает) разработаны инструменты search_function, get_module_structure и get_method_call_hierarchy. Агент за 12 вызовов и 3 минуты полностью раскрыл: имя функции, полный алгоритм, 6 вызывающих с деревом до 3 уровней, вспомогательные объекты. Старый образ без search_function и call hierarchy не мог бы дать такого результата.
