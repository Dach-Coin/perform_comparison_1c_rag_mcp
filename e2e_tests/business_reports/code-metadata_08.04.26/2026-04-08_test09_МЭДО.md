# Подсистема МЭДО в 1С:Документооборот КОРП 3.0
**Конфигурация:** 1С:Документооборот КОРП 3.0 (DO3)  
**Дата исследования:** 2026-04-08  
**Сервер:** 1c-code-metadata  

---

## 1. Общая характеристика подсистемы

МЭДО (межведомственный электронный документооборот) реализован как самостоятельная подсистема внутри DO3. Она отвечает за обмен документами между органами государственной власти по стандарту МЭДО версий 2.2 и 2.5.

**Подсистемы в дереве конфигурации:**
- `Подсистемы.СтандартныеПодсистемыДокументооборота.Подсистемы.МЭДО` — ядро, активируется константой `ИспользоватьМЭДО`
- `Подсистемы.СтандартныеПодсистемыДокументооборота.Подсистемы.МЭДОДокументооборот` — объекты, специфичные для DO3 (ОбщийМодуль.МЭДОДокументооборот)
- `Подсистемы.НастройкаИАдминистрирование.Подсистемы.АдминистрированиеМЭДО` — журнал событий, настройки

**Транспорт:** файловый обмен через общие сетевые папки или FTP (без HTTP/веб-сервисов для МЭДО). Каждая организация имеет отдельный каталог получения и каталог отправки.

## 3. Процесс отправки документа через МЭДО

### 3.1 Подготовка (пользовательская часть)

1. Пользователь создаёт или регистрирует внутренний документ в системе.
2. В карточке документа заполняются "Данные документа МЭДО" (`Документ.ДанныеДокументаМЭДО`):
   - ВидДокумента, МестоСоставления, ДатаРегистрации, ГлавныйФайл
   - Контрагент (получатель), Организация (отправитель)
3. Устанавливается флаг `ГотовКОтправке = Истина`.
   - Проверка: незарегистрированный документ отправить нельзя (контроль в `ПередЗаписью` объектного модуля ДанныеДокументаМЭДО).

### 3.2 Отправка (автоматическая — регламентное задание)

**РегламентноеЗадание.ВыполнениеОбменаМЭДО** → `МЭДО.ВыполнитьОбменМЭДО()`

Алгоритм `МЭДО.ВыполнитьОбменМЭДО()`:
```
1. Проверка: ОбщегоНазначения.ПриНачалеВыполненияРегламентногоЗадания(...)
2. МЭДОПереопределяемый.ПроверитьОбменСВнешнимиРесурсами(Отказ) — проверка доступности
3. Запрос всех организаций из РС.НастройкиОрганизацийМЭДО
4. Для каждой организации:
   а) ПолучитьВходящиеСообщения(Настройки, "Транспортный контейнер, Документ, Уведомление, Квитанция")
   б) ОтправитьИсходящиеДокументы(Настройки, ...)
   в) ОтправитьИсходящиеКвитанции(Настройки, ...)
   г) ОтправитьИсходящиеУведомления(Настройки, ...)
```

**Цепочка отправки документа:**
```
МЭДО.ОтправитьИсходящиеДокументы(Настройки, ДанныеОтвета)
  → МЭДО.ИсходящиеДокументыКОтправке() — выборка ДанныеДокументаМЭДО с ГотовКОтправке=Истина
  → Для каждого документа: МЭДО.ОтправитьИсходящийДокумент(Настройки, Документ, ДанныеОтвета)
    → МЭДОПереопределяемый.ДанныеИсходящегоДокументаДляОтправки() — получение данных из DO3
    → Для каждого пакета (версии МЭДО):
      → МЭДО.ЗаписатьСообщениеПоИсходящемуДокументу() — формирование XML по XDTO
        → СоздатьПаспортКонтейнераИсходящегоДокумента() — паспорт контейнера
        → ЗаписатьСодержимоеКонтейнераИсходящегоДокумента() — вложения
      → Запись файла в КаталогОтправки
      → МЭДО.ЗаписатьДанныеИсходящегоДокументаМЭДО() — обновление ТЧ Пакеты
    → Установка Отправлен = Истина
```

### 3.3 Получение входящих документов

```
МЭДО.ПолучитьВходящиеСообщения(Настройки, ТипыКонтента)
  → Сканирование КаталогПолучения
  → Для каждого файла:
    → Определение типа (Транспортный контейнер / Документ / Уведомление / Квитанция)
    → ПрочитатьВерсиюМЭДОИзЭСД() — чтение версии из XML
    → ОбработатьВходящийТранспортныйКонтейнер() или
      ОбработатьВходящийДокумент22_25() — разбор XML через XDTO (версии 2.2/2.5)
        → ЗаписатьДанныеВходящегоДокументаМЭДО() — создание ДанныеДокументаМЭДО
        → МЭДОПереопределяемый — создание входящего документа предприятия
        → СоздатьИсходящуюКвитанцию() — автоматическая квитанция о доставке
    → Успех: файл → подпапка "processed"
    → Ошибка: файл → подпапка "errors"
```

### 3.4 Обработка входящих уведомлений

```
МЭДО.ОбработатьВходящееУведомление(ВременныйКаталог, communication, ДвоичныеДанныеЭСД)
  → Чтение: ИдентификаторУведомления, ИдентификаторДокумента
  → МЭДОПереопределяемый.ПолучитьДокументПоИдентификатору()
  → Создание/обновление Документ.УведомлениеМЭДО
  → Заполнение ТЧ в зависимости от типа уведомления
```

### 3.5 Ручной запуск (интерактивный)

Обработка `Обработки.ТекущиеДелаМЭДО` предоставляет пользователю кнопки:
- **Получить входящие документы** → `МЭДОВызовСервера.ПолучитьВходящиеДокументы(Организация)`
- **Получить уведомления и квитанции** → `МЭДОВызовСервера.ПолучитьВходящиеУведомленияКвитанции(Организация)`
- **Отправить исходящие документы** → `МЭДОВызовСервера.ОтправитьИсходящиеДокументы(Организация)`
- **Отправить уведомления** → `МЭДОВызовСервера.ОтправитьИсходящиеУведомления(Организация)`

## 5. HTTP-сервисы и веб-сервисы для МЭДО

**Специализированных HTTP-сервисов или веб-сервисов для МЭДО не существует.**

В конфигурации присутствует `HTTPСервисы.ЭДО` — но он относится к обмену с операторами ЭДО (ФНС, коммерческие), а не к МЭДО.

Обмен МЭДО реализован **файловым транспортом**:
- Поддерживаются два режима (поле `СпособОбмена` в НастройкиОрганизацийМЭДО, перечисление `СпособыОбменаМЭДО`):
  - **Файловый** — через сетевую папку (UNC-путь)
  - **FTP** — через FTP-сервер (поля `КаталогОтправкиFTP`, `КаталогПолученияFTP`)
- XML-сообщения формируются через **XDTO** (пространства имён МЭДО 2.2 и 2.5)
- Формат файлов — транспортный контейнер (ZIP-архив) с XML-паспортом и вложениями

## 8. Ключевые выводы

1. **МЭДО в DO3 — полноценная подсистема** с 5300+ строками кода в основном модуле, 3 специализированными документами и набором регистров/справочников.

2. **Транспорт — исключительно файловый** (папки или FTP). Никаких HTTP/веб-сервисов для МЭДО нет. Это ключевое архитектурное решение, отличающее МЭДО от ЭДО (у которого есть HTTPСервис.ЭДО).

3. **Поддерживаются версии 2.2 и 2.5** стандарта МЭДО. Версия хранится в НастройкиКонтрагентовМЭДО и в ТЧ Пакеты документа ДанныеДокументаМЭДО. Одному документу могут соответствовать несколько пакетов (для разных версий).

4. **Регламентное задание ВыполнениеОбменаМЭДО** по умолчанию выключено. Обмен запускается либо по расписанию (после настройки), либо вручную через обработку ТекущиеДелаМЭДО.

5. **Автоматическое создание квитанции**: при успешной обработке входящего документа система автоматически создаёт исходящую квитанцию о доставке.

6. **Переопределяемый модуль МЭДОПереопределяемый** — точка интеграции между универсальной библиотекой МЭДО и конкретными бизнес-объектами DO3. В нём реализованы: получение данных документа для отправки, поиск документа по идентификатору МЭДО.
