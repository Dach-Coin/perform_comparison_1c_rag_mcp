**Дата анализа:** 2026-04-08  
**Сервер:** 1c-code-metadata  
**Конфигурация:** DO3 (1С:Документооборот КОРП 3.0)

## 1. Общая характеристика

**Полный путь:** `Справочники.Сотрудники`  
**Синоним:** Сотрудники  
**Комментарий:** "Содержит сотрудников на определенных должностях в структурных единицах."

Ключевые свойства:
- Иерархический: **нет** (плоский список)
- **Подчинён владельцу:** `Справочник.ФизическиеЛица` — каждый элемент Сотрудник принадлежит физическому лицу
- Длина наименования: 150 символов
- Основное представление: в виде наименования
- Стандартные команды отключены (кастомный интерфейс)

## 2. Реквизиты

| Имя | Синоним | Тип |
|-----|---------|-----|
| `ГрафикРаботы` | График работы | `СправочникСсылка.ГрафикиРаботы` |
| `ДатаНачалаДействия` | Дата начала действия | `Дата` |
| `ДатаОкончанияДействия` | Дата окончания действия | `Дата` |
| `Действует` | Действует | `Булево` |
| `Должность` | Должность | `СправочникСсылка.Должности` |
| `Подразделение` | Подразделение | `СправочникСсылка.СтруктураПредприятия` |
| `Помещение` | Помещение | `СправочникСсылка.ТерриторииИПомещения` |
| `ПредставлениеВДокументах` | Представление в документах | `Строка` |
| `ПредставлениеВПереписке` | Представление в переписке | `Строка` |

**Важно: ФИО сотрудника** хранится в стандартном реквизите `Наименование` (длина 150) и наследуется от физического лица через механизм подчинения. Отдельного реквизита ФИО в справочнике Сотрудники нет — полные персональные данные (ДатаРождения, Пол, ИНН, СНИЛС) хранятся в родительском справочнике `ФизическиеЛица`.

**Логика реквизита `Действует`** автоматически вычисляется в процедуре `ЗаполнитьПризнакДействует` (ObjectModule):
```bsl
Если ПометкаУдаления Тогда
    СотрудникДействует = Ложь;
ИначеЕсли ТекущаяДатаСеанса < ДатаНачалаДействия Тогда
    СотрудникДействует = Ложь;
ИначеЕсли ЗначениеЗаполнено(ДатаОкончанияДействия)
        И ТекущаяДатаСеанса > КонецДня(ДатаОкончанияДействия) Тогда
    СотрудникДействует = Ложь;
КонецЕсли;
```

## 4. Связи с другими справочниками

### 4.1. ФизическиеЛица — владелец

Справочник `Сотрудники` **подчинён** `ФизическиеЛица` (ИспользованиеПодчинения = Элементам).

Это означает:
- Один человек (ФизЛицо) может иметь несколько записей Сотрудник (например, работает в нескольких подразделениях или на нескольких должностях)
- Связь: `Сотрудники.Владелец` → `ФизическиеЛица`
- Регистр `РегистрыСведений.ОсновныеСотрудники` (поля: Сотрудник + ФизическоеЛицо) дополнительно фиксирует "основного" сотрудника для физлица

**Справочник ФизическиеЛица** содержит персональные данные:
- ДатаРождения, Пол, ИНН, СНИЛС (СтраховойНомерПФР), ФайлФотографии, ГруппаДоступаФизическихЛиц

### 4.2. Должности

Реквизит `Должность` (тип `СправочникСсылка.Должности`) — прямая ссылка на справочник должностей.

`Справочник.Должности` — простой плоский справочник (1 реквизит: тст_ТиповаяПечатнаяФорма). Навигация "по должности" реализована через команду `СотрудникиДолжности` (тип параметра `СправочникСсылка.Должности`).

### 4.3. СтруктураПредприятия

Реквизит `Подразделение` (тип `СправочникСсылка.СтруктураПредприятия`) — прямая ссылка на узел оргструктуры.

**Обратная связь:** В `Справочники.СтруктураПредприятия` реквизит `Руководитель` ссылается обратно на `СправочникСсылка.Сотрудники` (или Пользователи). Таким образом образуется двунаправленная связь: подразделение знает своего руководителя-сотрудника.

Навигация реализована через команду `СотрудникиПодразделения` (тип параметра `СправочникСсылка.СтруктураПредприятия`).

## 5. Механизм замещения сотрудников

Замещение реализовано через **отдельный справочник** `ЗамещающиеИПомощники` (подсистема `СовместнаяРабота.ЗамещающиеИПомощники`).

### 5.1. Справочник ЗамещающиеИПомощники

| Реквизит | Синоним | Тип |
|----------|---------|-----|
| `Сотрудник` | Кто замещается | `СправочникСсылка.Сотрудники` |
| `Замещающий` | Заместитель | `СправочникСсылка.Сотрудники` |
| `ВидЗамещения` | Вид замещения | `ПеречислениеСсылка.ВидыЗамещения` |
| `ДатаНачала` | Дата начала | `Дата` |
| `ДатаОкончания` | Дата окончания | `Дата` |
| `Действует` | Действует | `Булево` |
| `Основание` | Документ-основание | `ДокументСсылка.Отсутствие` |
| `Создал` | Создал | `СправочникСсылка.Сотрудники` |
| `Комментарий` | Комментарий | `Строка` |

**Табличная часть ВопросыЗамещения:**
| Поле | Тип |
|------|-----|
| `Область` | `СправочникСсылка.ОбластиЗамещения` |
| `ЗначениеОтбора` | `ОпределяемыйТип.ЗначениеОтбораОбластиЗамещения` |

### 5.2. Документ Отсутствие

При создании документа `Отсутствие` пользователь может указать заместителей:
- Реквизит `Сотрудник` — кто отсутствует
- ТЧ `УдалитьЗаместители` (Заместитель, Комментарий) — список заместителей (ТЧ помечена на удаление, заместители переведены в справочник ЗамещающиеИПомощники)
- `ВидОтсутствия` — причина (→ СправочникСсылка.ВидыОтсутствий)
- `БудуРазбиратьЗадачи` — флаг "буду на связи"

### 5.3. Регистр ИсполнителиРолейИДелегаты

Регистр `РегистрыСведений.ИсполнителиРолейИДелегаты` является **рабочей таблицей** маршрутизации задач — хранит вычисленные данные по делегатам:

| Поле | Тип |
|------|-----|
| `РольСотрудник` | Сотрудники / ПолныеРоли / Пользователи |
| `ИсполнительДелегат` | Сотрудники / Пользователи |
| `НастройкаДелегирования` | ЗамещающиеИПомощники |
| `ИмяОбластиДелегирования` | Строка(100) |

### 5.4. Логика работы

1. Сотрудник создаёт документ `Отсутствие` с датами отсутствия
2. Система создаёт записи в справочнике `ЗамещающиеИПомощники`
3. Регламентная задача (или триггер) перестраивает регистр `ИсполнителиРолейИДелегаты`
4. При маршрутизации задач общий модуль `ЗамещающиеИПомощники` вызывает `ВсеЗамещенияПоДействиямЗадач` и перенаправляет задачи заместителю
5. РегламентноеЗадание `ОбновлениеДействияСотрудников` обновляет флаг `Действует` у сотрудников по истечении срока

## 6. Регистры, хранящие данные о сотрудниках

### 6.1. ОсновныеСотрудники (непериодический)
**Назначение:** Связь "один физлицо — один основной сотрудник"  
Поля: `Сотрудник` (→Сотрудники), `ФизическоеЛицо` (→ФизическиеЛица)

### 6.2. СотрудникиПользователей (непериодический)
**Назначение:** Привязка учётной записи системы к сотруднику  
Поля: `Сотрудник` (→Сотрудники), `Пользователь` (→Пользователи)

### 6.3. ПротоколРаботыСотрудников (непериодический)
**Назначение:** Аудит действий сотрудников в системе  
Поля: `Сотрудник`, `Дата`, `ТипСобытия` (перечисление), `ОбъектДанных`, `ОписаниеСобытия`, `Длительность`, `ИмяКомпьютера`

### 6.4. ИсполнителиРолейИДелегаты (непериодический)
**Назначение:** Кэш маршрутизации задач — кто является фактическим исполнителем роли с учётом замещений  
Поля: РольСотрудник, ИсполнительДелегат, НастройкаДелегирования, ИмяОбластиДелегирования

### 6.5. ДанныеSAPСотрудники (периодический — по дням)
**Назначение:** Буфер интеграции с SAP HR  
Содержит: ТабельныйНомер, ФИО (Фамилия/Имя/Отчество отдельными полями), ДатаРождения, ИНН, ПФР, Пол, КодДолжности, КодПодразделения, КодОрганизации, Логин, Телефон, ЭлектроннаяПочта, МестоРождения, УдостоверениеЛичности, Штатность, ФизическоеЛицо

### 6.6. СотрудникиВКонтейнерах (непериодический)
**Назначение:** Кэш принадлежности сотрудников рабочим группам/контейнерам (для поиска и прав доступа)

### 6.7. СотрудникиДляКонтроляСамочувствия (непериодический)
**Назначение:** Список сотрудников, подключённых к модулю контроля самочувствия (опциональная функциональная опция)

### 6.8. ДоступноеВремяСотрудников (непериодический) — УСТАРЕВШИЙ
**Статус:** Помечен "(будет удален в будущих версиях)". Заменён механизмом ГрафиковРаботы.

## 8. Выводы

1. **Модель "сотрудник ≠ физлицо"**: DO3 разделяет понятия физического лица (персональные данные) и сотрудника (должностная позиция). Один человек может иметь несколько активных записей Сотрудник.

2. **Статус "действует"** автоматически вычисляется на основе дат действия и поддерживается регламентным заданием.

3. **Замещение** — полноценная подсистема с собственным справочником `ЗамещающиеИПомощники`, поддержкой областей замещения и интеграцией в маршрутизацию задач через `ИсполнителиРолейИДелегаты`.

4. **Интеграция с SAP** предусмотрена "из коробки" через периодический регистр `ДанныеSAPСотрудники`.

5. **Центральная сущность**: справочник Сотрудники — одна из наиболее связанных сущностей конфигурации (50+ объектов ссылаются на него).
