## 1. Общая архитектура системы нумерации

Система нумерации в DO3 построена на трёх уровнях:

```
ВидыДокументов (что нумеруем)
    ↓
НастройкиНумерации (какой нумератор применить)
    ↓
Нумераторы (как формировать номер)
    ↓
Нумерация (регистр-счётчик текущего номера)
```

Общий модуль `Нумерация` (1653 строки, 30 функций) реализует всю логику. Клиентский модуль `НумерацияКлиентСервер` отвечает за сбор параметров.

## 2. Автоматическая нумерация при создании документа

При создании документа автоматическая нумерация **не присваивается сразу**. Документ получает временный номер.

**Алгоритм в событии `ПередЗаписью` (Справочники.ДокументыПредприятия):**

```
1. НумерацияКлиентСервер.ПолучитьПараметрыНумерации(Объект)
       → собирает контекст: ВидДокумента, Организация, Подразделение, Проект и т.д.
2. Нумерация.ПолучитьНумераторДокумента(СтруктураПараметров)
       → ищет нумератор через РС.НастройкиНумерации
       Если нет нумератора → спрашивает у пользователя (ВвестиДанныеРегистрации)
3. Путь A — РЕГИСТРАЦИЯ (есть нумератор):
       → Нумерация.СформироватьЧисловойНомерДокумента() — получает следующий ЧисловойНомер
       → Нумерация.СформироватьСтроковыйНомерДокумента() — применяет ФорматНомера
       → Делопроизводство.ЗаписатьСостояниеДокумента(...Зарегистрирован)
   Путь B — ВРЕМЕННЫЙ НОМЕР (нет нумератора):
       → Нумерация.УстановитьВременныйНомерПередЗаписью()
```

Кнопка **«№»** в форме документа запускает ручную регистрацию — тот же алгоритм, но инициированный пользователем.

## 3. Регистрация документа — бизнес-процесс

**Регистрация** — это присвоение регистрационного номера и фиксация статуса `Зарегистрирован`.

### Бизнес-правила (из встроенной справки конфигурации):
- Регистрируются только **утверждённые** документы
- Документы, подписанные **руководством**, регистрирует **секретарь**
- Остальные документы регистрируют **авторы в подразделениях самостоятельно**
- Срок: в день утверждения или **не позднее первой половины следующего рабочего дня**
- Обязательные поля при регистрации: **регистрационный номер** и **хранение**

### Техническая реализация:
- Проверка через `Делопроизводство.ПредметМожетБытьЗарегистрирован()`
- Регистрация через `Делопроизводство.ЗарегистрироватьПредмет()`
- Состояния хранятся в двух регистрах:
  - `РегистрыСведений.ИсторияСостоянийДокументов` (периодичность: Секунда — полная история)
  - `РегистрыСведений.ТекущиеСостоянияДокументов` (Непериодический — текущее состояние)

## 5. Формирование регистрационного номера

### Шаблонный механизм

Формат номера задаётся строкой с **маркерами в квадратных скобках**. Функция `РазобратьФорматНомера` (модуль Нумерация, строки 251-406) парсит шаблон в таблицу токенов.

**Пример формата:** `[Номер]-[ИндексВидаДок]`

**Известные маркеры (из кода):**
- `[Номер]` — числовой счётчик нумератора
- `[ИндексВидаДок]` — идентификатор вида документа
- `[ДатаРегистрации]` — дата регистрации
- `[Контрагент]` — наименование контрагента
- `[РегистрационныйНомер]` — готовый рег. номер (для имён файлов)

**Пример результата:** `1.5.4-01-15-52` (встречается в тестовых данных)

### Двухэтапное формирование:
```bsl
// 1. Числовой номер (счётчик)
Нумерация.СформироватьЧисловойНомерДокумента(СтруктураПараметров, ДокументОбъект.ЧисловойНомер);

// 2. Строковый рег. номер по шаблону
Нумерация.СформироватьСтроковыйНомерДокумента(СтруктураПараметров, ДокументОбъект.РегистрационныйНомер, ОписанияОшибок);
```

### Пропущенные номера:
Если пользователь отказался от номера или документ был удалён — номер сохраняется в `РегистрыСведений.ПропускиРегистрационныхНомеров`. При следующей нумерации (если `ИспользоватьПропущенныеНомера = Истина`) пропуски заполняются первыми.

## 6. Разные схемы нумерации для разных видов документов

**Да, полностью поддерживается.** Механизм многоуровневый:

### Уровень 1: Разные нумераторы для разных видов
В регистре `НастройкиНумерации` каждый вид документа (`ВидДокумента`) получает свой нумератор. Например:
- Приказы → Нумератор «Приказы», формат `П-[Номер]/[Год]`
- Договоры → Нумератор «Договоры», формат `Д[Номер]-[Год]`
- Входящие письма → Нумератор «Входящие», формат `[Номер]-[ВидДок]`

### Уровень 2: Независимые счётчики внутри нумератора
Флаги `НезависимаяНумерацияПо*` в справочнике Нумераторы позволяют разделить счётчики по:
- Виду документа (если один нумератор для нескольких видов)
- Организации (отдельная нумерация для каждого юрлица)
- Подразделению, Проекту, Тематике и т.д.

### Уровень 3: Периодичность сброса счётчика
- **Год** (по умолчанию) — счётчик сбрасывается с 1 января
- **Квартал** — каждые 3 месяца
- **Непериодический** — счётчик не сбрасывается никогда

### Уровень 4: Временные номера
Для документов без утверждённого нумератора используется отдельный нумератор `"Временные номера"` с форматом `[Номер]-[ИндексВидаДок]` и независимой нумерацией по организациям.

### Пример сочетания настроек:
```
Вид: "Приказ по личному составу"
Организация: ООО "Ромашка"
Нумератор: "Кадровые приказы"
  ФорматНомера: "П-[Номер]/[Год]"
  Периодичность: Год
  НезависимаяНумерацияПоОрганизациям: Истина
  НезависимаяНумерацияПоВидуДокумента: Истина

→ Счётчик в Нумерация: {Нумератор=..., ВидДокумента=Приказ, Организация=Ромашка, Период=2026}
→ Результат: "П-42/2026"
```

## 7. Итоговая схема объектов

```

  └─ определяет правила регистрации
       ↓ (через НастройкиНумерации)

  ├─ ФорматНомера (шаблон "[Номер]-[...]")
  ├─ Периодичность (Год/Квартал/Непериодический)
  ├─ НезависимаяНумерацияПо* (8 флагов)
  └─ ИспользоватьПропущенныеНомера
       ↓ (счётчик хранится в)
РС.Нумерация
  └─ ТекущийНомер [по каждой комбинации измерений]
       ↓ (при сбросе номера)
РС.ПропускиРегистрационныхНомеров
  └─ ПропущенныйНомер [для повторного использования]

ОбщийМодуль.Нумерация
  ├─ СформироватьЧисловойНомерДокумента()

ОбщийМодуль.Делопроизводство
  ├─ ПредметМожетБытьЗарегистрирован()

```
