## Шаг 1. Поступление ВходящегоПисьма от контрагента

### Объект
**Документ `ВходящееПисьмо`** (`Документы.ВходящееПисьмо`)

Ключевые реквизиты:
| Реквизит | Тип | Назначение |
|---|---|---|
| Тема | Строка(1024) | Тема письма |
| ОтправительАдресат | СправочникСсылка.АдресатыПочтовыхСообщений | Контрагент-отправитель |
| Папка | СправочникСсылка.ПапкиПисем | Почтовая папка |
| ДатаПолучения | Дата(ДатаВремя) | Когда получено |
| УчетнаяЗапись | СправочникСсылка.УчетныеЗаписиЭлектроннойПочты | Аккаунт получателя |
| ЕстьВложения | Булево | Наличие вложений |
| Предмет | ДокументСсылка / СправочникСсылка (составной тип) | Предмет переписки |

Табличные части: `ПолучателиПисьма`, `ПолучателиКопий`, `ПолучателиОтвета`

### Бизнес-процессы
Письмо входящее — начало цепочки. Бизнес-процессы не запускаются автоматически, но настроена **подписка на событие**:
- `ПодпискаНаСобытия.ДокументооборотПраваДоступаПередЗаписьюДокумента` → обработчик `ДокументооборотПраваДоступа.ДокументооборотПраваДоступаПередЗаписьюДокумента`

### Регистры, обновляемые при записи
- `РС.HTMLПредставленияСодержанияПисем` — HTML-тело письма
- `РС.КоличествоПисемВПапках` — счётчик писем в папке
- `РС.ОповещенияОПисьмах` — уведомления о новых письмах
- `РС.СведенияОПросмотреПисем` — факт просмотра
- `РС.ПротоколРаботыСотрудников` — фиксация работы

### Код
| Модуль | Процедура | Событие |
|---|---|---|
| `Документы.ВходящееПисьмо / ObjectModule` | `ПриЗаписи` | Запись объекта в БД |
| `Документы.ВходящееПисьмо / ManagerModule` | (обработка HTML, CountPisem) | Менеджер документа |
| `Документы.ВходящееПисьмо / ФормаДокумента` | `ПриЗаписиНаСервере` | Запись вложений, замена предмета переписки |

## Шаг 2. Рассмотрение письма руководителем и вынесение Резолюции

### Объект
**БизнесПроцесс `Рассмотрение`** (`БизнесПроцессы.Рассмотрение`)

Ключевые реквизиты:
| Реквизит | Тип | Назначение |
|---|---|---|
| Исполнитель | Сотрудники / Пользователи | Рассматривающий (руководитель) |
| ВариантРассмотрения | Перечисление.ВариантыРассмотрения | ВвестиТекстРезолюции / другие |
| Резолюция | Строка | Текст резолюции |
| ВариантОбработкиРезолюции | Перечисление | Как обрабатывается резолюция |
| ГлавнаяЗадача | ЗадачаСсылка.ЗадачаИсполнителя | Задача рассматривающего |
| Предметы (ТЧ) | ВходящееПисьмо, ИсходящееПисьмо... | Предмет рассмотрения |
| ШаблонИсполнения | СправочникСсылка.ШаблоныИсполнения | Для создания подпроцесса |
| ИсполнителиИсполнения (ТЧ) | Сотрудники | Исполнители по резолюции |

Карта маршрута БП.Рассмотрение (из ObjectModule, 1535 строк):
- Точка **`СтартПередСтартом`** → предварительная проверка
- Точка **`Рассмотреть`** → создание задачи руководителю (`РассмотретьПередСозданиемЗадач`)
- Точка выбора **`ВыборВариантаРассмотрения`** → маршрутизация (ввести резолюцию / ознакомиться)
- Точка **`ВыборВариантаОбработкиРезолюции`** → создать исполнение / ознакомить
- Точка **`СформироватьИсполнение`** → запуск БП.Исполнение
- Точка **`Завершение`** → `ЗавершениеПриЗавершении`

**Справочник `Резолюции`** (`Справочники.Резолюции`) — хранит вынесенные резолюции:
| Реквизит | Тип |
|---|---|
| ТекстРезолюции | Строка |
| АвторРезолюции | Сотрудники |
| ВнесРезолюцию | Пользователи |
| ДатаРезолюции | Дата |
| Источник | ЗадачаСсылка.ЗадачаИсполнителя / БП.Рассмотрение |
| Подписана | Булево |

### Бизнес-процессы
- Запускается **`БП.Рассмотрение`** через `СтартПроцессовСервер.СтартоватьПроцесс()`
- Создаётся **`ЗадачаИсполнителя`** для руководителя (точка маршрута `Рассмотреть`)

### Регистры
- `РС.РезультатыВыполненияПроцессовИЗадач` — записывается результат (Объект=задача/БП, Результат=ВариантВыполнения)
- `РС.ХодОбработки` — журнал событий обработки (Дата, Действие, Сотрудник, ТипСобытия, Результат, Этап)
- `РС.ОбращенияКОбъектам` — фиксация обращений к документу

### Код
| Модуль | Процедура | Назначение |
|---|---|---|
| `БП.Рассмотрение / ObjectModule` | `ОбработкаЗаполнения` | Заполнение реквизитов при создании |
| `БП.Рассмотрение / ObjectModule` | `РассмотретьПередСозданиемЗадач` | Создание задачи рассматривающему |
| `БП.Рассмотрение / ObjectModule` | `СформироватьИсполнениеОбработка` | Запуск БП.Исполнение по резолюции |
| `БП.Рассмотрение / ObjectModule` | `ЗавершениеПриЗавершении` | Финализация процесса |
| `ОбщиеМодули.РаботаСБизнесПроцессамиКлиент` | `ПередСтартомБизнесПроцесса` | Проверки перед стартом |
| `ОбщиеМодули.СтартПроцессовСервер` | `СтартоватьПроцесс` | Старт процесса на сервере |
| `Задачи.ЗадачаИсполнителя / тст_ЗадачиМне` | `ПродолжениеВыполненияКомандыЗадачаРассмотреноПослеПодписанияРезолюцийЭП` | Выполнение задачи рассмотрения с резолюцией |

## Шаг 3. Создание задачи на исполнение по резолюции

### Объект
**БизнесПроцесс `Исполнение`** (`БизнесПроцессы.Исполнение`) — создаётся автоматически из точки маршрута `СформироватьИсполнение` БП.Рассмотрение

Ключевые реквизиты:
| Реквизит | Тип | Назначение |
|---|---|---|
| Наименование | Строка(250) | Текст поручения (из резолюции) |
| Описание | Строка | Подробности |
| Контролер | Сотрудники | Контролирующий исполнение |
| Проверяющий | Сотрудники | Проверяющий результат |
| ВариантИсполнения | Перечисление.ВариантыМаршрутизацииЗадач | Параллельно / последовательно |
| СрокИсполненияПроцесса | Дата | Срок исполнения |
| Предметы (ТЧ) | ВходящееПисьмо, ИсходящееПисьмо... | Предмет поручения |
| Исполнители (ТЧ) | Сотрудники | Исполнители задачи |

| РезультатыПроверки (ТЧ) | ЗадачаИсполнителя | Задачи проверяющих |

**Задача `ЗадачаИсполнителя`** — создаётся для каждого исполнителя:
| Реквизит | Тип | Назначение |
|---|---|---|
| Наименование | Строка(150) | Наименование задачи |
| СрокИсполнения | Дата | Срок |
| РезультатВыполнения | Строка | Текст отчёта исполнителя |

Адресация задач: `РегистрСведений.ИсполнителиРолей`

### Бизнес-процессы
- **БП.Исполнение** запускается через `СтартПроцессовСервер.СтартоватьПроцесс()`
- Для каждого исполнителя создаётся **`ЗадачаИсполнителя`**
- Если указан Контролер — после выполнения создаётся задача контролеру

### Регистры
- `РС.РезультатыВыполненияПроцессовИЗадач` — результаты по задачам
- `РС.ХодОбработки` — события исполнения (старт, выполнение, контроль)
- `РС.ИсполнителиРолей` — адресация задач по ролям

### Код
| Модуль | Процедура |
|---|---|
| `БП.Исполнение / ObjectModule` | `ОбработкаЗаполнения` |
| `БП.Рассмотрение / ObjectModule` | `СформироватьИсполнениеОбработка` (создаёт БП.Исполнение) |
| `ОбщиеМодули.БизнесПроцессыИЗадачиСервер` | `ЗаполнитьГлавнуюЗадачу` |

## Шаг 4. Исполнитель выполняет задачу и прикладывает файл-ответ

### Объект
- **`ЗадачаИсполнителя`** — исполнитель открывает, заполняет `РезультатВыполнения`, устанавливает `ДатаИсполнения`
- **`Справочник.Файлы`** (через механизм присоединённых файлов) — к задаче прикладывается файл-ответ
- Файл хранится: `РС.ДвоичныеДанныеФайлов`

### Бизнес-процессы
- При выполнении задачи: БП.Исполнение движется по маршруту
- Если есть Проверяющий → создаётся задача проверяющему
- Если есть Контролер → уведомление контролеру

### Регистры
- `РС.РезультатыВыполненияПроцессовИЗадач` — пишется результат задачи (Объект=ЗадачаИсполнителя, Результат=ВыполненоПоложительно)
- `РС.ХодОбработки` — событие "Задача выполнена" с реквизитами Сотрудник, Дата, Результат
- `РС.ОбращенияКОбъектам` — обращение исполнителя к задаче

### Код
| Модуль | Процедура | Назначение |
|---|---|---|
| `Задачи.ЗадачаИсполнителя / тст_ЗадачиМне` | `ВыполнитьЗадачу` | Выполнение задачи |
| `ОбщиеМодули.ВыполнениеЗадачПоПочтеСервер` | `ПроверитьСоответствиеРезультатВыполненияИЗадачи` | Валидация результата |
| `ОбщиеМодули.РаботаСФайламиБЭД` | `ДвоичныеДанныеФайлов` | Работа с файлами |

## Шаг 5. Формирование ИсходящегоПисьма с ответом

### Объект
**Документ `ИсходящееПисьмо`** (`Документы.ИсходящееПисьмо`)

Ключевые реквизиты:
| Реквизит | Тип | Назначение |
|---|---|---|
| ПисьмоОснование | ДокументСсылка.ВходящееПисьмо | Ссылка на исходное письмо |
| ТипОтвета | Перечисление.ТипыОтвета | ОтветНаПисьмо / ПересылкаПисьма |
| ОтправительКонтакт | Сотрудники / ФизЛица | Отправитель |
| ПолучателиПисьма (ТЧ) | АдресатыПочтовыхСообщений | Получатели |
| ДатаОтправки | Дата | Когда отправлено |
| ЕстьВложения | Булево | Наличие файла-ответа |

### Связи с ВходящимПисьмом
Через **`РС.СвязиОбъектов`** устанавливается связь:
- `ТипСвязи = Справочники.ТипыСвязей.ПисьмоОтправленоВОтветНа`
- `СсылкаИз = ИсходящееПисьмо`, `СсылкаНа = ВходящееПисьмо`
- `ТипОбратнойСвязи = ОтправленоОтветноеПисьмо`

### Бизнес-процессы
- При необходимости подписания/утверждения исходящего запускается **`БП.Подписание`** или **`БП.Утверждение`**
- Отправка через **`ОбщиеМодули.ВстроеннаяПочтаСервер`**

### Регистры
- `РС.СвязиОбъектов` — связь ИсходящееПисьмо ↔ ВходящееПисьмо
- `РС.ПодготовленныеКОтправкеПисьма` — письма в очереди отправки
- `РС.ПротоколРаботыСотрудников` — отправка письма
- `РС.ХодОбработки` — событие отправки ответа

### Код
| Модуль | Процедура | Назначение |
|---|---|---|
| `ОбщиеМодули.РаботаСПравиламиОбработкиПисем` | `СформироватьУсловияПоПисьму` | Анализ типа ответа (ОтветНаПисьмо/Пересылка) |
| `ОбщиеМодули.ВстроеннаяПочтаСервер` | `ПолучитьДанныеПисемДляОтправкиИзСписка` | Подготовка письма к отправке |
| `ОбщиеМодули.ВстроеннаяПочтаСервер` | `ЕстьВнешнийАдресатУИсходящегоПисьма` | Проверка внешнего адресата |
| `ОбщиеМодули.ОбновлениеИнформационнойБазыДокументооборот` | `ЗаполнитьНастройкиСвязейПредопределенные` | Создание связи ИсходящееПисьмо→ВходящееПисьмо |

## Итоговая схема сквозного сценария

```
ВходящееПисьмо (от контрагента)
  ↓ запись в БД
  РС.HTMLПредставленияСодержанияПисем, РС.КоличествоПисемВПапках,
  РС.ОповещенияОПисьмах, РС.СведенияОПросмотреПисем
  ↓ руководитель запускает
БП.Рассмотрение (Исполнитель=Руководитель, Предмет=ВходящееПисьмо)
  ↓ СтартПроцессовСервер.СтартоватьПроцесс()
  ЗадачаИсполнителя (точка "Рассмотреть") → руководителю
  ↓ руководитель заполняет Резолюцию и выполняет задачу
  Справочники.Резолюции (ТекстРезолюции, АвторРезолюции, Источник=задача)
  РС.РезультатыВыполненияПроцессовИЗадач, РС.ХодОбработки
  ↓ точка "СформироватьИсполнение"
БП.Исполнение (Предмет=ВходящееПисьмо, заполнено из резолюции)
  ↓ СтартПроцессовСервер.СтартоватьПроцесс()
  ЗадачаИсполнителя (точка "Исполнить") → исполнителю
  ↓ исполнитель выполняет, вносит РезультатВыполнения, прикладывает Файл
  РС.РезультатыВыполненияПроцессовИЗадач, РС.ХодОбработки
  ↓ (опционально: задача Контролеру)
  ↓ БП.Исполнение завершается
  ↓ пользователь создаёт
ИсходящееПисьмо (ПисьмоОснование=ВходящееПисьмо, ТипОтвета=ОтветНаПисьмо)
  ↓ запись
  РС.СвязиОбъектов (ПисьмоОтправленоВОтветНа → ВходящееПисьмо)
  РС.ПодготовленныеКОтправкеПисьма
  ↓ отправка через ВстроеннаяПочтаСервер
```

| Модуль | Роль |
|---|---|
| `СтартПроцессовСервер` | Запуск всех БП |

| `ВстроеннаяПочтаСервер` | Отправка ИсходящегоПисьма |
| `РаботаСПравиламиОбработкиПисем` | Правила обработки писем |
| `ДокументооборотПраваДоступа` | Права при записи документов |
