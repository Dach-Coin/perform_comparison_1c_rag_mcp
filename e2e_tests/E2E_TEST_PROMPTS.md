# E2E тесты MCP-серверов OneRPA на конфигурации ДО3

## Идея

10 одинаковых бизнес-вопросов прогоняются через каждый из трёх MCP-серверов по отдельности.
10 промптов × 3 сервера = **30 прогонов**. Сравниваем, как каждый сервер справляется с одним и тем же вопросом.

## Структура каталогов

```
e2e_tests/
  E2E_TEST_PROMPTS.md           — этот файл
  agent_logs/                    — полные логи вызовов MCP
  business_reports/
    cloud-embeddings/            — отчёты по 1c-cloud-embeddings
    code-metadata/               — отчёты по 1c-code-metadata
    graph-metadata/              — отчёты по 1c-graph-metadata
```

Именование файлов:
- Логи: `agent_logs/test<ID>_<сервер>_log.md`
- Отчёты: `business_reports/<сервер>/<ДАТА>_test<ID>_<название>.md`
- Пример: `business_reports/cloud-embeddings/2026-04-07_test01_вх_письмо.md`

## MCP-серверы

| Сервер                          | Краткое имя для файлов |
| ------------------------------- | ---------------------- |
| 1c-cloud-embeddings (порт 8000) | `cloud-embeddings`     |
| 1c-code-metadata (порт 8001)    | `code-metadata`        |
| 1c-graph-metadata (порт 8006)   | `graph-metadata`       |

## Протокол для агента-анализатора

Оркестратор вставляет этот блок перед каждым тестовым промптом, подставляя `<СЕРВЕР>`, `<ID>`, `<ДАТА>`.

```
## ПРОТОКОЛ (обязательно)

Ты — агент-анализатор, выполняющий e2e тест MCP-сервера для 1С.
Конфигурация: 1С:Документооборот КОРП 3.0 (DO3).

Используй ТОЛЬКО MCP-сервер <СЕРВЕР>. Другие серверы НЕ трогай.
Используй любые доступные инструменты этого сервера по своему усмотрению.

### Правила логирования

1. ПЕРЕД каждым вызовом MCP-инструмента запиши:
   - [MCP_CALL #N] Инструмент: <имя>, Запрос: "<текст запроса>"

2. ПОСЛЕ каждого вызова MCP-инструмента запиши:
   - [MCP_RESULT #N] Символов в ответе: <число>, Результатов/чанков: <число если применимо>
   - [MCP_RESULT #N] Релевантность: <высокая|средняя|низкая|нерелевантно> — краткое пояснение

3. Если ответ MCP не помог и нужен повторный/уточняющий вызов, отметь:
   - [MCP_RETRY #N→M] Причина: <почему предыдущий вызов не дал результата>

4. В КОНЦЕ анализа обязательно выведи сводку:

   ### Сводка логирования
   | #   | Инструмент | Запрос | Символов | Релевантность |
   | --- | ---------- | ------ | -------- | ------------- |
   | 1   | ...        | ...    | ...      | ...           |

   - Всего вызовов MCP: N
   - Полезных (высокая/средняя): N
   - Шумных (низкая/нерелевантно): N
   - Повторных (retry): N

5. После сводки дай субъективную оценку:
   - Ответ на вопрос: ПОЛНОСТЬЮ / ЧАСТИЧНО / НЕ СМОГ
   - Что пришлось додумывать (гадать) vs что получено из MCP
   - Какой информации не хватило

### Временные файлы

Если нужно сохранить промежуточные данные (большие ответы MCP и т.п.), пиши их в:
`/e2e_tests/tmp/test<ID>_<СЕРВЕР>_*.md`

### Метрики производительности

В конце лога обязательно добавь секцию:

```
### Производительность
- Общее время выполнения: <MM мин SS сек>
- Символов получено из MCP (суммарно): <число>
- Оценка токенов MCP-ответов: <символы × 1.8> (коэфф. 1.8 для кириллицы)
- Оценка общего расхода токенов агента: input ~<число>, output ~<число>
```

Для оценки расхода токенов агента: считай что каждый MCP-ответ целиком попадает в input,
плюс сам промпт (~2000 токенов). Output — это текст лога + бизнес-отчёта.
Кириллица: 1 символ ≈ 1.8 токена.

### Сохранение результатов

- Лог: /e2e_tests/agent_logs/test<ID>_<СЕРВЕР>_log.md
- Бизнес-отчёт: /e2e_tests/business_reports/<СЕРВЕР>/<ДАТА>_test<ID>_<краткое_название>.md
```

## Как запускать

1. Убедись, что нужные контейнеры healthy (`docker ps`) и LM Studio запущена с bge-m3
2. Для каждого теста × каждый сервер:
   - Вставь **протокол** (подставив `<СЕРВЕР>`, `<ID>`, `<ДАТА>`) + **текст теста**
   - Запусти в новой сессии Claude Code
3. Итого 30 прогонов: 10 тестов × 3 сервера
4. После всех прогонов — собери сводку в `E2E_SUMMARY.md`

## Что оцениваем

| Метрика                | Описание                                      |
| ---------------------- | --------------------------------------------- |
| Полнота ответа         | Смог ли агент ответить на все подвопросы      |
| Количество вызовов MCP | Меньше = лучше (при том же качестве)          |
| Доля шумных вызовов    | Вызовы с низкой/нулевой релевантностью        |
| Количество retry       | Сколько раз пришлось переформулировать запрос |
| Размер ответов MCP     | Косвенная метрика расхода токенов             |
| Субъективная оценка    | Полностью / Частично / Не смог                |
